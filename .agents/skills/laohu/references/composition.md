# 多能力组合与交接规则

仅当 `/laohu` 确认单个入口无法独立覆盖用户目标、确需多个入口提供各自不可替代的贡献时读取。候选均来自当次动态扫描并已核读正文，不套固定套餐；路径沿用 `{SKILL_DIR}` 与 `{PROJECT_ROOT}`。

## 1. 先过成员必要性核对

逐项检验每个候选成员，通过才保留：
1. **不可替代**：去掉它是否确实缺失一项用户要求的必要产出或判断？重叠时择优留一。
2. **不重复拆父子**：若已选主入口通过自身 Reference 或内部子级即可完成（例如 `laohu-htmlshow` 本身即涵盖离线展示与公众号排版），直接由该入口完成，不拆成组合。
3. **归属同一目标**：互不相关的多个愿望按用户优先级分开处理，不硬凑单一主责。
4. **边界与来源真实**：核实入口正文确有该职责，且上游输入真实存在（缺关键前提时只推荐可执行部分并标出决定点）。

## 2. 定主责、排依赖、严守授权

- **唯一主责统筹**：选最贴合最终交付的 Skill 统筹全链——保管任务状态、承接协作返回、核对保护项并统一汇总成品（不拼接内部过程报告）；无合适主责时说明冲突并建议收窄或拆分。
- **按依赖排顺序**：先做会改写方向的判断，再备料，再制作与核查；互不依赖的产出不硬造先后转换，组合也不自动触发多 Agent 或归档写入（仅获保存授权时按 `docs/runtime.md` §2 接入 `laohu-archive`，同一作品始终沿用同一目录）。
- **明确停点与不扩权**：关键方向、归属或权限未定时设清晰等待点；推荐组合绝不附带发布、付费、外部通信或长期改规则授权。

## 3. 交付自足的组合建议

先用两三句自然人话交代谁主责、谁协作、为什么单入口不够、先后次序与哪里需用户拍板，再附一段可直接发送的提示词（按需精简字段，省略无关项）：

```text
请使用以下能力完成这个任务：{已明确的目标与交付物}。
主责：/{实际名称}（入口：{实际路径}），负责 {统筹范围与最终交付}。
协作：/{实际名称}（入口：{实际路径}），接收 {输入}，负责 {必要贡献}，返回 {产物或判断} 给 {接收方}。
已有材料、决定与保护项：{沿用的内容、路径与锁定项}。
顺序与等待点：{按依赖排序；遇到未决条件或失败时的暂停/询问动作}。
本次授权范围：{明确授权边界}；完成时由主责统一汇总交付并说明实际路径与未完成项。
```

交完推荐即止步（用户同一消息已明示选好直接做时，说明方案后按序交接执行）。
