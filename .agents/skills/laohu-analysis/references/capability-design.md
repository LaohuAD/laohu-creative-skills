# 完整能力设计

由 [analysis 主文](../SKILL.md) 在新建一项可复用能力、整体重构现有能力、扩大其职责，或用户明确要求端到端设计时读取完整设计流程；由 [evolution 主文](../../laohu-evolution/SKILL.md) 在实施已确认的整体方案、需要核对各部分职责与衔接时读取。它教怎样从目标走到一套各部分互相接续的能力方案。analysis 读完回主文交付方案；evolution 只据已确认目标核对设计覆盖与依赖，不重新开展整体分析，随后回 [“组织可执行的专业方法”](../../laohu-evolution/SKILL.md#组织可执行的专业方法)，并按实际写回依赖进入[“依据语义把规则合并、替换或分支”](../../laohu-evolution/SKILL.md#依据语义把规则合并替换或分支)。另当已选关键方法缺少适用输入、实际动作、产物、例外/失败处理或消费者，导致执行者不得不临场发明时，可依 analysis 主文索引只读补足该缺口的相关部分；这不升级为完整能力设计。局部原因判断、已知方法的正常单点应用不必走完整设计。

整体设计沿六个相连的问题推进：**要为谁改变什么结果 → 对象和知识说明了什么 → 能力怎样分工 → 各部分怎样做事 → 各部分怎样合成一个整体 → 怎样核对并交接。**这是一条完整设计主线，不是必须逐项填满的表格；一项已由材料回答的问题直接沿用，不重复研究。

## 1. 定目标与范围

从已确认的任务状态开始，把愿望落成可检查的工作边界。负责作者按[运行约定](../../../../docs/runtime.md#作者表达意图与成品保真)的标准，以适合本作目标、体裁、文化语境与媒介的顶尖人类完成度为目标；不因用户请求粗略或专业经验不同而降标，也不因此扩展用户确认的范围、预算或风格。从相称的人类作品和成熟专业方法中找可观察的完成条件，并把它们转成实际生成与修订动作。顶尖目标、选定标尺、一次试作的表现和已验证的质量成绩是不同判断；声称达到的范围按[验证协议](validation.md)提供证据。

- 谁在什么情境下提出什么普通请求；
- 能力需要理解哪些输入，交付什么结果给谁；
- 哪些已确认观点或文化立场、叙述视角、声音、情绪力度、技法、优先级和原句必须保留，哪些仍开放；事实断言是否需要另行核实；
- 先辨最终读者、观众或使用者要理解、感受或采取什么行动，再定作品体裁与形式；若中间经过模型、解析器或制作流程，明确各直接消费者所需的输入与规格，按接口验收中间交接，按实际成品和最终接收证据判断人的目标效果；据真实使用情境选择语言、口吻、信息组织和版式，若产物还受机器接口约束，明确要保持的字段与格式；
- 哪些情况属于能力职责，哪些情况退出、询问或交给别的负责人；
- 什么观察足以说明方案可交接，什么效果仍未验证。

用代表任务确认范围覆盖。不要只用“提高质量、更加专业、功能完整”等词代替接收者能看到的变化。已有目标、约束、风格和接口要求直接继承；只在缺项会改变产物、权限或专业取舍时追问，常规且可恢复的格式选择由负责作者按使用情境确定工作默认。上述对象是设计检查，不是每次都要向用户展示或让用户逐项填写的问卷。

将要求分成不可违反的约束、已确认的优先目标、仅在条件成立时适用的目标和仍开放的偏好。它们相容时一并保留；发生冲突时说明本轮按什么已确认优先级作决定、会牺牲什么，只在取舍未定且会改变主要产物时询问。不要把所有目标都写成同等强制，或声称一套方法同时最大化互相冲突的效果。

## 2. 理解对象与知识基础

先看能力实际处理什么对象。沿输入、判断、变换、交接和最终结果还原关键元素及其关系；逐项问“这项材料或条件改变时，处理会不会改变？”只有答案会改变动作、结构或验收时，才把它做成独立规则或分支。按真实材料发现领域需要，不预填固定学科或模块，不把共享模型变成答案清单；正式设计时仍须按本节模型要求完整应用全部交点。

重构现有能力时，若历史执行缺口会改变设计，按[调查取证、解释与方案比较](investigation.md)中“区分方法缺失与执行断点”一节区分方法缺失、未加载、未执行、评价未覆盖目标与适用条件失效；只在已有材料支持的范围内定位当前问题，读完回本步，不复制一套失败分类流程。新建能力没有执行历史时，按目标和代表任务设计，不编造旧版缺陷。

知识调查和设计同时进行。先找出会改变设计的关键专业判断，再主动盘点该领域已有的理论、模型、标准术语和作者方法。找到相关方法时，核对原始来源、专业教材或可靠记录，保留标准名称与核心命题；准确适用的原句优先直接用于承担判断的运行规则，并标明出处。原句或术语已能指导选择时就直接使用；只有迁移到本地后仍有歧义或执行缺口，才补足会影响执行的最少条件、动作或取舍，并清楚标成适配或推论。**方法名称或一段描述存在，不等于它对当前目标准确、覆盖足够或能被执行：核对实际方法内容、适用条件、必要步骤与取舍是否完整进入普通任务路径，再决定保留、校准或补缺；不得只因输出不佳就假定方法缺失。**

方法用于支持相应判断，不负责替本地材料作结论。成熟方法可作为有条件的工作选择，不需证明普遍成功；但来源声誉、术语或引文不能代替适用性判断。来源暂时无法核验时，标明是转述或待核内容，不伪称原话。**非创作流程、数据或接口设计没有适用专业方法时，可依据本地对象和可观察约束形成规则；创作与审美能力的核心生成路径则不能把“材料之间有某种关系”当作成熟法度的替代。先沿用户已选方向选择并配置适用的专业结构、理论、方法或技法；若没有适用法度，明确指出具体方法缺口，只推进不依赖该缺口的设计，不将临时推导的关系改称专业方法。对关键审美、声口、节奏、叙述与媒介表现，仅有通用理论、行业底线或“有动机/有变化/自然”等抽象判据不足以构成具体写法参照；须保留相配的实际作品单元或可核方法、必要上下文、具体处理及适用条件。通用理论仍可检查作品是否成立，但不能替代这些实际参照。**不要求每个模块配理论，不为显得严谨而搜集理论。

### 先对齐方法解决什么，再决定保留或改动

本节判断来源方法是否适用于本地问题。凡要把选定方法并入已有运行规则，或更新、新建、融合规则，语义对照、增补、条件分支、冲突裁决与信息去向统一按[evolution 的规则表达与方法保留](../../laohu-evolution/references/rule-expression.md#更新规则前按语义对照)执行；该 Reference 是内容融合的唯一细则，本节不再维护第二张取舍表。专业适用性仍按可定位的材料、机制、条件和代价判断；没有本地效果记录不妨碍按授权试用，但预期不能写成已验证结果。

来源意见有分歧时，按该语义对照先判是否条件不同或同条件冲突，再核验原始依据或设计能区分处理的检验。来源只给原理、没有操作办法时，标出方法缺口；范例只展示结果、没有创作过程时，只作为可观察参照，不声称复原作者的方法。

需要真实作品来打开未决方向、检查一种方法或比较可迁移处理时，先确认这会改变哪项方法、表现设计或成品判断，再按[真实作品研究方法的日常创作取法与方向](../../../../references/exemplar-study.md#日常创作取法与方向)细读。它统一作品身份、原作语境、可观察证据、专业解释、资料角色、迁移决定和来源边界；本节只要求研究结果接回本地能力的生成步骤，不复写完整研究协议。范例中可观察的形式、对其作用机制的解释、本地采用的生成方法彼此分开；只有创作过程来源确实说明作者怎样生成，才称为作者方法。普通创作无需例行外搜，也不因作品流行、名气或表面相似就迁移。研究所得必须改变某项实际选择并进入真实产物路径；否则不能声称已完成迁移。正式标尺选择、校准与 L/C/D/H 用途另按[正式评估与 L/C/D/H](../../../../references/exemplar-study.md#正式评估与-l-c-d-h)和唯一验证协议处理，不能让日常取法替代质量比较。

把依据分清：

| 内容 | 在方案中的身份 | 应由什么支撑 |
|---|---|---|
| 本地对象、限制与发生过的事 | 事实 | 可定位的原始材料、当前记录或可复现观察 |
| 原因及其作用关系 | 解释 | 材料与机制；关键时用能区分解释的预测核对 |
| 用户明确选定的目标和偏好 | 决定 | 用户确认及其适用范围；不要求群体统计证明 |
| 成熟专业做法 | 方法选择 | 相关依据、适用条件、代价和切换情形 |
| 能力如何分工、采用何种接口 | 设计选择 | 目标、使用情境、依赖、成本及可检查性 |
| 方法已经带来何种效果 | 结果主张 | 与目标匹配的实际运行、成品、接收者或使用证据 |

方法、偏好、方案和效果不可混写成同一类“依据”。查不到来源时收窄事实或标出未知；有适用方法但没有本地效果数据时，可建议或按授权试用，不把预期写成已验证结果。不要为了给每条设计配理论而虚构学说，也不要只在方案末尾贴上一段与选择无关的理论。

## 3. 设计整体架构

先按不同的使用情境、决定和交付责任拆分能力的功能。为每一部分说明它接收什么、作出什么决定、产出什么，以及谁会使用该产物。再检查：

- 哪些部分有真实依赖，前一步的产物是否正好满足后一步；
- 哪些部分可由任务条件触发，哪些是每次都需要的共同步骤；
- 哪些决定只该由用户作出，哪些可由专业方法形成工作默认；
- 哪些内容由主 Skill 统领，哪些独立方法适合放入可按条件读取的 Reference；
- 用户、文件、媒介和外部动作分别由谁负责，是否保持原有授权与输出接口。
- 沿终端读者或使用者的实际路径，明确作品要让读者怎样理解、感受或使用，再选择对应的体裁与形式；同一能力承担不同用途时，分别设计产物路径，不预设封闭的作品类型清单。

以普通请求检验职责划分：每个请求只需读取和运行它依赖的部分，不让局部任务负担整套能力，也不让模块数量代替实际分工。用户已给的表达和格式要求进入相应产物流程；内部分析完整性字段不自动成为可见栏目。区分名称表示的层级和物理部署：独立公开入口的主文承担完整专业方法；宿主内部配置由用户明确专项需求触发，叠加父级已有方法中的范围、取值或专项展示要求；二级不加载它仍能完成通用任务。设计时逐项回答：什么用户请求启用、什么材料提及不启用、启用后哪项决定或产物发生可观察变化、哪些普通方法继续归宿主；没有独特贡献不拆三级。角色归属与展示对象分开判断，不把绑定关系直接变成成图主体。子级不另立完整专业流程，也不因名称层级或目录嵌套推断公开身份或自动调用。配置如何表达维度、组合和真实消费者，按[能力文件增、改、删](../../laohu-evolution/references/change-workflow.md)和[能力运行约定](../../../../docs/runtime.md)办理。已有入口和共享路径优先沿用；只有新的独立职责确实需要完整的入口和交付时，才拆成独立公开能力。

完整能力设计仍须在授权对象内完整审视共享模型的交叉方向；本 Reference 只展开规模化能力架构与创作领域方法，不另立坐标、固定答案或输出格子。能力架构按目标、专业对象、决定责任、输入与下游产物划分：真实模块通常同时承担多个方向，一个方向也可能由多个模块接力完成。设计和未来运行都要在普通任务的判断、条件变化、材料处理、消费者与结果中体现模型作用；不按模块标题、文件数量或标签数推断覆盖，也不要求每个方向都新增一条规则。设计中的子项随对象生长，允许交叠、关联和融合。

创作中四维保留既有内涵：灵魂包含创作目的、作品立场、文化与审美判断及宏观策略；筋骨是为实现灵魂而选用、组合和配置的成熟专业法度；血肉是本作的具体表现设计；表皮是符合受众、体裁、文化语境和媒介的实际作品表现，文字包括真实成文。共同模型中“筋骨”与“表皮”也用于规则、流程和工程，不缩成流程清单或排版外观。各维度依其在当前判断中承担的作用辨认，不按名词硬分类；例如“节奏”可以指专业方法、具体安排或成品语言效果。

叙事尺度是创作专属的另一条坐标，描述故事整体或局部行动怎样组织、推进和变化；它不等于四个维度或四个工作层次。任一叙事单位都可能涉及模型中的多种判断，同一判断也可能跨越多个叙事单位。设计叙事时，先按已选方法确定实际采用的单位及上下级关系；从已确认的上级目的、作者立场与所选法度及其构成要求，确定本级任务、进入时的前提或状态，以及离开时须形成的变化。再将本级任务落实为具体内容、人物行动、信息次序、视角、词句或其他媒介表现，回看下级安排是否兑现上级承诺。只在所选方法实际采用的单位上设计，不自动套用电影三幕或其他未选结构，也不把结构术语清单当操作步骤。幕、序列、场景、节拍（beat）等单位及边界由所选方法和媒介决定：beat 不等于镜头，sequence 也不自动等于章节、集或卷；不采用叙事组织的任务不强加这些单位。

创作设计不是默认进入审错。只有当前任务本身要求审阅作品并确认目标差距时，才从实际成品定位最早出现偏差的相关单元，再按授权范围核对目标、专业方法、具体表现和上下级承接。设计与调查范围则随当前决策和依赖收敛：用户指定局部且判断不受其他部分影响时只看该局部；问题涉及全篇主线、声音或组织时看全篇；局部问题会改变相邻章节、段落或关键句时同时检查直接受影响部分。创作可从已有句子或画面进入，仍要让目的、专业方法与具体设计在成品中各自发挥作用。入口、角色、调用顺序和文件交接属于实施架构，不能彼此代替模型中的判断。

## 4. 逐部分设计可执行方法

按真实任务流程，先把授权范围内每个交点落实到目标能力中实际承担的职责、判断或消费者；确认现有能力已充分承接时保留原状，不为覆盖形式新增模块或规则。对每个真正承担判断或制作的部分，把已选领域方法写成能从材料走到结果的操作链：材料中的哪些差异会改变选择，执行者依据什么专业判据、用什么实际判断动作识别它们，据此怎样选择、组织、连接或转换材料，形成什么中间或最终产物并交给谁继续使用。条件改变时写明切换的方法或分支；没有真实依赖的独立职责不强造先后。下面的检查项共同构成可执行的方法，不是要求每个部分重复四层字段：一个完整方法可以跨多个部分，同一方向也可由多个子职责接力；要让关键交点的实际贡献和下游用途可追溯，而不是只靠模块标题或输入输出清单证明完整。

- 输入中要注意什么，以及哪些条件会改变处理；
- 默认选择是什么、为什么优先、舍弃了什么；
- 哪些方向必须明确、哪些实现细节留给下游模型；服装/道具/场景及穿搭不默认穷举微观字段，按规则表达Reference明确精控与已确认复现的扩展条件；
- 执行者怎样从判断走到动作，产生什么中间产物；
- 后一步由谁、怎样使用这项产物；
- 哪些是替代分支、例外、未知、暂停点或退出条件；
- 最终接收者能从哪个成品位置看见预期变化。

当任务要求覆盖一组对象时，明确本次对象范围；为单个对象写清输入、判断、动作和产物；指出当前对象到什么状态后切换到下一个对象；并在全部范围处理完后逐项核对已处理、待确认或按授权跳过的状态，确认没有把“开始处理”误当“整组完成”。如果用户明确只授权抽查或处理某个子集，就把该样本/子集单列为本次范围，说明抽取依据或边界，不能把局部结果写成全组完成。只有任务目标确实要求覆盖这组对象时才建立这条逐项路径；不要求每项创作都穷举或逐一使用所有输入素材。对操作/处理型任务的关键分支，还要沿实际状态变化核对动作前提：执行时所需对象和目标位置必须由输入明确提供并确认可用，或由前一步成功产出；新建的文件夹/路径在首次引用前创建。若取消或失败使副本、文件夹或其他产物未生成，后续步骤不得假定它已存在；补上实际创建/恢复动作，或明确停止该分支。只追踪会改变执行的关键依赖链，不把文学作品拆成逐词对象台账。

核心专业判断不要留给实施者临时发明。分支只在会改变选择时保留；用户明确选定的政策或方法按确认范围执行；成熟方法在适用条件成立时可作工作默认，不要求群体成功率证明。若需组合多种法度，逐项说清它解决的子问题、互相依赖和先后位置；核对它们对对象、比较尺度、信息前提、时间与声口的要求是否兼容、是否争夺同一重心或重复同一功能。每项方法只实现本作需要的作用，不按叠加技巧数量或增强强度判断质量；冲突且无相容变体时选择更贴合已确认目的的一项，其他方法退为可选或不采用。需要群体证据的是受众偏好、普遍效果等经验性推广主张；证据不足时将这类主张标为候选或待验证，本地效果状态另行记录，不反向降级已选方法。用户偏好仍只在明确范围内生效。把已确认的作品表达和格式要求写入实际生成步骤与最终交付验收，不只放在角色描述；需要机器读取的产物继续遵守精确接口，不为“更易读”擅自增删字段或加入解释。对事实不全、材料冲突、方法不适用等情况，说明哪一项依赖动作先停、哪些无依赖工作仍可完成。

方法“已存在”只说明有可核对对象，不证明其准确、适用、覆盖或执行充分。对本轮受影响的关键生成动作簇核对：已选法度是否被正确描述并符合当前目标，适用条件与必要构成是否齐全，正常任务是否会加载并执行，表现设计和实际作品是否接续，成品是否能观察到目标。不要逐句制作全仓台账；定位足以改变选择或产物的缺口，在其真实控制位置修正。若从例子开始整项能力诊断，先把例子拆成材料、作用关系、判断改变与成品位置；同一对象中有条件可比的成功和失败处时，再用它们检查候选机制边界。缺少某一侧的现成例子不要求先证明能力失败，也不阻止依据已确认升级目标或选定方法推进已授权、可恢复的设计；将未知边界和效果另标待查，并沿普通任务及其成品检查正常触发和消费者。将成立的机制转成相关专业入口的具体材料选择、媒介操作和验收，再映射到真实触发、读取路径、规则位置及消费者。此映射是设计交接，不代替 evolution 写回，也不把期待效果报告成验证结果；已有有效的专业操作保留在其消费者内，缺少证据的效果仍标未知。文字作品中的具体选词、成句和成段属于表皮实现；指导这些实现的词汇、句法、修辞、段落和文体方法属于筋骨，选什么内容和怎样安排其表现属于血肉。不得混淆方法选择、具体设计与成品语言，也不得只交“更自然、更有力”等验收词；本能力要设计实际文字生成或修订步骤时，读取根目录的[语言成文方法](../../../../references/language-realization.md)，并把对应动作写到文字消费者。能力服务具体读者，且理解、行动、情绪或审美价值会改变目标、组织或验收时，读取[读者价值与作品组织](../../../../references/audience-value-and-structure.md)，只把相关取舍写入本次设计，不把价值分类变成每篇作品的固定栏目。

宽泛效果词要继续转成执行动作：明确接收者要理解、感受或完成什么，定位相关成品位置和表现设计，再依据当前媒介选择能建立该表现的操作与纠偏办法。对创作或审美成品，先检查成熟方法是否适用；不适用时可选择另一成熟方法、适用变种或有依据的组合，并写清继承的构成要求。确无适用法度时，指出核心方法缺口，不以临时推导的任意关系冒充筋骨；不依赖该缺口的工作继续。若所谓技巧仍停留在名词、没有明确选择和操作，也未连接到实际成品表现，执行者还没有得到方法。当本轮交付物是运行规则改进方案或写回实施交接时，给出原位置/原句、完整替换段落及其接入正常生成步骤的位置；正向规则说明材料、转换顺序与产物形式，效果词用于验收而非生成。具体展开按[调查、证据与方案比较](investigation.md#把效果判断落到媒介内的动作)执行，本处不重复维护细则。

在用户普通创作请求的已授权范围内，无需为内部候选另行询问，但不把候选比较变成每项任务的固定步骤。先指出一个会影响目标表达、且存在至少两种可行处理的具体变量；仅当比较结果可能改变选择时，才写出足以呈现差异的候选，默认先比较两种，只有第三种有独立材料依据且可能改变选择时才加入。不得要求执行者在试写前准确预言差异；若成品比较后没有实质差别，合并或保留更简洁的版本，不凑数。若目的、专业方法、表现设计和事实条件均已定而只比较成文实现，锁定这些上层决定，在既定视角与表现设计内比较真实措辞、句法、信息顺序及必要上下文；候选改变视角、动作、关系或内容安排时，返回对应判断层重新处理，不能称为仅比较表皮。试写文字候选、比较词句或修订段落时读取根目录[语言成文方法](../../../../references/language-realization.md)；媒介专属的候选方法仍由目标 Skill 决定。选择后的成品还须经过定向修订并复查。额外交付多稿、触及用户锁定内容、超出本轮范围或产生额外成本与外部动作时，按运行约定核对相应边界；真实受众或平台效果另按其证据范围报告，不作为每次创作的强制测试。

设计各部分时持续检查关键判断是否已有可用方法，并按步骤二核对来源与适用机制。用户给出的准确适用原句、专业来源的标准术语与核心命题，写进目标主文或实际读取的 Reference，不只留在背景资料里。若它们已能指导选择，直接使用；若本地应用仍有歧义或执行缺口，只补足必要说明，并标清来源原意与本地适配。需要从真实成品学习时按[真实作品研究方法的日常创作取法与方向](../../../../references/exemplar-study.md#日常创作取法与方向)读取来源身份、上下文、实际证据和迁移要求；本节不重复维护例证处理协议。analysis 不自行创作作品充当方法示范或任务内试作。需要检查作品行为时，由经授权的目标执行 Skill 按最终文件实际产出。没有可核实来源时保留方法，说明具体受限的证据主张并继续不依赖它的设计。

把方法落到文件前，先将会改变运行的判断单元与目标位置、实际消费者对齐。核对条件、顺序、例外、表格中的条件—动作对应、模板字段与格式、语言力度及示范作用，再按本节已作出的保留、替换、增补、合并、分支或删除决定交接；只交核心命题会漏掉方法怎样运行，只照抄旧文又会保留已判定的错误或重复。对整体改造，交接中标明各项取舍及依据；有实质冲突未决时返回调查，不让实施者自行决定。

## 5. 比较并融合为一个整体

运行规则的范围覆盖、重叠、遗漏、条件分支和冲突按[evolution 的规则表达与方法保留](../../laohu-evolution/references/rule-expression.md#更新规则前按语义对照)统一检查。本节继续沿普通任务从头走到交付，检查各部分是否接得上、各有明确职责且后续消费者确实使用中间结果；跨部分原则放在唯一真源，被替代的补丁或旧方法说明如何迁移或退役。

只有方案确实有不同架构或取舍时才比较候选。先排除不符合硬约束的方案，再按已确认目标说明关键收益、成本、依赖、维护和验证难度；不造分数或权重。用户已决定的取舍照此落实；尚未决定且会改变整个架构时，给具体建议与后果，只请求该项选择。没有真实的替代方案，不为满足“比较”而凑数。

再用近邻请求确认边界：什么样的请求不触发该能力、需要跨入口时怎样说明职责和授权、必要的 Reference 读取如何避免被误作正式委托、用户更改决定时哪些环节须更新。新材料只改动受到影响的决定及其消费者，不推倒仍成立的部分。

## 6. 验证设计并交接实施

用一项代表任务沿架构做方案走查，从真实输入推演需要的决定、操作、中间产物、消费者和保护项；创作作品只推演其生成要求与验收，不由 analysis 写出作品示范或试作。改变会切换选择的条件，确认方案指出不同处理或退出；只换说法而条件不变时，核心选择保持一致。若用户目标是顶尖完成度，就持续以顶尖完成度为目标，不降级为“合格/熟练”来报告完成；实际达到范围由[验证协议](validation.md)中的标尺身份、校准与作品证据决定。方案走查证明设计可接手，不证明文件已改、能力已运行或用户质量已提升。若需检查实际作品行为，由经授权的目标执行 Skill 仅凭最终文件和普通输入产出，再按验证规则读取产物。

把交接写到实施者能直接落地：已确认目标与范围、每部分职责、选定方法及适用条件、实际控制位置与消费者、需要保留、替换、增补、合并、分支或删除的内容及依据、实施依赖、下游产物、验收输入和预期观察、未知项。整体迁移或重构要让实施者能把这些决定映射到原位置与目标位置；若缺少项会改变目标、权限、核心方法或关键验收，标明具体阻塞并只暂停依赖部分。

交接前反问：执行者能否只靠这份方案决定核心材料如何取舍、关系如何实现、什么成品表现算达标？若仍须用户临场示范核心选法，方案写明缺少的专业决定及其影响；不要把该决定伪装成普通措辞工作交给实施者猜。细节由实施者发挥的空间可以保留，前提是它不替代尚未确定的目标或核心方法。

行为与质量须按实际证据另行验证。说明结构检查、方案走查、试用观察、独立行为运行和真实接收者效果分别能支持什么；未执行的能力不能仅因架构完整就报为行为通过。实施写回由已授权的负责人交 laohu-evolution 完成；跨入口产物和授权沿项目共同运行约定处理。
