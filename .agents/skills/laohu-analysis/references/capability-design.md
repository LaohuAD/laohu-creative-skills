# 从专业任务到可实施能力

由 [analysis 主文](../SKILL.md) 在创建长期能力、扩展承诺范围、重建专业方法，或连续局部修订仍未改善结果时调用。由当前分析负责人执行，沿用已恢复的目标、授权和材料；完成后返回主文第 4 步交付方案，再按第 5 步走查。不用于已知解法的常规应用，也不要求每次完成所有研究动作。

## 先固定结果，再决定研究范围

从完整对话恢复仍有效的要求、用户纠正、保护项和已完成事项。用户要求解决此前全部问题时，在当前交付中逐项对应处理、保留、撤回或暂缺证据，不只围绕最近编号；不得为覆盖表另建空台账。先纠正执行偏差：现有方法已经明确而本次没有执行的，复现实际遗漏并修正执行，不先追加同义禁令。

选择一个实际任务作为起点，明确普通输入、接收者、使用条件、要改变的判断或产物，以及当前可见失败。没有失败历史的新能力，用用户所需结果和代表情境建立候选，不虚构旧版失败。比较标准先分成必须成立的条件、本轮优先改善的效果、要保护的风格与取舍；不以篇幅、步骤数或固定分数替代作品质量。

将当前问题沿实际材料连接：输入中有什么 → 执行者据此选择什么 → 方法做了什么 → 用户看到什么。文件规定只能证明写了什么，执行轨迹和产物才支持发生了什么。区别直接错误、使错误重复的条件和未被纠正的原因；针对各处分别提出动作，不用“能力不足”作为终点，也不把更深的解释自动当成更有效的干预。

## 先定义这项能力到底替执行者解决什么

从用户要完成的任务出发，写清“已有哪些输入，但在哪个决定或动作上仍做不好；本能力补上什么，最终交出什么”。这比“提升质量、深度分析、全面优化”更能决定范围。一个入口可以服务多个领域，但它必须拥有稳定的处理问题；领域内容通过对应方法承接，不能把通用流程冒充所有专业知识。

依次用四个问题确定边界：

1. **进入前已经成立什么？** 分清普通输入、可由本入口取得的材料、上游必须完成的决定。不能要求上游先完成本入口承诺解决的难题：分析入口不能先索要完整根因，创作入口不能先索要用户写好的成品。
2. **本入口对什么结果负责？** 用可交付结果限定责任。例如找茬负责确认差距，分析负责支撑选择，进化负责将选定方法变成可运行能力。它们都可能读取、比较、试跑，但共同动作不代表相同职责。
3. **最接近但不属于它的任务是什么？** 选择会实际误入的相邻需求，说明由谁承接、传什么、何时返回。不要列无关禁区充当边界，也不能把完成自身结果所需的取证或小样推给别人。
4. **何时结束，何时退回？** 正常结束必须由产物与检查证据决定；退回必须指明哪项决定缺失、为什么会改变实施、接收者补足什么后恢复。失败时重试同一步、换方法、交回判断或请求新权限，应有不同条件。

先用一个正常请求和一个近邻请求检查上述边界，再写 description。description 用普通任务语言表达“什么时候用—解决哪项缺口—交付什么”，必要时补最容易误入的边界；不要用宏大能力清单覆盖所有请求。主文展开进入条件、处理权和完成条件；Reference 只展开某项被调用的方法，写明调用条件、执行者、所需输入和返回位置。不能在 Reference 偷加全局路由、授权门槛或重新定义主文职责。

### 用变化检查逻辑是否稳定

对同一任务保持事实、目标与授权不变，只改变口语说法、材料顺序或是否出现技能名，检查入口和实质动作是否保持；再只改变一项决定性条件，检查动作是否按既定方法切换。最后把该条件删除：未知应触发必要核对或有限行动，不得直接当成否，也不得使整个任务无条件停摆。

多条规则同时适用时，列出具体冲突的对象和动作。以已确认的目标与保护项决定取舍，主文维护路由与权限，专业方法维护自己的选择条件；不是笼统宣布“主文永远优先”来掩盖专业内容缺失。真源与派生描述不一致时修正派生处；两个实质要求确实互斥时才交给拥有该取舍的负责人。新增例外必须有可辨认的触发条件，不能使用“特殊情况灵活处理”留下任意出口。

跨入口检查一条完整任务：上一步的交付应满足下一步的输入；下一步不能要求上一步先证明自己实施后的效果。循环返回必须带来新证据、修正方案或明确缺项；三个入口互相转交同一个未解决问题而没有增量，就是流程失败。

## 从任务差别建立专业能力，而不是列通用维度

先写出一次真实任务中必须作出的决定，再找哪些输入差别会改变这些决定。不能把“方向、结构、材料、表达”四个栏目填满就认为能力齐全；它们只有被翻译为领域选择才有用。例如采访报道需要决定哪些话可作为事实、哪些只能作为受访者主张、矛盾信息如何处理、何时能成稿；口播开头需要决定正文能承诺什么、哪条材料先出现、何时直接给答案、何时保留问题。

对承诺范围内的每项核心决定，依次完成：

1. **找决定性差别。** 从普通输入和已知失败中找能改变动作的条件。将该条件替换、删除或改为未知，观察应采取的处理是否改变；不改变处理的题材或人物替换，不单独算新分支。
2. **明确可观察依据。** 把“有价值、充分、可信、有张力”等评价词落到当前任务所需的信息。例如核对结果是否有正文支撑、两种方案是否有不同代价、关键事实是否有可读取来源。不能用同义形容词解释形容词。
3. **选定做法及优先级。** 多个做法都可用时，按用户优先目标选择；指出保住什么、付出什么、什么新条件会使选择反转。禁止把可行办法并列后让执行者自行决定全部核心取舍。
4. **走到实际产物。** 使用该分支的正常输入，给出取材、筛选、转换或制作动作及局部成品。只有解释为什么有效而没有制作方法的，继续补方法；只有模板的，补选择条件和材料使用方式。
5. **查另一分支。** 关键条件不成立时改用什么；事实未知时取得哪项材料、先完成哪部分、哪些动作暂缓。没有影响结果的未知不阻止工作，真正缺失的方法不能被“灵活处理”掩盖。

对主要分支列出已有方法、需要补足的方法和承诺之外的任务。在当前方案里完成即可，不另建空目录或长期表单。用户要求的核心分支不能因难做而悄悄删掉；确实无法建立时说明未完成内容及影响，提出具体替代或需决定的范围变化。

### 识别缺的是知识、选择还是制作能力

| 实际表现 | 去哪里找什么 | 如何使用，得到什么才算补上 |
|---|---|---|
| 看不出材料的重要差别 | 领域分类、专业拆解和误判案例 | 把关键概念落实到输入中的证据，能区分两个原来被混为一谈的情况 |
| 看出问题但选不出办法 | 专家处理同类问题的决策、条件分支和取舍 | 给定条件能选出默认办法，条件变化能解释为何换法 |
| 理论能解释，仍不会制作 | 工艺示范、编辑前后稿、逐步制作记录、可用模板 | 沿同一材料产生完整局部结果，不能只改写理论名称 |
| 能生成，却所有版本都说好 | 同材料的候选、删改理由和完整优秀成品 | 先排除违约结果，再依据本轮效果选择，明确舍弃版本失在哪里 |
| 原案例好，换情况就失效 | 关键条件不同的成功、失败和反例 | 找出被原例隐藏的前提，保留成立部分并写出切换做法 |
| 方法明确，机械步骤常漏 | 规范、脚本、模板、参数约束 | 将可确定操作固定下来，再检查实际调用与失败返回 |

专业独到之处体现为抓住决定结果的差别、选定有依据的优先级、提供可实施技法。它可以直接来自成熟来源，不必追求新理论。通用入口负责建立和检查这些内容，领域方法归目标 Skill，不能让所有任务都套用一份媒体或商业方法。

## 带着未解决的决定读取来源

### 找到适合的资料，而不是搜一堆相关内容

先把缺口写成“在什么输入下，尚不能决定或完成什么”，再决定资料类型。需要知道为什么发生时查机制与对照记录；需要知道怎样制作时查完整操作示范；需要选优时查同材料比较与舍弃理由；需要表达风格时看完整段落、上下文与修订，不能只取“犀利、温暖、专业”等描述。

已指定成熟方法时，先读原始规则和直接依赖；材料已足够时进入采用，不从零重做。方法缺失时按当前决定检索：任务对象＋具体决定或动作＋专业叫法＋制作/案例/失败等材料类型。先从来源中的用语修正检索词，再沿直接出处和引用寻找完整做法；不要只用“如何提升质量”这类问题重复搜索。

候选来源能给方法就继续读其条件、例子和失败处理；只能重复目标就换材料类型；有执行步骤但缺前提就查上下文；只有成品没有过程时可提出自己的处理假设，但不能声称恢复了作者原方法。两个来源意见相反时，先核对它们的任务、阶段、接收者和代价；适用条件不同则保留条件分支，同条件下真正冲突才比较依据和试用结果，不拼成“都要兼顾”。

### 从完整内容提取可采用的能力

读取一个来源时，辨认它如何组织工作，而不只摘好句子：

- **它改变了问题的哪种理解？** 例如把“没有吸引力”改为“没有告诉特定接收者继续听能得到什么”。
- **它要求看什么证据？** 文本句子、用户行为、记录、实际媒介，还是尚未查证的假设。
- **它怎样排除候选？** 哪个条件使某个办法不用，避免无差别罗列。
- **它优先选择什么？** 这项偏好服务什么目标，牺牲什么，在什么条件下应切换。
- **它怎样制作结果？** 取哪些材料，怎样组织、转换和修订，哪个中间结果交给下一动作。
- **它用什么表达推动执行？** 原句的态度、节奏、例子和反问是否承担判断、强调或记忆功能。
- **它如何面对失败？** 缺材料、条件不成立、结果未达到时各自怎么处理。

这些内容在方案中形成完整方法，不要求按七项模板展示。有效原句、图表、代码和模板直接保留；来源分散时先接上必要依赖，再决定是否合并。用户要求通读指定集合时完整覆盖指定范围；长输出被截断就分段补读，不能以文件已打开声称已经通读。

### 分清来源提供了什么证据

| 看到的材料 | 可以据此采用或判断什么 | 下一动作 |
|---|---|---|
| 作者给出明确偏好和连续做法 | 可识别一套可执行方法，不自动证明效果 | 核对任务条件，匹配时选定复用并试用 |
| 有输入、处理、结果的案例 | 可以还原该例的实际做法与结果 | 比较与当前任务的关键差异，迁移成立部分 |
| 只有优秀成品 | 可以建立可观察的效果参照 | 提取可见组织特征；制作方法仍须取得或自行试验 |
| 理论解释或行业规范 | 提供机制、约束或判断依据 | 翻译成当前任务的观察和动作，检查能否产出 |
| 热度、星数、作者名气 | 提供值得查看的线索 | 读实际内容，不据此推导整套规则正确 |
| 用户已选的风格和政策 | 决定本任务的目标和取舍 | 按选择实施，不要求统计证明其偏好合理 |

资料能支持哪个范围，就在该范围采用。缺少普遍效果证明不妨碍把成熟方法作为有条件做法；缺少操作内容不能靠理论声誉补齐。候选若只换词重复目标，应补内容或舍弃；若使已有能力更稳定、减少遗漏或保留用户偏好，这也是有效增量，不要求创造模型从未知道的知识。

核心分支已有可执行方法、关键冲突已处理、主要失败有去向时，进入小样。剩余资料只影响背景介绍就停止扩读；会改变方法选择且本轮可取得的材料仍须读完。运行时文件保留内化后的方法；当前任务事实需要查证时仍可获取资料，不能把“不回读研究原文”解释为禁止事实调查。

## 选择复用方式，而不是默认重写

| 实际条件 | 选定动作 |
|---|---|
| 目标、输入和关键条件匹配 | 直接采用；有效原句、方法顺序和示范可原样保留 |
| 方法适用，仅项目名称、路径或交接不同 | 调整接口，保留专业内容与力度 |
| 只有部分分支适用 | 保留该分支及必要依赖，说明使用范围 |
| 核心条件冲突 | 指出具体冲突，改选方法；不把整份来源笼统判差 |
| 有依据但本项目效果未证实 | 选定可恢复候选，以小样检查决定性效果 |
| 只有标签或结论，关键操作缺失 | 继续取得方法，或明确形成并试验自行补足的部分 |

分别识别事实主张、用户政策、经验做法、工作优先级和表达手段。工作选择可鲜明坚定，不必包装成普遍事实；因果声明需要相称证据。保真复用的实施要求归 [规则表达与方法保留](../../laohu-evolution/references/rule-expression.md)，本文件只选定采用内容、必要适配和保护项，不要求为原创感改写。

## 形成能执行的专业做法

方案不能只列“需要研究、完善、优化”的工作。给定正常输入，执行者应知道从哪里取材、以什么条件选择、怎样变换材料、如何比较结果。关键分支缺失时先补本轮可取得的方法；普通实现由负责人选择，不把小事退给用户。

**合成教学示例：口播开头。** 输入正文：“连续三个月每天发布视频，却一直没回答评论区反复出现的问题。后来把其中一个问题做成视频，第一次收到陌生人私信，问能否帮他处理同样的事。”任务是直接、不夸张地呈现发现，不要求悬念。

可采用的方法：先标出动作变化、结果及正文提供的支撑；优先保留“持续发布却没回答问题”这一具体差别。存在相关结果时把它与动作连接，没有结果时不补造收入或客户数字。正文只支持一次经历时按一次表述。用户要直接表达就给发现；只有目标需要等待答案、且正文确能兑现时才调整为后置揭示。没有正文时先取得承诺所需材料，已有开头满足目标时保留。

成品示范：“我连着发了三个月视频，却一直没回答评论区里别人反复问的问题。后来我拿其中一个问题做了条视频，第一次有人私信问我：能不能帮他也处理一下。”它示范材料提取与承诺控制，不证明真实传播效果。删除输入中的私信结果后，输出也必须删除该结果；不能把示范记成固定答案。

示例用于教选择和制作；下游能力还须获得其专业方法，不能把本例的口播做法写入所有创作入口。对只有理论解释的方案，补生成、选择和修订动作；对只有模板的方案，补何时使用和何时换法。

## 同时修复当前失败与重复发生的条件

先为当前可见产物选定修法并制作必要小样，再问同类任务会不会仍然失败；正式修订仍交原负责人。针对实际材料检查四处，而不把“根因”当成越抽象越好的总词：

| 核对位置 | 能改变方案的观察 | 对应处理 |
|---|---|---|
| 方法是否提供 | 加载文件只有要求，没有需要的专业选择或制作方法 | 取得并补入方法，再用原任务制作结果 |
| 方法是否到达并被执行 | 正确方法已存在，但未加载、被冲突规则覆盖或步骤未落实 | 修调用、优先级或执行，不新增同义要求 |
| 方法是否适用 | 已完整执行，仍在特定条件下失效 | 比较条件差异，改选择或缩小方法适用范围 |
| 评价是否抓住目标 | 检查只看格式，成品仍缺用户要求的效果 | 恢复真实质量判据，再比较候选 |

一个现象可有多个原因。用最小区分动作核对：把正确方法明确接入后是否仍失败；保持方法而换输入条件是否改变结果；固定输入比较原方法与候选有何差别。没有真实执行时只能提出待检解释，不能把表中任意一项套成确定根因。简单错字无需展开整条链；用户明确要求治标和长期改进时，交代当前修复、重复条件和反馈检查各由谁承接。

## 用实际成品作选择

比较前确定硬约束、优先效果和保护项。先淘汰失实、换题、违背授权或丢失关键内容的结果；剩余候选按本轮效果比较，不让优点数量抵消关键失败。双方各有优势时，说明取舍并按已定优先级推荐；优先级未定且会改变产物才询问。

评价词必须落到产物。例如规则的“深度”看它是否提供影响选择的区分、因果联系或执行技法；“广度”看承诺中的主要条件变化是否有不同处理；“信息密度”看文字是否交付独立判断、动作、解释或有效示范，而非同一要求反复说。对文学、音乐等作品采用相应专业判据，不能把这套规则文档标准当万能审美。

用户指出结果不好时，先回到具体片段和原目标，不用“质量未知”回避已可观察的失败。确定哪一项材料、决定、组织或表达需要改变，制作同材料的局部修订小样，再比较所需效果与保护项；不以小样替代正式作品交付。用户不必替执行者作全部专业分析；缺少用户真实反应时，不虚构满意或不满意。

按 [验证方法](validation.md) 选择无 Skill、旧版与候选比较和关键条件变化。每轮须取得新观察、比较不同方法、调整关键选择或落实必要动作；没有变化时停止同义改写，交代真正缺口。有效方法保留到对应真源并写明适用范围；替代旧规则时合并或删除失效补丁，避免每次反馈只加不减。

## 交给实施的内容

在现有方案中给出：承诺范围与主要任务差别、选定方法及具体做法、直接采用与适配部分、完整局部示范、质量依据与保护项、真实文件落点和消费者、候选试用或已验证状态、检查输入与预期观察、失败时返回位置。已有信息直接继承，不另建字段文件。

方案须能脱离制作聊天使用；专业选择、关键分支和目标效果不能留给 evolution 发明。具体文句、章节、示范实现与接入由 evolution 完成，不要求分析者先写完每个字符。已选定但未验证的候选可以试用，不把实施决定说成普遍有效；无法满足核心任务且方法未定的，标明未完成部分，不包装为完整方案。
