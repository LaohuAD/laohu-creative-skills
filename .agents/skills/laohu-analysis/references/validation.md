# 判断、运行与下游产物验证

由 [analysis 主文](../SKILL.md) 在需要复现、比较或方案走查时读取；由 [evolution 主文](../../laohu-evolution/SKILL.md) 在改动规则、调用或交付接口后按适用范围读取。它说明不同检查能支持哪些主张；读完回各自的主文继续判断、修正或交付。创作作品的实际验证由目标执行 Skill 产出；本 Reference 不授权 analysis/evolution 自行制作试作或示范，也不代替目标项目的维护检查。

## 先说清要证明什么

开始检查前，记录本轮要改变的目标、条件、输入、保护项和可恢复位置。沿用已确认规格与行为，不因预期结果不理想而临时降低验收标准。没有行业阈值时，可以在看结果前选择本次工作判据，并说明它只是本次判断标准，不是普遍规范。

把需要回答的问题拆成与证据相称的层次：

| 层次 | 要检查什么 | 能支持什么结论 |
|---|---|---|
| STRUCTURE | Skill/Reference 是否存在，格式、路径、链接和接口是否正确 | 文件满足静态约束 |
| ROUTE | 普通请求是否进入正确入口并加载该任务所需资源 | 指定条件下路由或调用成立 |
| BEHAVIOR | 执行者是否按最终文件的方法行动，条件改变时是否切换，并形成下游结果 | 指定输入和条件下的实际行为 |
| QUALITY | 接收者在真实媒介或使用中是否得到目标效果 | 有边界的真实使用质量观察 |

按 AGENTS.md 的定义使用 PASS、OBSERVE、FAIL、UNKNOWN。检查器只说明它实际检查的结构；方案走查只说明信息可接手；执行者自评最多说明观察到行为。没有真实接收者、媒介或使用结果时，QUALITY 为 UNKNOWN；已观察到目标未达到时记 FAIL，不能用反馈缺失掩盖失败。

## 让检查覆盖真正的执行路径

文件检查从最终消费者反向追到真源：目标主文在哪里，何时读取 Reference，路径能否解析，资源解决哪项判断，读完以后回到什么步骤。文件存在或链接可点不证明读取发生。修改运行方法时，使用普通任务输入和最终实际加载的文件，观察执行者怎样选、怎样做、交出什么结果；不把本轮设计聊天、隐藏答案或评分提示提供给执行者。若结果是创作作品，必须由目标执行 Skill 依最终文件完成任务，analysis/evolution 不代写。

按疑点选样本：

| 样本 | 用途 | 结论边界 |
|---|---|---|
| 原例复现 | 在原问题和可比条件下检查候选改动是否修正该问题 | 只覆盖已运行的条件 |
| 旧行为回归 | 检查修改前已有证据确认正常的任务是否仍正常 | 新旧都通过证明保持，不证明有增益；没有改前证据就标为候选回归 |
| 留出运行 | 检查能否把方法用于未参与设计的新输入 | 样本须未参与候选设计；执行者未参加设计，也未见该样本的设计过程；对象与至少一项关键条件不同 |

“未提供制作聊天”只能减少提示，不能单独构成留出。若执行失败或观察记录不完整，先修复执行或观察再判断；不把无效运行记作规则失败，也不把它算作成功。创作作品验证的产物须来自目标执行 Skill；分析方案中的自编片段、临时试作或合成示意不能替代它。

### 组合实验方式，不堆成每项任务的流程

`A/B`说明比较哪两个版本，黑盒/白盒说明检查是否观察实现路径，盲评说明评价者看得到什么，污染检查说明哪些信息被谁接触；这些属性可组合。按要证明的问题选择，不把每天的创作变成研究实验。

| 方法 | 怎样实施 | 结论边界 |
|---|---|---|
| A/B 新旧比较 | 固定任务、模型与工具、作者约束、预算、输出范围和评价协议；不同版本用隔离会话运行，保留所有原稿与失败记录，由独立评审匿名、随机顺序比较。若只测表皮改进，锁定其余已确认决定；整体换法则只能支持全链结果差异。 | 条件未保持或预算不同须单列；成品差异不自动归因单条规则，不能只挑最高分稿。 |
| 黑盒接收 | 给目标 Skill 普通作者输入和允许材料，读取完整实际交付；不把专业步骤、评分答案或理想措辞塞进输入，不看作者自我解释替作品接受判断。 | 说明正常任务结果在哪些位置实现或没有实现目标；不单靠输出反推唯一根因。 |
| 白盒路径 | 查看最终实际加载文件、版本/哈希、资源调用、必要中间产物、修订变化和分支是否切换；只记录可观察选择，不要求隐藏思维链，不把模型自述当真实内部因果。 | 支持实际控制路径/行为的结论，不单独证明读者效果、审美质量或因果唯一性。 |
| 盲评/成对比较 | 匿名化作者、模型与版本，随机或交换顺序，给足理解作品所需的任务/原作上下文，移除制作说明；记录评审熟悉度和分歧，必要时用独立人类校准。 | 被认出的作品不称完全盲；AI模拟接收不冒称真实人类评价。 |
| 污染核查 | 检查留出原文/作品家族是否进入生成提示、检索、文件读取或规则调试；评价者是否见到作者、胜者标签和制作说明；旧对话或当前材料是否带入相冲突风格。 | 一旦 `H` 样本进入生成或被用于改规则，就降为 `D` 并换新留出；不能靠一次检索未命中证明模型从未预训练见过公开名作。 |
| 消融 | 只有需要分辨某项专业方法对结果的贡献时，在任务、预算和其他决定固定时单独移除或变更一个因素；保留原保护项和实际版本。 | 移除用户目的、材料或必要约束只说明信息缺失会改变任务，不证明对应能力层可有可无；普通任务不要求多组消融。 |

正式改造的验收可按范围抽取代表性完整任务、局部成文、方向未定、方向/前三层锁定和目标媒介样本；不同目的分开报告。样本不足以覆盖其余任务时将未运行范围记 `UNKNOWN`，不以预设样本数或成品数量冒充统计充分性。固定任务输入与资源时保留回归保护，防止新能力提高一项却损害用户已确认的立场、格式、媒介约束或旧方法。

## 使用真实人类成品做学习、校准和留出

需要从作品取法、比较候选或评估质量时，按需读取[真实作品研究方法](../../../../references/exemplar-study.md)。`L` 学习、`C` 校准、`D` 开发、`H` 留出是样本用途角色，不是作品来源。所谓“人类标尺/锚点”是来源及评价用途：原作须有可核实的人类创作依据；人类发布、使用、推荐或认可不单独证明作品由人创作，只能作为选入理由。锚点必须另外标明来自哪个集合，不能把 `H` 误写成“人类标尺”。同一作品或作品家族一旦暴露给生成者，或其结果被用于修改规则，就不能继续作为该任务的 `H`；改列 `L` 或 `D`，更换留出作品家族。详细规则只在上面的共享 Reference 维护。

正式标尺包须包含：真实作品原文或足以评估本维度的完整单元、来源身份与版本、可核实的该作品由人创作的依据、读懂该部分所需的原作上下文、选入理由、目标任务与可比条件、评价维度、作品家族及 `L/C/D/H` 状态。人类发布、采用或认可另作为选入依据记录，不替代人类创作来源证明。来源或上下文不足时，该标尺不能支持对应的正式评分；不允许评审者根据标题、记忆或制作者摘要补造原文和语境。

成品接收与比较的评价包必须给出正常完成判断所需的任务和接收语境、匿名的实际成品、必要的上下文、同条件人类标尺原文/上下文及已确定的评价维度。不附作者名、版本标签、生成过程、创作者自我解释、推理说明或“本作想表达”的提示；缺少作品理解所必需的信息时，补原作/任务上下文，不补创作者的辩护。作品应凭实际表达接受判断。评审无需、也不应依赖制作者额外解释才能给出判断。

### 何时可给等级分

日常内部候选比较优先说明具体差异，不要求数字分数。若本次确需正式评分，先选可比人类标尺、固定目标维度和锚点含义，再让评价者在与最终留出分开的 `C` 校准材料上，对照真实人类判断检查其证据和判断能力。选入理由必须有具体作品、相称条件及独立人类判断/专业依据；流行、获奖、出版或 AI 的熟悉感都不能单独授予“顶尖”身份。

本地可以采用 0—4 的有序等级来描述本次相对标尺的完成度，但这不是通用量表、等距测量或百分比；词语/意象与标尺相似、词频罕见或辞藻华丽都不自动提高完成度。每个等级必须带作品证据：本作位置、标尺对应位置、双方分别完成什么、差异为何影响本任务。`0` 表示关键作用未成立或受损；`1` 表示基本成立但仍普通/薄弱；`2` 表示有明确长处且仍有重要差距；`3` 表示该条件和维度上与选定顶尖人类标尺可比；`4` 表示该条件和维度上有证据支持强于标尺；`未评`表示材料不足、不适用或不可比，不能当零分或以平均值补齐。若目标用户明确要求试评，而正式的人类校准尚未完成，仍可依这套锚点提供有证据的暂定等级；必须将评分状态标为 `OBSERVE`/未校准，不称最终质量成绩，不宣称“达到顶尖”。经过 `C` 校准的评审者方可给出正式的任务内等级结论；其范围仍受样本、维度和实际接收条件限制。

先单独检查不可被其他长处抵消的约束：任务范围、作者立场和锁定内容、事实与归属、原创边界、必要格式及真实媒介。失败时明确记录失败，不让优美、押韵、数据或其他分项高分抵消。分项不默认取平均；只有在任务需要汇总、权重和不可补偿项已事先明确时才汇总，并同时保留分项与分歧。还可在同一任务条件下随机顺序并列两件匿名作品，记录甲胜、乙胜、相当、两者均未完成或不可比；先给文本/媒介位置证据，再给选择。分数与成对判断冲突时保留冲突并复核。

模型或 AI 评审员只有在其判断依据通过独立人类校准后，才可参与正式评分；换角色名称、增加模型数或评分提示都不是校准。没有真实人类校准时，可以让 AI 指出成品与标尺的可见差异，帮助定位修订，但成绩标为 `OBSERVE`，不得证明顶尖水平。盲评移除制作解释，是为了防止解释替作品说服评审；不是以信息不足迫使评审猜测。作品的实际语境仍须完整提供。

每次正式评分记录评测包版本/哈希、任务与评价范围、真实成品版本/哈希、标尺原文版本和作品家族、标尺身份及入选依据、资料角色、评价维度与等级、评审者是否经过 `C` 校准、顺序/匿名安排、逐项证据、分歧、保护项结果及未知条件。无需记录或要求制作解释。

按疑点选一种或多种验证，不固定测试次数。比较版本时保持任务、权限和判据一致，并记录无法保持的差异。在用户普通创作请求的已授权范围内，若存在会影响目标效果的未决变量，且比较可能改变选择，可先内部试写足以判断的候选，再从实际成品中比较、筛选并定向修订；无需为不展示的草稿另行确认。不要求每项任务都生成候选，也不设统一数量；不要求落笔前已能预知候选必然有差异。候选完成后若没有实质差别，合并或保留更简洁的版本，不凑数。按本轮要判断的层次保持其他决定不变，比较实际成品而不只比较设计说明。裁决后还须将选择落实到作品并复查；候选自评不能代替接收检查。额外交付多稿、触及用户锁定内容、超出本轮范围或产生额外成本与外部动作时，按运行约定核对相应边界。目标执行 Skill 的输出明显波动且本轮需要判断稳定性时，在合理预算内重复可比运行并保留失败结果；不能只挑最佳输出。普通任务不必生成固定数量的候选或强制运行外部受众实验。

对规则和调用链，选一项会真实切换处理的条件核对：条件不变、只改说法时，核心选择应相同；改变关键目标或事实时，方法和产物应转向对应分支；隐藏会改变选择的信息时，只暂停依赖该信息的部分；用户纠正时更新受影响判断并保留其他有效内容。失败时保留触发输入，将修改落到实际控制位置，再重跑相关样本。

### 记录运行中的额外指导

检查最终文件能否独立带来目标行为时，执行者只接收最终实际会读取的文件和普通任务输入；不得把设计讨论、评分提示或聊天中临时补充的专业取舍当成文件能力。若运行中确有额外指导，记录其原意及它是否补出了核心目标、材料选择、关系组织、操作步骤、分支或验收。额外指导若改变其中任一项，该次运行只证明“在该指导下”的表现，不能支持最终文件独立成功的结论；尚未经过无指导运行验证的部分记 `UNKNOWN`。若已观察到文件方法缺口或无指导运行失败，仍记 `FAIL`；后续有指导运行的改善不能撤销该失败。如果指导暴露出已确认的方法缺口，按职责交回 analysis 决定规则，再写回唯一真源并用不含该指导的普通输入复跑。若提示仅纠正拼写等不影响目标方法的偶发操作，说明影响范围，可保留其余有效观察，但不可隐去提示。

## 单独检查完整能力设计

完整能力设计需要走完“普通输入 → 需要的模块和知识 → 专业选择 → 中间产物 → 下游使用 → 接收者结果”。用一项代表任务做方案走查，推演应有的决定与交付关系，找出未交付的判断、断开的依赖、重复规则和未检查的保护项；再改变会切换方法的条件，确认是否能换法或退出。创作作品可在走查中检查生成要求、媒介关系和验收条件，但 analysis/evolution 不写出作品试作或示范。方法有名称或存在规则段落不等于设计完整；核对它是否准确适用、覆盖会改变选择的条件、说明必要操作，并由正常任务实际加载、交给正确的下游执行者。对文字创作，成品需要真实词句段，不可只以提纲、审美解释或验收词代替表皮实现。若目标包含已确认的作者表达意图，分别核对最终成品是否实现该意图、事实断言是否有相称支持；前者通过不能替后者作证，事实边界通过也不证明表达忠实。需要跨形式检查实际表现时，经授权由目标执行 Skill 依最终文件产出；不同材料应能生成不同形式而仍守住已定目标。形式相似不证明原理成立，形式不同也不自动判错。

元入口如 analysis 或 evolution 的实际能力建设须分两段：

1. 先用最终交付的 analysis/evolution 处理普通需求，真实建立或整体改进一个职责明确的目标能力；检查得到的文件与调用是否完整，目标能力是否能从最终文件执行。
2. 再由另一位未参与目标能力设计、未见该新样本设计过程的执行者，仅凭目标执行 Skill 的最终文件和新的普通输入，实际执行该 Skill、完成下游任务并产出结果。作品结果须由目标 Skill 依其文件完成，不能由元入口代写。

第一段证明元入口能把设计落成文件；第二段检查这些文件是否让新执行者做出目标行为。不得用同一执行者参与样本设计后的运行、只读方案、结构检查或修改者自评冒充第二段。

## 判断结果并返回修正

每项检查结束后，说明实际输入、观察到的执行路径、结果和未覆盖条件。原因支持程度与目标效果分开写；不以多因素同时变化的结果归功于某一条规则。

- 目标方法没有加载：修正触发条件、路径或调用顺序后重跑。
- 方法已加载但执行不完整：查明遗漏发生位置，补接消费者或纠正冲突，再检查实际结果。
- 方法完整执行但目标未出现：记录具体产物与条件，判 FAIL，返回 analysis 重看方法与适用条件。
- 保护项受损：回到方案中的取舍，修复后同时重查目标与保护项。
- 局部指标变好、整体目标变差：检查指标是否代表目标或漏了相互作用，不以平均分掩盖失败。
- 执行或观察无效：先修复路径并重跑，不提前推翻或确认原因。
- 只有实际接收者或使用证据尚缺：只将对应质量主张标 UNKNOWN，交付已有结构与行为证据。

完成检查后回到调用它的主文，报告哪些结论有证据、哪些仍未知、要改哪个控制位置。验证只覆盖明确运行过的路径；不要把有限样本说成普遍效果。
