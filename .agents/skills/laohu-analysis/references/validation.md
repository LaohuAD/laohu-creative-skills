# 必要试验与判断验证

当现有材料不足以区分会改变本轮处理的解释或方案，需要复现、对照或小样时读取。本文件只指导支持当前卡点的必要试验及其结果解释；正式作品制作、生产修复和长期规则写回由原负责人或适用能力负责。若待解决的问题边界仍不清，可以先读取对象、比较实例或做低成本且可恢复的探索，以形成可检查的问题表述；探索不能冒充原因定论。设计走查、模拟、试验执行和真实使用反馈分别说明。

## 在行动前固定比较方式

利用主入口已有任务状态，只补本次动作所需内容：原始表现、将改变什么、预测、观察方法、通过条件、保护项和可恢复位置。已有用户要求、适用规格或现有基线时沿用其阈值。若任务没有规定数值门槛，负责人可在观察结果前选择适合目标的工作阈值，并标为本次操作标准，不声称它是行业标准或客观事实；不得看过结果后才补一个刚好通过的门槛。新信息确实改变目标时记录原因，再更新测试。

改动前保存本轮涉及的实际内容，包括未提交材料；只读任务不额外备份无关资产。遵守现有作品路径和项目授权，实验副本不得悄悄替代用户主文件。

先做能够回答疑点的最小试验。需要因果区分时控制无关变化，存在交互作用时比较组合；检查实际执行环境、输入和观察方式是否可比。工具调用失败、目标未加载或记录残缺时，先解决测量与执行问题，不从无效试验推断方案失败。

## 按结果类型选择验证

| 结果类型 | 验证方法 | 结论范围 |
|---|---|---|
| 确定性规则、程序或数据操作 | 原始失败输入、正常输入、关键边界；检查实际输出与错误处理 | 说明通过了哪些输入与环境 |
| AI 选择、表达或工作过程 | 相同事实换说法、改变决定性事实、任务中途补充信息；保留输出与工具动作 | 观察判断的一致性及是否随证据更新，不要求逐字一致 |
| 作品的理解、情绪与使用效果 | 按目标接收者和真实媒介比较原版与候选；保留原有风格保护项 | 作者自查与接收者反馈分开，不以字数或自评分代替效果 |
| 架构、流程或方案的关键未知 | 沿代表任务检查输入输出、依赖和异常反馈；仅在能改变选择且可恢复时做原型或必要小样 | 走查只说明接口是否完整；小样只支持已测试的选择，正式运行由负责方验收 |

按本轮要回答的问题区分三类样本：

- **示例复现**：重跑原始失败对象及其关键条件，或运行 Skill/Reference 中已展示的教学例子及仅替换名词的近似任务，确认该失败或目标行为是否出现、改动是否影响该例。正式创作范例的来源按[规则表达与方法保留](../../laohu-evolution/references/rule-expression.md)执行；隔离评测中按任务生成的合成作品可作为本轮临时产物检查，但不能因此成为正式专业范例。这些样本都只能说明暴露过的具体例子；原始失败复现也不证明换对象或条件后仍成立，更不能作为留出验证。
- **旧行为回归**：检查改动前已确认正常的任务，比较旧版与新版是否都保留原有行为。两版都通过只说明兼容/保持，不能证明能力提升；没有真实历史通过记录时，把样本标成预期行为或候选回归样本，不冒称历史基线。
- **留出验证**：检查未参与候选设计的样本，且对象与至少一项关键条件不同，用来判断机制能否迁移。未向执行者提供制作聊天或评分预期有助减少提示，但本身不构成留出；执行者须未参与候选设计，也未见过该样本的设计过程。无法确认隔离时如实标为非独立验证。

AI 或生成结果有波动时，只有需要估计稳定性或结果确实波动时才在合理预算内重复可比任务，保留失败结果，不固定试跑次数或只展示最好输出。需要比较版本时保持任务、工具权限和评价标准一致；无法保持的差异记录下来。根据问题选复现、回归或留出，不把其中一种样本的证据说成另一种。

## 规则信息与逻辑稳定性怎么检查

规则改写先检查信息是否保留，再试运行，二者不能相互替代。将已定内容中的对象、触发、判据、动作、顺序、例外、要求强度和交付分别对应到最终文件；检查实际功能，不按关键词计分。许可改成强制、缺失改成否定、暂停一段改成停止全部，即使原词还在也属于信息改变。逐项缺口修复后再运行相关分支。

选择一项真实决定做成组输入：

- **只换说法**：事实、目标、授权完全相同，只换表达或材料顺序。实质处理应一致，允许措辞不同。
- **只换关键条件**：保持其他内容，改变会决定方法的那项条件。观察是否在正确位置换法，以及后续产物是否随之改变。
- **隐藏关键事实**：将该事实删去，检查是否取得必要材料、交付可完成部分，并准确暂停受影响动作；不能默认否定或编造。
- **中途纠正**：提供推翻原选择的新事实，检查是否更新受影响决定、撤回失效内容并保留无关的有效工作。

边界变更另用一个近邻需求检查 description 与主文实际处理是否一致，再从主文走到 Reference 检查同一条件是否存在相反动作。只做文本搜索不能证明语义一致；重复相同顺利输入也不能证明分支稳定。失败时保留触发失败的输入，定位到实际规则或执行步骤后修订并重跑。

检查深度时，选最决定结果的一项判断，实际完成从材料到选择再到产物的全过程；仍需执行者凭空补出核心方法就是缺口。检查广度时，选承诺范围内会改变方法的主要条件，不以多题材同一路径冒充覆盖。检查表达时比较完整片段是否保留事实、信息、力度及自然语感，不以格式整齐、术语数量或篇幅作替代。

仅当本次变更涉及来源分类、新材料修订或分层资源加载时，才增加相应检查：

| 本次变更 | 定向检查 |
|---|---|
| 目标用户默认或预设 | 用目标群体的代表任务检查候选是否服务该群体的共同任务；无试用证据时只报告候选行为，不宣称群体普遍偏好。若本次不改个人偏好边界，不额外构造个人偏好样本。 |
| 情境分支或个人偏好 | 改变会切换处理的条件，或核对已明确的个人偏好是否只在该用户范围生效；只检查本次实际修改的分支，不要求每项能力都覆盖所有范围类别。 |
| 新材料改变了归类 | 对照旧判断与新材料，确认只更新受影响的判据、默认、分支及消费者；仍有冲突时保留未知，不靠改标签掩盖。 |
| 二级知识或三级选项的调用 | 选一项真实任务依赖发生变化，检查入口是否读取了必要内容、未把无关资源强制加载，并按领域方法选用或组合适当选项；不测试或要求固定的文件数与选项数。 |

输入没有证据支撑某一分类时，按未知处理，不把缺证据当成否定，也不把候选冒充已验证默认。

### 检查专业关系、可变形式与指标是否有效

需要验证长期方法或创作规则时，除条目是否存在，还要检查被保留的控制关系是否仍能支配选择。按 analysis 的 [四层能力设计](capability-design.md) 中本任务适用的原理、内部组织、材料/技法与可感知表现，选一项关键关系沿真实材料走到成品；四层是专业检查坐标，不能用调用顺序、文件交接或参与者分工替代作品内部关系，也不强制每项任务逐层造出规则。

使用一项核心原则配至少两种材料条件不同的输入，检查是否能选出形式不同而仍满足同一目标、组织关系和保护项的产物。然后改变使原则适用的关键条件，检查是否退出或换法；不能因为第一例成功就把例子里的意象、句式或技法固化为唯一配方。方法关系成立而表现形式不同，应允许通过；表面形式相似但关系没有承载目标，应判未通过。

若验收使用数字或量化指标，验证它与目标效果的代表关系，而非只检查数字是否改善。指标变好、整体目标变差时，记录为评价失效或目标权衡问题，不能判整体通过。若各局部检查均通过而接收者仍未获得主要效果，也要检查局部判据是否遗漏相互作用或整体结构；局部通过不能简单相加成总体通过。缺真实接收者反馈时可以报告结构与可观察行为，但整体质量仍是 `UNKNOWN`；代表材料已显示预期目标未出现时则是 `FAIL`。

## 方案交接走查

### 能力建设须走到下游产物

创建或实质改进专业 Skill 时，先固定普通输入、目标结果、必须成立的条件和风格保护项。用该 Skill 实际处理任务并交付作品、规则或动作；只写“应该生成什么”、只检查新文件或自述流程完整，不能证明方法已产生目标行为。当前任务已授权的试验可以用局部完整产物，未经授权的付费媒体等保留为明确缺口。

需要判断能力增量时，按问题选择无目标 Skill、旧版、候选的比较。保持模型、输入、工具权限与评价标准可比；先保留实际版本，再运行，不能在文件并发变动时把读取当前文件称作旧版基线。新旧都好只证明保持，不能虚构旧版缺陷；增量可以是更准确的选择、稳定性、表达保持或减少操作。规则变化大但收益未知时如实说明。

检查元入口时安排完整任务：从普通需求建立或改进一个范围明确的能力，再让未参与设计的执行者用交付文件处理新输入，检查实际产物。创建与改进是不同任务，不用成功迁移已有规则证明能从零建立方法。评分者依据目标和实际输出评价，执行者不读取预期答案。按上文区分示例、回归和留出，不让同一执行者看过全部训练示范后冒称隔离。

表达效果用同材料完整成品比较：指出哪处选择产生了何种可观察差别，并检查事实、信息、要求强度和原风格是否保留。接收者真实反馈未知时记质量未知；已经观察到目标失败必须记失败。对关键条件改变后的样本检查方法是否切换，不只检查“是”的顺利路径；未知材料不能强算成“否”。

每轮保留有用观察，修正相应控制点；没有新证据或不同动作时停止同义改写。对重复有效的经验保留适用条件，写回唯一消费者；替代方法同时合并过时补丁。只有具有长期回归或维护价值的输入、方法与结果才持久化，不强制创建每次运行的日志和评分文件。

用户要解决问题、改变现状或交给他人实施时，在交付前沿一个代表任务走查方案；即使无需实际试验也要做这项走查。逐项核对：

- **动作**：执行者知道要改的对象与具体动作。
- **条件与动作关系**：触发／适用条件、必要输入与动作的先后依赖清楚；区分必须先后、确实可独立并行、按条件触发的分支和可选动作，不能仅凭编号或项目符号推断关系。
- **保护与验收**：保护项、交付物和可观察验收明确。

根因仍未知可以作为明确分支保留；要写清区分证据及各自动作，执行者不能被迫自行猜因。若执行者仍需重判目标范围或核心改动内容，或自行补出因果才能选择动作，回主入口第 4 步补方案；不得把泛化方向或待决定事项包装成可执行方案。走查能发现接口缺陷，不能冒充实际运行。

按方案对象继续走查：

| 方案对象 | 还要核对 |
|---|---|
| 项目规则 | 真实文件与控制章节、读者／消费者、增改删范围及可直接采用的规则文字；规则文字须保留准确的条件和要求强度，验收要能观察旧问题是否受控且保护项仍在。 |
| 作品或工具 | 输入如何到达对应专业能力、预期返回什么以及如何按目标验收；不扩写成项目级规则。 |

方案走查只证明交接信息完整，不证明文件已改、作品已完成或真实效果改善。

对表达或体验目标，走查方案时分别检查“目标效果”和“保护项”：用已给材料生成一段完整局部试作，判断它是否让指定接收者感到预期的语气、立场或情绪；另查事实、对象、内容和授权边界是否仍完整。二者分别记录为通过或未通过，不能让边界安全替代效果达成。若方案供可复用能力实施，分析阶段用普通任务输入、独立完整的交接方案和局部试作检查能否脱离制作聊天运行；这一试作是本轮检查产物，不自动成为 Skill/Reference 的正式作品范例，范例来源统一按[规则表达与方法保留](../../laohu-evolution/references/rule-expression.md)处理。把运行必需的目标、方法、标准写全，不能用“按上文”依赖创作者对话。此走查不是留出验证；实施后的正式文件运行测试、旧行为回归或留出验证由 evolution 按变更目标选择。这里的方案走查不等同于真实接收者效果验证。

如果一个未决事实会改变核心动作，先读取本轮可取得且已授权的材料或执行必要区分动作；无法取得时，写清它阻断哪项选择、不同观察对应的动作，并标注暂定部分。仅属一般措辞、可恢复实现或不改变主要路径的未知，由负责人选定可检验的工作做法并继续；不要把这些实现取舍升级成阻断，也不要把工作阈值说成普遍标准。

## 分别记录解释与效果

记录实际动作、观察及它改变的判断：

- 证据是否支持原因或设计假设；
- 方案是否在本次情境产生预期变化；
- 哪些适用条件被检查，哪些仍未检查。

绕开故障获得成功可以证明临时办法有效，不能证明原故障机制已消失。对象在验证期间变更时标明版本，重新检查受到影响的结论。执行者改变措辞、角色或自评标准，不构成独立验证。

返回位置按主入口第 5 步执行，不在这里另维护一套失败分类。调整后重新检查受到影响的结果和保护项，保留无关部分已取得的证据。

## 结束与交接

用户只求解释时，以足以厘清当前卡点的结论和可核查依据为完成，不强塞解决计划。用户要解决问题、改变现状或交接实施时，先用代表任务走查动作与接口是否清楚；这不要求根因完全确定。证据不足时区分哪些是事实未知、哪些只是工作方法待选：事实未知若会改变主要路径才继续核对或给条件分支；常规实现由负责人选可检验的做法。竞争解释可以保留为假设并给区分预测；成熟经验可支撑标明条件的建议，但不得写成已证实的因果结论。缺少工具、关键材料或接收者反馈时，标清方案尚未完整/验证，不能声称现实问题已解决。正式修改、生产验收或真实接收者反馈仍由原负责人或适用能力完成。

达到本轮目标后结束；若继续工作需要新事实、关键用户决定或新增权限，暂停相应动作，说明需要什么及取得后会作哪项判断。不得用无限追问更深原因代替可执行检查。

长期沉淀的交接同时包含有效方法、适用条件、原失败与保护样本、已执行结果和未知。一次试验成功不自动支持通用规则；是否长期写回由用户授权与进化入口判断。
