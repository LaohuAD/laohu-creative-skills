# 验证、走查与行为检查指南

由 [laohu-analysis 主文](../SKILL.md) 在复现问题、方案走查或设计验收测试时读取，也承接其他 Skill 对共享验证口径的引用。

**唯一顶层真源**：全仓统一的**四类证据维度（`STRUCTURE` / `ROUTE` / `BEHAVIOR` / `QUALITY`）× 四种状态（`PASS` / `OBSERVE` / `FAIL` / `UNKNOWN`）、隔离 A/B 盲测协议，以及正式评测集的 `L/C/D/H` 防污染规则**，全部维护在 [评估与验证协议](../../../../docs/governance/evaluation-protocol.md)。本文件不重复拷贝顶层条文，仅补充分析、方案走查与能力验收的实操要点。

## 1. 按疑点选最小有效验证（不把日常迭代变官僚实验）

先写清本轮**要证明什么主张**，再只选足以回答该疑点的最小组合：

| 验证动作 | 解决什么疑点 | 结论边界 |
|---|---|---|
| **静态与走查检查** | 文件结构、链接、配置是否合规；设计链路是否存在明显断层 | 只证明 `STRUCTURE` 或设计可接手，绝不冒充行为/质量通过 |
| **原例复现 + 旧行为回归** | 原问题在可比条件下是否消失？原本好用的能力与保护项有没有被改坏？ | 仅覆盖已运行条件；无改前基线时标为候选回归 |
| **干净窗口隔离 A/B 盲测** | 相比纯原生模型（A）或旧版 Skill（B），优化新版（C）是否既不受多余束缚又产生真实净增益？ | 遵循 `evaluation-protocol.md` §2：同题、同模型、独立隔离窗口、匿名盲评；AI 盲评记 `QUALITY: OBSERVE`，真实人工/媒介验收记 `QUALITY: PASS/FAIL` |

## 2. 检验规则与执行链的 4 个核心探针

用普通用户口语和最终实际加载的文件跑一遍，重点观察 4 件事：

1. **说法变、条件不变**：换更口语或更省略的说法，核心路由与判断保持一致。
2. **关键条件变**：改变目标、体裁、事实或权限，执行者能及时切换分支或退回确认，不死套默认模板。
3. **缺关键决定时的局部暂停**：隐藏会实质改变主要产物或权限的一项决定，确认只暂停依赖部分并问最小问题，不瞎猜也不全盘停摆。
4. **防泄漏与额外指导红线**：派发评测用例时，只传普通任务输入与允许材料（`write` 型夹具建在 `.cache/tmp/` 等同盘隔离目录，不碰真实资产），严禁传入 `expected_behavior`、评分标准、设计聊天或理想答案。若运行中途临时给了改变核心方法的额外指导，该次只记为有指导表现，不能算文件独立成功。

> **报告内局部对照的边界**：`audit` / `analysis` 在报告中基于用户真实材料给出的最小改后对照，仅用于佐证差距与修法；它不等于独立成品，不能替代目标执行 Skill 的独立运行验证。

## 3. 元能力（`audit` / `analysis` / `evolution`）的双阶段验收

验证本次改动是否真正提升了三技能本身时，区分两段证据：

- **第一阶段（元能力实操）**：给最终版元能力一个普通真实请求与问题材料，检查它能否独立完成诊断、定因、方案或规则写回（输入里已写好完整答案的只能验证忠实实施，不能证明独立发现与设计能力）。
- **第二阶段（下游独立实跑）**：若元能力产出了新/改后的目标 Skill，由**未参与设计的独立执行者**仅凭最终目标文件 + 新普通输入实跑，检验下游产出是否真正变好。第一阶段通过不自动代表第二阶段通过。

## 4. 根据观察定位下一步修正

| 实际观察 | 下一步动作 |
|---|---|
| 目标规则未命中或未加载 | 修正 `description` 触发条件、路径引用或加载信号后重跑 |
| 已加载但执行跳步或打架 | 查是否被文字墙埋没、或与另一条款冲突，先做减法清障再复测 |
| 完整执行但成品仍平庸/不如纯原生 A | 记 `FAIL`！回到 `analysis` 检查是否过度约束，或核心方法抓手选错 |
| 保护项或硬接口受损 | 立即回查取舍与硬契约，修复后同步复查目标效果与保护项 |
| 仅缺真实受众/人工最终体验证据 | 诚实将对应 `QUALITY` 标 `UNKNOWN` 或 `OBSERVE`，交付已有结构与行为证据 |
