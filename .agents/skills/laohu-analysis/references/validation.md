# 判断、运行与下游产物验证

由 [analysis 主文](../SKILL.md) 在需要复现、比较或方案走查时读取；由 [evolution 主文](../../laohu-evolution/SKILL.md) 在改动规则、调用或交付接口后按适用范围读取。它说明不同检查能支持哪些主张；读完回各自的主文继续判断、修正或交付。创作作品的实际验证由目标执行 Skill 产出；本 Reference 不授权 analysis/evolution 自行制作试作或示范，也不代替目标项目的维护检查。

## 先说清要证明什么

开始检查前，记录本轮要改变的目标、条件、输入、保护项和可恢复位置。沿用已确认规格与行为，不因预期结果不理想而临时降低验收标准。没有行业阈值时，可以在看结果前选择本次工作判据，并说明它只是本次判断标准，不是普遍规范。

把需要回答的问题拆成与证据相称的层次：

| 层次 | 要检查什么 | 能支持什么结论 |
|---|---|---|
| STRUCTURE | Skill/Reference 是否存在，格式、路径、链接和接口是否正确 | 文件满足静态约束 |
| ROUTE | 普通请求是否进入正确入口并加载该任务所需资源 | 指定条件下路由或调用成立 |
| BEHAVIOR | 执行者是否按最终文件的方法行动，条件改变时是否切换，并形成下游结果 | 指定输入和条件下的实际行为 |
| QUALITY | 接收者在真实媒介或使用中是否得到目标效果 | 有边界的真实使用质量观察 |

按 AGENTS.md 的定义使用 PASS、OBSERVE、FAIL、UNKNOWN。检查器只说明它实际检查的结构；方案走查只说明信息可接手；执行者自评最多说明观察到行为。没有真实接收者、媒介或使用结果时，QUALITY 为 UNKNOWN；已观察到目标未达到时记 FAIL，不能用反馈缺失掩盖失败。

## 让检查覆盖真正的执行路径

文件检查从最终消费者反向追到真源：目标主文在哪里，何时读取 Reference，路径能否解析，资源解决哪项判断，读完以后回到什么步骤。文件存在或链接可点不证明读取发生。修改运行方法时，使用普通任务输入和最终实际加载的文件，观察执行者怎样选、怎样做、交出什么结果；不把本轮设计聊天、隐藏答案或评分提示提供给执行者。若结果是创作作品，必须由目标执行 Skill 依最终文件完成任务，analysis/evolution 不代写。

按疑点选样本：

| 样本 | 用途 | 结论边界 |
|---|---|---|
| 原例复现 | 在原问题和可比条件下检查候选改动是否修正该问题 | 只覆盖已运行的条件 |
| 旧行为回归 | 检查修改前已有证据确认正常的任务是否仍正常 | 新旧都通过证明保持，不证明有增益；没有改前证据就标为候选回归 |
| 留出运行 | 检查能否把方法用于未参与设计的新输入 | 样本须未参与候选设计；执行者未参加设计，也未见该样本的设计过程；对象与至少一项关键条件不同 |

“未提供制作聊天”只能减少提示，不能单独构成留出。若执行失败或观察记录不完整，先修复执行或观察再判断；不把无效运行记作规则失败，也不把它算作成功。创作作品验证的产物须来自目标执行 Skill；分析方案中的自编片段、临时试作或合成示意不能替代它。

按疑点选一种或多种验证，不固定测试次数。比较版本时保持任务、权限和判据一致，并记录无法保持的差异。目标执行 Skill 的输出明显波动且本轮需要判断稳定性时，在合理预算内重复可比运行并保留失败结果；不能只挑最佳输出。

对规则和调用链，选一项会真实切换处理的条件核对：条件不变、只改说法时，核心选择应相同；改变关键目标或事实时，方法和产物应转向对应分支；隐藏会改变选择的信息时，只暂停依赖该信息的部分；用户纠正时更新受影响判断并保留其他有效内容。失败时保留触发输入，将修改落到实际控制位置，再重跑相关样本。

### 记录运行中的额外指导

检查最终文件能否独立带来目标行为时，执行者只接收最终实际会读取的文件和普通任务输入；不得把设计讨论、评分提示或聊天中临时补充的专业取舍当成文件能力。若运行中确有额外指导，记录其原意及它是否补出了核心目标、材料选择、关系组织、操作步骤、分支或验收。额外指导若改变其中任一项，该次运行只证明“在该指导下”的表现，不能支持最终文件独立成功的结论；尚未经过无指导运行验证的部分记 `UNKNOWN`。若已观察到文件方法缺口或无指导运行失败，仍记 `FAIL`；后续有指导运行的改善不能撤销该失败。如果指导暴露出已确认的方法缺口，按职责交回 analysis 决定规则，再写回唯一真源并用不含该指导的普通输入复跑。若提示仅纠正拼写等不影响目标方法的偶发操作，说明影响范围，可保留其余有效观察，但不可隐去提示。

## 单独检查完整能力设计

完整能力设计需要走完“普通输入 → 需要的模块和知识 → 专业选择 → 中间产物 → 下游使用 → 接收者结果”。用一项代表任务做方案走查，推演应有的决定与交付关系，找出未交付的判断、断开的依赖、重复规则和未检查的保护项；再改变会切换方法的条件，确认是否能换法或退出。创作作品可在走查中检查生成要求、媒介关系和验收条件，但 analysis/evolution 不写出作品试作或示范。若目标包含已确认的作者表达意图，分别核对最终成品是否实现该意图、事实断言是否有相称支持；前者通过不能替后者作证，事实边界通过也不证明表达忠实。需要跨形式检查实际表现时，经授权由目标执行 Skill 依最终文件产出；不同材料应能生成不同形式而仍守住已定目标。形式相似不证明原理成立，形式不同也不自动判错。

元入口如 analysis 或 evolution 的实际能力建设须分两段：

1. 先用最终交付的 analysis/evolution 处理普通需求，真实建立或整体改进一个职责明确的目标能力；检查得到的文件与调用是否完整，目标能力是否能从最终文件执行。
2. 再由另一位未参与目标能力设计、未见该新样本设计过程的执行者，仅凭目标执行 Skill 的最终文件和新的普通输入，实际执行该 Skill、完成下游任务并产出结果。作品结果须由目标 Skill 依其文件完成，不能由元入口代写。

第一段证明元入口能把设计落成文件；第二段检查这些文件是否让新执行者做出目标行为。不得用同一执行者参与样本设计后的运行、只读方案、结构检查或修改者自评冒充第二段。

## 判断结果并返回修正

每项检查结束后，说明实际输入、观察到的执行路径、结果和未覆盖条件。原因支持程度与目标效果分开写；不以多因素同时变化的结果归功于某一条规则。

- 目标方法没有加载：修正触发条件、路径或调用顺序后重跑。
- 方法已加载但执行不完整：查明遗漏发生位置，补接消费者或纠正冲突，再检查实际结果。
- 方法完整执行但目标未出现：记录具体产物与条件，判 FAIL，返回 analysis 重看方法与适用条件。
- 保护项受损：回到方案中的取舍，修复后同时重查目标与保护项。
- 局部指标变好、整体目标变差：检查指标是否代表目标或漏了相互作用，不以平均分掩盖失败。
- 执行或观察无效：先修复路径并重跑，不提前推翻或确认原因。
- 只有实际接收者或使用证据尚缺：只将对应质量主张标 UNKNOWN，交付已有结构与行为证据。

完成检查后回到调用它的主文，报告哪些结论有证据、哪些仍未知、要改哪个控制位置。验证只覆盖明确运行过的路径；不要把有限样本说成普遍效果。
