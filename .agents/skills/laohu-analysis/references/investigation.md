# 调查取证、解释与方案比较

解释、调查、宽泛质量反馈或方案比较时，由 [analysis 主文](../SKILL.md)按任务读相关小节，把观察、解释与方案返回主文。新建、扩大或整体重构能力时，以[完整能力设计](capability-design.md)为主；查历史执行缺口只读取[断点归因](#区分方法缺失与执行断点)，把归因带回完整设计第二步。

本 Reference 深入处理调查取证、解释检验、方法缺失与执行断点、方案比较，以及怎样把效果要求转成媒介内动作。万能造梦框架的实际应用方法由 [analysis 主文](../SKILL.md)承担；这里不另列一套通用维度总述。按当前缺口选择下列细则，再回主文综合成用户所需的解释或方案。

## 先找到会改变处理的判断

沿用已确认目标、用户决定和任务状态，指出当前对象、观察到的差距，以及下一步最需要弄清的问题。没有可观察的表现时，说明能取得哪项材料；不让用户重述已知目标，也不要求他先替执行者选改法。

有具体例子、稿件片段、画面或运行结果时，从这个可定位的对象进入机制调查：看哪些材料被选中、关系怎样建立、信息或动作怎样排列、哪项判断因此改变，以及这怎样传到成品。不要把“有某个技法/标签”当成机制；也不从单个例子推成普遍规律。全域能力设计没有现成例子时，沿范围内普通任务和可读取成品检查；不为分析流程另造作品样例。

用户提供示范、前后改稿或指定处理方式时，先拆清原处理、示范希望完成的作用、它改变了哪项材料关系/决定，以及哪些事实、力度或范围要保护；不要把示范的措辞当成必须复刻的答案。再把这些决定放回同一作品、任务或对象中相近的有效与失效位置，检查输入条件是否可比、哪些差异跟着处理改变。没有可比位置时不据此断定普遍根因；因材料或历史记录缺失而无法区分的部分保留为未知。

扩展或重构时，把有据候选机制带入[完整能力设计的专业取法](capability-design.md#先对齐方法解决什么再决定保留或改动)。回到本节区分观察、解释和可迁移决定。若有同一作品、任务或对象内可比的有效与失效位置，固定目标和条件比较；单个成功、共现或作者名望不证明因果。缺一侧样本只限边界和效果结论，仍可有据建设。

从接收者看到的结果向前追：相关输入是什么，谁在何时读到或做了什么决定，经过哪些变换和依赖，怎样到达当前输出。对照正常结果、明确要求或适用专业判据；没有可比样本时，把预期标成待检验目标，不写成已观察事实。只沿会影响解释或动作的环节继续，不为画完整流程而扩范围。

用户用“审美不够”“节奏乱”“没有感染力”等宽泛说法时，先把它落到可检查的位置，再接上适用判据和后续动作：

| 判断环节 | 需要说清的事 |
|---|---|
| 目标与接收者 | 这项内容要让谁理解、感受或完成什么？ |
| 具体表现 | 哪句话、画面、声画时刻、步骤或交互出现了什么？ |
| 判据 | 为什么它影响当前目标；何种条件下该表现仍可成立？ |
| 可能原因 | 哪些已观察的输入、决定、执行或反馈可能造成它？ |
| 区分办法 | 哪个最小读取、比较或试验会让不同解释产生不同观察？ |
| 控制位置 | 证据指向改哪项规则、选择、材料、参数、工序或成品？ |
| 验收 | 要改善什么，哪些事实、偏好和风格必须保留？ |

有依据的部分直接沿用，不为填满表格重复分析。把明确规格未满足、相对已定目标的损失、尚无共同判据的偏好差异和现有材料不足以判断的未知分开。说“可以提升”时，至少指出当前表现、适用判据、目标损失和可改变的位置。

判据按对象使用，不把审美压成一张通用打分表：

- **规格**（尺寸、时长、字段、明确比例或包含项）可按定义检查数值或通过/未通过；必须说明测的对象、单位、分母与观察条件。
- **内部关系**（视觉主次、叙事铺垫与结果、人物行为和环境细节的联系、步骤依赖）要定位关系是否成立及为何服务目标；没有可靠通用数值时作有依据的定性判断或同材料比较。
- **整体效果**（情绪、自然感、风格、可理解性或真实使用效果）依赖目标接收者与媒介，优先比较完整成品并解释观察依据；没有校准参照时不伪造分数或普遍阈值。

任何数字都只是测量，不自动等于质量。采用指标前说明测量对象、观察条件、它为何代表当前目标，以及哪些目标侧面没被它覆盖。若指标达到而整体效果变差，暂停优化该指标，检查它是否测错目标、与其他要求冲突或仅改善了局部。多个观察者分歧时，先核对他们是否使用同一目标、材料、判据与条件；若仍有合理的专业取舍，保留分歧与代价，不用平均分掩盖。

### 把效果判断落到媒介内的动作

“更有吸引力”“更清楚”“更有感染力”等评价须落实到媒介。沿接收者要获得的反应，定位实际成品位置，说明哪种材料关系承载它、哪项具体操作能建立它、怎样检查接收者能感知该关系。

**方案明确要做的动作。** 写明取什么材料、按何顺序选择或转换、产出什么形式、如何接入正常步骤与下游消费者。自然、清楚、信息密度等成品判断用于验收。涉及运行规则时，按[决策级变更规格](#交付规则的决策级变更规格)核实际控制文件、原位置、触发和接入点，带回本节说明变化。普通解释、作品或工具方案按所求产物展开影响下一步的环节。

语言差距要接到不同处理。分析对象本身是给人阅读的文字，且本轮会判断词句、语义、信息次序或篇章关系时，读取或复用根目录[语言成文方法](../../../../references/language-realization.md)中对应判据，实际检查被分析文本并把观察带回本节形成解释；只按该方法写好 analysis 报告，不能代替对对象的检查。非文字对象或只核字段/格式等有限契约时不因此扩查语言。若目标或已定态度偏离，回到本轮决定并恢复其方向；意思或关系缺项时，补准读者实际缺少的对象、动作、条件、数量或确定程度；材料齐全但信息顺序妨碍理解时，重排并只补必要衔接；关系成立而搭配或语序不自然时，改用符合语境的词组和句法；有效规则存在但未加载或未执行时，修复触发、读取或执行路径，不把调用断点当措辞问题。必要小词、解释和有作用的重复按其实际贡献保留；不把所有语言问题都改成更口语或一律扩写，也不以删字作为质量提升。

分析文本词义、图像空间或流程状态时，从当前对象选能改变判断的操作变量。文字可查词义、搭配、行动、视角、连接、次序、节奏和省略；图像可查主体、空间、形状、边缘、比例、色彩和光影；流程可查前提、状态、分支、反馈和结果。把术语落实到材料和纠偏，事实按断言核实，权限按实际动作检查。局部修正保护其余已确认选择。报告本身依[主文成文](../SKILL.md#综合表达验证与交接)检查。

### 把已确认差距落实为报告内的局部改后对照

材料已读且具体差距已确认时，按[同材料局部改后对照](../../laohu-evolution/references/rule-expression.md#对已确认差距做报告内局部对照)做报告内最小完整处理；分析本入口负责核事实、声音与目标，回查改后真实关系及首个下游，结果带回[主文综合表达、验证与交接](../SKILL.md#综合表达验证与交接)。

### 核对表达意图是否在规则链中走样

分析、拆解或迁移运行规则与专业方法时，按[双关口第一关](../../laohu-evolution/references/rule-expression.md#回核原始意图与既有规则的偏移)定位已选表达怎样在现行规则、执行或成品走样，不等用户指出。把源头最新确认、首个偏移控制点、影响、实际语义与保护项带回方案，再由实施应用第二关。明确区分无据事实校正与继续有效的立场/声音；若作者的选择与用户已确认目标、可核事实或适用方法相冲突，或用户要求比较，另陈依据、代价与备选。

## 让证据回答具体问题

按会改变判断的缺口挑材料。原始对象说明内容本身；执行记录说明某一步实际发生了什么；调用记录说明规则或 Reference 是否加载；规则文件说明当时可能提供什么方法；成品与接收者反馈说明实际结果。单独一份提示词、规则或输出，不能证明其他环节的行为或因果。

| 证据类型 | 能帮助判断什么 | 不能单独证明什么 |
|---|---|---|
| 明确规格与用户已选要求 | 边界、交付契约、当前必须保留的选择 | 一般用户都偏好此选择 |
| 专业方法或原始来源 | 该方法如何判断、适用条件和限制 | 它已造成当前本地结果 |
| 相近历史案例 | 候选机制是否可能迁移及关键差别 | 当前对象发生该原因 |
| 本地执行记录 | 本次输入、环境、决定、顺序与动作 | 其他运行都如此 |
| 受控试验与完整产物 | 改变条件后本地观察怎样变化 | 未覆盖条件下也有相同效果 |
| 实际接收者或使用反馈 | 指定媒介、对象与情境中的体验或使用结果 | 所有人、所有媒介都相同 |

在把关键原材料写成“缺失/未提供”之前，先检查已经读到的证据、索引与交接是否给出明确源路径、链接或字段/记录选择器。若指向本轮授权内可定位且可读的内容，实际沿指针读取会改变本项判断的最小原件/记录，不因原件未内嵌或未列 input_files 就判未提供；只补读与判断相关的记录，工具输出截断时继续取得关键范围，不整包暴露无关材料。哈希用于核实材料身份，不代表内容已经阅读。只有源内容无法定位、无权限或不可读时，才把该项结论限制为未知/受限；即使已读原材料，缺少逐轮调用或执行记录仍意味着历史加载/执行因果未知。

需要专业知识时，先把问题写成“什么条件下，哪一种处理会更适合当前目标”，再查阅相关的一手来源、专业教材、可靠案例或可核验记录。读取足以理解主张上下文和适用边界的材料；把作者原话、后来的解释和本地推论分开。理论解释机制，案例检查迁移差异，记录说明本地发生过什么，试验核对本地预测。经典、名气、转载次数或术语都不能替代相关性；新且可核查的一手材料也不因来源不出名而排除。没有会改变判断的知识缺口时，直接用已有材料，不为答案装饰理论。

用户提出原因、理论或改法时，先辨认它是事实声明、个人政策/偏好，还是经验方法。事实判断核对来源、因果跳跃、样本边界和从结果反推唯一原因；政策按用户明确范围执行；成熟方法可作为有条件的默认建议。适用的方法不要求普遍效果统计，但它的作用仍须以方法或工作选择说明，不能包装成已证实事实。

## 形成并区分解释

从最早出现且与目标有关的差异开始，提出一个有材料支持的首选解释。对能解释主要观察且有材料依据的不同解释，只要会改变原因/机制理解、结论把握、可检验预测或后续动作，就保留其独立部分；即使暂时导向相同的最小检查或下一步，也不因此删除。同义解释合并；不能解释主要观察或缺少材料依据的纯可能性不罗列。

对每个保留的解释，写出它若成立应看到什么，以及什么可取得的观察会削弱或区分它；即使当前第一步检查相同，也说明可用什么材料区分这些解释。先读能够直接回答问题的记录；需要比较时，保持重要输入和环境可比，只改最能区分解释的条件。若无法控制条件，说明混杂和结论范围。解释能覆盖失败却不能说明相近成功时，检查遗漏条件；解释听来完整但没有可区分的预测时，继续把机制说具体。

检查结果可以支持、削弱或暂时不能区分解释。将新的观察写回当前任务状态，只更新受到影响的判断。相关变化可以支持进一步检查，不自动证明单一因果；方法声誉也不代替本地适用性。

## 区分方法缺失与执行断点

分析 AI 或工具结果时，分别核对最终产物、当次输入、实际运行记录、当时加载的规则/配置、工具环境和后续编辑。按证据区分：

- 规则没有提供必要的专业动作；
- 规则提到了方法，但相对已选目标或可核对的方法依据存在准确性、适用范围、覆盖条件或执行表述缺口；
- 规则存在，但没有在相关任务中加载；
- 方法加载了，却被跳过或执行不完整；
- 方法已执行，但材料、环境或条件可能超出适用范围；
- 方法和表现设计已进入成品流程，但成品没有实现目标；
- 评价没有观察目标效果，或指标不能代表目标；
- 产物有改善，但哪些机制起作用尚未分清。

规则中出现方法名称、术语或一段原则，只能证明有这段文字，不能单独证明它准确、适用、覆盖充分或能指导制作。若有可定位的用户已选方法、可靠来源或任务目标，沿其条件、必要构成、操作与成品判据对照现行规则；明确指出差距在哪一环，不因成品问题直接宣称“方法缺失”。若首轮产物和后续指导修订可取得，把当次输入、失败位置、现行规则/实际加载记录与改后版本并读，定位最早差别；再把指导逐项对照现行方法，判断它只是提醒执行一个已有动作，还是新补了关系重建、材料处理或下游复查步骤。前者说明方法可能已有而调用/优先级/消费遗漏，修相应路径，不重复增加“必须”；同时写清本次应在什么输入、哪一动作/时点形成什么可核材料结果，以及由哪个后续步骤实际读取或使用它，不止建议“复用现有条款”或“以后再观察”。后者若由已选目标、可靠方法或直接可证的规则缺口支持，可作为方法增量写入正常工作路径。缺少加载日志、初稿或中间反馈时，相关历史因果标未知；不把反复失败设为提出有据改进的前置。若适用性本身仍不确定且会改变规则，才把进一步区分作为前置。完整执行后目标仍未出现时，保留具体产物和条件，进一步判断是适用范围、表现设计还是成品实现问题，不预设单一原因。

追溯历史运行时，以当轮调用和执行记录为证据；当前规则只能说明现在的文字，不能充当旧轮次加载日志。没有相应记录就不推断资源曾加载或被遵循，按已知阶段产物和反馈继续判断，标明历史调用状态未知。多轮结果变好或变差时，比较真实阶段稿与明确认可范围，不能把变化只归功于最近一处修改。

## 比较路径并选定下一步

原因解释与改法不是一回事。沿已查明或仍待验证的关系，比较直接修正当前输出、改变重复出现的条件、补足反馈或暂时绕开问题的实际作用。根因最深、改动最大和文字最少都不是单独的优先标准；看哪种办法能改变主要结果、代价是什么、如何检查。

目标和证据足以选择时，明确建议及其适用条件。未知只有在会改变主要动作时才继续调查；暂时不能查清时，给出各结果对应的分支，并完成不依赖它的工作。存在可恢复、低成本且可检查的步骤时，可标明事实未知与工作假设后推进，不必先查明完整因果链。目标、授权或关键验收取舍仍未确定且会实质改变主要产物时，只暂停受影响部分并说明所需决定。

用户只求解释时，交付材料支持的关系和未知，不强塞修复计划。用户要解决问题、提出改法或交接实施时，方案必须点明对象、动作、适用条件、必要顺序与依赖、保护项、负责人、产物和可观察验收，不以“优化、加强、提升质量”收尾。

每项建议的改动都要接到一个真实控制点：指出哪个输入或材料进入判断、判断时要作出什么选择或动作、结果由谁/哪一步接收，以及怎样按本轮目标验收。若原因仍未知，但某项直接行为缺口已由材料确认，可先提出对应的可检查改动；只换措辞而无法说明它改变了哪项选择、动作或下游结果，不算查明或修复了原因。

### 规则改动前的生态影响面扫描

方案涉及共享规则、高频 Skill、跨入口锚点或规则接口时，选方案前从真实控制点向外扫描。搜索相对路径、原锚点、入口名、关键动作/字段、近义说法与历史失败；检查可读的直接 Skill/Reference 调用、配置、脚本、模板、离线测试和现有 `evals/evals.json`。沿触发、加载、运行及首个消费者核每条命中是否真实依赖，区分只提及、兼容复用、预期受影响及证据不足。只读授权内的相关材料，缺可读证据标未知，不据文本相似判断链。

**跟踪状态怎样进入接口。** 改动会改变状态判断或字段映射时，固定同一对象与时点，代入可改变判断的缺失、明确的相反证据及有据确定值。逐项比上游材料与证据状态、实际分支、下游布尔值或枚举及后续消费者。不同依据即使输出同值，也保留各自的判定与仍须核实的分支，不凭字段反推出上游事实。必要分支的业务语义或接口契约无证据时，标未知并列出待核条件，维持已确认的字段与保护项。

输出影响文件/章节、实际消费者和测试、接口与权限保护项、兼容或迁移策略、需派生验证与无法覆盖的部分，带入[决策级变更规格](#交付规则的决策级变更规格)。涉及共享读取、阶段数或认知复杂度时，按[上下文负载预算](capability-design.md#评估上下文负载与认知复杂度代价)逐条比较当前与各可行候选，把实际读取、去重后固定/增量开销及估计假设放入取舍依据。

### 交付规则的决策级变更规格

分析证实规则改进时，给出目标行为、八类断点中的可证位置或未知、选定方法与代价、旧控制文件/章节、核心新逻辑、触发/退出与必要分支。写明新旧冲突裁决、必须保留的约束和接口、写回涉及的消费者/评测、可观察验收和未知。注明真实的增、改、替代、保留位置；正向方法具体到输入、转换顺序、交付形式和下游用途。规则与成品标准用在各自环节。

按[三技能职责](../../../../references/triad-handoff.md#1-三技能单一职责与交接红线)以决策级深度交 evolution。仅用户明确要不经 evolution 交独立执行者或明确要精确补丁时，提供原位置、原句、上下文、完整替换段和接入位置。把选定判断接到普通生成步骤，未定的核心动作或用户取舍仍显式标出。

### 把调查所得交回主文综合

调查中形成的观察、方法应用和条件判断，应组成后续解释或方案可直接使用的依据，而不是散列成材料目录或维度标签。对每项重要发现，保留能定位的材料/上下文、实际用过的判据或方法、观察到的关系、它怎样支持或削弱当前判断，以及限制结论的反向观察或未知；没有相反材料时不编造。将互相依赖的发现接成机制或选择路径，独立发现则分开保留。只求解释时返回证据所支持的关系和边界；判断原因时返回能区分解释的机制与观察；比较方案时返回形成差异的判据、收益代价和切换条件；设计能力时返回应由哪些功能/消费者承接的具体方法与输入输出关系。主文再按用户要的产物组织成可读结论；本 Reference 不要求逐个交出16个栏目，也不替用户或执行者实施写回。

规则改进按[决策级规格](#交付规则的决策级变更规格)带回主文，在已选升级目标、可靠方法或直接规则缺口支持下给方案；单例或缺少普遍统计只限制频率与效果，不挡有据的可恢复设计。作品或工具改法保留实见问题、预期改变、适用专业能力、输入、产物和验收，仍按该对象交付。

### 比较可迁移的方法与跨对象案例

创建、扩展或重建长期能力时，资料取得、方法适用性和整体设计以[完整能力设计](capability-design.md)为准；需要从真实成品反向细读、形成可迁移方法或区分学习与评价材料时，读取[真实作品研究方法的日常创作取法与方向](../../../../references/exemplar-study.md#日常创作取法与方向)。这里仅判断跨对象比较会不会区分当前的解释或下一步。优先沿用已经成立的方法；只有候选会改变目标、功能分配、依赖、执行方式或关键取舍时才比较，不为“看起来研究充分”凑作品或理论数量。正式质量评估另按[正式评估与 L/C/D/H](../../../../references/exemplar-study.md#正式评估与-lcdh)和[验证协议](validation.md)处理，不能把日常取法当作评分依据。

比较时只用可定位的作品证据和会改变判断的目标条件。成功样本用于提出候选机制，失败样本用于检查机制边界；相似不证明可以迁移，差异也要说明是否影响作用。分开说明可观察的作品形式、对效果机制的解释、本地决定和未验证主张。若目标只是正式的作品质量评级或留出验证，按[验证协议](validation.md)处理数据角色、人类标尺原文/语境、校准和评价证据；不能把赏析、同材料试写或模型自评分数当质量结果。

如果要把判断转成创作表达原则，读取 [规则表达与方法保留](../../laohu-evolution/references/rule-expression.md)：以用户确认的材料关系提炼方向句，交代机制、适用条件、开放变量和正向动作。analysis 可检查生成方法与验收条件；具体用户材料的局部对照按本 Reference 上述小节执行，不另造材料无关的作品作示例或待验试作，也不以报告对照冒充独立作品验证。当读者/观众/使用者要理解、感受或完成的事会改变方案中的目标、内容次序或验收时，读取根目录[读者价值与作品组织](../../../../references/audience-value-and-structure.md)并把相关取舍接入方案；方案设计文字词句段生成或修订时，读取[语言成文方法](../../../../references/language-realization.md)并交代相应动作。条件不成立时跳过该 Reference，不把分析用的结构投射成用户必须填写或作品必须展示的栏目。需要以实际作品判断表达效果时，按授权交目标执行 Skill 依最终规则和真实任务材料产出，再分别检查目标效果与事实/内容边界。范例来源及效果证据按规则表达 Reference 执行。

本轮若从局部调查发现需要整体新建或重构长期能力，回到主文调用 [完整能力设计](capability-design.md)，而不是把所有模块都塞进本地问题诊断。完成原因、比较或方案判断后返回 [analysis 主文](../SKILL.md)，按请求交付并决定是否需要相称的验证。
