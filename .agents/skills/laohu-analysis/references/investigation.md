# 调查取证、解释与方案比较

由 [analysis 主文](../SKILL.md) 在本轮需要界定具体问题、核对原因、理解宽泛质量反馈或比较局部处理办法时读取。它帮助从材料走到证据相称的解释和下一步建议；完成当前判断后回主文交付。新建、扩大或整体重构长期能力时，转读 [完整能力设计](capability-design.md)，不要把整体设计缩成一次故障分类。完整设计中的现有能力重构若须判断历史执行缺口，只读本篇“区分方法缺失与执行断点”一节，读完直接回完整能力设计第二步，不再重启整体设计入口。

## 先找到会改变处理的判断

沿用已确认目标、用户决定和任务状态，指出当前对象、观察到的差距，以及下一步最需要弄清的问题。没有可观察的表现时，说明能取得哪项材料；不让用户重述已知目标，也不要求他先替执行者选改法。

从接收者看到的结果向前追：相关输入是什么，谁在何时读到或做了什么决定，经过哪些变换和依赖，怎样到达当前输出。对照正常结果、明确要求或适用专业判据；没有可比样本时，把预期标成待检验目标，不写成已观察事实。只沿会影响解释或动作的环节继续，不为画完整流程而扩范围。

用户用“审美不够”“节奏乱”“没有感染力”等宽泛说法时，先把它落到可检查的位置，再接上适用判据和后续动作：

| 判断环节 | 需要说清的事 |
|---|---|
| 目标与接收者 | 这项内容要让谁理解、感受或完成什么？ |
| 具体表现 | 哪句话、画面、声画时刻、步骤或交互出现了什么？ |
| 判据 | 为什么它影响当前目标；何种条件下该表现仍可成立？ |
| 可能原因 | 哪些已观察的输入、决定、执行或反馈可能造成它？ |
| 区分办法 | 哪个最小读取、比较或试验会让不同解释产生不同观察？ |
| 控制位置 | 证据指向改哪项规则、选择、材料、参数、工序或成品？ |
| 验收 | 要改善什么，哪些事实、偏好和风格必须保留？ |

有依据的部分直接沿用，不为填满表格重复分析。把明确规格未满足、相对已定目标的损失、尚无共同判据的偏好差异和现有材料不足以判断的未知分开。说“可以提升”时，至少指出当前表现、适用判据、目标损失和可改变的位置。

判据按对象使用，不把审美压成一张通用打分表：

- **规格**（尺寸、时长、字段、明确比例或包含项）可按定义检查数值或通过/未通过；必须说明测的对象、单位、分母与观察条件。
- **内部关系**（视觉主次、叙事铺垫与结果、人物行为和环境细节的联系、步骤依赖）要定位关系是否成立及为何服务目标；没有可靠通用数值时作有依据的定性判断或同材料比较。
- **整体效果**（情绪、自然感、风格、可理解性或真实使用效果）依赖目标接收者与媒介，优先比较完整成品并解释观察依据；没有校准参照时不伪造分数或普遍阈值。

任何数字都只是测量，不自动等于质量。采用指标前说明测量对象、观察条件、它为何代表当前目标，以及哪些目标侧面没被它覆盖。若指标达到而整体效果变差，暂停优化该指标，检查它是否测错目标、与其他要求冲突或仅改善了局部。多个观察者分歧时，先核对他们是否使用同一目标、材料、判据与条件；若仍有合理的专业取舍，保留分歧与代价，不用平均分掩盖。

## 让证据回答具体问题

按会改变判断的缺口挑材料。原始对象说明内容本身；执行记录说明某一步实际发生了什么；调用记录说明规则或 Reference 是否加载；规则文件说明当时可能提供什么方法；成品与接收者反馈说明实际结果。单独一份提示词、规则或输出，不能证明其他环节的行为或因果。

| 证据类型 | 能帮助判断什么 | 不能单独证明什么 |
|---|---|---|
| 明确规格与用户已选要求 | 边界、交付契约、当前必须保留的选择 | 一般用户都偏好此选择 |
| 专业方法或原始来源 | 该方法如何判断、适用条件和限制 | 它已造成当前本地结果 |
| 相近历史案例 | 候选机制是否可能迁移及关键差别 | 当前对象发生该原因 |
| 本地执行记录 | 本次输入、环境、决定、顺序与动作 | 其他运行都如此 |
| 受控试验与完整产物 | 改变条件后本地观察怎样变化 | 未覆盖条件下也有相同效果 |
| 实际接收者或使用反馈 | 指定媒介、对象与情境中的体验或使用结果 | 所有人、所有媒介都相同 |

需要专业知识时，先把问题写成“什么条件下，哪一种处理会更适合当前目标”，再查阅相关的一手来源、专业教材、可靠案例或可核验记录。读取足以理解主张上下文和适用边界的材料；把作者原话、后来的解释和本地推论分开。理论解释机制，案例检查迁移差异，记录说明本地发生过什么，试验核对本地预测。经典、名气、转载次数或术语都不能替代相关性；新且可核查的一手材料也不因来源不出名而排除。没有会改变判断的知识缺口时，直接用已有材料，不为答案装饰理论。

用户提出原因、理论或改法时，先辨认它是事实声明、个人政策/偏好，还是经验方法。事实判断核对来源、因果跳跃、样本边界和从结果反推唯一原因；政策按用户明确范围执行；成熟方法可作为有条件的默认建议。适用的方法不要求普遍效果统计，但它的作用仍须以方法或工作选择说明，不能包装成已证实事实。

## 形成并区分解释

从最早出现且与目标有关的差异开始，提出一个有材料支持的首选解释。保留的其他解释必须同样解释主要观察，且会导向不同动作；不为显得全面而堆可能性。

对每个会改变行动的解释，写出它若成立应看到什么，以及什么观察会削弱它。先读能够直接回答问题的记录；需要比较时，保持重要输入和环境可比，只改最能区分解释的条件。若无法控制条件，说明混杂和结论范围。解释能覆盖失败却不能说明相近成功时，检查遗漏条件；解释听来完整但没有可区分的预测时，继续把机制说具体。

检查结果可以支持、削弱或暂时不能区分解释。将新的观察写回当前任务状态，只更新受到影响的判断。相关变化可以支持进一步检查，不自动证明单一因果；方法声誉也不代替本地适用性。

## 区分方法缺失与执行断点

分析 AI 或工具结果时，分别核对最终产物、当次输入、实际运行记录、当时加载的规则/配置、工具环境和后续编辑。按证据区分：

- 规则没有提供必要的专业动作；
- 规则存在，但没有在相关任务中加载；
- 方法加载了，却被跳过或执行不完整；
- 方法已执行，但材料、环境或条件可能超出适用范围；
- 评价没有观察目标效果，或指标不能代表目标；
- 产物有改善，但哪些机制起作用尚未分清。

若记录显示方法未加载或未执行，先提出修复触发条件、读取顺序或消费者并重跑的建议；只有方法完整执行后仍不能产生目标结果，才有依据考虑增补方法或缩小适用范围。

## 比较路径并选定下一步

原因解释与改法不是一回事。沿已查明或仍待验证的关系，比较直接修正当前输出、改变重复出现的条件、补足反馈或暂时绕开问题的实际作用。根因最深、改动最大和文字最少都不是单独的优先标准；看哪种办法能改变主要结果、代价是什么、如何检查。

目标和证据足以选择时，明确建议及其适用条件。未知只有在会改变主要动作时才继续调查；暂时不能查清时，给出各结果对应的分支，并完成不依赖它的工作。存在可恢复、低成本且可检查的步骤时，可标明事实未知与工作假设后推进，不必先查明完整因果链。目标、授权或关键验收取舍仍未确定且会实质改变主要产物时，只暂停受影响部分并说明所需决定。

用户只求解释时，交付材料支持的关系和未知，不强塞修复计划。用户要解决问题、提出改法或交接实施时，方案必须点明对象、动作、适用条件、必要顺序与依赖、保护项、负责人、产物和可观察验收，不以“优化、加强、提升质量”收尾。

项目规则方案须核实真实控制文件、章节和消费者，给出包含触发条件、动作、范围与要求强度的可采用文字，并说明增、改、删位置及保留内容。一次失败只有在证据表明机制会复现或已有共享控制点时才升级为长期规则。作品或工具方案说明已经观察到的问题、预期改变、所需输入、专业接手能力、产物和验收，不把它改写成项目级规则。

### 比较可迁移的方法与跨对象案例

创建或重建长期能力时，任务覆盖、资料取得、直接采用或适配的方法选择以[完整能力设计](capability-design.md)为准；本节只在关键条件有差别、确需判断迁移性时比较跨对象案例。条件已匹配的现成方法可直接复用，不为“自己设计”重做。

优先复用已经成立的能力。只有候选在功能分配、依赖、执行方式或关键取舍上确实不同，才比较实现方式；先检查硬约束，再比较它们对主要目标的贡献、实施成本、验证难度和未来变更影响。没有数据时作有依据的定性比较，不制造百分比和权重。

只有本地样本不足或新设计需要时才做跨对象结构类比。比较案例的角色分工、目标、关键约束与资源、依赖反馈和措施作用点；不凭同领域、表面相似、结果相同或人物名气决定迁移。只有案例材料中确实出现且能映射到本地目标的机制才列为“可借”；将案例借鉴与按本地约束独立推导的建议分开说明。成功案例只提供候选机制，失败和反例用于检查边界；交付可借机制、不可照搬部分和所需本地证据。关键差异破坏映射或根本没有有效映射时，说明无可迁移机制，不为借鉴而造机制。类比只形成假设或方案线索，不证明本案因果；没有适用案例就停止，不凑数量。

如果要把判断转成创作表达原则，读取 [规则表达与方法保留](../../laohu-evolution/references/rule-expression.md)：以用户确认的材料关系提炼方向句，交代机制、适用条件、开放变量和正向动作，再用具体产物检查；用户想要表达或体验变化时，用真实任务材料制作待验局部试作，分别检查目标效果和事实/内容边界。试作只服务本轮判断，不自动成为长期范例。

本轮若从局部调查发现需要整体新建或重构长期能力，回到主文调用 [完整能力设计](capability-design.md)，而不是把所有模块都塞进本地问题诊断。完成原因、比较或方案判断后返回 [analysis 主文](../SKILL.md)，按请求交付并决定是否需要相称的验证。
