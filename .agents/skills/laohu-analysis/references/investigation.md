# 调查与设计方法

主入口按当前理解卡点选择读取调查或设计部分；共同方法用于建立对象理解，不要求逐项输出本文件标题。

## 共同方法：把对象理解落实到材料

若问题本身尚未界定，先沿用已确认目标，写清实际现象、目标差距、对象与相关约束，形成可核对的问题表述；不重问已经明确的目标，也不要求用户先选改法。只补足会改变问题边界的信息。问题已能检查后，再按卡点调查原因或比较方案；材料不足以支撑判断时，说明已知部分、最有价值的一项证据，以及不同结果将如何改变判断。这里只做当前任务需要的部分，不是固定阶段清单。

从用户接收到的结果向前追到生成它的动作、判断、输入和依赖，再沿实际顺序核对。对照正常结果说明哪些关系必须成立；找不到正常样本时，用适用规范或用户认可的目标构造待检验的预期，不能称为已观察事实。

优先使用当前对象、有效用户要求、实际执行记录和匹配该领域的专业方法。按缺口选择切入点：

| 对象 | 首先还原什么 | 容易混淆的材料 |
|---|---|---|
| 文字、图像、声音与视频 | 接收者通过哪些内容、顺序和媒介特征形成目标理解或感受 | 提示词与生成物；创作者意图与接收者反应 |
| Skill、提示词与 AI 输出 | 任务如何识别，哪些材料实际可见，如何选择并执行动作 | 文件规定与实际加载；推荐、调用与成功执行 |
| 项目、工具与工作流程 | 输入如何经过接口、资源、责任和反馈到达输出 | 设计流程与真实操作；局部成功与最终完成 |

这些切入点用于取得对象知识，不是固定缺陷列表。单点问题可由直接证据或已知方法处理，不强制做背景研究。反复失败、竞争解释或跨入口规则设计若依赖尚未确定的专业判断，先确定：哪项判断会改变方案，当前依据是什么，哪个领域方法能评估它。已有明确适用的方法直接使用；关键知识缺口影响结论时，查找并实际读取对应资料，不用流畅解释或临时方案代替这一步。

按一条研究链推进：待解释的关系 → 对应专业方法或资料 → 方法的适用/失效条件 → 不同解释各自的可观察预测 → 本地记录、匹配案例或实验核对 → 是否需要改变选择。材料各有用途：理论和方法说明机制及边界；历史案例用于检查机制迁移及关键差异，不能证明当前对象的原因；当前执行记录说明本地发生了什么；实验检验当前对象中的预测或改动效果。按它能否改变判断选材料，不按论文、理论或案例数量凑足。

来源先看是否对应当前机制，再核对可追溯的原始主张、相关领域的证据及适用条件。经典、专业声誉和长期使用可提示成熟度，但不能证明本案效果；适用的方法可以形成有条件的默认建议。重要反例或本地反证与支持材料一并核对。新且可核查的一手资料不因作者不出名而排除，多次转载不算独立验证；只有术语、无机制或出处不可追溯的内容不能承担关键判断。缺资料时缩小结论；无网络时先完成可做的本地工作，并说明未能查证的关键专业判断。

对关键关系说明前一条件如何影响后一结果、依据在哪里，以及什么观察会改变判断。不要用“能力不足”等抽象归因收尾；指出谁在什么输入和条件下作了哪项选择、经由什么环节产生结果。跨越多个未查实环节时先查最影响选择的一环。若用户要求长期规则或结论，而相关资料本轮可得且可能改变适用方法或范围，实际读完再定稿；暂时绕行方案可以先给，但不能据此标记关键调查已完成。

### 将宽泛质量感受拆到可判断、可干预的位置

用户说“图片审美不够”“文章没感染力”“流程不顺”时，先确定所需效果、接收者与媒介，再指向材料中的具体表现。沿下面这条诊断链前进；某一环已有依据就沿用，不为填满字段重复分析：

| 环节 | 必须回答的问题 | 常见误判 |
|---|---|---|
| 目标效果 | 这项材料要让谁理解、感到或完成什么？ | 用“高级、专业、有感觉”代替结果 |
| 可定位表现 | 哪个句子、画面区域、声画时刻、步骤或交互实际呈现了什么？ | 只重复“构图不行、节奏不对” |
| 判据 | 为什么该表现影响当前目标；什么条件下它其实可以成立？ | 把检查者偏好当成普遍标准 |
| 候选原因 | 哪些已观察到的输入、决定、执行或反馈可能产生该表现？ | 仅凭成品或提示词断言唯一根因 |
| 区分动作 | 做哪项最小读取、比较或试验，能让不同解释产生不同观察？ | 同时改许多因素，结果无法归因 |
| 控制位置 | 证据指向应改哪项规则、选择、输入、参数、工序或成品内容？ | 只说“加强意识、优化流程” |
| 验收 | 哪个目标效果要改善，哪些约束与风格要保留？ | 只看局部变好或指标达标就宣布整体成功 |

按证据分开报告四种情况：明确约束未满足，是缺陷；约束已满足但相对已定目标与适用专业判据仍有具体损失，是目标未充分实现；目标尚未确定且无共同判据时，差异可能只是偏好；现有材料不能判断时，标为未知并指出所需观察。报告“可以提升”须给当前表现、判据或有效参照、目标损失和可改变的位置，不能把无限可替换的创作选择都报成缺陷。

判据按对象使用，不把审美压成一张通用打分表：

- **规格**（尺寸、时长、字段、明确比例或包含项）可按定义检查数值或通过/未通过；必须说明测的对象、单位、分母与观察条件。
- **内部关系**（视觉主次、叙事铺垫与结果、人物行为和环境细节的联系、步骤依赖）要定位关系是否成立及为何服务目标；没有可靠通用数值时作有依据的定性判断或同材料比较。
- **整体效果**（情绪、自然感、风格、可理解性或真实使用效果）依赖目标接收者与媒介，优先比较完整成品并解释观察依据；没有校准参照时不伪造分数或普遍阈值。

任何数字都只是测量，不自动等于质量。采用指标前说明测量对象、观察条件、它为何代表当前目标，以及哪些目标侧面没被它覆盖。若指标达到而整体效果变差，暂停优化该指标，检查它是否测错目标、与其他要求冲突或仅改善了局部。多个观察者分歧时，先核对他们是否使用同一目标、材料、判据与条件；若仍有合理的专业取舍，保留分歧与代价，不用平均分掩盖。

### 追踪生成结果与实际控制点

分析 AI 或工具产物时，把成品、实际执行记录、当时真正加载的规则/提示词/配置、原始输入和后续编辑分别核对。保存下来的提示词只能证明文件写了什么；必须有调用记录或同等证据才能说明它实际加载；即便确认加载，也只证明它是可能影响结果的条件，不能单独证明它造成了该结果。区分“规则没有提供方法”“提供了但未被加载或遵循”“材料或环境改变了结果”“改后效果变好但机制仍不确定”。

若两个原因会导向不同文件或动作，先写出各自不同预测，再保持其他重要输入与环境可比，只变更最能区分它们的条件；条件无法控制时说明混杂因素与结论范围。明确哪项观察会使你改判。最终方案指向证据支持的控制位置；尚未区分时给轻量检查或条件分支，不把提示词里相关一句直接认定为唯一根因。

### 校验用户给定的原因、理论或改法前提

用户带入内容时，先识别它是事实声明、用户选定的政策/偏好，还是经验方法/启发式。事实声明检查来源、因果跳跃、概念变化、单例推广及从结果反推唯一原因，并按证据保留或收窄；用户选定的政策按其授权执行，不要求普遍统计证明；成熟经验可作为带适用条件的默认建议或规则，并说明如何检查效果。若策略或工作阈值只是推论，应如实标为选择，不包装成外部证据或用户决定。

## 调查：区分现象、原因与干预点

### 还原与比较

将可观察现象与当前已确认的目标对照，保留原始样本和条件；只有目标确实缺失且会改变问题表述时才补问，不让用户重证已确认目标。优先寻找同一对象相近情境的成功、失败与变化前后样本，比较任务、材料、环境、顺序和关键选择；只读到片段时说明覆盖。直接矛盾或确定性错误可以就地证明，不为简单问题强制组织多轮研究。

首次出现差异的位置是调查入口，不自动等于唯一根因。沿其前置条件和后续反馈检查：什么触发错误，什么使其重复，什么使其未被纠正。只有会改变处理办法时才扩展范围。多个因素共同作用时保留关系，不以单一原因的整齐程度决定真伪。

### 形成并检验解释

从对象机制与差异提出首选解释。保留的其他解释须能解释主要事实，且会导向不同动作；不为了全面罗列无依据可能性。为每项解释写出与另一个解释不同的可观察预测，确定最小区分动作。只有一个有依据的解释时，核对它的关键预测，不强凑对手。

借助理论或方法时，先把机制映射到当前对象的条件和可观察指标，再写出成立时的不同预测及不适用条件或反证。缺少会改变当前专业结论的必要条件时标为未知，不因作者有名而跨领域套用；但可把有适用依据的方法作为待检验建议，不必等到本案因果关系完全确证才给出下一步。

- 记录能够直接回答疑点时，先读取记录。
- 怀疑某个条件触发结果时，在授权范围内隔离、替换或移除该条件，观察结果是否随之变化。
- 怀疑多个条件共同作用时，比较必要组合，记录其他因素是否同时改变。
- 无法干预时，利用发生时间、跨样本差异和机制材料核对，保留因果归属的限制。

一个解释需要同时面对支持与相反材料。能解释失败却不能解释相近成功时，检查遗漏条件；能解释一切却无法给出不同预测时，继续具体化。相关变化只能支持进一步检查；原因判断强度应与实际识别方法一致。

检查返回的观察可支持、削弱或暂时不能区分解释。将新观察写回同一任务状态，明确哪项判断改变；不因用户不满意就替换成另一个未经检查的总原因。

### 从原因到改法

沿已识别关系找可干预位置，比较直接修复、改变重复发生条件和改善反馈的实际收益。根因最深、改动最大或文字最少均不是单独的选择标准。优先处理主要影响且现实可行的机制；暂时绕开问题可以作为有效临时措施，但标明原条件是否仍存在。

用户要解决问题、改变现状或交接实施时，把已确认的目标和原因转成明确干预：哪个条件、决定、接口或内容要变化；执行者具体做什么；依赖什么输入与先后步骤；保留什么；用什么观察验收。方案中的动作要写清实际关系：有依赖的先后项说明前置条件；只有确实互不依赖时才标为可并行；按条件才执行的动作留在相应分支；可选动作说明适用范围，不把编号或项目符号本身当成关系说明。不要用“优化流程”“加强检查”等方向词替代行动。

根因未定时，按它是否改变可行的下一步处理；以下条件可以同时适用：

| 条件 | 处理 |
|---|---|
| 根因会改变可行的下一步 | 核对范围内证据；暂时无法确认时给出条件分支及各自动作 |
| 已有可恢复、低成本且能验证的路径 | 直接推荐或执行并标明假设，不以根因未全明为由停住 |

再按交付对象补足方案。

**项目规则任务：**

- 先读实际控制行为的文件、章节及其调用者，再说明新增、修改或删除的落点。
- 被审查文件只证明当前写了什么，不自动证明每项现存要求都已由上游确认。将候选改动对照原始已定目标、用户明确授权和相关材料；实质增删须有这些依据，或明确标成新建议／待决定，不能把为解释文件内部歧义而作的假设反向补成需求。
- 凡需写入规则，给出包含触发条件、执行动作、适用边界和要求强度的可直接采用文字，不只写“完善规则”；同时列明有效内容的保护项、实施顺序／依赖、可复现验收输入及预期观察。
- 把当前故障修复与长期防复发分开；只有材料表明该机制会重复出现或已有共同控制点时，才提出长期规则。

**作品或工具任务：**

- 指出当前材料中的实际发现、要改变的效果或功能、交给哪个专业能力／负责人、需要的输入、应返回的产物、保护项与验收条件。
- 不把作品问题改写成项目级规则任务。

分析交付的是可接手方案，不代表已获准实施或效果已验证。

例如，日志证实图表生成晚于报告组装，且用户要求消除漏图：可执行方案应把“生成完成/结果就绪”作为组装前置条件，明确生成失败或超时就不发送空图，保留其他报告内容，并用正常完成、延迟完成、失败/超时输入检查。若需写入长期规则，还要核实实际控制组装顺序的文件并给出完整规则句；“加强依赖管理”仍不是方案。

原因未完全确定而探索试验成本低、可恢复时，允许先试；所得效果与因果归属分开登记。对涉及多方面改动的试验，不把改善全部归功于其中某一条规则。

## 设计：从目标到可接手的方案

### 确定功能与取舍

将用户想得到的结果转换为必要功能。每项功能写清输入、处理动作或决定、输出、接收者及可观察完成条件，沿产物流检查前一步是否真的给了后一步所需输入。只有调用者、材料或输出确实不同才拆分职责；按步骤数量机械创建多个 Skill 没有充分依据。

将要求区分为必须满足的约束、优先保留的结果和可协商项。相互冲突时展示具体代价并提出推荐。新设计没有失败历史时，以功能覆盖和代表情境比较方案，不虚构事故解释。

### 比较实现方式

创建或重建长期能力时，具体任务覆盖、资料取得、直接采用或适配的选择以 [专业能力设计](capability-design.md) 为准。下文跨对象类比只处理关键条件有差别、需要判断可迁移性的情况；条件已匹配的现成方法可直接复用，不为了“自己设计”重做。

优先复用已经成立的能力。只有候选在功能分配、依赖、执行方式或关键取舍上确实不同，才需要比较。先检查能否满足硬约束，再比较对主要目标的贡献、实施成本、验证难度和未来变更影响。没有数据时采用有依据的定性比较，不制造百分比和权重。

只有本地样本不足或新设计需要时才做跨对象结构类比。比较案例的角色分工、目标、关键约束与资源、依赖反馈和措施作用点，不凭同领域、表面相似、结果相同或人物名气决定迁移。只有案例材料中确实出现、且能映射到本地目标的机制才列为“可借”；把案例借鉴与按本地约束独立推导的建议分开说明。成功案例只供提出候选机制，失败和反例用于检查边界；说明关键差异是否破坏迁移，并交付可借机制、不可照搬部分和所需本地证据。若无有效映射，说明本例没有可迁移机制，不为借鉴而造机制。类比只形成假设或方案线索，不证明本案因果；无适用案例就停止，不凑数量。

当材料足以支持取舍时，明确方案建议及其解决的主要矛盾；若当前缺口仍是问题界定或关键证据，不越过缺口强行推荐。若决定依赖某项未知，设计能改变选择的小样或试验，不无限收集泛相关资料。已有方案被替换时，说明新增证据、受影响部分和仍保留的决定。

### 写到能够支持选择与交接

方案已有足够依据时，先明确关键输入输出、必要顺序与依赖、负责能力或工具、失败反馈的位置。

未决事项按其影响处理：

- **常规实现细节未规定**：由负责人选定并标明工作假设。
- **未决目标、权限或事实会实质改变主要路径**：说明阻塞和所需决定／证据，并给可安全执行的临时措施或条件分支。
- **根因仍未知**：可以保留，但须把未知变成显式分支，说明如何区分及各自动作。

再用一个代表任务沿方案走通，检查材料缺口、互相等待、未分配的决定、保护项和验收观察。若执行者仍得自行猜根因、目标范围或核心改动内容才能行动，方案还未到可接手程度，返回调查／方案形成继续补足。走查能发现接口缺陷，不能冒充实际运行。

需要正式实施时，交回原负责人或已明确选定的专业能力。跨入口正式工作按 `{PROJECT_ROOT}/docs/runtime.md` 的共同边界判断；同一 Agent 身份不证明承接能力已选定。用户已明确选择匹配组合或授权按目标选配时，沿用任务状态继续，不额外制造串行交接；否则完成本入口可交付部分并说明未承接内容及后续选择方式。

作品的专业构思、工具实现等由具备相应方法的能力执行。确定接手方时交付当前对象、已选方案、保护项、所需产物与返回位置；不能用交给专业能力掩盖不存在或无法调用的依赖。已知修法的常规应用交给原负责人，不由本入口为了证明方案而接管正式修改。

### 表达与体验设计

先根据实际阻碍选择介入方式，再确定语气。事实断言的强度由证据控制，表达可以明确坚定；两者不混成统一的温和或强硬。

| 已观察的条件 | 选择的处理与应得结果 | 切换条件 |
|---|---|---|
| 目标、步骤及必要条件清楚，讨论反复停在同一笼统拒绝 | 点出重复，追问具体哪一步受阻或推进已授权动作；得到可处理障碍或实际进展 | 出现新事实、真实限制或目标改变就更新，不判定用户必然逃避 |
| 缺失事实会改变选择 | 读取、检索或索取那项材料，拿到能区分路径的信息 | 信息足够时选择行动，不继续劝说 |
| 方案都可行但优先目标不同 | 说明具体代价并给推荐，交付可选取舍 | 用户选择或新条件改变代价 |
| 已有证据显示目标落空 | 定位差距，直接指出，不用泛泛保留意见软化 | 反证推翻判断时撤回 |
| 方法适用且授权清楚 | 直接执行或交付已选方法，不用研究替代行动 | 执行暴露新条件时重审相应部分 |
| 用户尚在探索、未定方向 | 给同材料的可比较候选与推荐，允许拒绝 | 用户选定后深化，不持续发散 |

迁移作者的强立场时先辨认它推动的决定、排除的干扰和退出条件；有效的工作选择与过度事实断言分开处理。不得仅因措辞强烈整体否定，也不得用一句口头信号断定人的动机。原文已经准确承担作用时可保留；重组后须在完整片段中检查重点、节奏和力度，不能只看字面意思相近。

当用户要改变文字的语气、读者感受或体验强度时，方案必须回答：采取什么立场、面向谁、希望读者产生什么可观察反应、靠什么正向写法达到、强度到哪里、哪些事实与内容边界不能越过。把效果写成读者能感到的结果，而不是只贴“犀利”“有感染力”等标签；把正向方法写成可操作选择，而不以禁令代替方法。组织表达时先明确目标与期望反应，再选择与当前阻碍相匹配的动作（如解释、询问、比较或示范）；标明动作成立的条件，以及现有材料不支持哪些断言或推进。缺少关键步骤或事实时，指出缺项，不编造。

最后，依据本轮真实任务材料形成一段完整的任务内待验试作，核对它是否产生目标效果、保留事实边界，并能说明所选动作及其成立条件。试作只用于本轮判断，不自动收入正式 Reference 或成为长期范文；要收录长期范例，按 [规则表达与方法保留](../../laohu-evolution/references/rule-expression.md) 的来源门处理。
