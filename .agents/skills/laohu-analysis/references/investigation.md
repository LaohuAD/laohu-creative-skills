# 因果调查、断点诊断与方案决策

由 [laohu-analysis 主文](../SKILL.md) 在宽泛反馈定因、多解释区分、路径比较、规则生态影响扫描或交付变更规格时读取，完成后带回主文综合交付。

## 1. 先穿透表层需求做三态定盘，再落到可定位机制

用户说太死板、像 AI 说明书、后半段很虚、没有感染力，或丢来一份卡壳方案时，先沿需求五层穿透（字面手段 → 背后真实意图 → 不变的核心情绪与人性诉求）辨清对象落入三态中的哪一态，再用两三句人话定死总盘（底子已立只需精修，还是字面前提/外壳偏离本领域殿堂级特征须先换血），接着只展开会改变下一步的环节：

- **具体落点**：哪句话、哪个界面、哪一步交互、哪段提示词/简报或哪条规则出了偏差？
- **真实作用差距**：它具体削弱了哪项终稿目标或受众体验？哪些已成立的好资产（立场、声口、同向好方向、有效硬护栏）必须保住？
- **最早控制点**：从最终成品向前追，是输入外壳本身偏离、哪条规则/默认选择、哪次上游简报转换、还是下游漏消费最早引发了偏差？

## 2. 五类根因断点诊断模型（先查做减法！）

> **使用与表达边界**：下表是内部归因坐标，**面向普通用户或作者的报告严禁外露顺位断点编号、最早杠杆断点、文本层确证或 `FAIL`/`UNKNOWN` 等仓库内部术语与跳号标签**，一律转化为贴合该领域痛点的自然人话。其中 ① 过度约束/负资产主要针对 AI、Skill、Prompt、规则与流程系统；分析人类创作稿件或普通业务问题时，直接挖掘最本质的事实、商业机制、结构或受众根因，并把每项未核实的稿外事实拆成清晰分支，不生硬套用系统模型。

分析 AI、Skill、Prompt 或工作流为何效果不佳时，将实际产物、输入、加载规则与执行过程并读，按以下五类定位最早可证断点：

| 顺位 | 断点类型 | 典型信号 | 正确解法方向 |
|---|---|---|---|
| **①** | **过度约束 / 负资产断点（第一顺位必查！）** | 规则厚重、微观手把手写死、满屏否定禁令与免责括号、条款互相打架，导致强模型发挥反而不如纯裸跑 | **做减法**：直接删冗余、松微操、裁冲突、清文字墙，绝不继续叠补丁 |
| **②** | **方向 / 品味锚点缺位断点** | 目标模糊、缺少本任务专属的高水准标尺、关键取舍未拍板，输出滑向平庸安全牌 | **补方向**：用极简高辨识度的正向锚点定死目标与核心优先级 |
| **③** | **专业抓手 / 确定性工具缺位断点** | 面对强模型原生确实易失手、偷懒或必须确定性保证的环节，缺乏领域硬方法或脚本契约 | **补高杠杆抓手**：精准补充反直觉检查、领域机制或确定性脚本/接口 |
| **④** | **链路 / 消费断点** | 有效规则写对了，但 `description` 未命中、Reference 没加载、上下文未传递或下游没消费 | **修接线**：校准触发条件、参数传递、路径引用与下游接入点 |
| **⑤** | **材料 / 外部边界断点** | 输入本身缺关键事实、客观工具/平台限制或受众验证数据尚未产生 | **诚实划界**：补最小必要材料或收窄承诺，不靠写规则硬扛客观限制 |

> **区分历史因果与现状**：规则文字已存在不代表它曾被加载或有效执行；若旧轮次加载日志或初稿缺失，将历史因果诚实标为 `未知`，专注基于当前可读材料与现行文件给出可检查的下一步。
> **工艺全过却不对味或出现改 A 冒 B 钟摆震荡时，立刻向上追根**：表面流程、格式与局部技法全都达标，成品却仍显假大空、温吞或反复震荡，说明病灶不在表皮措辞。立刻停手表皮叠补丁，沿**灵魂（立意海拔/情绪电压/三态前提）→ 筋骨（领域法度/转化工艺）→ 血肉（审美提纯/核心母体）→ 表皮（感官质地与非对称工艺）**自上而下追查最早错位层，并核查核心原理是否误锁进 `SOURCES.md` 以及下级子文件是否残留打架旧规。

### 创作与生成类顽症的大模型机理速诊（防只加表皮提醒）

当规则越写越全但 AI 成品依然甩不掉固定怪味时，直接按底层生成机理定因，绝不继续在表皮贴禁令或换一张新黑名单以毒攻毒：

- **总甩不掉土味杂物、越禁越空或飘着散文作文腔**：同时排查**双向词面引力**（粗糙原词的正向引力、禁词黑名单引发的粉红大象与语料塌缩、上游散文简报塞满文艺形容词的反向污染）以及**缺少具体殿堂真品定音** → 解法先穿透用户嫌土的真实诉求，**绝不把用户嫌弃的低质感杂物原样塞回新方案**，也不用新黑名单或死字数枷锁替代，而是走**正向挑材物理换血**（换成干净、有动作感、跨受众可代入的真实切片）、**1–2 部具体经典作品定音**（只取说话与审美分寸，不笼统并列差异极大的多个创作者）与**极薄白描交接卡**；
- **句尾老冒出怪异单字形容词或生硬缩写**：查**自回归从左向右逐字生成撞上字数/韵脚墙**被迫词类截肢 → 解法不能只靠口头叮嘱，须改为**先显式吐出候选自然实词落点（草稿槽）再回推顺嘴前半句**，放宽机械死方阵，把口语自检后移到成稿后轻扫疤；
- **铺垫精彩但核心高潮发软，或高潮直白把全篇冲泄**：查**规则内部目标左右互搏**（如低饱和克制与高强度爆发直接打架）与**爆点大脑/铺垫大脑单锅双向污染**（铺垫拖垮爆点、爆点要求倒灌让铺垫提前泄气）→ 解法先统一张力曲线、改为两阶段物理拆步，先独立锁死高潮核，再切回克制大脑倒推铺垫；
- **上游动态交接卡与下游静态系统提示词彻底分层**：产出上游简报/卡片改后对照时，动态卡只锁本轮视角与说话对象、核心矛盾、极薄白描切片与定音坐标（严守自己定下的薄度且不越界编造狗血履历），**绝不把本属下游静态系统提示词的流程步骤、押韵规范或禁词清单混写进每轮动态卡里**；
- **提示词中继生成（生图/视频/音乐）成品塑料变形、构图散架或失准**：**绝不靠继续堆空洞修饰词硬救**，必须以真实渲染物沿四维反查最早编码断点（风格廉价查灵魂、构图/时序乱查筋骨、主体/景别/光影/音色失准查血肉、漏读串词查表皮语序）。
- **底层内容不错，但用户仍觉难读、找不到重点或下游报错**：查**表皮呈现错轨与固定格式契约破损**——中间态选题、分析或方案堆成紧凑文字墙、缺标题层级/对比表/推荐排序与重点加粗，或最终作品本体混入过程说明、擅改用户明确约定的固定输出格式（如段标、气口、纯代码块或字段模板）→ 解法按 `docs/runtime.md` §4 强制分轨并把用户固定格式升格为不可擅改的硬契约。

## 3. 区分竞争解释、单变量探真与增量权衡

1. **多解释并存与单变量隔离探真**：保留能解释主要观察且会改变判断或动作的独立解释（合并同义、不罗列无据空想）。常规歧义用成本最低的 1 步区分读取或局部对比裁决；若涉及颠覆性底层假设、审美大转向，或怀疑既有规则本身已成隐形天花板，先在 `.cache/validation/` 剥离干扰、单变量跑出真实成品交创作者肉眼或真耳确真，再进入正式融写方案。
2. **真权衡与防刷假指标**：比较改法时先筛掉破坏硬约束（安全、授权、锁定项、接口契约）的方案，再横向比较**核心效果收益、上下文/维护代价与返工风险**，明确给出首选方案及条件变化时的切换边界。局部代理指标（如压字数、单项分或检查表打勾）变好但整体成品变差时，立刻停刷该指标、回归真实成品。
3. **增量融合三问（防拆东墙补西墙）**：凡局部新需求或迭代升级方案，定案前必答三问——① 新要求归属灵魂/筋骨/血肉/表皮哪一层，绝不覆盖删掉已验证有效的旧强规则；② 新旧要求存在表面张力时（如短脆与舒展、锋利与零说教），明写各自的 **A×B 共存条件**；③ 每条高杠杆手法钉死**适用与不适用的媒介体量及题材边界**。

## 4. 规则改动前的生态影响面快扫

凡方案涉及共享规则、高频 Skill、跨入口锚点或接口字段，定案前必做两项快查：

1. **调用方与消费者扫描**：搜索目标路径、章节锚点、入口名、关键字段、脚本与 `evals/evals.json`，区分真实依赖、仅提及与需兼容保留项，避免修一处把下游拆断。
2. **上下文负载核对**：比较改前与新方案在典型普通请求下的**必读文件数、去重后总字节、超 300 字多条件文字墙数量与跨文件跳数**；避免通过把文字搬去另一个仍必读的文件假装减负。

## 5. 交付规则的决策级变更规格

按[三技能协作协议](../../../../docs/governance/triad-handoff.md)将已定规则改进交接给 `laohu-evolution` 时，提供清晰可落地的 6 项规格（不要求写死原句，除非用户明确要求不经 `evolution` 交独立执行者或明确索要逐字补丁）：

1. **`AUDIT-ID` 与目标行为**：要改变什么真实表现，最终接收者能看到什么不同。
2. **诊断断点与根因**：落入五类断点中的哪几类及关键材料依据。
3. **减法清单（要删除/松绑的限制）**：明确哪些过时微操、重复防呆或冲突条款应删除或放宽。
4. **控制点改动、4×4 归属与新逻辑**：落在哪个唯一真源文件/章节及 4×4 归属层，触发条件、新判断（含须显式留运行态的底层原理）、动作、A×B 共存条件、媒介适用边界与分支退出是什么；若是示范沉淀，写出从示范反推出的底层原理与四元闭环。
5. **保护项与跨文件扫残同步清单**：必须无损守住的已验证旧长板、硬契约与接口，以及同步受影响的 `description`、`agents/openai.yaml`、下级 `skills/*/SKILL.md` 与 `references/` 残留打架旧规清理、调用方链接或评测用例。
6. **自适应对比验证级、纯终端受众标尺与未知边界**：按[评估与验证协议](../../../../docs/governance/evaluation-protocol.md#22-自适应分级实证与防负进化闭环进化放行门禁)标明本改动走哪一级实证门禁（重大底层假设先走单变量隔离探真），给出覆盖回归痛点与全新零污染留出题的普通口语真题、由本次本质标尺派生的 **3–5 项纯终端受众体感维度（严禁夹带内部规则术语打卡）与硬边界否决项**，含多风格子技能时明确脱标盲辨要求，并标出仍待人类肉眼/真耳终审的未知范围。
