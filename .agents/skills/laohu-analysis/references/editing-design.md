# 动画的剪辑决定与真实时间依据

本 Reference 在动画输入涉及录音、口播、现成视频/录屏、剪辑、重排、停顿或循环播放时读取。Analysis 决定哪些材料与语义应出现、先后关系及可见重点；ASRcut 执行用户录音的识别、剪切、重排、时间编译与真实媒体处理；Motion 用原生 Motion Showreel 将已定事件实现为画面和声音。新建动画的视觉决定保存在唯一 `brief.md`；既有项目按当前真实消费者处理，不把旧项目格式作为新设计入口。

## 先区分内容改写、镜头安排和实际剪辑

检查用户原稿、录音和视频的真实材料身份、版本与锁定条件。原文是否保留、是否删词、是否重排，是内容决定；对象怎样出现、同一画面持续多久，是镜头/展演设计；实际删片、移动片段、改变速度或加入新停顿，是时间线修改。不可将这三种决定混为一项，也不能为了视觉方便擅自改稿或剪掉口播。

需要 ASR 或真实词级时码时，先查项目相关上下文中与当前媒体文件身份和版本一致的 ASRcut transcript、SRT、segment/word timestamps、edit plan 与 compiled timeline。保留 ASR 原始识别、用户备注与分析注释为不同内容；注释通过真实 source/segment/token/occurrence ID 关联，不回写原始识别文本，不创造第二个时间真源。

## 何时需要取得真实时间

- 用户已提供句段时间、ASRcut 已输出剪后 timeline，且实际媒体身份匹配：沿用这些时码，不重新估算。
- 画面只需随段落理解推进：真实句段边界即可，Motion 的镜头可跨句，不要求把每句变成一个场景。
- 关键画面或声音必须跟某个词精准对应：只有 ASRcut 的真实词时码或对本段音频完成的人工听标才可建立词级事件。没有时先完成非词级的设计与代码，单独暂停依赖它的精确同步。
- 只有原稿但没有语音：只按语义任务设计，不宣称时间同步。
- 用户未给完整媒体但要求依据录音节奏：说明依赖实际录音；不以 silencedetect、字数、音节数或通用语速替代 ASR 与实际听标。
- 时长与语音/实际片段冲突：保留原媒体身份，不静默截断、加速或拉伸；只将受冲突影响的时间设计交回用户决定，其余设计继续。

## 编辑方案从意义和证据出发

Analysis 首先判断观众需要听到/看到什么、事件的因果或情绪顺序、内容是否允许重排、何处需要完整停顿或保留原始状态。再依据用户的媒体、稿件和真实时码提出需要删除/保留的区间、段落关系、需要延长的呈现时间及原因。不得为凑节拍抹掉论点限定、事实证据、声音停顿或用户锁定片段。

有录屏、实拍与代码画面混合时，区分原视频的播放时间、片段进入成片后的 timeline time 与源文件的 source-in/out。需要剪辑时把时间线修改交给 ASRcut，保证原件和编辑计划可恢复；不剪辑时由 Motion 以确定性帧 seek/预抽帧接入，不让 HTML video 自然播放时钟参与正式渲染。循环视频或动画明确指出循环接缝与素材可重复范围；需要拼接授权时不得假定素材可循环。

## 交给 Motion 的唯一可用时间依据

交接说明：

- 当前媒体文件、来源及可验证身份/版本。
- 实际 voice segment/word boundary 或原视频片段边界的准确引用。
- 是否重排、剪切、改变语速、添加停顿或新增 presentation time，以及谁执行。
- 哪些时间约束是锁定的，哪些画面事件必须跟随，哪些镜头应跨多个句段持续。
- 没有真实精度支持的内容明确标成语义预算/待对齐；不能把它导出成词级秒数。
- ASRcut 的 source timeline/compiled edit result 是唯一剪辑与真实语音时间线，Motion 的项目 timeline.js 只映射这些真实时间及本片原创视觉/声音事件，不另建一份抢时钟的镜头稿。

把上述依据落实到[制作片段登记](motion-design.md#登记时间身份与材料引用)。对每个已对齐的片段，确认起止是成片绝对时间，注明采用的剪后时间线/工程时钟身份、版本及实际用到的来源实例与锚。口播、原视频和字幕分别解释其时间角色。只拿到 SRT 时可按实际文件和版本引用指定 cue 的显示窗；句内启落须另有真实词级证据或核听标记。需要指向同一录音的重复片段时，同时定位 occurrence 与句/词 ID，避免把同名语句接到错误的播放实例。字幕或声画事件越过段界时引用同一实例，记录各段碰到的区间并设计接续，声音轨仍按其实际完整时间处理。连续动态验证应覆盖段内变化及段界；单张设计帧或短小样只能提供其覆盖范围的证据。

词级对齐锚可以驱动画面，也可能落在发声前的原气口。交接时按证据称为词对齐时点。若切点、接缝或同步要求依赖听得见的起音、呼吸或静音边缘，核听当前声轨并查看对应波形，分别记录实际声点及它与词锚和段界的关系。

只有稿件或录音尚待对齐时，按已确定阅读、运动与留停要求安排目标秒数和段界，标记计划与依赖；随后以真实录音/剪后时间和已确定的字幕窗口核对实际可用时间。若预算冲突，先调整同一时窗内可开放的画面安排；剪接、重排或净新增呈现时间转交 ASRcut 按本轮授权处理。无来源映射变化的纯视觉、音乐或 SFX 操作沿 Motion 的当前项目时钟。确认本次只改设计且不动工程时，分别交清设计值、已有工程值与待实施处。

声音设计与画面事件共享同一 event ID。只有实际语音或源片段剪辑、重排、变速改变其 source-to-target 映射时，才由 ASRcut 重新编译相应真实时间；这不会解除锁定语音的内容与时长约束。无口播原创视觉事件、音乐位置、SFX 裁切或 SFX 相位变化，更新本片 `timeline.js` 的共享事件与派生 audio-plan，再复核声画关系，不交给 ASRcut 重编。brief、影片代码、字幕接口和音频文件不各自复制时间。新动画的字幕设计写在唯一 `brief.md` 对应观看单元；需要双语字幕时使用 `caption-design/2`，由 ASRcut 沿 canonical timeline 生成 manifest/SRT。既有 `caption-design/1` 文件继续按原哈希语义读取；这两种字幕输入都只承担字幕编译，不是完整设计文档。没有语音、没有声音的片子直接按画面时长组织，不因缺原音设置阻塞。

交接完回到 brief.md 的对应观看单元，确认设计描述已按真实内容更新。ASRcut 技术通过不证明原文完整、画面可读、内容意义正确或声音/画面接收质量通过。
