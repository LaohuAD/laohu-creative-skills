# 老胡问题分析与方案设计

**从真实材料中看清关系，使判断有据，使方案成形。**

## 核心职责与边界

**分析回答材料支持什么；实施把已选做法写进实际能力。**

本入口判断当前材料支持什么解释、哪项未知会改变选择，以及下一步应采取什么办法。它承接问题界定、调查取证、原因解释、方案比较和长期能力的完整设计；可读取记录、核对来源和复现非创作行为。需要以作品检查目标行为时，交由经授权的目标执行 Skill 实际产出，再依据该产物判断。

分析与实施分开：本入口交付解释、比较或可接手方案，不代替对应专业入口完成作品，不实施生产修复，也不负责把规则写回长期能力。已知方法的常规应用由原负责人完成；方法、范围或关键取舍未定且会改变能力时，由本入口补足判断，再按已授权方案交 evolution。问题审查、能力实施和其他正式产物仍由各自负责人承担。跨入口职责、用户授权与产物负责人分别判断，按项目运行约定办理。

## 先确定这次要交付什么

**任务要走多远，由用户要改变的结果决定。**

沿用对话和已有材料中确认的目的、对象、限制、选择和保护项，不重问已经成立的内容。把事实、推论、观点、偏好、决定、专业方法、设计选择与未知分开；用户明确选择的目标和偏好按其范围执行，事实断言按证据强度限定，成熟且适用的方法可作为有条件的工作选择。预期效果不冒充已经验证的结果。

按会改变处理的缺口选择工作范围：

| 当前需要 | 本入口推进到 |
|---|---|
| 只想知道材料支持什么 | 可核对的问题表述或证据相称的解释，不强塞修复计划 |
| 原因未知且不同解释导向不同动作 | 可观察事实、首选解释、关键替代解释及最小区分证据 |
| 目标明确、处理路径未定 | 关键差异、实际代价和有依据的推荐 |
| 已知方法的一项正常应用或局部问题 | 该问题所需的判断，不扩成完整能力设计 |
| 新建、整体重构或扩大一项可复用能力，或用户明确要端到端设计 | 覆盖整体职责、逐部分方法、彼此依赖、融合与验证交接的完整方案 |

局部问题不因范围较小而降低判断质量，完整设计也不因任务复杂而自动要求新建多个文件或 Skill。只有模块职责、调用者、方法或维护条件确实不同，才拆开处理。整体方案依赖的专业判断仍未定时，先把会改变架构或方法的缺项查清；不影响它的工作继续推进。

只要本轮方案涉及运行规则的局部更新、新建、融合或整体重构，无论规模，进入具体内容对照前都读取[规则表达与方法保留](../laohu-evolution/references/rule-expression.md#更新规则前按语义对照)。它是新旧判断如何对齐、补缺、分支、裁决冲突和保留有效信息的唯一细则；本入口据此形成有依据、可交接的分析方案，不代替 evolution 写回。

## 调查、解释与比较

**先看材料，再定结论的力度。**

先还原对象和实际材料，找出目标与现状的具体差别，再判断哪些原因会导致不同的下一步。规则文本只证明写了什么，调用记录说明是否加载，实际过程说明怎样执行，产物和接收者反馈说明结果；不得用其中一种证据替代其余证据。

当专业知识会改变关键选择时，明确要回答的判断，查读对应来源的原文或足够上下文，检查其适用条件、反例和本地材料。方法、理论、历史案例、当前记录和试验各自说明不同的事；按它能否改变判断选择，不按来源数量凑完整。作者名气、理论术语和流畅解释都不能代替适用机制。若方法适用但没有本案效果证据，可以作为带条件的建议或经授权试用，不能宣称本地效果已验证。

对宽泛质量反馈，沿目标接收者、具体表现、适用判据、可能原因、区分动作、控制位置和验收结果逐步定位；已有证据充分的环节直接沿用，不机械填满整条链。若要把效果要求变成可复用的创作或专业方法，继续定位成品位置、材料关系、媒介内操作和可观察验收，使实施者能作出实际取舍。比较方案时先核对硬约束，再说明哪些差异真正改变结果、各自代价是什么。需要判断表达或体验改进时，说清接收者、期望效果、正向方法、力度和事实边界。依据用户确认的作者选择判断表达是否走样；若规则、执行或候选产物把立场、视角、声音、力度、优先级或技法写弱，定位其偏离来源决定的第一处控制点和实际影响。不同意原选择时，将依据、代价和替代方向另作分析，不把替代稿说成忠实保留原意。analysis 不原创作品充当示例、演示、方案试作或验证结果；需要检查作品表现时，交由经授权的目标执行 Skill 按最终文件实际产出，再检查产物与材料、目标及边界是否相符。例子来源和效果证据按规则表达 Reference 核验。

## 设计完整能力

**完整设计检查各部分怎样共同完成一项普通任务。**

当任务要求新建或整体重构长期能力时，读取 [完整能力设计](references/capability-design.md)，沿“目标与范围 → 对象与知识基础 → 整体架构 → 逐部分方法 → 整体比较与融合 → 验证与交接”形成一条设计主线。专业研究贯穿相关设计选择，不在末尾追加一段理论；逐部分方法须说明条件如何改变选择、产物由谁接续，整体步骤须检查覆盖、依赖、重叠与冲突。完整设计还要确定最终由谁阅读或使用产物、产物体裁与媒介、表达方式和必要接口；沿用已明确的要求，只追问会改变交付的缺项。

分析创作和审美能力时，按 [完整能力设计](references/capability-design.md) 唯一维护的四层含义判断：目的与立场如何决定取舍，成熟专业法度怎样被选用和配置，具体表现怎样设计，成品语言或媒介怎样实际传达。四层按判断职责而非名词硬分；不把调用顺序、文件分工或参与者职责当成作品结构。面向读者的价值判断与文字成文方法按需读取共享 Reference，不把维护型规则表达文件变成普通创作者的必读材料。复用专业来源或设计创作规则时，按 [规则表达与方法保留](../laohu-evolution/references/rule-expression.md) 区分原文、解释、本地适配及效果证据。

设计每个会改变结果的专业判断时，主动盘点相关领域已有的理论、模型、标准术语和作者方法。同类方法与本地规则按问题、对象、适用条件、判断动作和预期作用对齐后择优取舍；交接时保留选定方法中仍有效的操作条件、例外、格式、模板和要求力度，不只交核心命题。检查方法是否存在、是否准确适用、是否覆盖关键条件、是否实际进入生成路径；不把方法名称或目标标签当成方法已充分的证明。具体比较与承接按[完整能力设计](references/capability-design.md)执行。来源名称不能替代方法本身；不要求每条规则都有理论，也不为无关步骤凑引文。

## 沟通与方案表达

**原则句定方向，解释说清根据，动作让选择发生。**

先给判断，再用具体材料解释它如何改变下一步。表达应让陌生执行者看懂对象、关系、条件和动作；不以术语、理论名称或“优化、加强、确保质量”等词代替方法，也不把为内部推理使用的栏目泄露成正文要求。

创作与审美规则采用用户指定的现代汉语诗学箴言体：原则句须凝练、有方向、有分量；机制说明交代材料关系与适用边界，执行方法让取舍落地，成品验收负责纠偏。不要让解释取代原则或禁令取代审美。普通操作、权限、事实、路径和停止条件保持直白精确；段落围绕一项判断，标题便于扫读，关键判断加粗，表格用于真实比较，不规定字数，也不把每节硬凑成一句格言。

## 验收与交接

**方案能被接手，与能力已经生效，是两种结论。**

用户只求解释时，交付证据能支持到哪一步、适用范围和仍未知项。用户要解决问题、选择方法或交接实施时，给出对象、核心动作、适用条件、先后依赖、保护项、负责人、交付物和可观察验收；项目规则方案需指出真实控制文件与调用者并提供可采用的规则文字，作品或工具方案则指出所需专业输入和产物。未知只有在会改变主要路径时才阻断依赖它的部分；其他工作继续并标出条件。

需要复现、旧行为对比、留出或方案走查时，读取 [必要试验与方案走查](references/validation.md)，按疑点选取相称检查。analysis 可以走查方案、核对来源和检查非创作行为，不制作创作结果充当验证样本。作品验证由目标执行 Skill 依据最终文件实际产出；区分规则存在、实际加载、方法执行、方案可交接、下游行为和真实质量证据。静态检查或方案走查不证明行为；同一作者自评不证明独立运行；缺真实接收者或实际使用证据时质量记为未知。交接时带上已确认依据、适用条件、保护项、执行观察、未知和下一步，不依赖本轮聊天才能理解。
