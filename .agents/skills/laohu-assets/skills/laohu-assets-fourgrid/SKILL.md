# 四窗视图选择

仅当用户明确要求某一项资产做四宫格/四窗时读取；普通单视图、单项其他视图或多个资产并排不触发。本子级只选择四个视窗各自要解决的识别、功能或空间观察问题，不把四窗拆成四项资产、不把不同对象拼成跨资产总览，也不把多个状态塞进四窗。

1. 确认资产类别、视图目的、同一资产身份锚点及用户已锁定的媒介/风格。
2. 读取唯一布局与质量真源[图片提示词交接与固定输出](../../references/image-handoff-and-output.md)，完整遵守其四窗画幅、类别分支、局部清晰要求和成像保护；不复制或重建另一套布局表，不削弱人物、道具、场景或服装的既有条件。
3. 按四个窗口需要显示的证据确定各窗职责与观察面，避免重复视图；同一项资产的多个视角仍共享身份、材料和适用的世界光源语境。对人物或具有头部的生物角色，把相机观察面、躯干朝向和头向分开决定：先保留该窗指定的观察面，再选自然的躯干与头部姿态来呈现所需证据。比如背面全身窗仍从人物背后观察、躯干保持背向镜头，人物自然向一侧回头，露出足够可见的侧脸面；若该窗要求无五官，平滑无五官只作用于该脸部，不损失背面衣装、身体或全身轮廓的清晰度。不要把“脸可见”直接当作改成前视的理由，也不扭转躯干或强拧颈部来替代分开选择朝向。只有用户明确更换观察面时才改动对应窗口；若自然姿态无法同时满足窗口职责与用户要求，只指出冲突所在的窗口及原因，并询问是否接受最小视面调整。
4. 将每窗确定的职责、观察面、身体/主体朝向、可行的头向及需显示的证据交回父级，由父级写入原有的完整独立提示词；不新增用户可见字段或表单。人物下排无五官等局部要求只约束源 Reference 指定的对应区域，不扩成全图模糊；具体布局和成像保护仍以该 Reference 为准。

本子级不设计声音、不修改资产身份、不生成图片。实际图片操作仍须单独授权。
