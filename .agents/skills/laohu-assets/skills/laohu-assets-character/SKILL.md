# 老胡人物资产

## 适用范围与父级继承

本配置仅在用户明确提出人物资产的创作、修改或检查工作，或明确要求执行本配置时，由父级加载。通用剧本资产整理不因材料涉及人物就加载；读取已有依赖资料不等于执行对应子级。每轮重新核对适用性，历史加载不自动沿用。父级独立具备各类完整方法，仍负责范围、ID、跨类别组合和最终交付。

## 专项判断与可见贡献

先对照现有角色提炼不依赖衣服和当次表情的脸部/轮廓锚点，再核对各必要视角是否仍可辨；完整人物与第一视角手部是基础与派生视图关系，不能相互替代。返回少数身份锚点及其可见视图，避免通用美貌词抹平角色。

本配置返回专项判断，展示规格以父级[固定资产字段](../../references/image-handoff-and-output.md)为准；不递归加载其他配置，也不因普通依赖扩大任务。

## 确定本次任务

用户点名人物时只处理该对象；要求提取时使用父级给出的材料范围；要求补充或修改时沿用既有角色 ID 和未改项。修改请求可以没有剧本：直接读现有资产与修改要求，不强索完整故事。若一个称呼可能对应不同人物且会改变合并结果，只核对这一身份缺口。

## 确定人物资产

### 识别与筛选

从姓名、关系、行动连续性及材料中的独特描述识别人物。只有材料足以确认时，才把别称映射到唯一生产名；职业、年龄段、关系称谓或角色类型相似都不是合并证据。判断是否有复用、连续性或用户明确设计需要；只在一幕出现且无需后续保持的人物群像不必逐个建资产。

### 归并复用

记录显示称呼 → 已确认人物名 → 既有或新分配 ID。相同人物跨时段保持同一基础 ID；证据不足的别称先拆开待核，不让错误合并污染后续片段。

### 固定项与变化

正式人物保持完整身份：人物底色落实为可视行为，确定身体比例、脸貌识别、发型发色、肤色肤质、基准表情与妆造，既有选定身份不得被新穿搭改写。默认穿搭仅明确宏观剪裁、整套搭配、色彩和材质倾向，不逐项规定衣物工艺。细节开放不等于人物无识别点；首次探索提出可辨方向，用户选定参考后再锁定实际需复现特征。助手尚未确认的建议不自动成为锁定项。完整人物不因第一视角而缩成手部。

人物展示沿中央规范采用灰棚柔光、微侧坐姿、脸部与双脚清楚；必要视图服务身份识别，不默认三视图或T-pose。

## 与其他资产的关系

服装必须绑定具体人物；持续伤势、妆污或伪装作为该人物状态的候选，按时间范围判断；转身、哭笑和手势通常留在对应画面。与“人物 + 状态”配置组合时，只对所选人物判断状态，不自动扩至全体角色。多个类别的组合由父级统合，人物子级不递归调用其他子级。

## 返回内容与交付检查

回传本类别对象、ID、范围与归属、主要方向和关系、已接受或剧情必要的保持项、开放局部与必要精控依据，以及类别展示要求。人物仍有完整身体与面貌身份；其他类别不以字段齐全强制细节穷举。只对正式资产设计，候选保持轻量；不越过父级生成未授权提示词，不把设计文本说成已生成图片。
