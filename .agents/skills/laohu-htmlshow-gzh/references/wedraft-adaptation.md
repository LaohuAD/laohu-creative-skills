# 阅读主题适配与装配

主入口选中索引内 `wedraft-` 主题后读取；将已归一化原文、所选主题库和通用语义规则编译成正文，返回主入口第 5 步。它负责确定性样式装配，不负责创作或改写文章。五套都是本地适配版：保留原阅读系统的字体、段距、章节与引文差别，同时执行本项目的 leaf、图片、代码与便携交付规则。

## 从原文到语义块

按原文顺序逐块转为 JSON 数组，文字从源文复制，不先总结再填回。原文已有行内强调转成标记数组；普通字符串按普通文字处理，不再次解析 Markdown。保留段内明确换行；代码文本逐字符保留制表符、空格、空行与末尾换行。源稿与 JSON 逐项核对后才运行装配；JSON 是中间文件，放当前任务缓存，不作为作品版本提交。

| 源结构 | `type` 与字段 | 判断与动作 |
|---|---|---|
| 一级文章标题 | `title`、`text` | 沿用源文；平台标题字段由实际契约单独处理 |
| 二级章节 | `chapter`、`text` | 自动按顺序附结构编号；原文字中的编号仍属原文，不擅删 |
| 三级小标题 | `subheading`、`text` | 保留标题与相邻正文位置 |
| 正文／引文／源文提示 | `paragraph`／`quote`／`note`、`text` | 不新增引号、标签、摘要或作者身份 |
| 有序／无序列表 | `list`、`ordered`、`items` | `items` 为源项数组；不将有序步骤变无序观点 |
| 代码／命令／Prompt | `code`、`text` | 仅做 HTML 转义，整段放一个 leaf，不加入语言标签或模板换行 |
| 图片／GIF | `image`、`src`、`alt`、可选 `caption` | alt 按主入口核对；图注只取来源；保留图片顺序，不拉伸小图 |
| 数据表 | `table`、`headers`、`rows` | 表头数组和等长行数组；单元格明确换行保留，不能用来做页面布局 |
| 原有来源区 | `references`、`items`、可选 `title` | 来源原文与完整 URL 可见可复制；缺少区名不自动生成标题或脚注号 |
| 原分割线 | `divider` | 不为每段或每个章节额外插入 |

`text`、列表项和表格单元格接受字符串，或按顺序排列的行内对象数组。行内对象为 `{ "type": "text|strong|mark|underline|delete|code|em", "text": "源文文字" }`；链接为 `{ "type": "link", "text": "原链接文字", "url": "原目的地址" }`。链接输出可见的原目的地址，适用于公众号中需要复制访问的链接。若用户锁定只显示某种原格式，应保留原字符为普通文本，不强套链接对象。HTML 源文本按文字转义，不能把任意 HTML 当作可执行插槽。

多段引文、嵌套列表、合并单元格、脚注回跳或其他表中未覆盖的结构，须按源结构在所选主题内装配必要组件，并逐项核对文字和关系；不得扁平化、漏项或声称该工具覆盖全部 Markdown。工具遇到未知类型、列数不齐或不合法地址会停止；回到源文处理具体结构，不用删除该块来使工具通过。

## 装配与交付

```bash
python3 <SKILL_ROOT>/scripts/render_reading_theme.py --list
python3 <SKILL_ROOT>/scripts/render_reading_theme.py --theme wedraft-blueprint --input <任务缓存中的完整语义块.json> --output <正文片段.html>
```

样式真源为 `assets/wedraft-reading.json`；库中的 HTML 是按该数据和装配器导出的可读组件。修改样式时同步数据、对应库、画廊和实际软件的目录指纹，禁止只改一份。运行不读取外部网站、不依赖 Node 或上游检出目录，Python 3.9 及以上标准库即可执行。CLI 全部完成后才写目标文件，源文、旧文章与历史均不改变。

接收端兼容由装配器统一转换：同行章节采用固定宽度编号列与可换行文字列，保留长标题悬挂对齐；分行编号保留自身宽度和下划线。引用保持本主题的边线、底色与内边距，去掉原来为装饰引号预留的首行负缩进。表格按内容布局并在局部横向滚动。输出不用接收端未支持的 `text-indent`、`table-layout`、`overflow-wrap`、`word-break` 或 `border-spacing`，不为迁移主题放宽接收软件的 HTML 安全规则。

图片路径相对于最终正文文件的位置解释。原文在其他目录时，先把相对 `src` 换算为从输出正文目录可定位的同一素材；也可在任务中使用已确认的绝对输入路径，然后交主入口便携处理，最终便携 HTML 不留下本机路径。禁止搬动用户素材或将路径错误当作缺图删除。

已有 HTTP(S) 或协议相对图片地址按来源保留，不擅改协议、下载或上传。若实际接收端对地址有更严格的限制，按该端契约停止写入并说明具体素材问题，取得用户认可的可接收素材后再继续；不删除图片以换取检查通过，也不放宽软件的资源安全规则。

装配后逐项比较原文与产物的文字、标记、章节次序、列表项、代码字符、表格及图片数量，再进入 `wrap_preview.py --portable` 和 `validate_gzh_html.py`；任何一步未完成不提交到软件的正式正文版本。按 375 CSS px 连读，在 320 CSS px 检查长链接、代码、宽表的回流／局部滚动。静态通过和本地浏览器效果分别记录，微信端粘贴由真实编辑器另验。

## 主题之间的真实差别

素笺使用居中章节、上下细线引文和短居中分割线；墨刊用衬线标题／引文及同行等宽编号；青岚用单独一行的短线编号、浅青引文和较舒展行距；蓝图用同行等宽编号、蓝色侧引线及技术表格；朱砂用较大的衬线编号、暖色引文和左侧短线。保留这些布局差别，不将五套统一为同一标题结构后只换色。普通正文保持连续，原文没有独立提示、图表、引文时不为展示组件而补造。
