# 公众号结构检查规则

由 [公众号排版 Skill](../SKILL.md) 第 5 步读取。它把公开的文章结构检查规范适配为本仓库可直接运行的 Python 标准库检查；不是微信官方规则声明，也不等于上游完整浏览器引擎。

## 结果与处理

- ERROR 是本地生成约束可从 HTML 确定的问题。修复对应节点后重跑检查。
- WARN 是满足了源码级触发条件、但真实影响依赖布局或目标转换的候选。默认使检查返回非零；逐条修复，或只有在依据本条规则确认它是合法例外/非适用时，才用 --accept-warning RULE@NODE=理由 对该节点留明接受依据。不得批量接受、只为通过清空输出或把一个例外扩大到后代。节点编号按解析后的开始标签顺序；同一节点每种规则分别处理。
- 同一 HTML 的每轮验证只重跑检查；需要修时只改触发节点和必要相邻样式，不全文重排、不换主题、不重生图片。修复后再跑同一命令，直到无 ERROR/未处理 WARN。最终报告“内置规则检查通过”只代表本地静态检查通过。

## 上游条款到本地检查的覆盖

| 上游条款/ID | 本地触发条件与判断 | 修复与复检 | 本地状态 |
|---|---|---|---|
| §1.1 opacity | 上游问题依赖透明层和 SVG 背景叠放；本 Skill 已硬性禁用 <svg>，不把任意 opacity:0 误报成同类问题。 | 删除不必要 SVG/叠层；重跑硬规则。 | SVG 静态禁止；其余场景不仿测。 |
| §1.2 caret-color | 显式透明 caret 颜色可从内联样式识别，列 caret-color WARN。 | 改为可见颜色；重跑检查。 | 源码候选。 |
| §1.3 line-height | 显式行高小于显式字号，且同节点有 <br> 或直接文本换行，列 line-height-overlapping WARN；没有文字/图片拼接和明确单行不触发。源码无法确定窄屏自然折行后的重叠。 | 调整该节点字号/行高，或按规则给出准确例外理由；重跑。 | 源码候选，不冒充实际行框测量。 |
| §1.4 width | 未设自适应上限的 <img>、含正文/内容图片的显式数值固定宽度列 width WARN；50%、100%、auto 不按固定值报告。无文字/内容图片的小尺寸装饰不按正文布局宽度报警。祖先或节点含 data-ignore-width 时，对该节点及子树豁免 width 候选，其他规则仍检查。 | 常规图片用 max-width:100%;height:auto；无必要固定宽度改成比例/自适应。确有横向滚动、裁切或不可改第三方固定组件时，优先在最窄适用容器加 data-ignore-width 并重跑——已被标记跳过的 width 项不再用 --accept-warning；若不能使用该标记、但有依据确认该精确候选是合法布局，才逐节点用 --accept-warning 留明理由。 | 源码候选；不把候选称为多屏实测溢出。 |
| §1.5 height | 有可见文字的节点设置 height:0，或极小高度配合 overflow:hidden，列 height WARN。 | 去掉多余固定高度/裁切，或确需该效果时按具体节点理由接受；重跑。 | 源码候选。 |
| §1.6 text-align | start / end 静态识别为 WARN。 | 改用明确的 left、right、center 后重跑。 | 源码确定。 |
| §1.7 SVG begin | 上游针对 SVG 动画只设 touchstart；本 Skill 禁用 <svg>，因此当前输出由硬规则拦截。 | 仅在未来授权开放 SVG 时，再为 touchstart 与 click 双端补测。 | 当前不适用。 |
| §1.8 pre | <pre> 的内容可能是代码，也可能是普通正文，不能仅凭标签判断语义；本地代码组件使用通用库规定的代码块结构。 | 生成时普通段落不用 <pre>；代码字符按通用代码组件保真规则检查。 | 不自动分类，避免把代码误报正文。 |
| §2.1 同标签、同样式单子节点链 | 对非媒体节点，沿相同标签、相同内联样式且仅一个同类子节点的链静态计数；超过 10 层列 nest-depth ERROR，恰好 10 层允许。媒体元素不作为链节点；重复链必须满足同类、单子节点条件才触发。 | 删除冗余的同层包装，保留必要的普通结构/媒体节点，再重跑检查。 | 规范阈值的确定性 DOM 源码检查；不复制上游浏览器布局引擎。 |
| §2.2 span[leaf] | <span leaf> 任意深度包含块级元素时列 span-leaf-block ERROR。 | 把块级节点移出 leaf，再重跑。 | 静态确定。 |
| §2.3 section[nodeleaf] | 输入中出现 section[nodeleaf] 时列 section-nodeleaf WARN。固定来源的规则描述提到受限子项，但没有可核验的完整组件允许清单；因此不猜白名单、不因当前组件库少用该属性而跳过检查。 | 若无明确允许项依据，移除 nodeleaf 并保留普通 section；若有具体依据，按该节点记录理由接受并保留其普通结构。 | 标记静态覆盖；不伪称完成未知允许子项清单。 |
| §3 font-family | 上游为字体栈建议，不是所有自定义字体都算错误；本地代码组件有意使用等宽字体。 | 保留代码字体栈，不把主题字号/字体习惯一概拦截。 | 不自动阻断。 |
| §4.1.1 darkmode-low-contrast | 需先执行暗色转换再判断色彩对比；本地无 mp-darkmode，不凭源色冒充转换结果。 | 主题生成优先保留相邻前景/背景的清晰关系；脚本不声明已运行暗色算法。 | 上游算法未本地化。 |
| §4.1.2 darkmode-no-gradient | 节点自身有渐变背景且其可见文本/后代含可见文字时列 WARN；无文字的纯装饰渐变不触发。仅同一节点的 data-ignore-dm 含 text-bg-gradient 才豁免此项；不会把豁免传播给后代。 | 文字实际压在渐变上时改为纯色文字底或将渐变移至无文字装饰层；真实合法例外才按节点和理由接受；重跑。 | 保守静态候选，不复现 mp-darkmode 标记。 |
| §4.1.3 纯渐变背景 | 渐变节点与后代没有可见文字时，允许保留，不为清零而删除纯装饰背景。 | 保留原组件。 | 静态反例回归覆盖。 |
| §4.2 背景复用、DOM 与视觉顺序 | 样式层叠、透明背景和视觉叠放需浏览器/暗色转换；本地只延续现有定位硬禁项，不推断层叠结果。 | 组件源保持结构简单，生成后由本地确定性规则查可见问题。 | 不宣称覆盖转换引擎。 |
| §4.3 图片文字与透明像素 | img 本身不能证明含文字或透明像素在暗底上的可读性。 | 图片内容与透明效果不作源码猜测；按实际素材意图生成，不把静态检查说成图片暗色验收。 | 未实现图像语义分析。 |
| §4.5.1 darkmode-whitelist | data-no-dark 标记会跳过所标节点转换；检查器列 darkmode-whitelist WARN 提醒，后代不随之豁免。 | 删除无需要的标记；确需保留时逐节点用 --accept-warning 留明用途，不能批量接受。 | 属性和节点范围静态识别。 |
| §4.5.2 !important | 内联样式含 !important 时列 darkmode-important WARN。 | 去掉不必要的优先级强制；合法例外仅能按节点带理由接受。 | 源码确定。 |
| §4.6 data-ignore-dm | 只处理当前节点上的 text-bg-gradient 令牌；本地不忽略后代，也不把它当低对比检测结果。 | 仅为确认的渐变例外使用；重跑确认其他节点仍被检查。 | 渐变节点豁免静态覆盖，低对比转换不覆盖。 |

上游多屏宽度算法包含实际 viewport 测量和阈值；本地选择确定性源码规则，不用固定宽度正则冒充浏览器结论。上表逐项给出实现/不适用/未覆盖范围，不因某一检查通过而宣称等价覆盖全部规范。
