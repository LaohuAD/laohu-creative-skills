# 触发与主题选择 · 回归用例

维护本 skill（改 description、加主题、调路由）后用这组用例核对，确保该触发时触发、不该触发时不触发、主题推荐合理。

## 正例（应触发公众号排版）

- "帮我把这篇 Markdown 做成公众号排版"
- "微信公众号文章排版"
- "gzh，这篇用 XX 主题"（XX 为 theme-index 中已注册主题）
- "把下面这篇文章转成能直接粘进公众号编辑器的 HTML"
- "这篇文章帮我排个版，发公众号用"
- "给公众号排版生成一套新主题 / 自定义风格"（→ 按主入口区分单篇调整与复用主题建设）
- "按这张参考图帮我做一套公众号排版组件库"（→ 按主入口区分单篇调整与复用主题建设）

## 反例（不应触发，应转其它能力）

- "帮我做一个网页落地页" → 前端/web skill
- "把内容做成 PPT" → PPT skill
- "帮我排版这个 Word 文档" → 排版对象不是公众号
- "写一篇公众号文章" → 这是写作，不是排版（先有 Markdown 才用本 skill）

## 主题选择行为

- 用户指定了 theme-index 中已注册的主题 → 直接采用
- 题材有明确契合 → 自动选用最贴合主题，说明理由并继续排版
- 题材无明显倾向 → 采用 theme-index 第一行的默认主题并继续排版
- 用户明确要求自己选或先看选项 → 展示主题选项，等用户选择
- 用户明说"直接排/一键/不用问" → 自动完成结构推断、选主题、排版和校验，交付时说明重要推断
- 主题确定后 → 按"文章类型 → 组件组合配方"匹配组件
- theme-index 为空（无已注册主题）→ 不排版，告知用户先添加主题风格，不要凭记忆编造主题

## 代表性回归样本

- **正例：常规请求直接完成**——用户给出完整文章并说“帮我排成公众号格式”。文章是工具教程，未指定主题。按适用场景选用摸鱼绿，推断并保留文章结构，完成排版与校验；交付时说明主题和有影响的结构推断，不先询问用户确认主题或章节。
- **用户主动选择：先看选项**——用户说“先把可用主题列给我，我想自己挑”。展示 theme-index 中的主题和适用场景后等待选择，不提前排版，也不替用户定主题。

## 关键行为核对（用 assets/sample-article.md 或含代码块/图片的文跑一遍）

- [ ] 未指定主题、也未要求查看选项时，按文章题材选择；无明显倾向采用 theme-index 第一行并继续
- [ ] 用户明确要自己选主题时，展示可选主题并等待其选择
- [ ] 解析结构后判定了文章类型，并按主题库「文章类型 → 组件组合配方」表选组件组合（不是逐段随机选）
- [ ] 点缀组件种类不超过配方表规定的上限
- [ ] 目录/导航组件位置符合主题骨架（摸鱼绿：toc-scroll 紧跟封面之下，在引言和前言之前）
- [ ] 正文引号生成时即为全角弯引号，无需事后替换
- [ ] 代码块走代码块组件，不塞进段落
- [ ] 图片用图片组件、GIF 加动图角标
- [ ] 中文叙述的半角标点改成全角；完整英文句子（如 `Don't merge these notes.`）、英文专名、URL 和代码标识符保留原标点
- [ ] 开头引言卡署名按文章作者/主题定，不固定"甲木"
- [ ] 尾部签名区默认用 `{{作者名}}` 占位（不写死人名）；用户给了署名才填入，原文已有签名则沿用原文
- [ ] 原文已有签名段时合并进唯一签名区，不重复
- [ ] 强调/小标题用小标签或左竖条，无虚线框
- [ ] 代码块提取文字与原代码逐字符相等，包括普通空格、Tab、空行和末尾换行；没有模板缩进混入；真实复制另验
- [ ] `【插入…】` 类待补占位用 2c 居中板块，不是左对齐提示块
- [ ] 骨架按所选主题库的"完整文章模板骨架"装配，不套用其它主题骨架
- [ ] 生成后跑 scripts/validate_gzh_html.py，ERROR 与半角 WARNING 清零

## 自定义主题生成行为

- 用户明确要求长期主题且已给风格描述 → 沿用偏好，空缺常规字段按 theme-generator.md 补全，不重复收集
- 用户上传参考图 → 先 Read 提取视觉特征，只做风格转译，不复刻图中文字/Logo/构图
- 生成的区块库 HTML 保存到 `assets/theme-previews/{theme-id}.html`，全部区块在一页内连续排布，用户**整页一次浏览**确认风格（不逐块展示、不逐块确认），再转标准主题库
- 转换 `theme-{标识}.md` 时：补 `<span leaf="">`、去掉预览用 `id`、补齐五章节（变量表/组件/骨架/配方表/映射表）
- 新主题登记进 theme-index.md 且 `component_lint.py` 0 ERROR 后才算交付；之后"列全部主题让用户选"必须包含它
- 主题 ID 与已有主题冲突 → 提示换名或确认覆盖，不静默覆盖

## 格式兼容用例

- 给 `.docx` → 先跑 `scripts/extract_docx.py` 转 md，核对单元格文字、图片出现位置和换行；脚本报告不支持结构时先处理缺口再转换，按原结构推断继续排版
- 给 `.pdf` → Read 分页读取，删页眉页脚页码、合并硬断行，图位留居中占位
- 给无标记 `.txt`（含"一、二、"式标题）→ 正确推断为 `##` 并继续排版，交付时标明重要结构推断
- 给完全无标题的纯文本 + "直接排" → 全自动：语义分章 + 自拟标题 + 自选主题，交付附决策说明
- 给 `.doc` 老格式 → 提示另存为 .docx，不硬解析

## 维护 · 可验证循环

改了组件库或 SKILL 后，按这个闭环验证，确保不引入排版反模式（大空白、左对齐占位、正文虚线框、平台禁用项）：

1. **改** 组件库 / SKILL / 脚本
2. **源头关**：`python3 scripts/component_lint.py .`
   扫主题索引登记的库及通用库的 HTML 块，复用正文校验的标签、属性、样式、文字包裹规则；仅免除整篇正文顶层容器要求。须 **0 ERROR**。预览生成提示词不作为可直接粘贴的正文组件。
3. **生成** 用改后的 skill 排版 `assets/sample-article.md`（或真实文章）
4. **产物关**：`python3 scripts/validate_gzh_html.py <产物.html>`
   检测正文片段结构、禁用标签/属性/样式、全部可见文字节点的 `<span leaf>` 包裹及半角标点。须 **0 ERROR**。静态通过不代表在公众号编辑器中实际粘贴或显示通过。
5. 任一关不过 → 回第 1 步，直到两关全绿。

两脚本分工：`component_lint` 管「组件库源头不含反模式」，`validate_gzh_html` 管「最终产物合规」。组件合规不保证替换内容和装配后仍合规；两关必须分别检查，不能相互替代。

## 内容、归属与失败分支

- 同一代码输入包含普通空格、Tab、空行、`<>&` 和末尾换行；深浅两种代码组件提取文字均与原文相等，Python 样例仍能编译。真实浏览器与公众号复制效果单列，不以静态通过代替。
- 同一文章分别用全部已登记主题处理 `~~旧条件~~` 与 `==新条件==`；前者始终删除线，后者始终高亮，顺序和文字不变。
- 修复教程包含背景、术语、失败原因、修复方法、验收结果；导读依据本文目的选择后三项。仅两章不补三项；明确要完整目录时五章都出现。实际章节语义不同须重新选，不能记住这个编号答案。
- “这篇换成暖色，不要已有主题” → 成品和预览在作品目录，主题库与索引不变；“将这套风格做成以后复用的主题库” → 按长期建设交接、预览、转换、登记。只确认单篇预览不改变产物归属。
- 图片分别在正文、纯图片单元格及图文混排单元格中出现，重复资源只存一份但保留全部出现位置；图片关系缺失时失败且不产生不完整输出，已有资产不变。
- 自动复制返回 false 或抛出异常时只选中正文，提示直接复制；成功才显示成功。无法建立选区时指向干净正文文件，不能声称已选中。实际浏览器核对工具栏不进入选区。
