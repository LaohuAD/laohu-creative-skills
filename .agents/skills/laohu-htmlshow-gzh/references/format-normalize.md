# 格式归一化 —— 万物先转 Markdown，再进排版流程

排版流程只认 Markdown。任何非 Markdown 输入，先按本文件转成 Markdown 草稿，再进 SKILL.md 第 1 步选主题。转换只整理结构，**不得增删改写原文实质内容**；推断标题、段落或格式后继续排版，并在交付时列出可能影响阅读的推断，供用户核对和指定修订。只有现有材料无法支持忠实转换、且不同处理会改变内容时，才先询问。

## 输入类型判定

| 输入 | 判定依据 | 处理 |
|---|---|---|
| Markdown | `.md` 后缀，或文本含 `#`/`##`/`![]()` 等标记 | 直接进流程（剪存元信息按 gotcha 剔除） |
| Word | `.docx` 后缀 | 跑 `scripts/extract_docx.py`（见下） |
| PDF | `.pdf` 后缀 | 用 Read 工具分页读取 + 清噪规则（见下） |
| 纯文本 | `.txt` 或粘贴的无标记大段文字 | 语义推断结构（见下） |
| 网页/富文本 | HTML 标签或明显剪贴板样式残留 | 剥样式、按语义映射成 Markdown |
| `.doc`（老格式） | 后缀 | 无法直接解析——请用户在 Word/WPS 里另存为 .docx 再来 |

## Word（.docx）

```bash
<SKILL_ROOT>/scripts/extract_docx.py 文章.docx -o 文章.md
```

脚本零依赖：标题样式（Heading/标题 1-6）→ `#`–`######`，粗体→`**`，下划线→`<u>`，列表→`- `，内嵌图片解包到输出目录 `images/` 并以相对路径引用。图片按内容 SHA-256 命名，同内容复用，不覆盖已有文件；Markdown 输出已存在时默认停止；只有用户已明确授权覆盖该 Markdown 输出时才可加 `--force`，该参数不覆盖图片。显式换行保留为 Markdown 硬换行，制表符转成四个不换行空格作为可见分隔，不声称保留 Word 自定义制表位。普通段落和表格单元格共用按顺序提取文字、换行与图片的方法；图片资源可以去重，正文中的每次出现及位置都保留。脚本将表格转为 Markdown 表格，单元格内显式换行用 `<br>`、制表符用同样的可见分隔；合并单元格按普通格处理。脚本先解析并收集图片，再受控落盘；处理或输出失败时清理本轮新建图片，保留已有图片与输出。无法解析的图片关系、缺失资源、文本框或未支持正文结构使脚本报错且不生成输出；按错误位置取得可转换材料后重跑，不能将失败说成完整转换。跑完读取生成的 md，核对原文信息和推断结构。

## PDF

用 Read 工具直接分页读取（原生支持 PDF），读完按下列规则清噪再组装 Markdown：

1. **删页眉页脚**：每页重复出现的同一行（书名/章节名/URL）、纯页码行（`12`、`- 12 -`、`Page 12`）。
2. **合并硬断行**：行尾无句末标点（。！？；：）且下一行以小写字母/中文续接 → 拼成一段；行尾是标点 → 保留分段。
3. **识别标题**：字号信息拿不到，用纯文本启发式（见下节）。
4. **图表**：PDF 里的图无法提取，位置留 `【配图：原 PDF 第 N 页图】` 占位（会渲染成居中待补板块）。
5. 双栏 PDF 常见串行错乱——发现语句前后不接，提醒用户该 PDF 可能需要人工整理。

## 纯文本（.txt / 无标记粘贴）—— 语义推断结构

**标题识别启发式**（满足越多越可信）：

- 行长 ≤ 20 字，且不以句末标点（。！？）结尾
- 前后都是空行（或位于全文/段落群开头）
- 带序号前缀：`一、` `二、` `1.` `01` `第X章/节/部分` `Part N` `PART N`
- 与后文构成"短行 + 多个长段"的节奏

**分级**：全文最高频的标题模式定为 `##`；其下一级（若有）定为 `###`；文首孤立短行定为 `#` 文章标题。

**全文识别不出任何标题时**：按语义把内容切成 3–6 个主题块，为每块自拟一个 ≤12 字的章节标题（标题要说人话、贴内容，不要"第一部分"这种空壳），并在交付说明中标明这些标题是 AI 推断添加的。

其余映射：空行分段；`"引号金句"`/破折号署名 → 开头引言候选；`1. 2. 3.` 或 `·`/`-` 起头的行 → 列表。

## 网页 / 富文本

`<h1-h6>`→`#`级别，`<strong>/<b>`→`**`，`<img src>`→`![](src)`（外链 URL 原样保留），`<li>`→`- `，`<blockquote>`→`> `；样式属性、span 嵌套、`&nbsp;` 等垃圾全部剥掉。剪存工具的元信息块（原文链接/剪存时间/工具署名）不属于正文，剔除。

## 结构核对与交付说明

转换时按已有标题样式和段落关系推断结构，直接继续排版。交付时简要列出新增标题、合并的断行、未提取的表格或可能的双栏错序；用户可以据此指出要修的位置。除非两种解读会实质改写原文含义且无法从材料判断，否则不要把结构核对变成排版前的阻塞。

## 全自动模式（用户要求直接完成时）

用户说「直接排」「自动排」「一键排版」「不用问我」时：

1. 跳过结构确认与选主题提问，**全链自动**：推断结构 → 按题材从 theme-index 自选最贴的主题 → 排版 → 校验。
2. 交付时**补一段决策说明**（不是征求同意，是让用户可审计）：识别出的章节结构、自拟了哪些标题、选了什么主题及理由。
3. 用户对任何决策不满意，按点改（换主题重排 / 改章节切分），不用重来。

自动选主题与无明显倾向时的默认值均按 `theme-index.md` 的“选择建议”执行，避免在这里维护第二个默认值。
