# 动作语言与画面描述

完整动画的自然语言动作方法以正式资源 [共同动作语言](../templates/styles/motion/vocabulary.md) 为词汇真源。本 Reference 说明何时读取和如何交给工程，不复制词表；若正式资源不可用或其哈希校验失败，先修复输入入口，不临时凭记忆重建。

## 把观看变化写成看得见的动作

Analysis 先明确观众此刻知道什么、画面新增了什么、随后应能判断什么，再用可见对象和动作承担变化。根据该动作真实需要，写清进入状态、触发、对象间关系、路径/方向与速度、重要阶段、接触或揭示、落定、连带反应和退出/交接；不需要的字段可以留白。主体动作、镜头运动和转场分别描述，避免把“镜头推进”当作主体变化，也避免用“更有冲击力”“发生变化”代替过程。

动作句以具体对象和可见行为为中心，写清何物怎样改变、变化怎样服务于当前理解或感受。只在能表达本片内容时使用动作词，不以列完一串术语、节拍数量或某来源提供的动作种类为目标。熟悉和非惯常的运动方法都可参与比较，适配条件和作品中的实际贡献决定取舍；来源的局部条件只约束其具体使用范围。

## 从设计到确定性实现

Brief 仍使用原八个 XML 块。自然语言说明对象的可见形态、尺度、色彩关系、字体排版、材料、光影、空间、动作路径和真实 cue 覆盖。对本片已选成熟来源，先沿用其明确的形状、字体/字号、布局比例、色彩/材料、光影和动作规格；来源未规定或当前画幅无法移植时，才以相对关系补足。写可见结果，不把无关 props、RGB 列表、坐标代码或 renderer schema 当设计正文。

Motion 将承重动作映射到页面实际绘制的对象与状态，并让同一具名时间事件驱动物体、phase、镜头、转场和相关音效。事件开始、阶段、接触、落定和反应须在时间轴和实际关键状态中可追踪；静帧不能代替必要的连续检查。对每个动作只记录真实决定执行的时间、尺度、路径与速度，不能用相似时码或第二套计时器替代共享时间线。

具体动作词汇、常见易混词及共同阶段读法见上述词汇真源；原生页面与时间事件接口、动态验收见 [Showreel 运行环境与输入接口](showreel-runtime.md)。

## 从片段决定选择动作和实现

实现前从当前 Brief 和工程确定该段开始、结束、承重对象、要发生的可见变化、读清或听到什么才允许变化，以及相邻段共用的状态。输入不足且会改变观看结果时，把缺项标到该片段交 Analysis 补定。Motion 可选择现有资源、绘制属性与代码实现，并用可播放证据核对 Brief 对观众的承诺。

先从当前片段所需的可见变化检索真实候选。阅读所选风格及动作条目的完整正文，必要时续读源码、预览或相关工艺，确定采用的是整镜、连续动作组、独立属性或具体对象表现。同一位置的组件应有清楚分工。例如，箭头负责指明连接，主物体负责呈现因果，短标签保持指向同一端口。读源码时核对版本、许可、坐标、对象属性、时间单位、依赖和实际渲染入口。原生配方可优先比较同形路径、遮罩、运动速度或空间层级中的相关写法。[正式动效目录](../assets/motion-library/README.md) · [可复用原生实现](../templates/runtime/laohu-showreel/references/recipes.md) · [分层读取](showreel-runtime.md#设计输入与资源查阅)

### 用真实口播锚点安排书签时间

原例的列表先等待 A，将第一项的时长取为到 B 的剩余时间与 1 秒中的较小值。第一项即使提前结束也等 B，再开始第二项并以 C 为下一个期限。狐跃同样等 A，时长用到 B 的剩余时间。音节演示来自 TTS 的线性推算，使用它时须保留它的时间证据性质。[Manim 书签代码原文](../assets/editorial-sources/bookmark-example.py.txt)

本地按同一版编译 timeline 解析 A 和 B 的目标样本。对确实由语音约束的 phase，按现有绑定使用一个 A 的真实 anchor、明确的 offset 和有单位的 duration。先由 A 和已选偏移得到动作的实际起点 S，无偏移时 S 等于 A。需要在 B 落定时，给 duration 写 B−S。设有上限时先把上限换算到同一采样时钟，再写 min(B−S, 上限)。B 到来早于实际起点或与起点重合时，核对锚点和设计次序后再接线。以 24kHz、上限 1 秒为例，实际可用间隔 1.6 秒时给 24,000 样本的 duration，0.6 秒时给 14,400 样本。若下一动作必须等到 B，另以 B 为下一 phase 的 anchor，前段提前完成时保持其落定状态。B 到 C 的规则相同，各段各自核对可用时间和上限。[相位与声音事件接口](speech-cue-binding.md#相位与声音事件如何接线)

关键词锚分别指向真实的出现实例及词边界。只有句段证据时，按实际允许的句段精度写 segment 方案，或将依赖词级同步的动作留待真实词时码。revision 或 planSha256 变化后从新编译结果重解 A、B、C 和每段 duration，重新绑定 phase 与共享声音事件，并在实际起动、提前落定及下一事件时回看。口播动作的绝对秒数由这次绑定得到。

源文件中的参数、案例、限制和许可证按正式出处保存。只有已读且对当前决定有贡献的原文进入本片方法。采用其中的数字或顺序时写清其起点、单位、范围和本地改动。参考资料的外部 API 和代码示例供核对策略，工程按原生入口交付。[正式来源清单](../../laohu-analysis/assets/editorial-sources/SOURCES.json)

把选中的方法接成 `render(t)` 可重复读取的实际动作。按 Brief 对应片段和唯一事件时钟，将对象进入、中态、触发、声音、落定及接续映射到真实绘制结果。字幕与画面需要同时可读时，连看是否留出了足够的实际画面时间。用当前版本穿过代表帧前后连看，动效确认关注方向、落点、阅读、声音与节奏。只有目标图时给目标图状态，局部实渲按其证明的范围发布。Brief 仍须具体说明待做的画面和相邻段状态，缺设计决定时由 Analysis 在唯一 Brief 补齐。[制作协作](production-collaboration.md) · [动态检验](showreel-runtime.md#动态检验声明与实际工作台入口)
