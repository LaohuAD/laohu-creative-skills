# Garden motion recipe integration

This reference maps each of the 15 source recipe sections to its exact pinned snippet, helper dependency, local input, and actual renderer. The production consumer is `templates/adapters/laohu-motion-recipes.js`, called by `scripts/render.mjs` and the existing Film scene renderers. Source pins and provenance stay in `templates/maintenance/source-ledger.json`; original snapshots are private maintenance materials kept as needed and are not distributed with production. Source comparisons require an explicit `MOTION_SOURCE_ROOT` pointing to an actually available snapshot; if it is absent, source comparison is reported as not performed. Ordinary production does not load or depend on the snapshot.

The local runtime is `templates/adapters/laohu-motion-recipes.js`. Recipes 1–11 and 13–15 are consumed from a `custom:laohu-motion-recipes` Motion object with `objects[].data.motionRecipes[]`. Recipe 12 is a post-frame pass selected by `scene.motionPostProcessing[]`. `scripts/render.mjs` validates the selected catalog IDs, calls the adapter with MotionCore’s current scene-local seconds, prepares browser SVG frames before drawing when recipe 10 is selected, and records actual consumer calls in the render receipt. Film `/1` motion-scene and ASR-cut Film `/2` motion-scene segments call the same `render.mjs` entry and apply the same schema validator; no Garden page or new timeline is inserted.

## Source method and consumer map

1. **Masked text replacement** — Source snippet `recipes.md:11–29`; helper functions `motion.js:9–12, 14–26, 43–55`. Local consumer `drawMaskedText` reads `items[]` with text, font, position, size, color, start, gap, and optional exit times. It measures every actual browser glyph with Canvas `measureText`, sizes the clip from ascent/descent, and rejects any replacement whose old text has not finished exiting.

2. **Leading/trailing edge stretch** — Source snippet `recipes.md:31–42`; helpers `motion.js:43–69`. Local consumer `drawStretch` reads `moves[][]`, `y`, `width`, `height`, and color, and keeps the fast and slow edge spring choices from the source. `springTo` uses elapsed seconds and treats the first key’s value as the initial value.

3. **Shape state chain** — Source snippet `recipes.md:44–60`; helpers `motion.js:9–12, 43–69, 117–123`. Local consumer `drawStateChain` reads same-length `states[]`, `times[]`, and `colors[]`; optional labels fade and exit before the next label enters. It uses the source spring chain and perceptual color mix.

4. **Cursor driven** — Source snippet `recipes.md:63–73`; helpers `motion.js:43–80`. Local consumer `drawCursor` reads point keyframes, press intervals, and optional track geometry. The pointer path is time-keyed; its press state is an explicit interval. Click sound remains an `audio-plan` event bound to the same existing scene event clock.

5. **Zoom through** — Source snippet `recipes.md:76–90`; helpers `motion.js:14–26, 137–140`. Local consumer `drawZoomThrough` reads an explicit focus point, scale, and two full-stage source inputs, preserving the source’s two-pass exponential camera handoff. Each input may remain the legacy `{type:"source-frame",path}` single PNG, or use `{type:"source-frame-sequence",path,clock:{kind:"scene-local",sourceStartSec,playbackRate,endBehavior:"clamp"}}`. The sequence manifest path is relative to the scene JSON and uses `laohu.motion.source-frame-sequence/1` with only `format,width,height,fps,frames`; frames are 2–900 ordered PNG paths, relative to the manifest, each at scene size, with fps in `(0,120]`. Manifest and frame paths reject absolute paths, `.`/`..` segments, backslashes, and paths escaping the local manifest directory. `sourceStartSec` is non-negative, `playbackRate` is `[0.001,8]`, and `endBehavior` is `clamp`. `render.mjs` verifies the manifest and every listed frame’s path, stage size, hash, and encoded size, but `prepareFrame` decodes only the frame or frames needed by the current draw. Frame selection is `floor((sourceStartSec + sceneLocalSec × playbackRate) × fps)`, clamped to the sequence; receipts record verified hashes and consumed frame/time/hash samples. Each sequence is limited to 64 MiB of encoded PNGs, and sequence PNG inputs combined across a scene to 128 MiB encoded. Decoded RGBA `ImageBitmap` payload uses a shared 64 MiB LRU: current-draw frames stay pinned during drawing and evicted bitmaps are closed. Encoded and decoded limits describe different resources; base64 data URLs and browser allocation overhead can add memory. A sequence carries only motion already rendered into its PNGs: it does not run source `drawA`/`drawB` live callbacks or renderer handles. Legacy single PNGs stay frozen-frame inputs. Color/text panels remain technical fixtures only; ordinary shots are never frozen automatically.

6. **Wipe reveal** — Source snippet `recipes.md:93–104`; helpers `motion.js:9–12, 28–40`. Local consumer `drawWipe` uses the source `snap(seg(...))` cubic-bezier curve between the same full-stage inputs and accepts the same legacy single-PNG or pre-rendered `source-frame-sequence` descriptors described for recipe 5. It preserves scene-local start/duration and parallelogram slant while clipping the incoming frame on the existing Motion canvas. The frame sequence continues only motion already rendered into its PNGs, not live source callbacks or handles; other recipes and legacy `source-frame` inputs remain still-frame handoffs.

7. **Particle text** — Source snippet `recipes.md:107–131`; helpers `motion.js:14–26, 43–55, 102–109`. Local consumer `sampleText` → `drawParticleText` samples the active browser font’s actual alpha pixels after font readiness, then derives each particle’s start, delay, gather, drift, and burst from the stable index. It does not rely on `Math.random`, hidden downloads, or a separate HTML renderer.

8. **Stateless emitter** — Source snippet `recipes.md:134–148`; helper `motion.js:105–106`. Local consumer `drawEmitter` derives particle birth, direction, speed, gravity, and fade from the sample time, seed, and integer particle index. It has no previous-frame particle state.

9. **Counter impact** — Source snippet `recipes.md:150–159`; helpers `motion.js:14–26, 9–12, 90–95`. Local consumer `drawCounter` reads numeric endpoints, the existing scene-local timing, text style, and impact decay. The displayed number and pulse are visual. Tick or impact sound must be placed in the existing canonical event list and consumed through the existing audio plan; this renderer does not create audio.

10. **SVG stroke** — Source snippet `recipes.md:161–169`; helpers `motion.js:14–26, 9–12`. `prepareFrame` builds the source SVG path with `pathLength="1"`, `stroke-dasharray="1"`, and CSS `strokeDashoffset = 1 - ease.inOutCubic(seg(...))`. It serializes that DOM and awaits `createImageBitmap` before `MotionCore.drawFrame`; `drawSvgStroke` composites the prepared bitmap on the existing Canvas 2D stage and rejects an unprepared or mismatched scene-local timestamp. This preserves the upstream DOM stroke mechanism while bridging it into deterministic frame capture.

11. **Seamless loop** — Source snippet `recipes.md:172–178`; helper `motion.js:4`. Local consumer `drawLoop` computes position from `time % duration` and an integer harmonic. It produces a periodic scene-local path; this does not create an audio loop or authorize reusing an unedited music file as a seamless loop.

12. **WebGL CRT post-process** — Source snippet `recipes.md:181–227`; helper `motion.js:90–95` when canonical hit modulation is selected. Local consumer `buildPostprocessor` → `postprocess` reads `scene.motionPostProcessing[]`, samples the already drawn 2D stage into an independent WebGL2 output canvas, applies the pinned CRT curve/chromatic split/scanline/vignette shader, then copies the result back to the 2D stage before `dataURL` capture. It never calls `getContext("webgl2")` on the canvas that already owns a 2D context. The hit envelope can only read existing scene-local canonical audio event IDs.

13. **Temporal ghosts** — Source snippet `recipes.md:230–240`; helpers `motion.js:70–80`. Local consumer `drawGhost` samples an explicit mover keyframe function at earlier subframe times, with prior samples receiving the source’s decreasing opacity. It does not accumulate prior rendered frames.

14. **Beat and reveal timing** — Garden snippet `recipes.md:242–264` and helpers `motion.js:14–26, 9–12, 90–95, 137–140` provide the canonical timing, pulse and camera/punch orchestration; the snippet calls `drawIris` but does not include its implementation. Local consumer `drawCanonicalBeat` reads event IDs through `MotionOps.findSceneAudioEvents`, derives beat index and in-between progress from the existing scene-local clock, and computes `revealStart = hitTime − duration × revealProgress`. The renderer delegates the iris raster operation to the existing pinned Huashu `TRANSITIONS.iris` through `laohu-transitions.js`; that source owns the concentric ring colors and circular clipping algorithm. For the technical fixture, local timing maps the Huashu source progress to a 2 px inner B radius at the canonical event, then continues linearly to source progress 1 over the remaining duration while retaining the source iris's linear radius curve. A 24fps browser render sampled frames 47/48/49 around a 2.0s hit: the center pixel was Huashu B's `[49,93,56,255]` at the hit and after, while the prior frame remained the iris fill `[250,246,235,255]`. This proves the tested pixel-boundary mapping only; 2 px, fixture colors and center-pixel sampling are not aesthetic thresholds, and normal-speed timing/punch fit still needs a human review of an actual sample. Production A/B inputs are explicit full-stage frozen PNGs, not live source callbacks; use a live scene or existing per-frame consumer when both shots must keep moving. It rejects missing events, film-global event times without the existing time-map bridge, and reveal intervals outside the current scene. There is no recipe-local `BEAT`, `CUES`, or second event schedule.

15. **Canvas perspective boxes** — Source snippet `recipes.md:267–288`; helper source `motion.js:142–188`. Local consumer `camera3d` → `drawBoxes` → `drawPerspectiveBoxes` retains the source perspective basis, far-to-near painter ordering, and directional face colors on Canvas 2D. `camera3d` is perspective; it is not an orthographic camera.

## Sound and ownership

These recipes provide visual methods. Motion counter/cursor notes in the upstream snippets are not audio-generating code. The recipe adapter reads canonical event IDs only where a recipe explicitly uses a hit or reveal. Event sound generation, phase/peak alignment, voice-window ducking, music arrangement and loop editing, and the final mix remain on the actual existing path: `laohu-audio-source.mjs` may choose the pinned Huashu full-source route or write stems into the same `audio-plan.v1`; `scripts/audio.mjs` remains the only final mixer. Locked tracks and source-premix ownership checks remain enforced there. See `references/sound-design.md` and `../../laohu-arrangement/references/sound-editing-and-mixing.md` for the concrete request fields and consumer behavior.

Source identity, MIT license, exact copied source-file hashes, and local consumer mapping are recorded in `SOURCES.md` and `templates/catalog.json`. Source style references are separate and non-callable; a recipe being present in this inventory does not make an unconnected effect executable.
