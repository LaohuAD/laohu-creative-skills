# 内容到运动

本 Reference 把用户目标、主题、口播或交互行为拆成可见的、能交给制作工具的镜头数据。先判断本轮观看/使用任务，再决定什么由关系变化、感官进程或状态反馈承载，什么留给声音或画面。画风选择另见 [视觉设计](visual-design.md)，模板/实际工程与渲染见 [工具、渲染与媒介检查](toolchain-render-and-check.md)。本 Reference 的验收项是可见的镜头/媒体判据；是否帮助目标接收者理解、体验或成功操作，需另有独立观察证据。

## 输入与返回

本 Reference 接收可定位版本的口播/文稿、目标观众与用途、用户选定的体验或交互目标、可用前文、事实来源和限制；没有稿件时以用户创意和明确标记的工作假设为起点。返回有序观看单元（各自的原稿范围、进入前提、主要任务、完成依据及前后单元接入的对象/状态）、观看任务、每段要回答的问题、观众必要前提/前文关系、尚未展开的理解缺口、必要补充及其选择依据和来源状态、段落职责、承重主张或体验进程、事实/状态、对象关系与前后态、画面增量、明确时钟基准的真实锚点或暂定预算及逐镜语义约束。主文据此确认任务边界；这些输出规定观众需要理解/体验什么、哪些事实和关系必须保留，不替视觉设计预选布局、构图或整套材料。主线与视觉设计共同决定表示法和关键画面，再由局部方法与工具 Reference 写回镜头或工程；镜头须可追溯原文、素材或用户指定目标，缺口也须显式标出。

方案、制作或获授权修改任务按本轮作用范围形成表达意图：全片任务在语义单元确定后，结合真实材料与锁定范围说明视觉载体、推动变化的关系/感官进程及因此舍弃的形式；段落、镜头或对象级任务只处理该范围内的承重内容、限制与必要接续，不强制扩成全片设计。仅审查任务检查已有表达意图与声明范围、指出实际缺口并报告，不要求新写蓝图。构思不能只给预选组件补一个主题说明；只在未决选择足以改变关键画面时比较不同方向，专业选择留在主线，不转成用户必答问卷。


## 锁定原文与来源

**建立内容基线。** 先确认输入是原稿、现成口播、用户大纲还是无稿创意，并辨清逐字保留、允许剪辑或允许改写的范围。保存原稿版本并逐段编号；把明确事实、用户观点、助手推断和待核主张分别标记。镜头蓝图由此能返回原稿段落或音轨位置，也不会把推断写成用户原话。

**只核承重事实。** 当数字、因果机制、时间地点、来源真实性、现实人物/事件、用户要求搜索，或类比条件会改变理解时，找一手或权威材料，核对其适用时间、单位、定义和实际支持范围，并把出处与限制挂到镜头数据。证据不足时降低断言、标待核，或删去依赖该事实的画面；无来源内容只能作为明确的比喻、示意或假设，不能伪装成现实证据。

**沿着论证保留重点。** 把主张、解释、限定、例子、转折、结论、情绪句和重复铺垫分开看，判断每段承担承重、支撑还是节奏作用。弱化或删除重复画面已有信息的段落前，先确认没有丢掉条件、证据或必要铺垫。镜头序列最终仍须支撑原稿结论；删去的内容要有具体理由，不能造成论证跳跃。

## 原稿、字幕锁定与屏幕表达

不要把“原稿保留”误解为“每句都必须印在屏幕上”，也不要把“画面能补充口播”理解成可以改写事实。每轮先区分四种文本对象：用户提交的原稿/口播文案；实际录音或对白；逐字字幕、用户锁定的引用/台词或无障碍全文；为了让画面可读而创作的标题、解释语、标签、单位、数据和来源。标记每项文字的版本、来源、是否要求逐字锁定、是否锁定顺序及是否须全程可见。

原稿与实际音轨是内容基线；默认不改。只有用户明确要求把原稿全文当字幕、给出引用/字幕锁定或要求无障碍全文时，屏幕文本才必须遵守逐字、标点、顺序与持续显示要求。无此要求时，不要求把整段口播贴成标题或长句；画面可以选择讲解所需的短语、术语、对象名、数值和限定，也可以为理解重新组织屏幕说明，但需保留事实、方向、条件、来源和论证边界，且新增解释不得伪装成用户原句。若删减会丢失关键事实或限定，应由文字与图形共同补足，而不是只因画面想显得干净就删掉。

在镜头蓝图将每段原稿/音轨 ID、对应的语义动作、屏幕表达 ID、文字权限和必要的原句/数值锚定起来；标明哪些事实由口播承载、哪些由屏幕文字/图形承担、哪些重复只为无障碍而保留。若无旁白，仍须通过图形与分批屏幕说明交代全部关键事实和限定；若全文被锁定须始终可见，则保持全文，使用高亮/关联图形组织注意，不宣称未高亮文字尚未曝光。文字分组、标点、真实字体测量、颜色对比和有效阅读窗由 [字体、字幕与可读性](typography-and-legibility.md) 处理，本 Reference 不重复规定字号或版式。


## 将输入变成观看任务

**先确定每段运动要完成的工作。** 以用户目标和现有材料判断这是要看懂关系/状态、获得审美/情绪/氛围体验，还是响应界面交互；这些作用可以混合，只展开会改变镜头动作的部分。解释任务记录观众要追踪的对象、关系、前态、过程和落态。体验任务记录用户想要的感官走向与其视觉承载物，例如材质、形态、重心、速度或重复/变奏；不要为了“出现新信息”虚构事实变化。界面任务记录用户触发、系统实际状态和反馈。把这一观看/使用任务写进镜头蓝图，交给视觉设计落实，不能只写“有情绪”或“有动效”。

**解释任务先找理解缺口，再决定是否补充。** 输入是本段要回答的问题、目标观众可合理具备的前提、已有前文、原稿明确说了什么及锁定权限。没有受众背景时，按普通观众作最少前提假设并标出不确定处，不因此追问或假定专业知识。检查：只凭本段口播和这些前提，观众能否跟上核心关系并回答本段问题？若能，就不加内容，直接组织已有意义；若不能，指出差的是识别概念、分清易混类别、理解参与者关系/条件、必要尺度参照，还是从输入到结果的中间环节。

按缺口选择最小补充，而不是逐词扩写。概念认识不足时，只补后续理解所需的关键特征或作用；若用例子，须让概念名称与实例中可见的特征/作用建立对应，不能只把术语和实例并排摆出。关系未展开时，先说清参与者、各自作用和适用条件，再选空间位置、符号或图形操作把关系表现为可见的方向、依赖、包含、比较等；列出对象名称或画出一条线本身不算讲清关系。机制从输入直接跳到结果时，补足状态、关键操作/条件和结果之间不可跳过的一环，使变化可追；可以用预先设计的教学演示或简化状态，不必模拟真实机器学习系统，但身份、方向、条件和结果要自洽，并标明示意，不能冒充测量数据。只有在边界会改变判断时才补关键区别/非例；必要的联系、限定、尺度或具体例子也可补入，但“相关”本身不等于需要扩展。核实承重事实；来源不足的事实不得被画面补成确定结论。

当本段问题得到足够回答、需要的关系/条件/过程可追，且再加细节不会改变理解时停止。不要规定每个词都有定义、反例或公式，不强求每拍增加事实，也不把短片扩成完整课程；纯体验、真实 UI 操作或职责总结没有相应知识缺口时，继续走原分支，不强行补知识。把“本段问题—受众前提—缺口—所选补充及原因/事实状态”写进现有蓝图，交给动作抽取、视觉设计与相关局部方法实际消费。

**先按依赖安排有序观看单元。** 对口播/说明内容，沿原稿顺序标出论点、例子、条件、操作、结果和转折，并确认理解每项所需的前提、对象关系与证据；把观众为完成一个观看任务而需要共同看到的对象、状态、条件和证据放入同一候选单元。先检验一个连续视图能否容纳这些内容并给出完成依据，足够就保持，不按句或段自动切分。只有新的观察范围、内部细节、比较条件或证据需要时才拆分；重复且无新观看价值的部分可合并，并记录拆并理由。每个单元在现有蓝图记下原稿范围、进入前提、主要观看任务、完成依据、前一单元交付的对象/状态及下一单元所需接入的对象/状态。若进入前提缺失，或当前视觉范围无法容纳必要对象、条件与证据，将缺口和需要调整的内容交回主线/视觉设计，补足前提或重组观察范围后再拆拍；不虚构证据，也不擅自改变锁定顺序。把有序单元及其完成/双端接入依据交给主文和视觉设计，供后续在单元内抽取动作并映射真实绘制；沿用现有蓝图，不新建表格或 schema。

**在观看单元内抽取语义动作。** 先按已形成的单元任务写明观众要追踪什么：解释任务记录要看见的关系、对照、变化或证据；体验任务记录要感受的形态/材质/节奏进程；界面任务记录要响应的真实触发与状态反馈。解释内容在现有镜头蓝图/工程说明中按承重关系列出动作项，标明对应原稿触发短语/事实与成片锚点、该单元已经/尚未出现的文字和图形、参与对象、输入前态→实际操作→可见后态、理解所需的身份/空间锚点及对应实现位置。单元内若有多个需分别看清对象、作用或结果的关系，拆为连续拍点；可共用同一动作链的关系才合并。句号只是候选边界，不按关键词数逐字制作事件；一项动作可由现有分项或 `custom` 内具名相位表达，不要求一词一个对象或增加 schema。必要的概览、预示、并列比较或职责总结可提前显露相关对象/文字，但需标明其当前是导览/参照/预览还是已成立的处理结果。提供剪后 ASR 时间轴时，先完成观看单元与动作选择，再从真实保留词实例或完整句段范围挑时间锚点；不要把关键词清单直接变成逐词动画，也不要从源时间或字幕位置自行推算剪后时间。

**需要追踪、交接或动态证据时才分开语义实体与绘制实例。** 这类对象用稳定 `entityId` 表示观众需要追踪的实体/关系，用 `instanceId` 区分真实绘制层或表示；一次出现且无需跨状态判断的简单对象不另造身份字段。一个实体可由多个实例接力或并置，同一个实例也可能因遮挡、跳变或状态错误而无法代表原实体。需要跨层交接时写明前态、中态、后态、身份依据和切换理由；同名、同色、共用坐标或共用 scene 都不是连续成立的证据。实际运动是否连续由最终画面和同次绘制状态检查，不能从蓝图声明或观察到的对象反向生成预期对象。

### 主动判断口播后是否需要画面时间

用户已委托完整口播视频/知识动画，且该任务覆盖剪后声音、画面与最终节奏时，主线在每段语义动作图完成后，主动检查口播单元与视觉理解任务是否需要不同节拍。只在口播已经说完一项完整意思、下一项视觉内容仍需时间让观众辨认关系/证据/结果，而且继续说话会实质挤压理解时，提出 source-free presentation；连续说话、保留 source pause、裁掉源静音与增加 presentation 是不同决定，不为“有节奏”在每句后机械加间隔。先检查现有时间线中真实保留的 source range 是否已有有用停顿及其可用时长；该时间计入观看预算，不足的部分才作为净新增请求。source 内是否确有静音或可读时长必须以原音/可靠声学材料判断，ASR/SRT 的空隙只能作为检查提示，不能自动证明。预算由实际画面的对象/文字数量、比较步骤、状态变化、结论落定与正常观看可读性推得，不用固定秒数或静音阈值。

候选 timing request 回到共享剪辑计划作者，包含：当前 plan revision/hash；边界前的真实 `occurrenceId`；刚完成的口播语义单元；画面需要的 `focus`、进入态与离开条件；观看为何需要停讲；画面所需观看总预算、已有 source pause 的可用预算依据、净新增样本数；以及希望的音乐/SFX/安静/无附加声职责。完整声画制作授权已经覆盖这类常规取舍时，由计划作者直接判断并记录，不逐条向用户询问；plan 作者按 asrcut `/2` 的正式 sequence/decision 写入，再重编译 timeline。若时间线已冻结，Motion 只返回该请求并暂停依赖新增时段的局部 scene/event，不能自行拉长场景、平移 `filmTimeSec`、篡改字幕范围或生成私有 timeline；其余有有效绑定的镜头继续处理。纯音频任务、口播内容需改变、用户锁定原音文件/整片时长等范围冲突，只暂停受影响的 timing request 并说明冲突。

Motion 收到含 presentation 的 `/2` timeline 后，该段是已作决定的成片时间，不是新增口播、空白 source 片段或 ASR 识别结果。画面可在此段继续解释刚才说过的关系；cue 精确落在展示开始/结束时，使用 `{kind:"presentation", presentationId, edge:"start"|"end"}`。音频 handoff 说明此时配乐延续/让位、提示、安静或不加新声，不等于最终混音必须全静音；麦克风零样本和 ASR 低精度间隔也不能证明观众没有听到。口播原有停顿仍由 source range 保留，只有经授权的剪辑决定才从原声删去。

**让声音、文字与图形共同交代信息。** 有实际口播时，声音可承担原稿观点、解释和限定，画面使对象关系、空间、过程、对照或证据变得可见；必要的补充按本段理解缺口选择由画面、解释字或声音承担，不要求全部新增内容都变成字幕。屏幕字可用于必要原话、锁定/无障碍全文、术语、对象、所需特征或区别、条件、尺度参照、单位和来源；不机械逐字复写，也不因屏幕有空间而追加无关知识。没有旁白/原音时，仍须用分批屏幕文字和图形表达关键事实与必要限定，不能删除解释后让观众猜；没有音轨只能按语义安排暂定曝光预算，不声称配音同步，也不擅自删掉用户要求的配乐或音效。用户明确锁定全文同屏、或无障碍需求要求保留全文时，全文保持可见，可用活动高亮/图形焦点引导注意；不得称未高亮内容尚未曝光。逐镜记录声音、画面和屏幕字各自的职责；重复整句只在无障碍或用户要求时保留。可暂时遮去图形检查声音是否仍保留必要事实；无旁白时则检查文字与图形能否共同呈现该事实，而不是要求静音画面必须独立承担所有文字细节。

**把语义判断交给适用的局部呈现方法，再接回镜头动作图。** 抽取完对象、关系、前后状态和信息边界后，由主线按本镜真实承重操作读取适用模块：节点间包含/关联/比较/层级需作为结构被看见时读取关系图构建；同一对象轮廓连续对应时读取几何形变；块面遮挡或整体—局部聚焦时读取扁平分层；路径构建/擦改时读取白板；离散网格或姿态步进时读取像素；笔势/受限扩散/透明墨层时读取水墨；证据、说明、演示或体验材料确需裁切揭示、标记/遮罩、并置或跨材料接续时读取拼贴，若材料作为证据再核其来源语境。触发依据是本镜对象、操作和材料目标，不是题材词；用户锁定的材料/风格范围仍限制应用范围。模块只细化局部操作，不替代本 Reference 的事实判断，也不决定全画幅构图；其对象、状态、锚点和时序约束写回同一镜头动作图，再由 visual-design 选择如何共同组织成实际画面，toolchain 映射真实消费者。没有适用的承重方法时使用通用原子动作，不为增加丰富度强行载入模块。

**把抽象词变成可见状态。** “影响”“增长”“压力”“连接”等词只有对应到对象、方向、状态或可观察后果时，才足以驱动画面。将对象和状态具体写出，再选连接、挤压、分流、累积、阻断等动作；若只是情绪表达，标明它是表现性比喻而不是事实机制。静帧与顺播都应能看出变化对象和内容依据，粒子装饰不能代替关系解释。

**让语义推进成为主画面的可辨变化。** 没有真人出镜承担讲述时，若下一句实质推进了意思或关系，主画面要出现相应可辨的对象、关系、焦点、尺度或过程状态变化；若文字本身是主视觉，可由符合其职责的分组、形态/尺度、显现层次、焦点或空间关系变化形成可辨状态。普通字幕替换、轻淡换或角落微动不能借“文字主视觉”名义算作主画面推进。保留锁定字幕，ASR 换行、标点和单字差异不触发逐词动作。真人出镜时，可由与当前语义相符的真实表情、肢体表演或镜头变化承接；“画面里有人”本身不构成免责，仍须检查这份变化能否被看见并接上前后镜头。

默认以约 2 秒没有明显主画面变化为节奏复查点：按实际待读、待比较或待结果落定的内容和所需观看窗判断停留是否必要，不能只用“有意阅读”或“有意停顿”作理由；说不出具体内容与所需时间时，就调整主画面变化或时序。此检查点不是注意力统计，不要求每两秒全幅重排或持续抖动；有明确观看职责的停留可保留。

动态接续以实际画面中的对象状态、空间关系、方向和焦点为准，必要时检查声音桥；从前态、过渡到后态确认同一变化实际发生。稳定 ID、同名对象或同一 renderer 不能单独证明连续。语义转折可有意切开，不强迫每个段落形变衔接。

## 把一句解释编译成对象与事件

解释单元先辨认信息形状：它主要承载主张或感受、工作流、机制、证据、列表、转变、故事还是展示；一段混有多种形状时，只有表达切换服务本轮已定观看任务（理解、体验或真实状态响应）才拆开。纯审美、情绪或体验任务不必硬改写成知识形状或补造事实，可由材质、形态、节奏和感官进程承载。沿稿件/材料依赖记录输入与前提、观众需观察或比较的操作、可验证的后态，以及下一单元要接入的对象或状态。机制要保留不可跳过的中间过程；证据保留来源，涉及数字或比较时还要带单位、口径和基线；列举不伪装成因果或流程，模型判断、预测与人工目标要分清。再选能解释该关系的表示法，并决定运动还是静止；连续视图足够时保持身份和关系，不按句号拆镜。下表只提供候选关系，不是固定模板；同一单元可局部组合，事实不支持的关系不因画面漂亮而补出。把完成依据、对象前后态和下一单元交接写入现有蓝图，交给视觉设计与实际 renderer 消费。

| 内容关系 | 画面应让人看见 | 动作前后需保持什么 | 不应暗示什么 |
|---|---|---|---|
| 因果机制 | 条件/触发、可追的中间机制、结果按顺序出现 | 同一变量、方向、条件与对象身份 | 仅相关或先后被画成因果；中间机制没有来源却被补成事实 |
| 连续过程 | 同一对象经历操作前态、过程态、结果态 | 对象身份、观察角度、基线或容器关系 | 每一帧都换成新的装饰物，令过程无法追踪 |
| 同输入比较 | 共同基线或同一输入保持可见，差异部分被分离/高亮 | 输入、单位、尺度和非比较项 | 未控制的多项差异被说成单一因素效果 |
| 历史关系 | 时间轴/版本/阶段与对应对象一起变化 | 日期次序、资料出处、对象对应 | 共时变化被暗示成因果，日期被挪序 |
| 结构对应 | 部件、路径、层级、容纳/连接关系逐个对应 | 可验证的锚点、连接和整体边界 | 只因外形相像就断言等价，或强行连续 morph |

每个解释动作在镜头蓝图里落成一张小型“变化契约”：

- `object/state-before`：对象 ID 和可见前态；若是实际画面可使用的照片/材料，另写来源。
- `operation`：本段实际动作，写成对象和属性的变化，例如“两个同起点的条形共用零基线，第二条只替换输入值后变短”，而不是“强调差异”。若观看任务确实需要解释组合机制，按下文“需要讲清组合机制时，走完目标变化链”选择输入、展示贡献并组合结果；不把加权流程套到没有这类关系的任务。
- `state-after`：结果在哪里、哪些对象继续作为上下文或退出、什么保持不变、观众现在可读到什么。结果应能追到触发动作及其输入；若操作改变一个目标，须让同一可辨认目标接收结果并显出后态，新加一个输出标签或“回到目标”胶囊而目标本身不变，不算状态更新。
- `visual-increment`：相对口播新增或展开了什么理解所需内容，回答本段哪个问题/缺口，以及它如何实际呈现。可为必要特征/作用、关键区别、隐含联系/条件、尺度参照、证据或中间过程；只多放几个名称/对象不算解释增量。结尾回看可重新组织已有意义，不必强加新事实。
- `evidence/limit`：该动作支持的主张、对应证据和明确不能推断的边界。
- `event/binding`：若进入可程序化工程，标明时间基准、事件 ID、目标对象/图层/相机属性，必要时标出变量如何映射到属性。

若候选实现来自 Video Shotcraft，来源 `actionLandmarks` 必须先对上本片实际语义动作，以及该 landmark 自己实际控制的源文字单位/对象，再由 Film `/2` 的受支持 `actionBindings` 绑定，不能把 `phaseId`、组件名或目录里的 landmark 文案当成动作已经发生。具体源词/行拆分、帧公式与 ASR anchor 限制见[源接入规则](video-shotcraft-integration.md)。若源动作不能准确匹配本片语义或实际口播时间，就保留它为原生源动作/时间，不声称它与口播或音效同步；主线仍可改用 Motion 方法表达本片动作。

### 需要讲清组合机制时，走完目标变化链

只有当观看任务要求观众理解“哪些输入怎样按某种关系作用并形成结果”时，才使用这条方法；普通定义、没有组合关系的说明和纯体验任务不套用权重流程。先选一个确实要解释的处理目标，以及足以辨认作用的来源输入；保留来源的内容或数值、必要单位/出处和彼此身份，不用空 token、无语义色块或统一线条代替输入。再依据已核实的机制明确每个来源怎样关联或作用于目标，把该关系应用到对应输入，呈现各自可辨认的贡献，按机制组合成结果，并按实际机制呈现结果类型：若它更新既有目标，就让同一可辨认目标接收结果并显示前态到后态；若它生成新的结果对象，就让新对象作为输出出现并标明其结果身份，保持来源与贡献到输出的关系可追，不强行把输入/目标与输出认成同一对象。

真实运行或测量主张只使用有来源的权重、输入与结果，并保留它们的条件、单位和适用范围；没有实测值但需要解释原理时，可构造教学关系或数值，须在画面邻近位置标明“机制示意/教学构造，非模型实测或输出”。构造值也必须遵守所讲的已核机制，不能把示意当成任意配色或造势理由；同时不能因缺少实测而抹去理解机制必需的输入差异。若本镜需要比较不同关联程度的影响，才固定输入、只改变构造的关联因素，再依同一机制呈现各自贡献与目标结果；若不需要这项对照，仍可用单个可追踪的关联→贡献→结果讲清给定实例，并按实际机制呈现其结果分支。等权汇总可以示范求和，却不能替代本镜需要呈现的关联差异。若机制本身并非加权关系，就表现它实际采用的作用方式，不补造权重。

作者可用 `inputs → per-source relation/contribution → combined result → result state` 提醒自己核全链；这只是思考简式，不是镜头 schema，也不要求展开完整 Q/K/V、公式或所有位置。随后按机制选择结果分支：更新既有目标时，保留同一对象身份并呈现其前后态；生成新输出时，显出与输入可区分的新结果对象，并让来源及贡献能追到该输出。预演与最终媒介按整条链检查：起态辨认处理目标和来源，过程中关系与各项贡献可分，合成符合已核或明确标注的教学构造，落态按实际机制看见目标更新或新输出。若本镜的机制会更新既有目标，却只见关系线、总和框或“回到目标”标签而同一目标未变化，须修正该镜；任何结果分支若缺少可追的贡献或组合，也不能把标签或其他结构检查当作链路完成。

动作选择要由解释功能驱动：drawing/reveal 适合展示某对象逐段出现的过程，morph 仅适合有可靠部件对应的同一对象状态转换，camera zoom/pan 用于真实的整体—局部注意变化，mask/clip 用于揭示范围或保护局部，layer/alpha 用于控制遮挡和焦点，比较也可通过同框、镜像或同尺度位置移动实现。逐镜不需要这些字段全填；没有对应运动，就让该动作静止并说明落定任务。

### 反馈循环与重复迭代

仅当本段实际解释“结果/判断产生差距，差距触发更新，更新后再看结果”这类反馈机制时，才把迭代编成可见动作。先让观看者认出处理目标和本轮结果，再把差距连回会被更新的同一目标/参数，展示更新后目标状态确实变化；只画样本、箭头或运输线反复经过，不足以表达反馈更新。若为时长压缩多轮，应保留同一目标身份、变化中的结果或参数和每轮差异，避免把多轮画成一条静止结果外的重复搬运。所用数值/状态没有实测时标成教学构造，并遵守已核机制。一般步骤、清单或无更新含义的重复动作不套用该规则，也不强行加入训练循环。

**不要让字幕词数或关键词命中成为唯一视觉驱动器。** 两句口播字数相同，可能分别需要因果路径、共用基线或历史时间轴；一个词也可能只是一句修辞，不该触发新图形。检验办法是暂时遮掉文字：画面是否仍能看见本段真正的对象关系和结果？再单独看口播：声音是否保留了必要主张与限定？两者分工不同但互相可追。


## 高风险内容的可视化规则

### 因果机制

只有来源支持“甲导致乙”时，才把因果画成触发、可追踪的中间机制和结果，并在各镜保持变量身份与方向。若证据只说明相关或先后，就分开表现并标明性质，不加因果箭头。播放和对照来源后，画面所声称的因果强度必须一致，触发、过程与结果都能定位。

### 比较

比较前先核对对象、单位、口径、时间范围、测量方法和基线；能换算时标明基准，不能直接相比时分组呈现并说明口径差异。可比数值用同尺度与同单位，不用长度、颜色或运动速度制造来源没有支持的差距。观众应能辨认比较对象、方向及其依据。

### 步骤与过程

先区分因果步骤（前态如何触发或改变后态）、时间先后（状态依次发生但不据此声称因果）和目录（只列项目）；只有前两者的真实状态变化才适合用操作或先后动势呈现，目录不能画成因果链。按本段机制选择观众需要持续辨认的对象身份、状态与必要参照，每一步让人看见前态怎样变成后态，下一步再按内容机制消费前一步的后态。可以同框更新、局部放大、跨构图重排或切镜；对象身份连续不等于固定机位。对象交接或重新开始时，保留或明确必要身份、状态和基准，避免画出材料未支持的连续关系。

### 数字与数据

数值入画前补齐改变含义所需的单位、分母、基线/零点、时间段、样本范围及绝对量或比例定义。坐标轴、条形起点、图形面积和动画变化都服从同一数值口径；若仅作示意，明确标“非按比例”。最终画面应能读出必要口径，比例与绝对量不会被运动混为一谈。

### 类比与比喻

把目标概念与熟悉对象之间确实对应的属性，以及不应延伸的边界写入镜头说明；只动画化有效对应部分。失效处用口播/屏幕注释说明或及时退出类比，避免装饰细节带出新结论。成片应能看见对应关系和边界，不把类比道具误标为真实机制组成部分。

### 来源、档案与现实证据

当画面看起来像文件、截图、照片或新闻材料时，先确认实际文件的身份、语境和对应主张，并在工程资料记录来源。没有可用原件就改用中性、明确标作“示意”的视觉材料，不制作仿制件冒充证据。镜头里出现的证明力必须能回到来源，资料缺口不能被逼真的拼贴质感掩盖。

## 节奏与时间轴

**先为每个锚点标明时钟基准。** 区分源素材全局秒、成片全局秒、镜头局部秒和局部帧；局部帧同时记录它所属的 fps。不要留下没有基准的裸时间值。需要与旁白同步时，已有音轨就按实际版本标记句首、关键词、转折、停顿和结论；只有文稿却仍要求同步时，可先按理解节奏设计，并标“设计预算/待原音对齐”。无旁白动画、交互或界面动效按目标时长与事件顺序安排，无需等录音，也不加待配音标记；这不等于全静音，用户要求的 BGM/SFX 应保留并按现有音源或明确事件锚点安排。只有用户明确要求无任何音频时才走全静音分支。缺少音轨不会阻塞无旁白画面设计，但也不能伪造音频同步、擅自添加或删除音轨、购买或生成配音。相对预算只表示设计时序，不得伪造成 ASR 或音轨时间。时间轴应明确采用哪一条分支；任何估算不能冒称真实音轨同步。

Video Shotcraft source landmark 只给源组件自己的动作时间。先让动作匹配本段需要观众看到的语义事件，再按真实源 fps/local frame 转成 Film `/2` 输入；film-global 只能按成片时钟安排动作，不是 ASR 词级同步。asrcut-v2 的 point anchor 必须指向保留时间线中真实 occurrence 与 token 时间；默认语义关联允许屏幕解释字不同于口播，只有 `textRelation:"literal"` 的逐字字幕/词级高亮才要求词面一致。设计蓝图仍须让 `semanticCueId` 可追溯到本段原稿/语义动作，但运行时只校验其 ID 格式。`audioEventId` 是同一事件声部引用，不是根据源运动自动生成声音。详细 source 字段、帧界与不支持情况按[源接入规则](video-shotcraft-integration.md)执行。

**让阅读任务决定停留时间。** 长标签、数据、方向切换、细部证据和新术语都增加观看负担；按实际尺寸和播放速度给出辨认、比较和回看的时间。静止本身可以承载意义。若画面挤满信息，先删弱项或拆镜，不靠机械加速解决。最终正常播放时，必要文字与对象应可辨；时长根据当前任务而定，不套统一秒数或字数线。

**在段落交接处清理焦点。** 前镜尾部、转场、字幕和声音若同时变化，容易让观众错过边界。用明确结束状态、匹配动作、间隔或切点交接；只有内容连续时才用形变或运动连接。顺播应能辨认本段何时结束、下一段何时开始，结论也要留有足够呈现时间。


## 交给实现的镜头规格

**把镜头说明写成工程可接手的数据。** 需要方案或开始制作时，每镜记录稳定 `ID`、原稿段/音轨版本和带基准的时间锚点、主要观看/使用任务、事实或系统状态、口播/画面/文字分工、对象状态、构图空间、动作进程与停留、声音/静音、转场、素材来源、实现方式和验收条件。镜头长度可按媒介与预算填写或标待定；工程应能按 ID 对应，素材、时间和事实缺口不能留白。

**把需要保持的语义约束交给实现。** 若事实读法依赖对象身份、单位、基线、方向、前后状态、来源真实性或条件，就给对象稳定名称/视觉编码，并在镜头或工程中区分不可变项与可变项。蓝图还要标出后续步骤读取的实际后态；若该步骤是新一轮、重置或另起比较基准，则记录它的起始对象、位置与基态，避免旧状态无意滞留。每个影响事实读法的变化都能回到相应内容依据。

**实现改变设计时同步改记录。** 工具无法实现某镜头、素材改变了原设计或必须替换媒介时，说明限制及观看后果，再选不改变内容的可行替代；将变更同时写回镜头规格与工程记录。最终工程、蓝图和交付说明必须一致，可能影响理解的替代不可隐去。

若镜头交给 Video Shotcraft `/2`，在已定语义蓝图后再补真实 source catalog ID、原组件路径/hash/export/commit、允许 props 或 layers、source frame duration、composition group、film window/ASR unit、语义/声音锚点和 placement owner；严格字段与拒绝边界见[Video Shotcraft 源接入规则](video-shotcraft-integration.md)。这些字段只用于工程接手，不改写本段已定的观看任务和内容逻辑。
