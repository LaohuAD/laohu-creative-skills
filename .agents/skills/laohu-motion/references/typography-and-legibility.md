# 字体、字幕与可读性

本参考负责画面中全部文字的权限划界、气质选字、工程字体绑定、双语字幕消费与真实可读性验收。需要提炼解释性屏显短句时按需读取 Writing 的 [动画内屏显文字](../../laohu-writing/references/screen-text.md)；原生字幕绘制接口见 [原生字幕与章节 helper](../templates/runtime/native-presentation/README.md)。

---

## 1. 先判定文字权限与双通道分工（Mayer 冗余原则）

依据**多媒体认知负荷与冗余原则（Mayer）**：口播与画面图形已讲透的内容绝不逐句复读上屏，否则耳朵与眼睛同时争抢语言通道造成理解损耗。动笔排字前先给画面里的每组文字贴清权限身份：
- **口播原稿 / 录音**：内容基线，默认不改；原稿绝不自动整段铺屏，只有选作字幕时才上字幕轨。
- **逐字字幕、锁定引用与无障碍全文**：原字、顺序、标点与持续可见范围严格保真；用户锁定全文同屏时，用焦点线、高亮或图形引导阅读，绝不拆删或宣称未高亮字尚未曝光。
- **屏显标题、对象标签、数据单位与解释短语**：为画面看懂服务，讲求精简有力（一屏一句，留出大块留白与尺寸对比）；可按理解重排语序，但绝不改变事实、单位、限定条件与来源边界，也不把补充解释伪装成用户原话。
- **无口播 / 静音片**：屏幕文字与图形共同交代全部必要事实与限定，不为了极简删掉关键前提。
- **清扫伪 HUD 装饰角标**：除非题材本身属于监控界面、工程仪表或情报终端，绝不每帧角落挂无信息的英文斜杠饰条（例如无实质内容的双斜杠编号或假时间戳），把视觉安静留给真正主角。

## 2. 字体「引而不抢」的黄金之度、分情境选角与破除左上角母版

### 第一铁律：字体的意义在于尊崇内容与恰当引导注意力，绝不是炫酷（Robert Bringhurst × Brumberger）
依据排版经典 **Robert Bringhurst《字体排印风格要素》**（*"Typography exists to honor content"*）与 **Eva Brumberger《字体修辞学》**，字形在动画中的最高境界是**「先恰如其分地接住观众注意力，随即退隐透明让内容和逻辑发光」**。必须死守中间的审美之**度**，同时警惕两个致命极端：
- **严防极端一 · 过犹不及（炫技抢戏）**：为了追求所谓“有情绪/炫酷”，不分场合硬上夸张狂草、极粗挤压字、耀眼霓虹描边或沉重立体特效——观众光顾着看“这字好花哨”，反而打断思考与情绪沉浸；
- **严防极端二 · 什么都没有（细弱隐身）**：辅助说明、节点名称或引导短句用 300/400 极细字重配低对比灰暗色，在 1920×1080 或手机屏上细如蛛丝、模糊费眼，直接破坏加工流畅度，接不住任何注意力！
- **恰当之度**：无论主标题还是次级标签，**每一级字形都必须笔画饱满、清晰稳健、明度对比通透、松弛有尊严**；选族绝不僵硬写死，每一部片子先审清 **① 题材气质 × ② 说话人当下心情 × ③ 这组字的叙事职责** 再带完整原句去本地 62 款字库实测选角：

| 此刻的真实题材与情绪语境 | 适配的字形人格（不写死，守“饱满清晰、引而不抢”之度，带原句实测） | 推荐的空间演法（打破 PPT 左上角母版！） |
|---|---|---|
| **清明通透的认知拆解 / 商业与建筑美学 / 国际期刊风** | 骨力端庄、笔画对比克制的**中粗现代雕版宋体、饱满人文黑体或中粗温润楷体**（如 `Noto Serif SC 700` 配 `Noto Sans SC 500–600`，避免细如蛛丝的 400 暗字） | 大片呼吸留白、舒展的居中或非对称建筑秩序、字形随物理母体和焦点自然生长，绝不塞进左上角 PPT 框 |
| **宏大宣言 / 炽热感召 / 东方厚重情绪爆发** | 仅在情绪真需要笔锋张力时选用**清晰易认的毛笔楷书或行书展示体**（控制尺度与留白，避免压迫满屏炫技） | 2–3 层错落块面、清透高对比纯色单点爆发，克制配至多 1 处自然手绘互动 |
| **人文思辨 / 故事独白 / 温润叙事** | 有自然弧度与书卷温度的**温润中粗楷体、古典明体或人文仿宋**（确保手机端笔画清晰不断） | 舒展负空间、随主光与视线呼吸温和显现 |
| **真实产品操作 / AI 提示词输入 / 代码与数据现场** | **饱满清晰的现代产品 UI 人文黑体 + 等宽终端体**（纯拉丁等宽字绝不绑汉字） | 直接活在真实输入框/界面边框里，配真实闪烁光标、打字机输入、点击反馈与推镜放大 |

### 打破“左上角 PPT 标题盒”：让文字成为参与演出的演员（Saul Bass / Kyle Cooper）
1. **分辨三层感受，拒绝满屏大喊**：分清事情本身的情绪、说话者此刻的态度、观众这刻应有的体会。声音已经很激烈时，沉稳克制的字反而更有力量；平静的陈述需要拉出思辨空间时，避免用惊呼式大红字把设问变成警报。
2. **每镜按叙事角色决定文字去哪，彻底告别“左上角母版”**：
   - **主标题 / 情绪重锤**：大胆进画面核心舞台（居中跨幅穿景深、对角线劈裂、字窗透景、或独占半秒干净暗/光场一记定音），彻底打破“左上角写标题 + 下面摆内容”的讲义反射；
   - **多点推进 / 连续焦点跟随**：短词直接长在当下被点亮的光核、曲线节点或运动主体身旁，主角移走它就退让虚化，绝不赖在左上角占地盘；
   - **仅当本镜确属多维对照或冷静目录索引时**，才克制退到角落充当坐标，且仍须与整体光影材质融为一体。
3. **具身弧度、尺度起伏与清透纯色（Embodied Cognition × Bar & Neta）**：情绪主视觉大字优先远离机械等角硬斜切与铁皮冲压感，按词义拆出 2–3 层大起大落的体量与错落呼吸；大字配色坚持**清透高亮度纯色与干净光影厚度**，拒绝浑浊脏渐变。
4. **同一口气稳稳继承，口气转折才变字或变势**：普通标签与连续正文保持统一阅读字族；只有在独立题眼、视角反转、人物手记、真实输入框切换或情绪爆发处，才通过字族反差、字重跳变、位置或入场节奏给出新读法。
5. **带着完整原句查字试排**：不要只拿一两个字试字体，始终带本片真实原句、标点与数字查简体全覆盖与字重（剔除缺字豆腐块风险）：
   ```sh
   node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-overview --scope fonts
   node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-search --source fonts --query "<角色、气质、语言>" --text "<完整屏显原句>"
   node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-get --id <font:稳定ID> --text "<完整屏显原句>"
   ```
   本地样张可在 [动画字体样张](../assets/typography/index.html) 中输入原句横向直观比较。

### 破除字库上限：当字本身承担主视觉
本地 62 款开源商用字体（已清理机械斜切、生硬折角与简体严重缺字字族，字幕底盘独立保留）是零版权坑的可靠底盘，但不要把创意锁死在普通横排字上：
1. **按气质检索选族、拒用平庸默认**：中文字体按画面情绪用 `resource-search --source fonts` 结合完整原句实测检索——豪迈挥洒与深沉动情比毛笔楷/行/草，温润手记与人文叙事比楷书、仿宋、古典宋体与人文黑体，轻松活泼比圆润手写笔触粗黑；英文字母与数字混排时单独核对西文展示字的曲线张力与中文基线、字面高度及视觉重量匹配，绝不默认用 Inter/Arial 当主视觉大字。
2. **用工艺把字变成画面机关**：当标题或词眼要当第一眼钩子时，结合镂空透景、离屏遮罩以字为窗、描边笔顺显露（`laohu-motion-recipe-svg-stroke`）、字形轮廓提取（`scripts/laohu-glyph-outline.py`）或可变字重动态演出。
3. **库内仍缺特殊气质字源时**：可按本片授权引入本机已安装合规字体或作者绘制少量定制标题字形；绝不偷偷回退系统默认宋黑冒充定制造型。

## 3. 语义断行、字图关系与有效阅读窗

- **按语义短语手动断行**：避免超长整句压成细密一行、关键词被劈开，或标点/单位孤悬行尾；中文标点参考避头尾习惯，锁定文本保留原标点，可编辑短标题按视觉需要取舍句末标点。
- **字要有自己的地盘**：字与繁忙图形/粒子同屏时，先给文字划出稳定禁入区或用局部退让/底板保对比，不先把场景画满再把字硬塞进缝隙；镜头切入特写前，先让失去指向的远景标题退场。
- **动态入场不计入阅读窗**：文字尚未完整显现或剧烈运动导致难以辨认的时段不算有效阅读时间；完整可读后留足消化时间（中文参考 `字数 ÷ 4.5 + 1.5s`，英文参考 `字母数 ÷ 15 + 1.5s`）。需要提速时**删减字数**，绝不靠压扁阅读窗或缩成蚂蚁字糊弄。
- **随背景与时间动态查对比**：在渐变、照片、实拍或镜头移动背景下，检查整个阅读窗内最不利的那一帧；可用 WCAG 4.5:1（正文）/ 3:1（大字）做工程风险告警，最终以目标手机与桌面尺寸实播识读为准。

## 4. 把选定的字体交给工程

### 在 `brief.md` 声明字体与屏显登记
1. 在 `<direction>` 用 `typeface:` 声明角色字体与支持的整数字重（短名小写字母开头、≤48 字符）：
   ```text
   typeface: display | font:noto-serif-sc-variable | 700
   typeface: reading | font:noto-sans-sc-variable | 500
   ```
2. 在 `<structure>` 用 `<screen-text-registry>` 6 列表登记全部必显主标题、章节名、观点、事实标签与数据（ID、精确原文、材料/cue、方向·画面·出现起止·完整可读起止、对象·作用·空间/动态关系、必显），表外用 `typeface-use:` 按精确 ID 或角色绑定（精确 ID 优先）：
   ```text
   typeface-use: id=title-main | display
   typeface-use: role=对象标签 | reading
   ```
3. **工程真实消费与测量**：运行 `text-contract <project> --text-direction <方向名> --size <WxH> --fps <N>` 核验字体覆盖与本地资产，受控字体自动进入 `fonts/brief/`。页面必须先 `await screenText.prepareTypefaces()` 再置 `window.READY`；DOM/SVG 调用 `screenText.dom(context, id, el)` / `screenText.svg(context, id, el)`，Canvas 先设字号经 `screenText.measureCanvas(id, ctx)` 实测再调用 `screenText.canvas(context, id, ctx, x, y)`。
4. **可变字重随事件演出**：若字体文件真实支持 `wght` 轴，可在 `render(t)` 中由共用事件算出当前 `weight`，同步传入 `measureCanvas` 与 `canvas`/`dom`/`svg` 的 `{weight}` 参数，并检查字重变化是否引起版面跳动或对象指向漂移。

### 原生双语讲解字幕

有口播字幕时，在 `brief.md` 的 `<inputs>` 声明唯一真实字幕源（路径相对项目根，SHA-256 取原文件字节，二选一）：

```text
caption-source: caption-manifest/2 | voice/caption-manifest.json | sha256=<64 位小写十六进制>
caption-source: srt | input/字幕.srt | sha256=<64 位小写十六进制> | source=zh-Hans | display=zh-Hans,en
```

- 已有 `laohu-asrcut` 输出时优先复用其 `caption-manifest/2` 与编译时钟；直读 SRT 时每个 cue 按 `[开始, 结束)` 消费且不反推词级锚点；无口播 `presentation` 时段可暂留上句字幕作阅读延续，但绝不伪称发音区间。
- **中文屏显字幕标点硬规则（`zh-caption/2` 默认，直读 SRT 与 `caption-manifest/2` 一视同仁）**：除非用户明确要求锁定原文逐字标点（`verbatim/1`），中文屏显双语字幕**一律省略全角逗号（`，`）、全角句号（`。`）与屏末顿号（句内长停可换单空格或按语义分屏）**，**保留短并列句内顿号（`、`）、问号（`？`）、叹号（`！`）、书名/引号及小数点、网址等半角符号**——严禁在屏幕字幕一句末尾挂出多余逗号或句号！
- 声明 `caption-source` 后，原生字幕由编译器自动生成受控字项，无需再往 `<screen-text-registry>` 手抄逐条 `cue:` 行；`<screen-text-registry>` 专管画面内自主设计的标题、标签与数据。
- 正式 16:9 讲解字幕统一使用 `native-16x9-standard` 固定阅读安全区与每语言独立行框（防下伸笔画跳动），主画面主动避让底部字幕区；其他画幅单独校准。

## 5. 交付前实播验收

必查四处真实画面与顺播体验：① 首次完整可读帧与退场帧；② 动态背景中最不利对比帧；③ 最密文字段与手机缩略尺寸下的可读性（结合 `qa/text.json` 的 `CUT` / `OVERLAP` / `SAFE` / `TINY` 提示逐条复核）；④ 带着上一句、当前句、下一句连声顺播，检查文字有没有抢先剧透答案、歪曲语气或与主体争夺视线。发现问题定位到具体原因（字号/断行/背景/停留/速度）直接修，绝不静默删字或改数据。
