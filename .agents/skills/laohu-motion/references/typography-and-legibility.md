# 字体、字幕与可读性

本 Reference 为画面中的标题、标签、字幕、数据和解释文字建立可实现、可核验的版式。它不规定一种固定字号、字体、颜色、版面或标点风格；每项选择都要由文字职责、内容关系、实际字形尺寸、背景变化和播放媒介共同决定。事实与作者锁定边界见 [内容到运动](meaning-to-motion.md)，画面整体组织见 [视觉设计](visual-design.md)，Canvas 实际消费接口见 [工具、渲染与媒介检查](toolchain-render-and-check.md)。

## 输入与返回

**输入：**当前有效的原稿/字幕/口播版本，用户锁定的文字与无障碍要求，镜头语义动作与时间锚点，画幅、播放尺寸和实际字体资源，计划中的背景、对象、颜色、运动与停留。

**何时运行：**画面含任何需要观看者读取的文字时运行；全文字幕、无障碍文本、临时标题、标签、来源、单位与数据说明都算。无文字且无阅读任务时不强造版式。

**选择方法：**先辨别文字的内容权限与职责，再决定呈现形式；接着以实际字体测量排版，并沿文字有效阅读窗口检查真实背景对比；最后在目标播放尺寸与正常速度复核。不能先套一个固定版式，再压缩文字去适配。

**返回与消费者：**把文字内容/来源与锁定状态、文字角色、分组和断行、字号与字体、绘制锚点、行距/字距/可用宽度、颜色及背景变化、首显/有效阅读/退场时段写回同一镜头蓝图。`meaning-to-motion.md` 消费锁定原文与可改屏幕表达的区别；`visual-design.md` 消费文字层级、布局和阅读路径；`toolchain-render-and-check.md` 把这些实际字段接到 renderer 并做目标尺寸检查。只写“字要大、排版好看”不算交付。

字体与视觉角色和构图协同确定：先验证观看任务、对象/空间关系、运动时间与曲线能否成立，再用色彩、字体、背景和材质深化注意与读法。但实际字体及字形度量/占位、用户锁定的品牌或外观、承担对象身份/分类/数据含义的颜色编码，必须作为早期结构输入；用户锁定的材料以及原生机制中直接承担运动的材质也不能降成最后贴上的滤镜。深化过程中若改变空间、可读性或动作逻辑，回到构图和时序迭代。正文、标题、标签、数据和辅助说明可共用或分工；字体与颜色须符合本片材料、语言字形、观看尺寸和上下文，并进入实际 renderer。跨镜允许变奏，承载身份、分类、单位或数据的编码须保持可追或明确交接。只把字体名、色板或材质写在蓝图中而没有加载、测字并检查动态背景，不算实现。

## 1. 先判定文字是什么，能不能改

逐项标记文字是：

- **原稿或逐字稿**：默认原样保留。口播原稿没有自动变成画面字幕；只有当它被选作字幕时，才受字幕呈现规则约束。
- **字幕、引用、逐字锁定文字或全文无障碍文本**：保留指定字句、次序、标点和持续可见范围。用户锁定全文时不能用分批显隐、重排、拆删来优化布局；可用焦点线、高亮或相关图形引导当前阅读，但必须承认全文一直可见。
- **画面解释语、标题、术语、数据标签、单位、来源和辅助注释**：不是原稿的替身。只呈现完成当前解释或操作任务所需的信息；可按功能组织表达，但不得改变事实、方向、条件、来源或数值含义，也不得把新增判断伪装成用户原话。
- **口播与画面共同承担的内容**：口播已清楚说出的长句，不必默认整段再次铺屏；无旁白时，屏幕文字与图形必须共同补足全部关键事实和限定。画面不能用空泛标签替代必要解释。

同一镜头可同时有锁定字幕和可编辑标签。分别记录来源与权限，不能把“文字可排版”误解为“文字可改写”。

若文字由剪后 ASR timeline 编译而来，字幕词/句段窗口只读取其真实 `targetRange`；timeline/2 的 presentation 单元没有口播词，不能补造字幕、token 或 ASR timing。presentation 可按视觉意图暂留上一句的字幕，但必须明确这是“字幕延续/阅读时间”，不能把显示区间说成词的实际发音区间。只有 SRT 句段时继续标记粗粒度，不按读速或画面节奏反推词级锚点。

## 2. 按语言单位与阅读任务组织版面

先按文字在本拍承担的主题、对象命名、关系解释、条件或目标、结果及上下文职责分组，再从句意中识别主重音、转折、对象、条件和限定，确定主要字组与支持字组。每组说明它对应的对象、对象组、操作、关系或状态，以及需要与哪些图形同时可读。依据实际字形尺寸、语义分组和当前画幅，与图形共同选择位置和曝光次序；标签可贴附对象，解释语可接续视觉焦点，文字成为主体时也可获得独立空间。必要信息相互冲突时，调整布局、对象去留或展示时序，不先固定场景再把文字压进剩余位置。锁定文字、标点及持续可见要求按原权限保留。

标题可以开启一段解释，也可以在对象身份建立后退场，让主体接管；正文、数据和公式须有清楚的阅读顺序与回看路径。按起态、过渡和落态分别核对字图位置及曝光：动态入场尚未完整可辨的时段不计入阅读时间；字形完整、对比足够且没有遮挡时，运动阶段可以计入。渐变、照片、动态纹理与高亮下，检查有效阅读窗中最不利的真实背景。稳定并置只有在比较、阅读或关系参照确实需要它时才维持，不要求每拍都重排或移动。

断行依据语义短语、标点关系、数字单位和实际宽度。标点依其语言功能处理，不作“一律删除”或“禁止标点”的规则：锁定文本标点必须保留；可编辑的标题或标签可依表达需要选用句末标点；冒号、逗号、括号和单位不能因自动换行悬在无关行尾，也不应被装饰性放大成独立视觉对象。中文标点的避头尾和行间组织可参考 CLReq 的工作草案；它是设计参考，不在此宣称为强制国标。遇到不能靠自动折行处理的专名、公式或数值单位时，手动确定分组并在目标尺寸核对。

避免把超长整句压成细密一行、把关键词任意拆散，或让逗号/冒号成为本行唯一可见内容。允许一行、一组短句、跨行关系、沿路径标注或随对象出现；具体形式取决于信息职责和镜头构图，不设全片共用模板。


## 3. 以真实字体和 renderer 测量

字体选择同时考虑文字角色、字形适配、真实存在/加载状态、实际可用字重、屏幕尺寸与风格语境。先分别判断段落标题、解释正文、对象标签、数据/单位、来源/注释和锁定字幕需要怎样的识别速度、气质与层级；可以有意共用一套字族，也可让标题与正文分工，但需在同一画面核对层级、字面密度、标点舒适度和中英混排，不以字号/颜色/位移单独代替字形选择。不要只在分镜里写字体名：确认实际字体文件/系统字族、版本与来源；核对文件确实可加载、目标语言字形覆盖、实际支持的静态字重或 variable-font weight range，并检查是否被浏览器 fallback 或合成字重替换。`system-ui` 可以是有意选择，前提是实际目标平台的字形、fallback 与跨机器再现要求均已检查；自定义字体也不因知名或免费就自动适配。将最终字体带入 canvas 或排版器，用其真实测量结果检查行宽、字距、行距与可用区域。若自定义字体异步加载，必须等字体 ready 后再量字与渲染；不能以替代字体预览冒充最终字形结果。若可编辑工程需要跨环境复渲染，依许可保留可再用的字体资源或记录明确交付前提；已编码视频中的字形则按最终视频画面核验。

本仓库 Canvas2D scene 的接口边界如下，其他工具走它们自己的实际排版接口并记录等价结果：

- `text.font` 接受 Canvas CSS font shorthand，由它提供字体家族、字重和字形；若没有显式 `fontSize`，字号也来自 shorthand。对象态 `fontSize`（包含动画事件改动后的值）显式覆盖 shorthand 中的字号；改动字号后应重新测量。
- `maxWidth` 触发按 `measureText` 计算的软换行；场景中的明确换行保留。不可再拆的词或单位若本身超过宽度，可以溢出，因此作者要调整其分组、画布布局或可用宽度，不能假设 renderer 会自动缩小或具备完整 CJK 行断引擎。
- `lineHeight` 表示相邻基线间距；`letterSpacing` 表示每个字素之间的像素间距。`x/y` 锚定第一行，其中 `y` 按对象 `baseline` 选项解释，默认是 Canvas 的 `alphabetic` baseline。`layoutText(ctx, text, {maxWidth, lineHeight, letterSpacing})` 返回 `lines`、`widths`、`lineHeight` 和 `height`，文本 renderer 必须实际使用这份布局结果，而不是只输出无消费的测量预览。

把测得的行宽、行数和高度同实际对象、安全边距、图形标签、字幕区、镜头落点一起复核。换屏幕尺寸、字体文件、字号、字距、文案或对象位置后，旧测量失效，需重新布局和检查。逐字、逐词或逐行运动还要按真实拆分结果重新计算完整显现、有效阅读与退场时刻；文案变化既会改变字框，也会改变动画完成时间，不能只核对最终字框。若文字不能在可用空间和时轴内清楚呈现，按授权范围选择更合适的组件、调整屏幕表达或明确变更时序，并同步复核；不静默删除、裁掉必读文字，或延长用户锁定的时间轴。超宽的专名/数值不通过缩字号隐藏问题。

如果本镜选择 Video Shotcraft `TextReveal`，源 props、分行规则、局部 placement 和动作锚点以[接入规则](video-shotcraft-integration.md)为准。文字内容与分组仍先由本 Reference 决定；组件只执行已选的显现方式，不能代替字形测量、对比和完整阅读窗核验。

布局的垂直范围按实际字形 ink/paint bounds 与基线计算；Canvas `actualBoundingBoxAscent/Descent/Left/Right` 返回的 `0`、负值与 overhang 都是有效测量，不能用 `fontSize × 固定比例` 替代。advance、glyph ink 与描边/模糊后的 paint 不是同一个框，排版需要给三者各自的职责。空字形、未加载字体或缺失的真实指标要标为 unsupported/estimate，不要把错误度量当成完整字形，也不能为了让框适配而裁剪必要笔画。

依第 2 节已经确定的阅读单元，把文字、必要图形和可见标注部件共同排版。使用最终加载字体和实际 renderer 参数测得字形/描边/模糊的 `paintBounds`；底板、编号和其他部件分别记录其真实绘制 `drawBounds` 与效果后的可见 `paintBounds`。文字 measurement 中已有的 padding、底板内边距和额外避碰 `clearance` 是三种不同空间，不得漏算或重复计算。候选选位、文字与部件绘制、完整组逐帧登记使用同一组合几何结果；无需底板或附属部件时保持纯文字分支。

把绘制顺序与遮罩也纳入可见边界判断：底板应在字层下面，若场景安排后续对象覆盖文字，就把这段真实 z-order 当成遮挡来处理。动画中可为揭示而暂时遮住部分 glyph，但在蓝图规定的完整阅读状态，遮罩/clip 必须放出全部必读 ink；这是作品自己的阅读状态条件，不是对每种文字动画要求永远完整显露。包围框没有冲突不证明文字在像素合成后可见，之后的黑板/图层也可能把字盖住。

引线按真实端点、线宽、箭头和路径单独检查；不要用跨越大片空白的总 AABB 代替端点/线段关系，也不把所有相交一概判成错误。对象、文字和相机完成各自变换后，应在同一屏幕坐标核对文字/完整组边界与保护区。`chooseLabelPlacement` 只比较调用者给定的候选矩形与阅读区间元数据，不推演对象轨迹，也不判断文字所指。若要声称位置在整个阅读区间稳定可用，候选框与保护框须覆盖区间中需保护的范围（例如扫掠包围框），或披露采样点并拆分/重复检查；局部停点不能冒充全窗证明。变化无法稳定容纳时拆分阅读区间或重构画面。无解时调整构图/分组/时序，不自动删除必读文字。几何结果和完整可运行调用桥的接口契约在 [工具链 Reference](toolchain-render-and-check.md) 维护；它们只是局部保守 AABB，不能替代实际合成、语义或审美判断。实际指标不可取得时标明估算范围，不能把估算称作真实字形测量。

## 4. 颜色对比随背景与时间检查

为文字和当前背景选择可辨的前景/底色组合，别只从色板抽取一个文字色并假定全片都能读。背景若由光斑、照片、渐层、色块、camera movement 或对象移动持续改变，要沿实际阅读区域与有效阅读区间看每个相关时刻。遇到冲突，按实际成因选择可组合的修法：必需对象被挡时共同调整布局、对象去留或时序；纹理/边缘穿过字形时局部改背景、位置、字色或承载层；前景与合成背景颜色接近时按实际合成结果调整其中一侧；多个信息争主次时调整信息强弱与曝光；可读时长不足时重排信息和时序。修法不是固定外观配方，不默认底板、压暗、描边、发光、某套色板/字体/字号/卡片，也不要求每拍改变。局部隔离的范围应只覆盖影响识别的区域；对比数字不能代替字形、留白、层级和整体构图。颜色还要与其承担的语义和画面调性一致。

把显隐分为三个时段：入场、有效阅读、退场。入/出场若尚未完整显现、对比不足或运动妨碍连续阅读，就不计入有效阅读时间；文字虽处于运动或半透明状态，但在目标尺寸下已经完整可辨、对比与遮挡足够且阅读不受妨碍时，按实际可辨时段计入。有效阅读区间须有连续可辨的时长，并在背景运动中仍能区分前景字与底色。不要拿镜头的一帧、一个中间帧或母版像素字号替代实际播放尺寸上的检查。

如项目需要以 WCAG 4.5:1（普通文本）或 3:1（大文本）作工程告警，须先确认该口径适用于当前输出、文字类别及实际播放器显示字号，再按实际前景与背后颜色计算；这只是风险筛查，不是审美证明或所有动画场景的一刀切验收线。没有清楚界定的阅读任务、适用条件或实际尺寸时，报告观察与限制，不凭母版数值宣称达标。

## 5. 验收与返工

至少检查文字首次可读帧、有效阅读窗内的背景变化、镜头间最密文字处和最终画幅边缘，并从正常速度顺播。逐个核对标注是否指向正确对象或关系，字幕、标签、说明和图形是否在同一构图中各有空间；字形边界/底板/引线是否实际压住对象、图片、连线或其他必读文字。核对原稿锁定字句与屏幕内容对应、行序易追、标点未被断行拆坏、字体真实加载、宽度/基线/字距符合读法、正文与背景在有效阅读窗可区分、退场不与下一段文字打架。

工具报告的占位或包围框交叠只能指出需要复核的区域：它不证明像素被遮挡，也不判断语义指向；容器、剪影或有意并置可以合理覆盖。反过来，没有报告交叠也不能证明未登记的元素、纹理背景或动画中间态安全。把实际画面中观察到的碰撞修正后再编码复查；若仅有局部几何数据或抽帧覆盖，明确限定该检查范围。机器几何、OCR、色值和制作方自评不能代替正常速度阅读，也不能单独证明观众理解或审美达标。

若某个关键文字转场确需辨认“裁切/后续层到底遮掉了哪些 ink”，可按 [工具链 Reference](toolchain-render-and-check.md#可选的必需布局证据门禁与文字像素探针) 只对声明的临界帧运行配对像素探针。它以相同场景的目标层省略版本和不受遮罩的字形版本作局部对照；缺字、字体 fallback、未知 renderer 与非支持 blend 均为 `not-checked`。probe 可报告像素贡献、缺失与画幅裁切，不以几何或通用比例取代真实播放，也不证明一般可读性。

实际播放中读不清时，先定位原因再选修法：字号或字重不适、行宽、背景冲突、对比不够、停留不足、动画中移动太快，或图形遮盖。可调布局、颜色、字形与阅读时段；若这会违反锁定稿、总时长、品牌或平台要求，记录具体冲突并保留事实，不静默删字、改数字或降低有效阅读时间。结构检查通过只证明文件字段和接口正确；观众是否读懂仍需真实媒介/接收者证据。
