# 字体、字幕与可读性

本 Reference 为画面中的标题、标签、字幕、数据和解释文字建立可实现、可核验的版式。一般屏显文字的字体、字号、颜色和位置由文字职责、内容关系、实际字形、背景与播放媒介共同决定；选定的成熟来源若已规定具体长相或尺寸关系，应在原生 Brief 中保留这些可见规格及其适用画幅，不能将其降成笼统的相对描述。只有来源未规定、对应方法无法提取或当前媒介不能沿用时，才用相对尺度和自然语言补足设计，再由 Motion 按真实字体、画幅和 renderer 测量落实。Brief 写画面能看见的字形、主次、位置、颜色关系和运动，不抄与阅读设计无关的组件 props、RGB 清单或代码字段。**原生双语讲解字幕**使用单独的字幕 preset，见下文；它不规定标题、标签、数据或其他屏显文字。完整动画的 Analysis 设计负责人以及 Motion 实现阶段都可按需读取 Writing 的[动画内屏显文字](../../laohu-writing/references/screen-text.md)：Writing 提供确切文案、材料锚点和文字职责。视觉设计方法见 [Analysis 原生动画设计](../../laohu-analysis/references/motion-design.md)；字幕 renderer 的当前消费接口见[原生字幕与章节 helper](../templates/runtime/native-presentation/README.md)。

保留成熟来源给出的具体规格。例如[Swiss Editorial 来源卡](../templates/runtime/laohu-showreel/references/styles/swiss-editorial.md)规定全片采用一个 OFL 字族的多个字重，字号不低于 90 px 时字距约 −2%，并要求文字左对齐、落在网格线上；选用这一来源时，Brief 保留这些字号阈值、字距和网格关系，来源未约定的项目再按实际画幅测量补足。

## 输入与返回

**输入：**当前有效的原稿/字幕/口播版本，用户锁定的文字与无障碍要求，镜头语义动作与时间锚点，画幅、播放尺寸和实际字体资源，计划中的背景、对象、颜色、运动与停留。

**何时运行：**画面含任何需要观看者读取的文字时运行；全文字幕、无障碍文本、临时标题、标签、来源、单位与数据说明都算。无文字且无阅读任务时不强造版式。

**选择方法。** 先辨别文字的内容权限与职责。新建原创方向或重设这些文字时，从本镜的语气和观看任务推导用字，再查实际字体、排入原句，并结合对应的画面事件决定动作。沿文字有效阅读窗口检查真实背景对比，最后在目标播放尺寸与正常速度复核。

**原生 Brief 的返回与消费者：**Analysis 把文字内容/来源与锁定状态、表达功能、语言与语义分组、字图关系、主次层级、可见版式、时间行为和阅读任务写回唯一 `brief.md`。若选定的 L2 来源明确规定字体、字重、字号、位置、间距或尺寸比例，Brief 保留这些实际规格，并说明它们作用于哪些文字和画幅；若来源未给定或当前媒介不支持，才以相对层级、字图关系、可见位置和阅读任务说明开放部分。Motion 按这份设计在真实字体、画幅、背景和 consumer 中测量字形，落实剩余版式并核对保护区和有效阅读窗；无法装入时回到分组、翻译或构图处理，不默默压缩内容。Brief 不以 props 或代码参数代替画面描述；字段/时间声明也不能代替字体加载、目标尺寸测量、真实 consumer 或正常速度检查。新项目由 Analysis 的原生动画设计决定文字职责与画面关系，Motion 使用本地 Showreel `render(t)` 实现；Caption `/2` 的实际双语消费规则与 helper 见本 Reference 和原生 helper README。只写“字要大、排版好看”不算交付。

字体与构图一起确定。读懂观看任务和对象关系后，在代表状态用实际字形验证空间和读法，再细化颜色、动作与材质。但实际字体及字形度量/占位、用户锁定的品牌或外观、承担对象身份/分类/数据含义的颜色编码，必须作为早期结构输入；用户锁定的材料以及原生机制中直接承担运动的材质也不能降成最后贴上的滤镜。深化过程中若改变空间、可读性或动作逻辑，回到构图和时序迭代。正文、标题、标签、数据和辅助说明可共用或分工；字体与颜色须符合本片材料、语言字形、观看尺寸和上下文，并进入实际 renderer。跨镜允许变奏，承载身份、分类、单位或数据的编码须保持可追或明确交接。只把字体名、色板或材质写在蓝图中而没有加载、测字并检查动态背景，不算实现。

## 1. 先判定文字是什么，能不能改

逐项标记文字是：

- **原稿或逐字稿**：默认原样保留。口播原稿没有自动变成画面字幕；只有当它被选作字幕时，才受字幕呈现规则约束。
- **字幕、引用、逐字锁定文字或全文无障碍文本**：保留指定字句、次序、标点和持续可见范围。用户锁定全文时不能用分批显隐、重排、拆删来优化布局；可用焦点线、高亮或相关图形引导当前阅读，但必须承认全文一直可见。
- **画面解释语、标题、术语、数据标签、单位、来源和辅助注释**：不是原稿的替身。只呈现完成当前解释或操作任务所需的信息；可按功能组织表达，但不得改变事实、方向、条件、来源或数值含义，也不得把新增判断伪装成用户原话。
- **口播与画面共同承担的内容**：口播已清楚说出的长句，不必默认整段再次铺屏；无旁白时，屏幕文字与图形必须共同补足全部关键事实和限定。画面不能用空泛标签替代必要解释。

同一镜头可同时有锁定字幕和可编辑标签。分别记录来源与权限，不能把“文字可排版”误解为“文字可改写”。

落到具体画面时，沿用 Writing 对每项文字的表达功能、与对象的空间关系和时间行为判断；标题、字幕或标签这些角色名不自动决定字族、颜色、动效或位置。字幕可以与正在解释的图形/标签共同服务一个观看任务，只要实际排版仍能辨认，且观众不必在相冲突的阅读顺序间来回切换。总结句若承担本段主信息，必要时重排对象、扩大文字区域，或在明确保护的区域内让背景退开、遮罩、压暗、模糊或暂时退出；这些是可选构图手段，不是固定配方，支持文字与数据标签仍需在目标尺寸可读。

若文字由剪后 ASR timeline 编译而来，字幕词/句段窗口只读取其真实 `targetRange`；timeline/2 的 presentation 单元没有口播词，不能补造字幕、token 或 ASR timing。presentation 可按视觉意图暂留上一句的字幕，但必须明确这是“字幕延续/阅读时间”，不能把显示区间说成词的实际发音区间。只有 SRT 句段时继续标记粗粒度，不按读速或画面节奏反推词级锚点。

## 2. 从稿件口气选字、排版和动作

### 先决定这行字能让观众更清楚地感到什么

1. 读原句、前后意思和镜头里的真实变化。有当前录音就听重音、停顿和说话对象，看真实界面或物件在哪一刻反馈。分清**事情本身的情绪、说话者此刻的态度、观众此刻应经历什么**。把它落成具体关系，如观众随作者想象一种可能，或先比较两个对象再看到答案。遇到引语、人物台词或界面反馈，先确认这行字是谁发出的、面向谁，以及观众当前掌握哪些信息。
2. 对照相邻段落问这层关系变在哪里。旧话题换了但读法相同，沿用同类文字样式。作者从解释转为邀请、从设问转为判断，或文字由指认对象转为独立表达时，决定哪一项可见变化能让人察觉。如果几种理解都说得通，先取原稿、声音、画面能支持的读法。关键歧义仍会改变作者立场或事实理解时，只确认受影响的部分。证据只支持识别或阅读时，沿用本片稳定的阅读样式。
3. 看情绪或判断由谁先承担。声音已经提高力度或画面已出现危险时，检查加重、震动或突然放大的字是否会把设问读成警告。台词故意保持平静时，可以用稳定的字和激烈的画面形成反差。需要观众先看指针、比较证据或等到状态变化时，让相应对象承担过程，文字按指认或解释职责接上。承重文字确实要站到前景时，直接给它足够的视觉力度和阅读空间。以本段最容易出现的一个误读检验选择。
4. 将判断翻成能画出来的差异。比较笔画粗细、字面宽窄、转折、密度与节奏，以及字与对象的距离、重心、断行和停留。保留能改变语气、意义或阅读顺序的几项。连续字幕使用本节后文的专用 profile。并列标签和同一界面上的同类控制项通常共享字族、字级及呈现顺序，真实操作状态决定何时强调。图像和录屏中的现成字按来源保真。

《五层蛋糕》原稿中，“先在前面等风口”承接作者已做的准备，“如果有一天”把话转向依然悬着的设想。前一句的字可以完整落住，让风继续经过。后一句可以让正在倾斜的塔传递不安，让字保持为一个开头。若两句都用居中重字以相同动作入场，作品会少一处能传递口气变化的线索。同一字族也可以通过真实字重、位置、入退场以及可读时间做出差异。这里的处理针对这两句的前后关系。

字体会参与读者对语气的判断。Hazlett 等 2013 年的两项屏幕阅读实验中，字体与词义的匹配影响了受试者作判断的速度，字体变化也影响了页面的即时语气判断。中文排版的字形联想还依赖使用习惯和语境。W3C 的《中文排版需求》记录了仿宋用于文艺作品和正式公文的实例。这里用语境提出候选，再在真实语句和画面中比较。

### 带着原句查找并比较

从 Motion 的稳定入口查资源。以下是查询形态。命令中的字符串换成本片全部要显示的字、标点和数字，短语不足以核对整行字形。

~~~sh
node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-overview --scope fonts
node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-search --source fonts --query "中文 短句 收束" --text "每一种猫的识别规则"
node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-get --id font:noto-serif-sc-variable --text "每一种猫的识别规则"
node {SKILL_DIR}/scripts/laohu-showreel.mjs resource-fulltext --id font:noto-serif-sc-variable --level L2
~~~

- 用 **角色、该处读法、媒介条件**描述问题，再补必要的字形线索，如短陈述与连续阅读、笔画转折与字面宽度、目标尺寸、单独一行还是与物件同时出现。按结果检查对应的实际字体文件、可用字重、字符覆盖、子集、许可和 renderer。`font:` 条目对应字体文件，`type-use:` 条目对应可借鉴的用法，后者需要根据本片条件落实到可加载的实际字体。返回的用法与样张供比较。没有匹配项时，拆开描述中的作用、字形或语言条件重新查，保留原句覆盖校验。
- 用本片原句、目标尺寸、同一背景和同一阅读窗口试排。先看字形、主次和断行，再让声画动作进入。仍需取舍时比较同族变奏与另一有依据的方案，指出实际差异及代价。中文看密笔画是否粘连、细笔画是否丢失、关键限定是否被换行冲淡。中西混排同时核对尺寸、基线、单位和标点。设计尚未定案时保留当前可行的候选和真实缺口。
- 按本句在时间里要完成的事查动效。先决定静止、整体落定、逐组揭示、物件带动或其它表现，再按相应可见机制检索[动效目录](../assets/motion-library/README.md)，必要时看原预览的起态、过程和落点。沿本片真实的对象和时间选择。字形本身参与形变、遮罩或可变字重时，用当前字形验证轮廓、字腔、字轴和实时可读性。`--text` 的覆盖结果与许可只用于确认候选可用。字和画面是否表达了预计的口气，由试排与播放判断。

### 字本身承担主视觉时扩大字形候选

在本地[动画字体样张](../assets/typography/index.html)换入完整原句，用同一字号比较候选。在所选字体的「字重与来源文件」取得 `font:` ID 和实际档位，再用资源入口核对实际文件、用字、字重和许可。


标题以轮廓吸引第一眼、人物留下一行私密笔记、突发反应需要看得见的性格、文字要像特定年代的实物，或字本身要成为布景时，先从本镜材料选一项需要改变的形状或质地。例如笔画起收是否像人写、字面是否宽紧不一、转折是否硬、字的内部空隙能否让画面透出来。把它和说话人、所在物件、镜头动作一起考虑。然后与本片预计使用的阅读字比较一个有明显可见造型差别的实际候选。这里的对照用于做取舍。标签、连续正文和口播字幕等以连续识别为主的文字按各自职责稳定继承。

1. **字形已经能做出需要的区别时，试实际字体。** 在[字体库](../assets/typography/README.md)按字形类别单独查一次。泛搜“中文”“标题”常把通用字体排在前面；以 `--category 中文书写` 或 `--category 中文展示` 配合 `--text=<完整原句>` 取实物，再读相应 `type-use:` 的适用条件。霞鹜文楷 Regular 和 Medium 子集同属楷书笔意的书写字族，可比较笔画起收与手记感。同一句“等我回来”，留给家人的便笺可用龙藏体和文楷比较亲笔感，郑重的手书落款可试志莽行书，掌机里的存档提示可试方舟像素体。先确定是谁写给谁、字出现在哪里，再挑候选。站酷快乐体和庆科黄油体可在有铺垫的活泼短句里比较轮廓。草书省笔较多，承载姓名、关键事实或快闪字幕时要逐字辨清。Anton、Bangers、Orbitron 的展示文件覆盖拉丁字符与数字；混排时中文另用有覆盖的字体，检查两边基线、字面高度和分工。搜索返回候选后，仍按实际句子查缺字和目标地区字形。
2. **字形合适但表现依赖工艺时，选择实际做法。** 例如文字需要让光透出来，就比较字腔和纸面接触，按 `new:front-lit-jointed-paper-cut` 借鉴真正镂空的标题纸形，或按 `motion-prompt:motion2:133` 研究离屏文字形状与遮罩合成。该动作的源例是英文，当前原句必须另试字形及字腔。需要写出人物真正落笔的过程时，使用已核对的笔触、笔顺或原创路径，再按 `laohu-motion-recipe-svg-stroke` 随画面事件显露。仅需轮廓、字腔或切割时，按[现有字形工具](legacy/video-shotcraft-integration.md#remotion-local-authored-api)从有明确许可的实际文件提取可用轮廓，作为本片 Showreel 的形状输入。轮廓显示先后与书写笔顺分别由真实资料或人工标注决定。字体已转为轮廓、纸片或绘画时，按该对象的实际消费者回看字面与来源。
3. **库内没有适合的造型时，带着缺口继续查。** 字体资产当前已包含上述中文书写和展示样式；具体时期的题字、篆隶、可控笔顺书法、专门为本片作的美术字，仍须逐项核是否有适用原件。先按需要的材质和可见机制查现有风格、动效或项目素材；需要补真实字源时走本片允许的来源与许可路径，或由本片作者绘制少量所需字形。锁定原句的笔画与字面保真，不拿退回宋黑、系统回退字或把某个字体套个纹理当成已完成不同造型。缺少表现所需且获准可用的字源时，标明对应候选暂未成立，保住其他可完成镜头。

选定之前，把同一句放进同一背景、构图和目标尺寸比较。优先看关键笔形、字腔、跟物件的空间关系及是否像该人物或时代留下的东西。接着用同一阅读窗和原片前后关系看显现、落定与退场。字形确实改变读法，且没有吞掉必须识别的笔画、标记或数值，才把所用字体、局部制作方法和实际阅读窗写入对应导演段。最终保留阅读字也要能指出本镜成立的理由，如题字的力量已经由灯光从纸孔中出现承担。全片使用多少字体由各自职责决定。

## 3. 按语言单位与阅读任务组织版面

先按文字在本拍承担的主题、对象命名、关系解释、条件或目标、结果及上下文职责分组，再从句意中识别主重音、转折、对象、条件和限定，确定主要字组与支持字组。每组说明它对应的对象、对象组、操作、关系或状态，以及需要与哪些图形同时可读。依据实际字形尺寸、语义分组和当前画幅，与图形共同选择位置和曝光次序；标签可贴附对象，解释语可接续视觉焦点，文字成为主体时也可获得独立空间。必要信息相互冲突时，调整布局、对象去留或展示时序，不先固定场景再把文字压进剩余位置。锁定文字、标点及持续可见要求按原权限保留。

标题可以开启一段解释，也可以在对象身份建立后退场，让主体接管；正文、数据和公式须有清楚的阅读顺序与回看路径。按起态、过渡和落态分别核对字图位置及曝光：动态入场尚未完整可辨的时段不计入阅读时间；字形完整、对比足够且没有遮挡时，运动阶段可以计入。渐变、照片、动态纹理与高亮下，检查有效阅读窗中最不利的真实背景。稳定并置只有在比较、阅读或关系参照确实需要它时才维持，不要求每拍都重排或移动。

断行依据语义短语、标点关系、数字单位和实际宽度。标点依其语言功能处理，不作“一律删除”或“禁止标点”的规则：锁定文本标点必须保留；可编辑的标题或标签可依表达需要选用句末标点；冒号、逗号、括号和单位不能因自动换行悬在无关行尾，也不应被装饰性放大成独立视觉对象。中文标点的避头尾和行间组织可参考 CLReq 的工作草案；它是设计参考，不在此宣称为强制国标。遇到不能靠自动折行处理的专名、公式或数值单位时，手动确定分组并在目标尺寸核对。

避免把超长整句压成细密一行、把关键词任意拆散，或让逗号/冒号成为本行唯一可见内容。允许一行、一组短句、跨行关系、沿路径标注或随对象出现；具体形式取决于信息职责和镜头构图，不设全片共用模板。

每次排字先确定观众应先读哪一组、哪一组作支持；先让文案与可用画面宽度相容，再用字族、字号、字重、位置和颜色建立这层级。断行沿语义短语与自然停顿，随后在真实字体里比较字距、字偶间距、行距与边缘留白，不把软件默认值当成正确间距。把排版放回实际背景、运动对象和目标播放尺寸：若文字和图形争焦点、行断让语气错位或缩小后辨不清，调整分组、位置、对比或曝光次序，再检查首次可读帧、完整阅读态和正常速度短片。眯眼或缩小画面可快速发现主次不清，但最终判断仍看实际字形、背景和播放尺寸；不存在适用于所有字体和镜头的统一字距/行距数值。


## 4. 以真实字体和 renderer 测量

字体选择同时考虑文字角色、字形适配、真实存在/加载状态、实际可用字重、屏幕尺寸与风格语境。先分别判断段落标题、解释正文、对象标签、数据/单位、来源/注释和锁定字幕需要怎样的识别速度、气质与层级；可以有意共用一套字族，也可让标题与正文分工，但需在同一画面核对层级、字面密度、标点舒适度和中英混排，不以字号/颜色/位移单独代替字形选择。不要只在分镜里写字体名：确认实际字体文件/系统字族、版本与来源；核对文件确实可加载、目标语言字形覆盖、实际支持的静态字重或 variable-font weight range，并检查是否被浏览器 fallback 或合成字重替换。`system-ui` 可以是有意选择，前提是实际目标平台的字形、fallback 与跨机器再现要求均已检查；自定义字体也不因知名或免费就自动适配。将最终字体带入 canvas 或排版器，用其真实测量结果检查行宽、字距、行距与可用区域。若自定义字体异步加载，必须等字体 ready 后再量字与渲染；不能以替代字体预览冒充最终字形结果。若可编辑工程需要跨环境复渲染，依许可保留可再用的字体资源或记录明确交付前提；已编码视频中的字形则按最终视频画面核验。

### 把选定的字体交给工程

全片职责与字体样式放在 `<direction>`，按文字 ID 或相同角色的分工放在 `<structure>`。原文字、方向、对象、出现与完整可读窗全部沿用同一屏显登记表。对应导演段仍须写可见的断行、位置、字图层级、触发、入场与落定，制作前核实所选文件和字重足以实现。

~~~text
typeface: reading | font:noto-sans-sc-variable | 500
typeface-use: id=label-step | reading
typeface-use: role=对象标签 | reading
~~~

`typeface:` 写在 `<direction>`。短名以小写英文字母开头，其余可用小写英文字母、数字和连字符，总长最多 48 字符。最后一栏填写实际支持的整数字重。`typeface-use:` 在 `<structure>` 的文字登记表之外单独成行。上例展示两种作用范围。按角色绑定时，名称使用屏显登记表第 5 列“对象｜作用｜空间与动态关系”中间一段的原文。需要改单项时，精确 ID 优先。相同角色的常规实例可以一次继承，只在实际使用库内字体的地方加绑定。用户已有授权项目字体和已锁定模板按实际文件、许可及工程路径实现。字幕使用专用轨，已合成在图像或录屏中的字依来源呈现。

通过当前项目的 `text-contract <project> --text-direction <方向名> --size <宽x高> --fps <帧率>` 核对字体声明、用字覆盖和本地资源，参数取本轮登记的具体方向和成片规格。项目内选中的本地字体和许可随受控制作进入 `fonts/brief/`。页面先 `await screenText.prepareTypefaces()` 再置 `READY`。DOM/SVG 在实际文字元素调用 `screenText.dom(context, id, element)` 或 `screenText.svg(context, id, element)`。Canvas 先设当前字号，由 `screenText.measureCanvas(id, ctx)` 按绑定字体量字，再用 `screenText.canvas(context, id, ctx, x, y)` 绘制。已转成预置轮廓的数据继续走其实际路径并核对源字形。预览与导出走同一项目、同一映射和同一时间线，用真实关键帧复核字形落实。缺字、缺字重或字体文件不可用时，带本句和登记 ID 回到受影响导演段，比较已核实且获准使用的字体、字重或排版。定下取舍后更新同一 Brief 的资源贡献与字体绑定，以原文字实例和实际规格重新试排。采用正式目录的字体或用法时，沿现有视觉资源流程读取采用项正文并登记其贡献。


### 让字重随同一画面事件变化

当变重或变轻确实让观众看出态度、力量或状态的改变，在对应导演段写出起始字重、落定字重、开始和结束事件，以及变化期间何时需要读清。先用字体目录核对候选文件有可变字重 `wght`，并覆盖实际文字和所需范围。Brief 中 `typeface:` 的整数字重是默认值，未传动态值时仍用它。

在真实 `render(t)` 中从本片共用的事件算出当帧 `weight`。Canvas 把同一个值交给 `screenText.measureCanvas(id, ctx, {weight})` 和 `screenText.canvas(context, id, ctx, x, y, {weight})`。DOM/SVG 把 `{weight}` 作为第四个参数交给 `screenText.dom` 或 `screenText.svg`。这些调用作用于已绑定的实际字体，值须在文件真实支持范围内。静态字重文件只支持声明的单档。其它可变轴、预制轮廓及字幕按各自验证过的消费者使用。

在运动起点、变化中和落定时看实际宽度、字腔及与对象的接触关系。字重变化导致版面跳动或对象指向错位时，先用相同的逐帧字重重新量字和调整锚点，再判断是否保留这个动作。

### 原生双语讲解字幕

在 Brief 的 `<inputs>` 声明一份实际字幕源，路径相对项目根，SHA-256 取文件原始字节。以下两种写法选一项。

```text
caption-source: caption-manifest/2 | voice/caption-manifest.json | sha256=<64 位小写十六进制>
caption-source: srt | input/字幕.srt | sha256=<64 位小写十六进制> | source=zh-Hans | display=zh-Hans,en
```

已有 ASRcut `/2` 时沿用其项目、剪辑计划、时间线、当前译文和样本时钟。直接使用 SRT 时写明真实源语言和文件逐行显示顺序，每个编号 cue 须有有效的毫秒时码及每语言一行纯文本。实际字幕区间按 `[开始, 结束)` 消费。SRT 编译只提供显示窗、原有编号、原文与语言顺序。词级触发继续使用独立的 ASRcut 词锚，原始旁白仍作为声音来源交给工程。工作台和 renderer 共用同份声明。修改字幕后先核实新文件和语言，再更新摘要。当前文件、旧表和声明冲突时先修正真源。

`<screen-text-registry>` 继续登记为画面编写的主标题、章节名、观点、事实标签、专名、账号名、数据和带数字或单位的刻度。原生字幕由声明自动编译为每个实际 cue 和语言的受控字项。只含线段、点或图形的刻度可以直接绘制。旧项目若继续采用显式 `cue:<ID>:<语言>` 行，则沿原表和字幕清单双向校验。迁移到 `caption-source` 时移除旧字幕行，保留全部画面字项。

字幕 overlay 固定在画幅安全区内。正式 16:9 使用 `native-16x9-standard`，保持相同画幅比例缩放和每语言固定字框、行距、基线，避免下伸笔画导致跳动。场景为字幕留出稳定背景和阅读空间。涉及其他画幅或新的可读性目标时，按实际输出独立校准。候选 profile 只用于有明确选区、目的及至多六秒的技术 `probe` / `--draft-probe`。受控报告记录实际 profile ID、mode 和参数。浏览器中创建字幕轨、比例换算、样式和像素检查见[原生字幕 helper](../templates/runtime/native-presentation/README.md#双语字幕轨道)。

忠实复用已经锁定的完整原生镜头或成熟动作组时，先按实际公开的文字字段替换本片内容，保留适用的源字号/字体层级、标题位置、字距/曲线、颜色角色、画幅与 raster 条件。若文字在可调范围内仍无法完整可读，查精确 source index 与用户允许的成熟候选。仍有冲突时带受影响镜头及具体取舍回到方向决定。用户确认开放该部分的排版或文字运动后，在本片项目实现新设计。源组件的字幕样式示例只供相应组件使用；本片口播字幕由独立的 caption-only preset 实施。

普通原创新方向和只借用局部工艺的镜头，按本 Reference 主动选字与排版。每项来源约定只约束采用的部分。复用源动作时可忠实保留其确实依赖的文字条件，同时按本镜原句和观看任务决定仍开放的字形、尺寸、断行和空间。

把实际字形可见范围、基线、字距、行高和描边/阴影/模糊的外扩效果一起检查，不用字号比例或未经验证的通用边界代替真实测量。缺少字体、字形指标或实际 renderer 时，将对应值标为 estimate/unsupported，不把估算说成真实字形结果，也不裁切必要笔画。底板、编号、引线和其他可见部件与文字共同排版，留出各自实际占用空间，避免把 padding、部件内边距和避碰空隙重复或漏算。

绘制顺序、遮罩、图层和相机运动都可能影响实际阅读：在完整阅读状态确认全部必读笔画可见，底板位于字层下面，后绘对象没有遮住文字。引线按真实端点、宽度、箭头和路径检查；对象和文字变换后在同一屏幕坐标复核位置。若文字或随行部件在移动中与主体、字幕或保护区靠近，检查其真实运动范围或逐段采样，不以一个停点替代整个阅读窗口。包围框没有冲突也不能证明合成后一定可读，仍需在正常速度和目标尺寸播放检查。

换屏幕尺寸、字体文件、字号、字距、文案或对象位置后，旧测量失效，需重新布局和检查。逐字、逐词或逐行运动还要按真实拆分重新计算完整显现、有效阅读和退场时刻；不能只核对最终字框。若文字无法在当前空间与时轴内清楚呈现，按授权范围调整分组、构图、组件或时序，并重新复核；不静默删除、裁掉必读文字或延长锁定时长。超宽专名或数值不通过缩字号隐藏问题。

## 5. 颜色对比随背景与时间检查

为文字和当前背景选择可辨的前景/底色组合，别只从色板抽取一个文字色并假定全片都能读。背景若由光斑、照片、渐层、色块、camera movement 或对象移动持续改变，要沿实际阅读区域与有效阅读区间看每个相关时刻。遇到冲突，按实际成因选择可组合的修法：必需对象被挡时共同调整布局、对象去留或时序；纹理/边缘穿过字形时局部改背景、位置、字色或承载层；前景与合成背景颜色接近时按实际合成结果调整其中一侧；多个信息争主次时调整信息强弱与曝光；可读时长不足时重排信息和时序。修法不是固定外观配方，不默认底板、压暗、描边、发光、某套色板/字体/字号/卡片，也不要求每拍改变。局部隔离的范围应只覆盖影响识别的区域；对比数字不能代替字形、留白、层级和整体构图。颜色还要与其承担的语义和画面调性一致。

把显隐分为三个时段：入场、有效阅读、退场。入/出场若尚未完整显现、对比不足或运动妨碍连续阅读，就不计入有效阅读时间；文字虽处于运动或半透明状态，但在目标尺寸下已经完整可辨、对比与遮挡足够且阅读不受妨碍时，按实际可辨时段计入。有效阅读区间须有连续可辨的时长，并在背景运动中仍能区分前景字与底色。不要拿镜头的一帧、一个中间帧或母版像素字号替代实际播放尺寸上的检查。

如项目需要以 WCAG 4.5:1（普通文本）或 3:1（大文本）作工程告警，须先确认该口径适用于当前输出、文字类别及实际播放器显示字号，再按实际前景与背后颜色计算；这只是风险筛查，不是审美证明或所有动画场景的一刀切验收线。没有清楚界定的阅读任务、适用条件或实际尺寸时，报告观察与限制，不凭母版数值宣称达标。

## 6. 验收与返工

至少检查文字首次可读帧、有效阅读窗内的背景变化、镜头间最密文字处和最终画幅边缘，并从正常速度顺播。逐个核对标注是否指向正确对象或关系，字幕、标签、说明和图形是否在同一构图中各有空间；字形边界/底板/引线是否实际压住对象、图片、连线或其他必读文字。核对原稿锁定字句与屏幕内容对应、行序易追、标点未被断行拆坏、字体真实加载、宽度/基线/字距符合读法、正文与背景在有效阅读窗可区分、退场不与下一段文字打架。

承重文字从上一句开始连同原声与画面播放，看到下一句接住为止。检查观众能否辨认说话者的态度、先注意到正确的对象、等到应出现的结果。若字让语气变强、变弱或抢先公布答案，先分辨问题来自字形、层级、节奏、字图位置还是整体声画分工，再只调整直接导致差异的部分。需要分辨原因时，同原句同声画比较改变的一项。在真实观看中把误读指出来，例如候选越像一条警报，越不适合作为等待观众思考的一问。受控绘制日志只能证明文件与消费。观看效果以实际播放判断。

工具报告的占位或包围框交叠只能指出需要复核的区域：它不证明像素被遮挡，也不判断语义指向；容器、剪影或有意并置可以合理覆盖。反过来，没有报告交叠也不能证明未登记的元素、纹理背景或动画中间态安全。把实际画面中观察到的碰撞修正后再编码复查；若仅有局部几何数据或抽帧覆盖，明确限定该检查范围。机器几何、OCR、色值和制作方自评不能代替正常速度阅读，也不能单独证明观众理解或审美达标。

实际播放中读不清时，先定位原因再选修法：字号或字重不适、行宽、背景冲突、对比不够、停留不足、动画中移动太快，或图形遮盖。可调布局、颜色、字形与阅读时段；若这会违反锁定稿、总时长、品牌或平台要求，记录具体冲突并保留事实，不静默删字、改数字或降低有效阅读时间。结构检查通过只证明文件字段和接口正确；观众是否读懂仍需真实媒介/接收者证据。

既有 renderer 的具体字体、测量和组件接口仍由其实际源码、测试与专属工具文档维护；这些接口不能替代当前 Brief，也不会自动成为新项目实现选项。
