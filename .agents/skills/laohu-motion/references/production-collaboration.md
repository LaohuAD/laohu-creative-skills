# 完整动画的 Analysis 与 Motion 协作

新建完整动画、口播讲解和片段混合时，Analysis 在项目根的 `brief.md` 写导演设计，Motion 将它落实为 `render(t)` 画面、共享事件和真实输出。方向尚待选择时，两阶段流程允许同一份 Brief 先写决定首轮画面的内容，再扩成全片。

## 把专业制作阶段映射到本项目

行业流程可能经过 brief、分镜、styleframe、blocking/animatic 和最终动画；不同项目会省略或调整步骤。本项目把需要的决定收进同一份 brief.md，并用现有 Showreel 代码验证，不另造一组文件或审批：

| 专业工作 | 本项目中的落点 | 责任与检查 |
|---|---|---|
| Brief | 唯一 `brief.md` 的原版八个 XML 块 | Analysis 决定任务、事实关系、核心美术、字幕/文字、观看单元和声音职责；核心设计明确后才交 Motion。 |
| Storyboard | `<structure>` 中的观看单元与段内自然导演句 | Analysis 决定内容怎样展开、对象与关系怎样接续；表格用于定位，不要求另画逐句分镜，也不以句子或字幕 cue 自动切镜。 |
| Styleframe | 同一工作台上的方向设计帧 | 普通制作使用真实代码帧。已明确委托 Cover 设计帧时由宿主取得生图实图，待工程阶段用同一状态的实渲对照。方向未定时展示有实质区别的候选，方向已定时展示其关键状态。 |
| Blocking / animatic | 同一代码时间线与必要的连续动作预览 | Motion 核对动作阶段、时长、停顿、接触/揭示、落定和镜头衔接；连续过程必须看连续片段，静帧只证明其实际可见外观。 |
| Animation / finishing | 当前项目的实际代码、素材、声音与最终混音 | Motion 忠实实现 brief，检查真实渲染、媒体、字幕、声音和最终导出；若实现会改动内容读法、关系、美术或声音职责，返回 Analysis 改同一 brief。 |

这些对应关系帮助保留每一步解决的问题，不要求每片都经过同样数量的阶段。用户免除某项确认只免除其指定范围，不会把未做的时间/运动核验变成完成证据。

## 方向探索与全片制作

方向尚待确认时，先按[设计输入与资源查阅](showreel-runtime.md#设计输入与资源查阅)接收 L0、比较相关候选，并读取拟采用项的完整 L2。在唯一的 `brief.md` 里按顺序写 `<role>`、`<inputs>`、`<direction>`。方向写具体的视觉语言、色板、字体、镜头和素材使用，列 `direction-name` 供后续命令选择，列 2–4 个能帮助判断的实际代表时刻。已经会出现在样片中的字项登记在 `<structure>` 内的屏显文字表，尚待确认的头像、Logo 等在 `<inputs>` 说明会影响哪个画面。已经采用且需要继续对照的本地视觉资产可用 `direction-asset` 逐项登记项目相对路径。

```text
direction-name: 纸本剖面
styleframe-source: code
motion-probe: required; reason: 检查五层沿同轴展开时仍能读出上下承接。
explore-moment: assembled@0.6 — 五层合拢，观众能在同一轮廓内数清层数。
explore-moment: separated@3.8 — 层间被拉开，底层留下稳定的识别位置。
```

使用 `scaffold <project> --phase explore --audio <选择>` 创建工程，写实际片段后用 `render --text-direction <名称> --still <秒数>` 逐张取帧。至少发布两张有可见差异的代表帧，用 `progress --stage style --preview <PNG> --frame-source code --frame-event <事件ID> --frame-at <秒数>`。选定明确的 3–6 秒区间，使用 `probe <project> --text-direction <名称> --start <秒> --duration <秒> --selection <镜头或范围> --purpose <要检验的动作>`，再用 `progress --stage style --preview <生成的 WebP>` 发布。同一个 `editor <project>` 的制作进度里，打开关键帧栏查看设计帧和可播 MP4。需要字幕的样片仍核对实际 cue 和文字 consumer。样片的范围止于所选时段，最终预览和正式出片在生产阶段开放。

取得对当前方向帧和样片的真实回复后，用 `progress <project> --stage style --confirm --evidence-text <实际原话> --scope <已确认画面和方向范围>` 记录。把确认的方向继续留在同一文件，补全八块 XML、整片制作片段与逐段导演正文、成片时钟及实际语音和字幕引用。确保 `timeline.js` 使用本轮帧率和完整时长，保留代表时刻的身份及其必要制作证据。请 Audit 检查当前完整设计，将实际发现与检查结论保存到项目内审稿记录，加入一行 `brief-sha256: <当前 brief.md 的 SHA-256>`。运行 `brief-units <project> --final` 检查整片区间和实际 cue，再用 `promote-production <project> --audit <审稿记录相对路径>` 进入生产。已确认可直接提交完整设计的项目可以沿用省略 `--phase` 的脚手架。

方向确认绑定已采用资源、实际画幅和帧率、用户的确认范围与原话、指定画面内的屏显文字和字体、以及真正观看过的 PNG 和动态样片。补充全片导演正文或收录尚未采用的头像无需重新确认方向。修改决定方向外观的资产、所选文字、字体、方向或证据后，重新检查并发布当前方向。此前的旧确认继续按原证据验证，受管旧工程重新开轮并按事件发布新的设计帧时，使用当前范围来记录新的确认。最终预览和导出仍核对完整项目内容及同一版本的导出确认。两阶段工程完成实制后，用 `progress <project> --stage review --publish . --final --text-direction <当前名称>` 发布覆盖成片时钟的最终预览。

## 方向帧的两种来源与回交

1. **按观众要核对的关系选帧。** 从 brief 选决定全片视觉的代表状态、相邻动作段共用的状态，以及过程里改变读法的时点。例如纸模型第一次展开到五层都可辨，可验证材料、层次与阅读顺序。取景框最终锁定机柜，两段共用该状态。筹码触轨之后支路才露出，用实际播放核对先后，需定位变化时再取对应中态。同一状态只换字幕或次要短标签时沿用该状态，按实际字幕区间检查阅读。
2. **把用户选择和出图状态接回 brief。** 明确委托 Cover 或明确要求用生图探索方向设计帧时，由 Analysis 记 `styleframe-source: cover`，使用 [Cover 主入口](../../laohu-cover/SKILL.md) 调用关键帧专项。普通 Motion 路径按本片代码和真实素材取帧。已有确认图可按实际来源、角色与状态直接做设计参考，给过参考图本身不会切换方向帧的生成路线。用户只要提示词时，依 Cover 的交付范围完成，实际出图与制作状态仍按真实进度记载。
3. **Cover 先做代表帧，再派生必要状态。** 委托带上当前 Brief 的实际画幅、制作片段和帧 ID、成片秒数或计划时点、触发、观众此刻要看懂的关系及可见证据、真实素材、需继承对象以及仍可探索的视觉变量。按该时刻的屏显登记交准确原句、文字职责、已定字体 ID 和字重（已有绑定时）。若该帧有原生字幕，同时交当前 cue 和固定阅读区。需要精确排印时，设计图为相应可编辑字层留足位置，宿主可按本轮用途用实际字体叠排。事实、层数、身份或锁定信息先交清，留给图像工具提出构图、造型、材料或用光的设计空间。由宿主调用当前可用且在授权范围内的工具。核对实图后，将接受的变化写回同一份 brief。后续图引用已接受的代表图及直接相关的相邻状态，延续需要辨认的形状、材料、颜色角色和空间方向。实图与任务偏离时修对应图和相关决定，再扩展受它影响的部分。
4. **让图片成为实际制作输入。** Analysis 将宿主实际取得的图片和 Cover 的逐帧制作说明交给 Motion 接用。保留图片的实际文件、来源、所对应的事件与秒数、可变部分和后续接管方式。固定背景、纸纹等可把足够清晰且能合法使用的区域交给工程。会独立移动、变形、推近或遮挡的对象拆成相应图层，或用本片可用的 SVG、Canvas、3D 等方式重建。镜头将露出原图没有表现的一面时，补图、绘制背面或按需建模。精确文字、图例和数据优先从 Brief 的屏显登记与材料制作可编辑层，实图上可辨的误字、额外信息及进入成片后可能冲突的元素一并核对。
5. **同一工作台核对目标、实渲与连续运动。** Cover 实图发布到设计目标对照区。工程进场后，以相同事件 ID 和绝对时间发布本片 `render(t)` 的代码帧，核对造型、材质、构图、文字指向、阅读窗和遮挡。连续变化按 brief 的 `motion-probe` 同轮发布可播放样片，检查目标位置的前后变化。例如取景框经过时只放大它下面的原物，推近时远景说明已让位，细节标签在可读时出现。帧与样片对应当前工程版本。方向确认和最终预览按本轮授权办理，方向或时钟变化时刷新受影响的帧、样片与接缝。发布方法见 [本地工作台](showreel-runtime.md#方向帧与同一状态的工程实渲)。

## 本地制作过程与原版资料的适配

原版 Showreel 的 `editor.md`、`progress.md` 和 `brief-template.md` 保持受保护原样；本地新项目读取或生成 brief 时，按本地规则适配不同版本的工作流程，不能同时把相反条件交给执行者。

正式制作确认 work root 后，默认通过本地实际支持的编辑器进度入口打开同一个项目工作区，让用户看见真实阶段、正在形成的结果和已可检查的预览。已核实的工作台可呈现 brief/style/narration/scenes/audio/review 等阶段的状态、计数与说明，并挂载图片、音频、文档等阶段产物，或进入 shots 与完整 revision 的真实可播工作区；只发布实际已有的内容，不造占位产物。只启动服务不算打开页面；应主动打开真实工作台，无法打开时给出可用链接和当前真实状态。开始阶段、实际状态变化、方向关键帧/动态样片就绪，以及镜头、章节或声音等重要结果完成自查后，更新同一个工作区；不按每次代码动作刷新，也不只在整片完成后才出现。原版 `editor.md` 的默认最终预览与导出流程继续适用；它与本地默认持续展示实际进度并不冲突。原版 `editor.md` 第二段和 `progress.md` 首段中“用户提出才进入进度模式”的门槛，不再决定是否向用户打开实时进度工作区。更细粒度的逐步说明或用户是否逐次回复，单独按本轮要求处理；阶段进度不增加每阶段必须回复的门槛，方向选择和最终预览/导出仍分别按本地确认规则等待。

从原版 `brief-template.md` 生成项目根目录 brief 时，保持原件、八个 XML 块和 source-lock 不变，但须在生成的项目副本中改写与本地流程冲突的文字：在 `<inputs>` 中替换原文“制作过程预览：启用 / 未提出；用户反馈依据……；进度页链接……（启用时按 progress.md 更新阶段成果）”这一项，写成“制作工作台：正式制作默认主动打开同一工作区并展示真实状态和可检查成果；服务/页面链接按实际启动与打开情况记录；用户另行要求的更细粒度过程汇报单独注明，不控制默认工作台”。在 `<start>` 中，把“已定风格先出三张帧”“未定风格先给 3 个方向”改成按本片实际未决选择和关键状态提供足以看出实质差异的关键帧，不设固定张数；未定方向等待用户选择，已定方向展示该方向关键状态，连续运动是关键表达时同轮附真实动态小样。只写当前实际支持的生成入口，不照抄未核实命令。将“画面与混音准备好后默认打开 editor.mjs 工作区（长片逐章预览）”改成 work root 确认后尽早打开同一进度工作区，并在有意义的阶段与可检查成果形成时更新；仍保留方向确认和最终预览/导出确认。尚未打开时写“待启动/待打开”，不能预填链接或声称工作台已展示。

## 按观看问题比较与采用资源

自由新方向先接收一次 L0 星图，按本片未决问题展开 L1 并读完各采用项的 L2，实现时再查需要的 L3。目录、项目资源模式、完整正文回执与源文件入口以 [Showreel 设计输入与资源查阅](showreel-runtime.md#设计输入与资源查阅)为准。如何判断来源成立范围、完整语法和可借用的局部方法，见[动画视觉设计](../../laohu-analysis/references/motion-design.md#保留有效视觉贡献不把局部条件扩成全片硬约束)。

## Analysis 输入与阅读责任

Analysis 接收本轮稿件、原始录音/录屏/实拍、目标观众和用途、用户给定的素材、锁定内容与声音边界。先识别内容事实和观看任务；输入中没有旁白或声音时不补造。需要剪辑、ASR 或词级同步时，复用与素材 identity/version 一致的 ASRcut 转写、edit plan 和 compiled timeline，并查看实际 narration segment 字段（如 `wordTimingSource`、`words` 和起止时码），不能只读句段摘要就断言没有词锚。缺真实词级时间才不能制作词级 cue；有真实词锚也不要求逐词切镜。一个句段可连续呈现，但有多个重要语义转折时需按已提供的真实时码设计阶段，不压成单一粗述；名称可先做上下文，只有具有表达作用的强调才按真实读音时间触发。

在提出视觉方向之前，先完成上文所述全源 L0，再按未决问题扩展候选；来源不足处明确不确定，不根据题材或名称推断外观配方。75 张受保护原版卡全文继续保留在真实目录中，用户可按当前片子贡献采用任意资源；它们不构成强制组件或固定入口。把每项实际考虑和采用的资源、适用对象/段落、保留与调整的画面方法、必要条件和来源限制写在唯一 `brief.md`，不从摘要重造算法。

Analysis 阅读本片真正采用的专业参考，依据本片内容、观看任务及来源贡献组织方向。对于依赖速度、接触、遮挡、揭示时机的参考，检查对应可播放片段与必要的加密取样，在所属镜头保留实际可见的处理及其用途。拿参考片段、本片方向帧与实渲复查是否保住了已采纳的造型、材料、层级或运动机制。锁定风格按授权继承。自由方向按本片需要取舍，局部复用旧代码前检查真实来源、许可、接口与当前消费者。只有目录或静帧时，按它们能提供的范围判断，需时间过程的部分仍待核。

## 唯一设计产物 brief.md

普通新项目只写一份完整、可独立阅读的项目根目录 `brief.md`。它不是运行时 props 清单，Motion 从中挑出必要工程参数。原版 `references/brief-template.md` 的 XML 标签和结构保持原样，不增删重排；本地适配只改写生成到项目中的 brief 文本，不覆盖模板或 source-lock。

brief.md 必须让新接手的人不看对话也能据此继续，至少写清：

1. 观众、平台/使用情境、片长/画幅、中心表达、内容顺序、事实依据、锁定项，以及哪些是演绎或示意。
2. 全片的注意力路径，以及内容确实需要的情绪或兴趣变化：观众何时看主体/证据/文字、如何转向下一段、结尾留下什么。结合受众关切、结果意义和可理解性决定是否需要好奇、紧张、幽默、亲近或其他表现，并让选择落实为可见动作、关系或声画力度；不强造未知期待、反差或释放，也不把开放情绪处理成平淡默认。
3. 全片视觉身份及段落发展：辨认这支片子的共同视觉线索，同时说明各段如何按观看任务变化构图、景别、空间、明暗/密度和节奏。长片尤其要检查中后段不是只重复开头的同一版式；章节、渲染批次和技术构建单元不自动等于镜头。说明实际对象轮廓、尺度、材质、色彩角色、背景/前景、排版、字级、阅读路径、相机和视域，具体到能想象观众看到什么；按本片需要可写清圆角与否、厚度/平面、平铺/叠放/扇形重叠、线条/填充、字体类别、字号和字级关系、空间位置及遮挡/光影等。采用的成熟来源若规定字号、排版、位置或画幅关系，沿用其实际规格；仅来源未规定或无法移植的部分才用相对描述。已确定的全片属性可以继承，不需逐段复述全部属性；避免形容词词表和无关参数字典。
4. 运动与镜头语言：对承重动作写清可见进入/退出状态、触发、对象和文字主次、路径、方向、速度、必要阶段、接触/揭示、落定、变化所承载的内容或情绪和连带反应；镜头在何时保持、移动、推近、切换或让材料自身完成转场。不要只写“突出重点”“缓缓出现”或“发生变化”作为完整动作。按真实字幕 cue 可见起止时间覆盖当时状态或持续动作；连续镜头可跨多句和多个字幕 cue，不按句号切镜。
5. 声音职责：旁白版本、已锁音轨、成品音乐/SFX/环境声候选及来源许可，分别承担的作用、对应的视觉事件、起止/淡入淡出与避让；关闭的轨写明无意安排。来源候选不能写成已听审或已授权。
6. 按真实观看单元组织的完整覆盖表。每行指向稿件段落、真实 ASRcut segment/token、录屏片段或无声观看目的，写出本单元实际的注意变化及必要的情绪变化、可见对象形状与材质、文字层级、构图/排版、运动/镜头、共享事件、声音/静音与下段接续。对关键动作写进入状态、触发、路径/速度、阶段、落定、连带反应和退出/接续。屏显字幕按每条真实 cue 的可见区间覆盖画面状态或持续动作；无新动作时写清当时画面持续呈现什么。重要触发只用真实词时码，句段精度保持句段范围。观看单元可以覆盖多句/多 cue，也可以一段分多个任务；同一动作组能连续发展时保留连续性。
7. 当前画幅与其他规格的来源；新建或明确全新重做且本轮未指定时默认 16:9，既有工程局部修改则保留当前实际规格。brief、预览画布和最终导出规格一致，不能按旧目录、旧视频或平台习惯补猜。
8. 没有确认的资料、素材、许可、ASR 精度、字体/插件/格式、时钟或声音来源，注明具体缺口会影响什么和当前能继续的范围。

在 `<direction>` 中明确给出 Motion 消费的判断：`motion-probe: required; reason: ...` 或 `motion-probe: not-required; reason: ...`。reason 用人能理解的动作/关系说明要检查什么；required 时须指向具体动作或衔接及要看的连续性质，not-required 时须说明静态画面已足够验证什么、没有依赖何种时间过程。该声明不改变八个 XML 块，也不把创意 brief 变成 renderer 参数字典。若为 required，Motion 依当前受管 probe 接口按该 purpose/选区生成可播放小样，验证其绑定了当前设计、候选、规格与项目树，并把结果放入同一工作台；设计内容变化后重新生成，不以旧探针或四张静帧代替。

视觉设计写自然语言，直接说明观众会看到什么、对象怎样出现和发生什么。成熟来源明确规定的字形、尺寸、间距和位置等可见规格应写进 Brief；不要抄与画面设计无关的 props 清单、RGB 表或原始 CSS。字幕若有用户确认的固定样式，按字幕专用 preset 实施，不能被主题文字组件的示例样式覆盖。若技术限制会改写所选方向，Motion 返回具体缺口和受影响段落，请 Analysis 修改同一个 brief。

字形或文字时序承担表达时，Analysis 在对应导演段通过屏显 ID 引用本句，写清显示区、断行和入退场。若与字幕同时出现，写清那一刻先读哪处，分别给字句留出可辨的位置和时间。字体选择按[Brief 字体声明与绑定](typography-and-legibility.md#把选定的字体交给工程)挂到该文字实例或共同角色。已安排的代表帧若承担字形或字图关系核验，选本句完整可读的时点，用帧 ID 对照导演段和工作台上的实际画面。动态显现和阅读竞争沿相关字幕窗顺播。在 `<build>` 记录需另行准备的授权字体或尚未解决的实际制作条件。Motion 用当前字体文件、本句和同一屏显消费用法检查工作台与导出。发现字形替换、缺字或语气不符时，回到实际消费者或受影响的导演段修复，再复核该字及其相邻镜头。

## 时间片段与工作台交接

新项目在唯一的 `brief.md` 内使用原有 `<structure>`，加入一个 `<production-units>` 表。工作台读取本表建立制作进度，拿表中的 ID 找到紧接的逐段导演正文，沿成片时钟挂定位和核验证据。每个稳定 ID 对应一个完整观看任务。把需要分别控制的动画层、实拍和声音作为同段所引用的多次使用，保留各自的入场和退出。

~~~markdown
<production-units>
| 稳定 ID | 段名 | 开始 | 结束 | 制作说明 | 对应片段 ID | 时间依据 | 讲述与字幕 | 关键设计帧 | 制作职责 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| demo | 三块拼合 | 0 | 2 | 使原先分开的三块按同一槽口对位，闭合后才允许下一次操作。 | | 计划 | 无口播 | slots-aligned@1.20 | 动画 |
</production-units>

### [demo] 三块拼合
此处写完整导演正文以及 slots-aligned 所需的实际可见状态。
~~~

上表只演示格式，交接正文需要按[动画视觉设计](../../laohu-analysis/references/motion-design.md)写到可生产的粒度。表格填写准确的一句制作说明，每段下方用 `### [稳定ID] 段名` 写完整导演正文，按时间递进写清实际材料和内容、观察位置、对象身份和形态、进入时的构图和主次、动作和声音如何触发变化、应读清的窗口、目标帧与退出状态，以及上下段的交接。能继承的共同规格写确切指向，同一位置会出现两种画面时写清何时切换。执行者不看聊天而必须补猜关键视听选择时，带着片段号回 Analysis 补全。

- `开始`、`结束` 使用秒、分秒或时分秒，按 `[开始, 结束)` 从零连续覆盖全片。纯视频或仅有声音的段也有真实职责。字幕、音效、音乐和实际图层使用可以跨段或重叠，用各自在成片中的原区间和身份关联。填写剪辑清单中的真实使用编号时，第六列用半角逗号分隔现有 ID，待制作的使用可留空。
- 只有原稿时填 `计划`，以导演方案的拟定时码供准备和探索。已有源材料而剪后时间仍待确定时填 `待对齐`，保留已知语义。定案后用 `成片@timeline.js#区间ID` 绑定本片 `SHOTS`、具名区间事件或章节事件，也可选两个实际端点，例如 `成片@timeline.js#intro.t0,compare.t1`。可用 `成片@voice/timeline.json#occurrence-id` 直接绑定本项目冻结的 ASRcut 编译结果中的剪后 occurrence ID 或 presentation ID。表中两列时码须与当前绑定一致，原素材时间、字幕显示时间和成片时间各用其对应证据。
- `<inputs>` 有已经校验的本片[字幕源](typography-and-legibility.md#原生双语讲解字幕)时，`讲述与字幕` 填 `原生字幕轨`，工作台从同一来源取本段相交的全部 cue，显示原编号、原文、绝对显示窗和段内交集。与真实剪后实例并用可写 `原生字幕轨；voice/timeline.json#occurrence-1,occurrence-2`。旧项目可继续用 `双语字幕.srt#2,3,4,5` 显式登记本段的字幕。跨段声音只使用原事件或原剪辑实例一次。确实无口播的区间填 `无口播`，需要录制或对齐的区间填 `口播待对齐`。句段级材料用于相应精度的动作，精确到某个词的触发由现有真实词锚交接核对。
- `制作职责` 填 `动画`、`混合`、`视频` 或 `声音`。动画和混合段进入动画制作进度。其余段的时间、讲述和导演正文仍属于全片设计。
- `关键设计帧` 使用 `帧ID@秒`，多帧用半角逗号分隔。同一帧 ID 全片唯一。能从前段已登记画面状态直接接续时可填 `沿用@前段帧ID`，正文明确继承哪些关系。前段也沿用该帧时可继续引用。实际验证只需持续观看或现有素材时写 `无@具体原因`，并指出从哪段实片、哪个画面状态和哪个动作接缝验证。只有视频或声音职责且无需单帧时可填 `无`。新造型、构图转折或对象关系需要单帧验证时，登记实际片内时点。段界帧由其所在的后一段登记，前段正文可引用这个共同状态。连续运动的检验范围与关键帧分别说明。

运行 `node {SKILL_DIR}/scripts/laohu-showreel.mjs brief-units <project>` 读取与工作台共享的投影及未对齐项。`--final` 核验已成立的影片时钟、全片区间和当前引用。新项目 scaffold 先校验结构，只有稿件时仍可设计和探索。成片最终预览及导出对新表要求真实时间。`editor <project>` 直接读取同一 Brief，无需在剪辑清单另抄 `units`。剪辑清单继续承载实际进入影片的各层使用。

## Motion 的技术映射与接续

Motion 先确认 brief、原始内容身份与受保护工程，再决定实际页面结构及代码。方向未定时先展示实质不同的关键帧并等用户选择，只有用户明确按具体范围免除确认时才跳过；“你决定”不是自动豁免。设计已定时忠实实现。针对实际观看责任检索源码与素材，保留成熟效果的算法和真实参数，不因新框架而重造。可由本片代码直接建立新构图，不要求每风格先有固定组件，也不把现存组件当创意方向。全片视觉系统与对象身份统一，不代表构图必须不变、沿用一张目录地图或让同一对象持续占位；按观看任务调整观察侧、尺度和局部关系，承接的只是设计明确需要延续的可见状态与事件。核心表达依赖连续运动时，给关键帧同时准备真实动态小样。

Motion 将 brief 中的可见事件映射到项目 `timeline.js`。口播使用 ASRcut 的时间源；句级 cue 只支持句段范围，词级锚点必须有真实词时间。物体运动、动作 phase、镜头/相机、转场与声音效果消费同一具名事件，避免重复时间表。将临界事件、裁段起点和输出帧序号统一到同一时基，以实际导出的相邻帧核对触发前与首次出现的画面，避免小数换算使动作或字幕晚一帧。brief 的镜头连续性在实现时可以跨多个词句和字幕 cue，不把逐 cue coverage 变成逐 cue 切镜命令。工程实现仍须呈现 brief 的实际动作路径、速度、阶段、落定和反应；不可用一个“变化”字段或终态单帧代替。

有真实多章的知识讲解默认采用顶部紧凑的次要章节导航；单章、没有章节需要或用户明确例外时不添加。Analysis 将章界绑定到本片的起止事件 ID，Motion 通过 `chapter-binding` 与 `chapter-index` 按当前 brief/timeline 哈希和真实事件时码构建索引。索引 JSON 供平台填写，不表示视频像素可点击；已有 MP4 时，章节播放器按钮 seek 成片视频；还没有 MP4 时，播放器嵌入本片真实场景并调用 `render(t)` 到达绑定事件。正式 MP4 生成后重新运行 `chapter-index` 更新为成片 seek。播放器应在同一工作台流程中明确打开/提供链接。时码变化后必须重新编译，不能手写一套与 `timeline.js` 分离的秒数。

如果设计无损可实现，Motion 维护本项目的 HTML、脚本、字体和素材。页面暴露确定性的 window.render(t)，实际片长来自 window.DUR；素材与字体全部 ready 后再设 window.READY。需要摄像头、WebGL、Three 或实拍媒体时检查其实际浏览器/seek行为。实现不能使用不同运行环境下不稳定的计时或系统字体作为正式证据。

声音按 showreel-sound.md 与 Arrangement 已有能力取得实际文件。由 Motion 负责画面与最终工程的唯一事件时钟及唯一最终混音消费者。音轨工作区若修改声音，导出同一编辑会话产出的混音；不可在修改后重新调用未编辑的 build 混音。声音或资产未 ready 时继续无关镜头，在 brief 保留准确依赖和状态，不把空白、合成占位或目录候选当实物。

## 按可验收的动作段并行

用户已启用 Luna 时，Commander 在全片方向和共享对象稳定后，按 Brief 片段安排工作包。需要多人跨界生产时，在同一主时间线核定一对已确认代码帧作为端点，派发两者之间可独立验收的动作区间。每个端点对应本片实际 `render(t)`、绝对时间和事件 ID，相邻两段共用同一个端点状态。段内仅用于核对构图的代表帧挂到原片段。Cover 图用于对照目标外观，工程端点由代码帧核定。端点确认沿用现有授权和方向确认范围。两个或多个包输入齐备且能分别验收时，按当前容量成批派发。同一连续动作、机位或对象层难以安全拆开时，交给一名执行者。部分端点尚未核定时先推进可独立完成的段。

- **由 Commander 锁定共用输入并派发。** 给执行者本段的 brief、成对代码帧与对应绝对时间、当前设计和工程版本、共享对象与素材路径、具名事件、可写范围以及要回看哪段播放。写清端点需接续的位置、尺度、方向、速度、相机与遮挡层级，指定跨界转场由一侧或整合者负责。共享对象承担遮罩时，外缘与实际裁切共用同画幅下的坐标、大小和速度。只有设计明确允许外溢的光效可越过边界。遇到不明确的依赖时报告影响，独立工作继续。
- **各段从共用状态接续动作。** 前段把对象带到共同端点的形态和速度，后段从这一状态继续。各段使用同一具名事件与共用素材，在自己的文件或独立预览目录内制作，一处接触的画面、文字和声音使用同一事件。Worker 回交实际动态片段及端点前后可见状态。整合者更新共享对象、主时间线、字幕及整片声音。同一文件的重叠区域由整合者顺次接入。
- **逐缝合片。** 整合执行者把各段放回当前项目，接入同一声轨与字幕轨，保留尾音、节拍和动作连续性。局部预览时间按主时间线换算。Commander 对每个接缝核对相邻帧、端点和正常播放，逐项看事件时点、对象位置与运动方向、速度和相机、遮挡与裁切、文字退入场、旁白与声效。设计采用硬切时，按预定的画面交接与声音时点评价。发现偏差时定位到对应段、共享对象、设计或混音，修订相关范围并复核真实合片。在[工作台](showreel-runtime.md#默认显示真实制作进度)记录同一版本的播放和时码证据。工程镜头接缝使用 `seams`，镜头内两动作段的共同端点随对应 `segments` 证据记录。方向或时钟变化时将新约定与证据同步给受影响的执行者。

长片在扩大制作前，用开场的进入、代表性中段的解释难点和后段的视觉发展检查制作路线。凡依赖运动的处所选有辨别力的片段，检查新关系有没有在画面变化中发生，尤其关注接缝、阅读窗和声画时机。不同检查目的可由同一个有代表性的片段承担。

评估是否提速时，先固定同一 brief、画幅、素材与音轨，对照两种方向帧路线到可播放成品的耗时与实际画面。比较 Luna 串行和并行时再固定同一视觉路线和动作范围，以首次派发到实际成片的墙钟记录结果，另记实际任务重叠、调度与等待、整合、重复绘制、接缝返修和资源消耗。把这些时间与实际帧、动态接缝和观众反馈一起用于判断下一次是否值得拆分。

## 交接和质量边界

Analysis 完成 brief.md 并将真实材料与来源状态交给 Motion；Motion 返回技术映射、代码和媒体实况，不再改导演方向。需要改变材料读法、注意顺序、具体美术或声音职责时回到 Analysis 修订同一 brief，不另开同步稿。

Analysis 设计完整只证明本片设计已记录，不等于成片视觉已实现。Motion 的 schema、hash、运行成功或渲染输出只证明相应结构/消费事实。最终需分别检查关键静帧、真实连续运动、实际字体/媒体、声音听审和导出 MP4；审查承重变化时核对重点/主次，以及转换前、中、落定后的状态与反应。长片覆盖代表性中段和后段，检查全片视觉身份是否保持、构图/景别/空间与节奏是否仍按内容发展。静态技术 PASS 不可冒充动态或审美通过。没有实际音频试听时标未试听；没有用户或真实受众反馈时，最终接收质量为 `UNKNOWN`。
