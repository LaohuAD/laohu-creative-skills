# 像素画面与步进动画

## 适用与来源范围

方法依据为 `huashu-art-motion` 固定提交 `8a0d7d72ca65fcce6f8ba82c4a6c8dfe35b8422c` 的 `references/风格配方/14_8bit.md`。该卡记录了像素网格、最近邻整数放大、部件拆分精灵和步进动作；其具体示范包括角色/猫的分层精灵制作，以及猫尾四姿态循环 `[-0.55, 0, 0.55, 0]`。这是源项目自己的程序实现记录，不是原作游戏截图、原创像素画或普遍观众效果证据；不复制角色、游戏场景、界面、字体或素材。

专项迁移的是媒介处理：稳定像素颗粒、可读轮廓、部件遮挡和有意的姿态切换。像素感不等于游戏叙事，任何题材都不自动需要金币、生命条或关卡。

## 输入与返回

父级应传入本镜头要解释的关系、目标尺寸、用户确认的像素方向和运动要求。子级把工作网格、轮廓与部件分层、整像素位移及步进姿态写回镜头规格，并注明何处应衔接通用镜头。工具链据此实现后，在最终尺寸检查轮廓、遮挡关系和姿态是否仍可辨。


## 画面核心、开放项与切换

像素画面固定使用稳定工作网格、最近邻整数放大、清楚的色块轮廓和分层精灵，边缘按整像素移动；对象、色板和姿态数量随主题开放。部件确有遮挡关系时才拆层，动作需要逐帧姿态时才步进，否则可以保持连续运动。先按目标尺寸确认细节能容纳；若小图里认不清，简化剪影或提高工作分辨率，不用平滑滤镜掩盖网格问题。最终逐帧查看边缘是否糊、闪或亚像素漂移，部件是否仍可辨，也不因画风额外塞入游戏道具。


只有用户明确选择像素画、8-bit、像素游戏动画或确认该专项提议时才读取；“复古”、游戏题材、低分辨率素材或单独出现“像素”不构成触发。完成后，画面设计应能追溯这一明确选择；其他请求继续使用通用风格判断。

工作网格由目标输出尺寸、观看大小和对象细节共同决定。使用整数倍最近邻放大并关闭插值平滑，让边缘颗粒保持一致；缩小预览和最终尺寸都不应出现糊边或亚像素漂移。

只有部件会相互遮挡且整体剪影容易粘连时，才把头发、脸、四肢或道具拆成独立精灵层。用清楚内外轮廓与有限色阶保持身份；复杂抗锯齿形状需降采样复查，仍不清楚时直接重绘像素，避免线、阴影和高光糊成一块。

对象位置按网格整数变化；需要逐帧姿态时，安排少量关键姿态与有意义的停顿。需要平滑时移动完整对象而非模糊边缘。正常速度播放应无闪烁，动作可读且不成为无意义循环。

金币、生命条、砖块和 HUD 只在故事确实包含游戏界面时出现。像素方法也可用于普通人物、物件、数据与图示，画风标签本身不增加题材元素。
