# 路径构建、擦改与连续画布

## 何时采用

当观众需要跟着一条构建路径理解关系，或后续步骤必须回看同一画布上的前序内容时，使用本方法。若重点是段落独立、最终完整图、对象局部揭示或页面对照，则可直接显露成图、局部呈现或切换页面。教学、教师身份、复杂论点和出现“白板”一词都不自动触发；路径构建也不要求出现手、笔或真实书写动作，符号、结构线、数据路径和几何构件都可按次序构成画面。

## 输入与返回

主线传入需要被看见的关系和顺序、哪些对象先在/后在、擦改是否改变既有含义、观众何时要回看全图、目标尺寸及用户锁定范围。返回构建顺序、共享画布或分页选择、每一阶段保留/添加/淡出/改写的对象、视窗与停留位置；写回镜头蓝图，由 visual-design 整合全画幅，由 toolchain 按实际绘制接口实现。

若主线已选 `templateId`，用 `show` 与源 grammar 核实它是否实际支持本镜所需的连续画布、标题/point/draw/image/highlight 等 cue 与 camera 参数；具体字段以所选条目为准，不把“白板”名称当作任意 path 输入承诺。保留模板的原生绘制方式与布局，只提交真实 cue；需要的构建/擦改超出接口时交回主线。

本地 Canvas `path-reveal` 可直接调用原 `DG.drawPartial`，沿目标已有的静态点列描显；适合已经定义好的路径需要按顺序露出时使用。它不随对象端点动态更新，不提供擦改/重写，也不产生水笔材质；真正的连续画布与擦改需由场景 renderer 另行实际支持。

## 选择与操作

先判断构建次序是否承载解释。若观众需见关系如何逐步形成，就按真实依赖顺序揭示路径或组成部分；若最终关系已足够且逐笔过程不提供理解价值，可直接呈现完整对象。需要擦改时，明确旧状态何时仍可见、何时退出、新状态如何与旧状态区别；改写不能让不同结论错误叠在一起。连续大板适合先后区域需要互相参照的内容；分页或局部画面适合各段独立阅读、空间不断重置会更清楚的内容。选择由比较、回看、推理和阅读需要决定，不固定某种底色、笔色、页面数或运镜方式。

板面、字形和标注的材料可分别决定。可用逐段路径揭示、裁切揭示、对象移入或符号替换，不必模拟手写。若确实出现手/笔，笔尖和路径的对应、遮挡与速度需在实际帧中成立；否则不制作空泛的手部道具。视窗平移只在观众要找到另一处内容、进入局部或回看全局时发生。

## 映射到工程

逐段显露的 line/path 可用对象 progress 事件；内核按路径弧长裁出当前显露段。若镜头确实展示手/笔尖，需让笔尖与同一个进度同步：在具名 custom renderer 中调用 drawPathProgress(ctx, points, progress, options) 绘制路径并读取其返回的当前位置，或以同一 progress 调用 pointAt(points, progress, closed) 放置笔尖/笔形。不能各自使用不同时间曲线或时钟，否则笔尖会离开绘制前沿。该方法也可用于符号/结构线的构建，不要求手或字。不同阶段增添或退出独立对象，可使用 opacity、visible 或切镜；共享画布移动可用 camera 或 layer transform，已支持的 clip 可保护局部揭示。普通事件不动画 points、擦除轨迹或 line 的 x1/y1/x2/y2；复杂擦改/重画需由 custom renderer 根据同一 scene 时间确定性地绘制各层。路径揭示不等同于文字排版，文字仍由共同的字体与可读性规则决定。

## 回到主线检查

用实际帧序列查构建、擦改、视窗移动和落定：当前新信息是否按依赖顺序出现，旧信息是否按设计保留或退出，移动后观众是否知道自己在画布何处，最终关系是否完整可读。无意义的空白等待、错误笔序和把一张静态图硬拆成逐字出现都要修。若共同比较布局持续承担对照，可以稳定保留；不按每一拍运动或换色验收。
