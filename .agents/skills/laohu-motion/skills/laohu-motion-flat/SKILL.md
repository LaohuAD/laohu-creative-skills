# 块面分层与尺度聚焦

## 何时采用

当剪影、色块、前后层、遮挡或从整体移近细部的观看过程用于解释对象，或其形态、层次、尺度变化本身承担当前已选的视觉体验时，采用此方法。体验任务可以不增加知识事实，但形状与运动仍须服务明确的观看目标。它适合扁平形状与多层空间，也能局部使用于其他材料画面；不要求整片都只有纯色块。细胞、星球、卡通等题材本身不触发，亦不带入某频道角色、标识或固定配色。

## 输入与返回

主线传入当前观看单元的主要任务、进入前提与完成依据，前后单元接入的对象/状态，旧视图中需要延续的身份锚点/必要参照，局部目标范围、对象剪影、前后层关系、当前焦点、用户锁定范围、目标尺寸及真实尺度证据状态。返回各层对象与遮挡顺序、聚焦目标、目标范围（单对象、对象组或观察范围）、相机/对象的起中落位置和前后接入方式，以及是否为认知强调还是物理尺度陈述；写回蓝图，由 visual-design 统一背景与全画幅构图，由 toolchain 映射到 scene 实际字段或具名 custom renderer。父级决定是否保留整体参照或切换观察范围；局部模块不独自切整段画面，也不为身份连续性强制保留缩略图。

当本镜需要追踪、交接或动态证据时，将语义实体 `entityId` 与实际绘制实例 `instanceId` 分开记录；简单一次性对象不另加身份字段。声明的镜头/对象/标签属性要指定唯一实际控制者；若已有局部操作 provider 可消费，标明精确 `operationId`、目标实例、时间相位和允许参数，再由真实 draw 使用同一状态更新主体与屏幕锚点。普通对象事件、相机投影和静态 focus effect 各自保持原本范围，不把它们合称为通用推近操作。

若主线已选 `templateId`，按 `show` 与原入口确认该模板是否开放当前需要的对象层、遮挡、相机或聚焦输入。保留其固定构图与运动；只返回真实被消费的局部范围和参数，若模板不暴露本镜需要的操控就交回主线决定分段、换模板或走普通实现，不猜字段。

在本地 Canvas scene 中，若任务是突出某个静态矩形或让已命名的矩形对象错峰显现，可按 `focus` 或 `staggered-appearance` 查询局部效果。圈注不会改变对象尺度或相机；错峰项仅改变目标矩形自身 opacity。目标需为静态、未变换的 screen-space 对象，不把它扩成一般推近/缩放能力。

## 选择与操作

先判断观众需要看清层级、遮挡、重点部位，还是整体与局部的联系；让对象剪影保持可辨，按语义确定前后遮挡、焦点跟随的时机与落点，并在需要时回到整体确认局部如何改变全局关系。再判定当前变化属于单对象变换、对象组变换还是相机观察尺度变化，并写明实际目标范围、需要联动的对象和保持身份的锚点。单对象强调只向选定对象施加局部变换，其他对象按各自职责处理；对象组共同变化和相机推近则按其真实空间关系计算，不能把所有对象屏幕尺度变化都当成错误。细节放大可以是认知上的推近，不需要测量对象真实尺寸；保持对象身份锚点连续且不标成物理比例。只有画面声称真实尺寸、比例或距离时，才需要相应测量/来源依据并让标签/尺度编码一致。将目标对象的 world 锚点和想要停留的 screen 锚点写进镜头数据；由 `cameraForAnchor(worldAnchor, screenAnchor, zoom, width, height, rotation)` 求相机状态。需要让屏幕文字/标签追随 world 对象时，在当前相机状态上用 `worldToScreen(point, camera, width, height)` 求投影位置后绘制；若对象还有 layer/object transform，先按实际变换取得其 world 坐标，不能把未变换的原始点当成相机锚点。返回目标范围、属性归属、锚点和关键时态给工程实现；逐帧核对目标对象与非目标对象的实际变化，避免把局部进度无条件施加给整组。

剪影、描边、明暗、投影、高光和背景可共同建立轮廓、层次、焦点、气氛或审美，不要求每种形式都增加事实；只在它们压过阅读、吞掉轮廓或伪造材料/空间关系时调整。对象颜色需要稳定时保留承载身份/分类/数值含义的编码；背景色或审美色可随镜头交接改变。层次/视差既不承担空间关系，也不服务已选的层次、景深或注意体验时，删去无目的深度；若是审美景深，不标成实测距离。

## 映射到工程

简单块面可用 rect、circle、ellipse、polygon、path 等已支持对象，并以 scene 的 layers、parent、space、transform、clip、camera 组织前后关系和聚焦。事件可驱动已支持的对象位置/尺度、图层变换或相机属性；不要假定镜头会自动更新标签锚点。关系端点随对象移动时，用共同图层变换或由 custom renderer 按真实对象姿态重算锚点。物理比例依实际数值与口径呈现；不能用形状面积或镜头距离暗造数据。

若主线选择 Video Shotcraft，返回全局焦点目标、前中后态、必要参照与要变更的实际空间属性；来源组件自己的 placement 只负责其局部父坐标，不自动等于相机/尺度变换。区分 segment 内 Stage 背景层、组件局部 `placement`、源镜头自身构图与真正的相机 owner；当前 Film `/2` 没有跨 segment 的持久背景层，只有真实 renderer 提供该消费者时才能把跨段持续背景写入方案。其余只有在 [Video Shotcraft 接入规则](../../references/video-shotcraft-integration.md)和当前 catalog 中存在对应 source prop/adapter consumer 时才映射。若来源没有消费这个聚焦或尺度变化的入口，返回主线用 Motion 方法实现，不写虚构的 `camera`/`zoom` 字段。

## 回到主线检查

在目标画幅顺看起态、推近/遮挡过程、落态和必要回看：剪影是否认得出，前后层是否正确，焦点是否跟随当前讲解，文字/标注是否仍可读。若对象需在连续画面中持续可见，就按实际前后层、遮罩/clip 与可见几何核对；动画终点坐标或一张无冲突的 AABB 不能证明整段都露出。切镜或有意遮挡可以成立，只要它不违反本拍需要持续追踪的关系。对象完成职责后，按主线决定移出、复用或转成新状态；不能让上一状态只因绘制器仍保留而继续显示。严格 layout snapshot 核对的是登记框和蓝图预期 ID；像素可见性和实际正常速度观看仍分别判断。没有真实尺寸依据时，画面可以突出局部，但不暗示测得的物理尺度；有实测陈述时检查尺度和标签是否一致。若内容更需要关系展开、连续形变或证据细读，交回主线选择相应方法，不让“扁平”本身决定构图。
