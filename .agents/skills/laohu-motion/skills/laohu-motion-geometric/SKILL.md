# 轮廓对应与连续形变

## 何时采用

本方法处理同一对象、部件或可核几何结构从一种状态连续变到另一种状态。当观众需要看懂“哪些部分保持身份、哪些位置改变、变化后是什么”，或轮廓连续性本身承担当前已选的形态、节奏、张力或情绪体验时，采用连续形变；后者不必额外制造知识关系或事实增量，但每次变化仍须服务明确的观看体验。圆变方、组织拆分、部件转化等可成为触发例子，但题材名称本身不构成理由。

若两端对象没有可信的部分对应，或连续中间态会让观众误认数学等价、物理变化或因果，应切镜、先拆解再重建、并置比较或采用关系图。外形相似不等于实体相同，动画不能替内容证明结论。

## 输入与返回

主线传入对象身份、前后几何、可对应的部位/锚点、必须稳定的标签/数值/边界、变化范围、目标画幅与用户锁定的方法范围。子级返回对应表、关键中间态、连续与断开的部分、状态编码和停留/切换条件；写回同一镜头蓝图，让 visual-design 安排全画幅，让 toolchain 按真实对象与时间接口实现。

蓝图以 `entityId` 标识语义上持续被追踪的对象，以 `instanceId` 标识每一个实际绘制的形状或表示。连续形变可由一个绘制实例承担，也可以由不同表示按有据的对应关系交接；不要因复用实例 ID、对象名字或一个 scene 就默认身份连续。把关键对应点、属性控制者和交接前后态交给实际 renderer；只声明绘制器真正消费的局部操作，不以 MotionCore 基础插值重命名冒充专用形变机制。

若主线已选 `templateId`，仅在 `show` 与源 schema 确认该 grammar 实际消费对应几何、形态或显露 cue 时，才把连续形变/描线接入它；保留模板原有运动和固定构图，不把 `morph` 或 `path` 名称相似当作接口兼容。缺少对应输入时报告给主线，不改上游算法。

本地 Canvas 的 `path-reveal` 可让原 `DG.drawPartial` 沿一个静态、已绑定的线/路径逐步描显；它不对应 `morph`，也不改变轮廓几何。连续形变仍须使用真实支持形变的 renderer/输入，不能把描线效果记作对象变形。

## 选择与操作

先对齐对象身份、主要轮廓、部位顺序和锚点，再决定沿同一对象变形、把对象拆成可追踪部件、或分段重建。关键点可对应时让中间轮廓保持连续；只有整体比例能对应时，允许整体连续变形而不虚称局部结构也相同。对应失败的位置应分开出现并明确连接关系，不能用插值掩盖身份断裂。

连续变形中保留承担身份、分类、数据或单位含义的编码。若颜色本身承担了上述语义，改变时同步更新图例/说明；其余颜色、背景、明暗、材质和构图可为审美、对比或段落交接而变化，只要不让观众误读对象身份或数值状态。中间态需能说明变化如何发生，不必机械补满全部几何细节。

## 映射到工程

Canvas2D scene 可用 path 或 polygon 的 morph 配置配合对象事件 morphProgress 驱动已对应的点列形变；对象 progress 适合逐段显露路径。事件可以驱动已支持的对象属性，不要假定它能直接动画化 points 数组或没有列入接口的字段。若需要不规则拆分、非线性部件对应或额外绘制步骤，使用具名 custom:<name> renderer，以绝对时间或已声明进度确定性地计算中间态。简单整体位移/缩放可由对象或图层已有事件承担。

## 回到主线检查

按实际时间抽看起态、中间态、落态和状态转换边界：身份锚点有没有漂移，必要标签/数值是否仍在原意上，连续过渡是否暗示未经证实的等价，最终几何是否可辨。目标尺寸和正常速度下结果看不清时先修中间态或拆分呈现，不以源代码有 morph 字段代替画面验证。未用到连续对应时，退回主线的普通展示或适用的关系/分层方法，不为“动画感”强行形变。
