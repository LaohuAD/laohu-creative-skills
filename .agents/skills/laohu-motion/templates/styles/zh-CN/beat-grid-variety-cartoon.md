# 节拍格综艺扁平动画（beat-grid-variety-cartoon）

> 一句话：统一的玩具角色和硬边平面布景按固定节拍做轮次表演，以短 telop 和判定词收束动作。

> 来源参照（只学语法）：
> 平面矢量风格的节奏游戏综艺节目：玩具般的吉祥物出现在糖果色条纹和太阳芒背景上，每次撞击都落在固定速度网格上，以问答节奏回应动作，并在每轮获胜时用一个判定词收尾。
> 参照（只学语法）：Rhythm Heaven 模式的节奏动作派对游戏（提示 → 回应、轮次卡、判定词）、日本综艺 telop（粗描边字幕、条纹与太阳芒布景）、WarioWare 式舞台卡。绝不用它们的名称、角色、UI、关卡或音乐。
>
> 片长随轮数决定：每轮由一张标题卡和若干小节表演组成。旁白可有可无：这种风格仅靠短促喊声与 telop 也能撑起全片。

## 本质 / 不是什么

- **所有内容都踩在节拍格上。** 使用固定且快速的速度。每次弹出、落下、盖章、打字和相机冲击都标在（小节，节拍）位置，并同时成为声音事件；配乐从画面自己的时间线生成，因此画面与音乐不会错开。
- **一套绘制工具，多组舞台。** 平涂、一道粗墨色轮廓、圆端线条、硬边偏移阴影；每轮换一张饱和色背景与图案。
- **角色像玩具。** 全体角色使用同一种身体结构，用颜色、肚皮块、一件头部配饰和名牌区分。它们踩拍跳跃、撞击时挤压、喊叫时举起双臂。
- **一轮 = 可重复的动词 + 一次胜利。** 主题拆成若干轮；每轮一个能按节拍重复的动作，并以观众一眼可读的判定结束。

它不是微型游戏狂欢（没有计时器或每 3 s 一个动词指令的小游戏，每轮也不改变美术风格），不是中世纪卡通（没有有纹理的绘画背景或角色表演），也不是主题演讲（没有缓慢揭示或渐变）。

## 这个风格最俗的版本

来源没有给出一套可跨主题复用的固定俗套组合，因此不补造。风格特征与明确排除项保留在上面的本质说明中；具体故事、时间线和段落仍按新主题重新设计。

## 适配

- 用途：主题能拆成轮次、重复动作和一眼可读判定的综艺化短片。
- 内容：只借用下方可复用媒介规则；人物、故事、事实、镜头顺序和时长按本片目标重新设计。

## 材质与渲染

- **只用矢量，**在 1920×1080 画布上绘制 SVG 或 canvas 路径：平涂、一种轮廓色（近黑），人物和道具轮廓 8 px，小部件 5–7 px，圆角连接和圆端笔画。
- **不用渐变、模糊、纹理或柔和阴影。** 深度由**硬边偏移阴影**承担：用轮廓色画同形状并偏移约 10 px（贴纸、横幅）或 14 px（卡片），再把彩色形状放在上层。
- **舞台** = 一种饱和底色 + 同色相浅一档的图案：斜条纹（通常慢速滚动）、偏移圆点（约 20% 白色）、或旋转太阳芒。地面用更深色的一条底带表示，并在顶边画一道墨线，让角色站稳。
- **人物：** 圆润豆形躯干、短手臂与连指手套形手、椭圆眼睛带高光点、嘴型可切换为张开状态。人类角色共用同一身体结构；较古老的机器或年代可通过更方正的剪影呈现。
- **UI 工具组：** 圆角卡片、角落贴纸横幅、判定词、爆发图形（星形 + 圆环 + 速度线）、记分板。
- `render(t)` 是纯粹的 `t` 函数：每个元素的状态都根据 `t` 重新计算，不沿用上一帧的状态。

## 配色

- **墨色 + 纸色 + 糖果色。** 近黑墨色、白色和温暖奶油色用于卡片及纸质道具；另有约八种饱和糖果色（黄、橙、红、粉、绿、荧光绿、天蓝、蓝），再配两三种适合夜景或结尾舞台的深色及其更暗版本。
- **一组舞台配一种色相。** 背景、图案和轮次卡共用一个色相；轮次卡颜色匹配它所引入的舞台。相邻轮次不使用相同色相。
- **角色拥有固定颜色。** 每位参赛者的身体颜色就是身份，不能改变；它须与脚下舞台明显不同（角色不能与背景同色）。
- 大字使用白色或黄色填色，并带粗墨线描边；判定词可以是粉色或黄色。
- 舞台示例：橘色底 `#FFB870` 加 `#FFA85A` 条纹；青绿色加薄荷绿圆点；海军蓝加金色太阳芒。

## 字体

- **展示字体：** 拉丁字母和数字使用厚重圆体（如 Fredoka 700）；中文使用极粗无衬线体（如 Noto Sans SC 900）；手写道具才用手写字体（如 ZCOOL KuaiLe）。
- **Telop 字幕：** 白色或黄色填色、粗墨色描边约为字体大小的 14%，并放在填色下方绘制（`paint-order: stroke`）。标题逐字构建，让每个字形都能弹入。
- **Telop 就是字幕。** 轮次卡、角落横幅、标签、道具文字和判定词一起承载意思；文字保持简短（横幅每行约 ≤ 20 个中文字符，牌子上 ≤ 12 个；拉丁文字横向约占 1.6 倍宽）。有旁白时字幕做成底部描边 telop 牌，不另加细线通用字幕。
- 所有文字至少停留 max(1.8 s, 语音时长 + 0.6 s)；判定词可较短，因为扫一眼就能读完。

## 运动

- **待机 = 随节拍跳跃：** 每拍做一段抛物线（8–30 px）；邻近角色在反拍起跳，让人群像波浪一样荡开。
- **撞击 = 挤压：** 每次撞击后进行阻尼摆动（约 30 rad/s、0.35 s）；每个重拍都做轻微挤压。
- **入场时从天而降，**用缓入并恰好落在节拍上，让音效与角色同步落下。人群按每拍或半拍依次落下。
- **弹出时用 back-ease：** 卡片、贴纸、印章和文字显现都用回弹缓动；退场使用缓入。不做缓慢淡入：元素要么已经显示，要么正在弹出。
- **喊声姿势：** 举起手臂 + 张开嘴，约持续半拍。
- **打字机显现：** 按节拍细分显示，并每隔几个字播放一次点击声。
- 场景变化是**小节线上硬切，**并加一个极短白闪。淡出只保留给最终结尾（如确有需要）。
- 所有动作都落在节拍网格上；拍与拍之间的事件要放在对应细分位置。

## 画面怎么活

角色按拍跳跃、受击后短暂压缩回弹，邻近角色可在反拍起跳；背景条纹可慢速滚动。其余事件跟节拍时间表，来源未要求独立随机微循环。

## 镜头语法

舞台是正面、对称的镜框式结构；移动的是画框本身。镜头词汇，不是固定路线。开场和结尾由主题决定。

| 镜头变化 | 表达作用 | 可用于 |
|---|---|---|
| 节拍冲击（绕中心缩放 0.8–5%，约 0.16 s 衰减） | 让画框感受到撞击 | 任一重音、猛击、倒数 |
| 一个小节内连续几次冲击 | 让画框跟随音乐呼吸 | 副歌、逐渐升级的节奏模式 |
| 正面锁定广角 | 把整个舞台变成游戏棋盘 | 建立图案、展示人群、记分板 |
| 小节线上硬切 + 闪白 | 新一轮、新舞台 | 章节变化、前后对照 |
| 分割舞台（两半、两套舞台） | 双方隔空回应 | 竞争、人类对机器、旧方法对新方法 |
| 缩成缩略图（完成部分缩小，进入一个槽位） | 记忆、累积 | 回顾、“后来这些全都发生了” |
| 舞台从地面向天空垂直滚动 | 升高的风险或尺度 | 排行榜、增长、物件塔 |
| 快速推近一个道具（硬切到 2× 景别，下一小节再切回来） | 这个细节就是笑点 | 价签、数字、人物反应脸 |

同时发生的冲击幅度总和保持低于约 0.06，避免露出画框边缘。角色站在地面底带上；横幅放左上，判定词放中间偏上。只用硬切，不用溶解。

## 声音调色板

- **全部从画面事件合成：** 正弦波底鼓并加柔和饱和、带通噪声军鼓和拍手、踩镲、slap 贝斯、失谐锯齿波铜管重音（结尾带滤波下扫）、带颤音方波主旋律、类似马林巴的拨奏、八音盒铃声、三角波铺底、方波琶音、牛铃。
- **明亮大调流行和声，**循环短和弦，每小节一和弦；每轮可有自己的风味（放克、猜谜、电子、梦幻、厚重……），但不另起一首新歌。
- **事件拟音为玩具音高：** 弹出、啵声 + 弹跳落地、盖章、打字机点击、蜂鸣器、叮声、伺服马达嗡鸣、啪响；人群逐个落下时，可用有音高的短音拼成旋律。
- **喊叫，不说完整句：** 每次喊一个到三个词（“Hey!”、一个数字、一个判定），提前节拍 20–30 ms 放入，让辅音落在节拍上。人群喊声由多个不同声音叠在一起、彼此错开几毫秒，并在立体声场中横向分布。
- 可选的强度变化（按影片需要选择）：每轮进场前用一段 jingle（镲片 + 上行铜管 + 军鼓滚奏）；结尾升调；大撞击前一个小节只留鼓；揭示用一小节半速；或一小节静音后由单独一声喊叫打破。
- **混音：** 人声与拟音走独立总线；音乐根据该总线包络避让；使用软削波而非硬限制；−14 LUFS，真峰值 ≤ −1 dB。

## 原生手法

以下是方法菜单，按故事需要选用。

- **轮次卡。** 一张持续一小节的卡（轮次编号 + 名称 + 如年份或步骤这样的标签）随 jingle 飞入，然后开始表演。*适合内容：* 食谱步骤、创业阶段、博物馆导览章节。
- **成绩单。** 用打字机效果回顾成果，再盖成绩印章。*适合内容：* 季度评估、旅行总结、最终分数。
- **问答式回应。** 把轮流发言变成节奏模式；加快节奏（四分音符 → 八分音符）本身就是剧情。*适合内容：* 老师提问、全班回答；顾客点单、咖啡师回应；两名谈判者来回交锋。
- **下一关预告。** 有东西孵化出来，或被解锁。*适合内容：* 下一个版本、下一季、下一个年级。
- **判定词。** 一轮最后一次撞击时，让一个带粗描边的大词倾斜弹出。*适合内容：* 物流步骤上的“已送达！”、许可证上的“已批准！”、训练计划中的“个人最佳！”。
- **混剪板。** 一套舞台配一条时间线横幅；每个项目在中心表演几小节，然后缩小进入底部的一个槽位；高潮处所有槽位一起弹跳。*适合内容：* 年度回顾、团队发布清单、节庆演出阵容。
- **游戏 UI 里的统计数据。** 数字变成领奖台分数、冲向目标的计数器、被猛击的价签，或每拍长高的条形图。*适合内容：* 募资进度、每道菜的热量、应用下载量。
- **人群落下。** 每拍落下一名参赛者，并配一个有音高的短音。*适合内容：* 俱乐部所有成员、行星、一道菜的食材。

## 变化空间

由你决定轮次及其动词、角色、舞台和颜色、是否使用旁白、速度、开场、结尾和片长。网格、绘制工具组和 telop 语言保持不变。

与演示片保持足够差异：

- 结构：**淘汰赛对阵表**（每轮两名参赛者，胜者晋级，决赛使用分割舞台）；**一轮长镜头**中，单个节奏模式从四分音符逐步升级到十六分音符，表现故事压力上升；**问答节目**中有三名参赛者，每个问题都是主题中的一个事实，记分板本身构成论述。
- 开场：**先展示判定结果**（空舞台上弹出“Perfect!”，然后倒带，展示如何达成）；**单个参赛者**在空旷地板上独自跳跃，之后人群一一落下；**记分板**先展示最终数字，再倒数回零。
- 结尾：**集体照**（所有人停在跳跃中，闪光后画面变成卡片上的拍立得）；**关卡选择地图**中，每个完成轮次都成为一盏点亮的节点；**幕布**随着小节逐步落下，最后一声喊叫留在幕布下方。

## 坑

- **有状态的逐帧更新会破坏并行渲染：** 冷启动的工作进程只会显示初始状态。每个姿势都要根据 `t` 重新计算；对照单帧渲染与顺序渲染的结果。
- **如果切镜闪白、jingle 和编曲分开维护为多份 cue 清单，彼此会逐渐错开** → 全部由同一张表推导。
- **固定长度音频缓冲会切断尾音** → 根据真实时长设定缓冲区。
- **字体加载之前就计算文字位置**会让字幕牌溢出 → 先加载字体，再开始构建。
- **TTS 会误读喊叫中的数字和符号** → 将它们拼写成词。
- **把真实产品画成角色**：名牌上用真实名称、借用原版吉祥物、标志或 UI 都不可以；真实人物只能作为泛化替身。
