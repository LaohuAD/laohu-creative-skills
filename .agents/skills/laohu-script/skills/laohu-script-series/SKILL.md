# 系列开发：让下一集既能重复又会改变

## 触发边界

用户要求开发连续剧/系列、系列引擎、季弧、分集故事、series bible 或 writers’ guidelines，或想写成一集接一集看下去、每集有满足且人物关系还会变的剧时，进入完整系列开发；无需先说引擎等术语。

- **单集边界：** 只写或改第一集、前三集或指定单集时，仅用本级[单集接口](#单集接口)，不自动展开全系列引擎、季弧、产能测试或开发包。商业短剧仅在目标、情绪承诺与制作条件匹配路线前提时，轻量调用[商业短剧条件模板](../../references/series-and-production.md#commercial-short-drama-templates)，不为套表硬加故事线。
- **Pilot 边界：** 仅当用户明确要求 Pilot/试播集或其方法时进入 Pilot 分支。
- **非触发：** 既有成稿多集仅需排版，回父级交付；多章节电影或含连续事件的单部故事不触发。

本级同时锁住两种观看价值：**每集反复给观众什么满足**，以及**人物、关系、知情、资源或权力跨集发生什么不可逆变化**。

## 专业判断顺序：先定合同，再验证发动机

### 1. 选连续性形态，不用名称代替设计

先定观众从任意集入场能获多少满足、上集选择在下一集保留多少，再定主形态；混合型须逐线写清谁闭合、谁累积。

| 主形态 | 每集结算 | 跨集承接 | 失压信号 |
|---|---|---|---|
| 单元闭合（episodic） | 案件、任务或处境在本集解决 | 关系、身份、技能可累积 | 人物每集归零，长期无新选择 |
| 连续累积（serial） | 单集可留悬，必兑当集行动或情绪承诺 | 事件、秘密、关系、危险持续改后继 | 每集只成下集预告，离前情看不懂 |
| 选集（anthology） | 单季或单故事内部闭合 | 跨季换人或换世界，守共同观看承诺 | 仅剩主题相似，无稳定入口 |
| 混合（procedural/serial） | A 线结案或局部结算 | B/C 线累积并在指定节点兑现 | 既要闭案又要长线却无分工，结案无后果 |

同步锁定**剧集类型 × 季级问题来源**（plot-led / character-led / theme-led / hybrid / limited）：人物驱动且拟续季的剧不可在第一季耗尽主角全部内部缺口；限定剧开篇定终点。明记所选格式与舍弃选项的代价。

### 2. 把引擎写成可验证的因果句

用 Rabkin 四要素（concept + conflict + theme + story pattern）写一句可验证的系列引擎，不以题材标签代替：

> 在【世界/条件】里，【持续的冲突来源】迫使【有理由持续介入的人物】反复采取【可重复的故事模式】；这些行动把【可争辩的主题立场】变成具体选择。

- **Concept/world：** 独特观看入口是什么？换职业、地点或时代能否让熟悉关系变具体，而非只把规模写大？
- **Conflict：** 什么稀缺资源、制度、流程或关系矛盾持续催生新问题？为何结完一案不会终结整部剧？
- **Theme：** 写成能被人物反驳的命题，落进两种都讲得通却互斥的选择，不用抽象大词。
- **Story pattern：** 一句话写定每集可重复的行动形状，写成过程句（主角怎样在做 X 时应付 Y），不做一次性谜底。

### 3. 过产能与人物网测试

仅在完整系列/引擎开发时，用 **5–6 条彼此有别的未来集梗概**检产能（内部验证，不默认随单集交付）：每条至少改目标、对手、资源或关系策略之一；只换案名却重演同一误会，说明引擎未成立。限定/迷你剧改画有限冲突源的递进与失压终点，证明终点不可提前或延后。先分清每周变与不变的因素，核清引擎耗尽点；若每集都要硬添新规则，回引擎重调。

为主要人物建 **Want Grid**：当下想要什么、最怕失去什么、握有何种资源、谁能阻挡、对方为何也有道理、两人被何种关系或制度绑牢。逐人核查：

- **持续介入权：** 主角因职业职责、关系义务、资源控制或共同处境必须在场，绝非仅被剧情召唤。
- **自洽对抗力：** 先定对抗性质（人、制度、贪欲、创伤或旧债），再定面孔，让对手在自身目标里站得住。
- **新增配角门槛：** 必须改变至少两位既有角色的选择、可重复发挥独特功能，拿掉会断一条因果。

**系列合同最低项：** 主形态、可重复观看承诺、固定规则与人物网、单集结算尺度、累积变量、不可逆后果、持续介入理由、引擎失压点。过关标尺是新故事无需重置世界、记忆或已付代价。

## Pilot：选择入口，并在同一集里演示未来

先判世界与人物是否需从第一天建立、典型模式是否已在运转，再四选一：

| Pilot 类型 | 适用场景 | 必备成品证据 |
|---|---|---|
| premise pilot | 创立前提的事件不可跳过，或规则须借事件教会观众 | 触发尽早发生不拖集末；事件后当集试跑一遍常规故事模式 |
| typical / midstream | 人物关系与日常机制已运转，重点证明普通一集有多好看 | 首次进入即可跟上，必要背景融进当下行动，拒绝说明会 |
| hybrid | 起始变故与稳定模式同样重要 | 前半立新常态触发，后半转入常规模式，分清哪些不重演 |
| semi-cold start | 观众与主角同处未知、共同摸清世界规则 | 未知有依据，每次揭示直接改变主角下一步行动 |

四型共用**双重任务**：既完成本集触发、目标、阻力、策略转变与结果，又以实际行动向观众示范后续可重复的观看承诺（如 *Breaking Bad* 起源后即跑一次犯罪行动模式，*The Sopranos* 借治疗室框架立人且不靠硬悬崖收尾）。冷开场与悬崖断点按形式自决；构思可循造世界 → 找春芽 → 行动带人 → 定 Pilot，切入点直落事件进行中。

## 单集与季弧：一集兑现承诺，一季改变后续可能

### 单集接口

写或改单集、前三集或系列中任一集时，按六步锁清本集目标与状态：

1. **触发与本集问题：** 本集必须回答的具体危机或任务。
2. **人物各自目标：** 主要角色当集想赢或想守住什么。
3. **主要阻力及合理性：** 对手或处境的成立理由。
4. **策略变化：** 阻力如何迫使人物改换打法。
5. **本集结算与未结事项：** 列出已结行动、观众实得证据、各方对承重事实的确认/误判/未知及仍悬承诺。
6. **下集行动改变：** 本集结算如何具体改写下一集可选行动。

交锋若改写知情、资源、关系或对他人方法的判断，按[人物状态继承](../../references/character-and-relationships.md#2-重要交锋后的状态继承)更新并写入结算。A/B/C/runner 仅在各线承担不同观众任务、造对照或互改选择时设立；先各写线卡，再按信息与因果编织，不机械轮切。

商业短剧按条件读[商业短剧条件模板](../../references/series-and-production.md#commercial-short-drama-templates)；需带广告位的一小时剧读[一小时剧格式模板](../../references/series-and-production.md#35-美式一小时剧的条件格式模板先选播出交付分支)。

### 季弧与结算账本

从季末必须抵达的行动结果、人物新获或重解的事实、关系与资源状态倒推前置条件、关键节点（tentpole）、逐集任务与季初起点：

- **连续与单元分工：** 连续线里前段成果、损失或未结问题须实改下段目标、知情、资源或代价；单元线由引擎开启新案，人物与长线变化照旧继承，重要交锋同样按[人物状态继承](../../references/character-and-relationships.md#2-重要交锋后的状态继承)延续。无行动后果的秘密揭晓不算节点；本季起终必须可核，多季保留发现空间。
- **后果账本：** 闭合单元与长线并行时，为每笔已结单元记下留给后文的关系、承诺、知情或资源欠账并标明兑现集数（条目随季长伸缩，较长多线季可配 6–10 笔）。
- **瓶子集与两集连篇：** 空间、预算或危机确需封闭容器时采用，封闭 A 线仍可并行 B/C 线（*The Sopranos* “Pine Barrens”、*The West Wing* “17 People”）；跨两集危机须给两集各自独立问题与局部结算，第二集明确兑现。

## Bible 与开发文件：先选读者决定，再选模板

先定文件要促成谁做何种决定及所处阶段，接收方有模板时逐项沿用。按[开发文件的读者选择表](../../references/series-and-production.md#series-bible-and-development-package)选型，完整字段与可省条件见[系列开发文档模板卡](../../references/series-document-templates.md)。

要求完整立项包且未指定模板时依[制作文件链](../../references/series-and-production.md#production-path-document-chain-and-current-requirements)起稿；仅说整理资料且用途不明时先交短概念提案。

- **短概念/提案：** 标题、logline、世界与冲突、独特观看承诺、主要关系、故事模式与 pilot 方向。
- **Series bible：** 写清可供续写的世界、人物、关系、引擎运行与规则，全剧总览配 Pilot 摘要证未来。
- **Writers’ guidelines：** 写明协作边界、人物规则、创作红线与难写场景处法。

交付仅限本轮点名文件，标明模板来源并区分已定事实、提案与待定项，绝不因写单集自动附带 bible 或 pitch。

## 验收与返回父级

将形态、引擎、主问题与季级边界带回[父级主流程](../../SKILL.md)：定戏核、引擎与人物网回阶段一，搭单集结构、季弧与分场回阶段二，现场落笔回阶段三，自审回阶段四；外部开发文件走交付与下游接口。

**验收：** 完整系列须经 5–6 条互不换名的未来集过产能、核人物介入权与季节点实果；单集只核六步结算；要求 Pilot 时加核常规模式演示证据。缺证据先回形态—引擎—人物—单集最早断点修根。
