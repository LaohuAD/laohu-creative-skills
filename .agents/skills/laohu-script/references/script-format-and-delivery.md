# 剧本格式与交付：让接收者知道读到哪一层

当任务需要选择剧本交付层级、版式、集场/画面编号或工作台 Markdown 交换时读取；按用户指定的体例与既有编号执行，再返回主 Skill 当前步骤。本文维护阶段交付格式、普通正文/P分段模板及机器接口合同；故事、场次、对白、动作专业方法按文中链接读取，不在这里重复。

## 先定交付层级

只交用户当前要判断或使用的层级，不把完整开发包压给局部正文任务。

| 交付 | 内容边界 |
|---|---|
| 故事概念（步骤1） | 用自然段说明类型/背景、承重人物、行动、阻力、失败代价、结局方向和独特看点；不展开逐幕事件。用户称“一句话故事概念”仍交故事概念，不自动另附 logline。 |
| 三幕故事纲（步骤2） | 分第一、二、三幕写清大事件因果并到实际结局；不含对白、动作细节、环境、场头或节拍。只标真正影响方向的拟案/待定项。 |
| 转折/序列结构纲（步骤5） | 按幕列转折点与序列，写明前因、目标、阻力、结果和承接；不提前拆场或列行动节拍。 |
| 第二幕扩纲（步骤6） | 保持第一、三幕原定内容，只扩第二幕并核算字数与占比。 |
| 分场纲（步骤8） | 按实际连续时空写场头、人物目标、行动与场末变化；只在内部需要或用户明确要求时细拆节拍。 |
| 普通剧本正文（步骤10） | 只交获批范围的连续正文和场次；附件另行要求时另列。 |
| 系列开发包 | 只在用户要求系列/分集规划时提供系列引擎、关系、季弧或分集纲 |
| 逐镜稿 | 只有用户明确要求或项目工程格式已确认才编 M |

新作按用户指定阶段交付；普通新作默认先给故事概念和三幕纲，完整开发按步骤1–9走到用户审纲，再获批后写正文。已批准纲、明确跳过审纲或局部改稿按已定范围直接写。不要把更深层场次/节拍附到早期纲，也不要把人物、研究、地点、预算等内部材料拼成每稿必填的资料包。

### 各层纲稿给用户看什么

步骤1概念交代故事规模和可感卖点；步骤2交代完整三幕大事件及实际结局；步骤5只组织转折/序列；步骤6只扩第二幕；步骤8才拆成按连续时空成立的场次。事实、作者拟案和未知分开标；只附会改变当前结构判断的条件。线索承诺、证据路径或受限规则，仅在实际承重或用户要求时说明来源、人物推论和回答位置。纲稿供创作者/用户判断结构，不代替正文的观众信息体验。

### 稿件体例的优先级

1. 用户本轮指定体例优先，其次沿用该稿/项目已确认体例和编号。
2. 未指定时，普通影视正文用本项目的 △ 画面描述体例；△ 不等于镜头参数或镜号。
3. 用户选择舞台、音频、连续动作块等其他体裁时按该体裁，不把影视格式强加过去。
4. 旧稿已有镜号、场号或其他编号时保留可追溯含义，不静默删号、改义或批量重排。

### 普通任务的起稿预算与纲稿单位

各阶段开发字数预算和分档唯一维护在[主 Skill 步骤1–6](../SKILL.md#执行步骤)。用户未定片长但只要概念/三幕粗纲时使用500/1000字基准，不解释为长片或片长承诺；要定结构数量、扩纲分档或分场时再确认片长。开发字数、场数和实际播放时间分开统计；步骤8分场时用[并行事件核算方法](segmentation-and-handoff.md#逐字预算估时与并行事件核算)核算播放预算，步骤10完整正文估时或明确P分段时沿用同一方法。纯纲只记规划预算，不称成稿实测。

### 层级先分清：集、场、动作与画面

默认开发顺序为故事概念→三幕故事纲→转折/序列结构纲→第二幕扩纲→地点名册→分场纲→正文；场和关键节拍属于后段，不能提前塞进概念、三幕纲或结构纲。正文内部层级为幕/序列→连续时空场次→相邻行动/回应节拍；三幕只是本项目普通故事默认，用户或项目已定其他结构时照用。普通影视场次以连续时空为边界：地点或时段真实改变时另起场头；场内主要行动/观察重心改变本身不自动另起场。回忆/幻想标记不能代替实际场头；连续行动中的内外切换可用清楚的内/外场头承接，不按剪辑视点机械拆场。一个场可含多个画面段和回应节拍；不按动词、句子或每个身体动作机械拆场/拆段。P 是用户明确要求视频时长分段后才使用的内容段，详见[分段与下游交接](segmentation-and-handoff.md)。

### 剧本正文的默认 Markdown 层级与工作台交换

完整正文按集/作品 H1、场按 H2；标题沿用用户/项目名称与场头。独立短片不虚构集号；局部正文只输出已知层级，不编造全篇 H1、集名或场名。H3 可用于正文确有必要的小标题，不能拿来冒充机器段界。

普通剧本默认不分段。仅在用户明确要求把稿分段、按视频生成时长切段或表达同一目的后，沿用既定 P 边界；人读方案的 H3 标题可用“第一段（P01）”标示段号，但只是阅读层级，不是机器分隔符，也不能代替 ---。若此后用户要求导入，直接沿已定段界编译，无须再次确认：同场真实 P 边界转为单独一行 ---，跨场保留每个原场头且不加分隔线；不重复正文。来源/估时/上界/接口短注、资产事实和作者说明都在剧本正文之外。导入用 body_markdown 只含剧本正文，不能夹人读 P 标题或这些短注；以当前 OpenAPI 对实际接口和结构的定义为准。

准备 Markdown 不等于保存或导入授权。只有用户明确要求连接其指定工作台时，先读取当前 OpenAPI；按实际 schema 组装 envelope，不推测字段。完整剧本无用户可用标题时才使用中性正文标题，软件项目名不能充当作品标题。

### 基础排版合同

场头按项目已定格式写场号、内外景/地点/时段及必要出场人物；角色名、括注和台词的顺序保持全篇一致。出场表仅在有助定位或用户/接收模板要求时附。附件与正文分开，不为“完整”自动附人物表、简介、背景、提案或制作资料。

### 动作块写什么

△ 标记一个清楚的可见画面/观察单位，同一重心里的连续动作与回应可留在一段；观察对象、重要空间关系或需辨认的证据变化时另起段。场次动作如何展开见[场次展开](scene-development.md)；台词行按下节写表演括注，人物互动与情绪因果按[对白与视听](dialogue-and-audiovisual.md)处理。

### 台词行与表演括注

**括注点出表演的要害，不重复台词的表面。**表演括注写在人物名后、冒号前，只在需要着重突出本句情绪或表演转向时出现；普通应答及上下文已经清楚表达的状态不加，不把每段填满作为格式目标。声源标记另按下节执行，不因没有表演括注而省略必要的 `O.S.`、`V.O.` 或设备来源。用户指定其他体例或只准逐字保留源文时，遵守其范围。

落笔先连读触发动作、前一句、本句和对方回应，明确人物此刻要影响谁、争取什么，以及他愿意显露或正在掩饰什么情绪。这些是作者内部的表演依据，不原样填进括号。随后确定本句需要着重表现的区别：情绪在此刻突变；嘴上所说与实际态度相反；人物正在压住情绪却露出破绽；或一句话的停顿、重音、伴随小动作决定观众怎样感到这一刻。属于这些强调处，再从已建立的人物与现场条件中选一个最能承担该区别的表演信号。

将信号写成自然、短小的中文：用动作动词写说话如何起、停、抢、忍或失控；涉及目光和小动作时写清实际对象；变化发生在某个词或答复之后时写出时点。声音表现可选重音落点、话被哽住、没说下去等实际差别；身体表现可选目光回避、笑容中断或手上动作停住等当场可见变化。这些是选择维度，不是每句必配的动作词表。只写会改变这句情绪理解的部分，不把语气、表情、肢体和目的拼成清单，也不以堆叠形容词换取细腻。简短情绪词在前后场面已把含义和转向建立清楚时可以成立；不把“低声”“冷冷地”等词列成禁词，更不靠补更长的身体描写自动提高质量。

声源与表演在同一括号并列时用分号分开。只有声音可被接收时，选择听得出的情绪信号，无实体AI不凭空做身体动作。内心声音只有需要突出其情绪或思路转向时加表演提示；系统提示沿用既定播报方式，不逐行附“平直、匀速”，只有异常变化对情节有作用时才强调。录音的表演属于录音中的说话人，不能随现场听者的反应改变。

括注只容纳与说出本句紧密相连的提示；独立发生、涉及多人交互、改变空间或物件状态、需要看清过程的动作放进 `△`。不为增加画面感发明无关姿势，不重复抄写相邻动作，不让括注提前泄露尚未触发的反应或隐藏事实。交稿时将括注连同前后回合读回：只有删去会丢失需要强调的情绪差别或造成关键误读的提示才保留；只是重复台词已有的怒、急、轻，或给已发生的应答再写一遍“应了一声”的提示删除。需要强调却仍只写笼统评价时，回到该句的表演依据，改成能演出或听出的区别，不继续加同义形容词。

本地取法：Judith Weston《Directing Actors》及其本人总结用动词、事实、意象、身体生活和事件帮助演员进入过程，不把所求情绪结果直接当作表演办法；此处把它用于先定情境与对人行动，再选必要信号。John August、Craig Mazin《Scriptnotes》第533期区分影响读法的括注与需独立展开的动作；本项目不把其英文篇幅经验改成中文字数上限。《Big Fish》最终拍摄稿第194场以“voice cracking”标明儿子在父亲去世后打电话时开口哽住，周边动作承担完整的悲伤过程；这个局部选择用于说明情绪在说话中怎样显露，不是每句都写哽咽或每场都添动作的模板。

### 声音、文字与主观时空的标法

标声音时按顺序判断：先确认声源是真人、设备传声还是非人角色，再确认剧中人物能否听见，最后确认真人是否在画面内。同场同一时空、画框外且场内人物听得到的真人对白，在人物名后标 `O.S.`；门后、走廊等空间说明可另加，不能代替 `O.S.`；人物进入画面后取消 `O.S.`。`V.O.` 标叠在画面上的内心声音、旁白等场内人物听不到的声音。电话、录音、广播、车载扬声器等传声按实际设备标注，不因真人未入画就改标 `O.S.` 或 `V.O.`；非人角色按实际经过的设备/声源标注，不套用真人 `O.S.`。声源首次接入或改变时交代来源，连续对白不重复设备全名；表演提示仅在上节的情绪强调条件成立时添加，声源说明本身不充当表演提示。交稿前逐条核对对白行与当场声源状态，确保标记符合声源类型、可听性和画内/画外位置。

屏幕文字放在标明载体的 `△` 画面描述中，并注明剧情内谁能看见，不写成角色对白；若可见范围影响情节，后续画面、摄像头、转述或记录须按已建立的接收权限处理，不能无意改变谁能看见。用户明确锁定的能力/权限限制须连同作用范围保留；当前屏幕处在视野外、未同步或某次未接通，只说明本次读取条件，不能替代“该通道不能取得”的限制。角色据此行动时，让其依据适用的既定规则或实际检查及反馈；未核实的通道留作未知，不把作者设定逐项写成人物已检测的事实。用户本轮指定或该项目已有明确声源体例时按其约定处理；其他情况下采用以上项目默认，不混用标记。

### 回忆与梦境要成对闭合

回忆写“回忆开始”与“回忆结束（回到现在）”；梦境写“梦境开始”与“梦境结束（醒来/回到现实）”；幻想写“幻想开始”与“幻想结束（回到现实）”。退出时重建现实时间/地点、身体状态和当下行动。跨场持续时各场头保持时空标示；主观时空不自动变成现实事实。

### 场、集、画面与分段编号

沿用项目编号；无既定编号时，长片/短片场号用 S01 起，剧集按 E01-S01 等格式。新增场按既有规则插入，不为排版重排旧号。无明确要求不加 M 或 P；P 与集/场号、镜号分属不同编号空间。P 的来源映射、跨场延续、资产事实接口和每 P 一条提示词规则均见[分段与下游交接](segmentation-and-handoff.md#p-标识来源映射与下游交接)。

### 可复制模板

以下占位模板与主 Skill 十步一一对应。按用户本轮所需层级只复制对应模板；早期故事纲和结构纲不含场头、对白、△、环境细节或节拍编号；只有分场纲或用户明确要求关键行动节拍时才下钻。花括号内容由实际稿件替换，不是固定故事示例。

**步骤1｜故事概念**
```text

# {作品名}
故事概念：{用自然段写类型与背景、承重人物、行动、阻力、失败代价、结局方向和独特看点}
已定材料：{只列会影响当前概念判断的锁定项}
作者拟案 / 待确认项：{只列真正会改变故事方向的内容}
{仅当用户明确要求1–2句logline/提案时另加：Logline：主角+目标+主要阻力+赌注}
```

**步骤2｜三幕故事纲**

```text
# {作品名}
第一幕｜建置：{从人物初始处境写到主线由何事件/决定启动}
第二幕｜对抗：{人物行动、阻力回应、策略变化与代价递进}
第三幕｜结局：{危机选择、高潮行动、实际结果及必要余波；写到故事实际结局}
作者拟案 / 待确认项：{只列仍会改变方向的选择}
{线索、权限、信息差及钩子兑现表仅在这些内容实际承重或用户明确要求时附}
```

**步骤3｜实际调研项**

只有实际核读并能定位的来源才填写为研究结果。已有的一手资料足以回答时先据此核查；缺少相称证据时检索并阅读可靠来源。未取得资料的项目写成未知及其创作影响，不以模型记忆、搜索标题或待查问题代替结论。

```text
## 调研项{编号}｜{具体问题}
研究简报：{作品类型；故事时代/地区；与问题有关的已定剧情；具体研究对象/作品单元；它影响哪项决定及原因}
类别与所查对象：{……}
影响的纲稿位置及原因：{……}
可定位来源：{机构/作者；资料或作品标题；发表/更新日期；URL、页码、章节/场次或其他可复核位置}
查明结论与仍未知：{……}
对步骤1/2的实际修改：{……}
```

**步骤4｜人物功能小传**

```text
# 人物功能小传
{姓名/身份}：{角色定位、当前目标、关键关系、采取什么行动、这项行动怎样推动故事；只写会改变选择的背景}
{按功能列出，最多8人；主角最多2段，其他角色各1段}
```

**步骤5｜转折与序列结构纲**

```text
# {作品名}
采用结构：{默认三幕 / 用户选择的方法；适用依据}
第一幕｜{幕功能}
转折点1｜{事件、前因、主角处境/方向的改变}
序列1｜{局部目标、行动、具体阻力、阶段结果、怎样引出下一序列}
{按该片长/方法增删，转折点与序列分别编号}
第二幕｜{同一结构}
第三幕｜{同一结构}
字数预算：{I / II / III预分配；I+III占步骤6目标比例}
钩子铺设与回答：{只列承诺及对应位置}
```

**步骤6｜第二幕扩纲**

扩纲模板只承载故事层级的大事件与因果。写清每段事件的前因、人物选择、阻力、结果和后续改变；不写对白、具体表演动作、场头或逐场环境/场景描写。第二幕前段、中点改向、后段是结构段落，不是场景编号。

```text
# {作品名}
目标总字数：{……}
第一幕：{沿用步骤5，不扩写}｜{字数，占比}
第二幕前段：{新增的事件及其改变}｜{字数}
第二幕中点改向：{承重事件、前因与新策略}｜{字数}
第二幕后段：{新增阻力、代价及终局条件}｜{字数}
第三幕：{沿用步骤5，不扩写}｜{字数，占比}
总计：{各幕字数与占比核算}
```

**步骤7｜地点名册**

```text
## {固定地点名}｜{已定 / 候选}
对应情节与观众体验：{……}
空间布局与真实运作：{……}
可拍/可录的具体细节与地点独特处：{……}
人物会在其中怎样活动：{……}
来源与仍未知：{机构/作者；标题；发表/更新日期；URL、页码/具体位置；尚未核实之处}
```

## 按接收任务另交简介或制作附件

用户明确要求提案、读稿或制作资料时，按接收者要作的决定另列必要字段；事实未定标为待定，附件不混入作品正文或工作台 body_markdown。用户给定时长是目标；现稿估时按[逐字预算与并行事件核算](segmentation-and-handoff.md#逐字预算估时与并行事件核算)另行计算并标为预估。

## 产物、验收与返回

按指定体裁、范围、编号及模板交付；局部稿不扩成完整资料包。交付前核对正文/附件分离、场头与编号稳定、动作画面段 △ 完整、声音及时空出入可读。动作因果与连续性详见[场次展开](scene-development.md)，全稿审阅返回[全稿审读与修订](review-and-revision.md)。

工作台交换契约：导出为 GET /api/studio/scripts/{id}/markdown；导入为 POST /api/studio/scripts/{id}/commands 的 import_markdown，args 仅有 body_markdown、replace，并携带 request_id、当前 expected_revision。导入前读取实际 OpenAPI，按其真实 envelope 和 schema 组装。仅用户明确要求替换时 replace: true；revision 冲突则重读最新正文并依用户意图合并，不用旧 revision 覆盖。只有服务端成功响应确认导入；没有对应接口时交付格式化 Markdown，不声称已导入。导入只处理正文写入，不授权据此生成，也不自动调用生成接口或附加制作提示词。
