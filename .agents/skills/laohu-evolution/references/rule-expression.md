# 规则写法与双轨表达

由 [laohu-evolution 主文](../SKILL.md) 在编写、精简、合并或重构 Skill 与 Reference 时读取。

规则文档的读者是前沿强模型和维护者：写得越精准、清晰、留白得当，模型注意力越集中；写得越像滴水不漏的防御性法务合同，模型越僵硬迟钝。

## 1. 双轨规则写法（硬契约 vs 软判断）

动笔前先辨清每一条规则属于哪一轨，严禁一刀切写成满屏必须、禁止、不得：

| 轨道 | 适用内容 | 写法标准 | 重构原则 |
|---|---|---|---|
| **硬契约轨** | 安全授权、落盘与路径隔离、脚本 CLI 参数、JSON Schema、跨入口输入输出接口、仓库结构与 UI 校验规范 | 确定、零歧义的现代汉语；写清触发条件、动作、例外与停止点；精确模板与命令放入代码围栏 | **严格无损**：不得弱化或静默删改，移动位置须同步更新全部消费者 |
| **软判断与创意轨** | 审美品味、思考维度、创意发散、诊断洞察、拆解角度、语言风格与结构组织 | 按**目标 → 判断（显式底层原理与裁决标尺）→ 行动（事前轻定盘与事后轻扫疤分离）→ 结果（真实感官验真）**闭合写实；标清媒介体量与适用边界 | **敢于减负、增量融合**：淘汰老模型防呆与事前填字数独；引入新规则时绝不覆盖删掉已验证旧强长板，新旧张力明写 A×B 共存条件 |

- **示范反推原理与四元闭环法**：将拍案叫绝的好示范沉淀进 Skill 时，既不照抄示范里的现成词（防高频锚词污染），也不压成空洞抽象名词——先完整拆透背后真正起作用的**全部隐藏原理层级与根本判断**（含表层主反差之外的隐含第二层暗线，讲透机制不凑学者名表），再沿**目标 → 判断 → 行动（高阶叠加技法标明按需选用）→ 结果（贴合该工作形态的真受众直觉检验与退化对照）**闭合写入；绝不把示范里的具体微动作、单一句式或道具固化成新套路，保留同原理下的表达自由。

- **硬契约改写防走样与硬软共存**：重排或精简硬契约时，绝不把 `必须`/`禁止` 悄悄写软成 `建议`/`尽量`，也不把条件分支或局部暂停写胖成普遍义务或全盘停工；保留原表格的条件→动作配对及模板里的字段顺序、必填项与占位符名。创作类规则须同时写清**硬边界与自然流畅共存**（把锁定设定无痕揉进现场而非偷删或硬背），并保留**三态辩证裁决弹性**（尊重同向好方向、补齐模糊需求、对偏离本质的字面外壳提取核心情绪换血）。批处理或前后依赖管线须写明范围清点与前步失败保护。
- **按工作形态定细节自由与防反向污染**：先定用途、感受与宏观方向，不把完整写成无论用途都填满纹样/尺寸/坐标（微观精控仅由明确精控、已定资产复现或剧情关键识别触发）。写**提示词中继类**规则时，重在四维物理视听转译与实渲验真，剔除下游模型无法渲染的抽象心理词；写**上游规划简报**向成稿交接时，保持极薄纯净白描，防散文修饰词反向污染成品。

## 2. 语义对照、淘汰减负与冲突裁决

更新或重构既有规则时，按实际语义单元（而非字面相似度）决定去向，维护一份轻量的改前/改后心智对照即可，不制造逐句台账：

- **同义重复**：择优保留最简明准确的一处作唯一真源，其余副本删掉或改为 1 行相对链接指针（说明何时读、读完回哪步）。
- **过时微操 / 负资产限制**：经原生基线判断确认无硬契约风险、删掉后强模型原生表现持平或更好 → **直接删除**并在交付说明中列出删减项与理由，绝不搞一切历史条款无损硬保。
- **条件不同**：保留清晰条件分支，不为了合并抹平真实差异。
- **同条件冲突**：按上位约束（`docs/runtime.md`、`AGENTS.md`）与核心目标当场裁决并原位替换，绝不把两条打架的规则并列留存；若核心目标或方法取舍未决，暂停依赖部分交回 `laohu-analysis`。
- **源头意图防漂移**：转写或整合用户明确选定的方法/品味时，不借客观稳妥暗中加免责软化词把核心方向磨平；局部事实/安全边界只在真实触发处局部处理。

## 3. 冷热知识硬分界、本地闭合与范例边界

- **冷热硬分界与本地闭合**：供日常任务读取的 `SKILL.md` 与 `references/` **不得把外部网页 URL 当作运行方法入口**，执行者无需打开外站即可完成方法。凡直接参与日常决策、支撑跨题材迁移的核心学科原理与裁决标尺，必须**宁精勿滥地留在对应层级运行态判断层**（绝不抽空锁进 0 加载的 `SOURCES.md`，不硬凑无关学者名录写厚正文，也不因硬卡条数把跨体裁通用原理错塞进单一子技能）。
- **冷归档边界与出处诚实**：外部出处、版本核验、文献细分、证据边界及用户实战示范的脱敏溯源记录统一归入 `SOURCES.md`，热区运行文件默认不挂冷归档 `SOURCES.md` 的相对链接（防误预载冷台账），不往运行态灌学术论文黑话。区分原文短引、转述与本地适配，不编造来源；仅出处待核但方法已被用户明确选定，照常按确认范围落实，不附 `仅供参考`/`可尝试` 等削弱语。
- **许可与真实范例边界**：可执行脚本、Schema、模板接口按实际许可与契约原样保留；受版权保护的解释性文字或文学作品仅做必要短引，不整篇搬运。正式专业范例须来自可核验的真实作品、教材或原文，无可核出处时宁可省略，严禁自编创作片段冒充经典范例。

## 4. 创作类原则句的品味偏好

当编写需要统领多种创作取舍的**原则句**（用于创作类 Skill 定魂）时，保留老胡明确选定的现代汉语诗学箴言体偏好：

> 我要的是现代汉语的诗学箴言体。
> 它不是文言文，不靠生僻词，不写成学术说明，也不把规则平铺成禁令。
> 它用熟悉的字词，通过对偶、判断、反差、具体意象和关系压缩，写出一句能够统领多种创作选择的正向原则。
> 它要少说而不空，含蓄而有方向，简洁而有重量。
> 原则句负责定魂，机制说明负责解码，执行规则负责落地，验收规则负责纠偏。
> 不要让解释取代原则，不要让禁令取代审美，不要让细节框架压过文学中心。

**适用边界**：此偏好仅用于创作类规则中凝练定魂的**原则句**；此处的简洁与关系压缩指用熟悉的现代汉语凝住丰厚感受与多层余味，绝不把正常话抽干虚词压成生硬电报体或违背母语习惯的动宾怪搭。紧随其后的机制解码与所有工程/授权/接口步骤，仍用直白、通俗、无歧义的现代汉语写清，绝不拿含蓄修辞让执行者猜条件或动作。

## 5. 结构扫读与防膨胀底线

- **标题即工作流**：用真实动作或判断命名章节，不照搬内部框架坐标作死标题。
- **消灭文字墙**：每段围绕单一判断展开，先给结论再给动作；**禁止写超过 300 字且混杂多项独立条件的连续段落**，有先后顺序用编号，有横向对比用简表。
- **拒绝假减负**：主文保持轻量可扫读，独立重专项按真实条件拆进 `references/`；严禁把大段规则搬去另一个同样每次必读的文件里冒充减负。
- **局部对照与验证身份边界**：`audit` / `analysis` 在报告内展示同材料最小改后对照仅用于佐证差距，不改动原件、不冒充独立验证；`analysis` 与 `evolution` 严禁自编脱离用户材料的假作品或示意试作充当独立验证样本，正式能力验证须由目标执行 Skill 凭最终文件和普通输入实跑真题。

## 6. 内密外透、自然母语与防下游泄词

写好的 Skill 由前沿 AI 读取执行，而产出物分别面对审方案拍板的当前用户与消费成品的最终受众。落笔与收尾必须把**三种文字身份彻底拆清**，做到**对内高密度提效、对外说自然母语人话，且全链断绝电报硬压缩与偷懒引号**：

1. **规则层（写给 AI 看）——语体同构与双向反污染**：
   - **语体与能力同构**：确定性工程与精准判断类允许使用高密度精准原理名与确定契约；**发散创意与文学表达类 Skill 必须用顶级真人主编、导演或手艺人当面点拨的鲜活直白口吻写透机制，严禁把定盘、压测、闭环、偏移、标尺、支点等冷硬系统架构复合词照搬进下游创作规则里**（前沿模型会继承规则语体的松紧度，说明书腔会让下游作品发紧发干）。
   - **严守双向反污染**：既**绝不铺陈冗长旧词禁用黑名单**（防粉红大象反向激活禁区），也**绝不在正文反复投喂高频现成示范锚词**（防模型换啥题材都复读同一批词）；正文克制装饰引号、不写易被下游字面照抄的生猛怪比喻，断绝语体传染。
2. **沟通与方案层（写给当前人类用户看）——自然母语人话 ＋ 3 秒结构化扫读**：凡向人类用户汇报诊断、展示改造方案、解释取舍、给选题构思或请示拍板，**必须把内部术语、框架名词与流程代号全部译成自然开口的直白人话加具体例子**（遵守 `docs/runtime.md` §3，不压电报体、不滥用引号与反引号），同时按 `docs/runtime.md` §4 用**清晰标题层级、分条罗列、对照表、推荐优先级排序与核心结论加粗**组织版面，让用户一眼扫清重点与拍板项，严禁堆成紧凑文字墙。
3. **最终成品层（写给读者/观众/终端使用者看）——自然好句、媒介原生与固定格式严守**：
   - 规则里的内部定级名、工序名、跨体裁错位词（如图文里出现 `需补拍`）、打分自查与过程废话，严禁穿透或混入终端作品本体；**同时严防元治理或文章编辑的防病术语跨界串味**（例如克制装饰引号针对说明、报告、规则与评论散文，绝不机械搬进虚构故事、剧本或音乐技能自检以免误伤对白）。
   - 最终作品的高信息量靠平实顺嘴、留有余味的活人句法载多层感受，绝不靠压字数、删虚词硬造高密度；**并严守该媒介原生专业格式与用户明确的固定输出格式硬契约**（如特定段标、气口、纯代码块或字段模板），绝不擅自变造；确需保留跨体裁内部坐标时，明令对外按真实媒介译成人话。
4. **止步边界与交付版式贴合真实场景**：写只停在某环节、不越界代写下游的职责停止线时，须同步写清当用户明确追问切入手法、搭桥方式或落地细节时，仍须给出具象可感的场景对比、反差机制或操作抓手，绝不借不越界退化成空泛姿态声明；交付版式严格遵循 `docs/runtime.md` §4 表皮呈现三分轨。
