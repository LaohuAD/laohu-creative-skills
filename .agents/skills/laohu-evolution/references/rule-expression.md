# 规则表达与方法保留

由 `{SKILL_DIR}/SKILL.md` 第 3 步在编写运行规则、落实分析方案、迁移成熟方法或制作可复用示例时调用。当前实施者按本文件组织和核对文字，完成后返回主文第 4 步接入实际消费者。专业方法的采用依据与授权由主文处理；本文件负责把已选内容写完整、写准确、写到能产生目标结果。涉及专业四层时，先读取 `{SKILL_DIR}/../laohu-analysis/references/capability-design.md` 的定义，返回本文件核对其写回效果；本文件不另设四层定义。

## 先恢复完整实施内容，再写规则

用户要求落实整段对话或整套方案时，先从有效上下文逐项恢复：用户要求、已选方法、成立条件、正向做法、取舍、例外、成品示范、文件落点及验证要求。将后续纠正覆盖到相应项，保留其他仍有效内容；已完成的环境清理不重复执行，已撤回的问题不再写成事实。

对每项实施内容在当前工作中指定四件事：它应改变哪项判断或产物；写入哪个实际文件与章节；从哪个入口到达；用什么输入看到它起作用。可以在聊天或现有工作记录中简写，不默认另建报告。一个问题可对应多个控制点，但不能以多个文件都出现了关键词证明落实。

例如分析要求“先核对原始记录；存在两种相互冲突的说法时各自归属来源；无法确认的不合并为事实；允许保留用户原句”。写回只剩“核实信息、准确表达”，四项内容都未被完整落实。必须分别保留取证位置、冲突处理、无法确认时的动作和原句保留许可，才算覆盖原方案。

写完逐项反向查找：每项决定在运行文件中对应哪段文字或资源？找不到就补入；写了但入口不会读到就接入；被概括句替代就恢复做法；已不适用则按当前明确决定说明原因，不能默默省略。新增解释或示例不能抵消原方案内容丢失。

## 写回时检查四层专业关系

专业四层的定义真源是 [analysis 的专业能力设计](../../laohu-analysis/references/capability-design.md)。规则表达时沿用该处对“灵魂、筋骨、血肉、表皮”的定义，只核对已选方法的专业关系是否在落地后仍可执行：

| 追踪项 | 写回时核对什么 |
|---|---|
| 原理到选择 | 已选原理仍决定执行者优先取用、保留或舍弃什么；不是段首口号 |
| 选择到组织 | 成品内部需要成立的顺序、依赖、因果、照应或主次关系仍写清；不拿入口、角色或文件交接代替 |
| 组织到做法 | 指定材料、动作和技法确实服务上述关系；缺核心方法时返回 analysis，不自行发明 |
| 做法到感知 | 检查者能在成品的具体位置找到目标效果的载体；只写“更有感染力”等愿望不算落地 |

这些是写回核对，不是所有 Skill 都要出现的标题或必须逐层填满的模板。当前方法不需要某项时不造内容；调用、依赖、权限和交接另作工程检查，不能充当专业四层。

## 保真复用：保留的是信息与作用

已选成熟方法直接适用时，原句、顺序、范例与模板可以直接保留。接口不同就改接口，条件不同就按已定适配方案处理；不为原创感改写，也不把有鲜明偏好的方法整理成“综合考虑”。实质取舍已由 analysis 或用户作出，不在此重新筛选喜欢与不喜欢的内容。

规则文件的排版授权只覆盖规则文件本身。被它控制的输出契约也属于保真范围：固定模板、机器语法、接口字段、样式参数、目标媒介中的呈现效果和最终作品格式，按已确认方案原样保留。核对输出契约时，还要保留输出相对于周边内容是替代还是补充、固定行数、字段、前后缀及允许附加内容；这些边界依原契约逐项确认，不默认所有模板都独占输出，也不默认可以向前后追加。确需改这些内容时，先确认改动本身已在本轮范围内，再按依赖和消费者检查；不能借规则排版整理顺手改变成品含义或使用效果。

写回从用户资料中得到的方法时，保留每项判断的适用范围；分类名称不能替代判据和动作：

| 范围 | 写回要求 |
|---|---|
| 目标用户群的共享默认 | 可由开发者面向该群体的共同任务设计为候选，不必先证明群体已普遍偏好；没有试用结果时标成候选，不宣称群体共识。不能用单个用户的例子证明公共偏好。 |
| 随任务条件变化的做法 | 保留为有触发条件的分支，写明默认、替代或退出动作；不把分支压成无条件步骤。 |
| 个人偏好 | 有用户明确表达或确认时，按该用户范围固定，不需要群体认同证明；不能把一次未确认的选择泛化成稳定偏好。 |

后续材料若改变适用范围、触发条件或偏好归属，只更新受影响的规则与消费者，并保留尚未解决的冲突。

目标领域主文保留统领流程的专业判断、主要步骤及步骤间关系；Reference 展开专项方法的判据、动作、条件和局部失败处理。不能为了拆分文件把主文变成空路由，也不能把 Reference 写成不参与执行的知识摘录。拆分后由一个实际任务检查主文能否作总选择、调用专项方法并接回整体结果；同一项专业判断只在一个位置定义，其余位置明确调用关系。

逐项核对下列内容；它们可以分布在连续段落里，不强制每条都套同一种格式：

| 要保留的内容 | 常见信息损失 | 正确处理 |
|---|---|---|
| 对象与触发 | “已有正文的开头改写”变成“创作开头” | 保留输入条件，不能顺手扩大任务 |
| 观察与判据 | “核对正文是否兑现承诺”变成“检查质量” | 保留要看的材料与判定关系 |
| 默认选择 | “先从正文提取”变成“可以提取或补充” | 保留默认顺序与换法条件 |
| 执行动作 | “回查录音中的数字”变成“确保准确” | 保留材料位置、核对对象和处理动作 |
| 条件与例外 | “无法确认时按说法归属”被删除 | 保留未知与失败分支，不把未知算成否 |
| 要求强度 | “可以保留附注”改成“保留附注” | 许可仍为许可，不升级成必需项 |
| 结果与返回 | 做完动作后没有交付物或消费者 | 明确交什么、给谁、完成或返回哪里 |
| 解释与示范 | 只留结论，删掉避免误用的解释 | 保留承担理解、迁移或表达示范的部分 |
| 立场与表达 | 直接指出差距改成泛泛鼓励 | 保留已选力度、节奏与推动行动的作用 |
| 原理与统领关系 | 原则被保留成标题，后续选择却不再受它约束 | 写清原则支配哪些选择、优先级和退出条件 |
| 条件与替代关系 | “A优先，条件不成立时用B”变成“A和B都做” | 保留默认分支、切换条件、例外覆盖范围及先后依赖 |
| 示例与可变形式 | 自拟创作形式或临时试作被固化为配方、冒充正式专业依据 | 正式作品范例按本节来源规范处理；说明可核实范例展示的机制与可变形式，并将临时试作单独验收 |

字数相同不证明信息相同，字数减少也不必然丢信息。只在重复内容真正不再承担独立作用时合并；决定性条件即使只有几个字也不能删。信息密度来自每段交付不同而必要的内容，不来自删除主语、压缩成黑话或堆叠术语。

对强立场，保留它明确推进的选择，不擅自中和；事实与动机断言仍遵从已选边界。例如已选规则是追问“具体哪一步做不了”，可以保留直接质问，不能改成“你也可以慢慢想想”；但不自行补上“你只是在逃避”。若方案明确保留强度，不能以更客气为由删掉作用。

## 保住方法关系，同时给形式留出变化空间

写回前从 analysis 已确认方案中区分四类内容；具体选择来自已选方法，不由 evolution 重判：

- **必须保持**：目标、专业原理、作品内部关系、质量判据与保护项。
- **可以变化**：随材料变化的意象、词句、媒介实现、技法和组织形式。
- **默认做法**：当前优先采用、但条件改变时可切换的方案。
- **退出或替代条件**：方法何时不适用、由什么方案接手，以及未知时先核对什么。

将“原理 → 选择 → 组织关系 → 材料/技法 → 可感知结果”写成执行者能沿材料完成的路径。原则必须能改变取材或取舍；组织关系说明各部分如何共同产生效果；技法说明怎样制作；验收指向作品中可观察的承载位置。不要把读者、调用方、文件、交接步骤当作品内部结构，也不要靠四个层次都出现术语证明保真。

条件规则要保持方向与强度：默认方法在哪些条件下适用，哪个替代方法在什么条件下接手，例外覆盖哪一步或哪项内容，未知时先取什么证据。替代方案是分支，不自动变成连续必做；局部例外不能扩大为全局停工。若实质方法缺少会改变选择的条件或判断，返回 analysis 并指出缺项与影响；标点、段落、常规排序、实现方式等不改变方法的选择由 evolution 完成，不以“保真”为由阻塞。

当本次实施改动针对一项明确的创作原理、作品关系与可变实现时，正式范例只用于说明专业来源中的一种做法，不等于固定配方。保留其专业作用，并说明任务材料变化时哪些表面形式可换。沿同一原理走查两种材料条件不同的输入：两份产物可以使用不同意象、词句、节奏或技法，只要各自满足已选目标、组织关系与保护项，就不能仅因形式不同判错；反过来，照抄范例形式却未产生目标关系，也不能判通过。当前任务的局部试作可用于检查方法是否执行，不自动成为专业范例。此多形式检查不施加于路径、标点或无创作方法变更的普通修订。

若已选方法是以材料承载人物未直说的情绪，规则应保留“细节取舍由人物的注意、动作或关系决定”，不固定某种意象；当任务要求直接表达，或材料无法承载情绪时，应退出该方法，不为遵守原理补造内容。若修改者无法从已确认方案判断方法何时退出，这属于核心条件缺失，退回 analysis；不得自行增加专业结论。

## 先辨认关系，再选择 Markdown 形式

Markdown 标记只帮助读者识别关系，不能替规则补出没有写明的顺序、并行、许可、必需、优先级或停止范围。先确定要表达的内容关系，再选形式；自然解释和完整作品示范承担的信息不能为了整齐一律改成列表。

| 实际关系或用途 | 推荐形式 | 必须写明的语义边界 |
|---|---|---|
| 技能名称、主要职责、稳定的内部主题与局部主题 | 按层级使用标题 | 标题层级表示主题归属，不表示执行顺序。Phase／Step 只用于确有阶段或先后依赖的流程；平级主题、分类和分支不因排列位置变成顺序。 |
| 有真实先后依赖的操作 | 编号步骤 | 按依赖排列，并标明必要的等待、停止、返回或汇合点。只有当原因会影响选择、避免误用或说明依赖时才解释原因；不要要求每一步都附一段理由。 |
| 同层检查项、材料、独立对象或备选项 | 无序列表 | 表达并列，不表示顺序或并行。只有确需并行且可独立执行时，才明写“并行”及依赖、汇合点。 |
| 由输入触发不同处理 | 在发生判断的步骤下就地嵌套分支 | 正常路径先行；条件、动作及其局部停止或可继续范围相邻。明确分支是替代、可选还是补充；不能将一条局部例外扩大成全局停工。未知仅在会改变选择时单列。 |
| 同一组对象按稳定字段比较或映射 | 表格 | 列名定义每格的关系；比较、因果、优先或顺序关系须明写。复杂推理、细微条件和长解释保留为段落。 |
| 一个重复且稳定的简短信息结构 | 段内标签，如“输入／判据／动作／输出” | 标签帮助定位，不是每条规则都必填的字段；只在重复结构能减少寻找成本时使用。条件、动作和结果仍须写全。 |
| 需要精确复用的命令、路径、数据结构或输出形状 | 代码围栏 | 围栏前标明它是命令、必需结构、可改写模板还是示例。模板标明固定字段、可替换占位符和可省字段；若模板承载输出契约，还要标明契约规定的固定行数、字段及前后缀、允许附加内容，以及输出是替代还是补充周边内容；是否独占按原契约说明，不从围栏本身推断。命令标明可替换参数。代码围栏本身不表示可以自由改写。 |
| 用户原话、要直接发送的话术或供分析的作品片段 | 引用块 | 标明逐字原话、可直接发送的话术或待分析示例。说明允许替换的变量；不能把分析样例读成固定话术。 |
| 关键术语、路径、字段、状态值或字面命令 | 行内代码 | 精确指向可定位的字符串，不拿它代替概念解释。 |
| 少数真正需要强调的触发、强度或禁区 | 粗体 | 粗体只标重点；必需、允许、禁止和停止范围要用明确动词写出，不能靠加粗创建规则强度。 |
| 简短且方向明确的流程转换 | 箭头 | 写清起点、终点和触发条件；若可能被理解为因果、优先或执行顺序，改用文字。 |
| 供人逐项记录完成状态的清单 | 复选框 | 标明由谁依据什么证据勾选；空框不代表检查已执行，未勾选也不自动等于失败。 |
| 章节视觉分组 | 空行或水平分隔线 | 留白帮助看出内容边界；条件与动作不要被留白隔远。分隔线只作视觉分组，不承载条件、授权、优先级或流程转换。 |

以下是已选迁移方法的**正例**。围栏内是运行规则；步骤 1→2→3 有先后依赖，缩进项只在对应条件成立时触发，版本说明是可选项：

```markdown
1. 收到迁移清单后，核验目标文件的可恢复备份。
   - 缺少备份或备份无法恢复：停止本次迁移，不写入；返回受影响路径与失败原因。
   - 目标内容已完整、可读且有实际恢复方式：备份检查通过，不重复强制完整恢复演练。
2. 备份检查通过后，按清单顺序迁移。
   - 执行超时：停止后续步骤，返回已完成状态与失败步骤。
3. 全部迁移完成后，交付文件并检查原有效读取路径仍可用。
   - 可选：记录版本说明；跳过不影响完成。
```

以下是同一方法的**扁平化反例**，不能用作运行规则：

> 核验备份、按序迁移、处理超时、交付文件、检查路径并记录版本说明。

它把“缺备份时不写入并停止”和“超时后停止后续步骤”压没了，也把可选的版本说明写成了必做动作。把条件移成无条件步骤、把例外放到流程末尾或把许可改成祈使句，都会改变实际执行范围。正例与反例的区别在于关系和力度是否仍可读，不在于列表看上去是否整齐。

## 把判断写到能选择，把选择写到能做

先识别这一段承担的工作，再选句子结构。选择规则通常写成“观察到什么 → 依据什么判断 → 默认做什么 → 哪个条件使它改变”；连续操作按输入依赖排列；概念解释紧邻使用该概念的决定；完整成品独立展示，不夹入内部执行说明。

### 判据不能只是评价词

“素材充分”要说明充分到能支持哪项动作。例如用于解释一次结果时，至少能指出实际动作、结果及二者的已知关系；只有时间先后就按先后表达，不宣称因果。这里不要求所有任务采用同一充分标准，而要求本领域的标准来自已选方法，并且执行者能在输入中找到相应证据。

如果已有明确专业规范或 Reference，指向实际可读位置，避免主文重复展开。如果没有提供影响专业结论的判据，列出缺失的决定与材料交回 analysis；普通排序、章节和措辞由实施者选定，不以没有普遍统计证明为由阻塞。

### 分支要让不同输入得到不同处理

对每个关键判断，用成立、不成立和未知三种输入检查去向。成立时执行选定动作；不成立时用替代做法或退出；未知时取得能改变选择的材料，先完成不依赖它的部分。没有实际分歧的步骤不必人为拆三路。

不要只写“根据情况调整”。应指明调整哪个对象及条件，例如“用户要直接教程时先给第一步；正文价值在解释真实反差且用户允许等待答案时才后置结论”。相同素材服务不同目标可以有不同优选；规则应保留这种选择，而不是宣布某种写法永远更好。

### 操作不能停在任务名称

检查“补充、优化、深化、提炼”等动词后，执行者是否仍需自行发明核心办法。按照已选方案补出：取哪种材料、在哪里取、如何筛选、怎样变换、结果如何使用、做不到时怎么处理。材料与做法已有明确依赖承接就不重复；核心方法确实没有时不靠改句式掩盖。

“补素材”可落实为“先从正文和已给上下文提取遗漏的动作、对比或结果；仍缺支持核心承诺的事实时，向相应提供者索取该事实；未取得前交付现有材料能支撑的版本，不编造案例”。实际采纳哪些动作须来自本次已定方案，不强加给所有能力。

### 优先级应真正帮助舍弃

多个结果都满足硬约束时，按已选目标比较。先淘汰失实、换题或破坏保护项的候选；再看哪种做法更直接实现本轮效果。不要把每项都写“同样重要”，让执行者重新选择整个价值顺序。只有用户目标发生实质冲突才交回决定。

默认实现可以由负责人选。例如文件索引未定排序时，可按文件类型再按修改时间展示，明确只改展示、不移动文件；用户改变排序需求时切换。候选数量也可给工作默认值，但不能把默认数量说成成功率保证。

## 文字组织：完整、准确、密集，但让人和模型都读得明白

先按实际处理顺序组织，再检查句子。一个分支中的条件、动作、例外尽量相邻；只有触发、执行者或维护职责不同才拆段。长方法可以完整展开，不能为了短把关键判断移到没有调用条件的文件。

- **使用明确主语与对象。** “核对后调整”改成谁核对哪份材料、调整什么；代词只指向前文唯一对象。
- **让动词带来实际变化。** 选、删、移、比较、询问、生成、停止分别作用于具体内容；“赋能、提升、加强”只能表达目标，不能替代做法。
- **一句承担一个主要决定，必要条件随句保留。** 不把六个互不相同的要求挤成一串抽象名词，也不把一条完整条件拆得来回跳读。
- **成熟术语用于精确指定机制。** 绑定当前对象、动作和失效边界；名称不能替代解释，也不为通俗而丢失专业区分。
- **删的是重复作用，不是篇幅。** 两段都在提醒“不要空泛”可以合并；一段给选择、一段展示成品不能因主题相同删除。
- **检查实际语气与搭配。** 朗读完整片段，修掉不像人会说的话、生造名词和只在内部上下文成立的指代；不要用解释为不自然的成品辩护。

运行文件保留内化后的方法、必要解释、选择条件、动作、适用的成品示范及停止点，不塞入研究日志、DOI、来源评级或“本项目推导”。正式作品范例旁可简短保留作者、作品或教材及具体位置；其他资料出处和维护状态只在确有长期价值的维护位置保留。方法不依赖联网回读研究原文；当前任务需要核实新事实时仍按任务规则取得资料。运行内容齐全与研究过程不入正文可以同时成立。

## 逐段检验有效信息，而不是用长度代替质量

先读完整方法，再问每段使执行者多知道或多能做到什么。有效内容可以是区分、选择、动作、解释、示范或边界；必要解释即使没有命令，也能防止误用，不应按“不是动作句”删除。按下列情况处理：

| 读到的内容 | 检验方式 | 修订动作 |
|---|---|---|
| 目标、态度或质量标签 | 执行者能否据此在两个候选间作出不同选择 | 若不能，接上已选判据和动作；同一目标只在负责位置保留 |
| 正确但任何任务都能套用的提醒 | 删除后是否丢失本任务特有的决定、约束或保护 | 没有损失就删并；共同要求已在顶层维护则不反复复制 |
| 条件很多却不知道先做什么 | 给定一个普通输入能否确定第一步及下一步 | 按输入依赖组织，明确默认路径，将例外放在对应步骤 |
| 操作明确但不知道为何换法 | 改变一个决定性条件后，能否选择另一处理 | 补回适用原因和切换条件，不只再给一个模板 |
| 概念准确但读完仍无法制作 | 用正常输入能否产生可交付的局部结果 | 补材料变换过程与成品示范，不靠更多概念解释填补 |
| 示例好看却与规则无关 | 示例里的每个关键选择是否由已写方法支持 | 补方法或换成真正展示该方法的示例，不让隐藏经验承担全部效果 |

信息量不足时补的是尚未供给的决定与技法；密度不足时删除的是重复作用与无效解释。两种问题可以同时存在：一份很长的文件可以反复强调严谨，却没有任何冲突资料的处理办法。此时应删重复的严谨宣言，并完整写入资料比较、选择和无法确认时的做法；不是继续加一段“务必提高信息密度”。

深度检查沿一个关键决定追到底：看什么材料，依据什么关系，何时选哪种动作，怎么产出，什么情况不能这样做。广度检查横向覆盖已承诺的主要任务差别；遇到新条件能否转到有内容的方法，而不是所有分支最终都回到“综合判断”。二者以承诺范围为界，不强求穷尽所有知识。

文字修订完成后再次运行原例和关键条件变化的输入。若句子更漂亮却使选择变含糊、强度改变或关键例外消失，恢复原信息重新组织。若规则已经供给方法但实际未执行，修正调用或执行；若完整执行后产物仍不符合目标，交回分析检查方法和适用条件。这样当前稿的修订、长期方法的修复与反馈回流才分别有实际动作。

## 示例要展示选择过程与目标效果

### 正式作品范例的来源与临时试作的边界

正式 Skill/Reference 用来教授创作或其他专业表现的作品范例，须采用可核实的专业原作、原作者资料、专业教材或可靠机构教材。纳入前核读实际内容，确认出处可定位到作者、作品或教材及具体段落、页码或时间位置，并核对范例体现的机制和适用边界。名气、热度或数据表现不能代替专业依据；引文与转述要分清，引用只保留理解方法所需且与版权相称的内容；不得伪造出处、引文、作者或接收者反馈、效果验证。

引用在运行规则中保留简短的作者／作品／位置，必要时附来源链接；链接不可用时，规则中的方法仍须离线可执行，不把研究日志或联网阅读设为运行前提。找不到可靠且匹配的作品范例时，保留已定方法并标明示范缺口，不现编填充；缺少必要示范时不得声称教学验证已完成。

AI 自行创作、改写或生成的创作片段、段落或成品，即使标注“合成”“示意”或“案例”，也不能升格为正式的专业作品范例。正常用户创作、当前任务的完整局部试作和临时评测输出仍可按各自任务生成；它们用于交付或检查本次执行，不自动转入 Skill/Reference 充当范例。非作品型的语法、路径、字段或流程说明可以用合成片段解释精确结构，但不能借“语法示例”等标签偷渡自拟作品或作品话术。

若上游已选定方法，只缺少“找不到可靠范例时如何处理”这一实施边界，直接补为保留方法、标示示范缺口并继续可执行部分；只有缺失会改变方法选择或适用条件的专业判据时，才带着具体缺项返回 analysis。

根据所教能力选择示例，不按固定数量配齐：

- 教操作：同一输入怎样经过必要动作成为成品，中间结果确实被下一步使用。
- 教选择：同材料给出不同处理，指出哪条条件让其中一个更合适；不能换题后宣布更好。
- 教边界：改变决定性条件，展示为何改法也改变；只换人物名称没有这种作用。
- 教表达：给完整片段，让用户能直接感知语气、节奏和关系；只有“犀利、温暖”标签不算示范。
- 教失败修复：保留有缺陷的片段及具体问题，给实际修订稿，不只给修改建议。

指令规定动作，解释帮助理解，正例展示能力，反例展示失效，模板提供结构；五者不能互相冒充。真实案例按材料报告；非作品型语法／流程说明及临时评测产物可使用合成材料，并标明用途。不得伪造用户反馈、作品经历或验证效果。正式作品范例按上文来源要求处理；适用且可核实的原例可以直接复用，不为“不能模仿”重造专业作品范例。

### 保留已选方法的动作，不用虚构材料补范例

删除没有可靠来源的作品示范，不等于删除已选方法中的动作关系。若本次方案确实要求核对原始记录、比较来源口径、只暂停依赖未核实信息的段落并继续无依赖内容，这些判据、局部停止范围和继续条件仍须逐项写回；它们只按已选方法适用，不据此扩成所有领域的通用规范。用户要求的局部作品或临时评测输出可以单独交付，用于检查当前方法是否可执行；不得把该产物冒充正式教学范例。

## 核对描述、主文与 Reference 是否说的是同一项能力

逐一对照实际会被读取的位置：description 是否吸引正确请求；主文是否真正承接这个请求并交付所承诺的结果；Reference 是否在需要它时加载、用同一组对象和条件完成具体方法；示例与评测是否验证了这个结果。描述承诺超出实际供给时，优先落实已确认范围内缺失的方法，不私自缩小承诺来让检查通过。确需改变范围时交回拥有该取舍的负责人。

同一条决定只在一个位置定义。主文拥有任务边界、路由和完成条件，Reference 展开指定方法；引用处写调用条件与返回点，不把整套规则复制一遍。若同一条件在不同文件导向相反动作，定位并修复冲突，不能靠最后读取哪份文件来决定。检查术语指向是否一致，例如“验证完成”不能在主文指实际产物通过、在 Reference 却只指文件存在。

用普通请求、近邻请求、关键材料未知、途中修改条件四种情境走读。前两种检查谁应负责，后两种检查谁继续什么、暂停什么、如何恢复。检查循环：分析已经选定的方法不能被进化以“尚未实施验证”为由原样退回；进化发现方法缺少关键专业分支时，应带具体缺项返回分析，而不是自行补成既定决定。无新缺项、新证据或新取舍的重复转交不能算推进。

## 交付前的反向核对

先查覆盖：原方案每项决定是否有真实落点与消费者。再查保真：条件、动作、取舍、力度与效果是否还在。最后查产物：用普通输入加载交付文件，执行者能否独立完成关键选择与实际输出。

若规则只有提醒而没有承接原方法，继续修订；若核心专业方法本身缺失，带着具体缺项返回主文，不让用户重新复述整项需求。若已知方法存在但没有被执行，修调用或冲突，不追加同义禁令。文字更长、更短或检查器通过都不能单独证明完成。
