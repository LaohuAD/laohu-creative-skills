# 文件变更、配置与生态同步

由 [laohu-evolution 主文](../SKILL.md) 在定位文件真源、多文件重构、维护分层配置、同步宿主界面或更新评测时读取。本仓库的命名层级、部署边界、路径语法与校验规则以 [项目检查与版本维护](../../../../docs/maintenance.md) 为唯一真源，本文件给出执行清单。

## 1. 唯一真源归属速查

| 内容职责 | 唯一真源位置 |
|---|---|
| 跨项目极薄运行时硬契约（全仓必读） | `docs/runtime.md`（严禁塞入单 Skill 私活） |
| 仓库宪章、维护检查规范与元治理三件套 | `AGENTS.md`、`docs/maintenance.md`、`docs/governance/`（日常创作 0 加载） |
| 加载前的能力适用范围与路由判断 | 对应 Skill 的 `SKILL.md` frontmatter `description` |
| 加载后的核心方法、主流程与路由 | `.agents/skills/<name>/SKILL.md` |
| 宿主内部按需挂载的子级配置 | `.agents/skills/<host>/skills/<child-name>/SKILL.md`（仅单文件） |
| 按条件加载的专项方法或速查表 | 对应公开 Skill 的 `references/` |
| 确定性转换、CLI 工具或离线校验 | `scripts/` / `tools/` |
| Codex 展示与快捷入口 | 公开 Skill 的 `agents/openai.yaml` |
| 可复现评测与回归用例 | 公开 Skill 的 `evals/evals.json` |
| 老胡个人跨技能可复用偏好、事实与经验 | `knowledge/`（按授权沉淀） |

## 2. 多文件变更执行次序

1. **先读全盘并真备份**：读完受影响主文、Reference、配置、调用方与未提交状态，把实际现状备份至 `.cache/restore/`。若用户明确锁定了 Skill 名称、标题骨架或草稿框架，先记录锁定清单，绝不私自改动锁定项。
2. **按依赖顺序写回**：能在现有文件完成的就不新建，不创建 `_v1`、`_最终版` 等平行副本文件；依次更新 **唯一真源 → 宿主 `SKILL.md` → 加载前 `description` → `agents/openai.yaml` → 直接调用方与相对链接 → 必要回归评测**。
3. **接线核查**：
   - 凡新增或修改 `references/` 或内部子级，确保宿主主文把按需路由前置在动笔或核心执行流程入口之前，并用有效相对链接指向子级，写明触发信号、传入输入与读完回哪一步。
   - 若 Reference 仅优化内部写法而契约未变，不必为表面同步顺手改写无关主文。
   - **跨文件全局扫残与四层不复读**：凡松绑主文旧枷锁、升级核心原理或迁移文件，必须全仓扫描并清理下级 `skills/*/SKILL.md`、同级 `references/*.md` 与关联 `knowledge/` 偏好文件中打架或复读的残留条款（严守二级底座、参考深工艺、三级专属强化、个人偏好四层不复读；二级已落位的通用原理、护栏与成稿自检，三级子技能直接承接绝不换词复述，只写本专项独有机制、现实逻辑与专属检验）；合并、迁移或删除文件前先更新所有真实调用方，确认零遗留死链后再移除旧文件。向隔离输出目录交付改后 Skill 与配套诊断报告时，须将改后 Skill 单独放在独立子目录中，与诊断报告物理隔离防盲测泄题。

## 3. 加载前入口、UI 配置与分层硬规范

- **写好加载前 `description`**：仅当适用情境、对象、前提、范围或交付变化时更新；用普通用户口语说清什么时候进、交付什么、明确不做什么，避免被偶然关键词误触发，且正文必须兑现 `description` 的每项承诺。
- **同步 `agents/openai.yaml`**（公开入口受 `tools/check_project.py` 硬校验）：
  - `interface.display_name`：以精确 `<name> | ` 开头并含中文名称；
  - `interface.short_description`：**严格 25–64 字符**，且核心适用范围须与 `SKILL.md` 的 `description` 对齐（不擅自写窄或超卖）；
  - `interface.default_prompt`：包含 `$<name>` 的可直接发送请求；
  - 保留已有的 `policy`、`dependencies` 等无关字段；内部三级子级不建 `openai.yaml`。
- **内部三级子级守门**（详见 `docs/maintenance.md`）：
  - 严格单文件 `skills/<child-name>/SKILL.md`，禁止嵌套子目录、自建 `references/`、`openai.yaml` 或 `evals/`；
  - 区分**选择型专项**（仅用户明确意图选定时触发，未选时宿主沿通用路径独立完成）与**父级方法模块**（由宿主按主文声明的任务信号调用并整合），绝不因目录存在或材料偶现题材词自动触发，也不允许兄弟子级递归互调。
- **严守单向依赖**：顶层 `docs/runtime.md`、`AGENTS.md`、`docs/maintenance.md` 与 `docs/governance/` 不得反向链接任何具体 Skill 的私有内部文件。

## 4. 链接语法、评测同步与结构终检

- **路径与链接校验**：
  - 公开 Skill 正文必须包含 `{SKILL_DIR}/../../../docs/runtime.md`；
  - 仓库内所有 Markdown 链接必须以当前文件为基准写相对路径，**严禁在 `[...](...)` 中出现 `{SKILL_DIR}`/`{PROJECT_ROOT}` 占位符、本机绝对路径或 `file:` URI**。
- **按需同步 `evals/evals.json`**：
  - 触发条件、主流程或契约变化时，排查受影响的旧用例并更新冲突预期（保留原输入与仍有效保护项，不删旧例掩盖失败）；
  - 由真实断点或 `AUDIT-ID` 触发的改动，可追加 1–2 个普通口语最小回归用例（不把内部术语或答案写进 prompt；`execution_mode: "write"` 用例须提供隔离路径 `fixture_setup.files` 与完整 `input_files`）。
- **结构与污染终检**：改完必在仓库根目录运行 `python3 tools/check_project.py`（动到工具、发现、安装或版本逻辑加 `--test`），同时核查运行态体积、外部入链锚点完好度、装饰双引号与高频示范锚词清零、以及创作类规则正文未染上冷硬架构说明书腔，全部 PASS 后再进入实证门禁；并明示磁盘写回不等于宿主菜单已自动刷新。

## 5. 自适应对比实证执行与防负进化门禁

针对二级/三级实质改动，按[评估与验证协议](../../../../docs/governance/evaluation-protocol.md#2-隔离-abc-盲测自适应标尺与防负进化门禁)落地闭环实证（涉及颠覆性假设或反复钟摆震荡时，先在 `.cache/validation/` 做单变量隔离探真并交人类肉眼/真耳确真，再融写进入下方正式盲测）：

1. **隔离基线夹具（测完即清）**：改前先将目标旧版导出至 `.cache/validation/<run-id>/env-B/`（挂载与新版一致的其余公共顶层文件，确保 B 与 C 之间唯一变量为本次改动），验证结束后删除临时 `env-B/`，保留 `.cache/restore/` 改前恢复副本。
2. **零泄漏隔离派发与白盒监控**：派发彼此隔离的同模型独立子 Agent 分别跑 **A 组（纯原生 0 规则）/ B 组（`env-B/` 旧版）/ C 组（改后正式文件）**，至少覆盖回归痛点题与全新零污染留出题；输入只含普通用户请求与业务材料，严禁泄露重构讨论、设计意图或评分答案；同步统计白盒客观指标（加载规则字节数、读取文件数、端到端耗时，以及必要时的思考字节以排查事前填字数独损耗）。含多风格三级子技能时，增做摘掉流派标签的**脱标风格盲辨**。
3. **零格式污染拉丁方匿名盲评**：将三组完整原始输出脱敏（清理路径、技能名、版本线索）、逐份核查无格式残缺或打包污染，并按**拉丁方乱序换位**交独立匿名裁判；评分维度从本目标的第一性原理与**纯终端真实受众体感**现场派生（严禁把内部规则术语塞进打分表充当打卡项，防机器评委偏爱工整安全书面稿），强制要求裁判原句举证并毫不留情指出第 1 名的缺陷。
4. **放行、打回与回滚**：
   - 仅当 **C 稳胜纯原生 A、优于旧版 B（或质量不降且大幅减负）、且未破损硬边界** 时，判定正进化放行并透明交付（AI 盲评记 `QUALITY: OBSERVE`，附一字不改的 A/B/C 代表性完整原始输出交人类肉眼或真耳终审定音）；
   - 出现不达标或负进化时，记 `FAIL` 并自主打回分析重改再测（上限 **2 轮**，迭代复验须补全新未参与调优的留出新题 `H`）；2 轮后仍未达标或存在方向分歧，立即停止强推，带完整证据交用户决定改向或回滚恢复。
