# 老胡能力进化

## 核心职责与边界

**专业取舍由已确认方案决定，文件与调用由本入口接通。**

把已确认的能力目标、专业方法和关键取舍写进未来执行者会实际加载或运行的位置，让普通请求能沿最终文件完成工作。本入口核实真源、保护有效内容、重排规则、接通消费者并检查授权范围内的实现；不代改当前作品，也不替用户重选会改变规则的未决目标、权限、方法或取舍。出现此类分歧时，把材料、差异和影响交 analysis，并只暂停依赖部分；文件位置、自然措辞、章节组织和可恢复接线属于实施职责。

本入口同时承担两项模型责任：用万能造梦框架组织 evolution 自身的判断与实施规则；在创建、更新、重构或沉淀目标能力时，把同一模型转成目标 Skill 的专业规则。前者不能替代后者。能力建设要结合目标用途、接收者、已选专业方法与实际材料，逐一把16个交点落实为目标能力所需的职责、条件、判断、动作与可检查结果，写进目标主文和确有必要的 Reference，交付能指导普通任务的能力文件，而不是模型说明、坐标清单或“已覆盖”声明。普通业务执行不因此被要求加载或重述共享模型。

运行规则的新增、修改、融合或移除，先读完整[规则表达与方法保留](references/rule-expression.md#更新规则前按语义对照)；涉及多文件、迁移或消费者时，再读[能力文件增、改、删](references/change-workflow.md)。下列四组按真实职责组织，不是固定问卷或必须照标题顺序填表；普通任务路径、主文与 Reference 的职责在对应条款中落实。

## 确定能力目的与改进边界

本组确定本轮究竟要改变什么、为何改变，以及哪些既有能力必须保留；后续方法选择与写回都以此为准。

### 明确能力为谁解决什么任务

1. **从普通说法还原用途与入口。**对新建能力，结合用户普通表达、任务阶段、遇到的问题和期望结果，确定未来用户何时需要选它；对既有能力，再核对普通输入、输出和直接消费者。把 frontmatter 的 `description` 视为加载前的入口判断，也是能力组成之一；旧描述只作待核材料，不代替真实用途。
2. **分开接收角色。**标出委托改进的用户、负责规则的作者、未来执行 Skill 的模型或人、直接机器消费者，以及最终人类接收者；需要时说明他们各自如何使用结果。
3. **把目的接到两条链。**evolution 实施链要说明本轮请求具体改变什么、保护什么；目标 Skill 运行链仍须把已确认目的写成会改变普通请求处理或产物的规则，frontmatter `description` 在加载前帮助识别适用请求，正文和实际读取的 Reference 承载并执行该规则。用途不清时先核实目标材料，不从旧规则臆测原意。
4. **按职责变化决定是否改写入口。**每次实质能力更新都复核 `description`；只有适用情境、任务对象或意图、关键前提、范围、交付类型或足以区分近邻入口的边界发生变化时才重写。仅调整内部步骤、排版或措辞而不改变何时选用及交付时，保留原描述，不为“同步”而机械改字。

### 用现有证据判明差距与判断标准

1. **把材料对齐同一目标。**将用户反馈、当前规则、执行记录和实际产物相互对照，分别记清已确认事实、推论和未知项，再定位条件、决定、动作或接收的哪一处没有传递目标。
2. **找到第一个有证据的断点。**若方法存在但本次未加载或未执行，修触发、调用或运行路径；若规则确实缺已确认的核心方法，才补方法；若按规则完整执行仍未达成或适用条件不足，把方法/取舍差异交 analysis。不能从局部错误推断整条链都失效。
3. **用可观察标准代替赞语。**目标 Skill 的判断标准要说明该项功能如何改变用户处理或接收的结果；“更好、更自然、更完整”等词不能独立充当判据。
4. **不把形式证据当功能证据。**文件存在、链接可点、标题出现或单次局部通过，都不能证明方法被读取、执行或达成目标。

### 把已确认的优先级变成范围与取舍

1. **沿用已确认选择。**保留本轮任务状态、授权、方法、优先级和保护项；不重问已定事项，不由 evolution 重选尚未确定的专业取舍。用户亲自选定的方案按本轮范围实施，不冒称其外部效果已验证。
2. **按职责依赖选改动规模。**只涉及已知文字、路径或单点接口且不牵动其他职责时局部修；核心职责、主方法、Reference 分工或消费者相互牵连时，完整接通目标到交付。整体重构不能只改显眼一句；局部修订也不借模型扩成无关全仓扫描。
3. **局部暂停未决判断。**若核心目标、权限、方法或取舍仍未定且会改变行为，交 analysis 具体材料、差异、影响和待决点；暂停依赖它的写入，其余已授权工作继续。文件位置、自然措辞和可恢复接线是实施责任，方法本身不扩大授权。

### 写明改后能力的预期结果与证据边界

1. **定义可接手的预期。**写清目标 Skill 的普通请求应能完成什么、交给谁、保护哪些旧行为，以及哪些输入或产物能观察到变化；evolution 的预期则要能落到规则加载路径、消费者和下游动作。
2. **分开预期与事实。**分别记录规则选择、结构观察、实际执行和真实接收效果。缺少本地效果数据不阻止已授权且可恢复的实施，但不能把预期写成已经发生的质量改善；真实接收质量按项目证据等级判定。

## 组织可执行的专业方法

本组把已确认的目标落实为目标 Skill 普通任务里真实会发生的决定和动作。领域方法来自本轮已选规则、适用专业来源和实际输入；模型方向不能代替方法。

### 从普通请求还原核心工作路径

1. **先还原目标能力的普通任务。**创建、更新、重构或沉淀能力规则时，先读取根目录[万能造梦框架](../../../references/universal-dream-framework.md)，再结合目标 Skill 的 description、普通请求、输入与输出、直接和最终接收者、实际材料，依次还原输入、任务/边界判断、方法选择、材料处理、中间产物、下游接收与最终交付；说明已确认的用途、优先级和保护项在哪些决定上改变处理。不凭名称或旧标题推定目标。若只是执行普通业务请求，不为此流程加载模型。
2. **把16个交点落实为具体专业判断。**逐一审视四维与四层的交点时，依据目标能力的核心作用，确定此处必须作出的具体专业判断：输入中哪些差异会改变选择，依据何种方法识别和处理，怎样形成后续工作所需的内容，以及最终从何处观察其作用。已有规则充分承担时保留并接通；内容不足时，沿该项工作补足条件、方法、材料处理或成品实现。一个交点可以展开多组真实规则，完整方法也可以跨越交点；组织依据是实际工作关系，不是坐标数量。核心取舍仍未定且会改变规则时交 analysis。
3. **用唯一语义对照决定新旧规则去向。**逐项比较已确认的新方法/经验与现有规则，按[规则表达与方法保留](references/rule-expression.md#更新规则前按语义对照)的唯一语义表决定保留、融合、补充、分支、替换或新增；有效旧条件、例外、接口和保护项一并保留。核心方法或取舍仍未确定且会改变目标行为时，交 analysis 并只暂停依赖它的写入。
4. **让专业方法、材料操作与成品形成递进关系。**按已确认目的及其取舍，确定目标能力采用的专业方法；再把方法落实为当前材料的选择、组织与具体表现，最后进入真实成品的生成、修订和验收。章节使用领域工作语言，但必须让执行者看清前面哪项决定要求后面采取什么处理，后面结果怎样兑现前面目标；已有逻辑依赖不能整理成平行条款，独立职责不强造先后。跨多个交点的完整方法保留为一个可运行真源，在其他相关位置说明何时调用、影响哪项判断及结果回到何处。
5. **回到普通任务核验建设结果。**检查已确认的关键决定是否有实际规则承接、触发条件和动作是否明确、结果是否进入普通请求并由下一步使用；不能用条款数量、标题、术语或覆盖声明代替。后文[全方向检查](#用全方向检查确认已有承接和真实缺口)负责逐向核实既有承接和缺口，避免在两个环节重复建立清单。
6. **让主文与 Reference 各自承担真实工作。**主文保留统领判断、核心专业步骤和必要衔接，使执行者凭主文及明确调用的资源完成普通请求；Reference 可深化独立方法或条件分支，但不可成为知识摘录、改写上游目标/权限/入口职责，或让主文只剩“读取此文件”。不把 evolution 的实施清单复制成目标能力规则。

### 写出加载前可判断的 description

1. **从未来用户的实际起点写入口。**用常见任务语言说明什么情境或问题下该选此能力、它会完成什么任务并交付什么；新能力可从普通说法、模糊症状、任务阶段和用户期待结果还原，不要求用户先说出 Skill 名、专业术语或固定命令。必要前提和最近似的易混入口，只写足以帮助选择的区别。
2. **确保入口在加载正文前就有用。**`description` 必须独立说明适用场景、要解决的任务和预期交付，不以“详见正文/Reference”补足触发理由；但它不是工作流摘要，不把内部步骤、专业理论清单、框架坐标、关键词堆或全套排除事项塞进一句话，也不要求逐句装入目标、判断、行动、结果四层。
3. **按意图而非字面触发。**不同措辞表达同一任务时应能被识别；不要把某主题、文件名、引用文字或被否定的请求单独当作触发。description 不把用户锁定为某一种说法，也不因材料提及一个主题就承诺处理该任务。
4. **只承诺真实能力与授权。**将描述中的范围、输入、前提和交付与已确认方案、目标主文、真实会加载的 Reference 及 runtime 权限相互核对。未定专业取舍仍交 analysis；不能用更宽的宣传语补正文缺失的方法，也不能承诺正文与授权不支持的动作。

### 选定并核实真正指导工作的专业依据

1. **从实际功能找适用方法。**核对任务已明确的方法、现有规则与会被实际读取的本地专业资源；专业选择会改变操作时，读取能给出适用条件、判断依据和动作的方法，而非只记名词。用户或 analysis 已选定的方法按确认范围实施；来源待核只限制来源归属/原意与外部事实效果断言。方法或条件本身不清且会改变动作时，只暂停依赖决定并交 analysis。
2. **需要作品依据时读真实方法。**关键声口、节奏、叙述或媒介处理尚未选定且会改变生成方法时，读[真实作品研究方法的日常创作取法与方向](../../../references/exemplar-study.md#日常创作取法与方向)，核对真实作品单元、必要语境、可观察处理和适用条件，并接入生成步骤与成品位置；不以抽象赞语或作者/理论名代替表现方法。
3. **按实际依赖读取共享专业 Reference。**读者/使用者的理解、行动、情绪或审美会改变目的或组织时读取[读者价值与作品组织](../../../references/audience-value-and-structure.md)；目标 Skill 实际生成或修订文字时读取[语言成文](../../../references/language-realization.md)。读后回到主线中由该方法改变的决定。正式比较作品质量或校准时，依[正式评估与 L/C/D/H](../../../references/exemplar-study.md#正式评估与-l-c-d-h)及 analysis 验证协议办理。

### 把已选方法写成正常路径、条件和分支

1. **写全规则的执行关系。**在实际决定位置给出触发条件、输入、适用标准、执行者、动作、顺序、默认、替代、例外和退出；说明条件怎样改变选择。不得只写方法名、效果词或“按需/适当”。
2. **保真用户选择与专业来源。**保留适用条件、优先级、步骤、舍弃对象、例外、停止点和力度。准确适用的用户原句、标准术语、核心命题直接进入判断位置；只有迁移后仍有歧义/执行缺口才补本地说明并标清来源原意与适配。外部引文核实上下文、遵守短引边界；无法核实时转述，不冒称原话。
3. **让运行方法在本地闭合。**Reference 要写出执行所需的方法、条件、判断、步骤和例外，不以外链或网页为补缺依赖。诗学原则句可按用户选定的现代汉语风格凝练表达；机制和操作仍依 [runtime 的沟通与表达规则](../../../docs/runtime.md#沟通与表达)写清触发、动作、数量、产物和例外，不能让源头语体变成目标作品风格或以诗句替代操作。

### 使每一步产物成为下一步的真实输入

1. **跟踪关键中间产物。**为实际工作步骤标明产物、完成状态和接收者；后一步只能引用前面成功产生的对象或状态。失败/取消未产生产物时，补有授权的创建/恢复动作或退出该分支，不假设产物存在。
2. **检查结果是否被消费。**每一步产物须被下一步作为输入、判断依据或状态实际使用；它可以确认原有选择，也可以触发选择改变。最终产物分别满足人类接收者和直接机器消费者的用途。只追踪影响决定或下游动作的依赖，不把作品拆成逐词对象台账。
3. **保持接口与四作用自然衔接。**目标、判断、行动、结果可以由规则段内的多句话、相邻步骤或共同条件承接，不拆固定四栏；预期效果与实际效果分开。既有产物类型、字段/机器模板、用户话术的格式、顺序、必需项、占位符和适用条件保持不变。

## 用真实材料归组并写回控制点

本组把判断落实到真实文件与消费者：evolution 检查现有规则和改动依赖，目标 Skill 则把实际输入转成专业处理结果。先有材料，再判断缺口；标题不能代替规则执行。

### 找准实际文件、控制点和恢复位置

1. **查明真实控制文件与消费者。**核实项目根、Skill 真实目录，读取目标主文、受影响 Reference、调用方、配置、脚本和评测。沿请求触发、资源读取、决定、动作、消费和交付找到控制预期行为的位置；只查本轮授权范围和必要直接消费者。
2. **按调用关系确认 Reference 职责。**记录谁在什么条件下读哪份资源、它提供什么判断/产物、读完回到哪一步；不能从文件存在推断调用。区分规则已提供、运行时已加载、方法已执行、结果达到目标四种状态，不能相互推定。
3. **保留可恢复的当前状态。**编辑前依[运行约定的过程文件存放规则](../../../docs/runtime.md#过程文件与恢复副本的存放)把当前实际内容保存在项目同盘，包括未提交、未跟踪和需要保护的忽略资产；Git HEAD 不能代替当前状态。
4. **制作轻量变更映射。**记录本轮目标、旧控制点、有效保留项、拟融合/替换内容、消费者及检查点。多文件迁移另按[能力文件增、改、删](references/change-workflow.md)确定写回与恢复顺序。

### 用全方向检查确认已有承接和真实缺口

1. **先建材料基线。**任何运行规则改动都读根目录[万能造梦框架](../../../references/universal-dream-framework.md)，并用[找准实际文件、控制点和恢复位置](#找准实际文件控制点和恢复位置)的材料、已确认目标、专业方法、输入材料与消费者建立本轮盘点；不凭旧章节标题或模型标签预设缺陷。
2. **对两条链逐向给出实质判断。**对授权范围内16个交点逐一检查：在 evolution 实施链中，它如何改变改动目标、判断、写回动作或消费者判断；在目标能力链中，以[从普通请求还原核心工作路径](#从普通请求还原核心工作路径)确定的普通任务职责与专业方法为基准，核对它如何改变具体处理或交付。每个方向都要指向实际材料与规则位置；若该方向包含多个子职责或规则组，分别记录有依据的判断，同一方向可以同时存在已承接与待补缺等不同结论，不强求一个统一答案或固定状态模板。
3. **检查方向间的实际关系。**目的和优先级须能影响可观察任务；方法和标准须真实指导判断；输入、旧规则、分支和材料关系须进入具体动作；媒介、接收者、接口和结果须能被下一步使用。同一关系可承接多个方向，一个方向也可有多组独立规则；完整方法可以跨方向。
4. **不为覆盖而制造答案。**不是每格都要新增规则或向用户展示；没有材料不能推测缺陷，标题/术语不能证明充分。全方向检查拓宽注意范围但不穷尽领域知识、不证明方法有效，也不单独证明最终质量。

### 依据语义把规则合并、替换或分支

1. **先综合再安排位置。**完整走完全方向审查后，找出交点间依赖、重叠、互补、冲突、条件分支和跨方向完整方法，形成自然工作组、唯一真源与实际章节。
2. **按唯一语义表处理新旧内容。**在[规则表达与方法保留](references/rule-expression.md#更新规则前按语义对照)逐项比较旧判断与新选择，并用该 Reference 的语义对照表裁定融合、补充、分支、替换、新增或退役；不按旧标题盘点，不靠末尾总原则代替原控制点写回。
3. **保住独有有效内容。**规则迁移/合并后，逐项核对用户决定、事实边界、接口、保护项、例外、用户话术身份和合法范围仍有实际位置；失效内容可退役，但不得连带删除仍有效的独立条件。
4. **按完整方法组成可运行规则组。**语义单元用于比较，互相依赖的方法在运行正文保持完整的输入、条件、顺序、动作、例外和结果；按共同对象、条件、结果与消费者归组，同方向可有多组，完整方法可跨方向并由相关位置承接唯一真源。共享模型可以指导章节、段落和分组；标题用实际工作语言。归组与成文细则由规则表达 Reference 承担。

### 接通 References、配置和所有直接消费者

1. **以依赖次序同步文件。**先确定唯一真源，再更新主文触发时点、资源路径、解决的问题和返回位置；之后同步直接调用方、模板、配置与评测。新增文件须有独立职责和真实消费者，不能复制整套规则或只留下未被普通请求加载的引用。
2. **只改真实受影响的配置。**公开能力职责或默认触发变化时，核对 `agents/openai.yaml` 展示名、说明、默认提示；职责未变可不改。内部部署配置由宿主负责展示、调用和评测，不另造界面。
3. **保留评测与机器契约。**`evals/evals.json` 保留有效旧输入和失败样本，按新增分支补普通输入与可观察判据；不得删改预期掩盖失败。产品字段、机器模板和固定输出格式保持精确，未获用户要求不把资料、样例或内部审核写进目标成品。

## 形成接收者可用的结果并验证

本组检查最终执行者、读者或系统真正接收什么，并让条款既可直接执行，也可追到它在目标能力中的实际承接位置。

### 按真实任务命名章节和组织条款

1. **按任务标题组织正文。**标题写业务动作、判断或交付物，帮助执行者定位何时做、怎样做、交出什么；可以让模型指导章节和规则组，但标题不用模型坐标。组织可形成十六个自然职责组，也可跨组承接；不要求十六个标题或以标题数量验收。
2. **让陌生执行者能直接操作。**每条规则用自然语言说明真实关系、条件和动作，不把框架术语当答案或将具体工作压成抽象质量词。独立规范按可查找条款展开，必要时编号作索引；顺序由真实依赖关系说明，不从编号推断执行先后。机制和因果关系可在对应条款内连贯解释，横向条件对照才用表格。
3. **分开规则语体与作品语体。**Skill 的表达偏好不自动成为目标作品风格；机器和生产接口按契约呈现，不为好读任意增删字段。

### 校对措辞力度、输出接口和来源身份

1. **保真要求强度。**逐项检查行动主体、“必须/应当/可以/禁止”、默认、替代、例外和停止条件；局部暂停不可扩为全局停止，可选项不可变必做。
2. **标明内容身份与出处。**用户锁定原话和标准术语准确保留；分别标明可复用话术、可调示范、解释文字、外部引文、机器模板和最终作品。引用块不自动是外部引文；原文、译文、自译、意译与本地适配须区分，不能编造来源、作者、原话、反馈或结果。
3. **维护格式接口和复制性。**保住表格条件—动作对应、模板围栏/语言标记、字段顺序、必需/可选项、占位符、可替换段和条件；嵌套 Markdown 用足够长的围栏。示例不自动成为模板，除非所选方法明确要求固定输出。
4. **服从真实交付需求。**交付形式由用户要求、接口契约和接收者用途决定；未另定时用自然段交接，不另造报告模板。

### 用普通任务走通并修复真实断点

1. **按影响范围走通普通路径。**核对目标 Skill 主线、必要分支、Reference 消费与最终接收点；局部修改只查改动路径及必要近邻。使用普通输入走到下游产物，检查决定时点、中间结果消费、条件切换、保护项和接收接口。走查不产出创作作品示范。
2. **反向核对入口与加载后能力。**维护收尾时，先仅用候选 `name` 与 `description` 对照普通请求的表达意图和所需产物，不借正文或 Reference 补义：检查适用请求能否入选、近邻任务能否排除；只有关键信息不足且会改变入口选择时才澄清。这个对照只检查入口判断，不冒充宿主的真实隐式调用或完整业务执行，也不要求每次新开 Agent、填表或使用固定数量的样本。随后再将最终描述中的输入、范围和交付对照目标主文及本轮真实会加载的 Reference，确认有可执行规则承接。若入口信息不足，修描述；若正文或 Reference 缺方法，按已选方案补齐或报告未决，不以扩大描述代替能力，也不因磁盘写回就宣称现有会话菜单已刷新。
3. **元能力使用两阶段独立验证。**第一阶段从普通请求和真实原始材料出发，由最终 analysis/evolution 自己还原目标、形成必要的专业判断与条件动作，再建立或整体改进目标 Skill；不得把已给出完整 `approved-method`、理想架构或逐项答案的实施案例算作从普通请求构建方法的证据，这类案例仍可用于验证对已选方案的忠实写回。第二阶段另由未参与设计、未见过程的执行者，仅凭最终目标主文、真实会加载的 Reference 和新的普通输入，独立完成任务。构建者不执行第二阶段、不提供评分预期。追加聊天若补足文件缺少的核心方法、目标、取舍或验收，只记录为额外指导下的表现，按[判断、运行与下游产物验证](../laohu-analysis/references/validation.md)记影响；写回已确认内容后再作无指导复查。
4. **单个目标能力变更也由独立执行检验。**方法或行为有实质变化时，未参与候选设计者只凭最终文件和普通任务输入独立执行；看条件是否改变选择、中间结果是否被消费、保护和接口是否保留。
5. **守住创作样本边界。**analysis/evolution 不创作标题、文案、故事、歌词、场景等作为教学、试作或验证样本；作品需实际生成时，只由获授权的目标 Skill 按最终文件完成用户任务。合成材料只验证技术路径、结构和接口。若专业表现方法未定，补已确认方法或交回专业判断。

### 按证据交付，不把结构检查说成质量通过

1. **运行适用静态检查。**从核实的项目根运行 `python3 tools/check_project.py`；只有脚本、发现或版本逻辑改动才另按 maintenance 跑离线回归。引用、JSON和本轮适用检查均运行并记实；临时目录与恢复副本留在项目同盘。
2. **分开报告四类证据。**按项目定义记录 `STRUCTURE`（路径/格式/引用）、`ROUTE`（真实请求读取正确规则）、`BEHAVIOR`（动作/分支/产物变化）、`QUALITY`（接收者、专家或真实使用结果）。未检查是 `UNKNOWN`，有观察但证据不足是 `OBSERVE`，已观察到的目标差距是 `FAIL`；其他范围的结构通过不能覆盖失败。没有真实接收/使用结果时质量为 `UNKNOWN`。
3. **交付可恢复的改动报告。**说明文件路径、保留/融合/迁移/退役内容、实际检查、证据状态、未知项与恢复位置；实施自评不是独立验证。除非另获明确授权，不准备版本、不提交、不推送、不发布。
