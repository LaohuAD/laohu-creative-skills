# 老胡能力进化与重构

把**已确认的目标、方法、经验教训或变更规格**，低熵、精准、安全地编译进长期能力文件与真实执行链路，让未来的普通请求不靠人工临时叮嘱即可稳定变强。承接[三技能协作协议](../../../docs/governance/triad-handoff.md)的决策级变更规格；写回中若暴露会改变核心目标、专业方法或权限边界的未决冲突，只暂停依赖写回并带事实交回 `laohu-analysis`，其余已授权工作继续。

## 0. 进化第一铁律：先除限，再归位，最后才增补（Subtract Before Add）

动笔改任何规则前，强制先过三问——**杜绝遇到问题就往末尾贴补丁的规则棘轮**：

1. **能不能靠做减法解决？** 先查原问题是不是由过时微操、重复防呆或条款打架引起——凡能通过**删除、松绑、合并**解决的，绝不追加新禁令。
2. **现代强模型原生是不是本来就会？** 如果删掉这段话，前沿强模型纯裸跑也能做得同样好甚至更有灵气，**绝不写操作手册**；只把规则篇幅押在**原生稳定短板、稀缺品味锚点、以及确定性工程/安全契约**上。
3. **这是单次作品偏好还是跨任务真规律？** 只适用于眼前某件作品的喜好留在该作品，不把偶然好评硬编码成全局死规矩；沉淀拍案叫绝的好示范时，先反推背后的底层原理与根本判断，再按目标 → 判断 → 行动 → 结果零锚词闭合写入（细则见 [rule-expression.md](references/rule-expression.md)）。

## 1. 核清目标范围、真源与改前真备份

1. **分清目标项目与改动规模**：先按 `docs/runtime.md` 确认要改的是当前业务项目规则还是共享老胡仓库；局部单点修只动受影响控制点，新建或整体重构从目标到消费者完整接通。
2. **找准唯一真源并备份现状**：编辑前查清当前受影响的全部主文、Reference、配置、调用方与未提交状态；将实际现状（含未提交、未跟踪或被忽略的重要资产）备份到 `.cache/restore/`（项目外依当前项目缓存约定），**绝不拿 `git HEAD` 替代当前实际现状备份**。

## 2. 双轨写回与全向校准

1. **按改动范围核对生效方式**。整体新建、重构或跨职责融合时，按[三技能协作协议](../../../docs/governance/triad-handoff.md#3-三技能的检查范围)把必要方法落实到目标领域的流程和判断。局部修订聚焦受影响的位置及直接上下游，核对保护项与接口。
2. **按双轨法则落笔**：读取[规则写法与双轨表达](references/rule-expression.md)编写与合并条款：
   - **硬契约轨**（安全授权、路径隔离、脚本命令与参数、JSON Schema、跨入口接口、**用户或领域明确约定的固定输出格式契约（如特定段标、气口、独立代码块、指定 JSON/CSV/表格模板）**、仓库校验红线）：确定、零歧义、写清触发与停止，**严格无损，绝不借做减法误删或擅自增改接口细节（如私自增删代码块语言标、符号边界等）**；
   - **软判断与创意轨**（品味、思考、诊断、拆解、创作与规划方法）：给**殿堂级标杆、三态裁决弹性、正向抓手与底层原理（Why）**，把执行自由还给强模型，绝不把好原则写死成僵硬教条，更不把刚删掉的常识换个马甲复读导致越精简越膨胀。
3. **原位增量融合，不拆东墙补西墙、不叠尾部补丁**：先判新要求在 4×4 的归属层，直接在真正决定行为的控制点合并、替换或删除旧条款；写回必守**三不丢（不丢已验证有效的旧强长板、不丢新旧张力的 A×B 共存条件、不丢媒介体量与题材适用边界）与三必清（必清运行态学术黑话与示范锚词污染、必清非物理死数字枷锁与冗长禁词表、必清下级子技能及参考里打架或复读的残留旧规）**。主文保持轻量可扫读，独立重专项按需拆入 `references/`，运行方法须在本地闭合、不依赖外链网页。

## 3. 生态接线与依赖同步

涉及多文件、引用、公开/三级子技能或评测时，读取[文件变更与生态同步](references/change-workflow.md)按依赖次序完成收口：

1. **先真源、再主文、再入口与消费者**：依次更新唯一真源 → 宿主 `SKILL.md` → 加载前 `description`（仅适用情境、对象、前提或交付变化时更新，保证加载前可独立判意图）→ `agents/openai.yaml` → 直接调用方/相对链接 → 必要回归评测（`evals/evals.json`）。
2. **共性经验沉淀边界**：仅当跨多个 Skill 反复验证有效且用户明确授权长期沉淀时，按[三技能协作协议](../../../docs/governance/triad-handoff.md)将经验写入根目录 `knowledge/`；真正改变运行时行为的规则仍写回唯一规则控制点。

## 4. 自适应对比实证门禁（防负进化闭环）与透明交付

写进磁盘绝不等于完成进化——不是每条看似有理的新规则都能在前沿强模型上带来净增益。除纯机械维护外，**必须经独立对比实证确认确有提升才算完成进化，坚决阻断负进化**：

1. **减负清透自查 + 静态强校验**：
   - 核查是否清除了重复真源、300+ 字文字墙、高频示范锚词、装饰引号、下级子文件残留旧枷锁与换马甲回流的旧限制，硬契约/保护项/下游接口 100% 完好；
   - 维护老胡仓库时，必在仓库根目录运行 `python3 tools/check_project.py`（动到工具、发现、维护或版本逻辑加 `--test`），退出码须为 0。
2. **自适应分级独立对比测试（详见[评估与验证协议](../../../docs/governance/evaluation-protocol.md#2-隔离-abc-盲测自适应标尺与防负进化门禁)与 [change-workflow.md](references/change-workflow.md#5-自适应对比实证执行与防负进化门禁)）**：
   - **重大底层假设先单变量探真**：怀疑既有规则成天花板或做底层审美大转向时，先在隔离区单变量跑出成品交人类肉眼/真耳确真，再融写正式文件跑完整盲测。
   - **一级（纯确定性/机械维护）**：改错字、修死链、调脚本参数/UI 字数、不改模型判断逻辑 → 静态校验 + 受影响单测全绿即放行。
   - **二级（局部规则/判断修订）**：静检全绿 + 隔离定向对照（至少 **A 纯原生 / B 改前旧版 / C 新版**，1 道贴近痛点的典型题 + 拉丁方独立匿名盲评 + 白盒加载与思考字节）。
   - **三级（新建 / 整体重构 / 共享规则大改）**：静检全绿 + **完整隔离三向盲测（A 纯原生 vs B 改前旧版 vs C 优化新版）**（至少覆盖回归题 + 全新零污染留出题 `H`；元治理改动须做双阶段验证；含多风格三级子技能须增做脱标风格盲辨）。
   - **纯终端受众体感标尺（严禁内部术语打卡）**：盲评维度须从本次目标的第一性原理与真实挑剔受众体感动态派生，严禁把新加的内部规则术语塞进打分表充当优等生考卷打卡项，并把硬边界列为不可抵消项。
3. **不合格必打回（防负进化铁律）**：
   - 若实证表明 **C 未能稳胜纯原生 A、核心表现反不如改前旧版 B、或暴露明显新短板/残余束缚**，**绝不宣称完成进化**——必须直接打回查明根因、重新优化文件并再跑隔离复测（最多自主打回迭代 **2 轮**；2 轮后仍存负进化或方向取舍分歧，带完整实测证据暂停，交用户拍板方向或一键回滚至改前恢复副本）。
   - 若当前环境因用户明确要求只改不测或受工具限制无法派发独立子 Agent，必须如实标明未跑独立对比实证（本仓库正式维护时 `BEHAVIOR/QUALITY` 不得标 `PASS`，可附开箱即用的隔离测试命题与标尺；若仅为外部业务草稿且用户明确不跑测试、只索要精简说明，则用一两句直白人话交代未实测与试跑建议即可，不硬挂冗长测试包）。
4. **诚实透明交付（含一字不改原始对照，区分仓库维护与外部草稿）**：
   - 清理 `.cache/validation/` 中的临时旧版对照基线（保留 `.cache/restore/` 改前恢复副本）；
   - **维护本仓库正式 Skill 时**，按[评估与验证协议](../../../docs/governance/evaluation-protocol.md)报告 `STRUCTURE`、`ROUTE`、`BEHAVIOR`、`QUALITY` 四态（正式仓库跑过 `check_project.py` 方记 `STRUCTURE: PASS`，隔离沙箱自查最高记 `OBSERVE`；仅静态看 `description` 不得将 `ROUTE` 标为 `OBSERVE` 或 `PASS`；AI 盲评最高记 `OBSERVE`）；
   - 同类维护汇报中，用自然大白话交代改动清单、体量与负载变化、改造代价与切换边界、匿名盲评得分与新版短板剖析、承接的 `AUDIT-ID`、恢复位置及一字不改的原始输出对照；
   - **面向外部业务草稿或普通用户的精简重构汇报**，严守 `docs/runtime.md` §3–§4 的自然人话与 3 秒结构化扫读版式（清晰层级、改动对照表、重点加粗、松绑后的真实风险与使用边界、一两句直白未实测提示），**绝不外露 `STRUCTURE`/`UNKNOWN` 等仓库内部英文状态枚举或塞入无关冗长清单**；
   - **本地写回不自动提交、推送、升版本或发布**；写回磁盘也不等于宿主会话菜单已自动刷新。
