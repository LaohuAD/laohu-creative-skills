# 老胡能力进化

## 核心职责与边界

执行已确认的目标、专业方法和关键取舍，把它们接到未来普通请求真正走到的入口、规则和消费者。按[三技能职责](../../../references/triad-handoff.md#1-三技能单一职责与交接红线)承接决策级变更规格，负责真源、语言、实际文件、调用和验证。当前作品修改归其专业入口；会改变核心目标、权限、方法或取舍的未决判断，只暂停依赖写回，把材料、影响和具体待决项交 analysis，其余已授权工作继续。

## 确定能力目的与改进边界

1. **从真实请求定位用途。** 结合普通说法、任务阶段、输入、期望和实际下游，确认目标能力为谁、在什么条件下做什么。分清委托用户、负责规则的作者、未来执行者、直接机器消费者和最终接收者。旧章节与 `description` 只提供待核线索。
2. **找可观察差距。** 对照反馈、当前实际规则、执行记录和产物，标事实、推论、未知、首个有据断点和影响。需区分方法缺失与未加载、未用、未消费时，用[断点归因](../laohu-analysis/references/investigation.md#区分方法缺失与执行断点)比较首轮与指导修订并回实际控制点；修触发/优先级/消费者或补有证据的已选办法。无历史记录不硬判内部因果，有已选目标、可靠方法或直接缺口时可推进，不以反复失败作为条件。
3. **按职责确定改动规模。** 已定文字、路径、单点接口局部修；核心职责、方法、Reference 和消费者互相牵连时，从目标到交付完整接通。明确普通请求应能产出什么、保护什么、从何处观察；真实接收证据不足时仍可作获授权的可恢复实现。

运行规则的新增、修改、融合或退役，先读[语义对照](references/rule-expression.md#更新规则前按语义对照)和[确定规则措辞](references/rule-expression.md#确定规则措辞)，归并、压缩或移动时读[无损结构代谢](references/rule-expression.md#无损结构代谢与跨文件真源归位)。迁移来源、写创作原则、采用范例或保机器接口时，再读对应小节，回到实际语义取舍。涉及多文件、消费者、界面或评测时，按[文件变更与调用依赖](references/change-workflow.md)选实际所需小节。

## 组织可执行的专业方法

### 从普通请求还原核心工作路径

读取[万能造梦框架](../../../references/universal-dream-framework.md)，按[分级深耕](../../../references/triad-handoff.md#3-万能造梦框架的跨入口接力与分级深耕)核两条链：本入口如何判断、写回和确认消费者，目标 Skill 如何沿普通请求产生产物。整建、重构或跨职责融合时两条链全 16 个交点实质审视；局部修订深审受影响和直接上下游交点，其余核权限、保护和接口。普通业务执行不用为此加载模型。

1. 从目标描述、普通输入、专业方法、真实消费者和材料还原：触发/边界 → 选择 → 处理 → 中间产物 → 消费 → 最终交付。指出目标、优先级与保护在哪一步改变了判断。检查点可有已承接、局部缺口、证据受限和不适用，有据即可保留，避免按格数造问题。
2. 将专业方法落实到当前材料选择、组织和制作，再在实际媒介核成品。前后依赖写顺序，独立职责可并列，一项完整方法可跨多个交点。读[普通路径](references/rule-expression.md#把条件和动作安排到普通路径)把输入、触发、执行者、适用标准、顺序、默认、替代、例外、退出及产物写到实际决定位置，再回本节核普通请求。
3. 关键中间产物要有完成状态、实际使用者与下一步用途。失败或取消时核真实前置状态，补获授权的创建/恢复或退出，后一步只用已产生的结果。目标 Skill 主文应有可独立引导普通任务的核心流程、判断与调用；Reference 深化独立职责，不能接管上游目标/权限或把目标能力正文变成实施台账。

### 写出加载前可判断的 description

每次实质更新核 `description`。仅适用情境、对象、意图、关键输入/前提、范围或交付发生变化才写新描述；内部排版、措辞与步骤不自动改入口。在正文加载前，描述独立用普通请求语言说清情境、实际能力及产物，近邻只写影响选择的区别。引用、文件名、偶然题材或用户已否定的要求不单独触发。把承诺交回主文和明确触发的 Reference 验证，权限以实际授权为准。

### 选定并核实真正指导工作的专业依据

用户或 analysis 已选方法按实际条件实施，核与本任务相关的局部规则和来源。来源、许可或实施方法的必要条件未齐时，按[保留方法怎样作出选择](references/rule-expression.md#先保留方法怎样作出选择)处理已选片段、必要依赖、准确术语和接口，再回具体动作。运行时必要方法应在[本地闭合](references/rule-expression.md#让运行方法在本地闭合)；题材名称和外链不替代做法。

- 关键声口、节奏、叙述或媒介尚需有据选择时读[真实作品的日常取法](../../../references/exemplar-study.md#日常创作取法与方向)，把可核原作单元、语境、作用与适用条件接到实际生成、复查处。涉及正式标尺时按[正式评估与 L/C/D/H](../../../references/exemplar-study.md#正式评估与-lcdh)和[验证协议](../laohu-analysis/references/validation.md)取相称证据。
- 接收者的理解、情绪、审美或行动改变设计时读[读者价值与作品组织](../../../references/audience-value-and-structure.md)对应部分，带回内容或验收决定。目标 Skill 执行文字生成/修订时读[语言成文](../../../references/language-realization.md)相关方法，接回其实际文字步骤。evolution 写规则或说明时见下文的成文回核。

## 用真实材料归组并写回控制点

### 找准实际文件、控制点和恢复位置

核目标项目、主文、Reference、调用方、脚本、配置、评测与消费者，沿请求、资源加载、决定、动作、消费和交付查真实控制点。读[文件归属与真源](references/change-workflow.md#找到唯一真源与实际控制点)按职责定位，记谁在何时读、提供何种判断或产物、回哪一步。只查已授权对象及必要依赖。

编辑前按[运行约定的恢复位置](../../../docs/runtime.md#过程文件与恢复副本的存放)保存当前实际内容，包括受影响的未提交、未跟踪和需保护忽略资产。用轻量映射记录目标、旧位置、仍有效的保护及接口、拟采用内容、消费者和验收；Git HEAD 不替代现状。

### 用全方向检查确认已有承接和真实缺口

用相关规则、专业方法、输入、消费者和用户目标检验[两条链](#从普通请求还原核心工作路径)。整体覆盖、局部深审及副作用核对依上文深度，每个深审结果应能指实物规则与操作；同处多个职责可有不同结论。把适用方法怎样影响选择、条件步骤怎样影响材料、产物怎样被真实使用接成一条链，不靠旧标题、术语或覆盖声明代替。

### 依据语义把规则合并、替换或分支

按[语义对照](references/rule-expression.md#更新规则前按语义对照)裁定重合、补缺、分支、冲突、失效和新增。改写前按[结构代谢](references/rule-expression.md#无损结构代谢与跨文件真源归位)核实全部受影响判断的保留位置；先汇真源再接消费者。同一交点可有多组规则，跨方向的完整方法要保持条件、顺序、动作、例外和输出完整。依真实关系选控制章节，不把尾部总原则当原位替换。

### 接通 References、配置和所有直接消费者

1. 多文件修改按[依赖顺序](references/change-workflow.md#安排多文件变更)先真源、再主文、直接调用方、模板、配置和评测，带入变更映射。参考[消费者契约](references/change-workflow.md#让每个消费者真正接到文件)确认真实接收；Reference 读取或返回契约变化、公开入口或分层关系变化时取其对应专项。新增资源须有独立职责和实际消费者。
2. 改变公开入口的职责、适用条件或交付时核 `agents/openai.yaml` 的展示名、简述与默认提示；内部配置由宿主按契约维护。机器产物保既有类型、字段、语言标记、顺序、必需/可选、占位符和适用条件，用户话术原句/范例身份按[规则表达](references/rule-expression.md#确定规则措辞)核实。
3. 触发条件、主流程、分级或结果契约变时，按[同步评测](references/change-workflow.md#同步-evalsjson影响面排查与故障转回归用例)复核旧输入，记录本轮受影响例；适用时将故障转成最小回归，隔离夹具和必须保有的旧预期跟随消费者。
4. 多个 Skill 重复出现有价值的模式且已授权长期沉淀时，按[共性经验边界](../../../references/triad-handoff.md#5-共性经验向-knowledge-的按授权沉淀环)将适用条件、信号与做法归到正确位置，关键运行决定写回控制点。

## 形成接收者可用的结果并验证

### 按真实任务命名章节和组织条款

标题用实际动作、判断或交付方式，段落沿职责和依赖组织。对规则、解释、计划、比较和报告，按[成句](../../../references/language-realization.md#成句把表达动作写出来)及[成段](../../../references/language-realization.md#成段让句子共同完成一项工作)核完整意思、目的、态度、信息次序和来源材料，读回实际文字。按[标题和段落方法](references/rule-expression.md#按实际任务组织标题和段落)组织规则，诗学原则或输出契约受影响时，读[规则表达](references/rule-expression.md#用结构让文档更好读更好执行)相应小节；保留用户作品的独立表达及机器接口。报告解释改前实际处理、目标、改后差别及影响，路径和哈希用于定位。

### 用普通任务走通并修复真实断点

1. 按[控制点和普通输入](references/rule-expression.md#写回真实控制点并用普通输入核验)走到受影响的下游，核决定时点、分支、退出、产物消费、保护行为和接口。先仅看 `name` 与 `description` 区分普通意图和近邻，再核实际加载能否兑现承诺。入口信息不足修描述；正文或 Reference 缺动作按已选方案补足或标明待决。仓库写回不证明宿主菜单已刷新，走读不冒充真实路由或独立试用。
2. 写回后做**两个门禁**。门禁 A 核信息与力度：与实际基线逐项比，条件、例外、接口、保护项、局部停止及强制/禁止力度完整落位。门禁 B 核执行与闭环：无新增约 300 字且混杂多项规则的段落，真源与三要素指针可达，直接消费者和适用评测已同步，承接的 AUDIT-ID 及其写回/验证关系可追。发现缺项回实际控制点修正，再走受影响路径。
3. 方法、行为或交接变化时按[检查执行路径](../laohu-analysis/references/validation.md#让检查覆盖真正的执行路径)和适用验证小节确定独立证据。元能力第一阶段用普通请求和原始材料查专业判断与构建；已给完整方法/架构的只验忠实实施。第二阶段由未参与设计的执行者仅凭最终文件和新普通输入运行，不提供制作解释或评分预期。新指导补出缺失核心方法时记录影响，确认写回后无指导复查。

   方法或行为有实质变化时，单个业务 Skill 亦须独立执行。由未参与候选设计的执行者仅用最终目标主文、实际加载的 Reference 和普通输入，观察条件怎样切换、结果怎样被消费和保护项/接口是否保留。缺少独立执行或没有相应授权时，将该项明确留为待验证。
4. 需要局部对照、专业范例、走查或作品行为证据时，按[内容身份与独立验证](references/rule-expression.md#创作范例材料局部对照与独立验证的边界)取对应小节，再回本节使用相称依据。走查验证操作和依赖，不生成脱离材料的作品；正式作品行为由经授权的目标执行 Skill 实际产出。

### 按证据交付，不把结构检查说成质量通过

运行适用的 [项目维护检查](../../../docs/maintenance.md#本地检查)。报告按 [AGENTS.md 验证](../../../AGENTS.md#验证)标明各自证据范围和状态，给实际文件、改动、真源、检查、双门禁、未知与恢复位置。承接的问题按[追溯交接](../../../references/triad-handoff.md#2-统一追溯主线audit-id-交接契约)传 AUDIT-ID、原条件与证据、变更及待复查项。按授权结束或交独立验证；本地实施不自动提交、推送、升版本或发布。
