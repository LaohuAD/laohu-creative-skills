# 完整仓库与入口安装

用户要求首次安装、全局使用、检查入口、修复链接或卸载时，由 `laohu-update` 读取本文件；操作结束返回主文报告实际状态。用户只问使用方式时只解释，不执行安装。README 是使用说明，阅读它不构成全局安装授权；用户明确选择宿主与安装方式后，常规链接操作不重复询问。

## 一份仓库，两种范围

每份安装保留完整 Git 仓库，项目内使用与全局使用共享这份文件，不另建开发或稳定副本。已有可用仓库直接复用；没有时按 `git-update.md` 的首次安装分支克隆到已确定的新目录。全局使用只创建指向 `.agents/skills/` 中正式入口的目录链接，保留根规则、工具、知识和引用依赖。跳过空的预留目录，不只复制 Skill，也不把整个仓库链接进宿主技能扫描目录。

需要 Git 和 Python 3.9+。内置目录适配：Codex 用户级 `~/.agents/skills`，Claude Code 本机用户级 `~/.claude/skills`。选择用户实际使用的宿主，不默认安装到所有已发现宿主。其他宿主先确认其技能目录与目录链接支持，再用 `--skills-dir`；不能据此承诺所有 Agent、Windows 链接权限或云端环境已经适配。链接不可用或工作盘离线时明确失败，不静默复制或换盘。

项目内使用：在完整仓库中打开 Agent。Codex 可发现 `.agents/skills/`；不读取此目录的宿主可以让 Agent 直接读取 `.agents/skills/laohu/SKILL.md` 开始，不因此擅自安装到全局。原生命令显示仍取决于宿主发现和重载。

## 注册、检查、同步、卸载

解析 `{PROJECT_ROOT}` 为当前完整仓库路径。安装脚本始终从自身位置定位仓库，不更新当前业务项目。以下命令默认预览；已获相应操作授权、预览无冲突后，同一命令加 `--write` 应用。`status` 始终只读。

```bash
python3 "{PROJECT_ROOT}/tools/install.py" install --host codex
python3 "{PROJECT_ROOT}/tools/install.py" install --host claude
python3 "{PROJECT_ROOT}/tools/install.py" status
python3 "{PROJECT_ROOT}/tools/install.py" sync
python3 "{PROJECT_ROOT}/tools/install.py" uninstall --host codex
```

只执行用户选中的宿主安装命令。用户明确要求其他已核实目录时，用 `--skills-dir "{实际技能目录}"` 替代 `--host`。首次注册全部正式入口，维护入口随之注册；暂不承诺选择性安装。`sync` 只维护已登记的目标，不安装到新宿主。

脚本写本仓库被忽略的 `.laohu-install.json`，记录源位置、目标目录和受管理链接。已有链接指向同一真源可登记复用；同名文件、真实目录或其他源的链接均报冲突，整次预检失败前不改入口。不能删除冲突对象来让安装通过。说明具体路径与当前来源，由用户决定保留哪套；宿主对同名入口的优先级不能推测。

`status` 返回当前真源、注册目录和所需操作；它只证明文件系统状态，不证明宿主已经重载。安装后读取一个全局入口的 `SKILL.md`，核对真实路径与同级引用；再按宿主实际方式刷新或新建会话检查发现。区分“链接已建”和“宿主已发现”，后者未验证时明确说明。

`sync --write` 补齐新增入口和缺失链接，删除官方已退役且仍指向本安装的受管理链接。被用户替换的链接或同名目录先报冲突，不删除。写入失败脚本尝试撤回本次链接操作；异常中断后保留现场，重新检查记录和实际链接。锁文件表示可能有未结束操作，确认没有进程在执行并核对现场后才移除该锁；不能自动忽略锁继续写。

卸载先预览，再加 `--write`；只移除登记且目标仍匹配的链接，保留仓库、作品、其他技能和本地修改。空的安装记录可保留，未登记的链接不批量清理。需要移走仓库时，先从旧位置卸载入口，移动后在新位置重新登记；本地记录仍指旧源时，核对已经无受管理链接后移走旧记录，再注册。仓库已经失联时先恢复可访问位置，不能猜测新目录或自动删除全局条目。

## 更新时的接入

更新前记录现有登记及入口状态，在隔离候选里比较正式 Skill 的增删改名，对照真实登记目录检查预期新增路径是否被占用。此阶段只读真实全局目录，不在候选副本注册链接，也不把候选路径写入真实记录。链接冲突和规则冲突一样，先给具体方案再应用依赖它的变化。

按 `git-update.md` 完成仓库合并及检查后，从原仓库运行 `sync` 预览，无新冲突则运行 `sync --write`，再运行 `status`。既有更新授权包含已登记入口的必要同步，不扩大到未登记宿主。官方目标已在历史中时，也检查并同步现有登记，不因省略 Git 合并而漏掉入口修复。

无登记表示项目内使用，同步为空操作。登记记录、锁和安装临时文件属于本地资产，不纳入提交或发布。仓库已更新而入口同步失败时分别报告两种状态、冲突路径和恢复依据，不报告整套更新成功，也不强制回滚用户文件。
