# 原子记录、完整分析与使用反馈

本 Reference 负责把已分析的来源与独立处理关系编译成可回读记录：保留完整分析、编写短检索卡、交付可确认的入库方案，并在真实采用获授权记录时填写 usage。它不要求每次解释都建卡，不替专业 Skill 决定成品，也不扩展保存授权。入口状态、候选 query、分层详情读取和当前任务采用说明见[本地资料库分层检索与回读](library-retrieval.md)；两份 Reference 分别承担写入前的内容整理与只读取用流程。主 Skill 负责来源身份、机制证据、材料分析和保存授权。

## 1. 先决定形成什么记录

只解释一个局部问题时，直接回答，不必为了归档把它硬做成原子。

用户明确要求拆解并收录、整理成以后可查的方法，或本轮资料沉淀时，先完成面向人的完整分析，再把**准备保留的具体处理关系**编译成可审阅候选和具体入库方案。默认按[主文的保存授权](../SKILL.md#保存授权与工具)等待方案确认后写入；本 Reference 不把收录意愿另行解释成直接写入授权。候选须有完整内容，不只报标题、主题或名单；先让读者沿材料看懂具体处理、它可能改变什么理解或决定、推论依据与边界、未来决定和采用条件，再整理成可独立回读的记录。记录可以按机器字段保存，但字段名和schema不要求原样展示成人类报告模板；人类解释和机器接口分别检查。`index_card.summary` 的200字符限制只适用于检索摘要，不限制分析正文或完整候选说明。没写入之前不编 source ID、atom ID 或“已入库”状态。材料不足以填写的字段明确标出缺口，不能用格式完整掩盖证据不足。

来源与方法原子走不同分支：

- **来源记录**保存作品身份、版本/定位依据、实际读取范围和必要的目录说明。若当前只确认了值得留存的来源，机制尚未成立，在方案里提出 source-only，按主文完成确认后保存；不凑原子、binding 或 usage。
- **原子记录**描述一项可独立采用的处理关系。先完成主文[灵感分项与变化分析](../SKILL.md#辨认独立灵感在共性与差异中寻找可用变化)，再按每项内部的关系判断原子粒度；原子去重不能倒过来决定输入里只有一个灵感。不按菜品、段落、观察点或消费者数凑原子数量；必须一起工作的步骤留在同一原子。每条原子保留足以理解关系与适用条件的共同上下文。来源事实、机制推论、使用办法和新增建议清楚分开。
- 一条处理关系要能让未参加本次分析的人从记录读懂它为何进入库、以后可能在哪项决定上派上用场。若机制或条件还未成形，可以只保留来源；如果用户本轮只要局部解释，则不进入写盘流程。

批量收录时沿用已逐项分析的对象清单，为每项保留具体内容、原话定位、纠正依据（若有）和独立采用说明。来源可按真实来源身份与定位合写，也可在确有独立内容与检索用途时分记，不强求一条消息一个 source 或一个灵感一个 atom。合写来源时，在 `source_material` 中明确各项范围；保留为原子的具体差异进入其上下文、分析、检索卡和适用说明，不只剩“身份可换”。若某项尚不足以形成方法原子，在来源记录的 `provenance` 可扩展内容中保留该项说明与待展开处，`notes` 仍只放简短单行检索说明；按 source-only 路径处理，不因无 atom 就从本批消失。若用户提供并授权留存一批材料，来源记录保留完整原文和各个独立分支；在来源的 independent_units 中分别保存分支内容、定位与完整分析，不用汇总摘要吞掉差异。来源原文只保存一次，原子保留理解关系所需的上下文摘要和细读；外部受保护作品仍只记录必要短摘录或精确引用。共用方法只去重确实相同的关系，仍保留各具体灵感与可回指的位置；新增方法 binding 不替代它们自身的内容。创意推进所得的变体，另在分析中注明改变的变量、产生的实质差异及适用条件；关系未变时不为每个换皮复制方法原子，若变化形成另一项可独立采用的关系，再按主文标准另立候选。沿用现有 schema 和稳定 ID 规则，不为分项另造一套库格式。

### 交付能由用户确认的入库方案

完整分析交付后，同一轮继续给出本批如何落地的方案，不等用户再次追问怎样保存。先只读盘点已有库及相关详情，沿用已确认的库位置；库还不存在时说明拟用位置，预览不创建。把来源、独立灵感、组成元素与方法关系分清：人物、道具、动作、形态或时序可以是分析元素，只有能独立指导采用的一项处理关系才立原子；几个元素必须共同起作用时保留为一个完整关系。共同方法可复用，具体灵感的差别与用途仍须留存。

方案应让用户看见将来实际保存和取得什么，按本批真实材料说明：

- 哪些内容进入来源记录、完整分析放在哪里，原始材料、推论和新增建议如何区分；只保留来源的条目也说明原因和待发展处。
- 准备形成哪些原子，每项保留的具体关系、独立拆分或合写的理由、可替换元素及不能丢掉的条件；带入第2节的完整草案，不只交标题或摘要。
- 每项未来适合哪种情境、题材或表达任务，具体帮助哪个专业决定，怎样转换到本作、在什么条件下不适用；内部编译完整 binding，面向人自然解释，不强制展示七项字段。
- 用哪些材料词、关系词和未来需要词寻找来源或方法，哪些词进入各自检索入口，以及保存后怎样用实际查询和详情回读核对。未保存时只称拟用入口，不称已经能检索。
- 本批拟新增、复用、经授权更新或暂留的范围，以及实际库路径、类别和证据状态。发现已有关系时引用真实已有ID，说明是否只复用；不为新候选编造ID，不默认覆盖已有记录。

按读者需要用自然段或按素材分点，真正需要横向比较时再用表格。上述作用不是固定报告栏目，不能以换栏目名代替具体解释。给出一份内容清楚的当前方案并请求确认；用户已接受这份方案或明确要求直接执行时，沿主文授权继续，不重复请求许可。修改方案时保留已经确认的部分，只对会改变保存内容或范围的部分重新确认。

## 2. 组装能独立回读的候选

组装候选前，先把主文来源观察得到的约束带进记录工作：针对当前源单元，列出会改变候选含义的已确定关系与真正未决项。它是内部工作底稿，不另设固定字段表；至少要辨认语句中可确认的对象、动作主体与承受对象、明示或可由句法承接确认的先后/条件，以及已经说清的评价或预期对象。身份没有姓名或外部背景未核，不等于句群内可确认的主语承接和动作顺序也未知；只把句法、材料或必要上下文确实无法消歧的部分列为开放。

先完成足以解释材料的连贯分析，再筛出可保留关系；多个部件若共同构成一项关系，就在同一记录中说明其各自作用。合写时保留任何会改变关系解释、成立条件或未来采用决定的差异；只有关系确实可以独立选择并指导决定时才拆开，不因字段、消费者或返回步骤不同而拆分。

写来源摘要、检索卡、事实、机制推论、适用条件、fixed/open、binding 和本次采用说明时，都使用这同一组约束。紧凑表达可以省略某项细节，但不能否定或把已确认关系降成未知；为未来创作改人、改序、改对象等自由度属于新增变体，不反写成原材料缺口。涉及前后评价/预期关系时，按[主文第2节](../SKILL.md#2-先记录可见选择再提出机制)核对前后对象与面向是否可比、后项具体改变或动摇哪项判断；把该结论及真实未定项一致带入候选字段。

写入前逐项确认候选在脱离当前对话后仍可理解。以下是记录自足性的核对方向，不是要求面向人的说明逐项填表：

1. **来源与范围：**标题、创作者、媒介、版本、身份依据、定位和实际读取范围来自真实材料；原作、转述、构想或新增建议不可混写。来源素材只在用户提供或明确允许时保留必要摘录。
2. **定位与上下文：**写明观察位置，并用充分但不过量的摘要交代前后关系。读者应能分清实际看见/听见的事实与没读到或未核对的范围。
3. **关系与解释：**先记录材料中具体部件、动作、词句、图像、声音或次序怎样相接，再说明可能的作用、依据、必要条件、固定关系、开放变量和限制。使用“可能”时仍要指出是哪项材料关系让这个推论成立；不把机制说成已证实效果。若把多处观察合成一条解释，保留会改变其意义、适用条件或用途的差别，不用宽泛标签替代材料里的关键变化。
4. **新增建议：**如果为了当前工作提出改序、替换、变体或实现方案，标明是本次建议，不能回填成来源事实或原作机制。
5. **后续入口：**写明未来可遇到的具体决定与采用边界；没有当前项目时，说清这是未来可用的决定，不虚构作品、段落或返回位置。
6. **回指校验：**候选各字段写完后，重新读取当前源单元，逐项核对来源摘要、检索标题/summary、可见事实、机制解释、条件和binding是否仍遵守同一组确定关系与真实未知项。发现字段之间或字段与原句不一致时，修正候选；如有意改变关系，则移至明确标出的新增建议，不用“身份未明”抹去可确认的动作承接。

若事实或机制尚不足以独立成原子，只保存被授权、可真实记录的来源。不要为了满足栏目把未知编成事实；也不要把全份原作、长摘录或个人隐私搬入 atom。原子上下文用于重新理解，source_material 用于标识与必要复核，检索索引只承担找到记录的工作。

完整分析必须进入可长期回读的正式记录。整体正文可放在 `source.provenance.full_analysis`；批量材料若已在 `source.provenance.independent_units[].analysis` 中逐项保存完整内容，就沿用这份正文，不再复制一份总文。单条原子的 `analysis` 保留解释该关系所需的上下文、具体细读和采用条件；来源只回指原子中的细读也可以，但不能因此丢失未形成原子的分支解释。使用现有允许扩展的字段，不新增顶层schema字段。`source_material` 负责材料身份与必要原文，不能装入分析来冒充来源；分析正文不放进 `notes` 或200字符检索摘要。来源与原子均不能只指向聊天或 `.cache/` 中的报告，令正式记录失去完整解释。方案阶段说明这些去向，确认后再写入。



### 按需要记录跨媒介的转移判断

同一条可迁移关系面向不同真实用途时仍只存一份 atom。只有当记录者需要保留不同用途的适配比较、且这些差别会影响以后采用时，才可在现有可扩展的 analysis 对象中使用 transfer_assessments 数组。每项按目标消费者、专业决定和阶段记录，并写清它对应的来源关系、用途是否已有 binding、关系在目标用途保留了什么、需要怎样重建或改变、什么不能承接或会损失、成立条件，以及依据来自哪段来源材料、哪份目标专业方法或哪件实际目标成品。没有目标成品时明确写明只有计划或设计推论。

下面是放入 atom `analysis` 对象的可选属性片段，用于记录一个目标用途。它只展示应合并进现有 `analysis` 对象的属性，不是完整 atom，也不是新增顶层字段、strict binding 或使用记录：

```json
{
  "transfer_assessments": [
    {
      "consumer": "目标消费者的实际名称",
      "decision": "目标专业决定",
      "stage": "目标专业阶段",
      "binding_status": "registered 或 exploratory",
      "source_relation": "来源中可定位的关系及条件",
      "preserve": "目标用途中仍要保留的作用",
      "rebuild_or_change": "目标媒介需重新组织的信息或改变的作用",
      "cannot_transfer_or_loss": "无法承接的部分及信息损失",
      "conditions": ["目标用途成立所需条件"],
      "evidence": "来源位置、专业方法依据，以及目标成品是否实际检查"
    }
  ]
}
```


registered 仅表示该消费者、决定、阶段已有一条七字段 consumer_bindings 完整承接；相关值须与那条 binding 完全一致。若只是判断某条关系可能适用于新形式，记为 exploratory；先读取该消费者当前的专业方法，不能把探索写成已登记用途或已发生采用。consumer_bindings 仍须逐项保持七个既有字段，不能用 transfer_assessments 替代、补齐或放宽它们。该扩展只便于 get-atom 后人工理解，不会因此自动进入 search 索引、成为 usage 或触发写盘；真实采用仍按授权流程操作。

## 3. 为普通问法写检索入口

检索卡服务于“以后的人会怎么问”，不是给当前分析贴标签。`index_card.title` 用短而可辨认的具体说法；`summary` 用一条单行自然语言说明材料中何种处理可能帮哪类决定，最多 200 字符；`terms` 收入来源材料里实际出现的关键说法，以及未来创作者可能用来描述相关需要的常见词、动作和关系。

编写检索卡时遵守几条边界：

- 从实际材料出发，再推想正常使用者会怎样问；未来问法词只放在检索卡，不倒灌为原作事实、机制证据或用户原意。
- 同一材料可以有多个自然检索入口，但不按字段数量、标签数量或固定配额扩写。没有把握的词不硬加，题材相同也不代表适用。
- `category` 是原子存放类别；`consumer`、`stage`、`decision` 是专业使用过滤；`terms` 是寻找记录的词。三者用途不同，不把消费者或流程标签假装成机制关键词。
- 不设封闭关键词表或每卡最低词数。保留能区分这项关系、帮助普通查询命中的材料词与需要词即可。
- `source.notes` 可写简短的来源检索说明，帮助以后按普通问法找来源；它不是摘录区。尽量保持简短、单行，不把正文、完整 provenance 或长摘要塞入 notes。

当来源确实包含需要分别查找、回读的独立材料单元，并据此写入 `provenance.independent_units[]` 时，为每个入列单元提供非空、在该来源内唯一且稳定的 `provenance.independent_units[].unit` 键。键不能用数组序号，创建后不因单元排序或插入而改变。只在单元有独立材料检索价值时建单元；不按菜品、对象清单或段落机械拆卡，也不因此为每个单元新建方法 atom。

每个新写入的独立单元都配自己的 `provenance.independent_units[].index_card`：`title` 写清该单元的具体内容，`summary` 用自然语言概括该单元关系如何帮助未来决定且不超过 200 字符，`terms` 按该单元自身关系和常见未来问法填写有依据的词；只收该单元实际材料词及相关需要词，不设词数配额，也不补造词。作者编写的卡片只依据该单元自己的标题、disposition、locator 与 analysis 等信息；不要把来源合集的 `source.notes` 复制进每张单元卡，也不要靠合集说明把无关单元一并检出。source.notes 保留来源层概览。旧单元若已有可用的唯一稳定 unit 键，即使没有显式 index_card，query 仍可仅依据该单元自己的 title、disposition、locator 形成候选卡；这不等于回填了经作者核定的摘要，也不继承合集 notes。只有来源缺少可用的唯一稳定 unit 键时才按 whole-source fallback 处理。旧记录不因本规则批量回写 canonical JSON，候选卡也不能证明任意原文措辞可被检索。

各单元的完整细读写在 `provenance.independent_units[].analysis`；获准保存的原文或摘录在来源记录的 `source_material` 中按范围留存一次，不复制到每张检索卡或 atom。只有在源版本、精确起止范围和 SHA-256 均已核验时，才写 `provenance.independent_units[].verified_span`；缺少核验时保留实际 locator 并省略该字段，仍可回读 analysis，但不得将分析说成原文摘录。atom 的 `analysis.observed_unit.source_unit_ref.unit_key` 仅在该 atom 确实对应一个明确单元时填写该 `unit` 键；跨单元或对应关系不明时不硬指定单一单元。

合写来源时注意当前原子搜索也匹配来源标题。若来源只是本轮口述的合集、说明名由执行者拟定，就用准确的来源身份说明命名，不把各个独立素材的关键词都堆进标题，导致任一关键词召回全部原子；各素材的具体入口放在对应原子的检索卡，来源汇总入口放在 `notes`。真实作品的原标题仍须保真，不能为减少命中改造原作身份。收录后用有区分力的材料词与关系词实际查询，回读命中详情；发现无关命中时核对命中字段，修正本轮记录里放错位置的说明，不以删除素材或篡改真实来源来换取精度。

### 确认方案后完成写入、回读和检索

沿用主文已确认的方案及归类规则，由 archive 返回正确容器，再组装 source/atom 数据并调用 `put`；已存在的关系按稳定ID和修订授权处理。只写已批准的内容，未形成方法的分支随来源保留，不为凑数立原子，不把尚未发生的作品采用记作 usage。

写后执行 `validate`，并按[分层检索与回读](library-retrieval.md)对本批候选执行有界 query、回读新增或本次更新的 source/atom 详情，确认原始材料、完整分析、独立关系、真实未知、采用说明和状态均可取得。对本批新写的独立单元，用其自身材料/关系词运行 `query --kind material`，再按卡片返回的稳定 unit 键以 `get-source --unit ...` 回读；对本批方法 atom，用 `query --kind method` 查找并以 `get-atom` 回读。只有确有单元卡或可用的 whole-source fallback 时才报告材料查询可命中，不把合集 notes 复制或任意正文词当作单元可检索证据。没有 verified_span 时核对 locator 与 analysis 视图，并区分分析和原文。已具备明确专业过滤时确认同一条 binding 满足条件，不能仅以关键词命中代替适用检查。按实际命中字段修正本轮说明放错位置造成的干扰；不擅自修改其他记录或真实来源身份。工具报错或索引未更新时报告具体未完成范围，不宣称整批落地完成。

最终向用户交代实际文件位置和ID、完整分析的保存处、保留的方法与分支、实际查询及命中范围、仍未验证的效果；已有完整分析不必再整篇复述。记录成功不证明创作质量已通过，来源/方法成熟状态与后续使用结果仍分开。

## 4. 读取详情并形成当前采用说明

检索入口、卡片筛选、详情视图、未登记用途探索、跨入口复用及返回专业工作，统一按[本地资料库分层检索与回读](library-retrieval.md)执行，避免在写入 Reference 重复维护另一套查询/详情协议。对当前任务选中的关系，作者应给专业 Skill 一段可执行的采用说明：标出来源/atom ID、具体要保留的关系、适用条件与限制、当前产物位置或待处理对象、用户锁定项、转换动作、返回环节和成品检查；没有当前作品时不虚构位置。经授权直接采用来源素材与迁移抽象方法是两条不同路径，前者可以在授权范围保留原素材；若借的是方法，就按当前作品重新组织，不复制独特表达。

没有具体任务时只提供未来可能面对的决定与条件，不制造当前采用说明。打开详情或提出建议都不代表实际采用；usage 只记录真实使用，并且不能将一次结果外推成其他 consumer、阶段或媒介的效果。真实使用反馈依下节权限和字段写入规则处理。

## 5. 真实使用与反馈

只有用户明确要求记录真实使用结果，或当前任务已明确授权记录该次结果时，才调用 `log-usage`。写入的 `consumer`、`decision`、`stage` 必须与同一个现有 `consumer_bindings[]` 三项完全一致。本次情境的 `required_context`、实际改编 `adaptation`、返回位置 `return` 和成品检查 `check` 应分别显式填写；若本次与通用 binding 不同，不能依赖工具默认复制 binding 文本。也不要用更改 binding 的方式把本次变动伪装成新的通用接口。

`case_ref` 与 `result_evidence` 只填真实可核对的作品位置、版本、提交、检查结果或用户反馈。没有可核对结果时按真实状态记 `pending` 或不记使用；搜索推荐、阅读候选、尚未采用都不是 `applied`。不因默认值或方便而复制通用 binding 内容制造“已经采用”的证据。直接使用来源素材时，在当前工作已有的来源/版本说明中承接依据；没有发生方法原子采用，就不造 atom usage。

反馈能支持哪些结论取决于证据：记录一次采用、调整、拒绝或未使用的事实，不会自动证明该方法有效；使用结论不能回写成来源事实，也不能仅凭单次结果升级成熟状态。需要改动已有原子时按主 Skill 的授权、实际备份、稳定 ID、验证和索引维护流程处理，不用 usage 绕过内容修订授权。
