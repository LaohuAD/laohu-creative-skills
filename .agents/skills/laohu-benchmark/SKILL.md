# 作品拆解与方法原子

把作品和创作素材拆透看清：接收者每一步感受究竟靠哪几步衔接成立、哪些底层组织方法可以迁移复用、哪些属于原作独有不能硬抄的表层素材，并把判断落成下游创作者马上能动手的决定。本入口服务拆解、迁移与本地方法库管理，**不代替下游 Skill 写完整成品，也不自动落盘或把候选当成已验证规律。**

## 1. 先分流模式与材料身份（默认只读、按需挂载）

先辨清本轮走哪条路径，只加载所需手册，**切忌无关任务背负整套文档**：

| 本轮需要 | 怎么走 | 按需读取 |
|---|---|---|
| **纯拆解 / 拆口述灵感 / 跨媒介迁移 / 找差异化变招** | 全程只读，用主文四招直接交付锋利分析；不强迫建原子卡 | 仅当深度涉及特定媒介时，读下节对应 **1 份**领域适配 |
| **查本地方法库找招数或材料** | 严格只读三步曲（`info → query → get-atom / get-source`），不倾倒全库、不隐式建库 | [本地资料库分层检索与回读](references/library-retrieval.md) |
| **拆解并收录进库 / 记录真实采用反馈** | 同轮先交完整分析 + 可拍板入库方案，**用户确认后再写盘**；记录反馈仅在明确授权且有真实成品依据时执行 | [原子记录与取用](references/atom-recording-and-reuse.md) |
| **正式基准评分、人类标尺与 L/C/D/H 评测**（日常不触发） | 按仓库评估口径执行，不拿日常拆解冒充正式评测 | [评估与验证协议](../../../docs/governance/evaluation-protocol.md) |

同时把两条独立判断分开，绝不混淆：
- **研究用途**：**当前任务取法**（紧扣眼下消费者、决定与锁定项）vs **资料积累**（即使没有正在做的项目也照常拆透并说明未来可能适用的具体决定，绝不追问或虚构一个当前项目）。
- **材料身份**：**原作实读**（实际读到/看到的媒介、版本与可读范围）vs **二手转述**（只能支持“转述提到……”，不自动证明原作镜头/次序/受众反应）vs **未定构想**（分析内部关系与成立条件，不写成已发生事实）vs **本次新增建议**（与来源原话清楚分开，不回填成原作机制）。

## 2. 核心拆解与迁移四招

### 招一：批量灵感先保真分项、锁主语与时序，不压扁不强造冲突
- 面对一段连续口述或多条灵感，按完整话意辨认独立对象、并列候选、补充限定与语音纠错：明确纠正直接更新工作表述（不把错字另立为灵感）；用户明说无关联的条目各自独立拆透，不替它们补共同人物或强拼因果，也绝不先压成一个笼统母题下的可替换占位符。**即使归在同一母题下的并列具体例子（如不同处境或阻力载体），若动用不同心理机制，也须先分别拆透各自体验差异，再提炼共同的底层方法。**
- 忠实还原原句里的动作主体、承受对象与先后/条件次序：材料已明示的连续动作归属必须锁住，**不因人物未起名或背景未交代就把已确认的主体/时序降为未知**；仅在句法或上下文确有歧义时标开放；另提换人、改序另标为新增建议。
- 静态观察、视觉双关、称呼错位本身即可成立，**绝不为凑戏剧性给每条素材强加冲突或反转**。只有后项与前项落在同一评价/预期对象与面向、并真正动摇前置判断时才称反转，不把简单并置或递进说成反转。

### 招二：体验时序 + 删改检验（看清真正起作用的关键，拒绝贴标签）
绝不用有反差、有张力、节奏好、高级这类空词当结论，拆一条有效处理必落三步实操：
1. **接收者体验时序**：沿最小完整上下文，还原接收者先看到或听到什么 → 心里形成什么预期 → 哪一处具体词句、动作、画面位置、停顿或顺序把预期掰弯、聚焦或延迟回收；涉及命名、比喻或视觉错位时，追问它在字面或姿态上为什么严丝合缝，却在真实处境或语境上彻底翻车，以及揭示先后顺序如何改写体验。
2. **删改检验（验证核心机制）**：逐一试探拿掉、替换或调换哪一步之后，整段作品最打动人的那股劲就会明显泄掉或变味——由此分清**必须保留的核心结构关系**与**可以自由替换的表层素材**。如果删改后毫无具体损失，那只是评论者贴上去的虚优点。
3. **剥离不能照搬的表面素材**：明确划出原作独有的专名、标志性句式、特殊语境、作者独占身份、实拍/动物伦理或老梗风险；借方法须用本作材料重建，绝不复制可识别原句或独特组合冒充迁移。

从真实作品日常取法时，按**体裁、用途、受众、语域与媒介限制**选可比样本（不按名气或热度选）；学语句连同前后轮次读，学结构不逐句硬配；缺证（未查到/不可核验/上下文不可读/不可比）只收窄对应主张，继续推进其余有据分析，不凭模型熟悉感编造引文或未读内容。

### 招三：高杠杆变量压测——区分真变招与伪换皮
用户带着素材找自媒体差异化切口或创意变体时：
- 先逐项保真拆清原结构，**严禁做身份 × 风格 × 路线机械全排列水表**，也不按数量凑点子。
- 只抓 **1–2 个能实质改写人物处境、行动规则、信息差或观众预期的关键变量**，代回原结构走一遍，只交付 **2–4 个真正产生新化学反应的尖锐方向**（每条聚焦单一高杠杆切口，不把两条相反思路硬挤在同一条里），并写清每个新方向成立必须补足的前提。
- 直接点破只换职业、服装、场景名或画风词只是装饰换皮（视觉可有价值，但不冒充结构创新）；跨条目重组须明确标为新增建议并说明相容性。

### 招四：跨媒介换轨三笔账（把机制真正翻译到目标媒介）
把一条关系迁进目标媒介（如短视频桥段 → 静态封面、视觉画面 → 歌词、小说 → 口播）时，结合目标 Skill 主文方法算清三笔账：
1. **原媒介红利**：原招数到底靠什么媒介条件吃饭（时间差、声音骤停、连续镜头、对话轮次还是语境常识）？
2. **目标媒介重建动作**：新媒介没有该条件时，改用什么原生手段重造同一股张力？（例如静态封面无时间差，靠视觉第一落点 + 标题错位或定格决断瞬间重建；非语言素材进歌词，重建歌者身份、言语动作、段落推进与副歌回返，绝不把画面事件逐行切句。）
3. **诚实认损与成品检查点**：明确写清换轨后注定保不住哪块信息、损失能否接受，并落到目标成品的 1 个真实核查点（无成品时只给设计判断，不宣称效果已成立）。

只针对当前目标媒介算账，不为单条素材强配全媒介清单。

## 3. 证据底线与内密外透的自然人话写法

- **四层依据心里清，绝不越界推因果**：分清可见事实、创作者自述、机制推论与实际效果证据（无真实受众/实测数据就标未验证）。绝不从播放量、奖项、名气或经典标签反推技法因果，不编造作者私密过程，不把静帧/转述/文字描述脑补成视频运动、源码算法或实听音色。
- **内密外透——像真人同行面对面聊片子**：拆解报告按材料或实质发现自然分节，把具体证据、机制拆解、变招思路与落地决定写成母语真人自然顺嘴的段落，遵守 `docs/runtime.md` §3——**不把正常话抽干虚词压成电报缩略语或超长定语块，不生造违背汉语习惯的动宾搭配（也不照字搬用规则里的比喻词），不滥用装饰引号，更不把每段硬切成死板的四栏审核填表格式**；确有横向比较、步骤说明或用户明确要求卡片/JSON 时再用对应结构。
- **交付前 10 秒回查**：检查是否把转述/构想写成原作实锤、是否把原话已确认的主体/时序误降成未知、是否把新增建议混入原话，并压住中段顺嘴滑出的必然、100%、极易引爆互动等过满预测；分寸自然融在叙述里，绝不用每隔几段贴免责括号的方式打断阅读，同时删掉只重复结论的空赞语，默读一遍确保句句顺嘴。

## 5. 本地资料库归属与安全边界

**只分析不写盘。** 单纯分析、灵感拆解、检索、读卡、统计或校验绝不写盘；普通“拆解并收录”必须先在同轮交出完整分析与具体可拍板的入库方案，**待用户确认后再按 [原子记录与取用](references/atom-recording-and-reuse.md) 执行写入与回读验证**（仅当用户明确要求跳过确认直接收录，或正在执行已确认方案时直接写入）。

### 选择研究库

1. **新收录的专业研究归接收 Skill 同级 `benchmark/`**：按研究成果将由哪项专业工作接手，定位该 Skill 解析真实路径后的 `SKILL.md`，写入其同级 `benchmark/`（例如剧本入 `laohu-script/benchmark/`，动画入 `laohu-motion/benchmark/`；跨项目调用亦沿用该共享库）。限于某业务项目的私有材料按已确认项目路径处理。
2. **一来源多域共享、一关系多端复用**：同一作品产出多领域成果时，主库留唯一来源记录，其余接收库用 `source_links` 指向主库同一 `SRC-ID`；同一底层机制服务多个消费者时只保留同一 `ATM-ID` 并挂多条完整 7 字段 `consumer_bindings[]`，不复制原子。
3. **兼容旧库与清晰分工**：仓库根目录 `benchmark/` 中的旧编号通过 `--library-root "<绝对路径>"` 继续兼容检索（需准备兼容容器时交 `laohu-archive` 的 `library_workspace.py`）；单篇独立分析作品按保存授权走 `laohu-archive` 入 `works/benchmark/<作品名>/`；供直接渲染调用的原生动效资产归 `laohu-motion` 本地生产资源，**私有研究库不充当生产运行时依赖**。
4. **工具入口**：本地资料库统一由 [library.py](scripts/library.py) 管理（JSON 真源 + 可重建 SQLite 检索缓存，私有记录本地忽略）；只读查询命令详见 [library-retrieval.md](references/library-retrieval.md)，写入、归类与 `log-usage` 命令详见 [atom-recording-and-reuse.md](references/atom-recording-and-reuse.md)。

## 6. 交接与停止

- 下游可采用时，交出具体来源/原子 ID、承重关系、适用条件与限制、目标产物位置/重建动作、返回步骤与 1 项真实成品检查点；两项候选冲突时交给创作负责人按整作方向与用户锁定项裁决，不靠数据库排序定胜负。
- 证据足够即停，不凑原子数、词条数或固定栏目；材料不可读说清实际范围，无成品或受众反馈时质量与效果保持未知。
