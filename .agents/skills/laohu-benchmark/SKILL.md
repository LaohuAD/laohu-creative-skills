# 作品拆解与方法原子

本 Skill 研究具体作品或创作素材如何组织内容、语言、画面、声音、时间和读者入口，并把观察编译成下游创作者可执行的专业决定。它服务当前创作，不代替故事、剧本、小说、歌词、编曲、视觉、视频、选题、标题或排版 Skill 的成稿方法；方法候选也不自动成为已验证规律。

开始时先解析当前 `SKILL.md` 的真实目录为 `{SKILL_DIR}`，从 `{SKILL_DIR}/../../../docs/runtime.md` 读取共同运行、材料授权、路径和保存边界；`{PROJECT_ROOT}` 是 `{SKILL_DIR}/../../..`，仅指这个完整技能仓库，不等于任意当前业务项目。再从 `{PROJECT_ROOT}/references/exemplar-study.md` 读取跨作品来源核验、上下文细读及正式评估边界。

普通作品或创作素材拆解时，读取或复用 `{PROJECT_ROOT}/references/universal-dream-framework.md`，在本轮授权对象内实质审视16个交点，并让检查结果进入实际观察、解释和采用判断；最终自然综合，不公开坐标或另列成问题清单。若请求只要求原样执行 CLI 或返回机器结果，不扩成作品拆解，也不触发这项框架分析。

资源准备时同时判断本轮交付物：若要交付面向人阅读的解释、拆解报告或原子候选说明，须在读取分析材料前读取 `{PROJECT_ROOT}/references/language-realization.md`；本轮已加载时复用。若任务只要求原样执行 CLI 或返回机器结果，不另写解释报告，则不增加这项读取。读者价值与作品组织仍仅在读者理解、行动或体验会改变报告内容或次序时按需读取。

当本轮明确涉及形成完整候选、编写检索卡、记录真实使用反馈时，按所做步骤读取本 Skill 的[原子记录与取用](references/atom-recording-and-reuse.md)；它负责候选写作、完整分析保存、确认及真实使用规则。用户明确要加载/搜索/读取本地库，或调用者已进入具体作品的材料/方法选择时，按需读取[本地资料库的分层检索与回读](references/library-retrieval.md)；它负责只读入口、短查询、typed cards、详情与跨步骤复用。局部解释、概念讨论或纯技术任务不因提到作品就额外加载。主文继续作为来源、分析、证据、专业绑定和写入授权的规则真源。

调用者负责的规则沉淀另回 `laohu-evolution`；用户稿件诊断遵循 `laohu-audit` 或 `laohu-analysis` 的职责和验证协议。链接提供定位，不能替代任务中实际读取这些约定。

## 什么时候进入

当用户希望理解一件作品或一段创作素材/点子内部怎样组织、希望累积可迁移的方法、按普通问法找回本地来源/方法原子，或已要求把已核实处理用于某项创作决定时进入。材料可由用户提供，也可由负责人按本轮允许范围核验取得；用户提供的口述或未完成构想可以直接作为构想分析，不要求先变成已发布作品。来源检索也不限定为研究已完成作品。用户已指定或锁定的参照优先；对已有明确方法的局部修订，只研究能改变当前决定的那一部分。

普通创作不需要先完成名作研究。适配 Reference 的调用既可由本轮待解释的材料关系触发，也可由具体下游决定触发；具体按末尾[按待解释关系与下游决定读取专业适配](#按待解释关系与下游决定读取专业适配)执行。用户要求比较真实作品或学习某一具体参照时，读取相应方法并核对上下文。看到“像某类作品”“想要高级感”不能代替一个可定位的源作品，也不能单凭风格词推断原作怎样做。

先判断本轮是**当前任务取法**还是**资料积累**。当前任务取法要明确具体消费者、专业决定、阶段、用户目标及锁定项；资料积累是用户想深入拆一件作品并留存方法，即使没有正在创作的作品也照常工作。此时用户的目标是看清原作中值得保留的真实处理及其可迁移边界，不追问一个虚构的当前项目；从原作实际机制出发，编译一个或多个未来消费者可能遇到的具体决定。用户已表达在意之处就以它定观察重点；没有特别偏好时，完整拆读最能解释该作品的真实处理，不从不存在的创作难题反推分析结论。只有某个信息缺口确会改变来源选择、适用范围或写入位置，才问最关键的一点。涉及拆解并收录时，本轮须继续交出具体入库方案，按[保存授权与工具](#保存授权与工具)完成方案确认后再执行写入，不能以分析结束代替收录流程结束。

两种模式都要同时保留用户目的、原作实际可见处理和专业方法；在资料积累模式中，“下游决定”可以是明确描述的未来适用场景，不要求本轮有成品任务。某项新发现超出目前 Skill 或本文件的既有方法时，记录其位置、事实、推论、成立条件和待接手的能力，作为方法候选继续收录；`consumer-map.json` 是当前消费者速查，不是消费者白名单或专业词表。必要时用 `candidate-unmapped` 作为暂存 binding 并写明未映射的实际决定，不能因此删去发现、强塞进近似旧标签或直接改 Skill。规则写回仍需单独获得进化授权。

### 研究用途和材料身份分开判断

先判断本轮为何研究，再判断手头材料是什么。**当前任务取法/资料积累**说明研究用途；**原作、转述、构想、新增建议**说明材料身份，两条判断互不替代。用户口述了一组灵感，不代表它来自一段已发布的视频；用户转述了一个场面，也不等于已经读到原作。

- **原作：**当前确实读到或看到了作品本身。只把实际读取的媒介、版本、片段和可见范围当作证据；读到文本不等于读到对应视频、声音或完整作品。
- **转述：**用户、评论者或其他来源对作品的描述。它可以支持“转述中提到……”的分析，不能支持原作里确有某个镜头、动作、先后或观众反应；要判断这些事实须继续核对原始媒介。
- **构想：**尚未完成或尚未被证实发生的设想。可以分析它内部已有的关系、实现条件与可能用途；不把“如果拍出来可能怎样”写成“原作就是这样”“观众已经这样反应”。
- **新增建议：**本次分析提出的补充处理。明确标为建议，与来源事实、用户原意和机制推论分开；它不自动变成原作证据或方法原子。

做来源记录时保留这项身份和核验范围，不改现有 schema；可在现有 `source.provenance.identity_basis`、`access_scope` 与 `notes` 中按职责写清依据和未核部分。必填身份内容若无法真实填写，就先说明缺口，不编作品名、作者、版本或媒介；不能为了写入而把构想伪装成已完成作品。一个具体材料可以作为当前任务的分析对象，却尚不足以支持原作事实或成熟方法。

### 辨认独立灵感，在共性与差异中寻找可用变化

一条消息、一次连续口述或用户所说的“第一个灵感”，都只是输入的包装，不预先决定分析单元。批量口述中，先按完整话意辨认每项可独立研究的对象、场景、身份、表现方向或片段；“或者、还有、再一个、也可以”等是检查边界的线索，不是机械切句的命令。用户明确说明各项无关联时，按该决定分别处理，不替它们补同一人物、共同世界、事件因果或必须组合的关系。

先区分并列候选、同一对象的补充说明、自我纠正与连续事件。并列身份、场景或风格即使可能共用方法，也先各自研究具体处境、信息或呈现如何改变用途，不能先压成一个方法的可替换变量；仍属方向词的条目可单列为待展开灵感，不伪造完整情节或原作。补充条件留在它所限定的对象旁；明确纠正替换受影响的工作表述，并在留存原口述时保留纠正依据，不把错误转写另建为灵感；必须相接才能成立的动作留在同一片段。只有无法消歧且会改变重要内容或归属时才问对应项，其余继续。

据此形成与原话可回指的对象清单，逐项拆解后再进入共同方法比较。对每项说清它具体提供什么内容、关系或体验，为什么值得保留，以及未来哪项创作决定可能采用；一项里发现多个可独立采用的关系就分别展开，不能只选最显眼的一项代表全部。材料少的条目说明目前能判断到哪里。全部处理后回核原话，确认每项均已分析、明确待定或经用户授权略过，不用“等、各种身份、不同风格”代替遗漏项；也不把分别提到的身份、风格和路线自动做全排列。

用户希望继续找创意、变量或差异化机会时，在各项具体分析上辨认哪些关系支撑了原有体验，哪些身份、处境、信息、目标、手段或呈现可以变化；只展开会影响当前材料的变量，不套全维度问卷。判断一项变化是否值得推进，要把它代回原有关系，说明它怎样改变人物可做的事、观众的预期、体验或用途；给出有材料依据的新切入点，并指出新方案成立需补足的条件。可以重组多个关系，但须标为新增建议，说明组合为何相容，不把独立来源说成原本相连。只换名字、服装或风格也可能有视觉价值；若只是装饰变化，就如实说明，不冒称叙事机制已创新。没有实质差异的候选合并，不以变量数量或组合数量代表创意。

面向人按独立灵感或实质发现编号或分点，各项内部用连贯段落解释；不把“成立条件、保留关系”等内部核对项套成每节栏目。分析对象数、来源记录数和方法原子数分别判断：多个独立灵感可以共用一种方法，一个灵感也可以包含多个方法；抽出共同方法后仍保留各灵感的内容与单独用途，不让方法去重变成素材删除。具体收录与回读接入[原子记录与取用](references/atom-recording-and-reuse.md#1-先决定形成什么记录)。

## 主线：从原作行为到下游决定

每次拆解都须把三件事对齐：**用户看重的体验或目标、原作实际可见的处理、下游此刻必须作出的专业决定。**三者缺一时先缩窄结论。原作可能有意思但不适合当前目标；下游可能遇到某类问题但原作并未采用所猜的方法；某项细节可能值得研究，却没有能接手它的实际创作位置。

资料积累模式中的“用户目标”可以就是把一件作品拆透并保留可迁移方法，“下游决定”可以是未来创作者在某一步需要如何处理；不可把这种目标说成已存在的用户项目。无论哪种模式，普通作品/创作素材拆解与系统完整设计都按仓库[万能造梦框架](../../../references/universal-dream-framework.md)实质检查四个判断维度与四个工作层次的16个交点。下面是本 Skill 的具体问题方向，不是逐格问卷、分析报告栏目或每个原子必须齐写的字段；内部交叉检查后，把彼此依赖的判断自然综合进观察、保存或交接。

| 维度 / 层次 | 目标：本轮/未来要实现什么 | 判断：依据什么取舍 | 行动：实际怎样处理 | 结果：形成什么并如何接续 |
|---|---|---|---|---|
| **灵魂**：用户与作品目的、立场和优先级 | 当前决策或资料收录想保护/发现什么价值、体验与审美方向？ | 用户明说的兴趣、事实和锁定项分别是什么；某个原作做法是否真的服务它？ | 按目的选比较轴、阅读范围和不外推的边界；资料积累不虚构下游项目 | 用户实际需要的是解释、可迁移方法还是当前创作决定；未取得反馈时不声称它有效 |
| **筋骨**：专业方法、证据和机制 | 下游在什么专业步骤需要一个成熟方法，或本次研究要辨明哪类创作能力？ | 哪个专业标准/方法与来源机制适配；证据足以支持到什么层级、哪些条件限制迁移？ | 读取源 Skill 真正的方法，把理论名称转成可检验动作；新机制不被现有菜单排除 | binding 应回到哪个专业步骤、交给谁、用什么成品检查；没有现成接手者时明确标候选 |
| **血肉**：原作与当前材料中的具体构成 | 哪个段落、动作、图像、声音、时间或关系代表这次要研究的价值？ | 它怎样接邻近材料/父作品/接收顺序；与近似单元相比改变了什么；事实/推论分界在哪？ | 读取并标位具体材料，展开部件与动作关系，有限推演成立机制和固定/开放变量 | 形成可定位的来源记录和细读；原子检索卡够找、详情够重读，未知状态不伪装成熟 |
| **表皮**：接收者实际遇到的媒介与产物 | 下游用户、观众或创作者实际要看到、听到、读到或操作什么？ | 是否读到原作真实媒介/目标成品/对应屏幕和声音；效果证据与未知分别是什么？ | 把关系迁移成目标 Skill 的真实文本/画面/时序/文件检查，不以评论说明替代作品 | 当前产物如何呈现并被下游使用；没有成品、受众或使用反馈时质量/效果保持未知 |

这16个方向彼此支持，某项事实可能同时改变数格；不拆成互不相认的原子，也不强迫对用户展示坐标。以下媒介观察只帮助选合适的细读尺度，不替代上述完整判断。

### 1. 定位来源与证据范围

先确认作品名称、创作者、媒介、版本和身份依据，再记录读到的具体范围、位置及来源。搜索摘要、二手转述、截图、片段或记忆可以帮助找材料；它们不能证明尚未读到的完整段落、全片关系或作者意图。作品无法核实、上下文不可读或版本不明时，明确限制，并把可用内容留在“来源候选”或“局部观察”状态。

逐层读取真正影响判断的上下文：被拆解的局部；它紧邻的前后单元；所在章节、场景、段落或段落组；父作品中先前建立的前提与之后的回收；以及接收者实际接触材料的次序。只读到节选时，说明哪些依赖无法判断。需要声音、画面、乐谱、字幕、封面版式或发布时间才能做判断时，应检查实际对应媒介；文字转述不能替代原始证据。

来源身份或媒介范围不确定，限制的是能对原作、版本和效果作出的外部主张，不会自动抹掉用户材料内部已经说清的关系。针对本轮要拆的具体片段，先按完整句群/话轮复原对象、明示主语、动作由谁发出及作用于谁或什么；再识别“先、之后、同时、一边……一边……、直到、当……时”等时间词和条件表达，记录事件是先于、同时于、包含于另一段行动中，还是只在某个条件成立后发生。先整理这些事件约束再解释；没有依据的先后关系保持未定，不强排成线性顺序。摘要或标题中动作词的排列不能覆盖材料明示的时间关系。主题相近的不同片段要分别还原，不能从前一片段或前次回答借用事件次序。中文省略主语、代词和连续动作要结合句法、语义承接及邻近上下文判断主体是否沿用；材料已能确认的主体与事件关系应作为约束保留，不因角色未命名、动机未交代或字段缺失就改成未知。只有句法或时间表达确实允许多种读法、且上下文无法消歧时，才把对应关系标为开放。形成重要复述或原子候选后，必须回指当前片段核对主体和时序；另行比较换人、改序或改变关系时，标为新增建议，不回写成输入原本未定。

定位不是把整部作品平均复述一遍。选取能解释目标决定的最小完整单元：如一组行动及其结果、一段句群及前后照应、一组构图元素的相对关系、一段音画接续或标题与兑现内容。若删掉上下文就无法说明它为何成立，观察单元就还不完整。

### 2. 先记录可见选择，再提出机制

记录原作实际出现了什么：材料、行动、语言、位置、先后、重复、对照、视点、声画关系或版面层级；哪些部件彼此作用；哪个变化由什么前提带出；某项内容又在哪处被延迟、展开、缩短或回收。说明构成关系和实际次序，不只写“用了反差、铺垫、留白、节奏”等抽象标签。

解释关键处理时，从材料中可定位的部件及其顺序出发，跟着接收者在各处实际能看到、听到或知道什么，再判断这些信息如何形成或改变理解、注意、期待和选择；只写材料支持的关系与必要前提，不要求每次机械补齐一条固定链。

讨论具体动作、措辞、命名或姿态时，还要放回当时语境：它在这里通常传达什么意味，对象所处的境况、双方关系和已掌握的信息怎样支持、修正或偏离这种读法；若判断为评价，先弄清评价者、对象和面向。若要把后项解释为推翻、挑战或反转前项评价/预期，分别从材料复原前项评价或预期指向的对象与面向、后项反应能说明什么及其指向的对象与面向，再判断两端是否落在可比较的同一关系上，并具体指出后项改变或动摇了哪项前置判断；只有前后关系对应且后项确实改变判断时，才作这类解释。对象或面向未明、两端不对应或证据不足时，只说明材料支持的并置/差异，把可能的联系写成有依据的条件推演，同时保留已确认的主体与时序。只有这层意味或错位会改变材料关系、接收者的预期或下游采用时，才展开说明。理论或专业术语只有在能解释这项材料中的差别、限定推论范围或改变采用决定时才取用；须实际代入材料说明它解释了哪个关系、适用条件是什么，不只列理论名称，也不为显得深入而强配心理学框架。

证据暂不足以确定一种读法时，可以把不同成立条件写成清楚的条件推演，标出依据和未知；这不应使其余已有依据的分析停下来。若没有接收者研究或使用反馈，描述为对材料结构的机制推论，不声称真实观众必然如此反应。分析深度看是否揭示了影响解释或采用的关键差别，不看篇幅、术语数或链条长短；继续展开若不会改变这次判断或下一步，就不为形式上的“深入”添层。

比较是解释机制的工具，不是每次分析的配额。只有删除、替换、调序或同作品近邻对照可能改变这次判断时，才选其中最小而有用的一种：例如检查拿掉哪个线索后结论不再成立，换一种顺序后接收者会先知道什么，或近邻单元哪项关系确实不同。比较对象必须来自当前材料或能明确说明是假设；不存在可核对对象时直接说明推论的限制，不强造对照。主题相同不证明采用同一机制。

不要为制造戏剧性，强迫每项素材形成反转、人物行动、行动后果或笑点。只有原作/材料实际出现并且对用户问题有用时，才分析这些关系；静态形态、语言命名、读者误认或持续体验本身也可能值得研究。机制不成立、条件不明或并非本轮所需时，结论可以是“目前只能描述这项构想/材料，不能证明一种可迁移方法”。

对每条重要说法标明属于哪种证据：

- **可见事实：**原作里能定位复核的文字、构图、行动、声响、顺序、字幕、发布资料或版本差异。
- **创作者自述：**创作者或可靠访谈明确说过的想法；保留说话人和语境，不扩展成外部已证实的创作因果。
- **机制推论：**由观察得出的解释，说明其依据、其他可能解释和成立限制。
- **效果证据：**具体观众、评论、研究或可复核表现数据实际支持的结果，并交代样本、口径与范围；没有就写“未知/未评估”。

不从播放量、奖项、传唱、名气、转载或“经典”反推语言、画面、节奏或因果必然成功；这些指标只能证明其本身所能证明的传播、制度评价或使用情况。不得虚构作者私密创作过程，不把文本中未出现的动机补成事实。

### 3. 形成完整、可迁移的分析单位

不是每个有趣细节都值得建原子。只有当一项可定位的处理可能改变某个真实或可明确描述的创作决定，而且其关键关系与适用条件能从材料中说明时，才把它作为可复用方法候选；喜爱、猎奇或题材相似本身不是保留理由。若用户只要解释一个局部问题，直接解释即可，不默认制作检索卡或原子。若来源本身值得以后核对，但当前尚无可成立的机制或采用条件，在入库方案里提出只保留来源，经确认后保存，不凑原子。

一个词、一句金句或标题可以是检索索引单位；但记录不能只有摘录、金句、主题句或“反差/拟人/加强情绪”等标签。细读和采用说明必须保留足够完整的上下文。**一个原子围绕一项可以独立采用的处理关系**：如果两步必须一起工作才能形成同一机制，就保留在同一原子；同一材料片段可以包含多项关系，但只有确认它们各自能被单独选择并指导创作决定，才拆开记录，并让每张卡保留辨认关系所需的共同上下文。把同一关系合写时，保留任何会改变其解释、成立条件或未来用途的差别，不用一个宽泛标签把它们抹平。适用条件或返回步骤不同可以提示继续检查，但单独出现这种差别并不足以拆分；先确认它们是否确为不同且可独立采用的处理关系。来源媒介限定能观察和能主张的证据，不限定一条关系可以服务的目标媒介；换媒介后必须重新判断信息怎样成立，不能把原媒介中的作用或效果直接外推。相同处理关系跨消费者只保留同一原子，用各自的 `consumer_bindings[]` 说明不同消费者怎样采用。一个原子至少让后续使用者能定位它、看懂具体构成与次序、理解接收者可能如何遇到这些信息、说明推论根据与成立边界，并据此作出一项明确下游决定。

写卡时用平常说法说明“这件作品在什么位置做了什么，怎样接上前后内容，为什么这可能改变接收关系，在哪些条件下可以迁移”。再列出不应照搬的专名、独特句式、文化语境、制作条件或用户锁定项。

用户明确要求拆解并收录、整理成以后可查的方法或本轮资料沉淀时，先交完整分析，再给可确认的入库方案：说明准备保存哪些来源和完整解释，从中拆出哪些可独立复用的处理关系、为什么这样拆，各自适合什么接收者目标与专业决定，哪些内容只是可替换元素或待发展分支，以及拟用哪些材料词、关系词或需要词检索。若同一关系可供多个实际用途，方案保留一项共同关系，并分别说明每种用途的转换条件、保留/重建/改变的作用、不能承接的部分及信息损失；经授权后以同一原子上的多个 binding 表达，不按形式复制 atom，也不为封面、标题、歌词等类别凑齐清单。每项拟保留关系须有完整独立内容，使未参与分析的人也能理解其来源、上下文、处理、推论依据、条件、证据状态、用途和限制；不能只列候选名字、标签或未来用途。来源记录在获准保留用户提供材料时保存完整原文和独立分支，完整分析随来源/原子正式记录；不让报告或检索摘要代替。沿用已有库位置，只读查重后说明拟新增、复用、待发展及任何拟修改范围，不为未保存内容编 source/atom ID 或“已入库”状态。方案交用户确认，随后按[保存授权与工具](#保存授权与工具)写入；仅要局部解释时仍不强制建卡或交收录方案。方案、完整草案和回读的具体方法见[原子记录与取用](references/atom-recording-and-reuse.md)。

卡片中的可见事实、作者自述、机制推论、效果证据和新增建议须能区分。用户/来源未提供的机制不能伪装为事实；本次建议的应用方式也不回填成“原作做法”。

四类观察可按作品需要交织，不要求每个分析都塞满所有维度或栏目：

1. **内容与叙事关系：**事件、人物处境、信息权限、选择与后果、前后照应。
2. **语言与声音关系：**词义、搭配、语序、句群、声口、韵律、旋律或实际发声。
3. **视觉与动作关系：**对象身份、构图主次、观看路径、空间、姿态、材质、镜头和图像生成条件。
4. **时间、媒介与呈现关系：**先后、并行、时长、停留、切点、声画接续、读者入口和内容兑现。

细读至少要能在局部单元、相邻关系、段落/全作依赖和接收者采用位置之间找到实际相关的尺度。某层与本次决定无关时不强行扩写；某项声称依赖全作结构时，就不能只凭一句话下结论。

### 4. 为真实消费者编译采用方案

先从最终接收者、使用情境和目标成品媒介确定要改变什么：接收者需要看懂、听懂、感受或使用什么，材料要交付到哪里。目标已从当前任务或上游交接中明确时直接沿用；没有当前项目时，只说明未来创作者可能遇到的具体决定，不虚构作品位置、场次或版位。

再回到来源，选出确实能独立取用的具体关系及其成立条件。说清关系由哪些对象、动作、词句、图像、声音、先后或上下文共同成立；把这些可取用的具体内容与可迁移的关系都保留下来，不能只剩物件清单，也不能只剩“反转、冲突、悬念”等抽象标签。区分原作可见事实、机制推论、用户授权直接取用的素材和本次新增建议。

依据目标成品媒介和这项关系，找出真正负责该决定的专业消费者。用 consumer-map.json 定位实际入口和返回步骤，再读取目标 Skill 当前主文和必要 Reference，确认其专业方法、适用条件、输入、成品检查和返回接口。consumer-map.json 是导航，不是用途白名单；现有 binding 缺少目标消费者时，不因此排除关系，也不把已有剧本/视频采用当成其他形式已成立。若没有可核实的专业方法或成立条件，保留为探索或 candidate-unmapped，不临场发明方法。若适用的消费者方法会改变哪些源关系值得保留，可回到来源重看；这里的先后表示真实判断依赖，不要求把每项创作设计固定成一次走完的线性流程。

用刚读到的专业方法，判断关系进入目标媒介后哪些信息和作用可以保留，哪些必须重建或改变，哪些不能承接，以及转换会损失什么；把判断落实为当前任务的内容选择和组织动作：目标媒介需让接收者先接触什么、随后获得哪项关系证据、用什么内容或顺序补回原处理依赖的信息。连续事件转成静态成品时，说明单帧保不住的先后或变化，以及文字或其他画面关系能否重建所需信息；非语言材料进入歌词等文字形式时，重新设计说话者、言语动作、段落作用与回返关系，不把事件逐行切开。只写材料实际支持且当前目标需要的转换，不替每条素材列满所有形式。新增用途只有在能独立说明转换条件时才进入拟采用范围。

最后说明新内容交回哪个专业步骤、由谁接手，并在目标媒介的实际成品上复核：关系是否仍可由作品本身读出、用户目标和锁定项是否保留、转换造成的损失是否可接受。提示词、分析说明或计划不能代替真实成品；没有成品时只报告设计条件，不称采用或效果已验证。

每一项拟绑定用途都要写明具体专业决定、触发条件、关系成立条件、要保留/重建/改变/不能承接的作用、返回步骤及成品检查点。通用 binding 说明一条关系可能服务什么专业决定，不等于当前项目已经采用；真实任务选中记录时，另给当前接手者具体采用说明，包含作品中的位置或待处理产物、此次条件、待转换变量、用户锁定项、返回步骤和检查点。来源、binding 与本次采用说明的字段和交接路径见[原子记录与取用](references/atom-recording-and-reuse.md)。

绑定仍必须完整包含 consumer、decision、stage、required_context、adaptation、return、check 七项。查询消费者、决定、阶段时，过滤必须由同一条 binding 同时满足；不能从一条 binding 借消费者、另一条借决定。这七项是记录和机器过滤的完整接口，不要求面向人的报告逐项展示，也不因探索新用途而扩展严格 binding 字段。

迁移时保留原作关系和有效前提，按用户授权决定能否直接取用来源素材；若借用的是方法，就重建本作自己的内容。不得借用可识别原句、独特意象组合、专属事件顺序、专名或美术构件来冒充机制迁移。多个方法候选的取舍仍由创作负责人按用户目标与整体主方向决定；benchmark 不以“最像原作”自动胜出。

### 5. 保存检索卡、全文细读与状态

`index_card` 是快速找到候选的检索卡：标题用具体、可辨认的说法；`summary` 是单行自然语言说明材料中哪种处理可能对何种普通决定有用，最多 200 字符；`terms` 取自实际材料，并补充未来使用者可能说出的需要词、动作和关系词。词项数量不限，不设封闭词表；未来问法只用作检索入口，不回填成来源事实或机制证据。`category` 负责原子存放，`consumer`/`stage`/`decision` 是专业 binding 过滤，`terms` 用来找到记录，三者不可混作一类标签。来源 `notes` 可放简短单行的来源检索说明，不放原文、长摘录或完整 provenance。检索卡的写法和自足回读标准见[原子记录与取用](references/atom-recording-and-reuse.md)。

收录的完整分析须随正式来源或原子保存，并在入库方案中说明其实际去向；检索卡摘要不代替全文，也不能让以后回读依赖聊天或可清理缓存。来源分析与每条关系细读的保存位置及避免重复办法按[原子记录与取用](references/atom-recording-and-reuse.md#2-组装能独立回读的候选)执行。

来源 JSON 的 `source_material` 至少保留明确的材料引用、版本与读取范围；用户在对话中提供且获准留存的材料，可把本次足以复核的范围放入该来源记录一次。其他本地文件、网页、书目或音视频保留精确位置/版本/哈希引用；受保护作品只记录必要短摘录，不复制长段歌词或全文。atom 只写源位置、充分上下文摘要和具体细读，不重复来源原文。可重建的全局 `catalog.sqlite3` 和兼容保留的类别 `index.sqlite3` 只含检索所需的短元数据/卡片与 binding，不收录原作正文或完整细读；JSON 仍是真源。完整 `analysis` 保存在来源/atom JSON 中，需要时读取对应的 source/atom 详情。source-only 记录或材料单元可作为 `material` 候选查找，方法处理以 `method` 候选查找；卡片实际含有什么以对应视图为准，未建专用单元卡时不宣称可通过原文内容检索。具体查询与详情命令见[本地资料库分层检索与回读](references/library-retrieval.md)。

状态按证据成熟度记录，不按喜爱程度：资料身份和读到的范围尚不足时是候选；已定位并有实际观察但机制边界未清时保持观察或方法候选；达到可复核、可说明条件、可绑定一个真实专业决定的标准时才可标 `method-ready`。这只是资料成熟状态，不证明外部受众效果。已保存后的使用记录另记，`applied`、`adapted`、`rejected`、`not-used`、`pending` 描述一次使用结果，不能反过来覆盖原子证据状态。

### 6. 检索、选择和返回

具体作品选择中的触发边界由共享[日常创作取法与方向](../../../references/exemplar-study.md#日常创作取法与方向)统一维护；用户说要“加载”只看入口状态，不等于查询或读详情。读取库时按[本地资料库的分层检索与回读](references/library-retrieval.md)依次确认位置与状态、返回有界的材料/方法候选卡、只打开选中来源单元或 atom 详情，并回到当前目的。若任务状态已有同用途且 revision 未变的查询/详情，可复用；不要全量加载卡片。查询失败、无匹配、库缺失或缓存状态不适用时，明确影响范围，继续不依赖该库的材料分析和专业工作；只读命令不隐式建库、修复或重建。

根据候选类型核对来源材料还是方法原子，再判断它的证据范围、适用条件、锁定项与限制。材料卡不是方法 binding；`--for-consumer` 是排序偏好，不代表用途已经登记。没有目标 binding 的候选可以继续探索，但须读取当前 consumer 的专业方法确认输入、转换、返回位置及成品检查；consumer-map 不是白名单。候选排序、主题相似、读到详情都不决定采用。当前负责人可选择、拒绝、继续探索或保留未定，并把所需资料回交原创作步骤；benchmark 不替作者定目标，不以数据库结果覆盖用户锁定内容。

真正采用时按所选专业 Skill 完成实际材料或作品并检查其成品位置；不要求为普通创作附完整 benchmark 分析报告、16 格结果或新建 delegation。搜索、加载、推荐与读取都不是实际使用，不记 usage；记录真实反馈仍按[原子记录与取用](references/atom-recording-and-reuse.md)执行，须沿已授权流程并匹配原有 binding。来源身份、原作证据、内容授权和成熟状态仍按主文判断，不因 catalog 状态为 `current` 就视为内容审计通过。

### 7. 把研究写成清楚的分析报告

实际起草文字报告时，使用资源准备阶段已加载的[语言成文方法](../../../references/language-realization.md)落实表达并修订成文，再回到本报告写作；如果目标读者的理解、行动、体验或审美会改变报告要解释什么、先解释什么，再按需读取[读者价值与作品组织](../../../references/audience-value-and-structure.md)。两份共享 Reference 给成文和组织判断，不是固定报告模板，也不取代本 Skill 的来源与机制分析。

按用户的问题和材料的实际关系自然组织章节，不公开16格内部检查表。面向人阅读时，把具体证据、解释、成立条件与用途连成读者能跟随的段落；这些内部分析作用不能仅改名后变成逐项套用的默认栏目或报告骨架。可按材料或实质发现分节；确有横向比较、真实步骤说明或用户明确要求卡片、JSON、精确接口时，保留它们所需的表格或结构，不能让结构替代解释。重要结论后，用具体材料和前后关系让读者看见它为什么成立：对象是什么、动作或表达在此处意味着什么，接收者在每一步能得到什么信息，处境与关系如何支持或偏离这种意味，最终改变了哪项理解、预期或决定。处理关键词语时，先辨清材料中谁对什么做了什么、作用于谁或什么、评价指向什么以及结果/条件是什么，再选择准确、通行的称谓或动作词；若单个词会压掉主体、对象或限制，就用清楚的句子展开，不用术语名替代解释。

把条件、开放项和未知放在它们会改变的那项判断旁；证据暂不能定论时说明条件分支，继续完成其余已有依据的解释。需要承接陌生判断时，用读者熟悉的经验把材料和推论接起来，但不以赞语、术语或固定句架代替分析。对“反差”“反转”“钩子”“节奏”或“能放进剧本”等词，若使用就紧接具体展开，不能当作结论本身；没有相应证据的受众效果或因果关系明确标作推论或未知。

用户只要局部解释时，交付局部报告即可，不强制转成原子卡。深入研究、整理库或用户明确要求复用时，从关键处理中筛出独立可采用的候选，并交付可独立理解的完整候选内容；自然成文不等于可以省略材料定位、处理关系、机制依据、成立条件或采用边界。先让解释按读者需要成立，再把记录内容编译进 source/atom 字段和 binding；仅在实际收录或用户明确要求机器字段、JSON、精确映射/步骤表时，按所需接口组织机器结果，并与面向人的解释分清，不能以字段或重新命名的栏目替代解释。若去掉字段名后只剩泛化概括，就回到材料补做分析，不只是换一种排版。

报告和本轮机器结果（若有）交付前从读者/调用方角度通读并修订：检查证据是否支持解释，指代与术语是否清楚，是否把构想说成事实、把推论说成受众结果，或遗漏会改变判断的条件；删除只重复结论的赞语。对其中每个标为“未知/未定/需用户确认”的来源主张，逐项回到当前源单元，按[§1来源约束](#1-定位来源与证据范围)核对其所指关系是否已有明确依据；不把已确认关系降为未知。身份或动机未明不能抹掉材料已确认的主体与时序；若建议改变主体或顺序，另标为新增变体。发现读者必须靠追问才能懂的句子，直接在正文补出对象、次序、语境或边界。

## 保存授权与工具

**只分析不写盘。**单纯要求分析、解释、找灵感、检索、读卡、统计或校验，不会自动保存原作或方法原子；调用本 Skill 也不等于整批材料永久收录。

用户提出“拆解并收录”或选择本轮收集模式时，默认先完成完整分析和具体入库方案，等待用户确认该方案后再写入。表达想收录、认可分析或提供库路径，均不单独代替对本批拟保存内容的确认。方案须依[第3节](#3-形成完整可迁移的分析单位)说明具体内容、拆分理由、复用场景、检索入口、保存位置与新增/复用范围；不要只问一句是否保存，让用户批准尚未展开的内容。

确认前可只读盘点库、查重、读取详情和预览容器位置，不运行 `put`、`rebuild-index`、`log-usage` 或容器工具的 `--write`，不以来源候选、草稿或临时类别的名义先写进正式库。缺失或过期索引只在方案中说明，不为准备收录先行重建。方案直接在聊天中交付即可，不强制创建计划文件。

用户明确接受当前可定位的方案后，沿用其材料范围、库位置、归类和拟保留关系，完成写入及回读检索检查，不再逐文件或逐类别重复询问。只批准部分就只写该部分；范围有歧义时按 runtime 作最小澄清。若用户本轮明确要求跳过确认、直接收录，或当前指令是在执行一份已经确认的方案，按其明确授权直接执行；普通的“拆解并收录”不视为省略确认。写前发现材料或拆分等重要决定发生实质变化时，仅更新受影响部分并重新取得确认；不影响这些决定的格式和措辞修正由负责人完成。

资料不足时，在方案里提出保留为候选或只存可真实填写的来源，获确认后执行；不伪装成熟方法，不编造必填身份信息。`put` 允许 `source`/`sources` 单独提交，也允许省略 `atoms` 或传 `atoms: []`；这种 source-only 写入只产生来源记录，可用 `get-source` 读取，不会因这条来源新建空类别或原子搜索项，也不会新增 usage。`put` 仍按既有流程维护库中已有类别的索引，索引维护失败会单独报告，不影响已提交来源作为真源。显式填写的非法 `atom`/`atoms` 类型或不完整原子仍会报错，不能借 source-only 分支吞掉原子错误。

### 归类与原子复用

归类只决定原子存放位置，不限制可以观察或收录的方法。每条原子只选一个类别；跨消费者复用通过同一原子的 `consumer_bindings[]` 表达，不复制原子。

1. 用户明确指定类别或已有目录归属时优先沿用。若类别归属、收录授权和库位置均已明确，类别目录尚不存在是首条获准写入时按需创建的正常情况，不额外询问。只有命名无效、与既有归属存在实质冲突，或缺失信息确会改变写入位置/归属时，才澄清对应项。
2. 用户没有指定时，先只读查看当前类别和记录用途：用 `stats` 看已有类别及数量，再按[分层检索与回读](references/library-retrieval.md)以 `query --kind method` 查相关卡，并通过 `get-atom` 详情视图核对用途。之后按用户明确的主要复用用途选能承接的现有类别；用户没有明确用途时，按原作和被拆单元的工作类型选最贴合的现有类别。
3. 五组分析 Reference 是观察与适配方法的入口，不是存储类别表。不要因为某原子能用于不同消费者，就为每个消费者各建一类。词面不同本身也不构成新类理由；例如 `lyrics`、`music`、`language`、`article` 等相近叫法应先检查已有类别是否已承接同一主要用途，常规同义命名直接复用已有名称。
4. 同一处理已有原子时沿用其稳定 `ATM-ID`，不因换消费者复制、搬迁或改类。只有当前授权明确包含修改该既有记录时，才把新消费者 binding 合并进同一原子；先备份实际记录，保留 ID 和已有细读，写后运行 `validate` 并重建对应类别索引。未获准修改就原样复用已有原子，不擅自补写；`put` 拒绝覆盖，不能用它绕过修订边界。
5. 只有没有现有类别能承接主要用途或工作类型时，才按已有命名习惯提出简短、稳定的小写 slug，并在首条获准原子保存时创建该类；不预建空类别。新发现的处理即使超出当前 Skill、consumer-map 或既有方法词表，也继续作为方法候选分析和收录；缺少现成专业 binding 或类别时，记录具体决定/用途和待接手范围，不得排除该发现。
6. 若多个合理类别会实质改变未来检索或既有资产组织，而用户没有指定，只澄清类别归属；不暂停原作分析，也不通过重复保存来同时占多个类别。若差别只在消费者名称，则按现有原子与 binding 规则处理，不追问类别。

方案阶段可调用 archive 预览已有或拟用位置；只有本批方案已获确认，或用户明确省略确认且授权写入时，才按下例准备/复用容器并保存。`laohu-archive` 只返回位置，本 Skill 负责语义归类和记录：

```bash
python3 "{SKILL_DIR}/../laohu-archive/scripts/library_workspace.py" --library benchmark --root "{PROJECT_ROOT}" --write
python3 "{SKILL_DIR}/scripts/library.py" --library-root "{返回的 benchmark 路径}" stats
```

如果当前项目不在技能仓库内，按 runtime 的项目位置和用户确认规则传入正确项目根或已确认的精确路径，不把已安装 Skill 目录当项目资料目录。工具全部基于 Python 标准库运行；不联网、不安装依赖、不调用付费服务。

| 命令 | 用途与写入行为 |
|---|---|
| `put --input bundle.json` | 本批方案获确认，或用户明确省略确认并授权写入后，添加来源与一个或多个原子；若当前只有可追溯来源，可省略 `atom(s)` 或提交 `atoms: []`，只保存来源，不因这条来源新建空类别、原子搜索项或 usage。`put` 仍按既有流程维护库中已有类别的索引。仍须提供有效 `source(s)`；显式非法原子类型或字段继续报错。拒绝默认覆盖；相同提交重试幂等，语义重复可返回已有原子。 |
| `info` | 只读返回 catalog 状态、清单检查时间、revision 与可可靠统计的库存；`current` 只表示 path/size/mtime_ns 清单相符，不是内容审计。不会建库或修复缓存。 |
| `query TEXT --kind all|material|method [--for-consumer C] [--registered-only --consumer C] [--consumer C --decision D --stage S] [--category X] [--limit N] [--cursor CURSOR]` | 从全局 `catalog.sqlite3` 只读返回有界 typed cards，并带查询 revision、returned_count、has_more 和 next_cursor；不返回总命中数，不读全文、不自动修复或重建。`--for-consumer` 是软排序偏好；`--registered-only` 需有 consumer；显式 consumer/decision/stage 是须由同一条 binding 满足的严格过滤。详见[分层检索与回读](references/library-retrieval.md)。 |
| `get-atom ATM-ID [--category …] [--view decision|analysis] [--consumer C --decision D --stage S]` / `get-source SRC-ID [--unit KEY] [--view identity|material|analysis]` | 只读所选 atom/source 或 unit 的详情；不写入。未传视图时保留旧的完整 atom/source 读取行为，指定 unit 时只读所选单元。 |
| `search` / `search-sources` | 兼容既有的类别索引 atom 搜索和来源标题/notes 搜索接口；新调用流程使用 `query` 的 typed card 与游标协议。 |
| `log-usage --input event.json` | 用户明确要求记录真实使用结果时按月追加一条；`consumer`、`decision`、`stage` 精确对应同一条既有 binding，并为本次真实情境填写 `required_context`、`adaptation`、`return`、`check` 及可核对的 `case_ref`/`result_evidence`。默认按提交内容生成稳定事件 ID；完全相同的重试幂等。搜索或推荐不记 usage。 |
| `stats` / `validate` | 只读统计真源与使用记录，检查来源关系、证据状态、bindings、待恢复批次和类别索引新鲜度。 |
| `rebuild-index` | 经明确决定后重建全局 `catalog.sqlite3` 及类别 `category/index.sqlite3` 检索缓存；不修改来源/原子/usage 真源。读命令不触发重建。 |
| `recover` | 仅在待处理事务存在时显式回滚未完成的新增批次；保护不属于该事务的内容。 |

JSON 来源、原子、按月 JSONL 使用记录是可迁移真源；SQLite 是本地可重建缓存。批次事务与原子替换支持崩溃恢复；来源/原子已提交但索引失败时，工具会如实区分，不能把索引故障说成数据未写。索引及工作区内私有记录按仓库忽略规则默认不发布。所有命令都须显式传入 `--library-root`，防止静默写入安装仓库。

默认 usage ID 由事件内容稳定生成，不含工具自动填充的记录时刻；若两次确实是不同使用事件，应提供不同 `case_ref` 或调用方稳定的 `usage_id`，不要让幂等键把两件事合并。读取命令不隐式 `mkdir`，普通分析没有保存权限。

## 按待解释关系与下游决定读取专业适配

先确认本轮要解释或决定的具体关系，再读能提供实际观察动作的方法。若关键视觉形态或识别、词语命名/措辞/声口、叙事行动/信息关系等确实承担解释，即使目前没有制作项目或只有口述/文字构想，也读取对应的既有分析适配和本轮所需方法，完成来源观察后回到当前拆解；没有成图、实际声音或更广上下文时，将结论限制在输入支持的设计意图、文字线索与推论，不说成品已出现或受众已如此反应。若本轮还有具体下游决定，再按表中映射选择该决定实际需要的方法；读取适配不启动下游完整创作。只读取当前材料关系与决定需要的适配，不通读全表。下表保留消费者映射，供结果返回专业决定时参考，不是全量读取清单。

| 下游工作 | 按需读取 |
|---|---|
| 故事、剧本、小说与叙事型写作 | [叙事分析](references/narrative-analysis.md)，依赖目标内容和人物/读者信息。 |
| 文章、口播、歌词、编曲中的词句与声口、篇内句子 | [语言分析](references/language-analysis.md)，读取实际文字或可用声音证据。 |
| 封面、图片、视觉资产身份/连续性、动态画面及版式（不含声音身份） | [视觉分析](references/visual-analysis.md)，检查目标媒介与实际观看尺寸/状态。 |
| 稳定角色/旁白声音身份（`laohu-assets/voice`） | [时间与声音分析](references/time-and-sound-analysis.md)，只在实际声音可读并获准时把音频当作听觉证据；文字描述不证明实际音色或辨识度。组内声音仅在确有混淆或用户要求时同条件比较。 |
| 编曲、音画、剪辑、ASR、动作时序 | [时间与声音分析](references/time-and-sound-analysis.md)，没有声音/时钟证据时收窄结论。 |
| 选题、标题、正文入口、HTML 与公众号呈现 | [选题与呈现分析](references/topic-and-presentation-analysis.md)，让读者承诺回到可兑现材料。 |

完整映射见 [consumer-map.json](consumer-map.json)。`audit`、`analysis`、`evolution` 可以把本 Skill 用作证据查找、方法候选和适用范围材料，仍由相应 Skill 决定判断与验证；`archive`、`update`、`luna` 等操作入口只按自身职责取用位置或交接信息，不套用艺术评价标准。

## 交接与停止

下游已明确可以采用时，交出原子 ID、需保留的关系、适用条件和限制、目标产物位置、返回阶段及检查点；用户提供了本轮已有选择就沿用，不重复比较。两项原子对同一用户目标相冲突时，不靠数据库排序裁决，交给创作负责人结合整作方向和用户锁定项选择。

当材料不可读时说明读到的实际范围；当机制只能推论时保留推论状态；当适用条件未满足时只提供候选；当证据已足够时停止扩展，不按原子数量、标签数量或固定栏目配额硬凑。质量结论遵循项目的[验证协议](../laohu-analysis/references/validation.md)：本 Skill 的作者自评不能证明实际行为或作品质量已通过。
