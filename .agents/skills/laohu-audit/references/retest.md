# 问题复查

仅在用户明确要求复查，或已明确授权的职责组合包含复查时，由 [laohu-audit 主文](../SKILL.md) 读取。本 Reference 负责按原问题、原条件与保护项核对修复状态，不负责修复；核完回主文交付即止步。

## 1. 固定比较基准与保护项

1. 沿用原问题的对象、目标、触发条件、实际线索与保护项；无旧编号时用稳定段落、元素或行为锚点建立映射并编号，不要求用户补旧报告。若对象或目标已变化，先明说差异，不用新条件证明旧问题已解决。
2. 定向复查深审原问题、受影响保护行为及直接上下游，核对改动是否引入新副作用（例如修通了一处硬伤，却把原本的锋芒、关键硬约束或下游接口伤到了）。

## 2. 对齐原证据层级

- **文字改动只解文字层**：原问题若在运行行为、媒介呈现或真实接收效果层，仅凭规则或文案已改不能判为“已解决”；若本轮只看了低层，如实报告低层结果并把高层留为 `待验证`。
- **回核原控制点**：对照原句与修订句，检查原控制位置是否真正修复；只在末尾另加一句总原则而保留原冲突条款，不判解决。
- **标明复查身份**：修改者与复查者为同一人时须标明自查（按[评估与验证协议](../../../../docs/governance/evaluation-protocol.md)最高记 `OBSERVE`），不冒充独立验证。

## 更新原编号与状态

沿[三技能协作协议](../../../../docs/governance/triad-handoff.md)带回原 `AUDIT-ID`、证据与保护项核查结果，逐项判定状态：

| 状态 | 判定条件 |
|---|---|
| **已解决** | 原问题所在证据层、原条件及相关保护项均有相称证据支持，差距已消失。 |
| **仍存在** | 原问题在相同或可比条件下再次出现，定位具体位置。 |
| **部分变化** | 分别说明已改善与残余差距，不用局部改善掩盖未解问题。 |
| **待验证** | 缺少判定所需的运行、媒体或真实接收证据；说明最小缺口。 |
| **撤回** | 新证据推翻原问题的前提、适用条件或推理。 |
| **用户接受取舍** | 用户知情后决定保留现状（是取舍，不等于技术上已解决）。 |

独立新问题另行编号并按主文铁律筛选；交付状态、保护项结果与未验证范围后停止，不自动进入修复或生成额外台账文件。
