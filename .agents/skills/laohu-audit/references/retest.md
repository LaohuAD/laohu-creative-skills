# 问题复查

仅在用户明确要求复查，或已明确授权的职责组合包含复查时，由 [audit 主文“停止、授权交接与复查”](../SKILL.md#停止授权交接与复查)读取。本 Reference 按原问题、条件、层级和保护项核对状态，不负责修复；完成后返回主文同一节，用原编号或本次建立的稳定锚点交付。没有授权时，不因上轮有问题而自动启动复查。

## 固定原问题与比较条件

1. 沿用原问题对应的对象、版本、目标、条件、范围、实际线索、用户保护项和约定的检查方式。对照本次变化，只核验足以回答“原差距是否仍在、改动是否破坏相关保护行为”的材料。
2. 若原对象或目标已经变化，明确列出差异，不用新条件证明旧问题已解决。原问题可定位但没有旧编号时，使用稳定的段落、元素或行为锚点建立对应，并在本次复查中赋一个编号；不要求用户补做旧报告。
3. 重新读取根目录[万能造梦框架](../../../../references/universal-dream-framework.md)，在本轮授权复查对象内对全部16个交点作实质审视，关注原差距及受影响保护行为的目标、判断依据、实际处理和结果。模型补全检查方向，不扩大原授权，也不另建坐标式复查表；不能因某一条原问题改善或一个顺利样例就停止其余相关检查。

## 用与原问题相称的证据确认状态

- **对齐问题所在层级**：原问题在规则文字层，可对照原句、相邻条件和修订句判断文字差距；若原问题在实际运行、媒介呈现或接收效果，低层的文字改动不能证明高层问题已解决。用户仅授权低层检查时，报告该层结果，同时把高层问题留在待验证。
- **逐项核对保护行为**：沿原触发条件检查用户锁定的观点、声音、力度、技法或负责作者按目标应完成的专业选择，确认是否进入实际动作和成品。新增限制项通过，不代表原目标整体保真；原条件不再适用时说明变化，不能静默替换标准。
- **复核原控制位置**：若差距涉及规则措辞，把原句、上下文与改写并列检查；只在别处新增总原则，而实际控制语句仍削弱、丢失条件或使动作可选，不判文字问题已解决。说明、自述、静态文件存在或单个成功样本不能替代对应层的运行证据。
- **保持原质量判据**：若问题是硬规格通过但整体作用仍不足，沿用原目标、专业判据/参照、媒介和条件，检查真实成品及组合。候选表达形式不同不自动等于问题解决，也不把新的审查偏好加入原标准。
- **标明复查关系**：审查者与修复者是同一人时说明是自查，不能称独立验证。超出原授权或不可读的内容只记为限制，不猜测其状态。

## 更新原编号与状态

每项按原编号逐一比较，不把新旧问题、条件或证据层级混为一谈：

| 状态 | 适用条件与报告方式 |
|---|---|
| 已解决 | 原问题所在层级、原条件和相关保护行为都有对应证据，且差距已消失。文字变化只可解决文字层问题；运行/成品/效果问题须有相应层证据。 |
| 仍存在 | 原线索在相同或可比条件下再次出现，指出位置或实际材料。 |
| 部分变化 | 分别说明已改善与仍未解决的条件，不用一处改善覆盖残余差距。 |
| 待验证 | 缺少判定原问题所需的媒体、运行、接收者或其他证据时使用；说明最小缺口。若本轮只查低一层，另报该层结果，但高层原问题仍待验证。 |
| 撤回 | 新证据推翻原问题，指出什么事实、适用条件或关键推理发生变化。 |
| 用户接受取舍 | 用户知情后决定保留现状；这是接受取舍，不表示技术上已经解决。 |

新线索若与原编号属于同一目标和同一问题，可补在原项；独立的新问题才另行编号，并按主文问题筛选规则处理。目标或标准已改变时先说明变化，不静默重写原编号含义。

## 结束复查

交付每个原编号的状态、实际范围、保护行为检查结果和仍未知条件后停止。发现未解决问题不等于获准自动修复或继续循环；新问题、方案取舍和专业修复按用户授权交由 analysis 或相应专业入口。结果在当前交付中简要说明，不自动生成复查报告、结果台账或哈希文件。
