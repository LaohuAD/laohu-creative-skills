# 问题复查

用户明确要求复查，或已明确授权的职责组合包含复查时，由 `{SKILL_DIR}/SKILL.md` 的“输出问题包并停止”读取。执行者是当前 audit 检查者；本文件让复查按原问题层级、条件和本轮授权范围核对状态及相关保护行为，不负责修复；读完返回主 Skill 同一节，在原编号或本次建立的稳定锚点编号下交付状态。没有相应授权时，不因上轮有问题而自动启动复查。

## 保持比较条件

沿用已明确的复查授权，不因入口切换再询问；复查范围依据原问题与保护项，不把完整循环授权理解为无限扫描。单独找茬仍不构成修复许可。

沿用能取得的原对象版本、问题编号、目标、适用条件、实际线索、用户保护项和约定的检查方式。对照当前候选的版本或变更范围，只检查能回答“原问题是否仍在、改动是否破坏保护行为”的材料。原材料或用户目标已变化时标出差异，不拿新条件证明旧问题解决。

原问题或改前／改后对象可定位但没有旧编号时，可用稳定的段落、元素或行为锚点建立对应，并在本次复查中赋一个问题编号；不要求用户为同一问题补做旧报告。

状态证据必须覆盖原问题所在层级及原条件要求的保护行为：原问题属于规则文字时，可对照候选文本判断该文字差距；原问题属于实际运行、媒体表现或接收者效果时，文本改动不能证明原问题已解决。若本轮只授权检查文字，就单独报告文字是否符合要求，并将缺少对应运行、媒介或接收者证据的原问题保留为“待验证”；不越权执行未授权的测试。修改说明、作者自述、静态文件存在或单一正向样本不能替代其所对应的实测。审查者与修复者是同一人时标记为自查，不能称独立验证通过。

若原问题是“达到硬规格但整体效果仍不足”，复查时沿用原目标、专业判据或参照、媒介和关键条件。逐项比较能说明原差距是否变化；不要只因候选表达形式不同就判通过，也不要把一种新的风格偏好加到原标准里。若原问题关乎完整作品或组合效果，即使所有局部检查都通过，也要按原目标检查成品整体。新增或改变的条件另行说明，不能悄悄替代原条件。

## 逐项更新原编号

每个既有问题沿原编号比较，检查所需的相邻保护行为和相关回归，不扩成全项目审计：

| 状态 | 如何报告 |
|---|---|
| 已解决 | 原问题层级和原条件（包括与该问题相关的保护行为）均有对应证据，且原差距已消失。文字改动只能解决文字层问题；原问题属于运行或实际效果时，需验证该层，不能仅凭文字变化判已解决。 |
| 仍存在 | 原线索在同条件下仍出现，指出位置或复现材料。 |
| 部分变化 | 分开说明已改善与仍未解决的条件。 |
| 待验证 | 缺少判断原问题状态所必需的媒体、运行、接收者或其他证据；列出最小缺口。若本轮只核对低一层的文字或规则，另报该层检查结果，并保留原问题待验证，不把授权范围缩小当作原问题已解决。 |
| 撤回 | 新证据推翻原问题，说明观察如何改变判断。 |
| 用户接受取舍 | 用户知情后保留现状；这不是技术上已解决。 |

新线索若与原编号同一问题且同一目标，可补在原项；独立的新问题才另给编号并按主 Skill 的问题筛选规则处理。不要因目标或标准已经变更而静默改写原编号。

## 结束条件

交付复查状态、实际检查范围和仍未知的条件后停止。发现尚未解决的问题不等于获准自动修复或继续循环；新问题、方案取舍和专业修复由用户或经授权的 analysis／专业入口继续。结果在聊天中简要说明，不自动生成复查报告、结果台账或哈希文件。
