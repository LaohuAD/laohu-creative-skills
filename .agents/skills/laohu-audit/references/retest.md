# 问题复查

只在用户明确要求复查已有编号的问题时，由 `{SKILL_DIR}/SKILL.md` 的“输出问题包并停止”读取。执行者是当前 audit 检查者；本文件让复查沿原条件核对状态和相关保护行为，不负责修复；读完返回主 Skill 同一节，在原编号下交付状态。复查条件不清时按原目标与记录补齐；不因上轮有问题而自动启动复查。

## 保持比较条件

用户已明确授权完成整项改进并复查时，沿用该授权进入本文件，不因入口切换再询问；单独找茬仍不构成修复许可。检查范围依据原问题与保护项，不把完整循环授权理解为无限扫描。

沿用能取得的原对象版本、问题编号、目标、适用条件、实际线索、用户保护项和约定的检查方式。对照当前候选的版本或变更范围，只检查能回答“原问题是否仍在、改动是否破坏保护行为”的材料。原材料或用户目标已变化时标出差异，不拿新条件证明旧问题解决。

用户提供了改前／改后对象但没有旧编号时，可用稳定的段落、元素或行为锚点建立对应，并在本次复查中赋一个问题编号；不要求用户为同一问题补做旧报告。

必要的证据不足时，将状态保留为待验证并指出缺少哪项观察；不把修改说明、作者自述、静态文件存在或单一正向样本当成实测。审查者与修复者是同一人时标记为自查，不能称独立验证通过。

## 逐项更新原编号

每个既有问题沿原编号比较，检查所需的相邻保护行为和相关回归，不扩成全项目审计：

| 状态 | 如何报告 |
|---|---|
| 已解决 | 原条件下问题不再出现，且相关保护行为有证据仍成立。 |
| 仍存在 | 原线索在同条件下仍出现，指出位置或复现材料。 |
| 部分变化 | 分开说明已改善与仍未解决的条件。 |
| 待验证 | 缺少原约定的媒体、运行、接收者或其他关键证据；列出最小缺口。 |
| 撤回 | 新证据推翻原问题，说明观察如何改变判断。 |
| 用户接受取舍 | 用户知情后保留现状；这不是技术上已解决。 |

新线索若与原编号同一问题且同一目标，可补在原项；独立的新问题才另给编号并按主 Skill 的问题筛选规则处理。不要因目标或标准已经变更而静默改写原编号。

## 结束条件

交付复查状态、实际检查范围和仍未知的条件后停止。发现尚未解决的问题不等于获准自动修复或继续循环；新问题、方案取舍和专业修复由用户或经授权的 analysis／专业入口继续。结果在聊天中简要说明，不自动生成复查报告、结果台账或哈希文件。
