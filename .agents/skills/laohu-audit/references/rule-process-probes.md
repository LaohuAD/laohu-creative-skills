# 审查 Skill、规则与流程的第一性原理双向探针

由 [laohu-audit 主文](../SKILL.md) 在审查 Skill、Reference、Prompt、运行规则或工作流时读取，查完将可定位观察、受影响职责与证据层带回主文。

审查规则前先从**第一性原理独立锚定本质标尺**（这能力真正服务谁、做到极高水准到底该是什么样，不预设更严或更发散），再以**当今前沿强模型纯裸跑（A 基线）**为参照做**双面透视**：只查少了什么会把规则越补越厚勒死强模型，只删减不看短板又难以稳定超越纯原生 A——**同时揪出 A 面真缺口与弱抓手、B 面负资产过度限制**，才是高水准规则审查。

## A 面：真缺口、冲突、断链与弱抓手探针（查哪里跑不通、兜不住或赢不了原生 A）

| 探针 | 怎么查 | 差距成立条件 |
|---|---|---|
| **1. 陌生执行者首卡点** | 拿一条真实口语请求，仅凭目标 `SKILL.md` 和明确触发的 Reference 走一遍，找到第一次被迫猜测动作、判断标准、格式或退出条件的位置。 | 关键决策只留充分判断、自然衔接这类空词、或两种都合规的理解会导向相反结果且损害目标；刻意开放给模型发挥的创作细节不算缺口。 |
| **2. 加载前触发 vs 正文兑现** | 先只看 frontmatter `name` 和 `description`，试 3 类请求：**典型请求 / 相邻易混职责 / 偶然提词**；再核正文是否真能兑现 `description` 承诺的每项能力与交付。 | 真实请求漏命中、相邻职责误吞、偶然提词误触发，或 `description` 吹出的能力在正文根本没落点。 |
| **3. 规则冲突与死锁** | 拿同一正常请求同时代入主文、触发的 Reference 与 `docs/runtime.md`，检查是否产生互斥动作、打架的字数/格式要求，或无裁决的停止点。 | 同一真实条件下两条要求不可兼得且无明确优先级裁决（如一边限 300 字、一边强求塞满 5 栏长表与完整参数）。 |
| **4. 真源分裂、倒挂、四层复读与子级残毒** | 追踪共享规则、三层单向依赖、主文/参考/三级子技能/个人偏好四层分工、跨文件链接与下游接口：是否上层反向依赖私有文件？同一套通则是否四处复读？下级子文件是否残留与主文新原理打架的旧枷锁？ | 倒挂依赖、口径打架、四处复读、死链、本地方法依赖外链网页，或主文已松绑而三级子技能/旧参考仍在后台绑架模型。 |
| **5. 殿堂标尺、三态裁决、工作形态、表皮分轨与四元缺环** | 按[三技能协作协议](../../../../docs/governance/triad-handoff.md#3-三技能的检查范围)核对目标、判断、行动和结果，查清纯原生 A 最易失手处；重点核查目标 Skill 有没有先立**本领域殿堂级核心特征与三态裁决边界**、是否匹配其真实工作形态（直出 / 提示词中继须实渲验真 / 规划简报防填表 / 工程）、有没有明确**表皮呈现三分轨与用户固定格式硬契约**（中间态扫读排版、下游洁净定式、终稿原生格式不掺废话）、**核心判断原理有没有被洗出运行态锁进平时 0 加载的 `SOURCES.md`**，以及高杠杆手法是否漏标媒介与体量边界。 | 只会顺字面递钉子或一刀切篡改用户好方向；中继类只评提示词不验实渲；忽略表皮呈现分轨导致中间态文字墙或终稿擅改用户固定格式；运行态只剩旧例步骤或禁词表、换题材失灵；规则缺目标/判断/动作/真感验真或跨形态硬套（交 `analysis` 升维）。 |

> 若目标目录存在可读的 `evals/evals.json`，顺手核对历史高频故障用例与现行规则预期，既防止后续减负误删真实护栏，也揪出与新规则打架的过时用例。

## B 面：过度约束与负资产探针（查什么正在勒死强模型）

| 探针 | 怎么查 | 差距成立条件 |
|---|---|---|
| **6. 原生基线减法与事前数独测试（必查）** | 逐段审视核心条款，反问：**把这段删掉或放宽，前沿强模型纯裸跑（A）会不会在不偏离核心目的的前提下做得同样好，甚至更有灵气？** 同时核查是否把成稿后才该做的细部扫疤硬写进动笔前几十条填字数独，或对非物理硬上限强设死字数牢笼。 | 教授模型早已掌握的常识、微观手把手写死表达、事前微操过密触发雕刻伤气（把算力和思考全耗在合规解题上），留着直接压制原生创造力。 |
| **7. 防呆反噬、双向引力污染与语体传染** | 检查高频否定禁令、审计免责、**旧词禁用黑名单（粉红大象）与反复投喂的示范锚词**、规则正文堆砌装饰引号/冷硬系统架构词传染创作语体，以及前置流程是否允许粗糙原始词直通成稿或把上游简报写成散文详案（双向提示词词面引力）。 | 禁词表反向激活禁区、高频锚词导致跨题复读、冷硬说明书腔或散文简报反向污染下游成品、粗糙原始输入把高级技法拽回俗套，或内部流程词穿透进终端答复。 |
| **8. 上下文膨胀与热路径污染** | 统计一条普通请求实际必读的文件数与总字节，扫描超 300 字混杂多条独立条件的文字墙，以及被塞进必读热路径的垂直特例/维护条文。 | 核心动作被大段防御话术淹没、普通任务被迫背负几十 KB 无关规则，或一个简单判断需要跨 4–5 个文件拼图。 |

## 审规则时的局部对照边界

- **直接给最小改后对照**：规则冲突裁决、明显冗余/负资产删减示例、断链或触发描述校准、缺失退出/硬约束补齐等能从现有目标直接推出的局部修正，直接在报告中给出改前/改后精简对照，并检查首个消费者是否兼容。
- **标明待决交 `analysis`**：涉及多套架构方案取舍、核心职责重新划分、或牵动多个外部 Skill 公共接口的重大改动，列清分歧、保护项与待决判断，按授权交 `laohu-analysis` 定案，不借找茬越权重写整套架构。
