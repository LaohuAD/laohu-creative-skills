# 审查 Skill、规则与流程的实操探针

被审对象是 Skill、Reference、运行规则、工作流或提示词系统时，由 [audit 主文](../SKILL.md#按对象加载方法)读取。把可定位观察、受影响职责和证据层级带回[核实候选并确认差距](../SKILL.md#核实候选并确认差距)。沿本轮授权范围用能检验该作用的探针，定向审查只向直接依赖延伸。明确写出哪些范围不可读、探针不适用或需要行为证据。

| 探针 | 看什么、怎样检查 | 差距成立的条件与界限 |
|---|---|---|
| **1. 陌生执行者能否做下去** | 取一条真实普通口语请求，仅用目标 `SKILL.md` 和明确触发的 Reference 推演正常步骤。记下开始条件、判据、动作、退出和下一步输入，定位第一次需要猜测之处。 | “充分判断”“自然衔接”后无动作/判据，或两种都合规的实现得到相反结果并损害既定作用，足以定位执行缺口。用户或主文明确开放的专业变量，以及能由实际调用的规则确定的分支，保留其开放性。 |
| **2. 冲突、优先级与死锁** | 用同一次请求或状态同时触发主文、适用 Reference 与上位 [runtime](../../../../docs/runtime.md) 条件，写出两条规则各会导致的动作、默认力度和停止点。例如默认给对照的条件与核心未定时的授权边界。 | 同一真实条件下出现不能兼容的动作、优先级或停止点，且执行路径无裁决，才报冲突。条件互斥、上位优先级清楚或只在受影响分支暂停时，按其现有裁决检查。 |
| **3. 加载前触发与加载后兑现** | 先只看 frontmatter 的 `name` 和 `description`。按[入口的三种请求](#区分入口的三种请求)分别测试正向触发、相邻职责和偶然提词。再用实际会加载的正文和 Reference 查承诺产物的生成动作。 | 真实意图遗漏、近邻/偶然关键词误合、正文无法兑现承诺，都应分别定位。文字不同而意图和处理一致，可归同一入口。静态对照只证明可解释性，宿主实际调用另查。 |
| **4. 必读负载及埋没条件** | 沿普通请求枚举必读文件并去重，记文件数/UTF-8 字节。找 300–500 字以上混入独立条件的段或横跨五个文件的拼接，检查执行者能否找到关键动作、分支或停止；核对限制是否挤掉先要做的事。 | 具体动作或分支被埋、必须跨多文件拼全且没有可追路径，属于有据差距。字节、段长或否定词数量只用于找风险；职责清晰并按需加载的专项可有必要篇幅。 |
| **5. 真源分裂和消费者断链** | 从共享措辞、引用和中间产物追到实际读者。核同一条件的多处版本，核 Reference 的触发、判断用途和返回位置，再让后一步消费该结果。 | 有口径漂移、实际引用失效、输入或返回未定义导致职责落空，或中间产物实际无人使用，分别定位。仍有效的带锚点摘要、兼容入口和处于真实分支的不同动作应保留。 |
| **6. 现有评测与历史故障** | 仅目标存在且本轮可读 `evals/evals.json` 时，用相关关键词、旧接口和历史故障定位用例，核输入、预期、正文对应分支和明确保护动作。 | 旧预期与有效规则相抵，或真实高频失败只剩抽象口号且当前路径没有可执行动作，才报告。用例存在、预期写得好或一次通过只证各自范围；未获记录不猜测频率，缺失/不可读取如实记限度。 |

### 区分入口的三种请求

- **典型请求。** 用真实对象和状态，请执行者完成目标入口当前承担的动作或结果，检查能否命中。
- **相邻职责。** 固定同一对象和状态，只把用户所需动作或交付改成材料可支持的一项邻近业务职责。看入口能否排除它或交给有该职责的流程；若材料无法核实可比职责，就标出该项未覆盖。
- **偶然提词。** 另取所求动作明确无关、材料中恰好出现关键词的一条请求，核实引文或关键词不触发。相邻职责和偶然提词分别判断，不能用两条无关请求替代相邻职责检验。

按探针 3 带回每条请求的实际意图、加载前判断及相应原因，再核正文会不会兑现目标承诺。

遇到新旧语义、力度、例外或运行方法闭合有疑问，按需读[语义对照](../../laohu-evolution/references/rule-expression.md#更新规则前按语义对照)、[确定规则措辞](../../laohu-evolution/references/rule-expression.md#确定规则措辞)或[本地闭合](../../laohu-evolution/references/rule-expression.md#让运行方法在本地闭合)，回到对应探针核对真实规则和调用。影响层级依 audit 主文判定。

## 审规则时的局部对照边界

适用条件按[报告内局部对照](../../laohu-evolution/references/rule-expression.md#对已确认差距做报告内局部对照)判断。局部规则的正确处理能由现有决定推出时，可给最小改后条款。例如强制字样被写弱、已有条件却无触发/退出动作、能定位正确目标的断链、埋在长段的条件，或上位优先级已明的内部冲突。对照后查新条件和首个消费者，结果归当前问题包。

多条可行架构需取舍、核心职责要变、多个外部 Skill 接口受牵动或领域方法未决时，列出分歧、保护项和待定判断。按授权交 analysis，已能独立处理的局部继续。
