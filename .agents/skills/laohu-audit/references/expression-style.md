# 已确认问题的表达方式

由 `{SKILL_DIR}/SKILL.md` 的“表达已确认的问题”在问题已确认、准备写问题包时读取。执行者是本次 audit 检查者；本文件只把既有观察和目标差距写得直白、有质问感，不负责发现或确认问题。读完返回主 Skill 的“表达已确认的问题”，检查通过后再进入“输出问题包并停止”；表达不改变问题状态、排序、证据范围或授权。

## 从证据找到锋芒

专业缺口的锋芒来自指出执行者被迫补造的具体工作。确认某项能力承诺了怎样的结果后，检查主文及全部直接依赖是否给出达到该结果所需的材料来源、筛选依据和具体动作；只有这些内容确实缺失，且因此无法执行或验收，才报告方法缺口。说明缺少了哪一步、不指控作者动机，也不预测传播结果。若方法实际在 Reference 中，撤回这项缺陷，不能为了保留狠话忽略反证。

先锁住四个已确认事实：具体位置、材料中的实际观察、对应的已知目标、两者之间的差距。锋芒只从这条关系里来，不从作者身份、猜测动机或审查者情绪里来。

优先抓材料自身最清楚的落差：

- 前后两条要求互相打架；
- 明确目标说要做到什么，实际对象却显示了相反结果；
- 流程某一步跳过了它承诺要完成的动作；
- 标题或说法作出一种承诺，实际内容交付了另一种东西。

默认审查立场严苛、直接、有判断：不替作品找台阶，直接点出“材料表现了什么、目标要求什么、差距在哪里”，再把追问落到已确认的差距。语气可以尖锐、不客气；讽刺或反差只在能让矛盾更清楚、且符合用户语气时使用，不要求每项都挖苦。只有直白问句却没说清具体差距仍不够；“毒舌”标签、问号和形容词也不能替代判断。不要加安慰铺垫，也不要为显得严厉夸大问题。事实和目标差距已经坐实时，直接下结论；不为假设性例外添加“可能”“似乎”等缓冲词，只有会改变判断的反例或缺失事实才需要核对。

同一处已确认的冲突可以用中性陈述指出两项要求无法同时满足，再追问应按哪项执行；若反差本身能让矛盾更清楚且符合用户语气，也可以用冷幽默强调冲突。两种方式都须保留同一事实和问题；后者是可选修辞，不是验收要求。不同对象要重新抓自己的矛盾，不复用固定口头禅。

锋芒靠选准矛盾，不靠添形容词、感叹号或问号。先用标题或首句说清哪个要求撞上哪个事实、哪个目标落空或哪一步没执行，再把追问落到这一处。可以变化句式：直接指出矛盾后追问、用一句短标题后给观察，或把关键承诺原样摆出来再问；不把每项都写成同一种“既然……为什么……”模板。

## 拆穿空话

当已知目标要求实际可执行，而被检查文本只写“深入分析、确保质量、加强重视”等抽象口号时，核对它是否交代检查对象、动作、产物或通过条件。缺项只有在确实让目标所需的下一步无法执行或验收时才构成问题；不要把所有简短口号都自动判错。事实已经支持“要求没有给出动作”时，可以直说“这就是空话”；这评价指向文本，不是作者。

只有目标确实要求执行者作判断或处理，而文本缺少必要对象、判据、动作或交付，且因此无法完成下一步时，才指出空泛要求造成的具体执行缺口。冷幽默可用于强调“要求很多、实际动作缺失”的已确认反差，但不是必需动作；不得复用固定话术，也不能在材料不支持时套用该判断。

## 语气边界与交付前检查

默认保持审查立场严苛、结论明确、不替作品护短：直接说出可证实的落差，不用安慰话或长篇铺垫磨掉判断。锋芒可以由明确的否定结论、短促反问或有依据的讽刺产生；讽刺不是每项问题的必做动作，问题包也不设“必须挖苦”的风格配额。默认问题包用自然段，编号、位置和观察可短注。证实的问题要明确说出，不因根因未知或假设性例外把它写成待确认。不要靠固定三段、重复反问或口头禅伪装锋芒。质问感不等于人身攻击：不要评价作者是否专业、聪明、用心或故意，不把具体差距升级成“作品失败”“系统崩坏”或普遍规律，也不替观察补上未证实的原因、后果和严重性。

冷幽默、反差或网络口语是可选修辞。只有它准确复述材料中的矛盾、适合当前对象和用户语气且不遮蔽问题或抢走主要信息时才使用；笑点本身可以帮助读者看清落差，不为显得尖锐而造梗，也不固定重复某种口头禅。用户指定中性、正式或其他表达时照做，不能因此放松问题确认标准。

提交前逐项确认：

1. 标题、陈述和追问里的每个事实都能回到已经检查的材料。
2. 追问是“为什么出现这个已确认差距／哪一步失效”，不是“这里是不是有问题”。
3. 修辞没有新增问题、夸大影响、猜动机或攻击作者。
4. 语气服务于读者理解；立场清楚、问题判断直接。若用了幽默或讽刺，确认它没有遮蔽差距或抢走主要信息；没用讽刺不构成缺陷。
5. 用户要求其他语气时已调整表达，事实与问题边界保持原样。
