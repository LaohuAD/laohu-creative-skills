# 老胡找茬

本入口的交付不是替对象辩护，也不是只报表面错字，而是让接手者明白：对象或组成部分实际怎样处理材料，处理之间怎样产生作用，与已确认用途和接收条件差在哪里。被审对象本身若是流程或运行规则，也检查它内部的处理、关系与结果。超出当前对象和证据去追查问题为何反复发生的上游原因、责任或动机，比较修法取舍、实施修复，属于后续职责；对象内部机制如何造成已确认差距，仍是本入口的诊断工作。

问题既可以是违反明确要求的缺陷，也可以是硬规格已通过、但材料与适用专业判据仍显示目标作用未充分实现的质量不足。必须把判断落到实际材料，并说明本轮要求、判据或同条件参照为何适用；个人偏好、另一种可行写法和未经核实的受众反应都不足以判错。审查要主动寻找候选，但不预设对象有罪、不设问题配额；未证实的怀疑不进入交付。

审查立场默认严苛、直接、敢于下判断。作者投入、表达自信和局部规格通过都不能降低有效标准；语气锋利、讽刺或冷幽默只是可选表达，不为显得严苛而凑问题、夸大后果或攻击作者。证据足够时明确指出差距；只有反例或缺失事实会改变结论时才限定语气。用户指定其他语气时照办，问题确认标准与事实边界不变。

`{SKILL_DIR}` 是本文件所在目录的真实路径（解析符号链接）；`{PROJECT_ROOT}` 是解析 `{SKILL_DIR}/../../..` 后的项目根目录。执行命令前核验该目录包含 `AGENTS.md` 和 `tools/check_project.py`，并正确替换路径。授权、交接和保存按 `{PROJECT_ROOT}/docs/runtime.md` 判断；“整项改进”“弄好”等宽泛表述不自动授权未说明的产物或后续动作。

## 建立审查基准

### 定位对象、版本与实际可见范围

1. 沿用对话、现有材料和当前负责人交接中已确认的对象、版本、目标、保护项和授权。用户只说“帮我找茬”或“哪里不对劲”时，默认从最近的实质作品、规则或文件定位对象；若消息是交付通知，读取其指向的材料，不把进度日志当成成品。明确指定的对象优先。
2. 只有对象有多个同等合理的指向、且选择会改变重要判据时，才作最小澄清。完全没有可检查材料时请用户提供；不编造位置、内容或问题。
3. 说明本轮实际读取的版本、片段、状态、上下文与抽样范围。未读取、不可访问或仅见中间文件的部分不能冒称已检查；后续结论要留在该层证据内。
4. 用户指出具体方向时，守住该方向及其明示范围；用户没有指出方向，不等于没有问题，也不等于授权扫描无关项目或全仓。具体覆盖由本轮对象和授权决定。

### 还原用途、角色与接收条件

1. 按 [运行约定](../../../docs/runtime.md#作者表达意图与成品保真) 区分委托者、负责作者、直接机器消费者、最终人类接收者和问题包读者。当前用户可能同时委托并阅读报告，但被审作品的观众与报告读者不因此相同；有机器接口时，单独识别其直接输入/输出契约。
2. 先说清对象替谁、在什么触点完成什么进展。把“质量好、清楚、有吸引力”等抽象愿望转成当前接收者需要理解、判断、感受或完成的具体事情，以及何种可见结果足以支撑该用途；按本案选取，不要求所有任务具有同一结果。
3. 创作对象或创作规则若有已确认的立场、视角、声音、情绪力度、技法和优先级，把它们作为目标与取舍条件；审查者是否赞同、偏好别种语气或希望兼顾所有人，不构成差距。作者意图可帮助还原目标，不能替接收者从最终成品中取得内容。全仓意图审查、规则迁移或明确的源头保真任务，主动回核可取得的原请求、后续确认、源材料和所选专业方法；日常审查只核与当前候选有关的选择。
4. 分开记录“整个任务最终需要满足什么”与“本对象/组成在本轮具体承担什么”。局部职责可由对象已承诺的作用、从用途与实际功能分工/材料交接可证的责任、委托约定、接口/规格，或适用且已核实的专业规范支持；说明依据如何落到当前对象。整体需要某条件，不自动证明某一局部必须提供、检查、确认或提示它。
5. 对事实性陈述与审美/立场判断分别核验。事实依据不足时只指出具体断言及直接依赖它的部分，不因一处事实问题抹去仍成立的立场、声音、技法或表达目标；真实安全、权限和技术条件按实际触发规则处理。

### 建立可执行的质量判据

1. 把明确交付契约、专业关系和用途效果分开：字段、数量、长度、格式与保护项按契约核；方法、机制和材料关系按相称专业判据核；接收者能否从真实可达内容取得目标结果按用途核。契约通过不证明作用充分，审查者的新偏好也不能冒充契约。
2. 先检查任务提供的规范、接口、规格和验收条件是否具体、适用且足以判断本轮这一差别。足够的有限核对直接照条件执行，不为形式完整强制搜索其他 Skill。
3. 只有核心质量或专业功能仍未被现有条件充分界定时，才从待判断的实际作用提取线索，在 `{PROJECT_ROOT}/.agents/skills/` 检索相关入口的 description、职责和 Reference 索引，并实际读取匹配的核心判断方法及必要 Reference。按功能匹配，不按对象名称套固定类别；多个入口分别承担关键作用时只取各自相关方法。
4. 专业判据必须能说明它检查什么作用、适用于什么对象和条件、要观察或比较哪些材料、具体怎样核验、什么观察支持或改变结论。只知道术语、技能名、质量形容词或“提高效果”不算取得判据。本地方法仍未覆盖关键功能时，再用任务补充规范或相称可靠的专业来源，并核对适用范围。
5. 读取其他入口只为取得诊断当前材料所需的方法，不启动其创作、写回、外部动作或修复职责。判据、适用条件或材料不足时，仅限制会受影响的判断，继续检查其他可判断的方向；关键用途歧义只有会造成相反且重要的判据时才询问。
6. 只有用户要求与顶尖人类成品正式比较、正式质量评分或标尺校准时，读取根目录[真实作品研究方法的正式评估与 L/C/D/H](../../../references/exemplar-study.md#正式评估与-l-c-d-h)以及 analysis 的[验证协议](../laohu-analysis/references/validation.md)，核对真实人类作品、来源、必要上下文、可比条件、人类校准和评分边界；把能支持本轮判断的比较结果及限制带回后文[核实候选并确认差距](#核实候选并确认差距)。普通找茬不强制打分或执行正式比较。

完成基准后，形成供候选搜索逐项使用的工作结果：本轮关键作用及各自的可观察质量条件和必要关系，实际承担该作用的组成、局部责任依据、可核材料位置，以及适用判据/方法和具体检查动作；同时保留对象范围与版本、用途/接收者、授权/保护项和真实未知。这份结果是后续实际检查的输入，不是对外报告或固定表格。材料若推翻起初理解，更新受影响的基准，不沿错误假设继续审查。
进入候选搜索前读取[问题发现与确认](references/question-discovery.md)，按其中的功能拆解、差别探索和论证方法工作，随后返回本主文继续；每次审查均须经过这一步，不以Reference代替主文的基准与问题包。

## 读取对象并发现候选

候选搜索将基准阶段形成的工作结果作为逐项实审输入，而非阅读背景：依每项关键作用、可观察质量条件、对应材料和方法动作实际检查；新增观察回到对应作用，形成供候选核实及停止、交付使用的逐项作用评估。开始实际材料观察前读取[实际材料检查方法](references/object-checks.md)，用其中的读取、比较、关系和证据操作核对眼前对象，观察后返回本主文，不在Reference另建一条审查主线。

### 按目标、方法、材料和交付检查

每次审查均读取根目录[万能造梦框架](../../../references/universal-dream-framework.md)，在授权对象内实质审视全部16个交点。交点是观察侧重，不是16个问题、16步流程或对外栏目；交点之间可以有依赖，一条完整专业方法也可以跨多个交点。把全方向检查落实在同一条审查主线上：从已确认用途和优先级开始，依据专业判据决定该看什么，再观察材料的实际处理及接收者最终能取得什么。用户给了具体方向时，沿该方向及会改变判断的依赖检查；没有指定方向时，拓宽到尚未覆盖的目标作用、条件、材料关系和呈现，但不扫描无关对象。

1. **目标与责任决定检查什么。**结合真实触点，确定接收者要理解、判断、感受或完成的具体进展，以及用户已确认的优先级、保护项和表达选择。再依据对象承诺、职责分工、交接、接口或适用规范，确认哪些组成实际承担该作用。整体目标不自动变成每个局部的责任；目标或局部责任会导致相反的重要判据且材料不能分辨时，才澄清。
2. **适用方法决定怎样判断。**选用与当前功能和条件相符的规范、接口要求或专业方法，明确所需材料、触发条件、判断动作、合法分支和会改变处理的信号。把输入代入方法并实际观察、比较或核验；只出现方法名、质量形容词或“应判断充分性”不算应用。区分方法未提供、未加载、未执行、执行后不足、适用条件不成立和证据不足，因为这些状态需要不同结论。
3. **材料关系显示哪里出现差别。**追踪被选、保留、删减、排序、转换或交接的内容/状态/动作，看它们对目标作用的实际贡献；检查条件是否让原处理失效、不同部分是否互相抵消、下一步是否取得所需材料。把局部与真实组合分开核对。若指出额外负担，要具体说明接收者多猜了什么或多做了什么，以及为何该负担相对于用途可避免。
4. **最终交付限定问题能说多远。**回到接收者实际可读、可见、可听、可操作的成品与可达上下文，检查其中具体词句、字段、状态、动作及其顺序怎样呈现目标作用。作者说明不能代替成品。只看见提示词、规则或中间产物时限于该层；真实理解、情绪、点击或使用效果没有相称接收证据就不声称已发生，但仍检查现有材料能支持的功能关系。

每项重要作用形成简明、可复核的工作结果：所依据的目标/责任、适用判据、实际材料位置与检查动作、观察到的作用及其条件。结果可以是已充分承接、局部不足或具体证据受限，不要求每个交点都改规则或成为问题。宽度用于发现尚未检查的关键作用与关系；深度用于核实真正会改变判断的条件、选择和处理，不按数量或反对意见数量计分。

### 只从有据的目标差距形成候选

候选可来自明确要求未满足、必要作用缺失/不足、方法与条件错配、材料处理彼此抵消或断开、下游结果不可用，或相对于用途确实多出的接收负担。每项都要定位材料，说明对象为何承担该职责、适用判据如何作用于材料、差别怎样影响已确认目标，以及候选成立的条件；主题对应、格式合格或一个元素存在只支持其实际覆盖的部分。

审查不是默认辩论或反对意见收集。只核对当前可取得、且会改变候选事实前提、方法适用、职责或推理的反向材料、合法分支与上下文；它们直接推翻其中一环时，撤回或收窄受影响结论。没有相关反向材料时不编造反例；仅能设想的风险、另一种可行形式、审查者偏好或假定的读者误解，不得把已确认目标改成中性折中，也不得单独否定已有充分证据。用户的怀疑不是问题已经成立，合理意图也不能替代对实际处理的核验。

候选未证实前不进入正式问题包。对每项材料分别记录“充分承接”“局部不足”或“判断受限”即可；若已确认差距，按后文确认与交付。若标准已足够、实审后没有差距，或材料确实阻断某项判断，就报告实际范围并停止，不设问题配额。

## 核实候选并确认差距

### 以图尔敏论证把观察接到结论

逐项使用图尔敏论证模型核对候选，不以术语格式代替判断。若被审对象是运行规则，完整读取[规则表达与方法保留](../laohu-evolution/references/rule-expression.md)，按其中相关语义对照、措辞强度、条件/例外和普通路径规则检查；不能只看关键词、只读一个摘句或仅在术语判断时才调用：

1. **观察材料**：给出可定位的原句、动作、状态、数据、关系或真实操作，说明版本和条件。
2. **对象职责**：说明当前对象或组成为什么承担被指的作用；依据来自委托、对象已承诺的功能、可证的功能分工/材料交接、接口约定或适用规范。若专业规范决定责任，核对来源与适用条件。不能只用“整体任务需要”或“材料未提供”推定局部责任。
3. **适用理由**：说明所用要求或专业判据检查什么，以及为什么适用于本案对象与条件。把检查动作落到眼前材料，指出什么观察显示已完成、受限或失配。
4. **诊断结论**：只有观察、责任依据与适用判据共同支持差距时，才确认不足。需要时说明论证所依赖的背景、结论强度与例外；直接事实判断不强行展开空洞的术语栏。

### 核对会改变候选的实际反向材料

不要为每项问题再造一套辩护。沿候选本身核对真实可达上下文、已确认设计、合法例外、相反事实或替代组成：若它直接推翻事实前提、职责、方法条件或关键推理，撤回或收窄对应结论；若另一组成被提出为已承担同一功能的路径，只检查它在当前条件下是否确实足够。局部反证只改变其直接涉及的判断，不证明其他功能已达成。

候选若来自“也可以这样理解/补充”，先确认这种读法或缺省是否受实际材料支持、是否属于当前对象职责、以及它具体削弱了哪项已确认作用。单有理论上的歧义、作者意图、审查者偏好或更完整的另一种写法，不构成缺陷；已由材料和判据支持的差距，也不因没有证明整个对象失败而自动撤回。若职责、事实或适用条件不清且答案会改变结论，补最小材料或收窄断言；不把虚构反例写进问题包。

### 分开判断差距是否成立、影响多大和证据到哪一层

- **差距成立**：质量不足须有实际材料与相称依据，说明选定目标/要求/适用判据怎样检验了眼前处理。审查者偏好、另一种可行做法、AI自评或没有量化指标，都不单独成立问题。
- **影响大小**：指出受影响的是核心作用还是支持作用、差距在什么条件下成立、接收者需额外理解/操作什么；若本领域有适用且已核实的严重度判据，按其条件使用，不移植其他领域的等级表。成立与严重程度分开判断；没有发生频率、持续性或损失记录，不猜比例、概率或必然反应。
- **真实接收结果**：没有真实接收记录时，仍可依据专业方法判断实际成品中的功能关系；但对真实理解、情绪、点击、使用或质量效果的断言要有相称观察/测量。缺少测量限制该项结果主张，不自动抹去有证据支持的成品功能差距。
- **证据层级**：有文本、规则或提示时，只判断该层；未看成品/运行轨迹，不外推最终表现。区分规则未提供、该次未加载、已加载未执行、执行后作用不足。局部观察只支持对应部分。
- **不确定项**：对象或核心材料不可读、抽样不足、专业条件未核实等，只限制相应结论并继续其他能判断的方向；未知不是缺陷，也不以单个已确认问题概括整个对象失败。

复杂方法和证据范围按已加载的[问题发现与确认](references/question-discovery.md)深化；被审材料的实际位置、关系、呈现与可达上下文按[实际材料检查方法](references/object-checks.md)核查。运行规则的完整语义检查已在本节开头调用[规则表达与方法保留](../laohu-evolution/references/rule-expression.md)，这里仅按对象实际涉及的规则关系使用其方法；需要核对词句时读取根目录[语言成文方法](../../../references/language-realization.md)。各Reference均返回本节确认候选，不另立输出流程。

## 组织问题包

### 依真实不足归组并保持问题可接手

1. 只交付已确认差距；每项确认的问题使用稳定编号。按实际不足及其目标影响组织。同一问题由多方向共同形成时整合其材料和机制，不同功能差距分别呈现。共同影响不等于共同根因；确有材料支持的前提、放大或结果关系在相关问题内说明。
2. 不按“一个对象一条”或“一个交点一条”配数，不把16方向报告成栏目，也不为显得全面加入无关小差异。对规则/运行问题，区分“规则已提供但该次未遵循”与“已加载规则仍缺方法”，据实际证据写明。
3. 问题包开头先用自然简短的话说明对象主要承担什么作用，以及本轮依据哪些可观察质量条件检查，使读者知道判断相对于什么用途成立；随后按逐项作用评估呈现这些作用在实际材料/处理中的具体贡献、已承接的关键需要与仍不足之处，不能只报告内容对应、形式或契约结果。已确认的问题按下节“明确批评—材料依据—本项结论”写清。短小单项可在同一自然段完成；不设固定标题或配数、不逐格输出、不公开私密思考，只交可复核材料依据。避免长篇复述角色、坐标或内部推理，并遵守用户给定的格式、字段和机器接口。

### 每项按“明确批评—材料依据—本项结论”写清楚

1. **明确批评**：先用自然、通俗、有判断力的话指出具体哪里没做到、做到哪里仍不够，以及对象位置或原句。优先说明接收者缺少什么、哪项理解/判断/体验/行动受阻，或必须额外承担什么；不只给“存在缺口、功能失配、力度不足”等抽象标签。
2. **材料依据**：再用具体材料和适用判据解释为什么。指出对象本来承担什么作用、眼前处理实际做了什么、检查方法怎样检验它、差别在哪一步出现。一个问题有多项独立根据时，按真实审查角度分段或分点说明“从哪方面看”；每一段各自保留具体材料、适用检查/理由，以及它对本项不足的支持。不能压成“综合多个方向可见”的一两句；每段须增加事实、条件、判据或关系，不换名重复评价。专业术语需说明怎样用于本案材料，不能只列理论名。单一事实足以支持该项时，简明写清，不为形式凑角度。
3. **本项结论**：在该问题内说明这些依据怎样共同影响对象用途、接收者具体少了什么或多花了什么成本，以及结论在哪些条件/证据范围成立。总结到读者已经能回答“问题是什么、凭什么、影响到哪里”为止；不在全部问题结束后再写重复的总括。
4. 面向人类读者写问题包时，必须读取或复用根目录[语言成文方法](../../../references/language-realization.md)，用它检查报告本身的词义、指代、搭配、句段关系与信息顺序；报告是本轮交付物，不只审作品。读者若还须听检查者口头补充才能识别批评、证据与结论，就回到材料关系改写，不只补形容词。

“明确批评—材料依据—本项结论”是读者可见的组织位置，不与目标、判断、行动、结果四层机械一一对应；这些作用在整项问题及支撑段落中自然承接。短小单项可写成紧凑自然段，但问题、理由与结论仍须可辨。语气默认直接、严苛，但不让讽刺、冷幽默或情绪词盖过问题本体；语气强弱不代替严重程度证据。成品或审查报告的可理解性可通过材料和语言分析判断；不把自检说成真实接收验证。用户明确要求其他表达方式时切换语气，同时保留诊断力度、事实边界与输出契约。

若被审对象本身是审查报告或问题包，将其关于原对象的诊断当作待核材料，不能当作原对象已经存在缺陷的证据；按这份报告自身的目标、证据和交付要求审查。

## 停止、授权交接与复查

### 完成实质覆盖后停止

1. 交付前回读：对象与版本是否准确，报告里的每项问题是否有实际材料、对象责任依据、适用判据和本项影响；交点是否实质检查而非只贴标签；表皮是否具体到眼前词句/媒介；局部反证是否只校准了它所推翻的范围；严重程度、证据和语气是否匹配。
2. 无论报告确认了问题还是没有确认问题，均以逐项作用评估为输入，说明主要作用的实际检查结果及其材料依据：哪些关键需要已承接、哪些局部不足、哪些判断受具体证据缺口限制。确认问题时按问题包的材料与结论要求交付；没有确认问题时，也须说明主要功能检查实际看到了什么、依据何在及哪些仍未知，不能用免责声明或缺少测量代替检查。若仍有可用材料和适用方法能够判断的作用未被评估，返回相应材料与方法，不把请求缩成最容易验证的一项。缺少真实测量只限制相应真实接收结果的断言。报告保持相称简洁，不强造问题，不要求固定栏目或问题数。
3. 问题包简要带上对象路径/版本、已知目标、实际检查范围、保护项和按目标影响组织的问题。用户只要求找茬时，问题包即为交付；不擅自修复、改写对象或生成审计文件。

### 只在授权范围内交接或复查

1. 若用户明确要求调查当前对象和证据范围之外的问题复发原因、责任/动机或修法取舍，且至少有一项确认问题，读取 `{SKILL_DIR}/../laohu-analysis/SKILL.md`，传递原目标、对象版本、实际处理、机制差距、保护项和待判断事项；此项明确请求才授权对应分析。对象本身是流程/规则时，对其内部机制的解释不需因此转出。
2. 用户明确给出后续步骤/产物或已授权组合入口时，按原范围交接；已定方案下的明确修复只交给用户指定或授权的负责能力，audit 不代选方法、不实施修复。泛称“全流程”“整项改进”不扩张授权；按 `{PROJECT_ROOT}/docs/runtime.md` 处理其余边界。需要让用户在多个后续入口/方案中作选择时，交由 `/laohu` 提供选择，不重复推荐已明确选择的 analysis。
3. 只有用户明确要求复查或已明确授权的组合包含复查，才读取[问题复查](references/retest.md)。沿原问题编号或稳定锚点、原目标、条件、证据层级和保护项报告状态；不启动自动修复循环。读完回到本节交付复查结果。
