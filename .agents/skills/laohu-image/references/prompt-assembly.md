# 提示词整合

由 [laohu-image 主文](../SKILL.md) 在来自多个视觉维度的决定需要合成，用户提出相互竞争的条件，或用户要求精简、重排和修订提示词时读取。新图或明确要求完整成品时，它把已定内容编成一段完整、可想象的提示词；若资产交接是既有基础 ID 的状态/局部编辑，则按差异提示词只组织变化与保持条件，不重述基础材质、颜色或身份。完成后返回主文“内容选择与提示词整合”，由主文写效果说明并按两项交付格式返回。简单单主体画面且条件自然兼容时，主文可以直接整合，无需重复读取。

## 先给每项信息定状态

动笔前把信息分为四类，并确认每条信息在最终画面里承担什么职责：

| 状态 | 含义 | 整合动作 |
|---|---|---|
| 用户已定 | 明确指定且必须保留的主体、内容、形式或禁项 | 原意保留；只调整语序，不弱化要求 |
| 用户偏好 | 用户表达倾向但允许实现变化的要求 | 先满足；与硬约束冲突时说明取舍 |
| 开放变量 | 用户尚未决定且委托 AI 设计的部分 | 依据用途、材料与视觉主次补足 |
| 不适用或无关 | 当前画面不存在、不影响观看或无法执行的信息 | 省略；不要为了字段完整而填入 |

材料支持的事实、AI 的设计推断和用户决定不可混为一类。用户给了真实人物、地点或物件时，不以生成提示词为由改动其身份和事实；AI 补充的可见细节只须符合任务范围，不必逐项请用户确认。若两项信息互相竞争，先看哪项是核心关系的支点；用户已定的支点保留，AI 补充的变量服从它。

若输入包含资产规格，稳定身份、选定方向和用户保护项是画面的固定底稿；只改本次获得授权的变量。完整资产参考与具体镜头帧按各自用途处理：前者按资产交接要求完整呈现人物、衣装或地点，后者遵守机位可见范围，同时保留当前视图能看到的身份锚点。人物在剧本中以第一视角出现，不妨碍其完整人物参考图展示全身与脸；反过来，资产全貌展示预设也不能让具体第一视角镜头露出剧本禁止的主角面部或背影。收到资产交接时，由主文按触发条件读取 [图片提示词交接与固定输出](../../laohu-assets/references/image-handoff-and-output.md)，其固定字段与 ID 规则为唯一真源，本文件不再复制资产字段。

## 按观看顺序组织

提示词不是字段清单，而是一次观看的引导：先写关系和落点，再补足让关系成立的视觉条件。服装、道具、场景及穿搭先按主文“方向明确，细节开放”选择必要约束；不要因有字段就补全微观细节。通常按以下顺序写成自然连贯的一段：

1. 主体是什么，数量、状态或外观有哪些关键特征。
2. 主体正在做什么，或它与人物、物件之间有什么关系。
3. 环境提供哪些地点、距离或背景线索。
4. 观者从哪里看，主体在画面中的位置和大小怎样。
5. 光线、色彩和材质如何使主体被辨认或被感受。
6. 需要时补充媒介、画幅、边界条件和文字职责（环境字形、标题或准确可读文案）。

顺序随媒介和核心关系调整：概念海报可先说主体与留白，空间图先说观看位置，肖像先说姿态和面部可见度。结构示例（非专业作品范例）：“人物望向画外，左侧留白承接视线”，比“人物在右、留白、看向左”的并列清单更能保住关系。只保留会改变生成结果或帮助模型维持关系的信息；镜头数字、流派名和画质词不能替代画面指令。

专业名词承担标准命名与信息压缩，可见证据负责把它落到画面，二者互补时都保留。写“Rembrandt光”后补“暗侧脸颊留一块小三角亮区”；写“顶视”后补“桌面从正上方呈平面，杯、刀叉各自分开”；写“负空间”后补“人物目光前方留出一块低细节空处”。证据若与术语不符，就以目标画面为准改正术语；只删误用、不准确、互相冲突、无关或同义堆叠的词，不能因为具体描述已解释术语就删掉准确且有用的名称。

按当前观看尺寸选择资产细节。完整身份信息不等于每一项都要挤入单帧：写入本机位可见且影响辨认的脸型/发型轮廓、服装特征、物件结构或场景锚点，并确保描述足以让独立使用的提示词重现它们。仅在用户精控、已确认资产复现或剧情辨认确实依赖纹样时，保留其已定部位、比例、色彩与可见尺度；初次方向设计只描述纹样大类或整体装饰感，不新增精确位置和形状。若景别容不下细纹，就保留较大的剪裁、色块或位置特征，不把不可见小细节说成画面重点。不要为“精致”自动给所有表面增加装饰，选择应沿用用户/资产已定方向，或服务观看关系。

场景资产给出的坐标与固定物位置先在世界空间中保持，再换成当前镜头的可见关系：从哪个入口看、物体落在观察者的哪侧、前后间距、遮挡和尺度参照是什么。收到既有基础场景的视角状态时，只把观察点、方向和必要取景写成差异，保留空间身份锚点，不重设整套环境；基础参考未显示的区域不写成已确认结构。提示词不只贴坐标数字，也不在当前视图列出画外/被遮挡物；需要精确布局时，把坐标规格与平面图、场景参考图或三维底图共同使用。文字描述能明确关系，不能保证生成模型严格遵守每项测量值。

## 处理冲突与不确定项

先检查硬约束是否真互斥，再检查自己补入的变量是否破坏核心关系。多数冲突可通过调整位置、尺度、朝向或明暗层级解决；先改次要变量，保持用户已选的画眼。只有两项明确要求无法并存、且目的不能推导优先级时，才分别说清结果并询问取舍。

常见冲突需要落到画面后果：

| 条件组合 | 需要判断什么 |
|---|---|
| 全身与面部特写 | 哪个信息必须可见，是否改为更宽景别或分成系列 |
| 主体正面与身体背向镜头 | 观者需要看清脸还是动作方向 |
| 强逆光与衣料纹理清晰 | 轮廓氛围与表面细节各自的优先级 |
| 密集陈列与大面积空白 | 空白承担主体间隔、观看停顿、表达缺席，还是用户明确要求的后续版式 |
| 写实摄影与平面剪纸质感 | 采用哪种作为整体媒介，另一种是否只用于局部 |

表中是冲突识别的结构示例，不代表这些组合永远不能实现。用户有意要求抽象、拼贴、并置或不合物理常态时，不擅自把它“修正”为写实因果；确认该反差是表达选择后，将其写成清晰可见的画面指令。

## 省略与边界

删去不存在、不适用、重复或不会改变观看读法的变量。没有人物不写服饰，没有透视空间不写焦距；画内文字依主文“能力范围与交付边界”区分环境文字和需阅读的指定信息，清晰程度本身不决定分流。用户明确要求全画面禁字时按硬约束处理，水印另按用户要求。

负面提示只针对具体且可能发生的错误，例如多余手臂、用户明确禁字时生成字符，或背景抢主。避免堆叠“不要一切”式限制、互相重复的同义词和与任务无关的通用质量口号；必要限制要写清它针对哪个主体或区域。

视觉变量按目标取舍，不把景别、构图、机位、影调、色彩与媒介全部塞进一段提示词。准确术语与具体画面证据不是重复项；同义术语堆叠、错误命名或相互冲突时才删减。若术语改变不同维度，则分别写清职责，例如“高机位、光轴略向下、地平线保持水平”分别说明观察位置、俯仰和横滚。组合有冲突时先检验可见结果能否同时成立，再删减或定向询问。

## 整合后返回

先检查主体、动作、位置、光线和背景是否能共同实现画眼；确认固定决定没有弱化，AI 补充有取舍依据，省略项确实不改变画面。不可解的用户冲突只暂停受影响部分。新图或明确要求完整成品时，最终提示词是一段完整、自然连贯、可直接复制的可视描述；既有资产状态/局部编辑默认只写清差异与保持条件。每条提示词各放在独立代码块中，资产 ID、适用范围和解释留在块外；文本不代表图片已经生成或检查。
