# 飞书云文档创作与原生排版

若宿主直接命中本配置，先回 [laohu-writing 主文](../../SKILL.md) 确认任务、材料、授权与交付媒介。只有飞书是本轮交付、排版或写入目标时才加载本专项；如果飞书链接只是拿来做参考资料，由父级只按最小读取范围取材，成稿仍走用户实际指定的媒介。需要新手教程或操作手册结构时，由父级同步叠加教程模块，本专项负责把内容关系落成飞书原生块与可读版式。

## 一、先定本轮交付边界，严守聊天免运维门控

| 本轮实际目标 | 怎么处理与返回 |
| --- | --- |
| **聊天里先看飞书草稿** | 按飞书阅读习惯起草完整文稿与图文安排，在聊天交付正文。**材料已齐时彻底跳过 [feishu-ops.md](../../references/feishu-ops.md) 及一切远端连接、账号检查、安装与写入动作** |
| **只读飞书资料，在聊天里出稿** | 仅按最小只读范围读取飞书正文、图或附件，完成后回写作流程，绝不顺手申请写权限或改原文档 |
| **修改指定飞书文档** | 核实真实版本与权限，在获准范围内精准差异编辑，保护其余原文、原图与评论，交付文档链接与实际验收范围 |
| **新建并写入飞书文档** | 确认或沿用标题、目标空间/文件夹与企业归属，核验写权限后创建、写入并读回验收（未指明具体位置且已有明确默认个人空间时可沿用并如实说明归属） |
| **只优化已有飞书排版** | 逐字锁住已定标题、主张和原话，只调整原生块结构、层级与图文版式；内容本身有疑义交回父级 |

帮我写进这个文档这类明确表述已涵盖相应写入授权；新建、修改、公开分享和通知成员仍各自按用户本轮授权判断。仅当确实需要连接飞书、读远端、传图片、新建或差异写入、或恢复上次未明写入状态时，才按需加载 [feishu-ops.md](../../references/feishu-ops.md)。缺会改变远端目标的链接或企业归属时，只问最小缺项，不依赖它的起草和图文设计照常推进。

## 二、把内容关系映射为飞书原生块（不拿假格式凑数）

优先沿用用户或团队已有文档规范。无指定样式时，保持中性正文打底，用少量**加粗配合浅黄色行内底色**标出最关键的动作或决定，蓝色留给链接；绝不单靠颜色传递唯一语义，颜色之外仍靠层级和文字说清主次。

| 内容关系 | 飞书原生块写法 | 必须守住的阅读与协作能力 |
| --- | --- | --- |
| 主标题、章节与子节 | 文档标题与真实 heading 层级（按真实从属逐级递进） | 大纲目录自动生成与跳转；绝不用放大加粗的普通段落冒充标题；不擅改锁定标题 |
| 关键动作、决定或核心条件 | 完整语义短语加粗，极少数最关键处叠加浅黄行内底色 | 重点放回邻文连读完整，绝不把代码、字段名或命令只高亮一半 |
| 有先后依赖的操作步骤 | 原生有序列表（每项一个可执行动作，说明与子项按层级缩进附属） | 保持自动编号、跨图跨备注后正确续号与嵌套；绝不手打 1. 2. 冒充有序列表 |
| 并列选项、材料清单或核对表 | 原生无序列表；需逐项打勾跟进时用待办/复选框 | 支持逐项勾选、增删与调序，不把并列关系强写成假顺序 |
| 紧邻正文的旁注与补充解释 | 原生引用块 | 真实引用结构，不用引号或竖线字符模拟；引用块格式不代表内容是外部引文 |
| 必须停下来看的重提醒 | 原生高亮块（Callout），仅放影响选型、费用、密钥安全或失败恢复的关键提醒 | 与正文角色鲜明区分；绝不把每条小提示或完成标志全装进花花绿绿的高亮框 |
| 同尺对比、参数字段或方案表 | 原生表格（列名准确对齐比较维度，长篇解释留在表外） | 单元格直接可编辑、列数克制，绝不逼读者左右长距离横滚读步骤 |
| 简短双方案对照或图文并排 | 短内容可用原生两栏（三栏以上须有明确同屏对比收益） | 栏目标识清晰、读序自然；长顺序操作教程坚持单栏，核查窄屏折行顺序 |
| 命令、配置、完整提示词与原值 | 原生代码块或行内代码 | 完整保留原字符、缩进、换行与一键复制能力；绝不把代码截成图片 |
| 外部入口与文档内章节跳转 | 清晰锚文本超链接；篇内跳转在块落地后以真实 heading ID 建立 | 锚文本与真实目标一致；绝不把本地 Markdown 预览锚点当飞书真实块 ID |
| 真实截图、信息图或流程图 | 原生图片或适用的可编辑画板，附准确锚点与图注 | 真实可访问资源、原比例清晰显示，正文仍保留脱离图片也能懂的文字路径 |

按内容真实需要选用，绝不为显美观把所有组件堆满一页。涉及远端写入时，将富文本原生块接口与 Markdown 导入支持分开核对——凡转换器会降级丢格式的块（如跨图续号、高亮块、行内底色或两栏），改走可用的原生块接口补齐，绝不因为接口返回成功就把降级失真的成品直接交差。

## 三、图文整合与分情况验收交付

- **图文分工**：操作界面截图由父级走教程模块的实操截图三路径；复杂关系信息图按 [篇内图文四分法](../../references/article-craft.md#按读者任务安排篇内图文) 交 `laohu-cover`。新图必须经真实工具生成并打开核清后才算可用工件，区分已绑定实图、设计稿与待采项。
- **按真实交付形态收口**：
  - 仅聊天看稿时，按父级格式交完整正文与必要的图注或采图说明；
  - 远端写入完成后，按 [feishu-ops.md](../../references/feishu-ops.md) 完成读回校验，在聊天交付**可点击文档链接、本次改动范围、图片绑定与核验结果，以及确需用户补充的缺项**，绝不用整篇 Markdown 代码块冒充已写入云文档。格式、图片或真实飞书客户端预览有未验证项时如实说明，其余已完成部分照常交付。
