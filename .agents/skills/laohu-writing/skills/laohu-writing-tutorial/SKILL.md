# 教程、实操指南与技术文档

若宿主直接命中本模块，先回 [laohu-writing 主文](../../SKILL.md) 确认唯一上手读者画像、材料、授权与交付媒介。教程与技术文档同样遵循锁清读者任务与终点价值 → 清晰分层递进推进 → 铺展开的零卡顿大白话 → 扎实验收与排错闭环的底层逻辑，绝不写无层次散装流水文字，而是把中段权重全面倾斜到**整体流程把控、前置依赖梳理、步骤详细度、完成标志与排错闭环**上，确保零基础新手跟着走绝不卡死、熟手查排错一眼定位、真假软件界面绝不混同。成品若要发公众号或飞书，由父级同步叠加对应媒介专项。仅受托核对或规划实操截图时，直入[实操截图的三条路径](#实操截图的三条路径)。

## 按读者此刻要干什么定型（Diátaxis 四分法）

先判读者是要动手还是想理解，再判他是第一次学还是已经会用、来查具体解法或参数。同一份资料面向不同任务各自写透：

| 读者真实任务 | 开篇直接给什么（结果先行） | 正文核心侧重与完成标志 |
| --- | --- | --- |
| **入门教程**（新手第一次上手，要做出第一个可见结果） | 直接亮出最终能做出的具体成果、提前要备齐的最小条件，紧接立即可做的第一步（耗时仅在确有依据且影响开始时给，绝不凭空编造几分钟） | 只给一条最稳妥的最小推荐路线；按真实前置依赖拆步，每处关键动作紧跟可见完成标志，不夹带未介绍的专业工具名词 |
| **实操指南**（已有基础，要解决眼前一个具体任务或故障） | 直接交代适用条件、操作入口和目标状态 | 聚焦影响成败的先后顺序、关键参数范围、分支条件与对症排错 |
| **原理解释**（想搞懂为什么这样设计、底层怎么运转） | 明确要拆解的现象、机制或设计取舍，从读者熟悉的对象接起 | 讲清参与者、因果关系、状态变化与适用边界，辅以日常类比或关系图，绝不硬塞打卡练习 |
| **查阅手册**（干活时要快速找到准确字段、命令或限制） | 标明适用版本、对象或范围，提供可直接跳读的清晰条目 | 同类信息统一结构列清键名、类型、默认值、约束和来源；命令与配置可原样复制，未知值标待核 |

## 把动手路径写成零跳步、照着就能跑通的六步

1. **先把看得见的终点亮出来**：开篇写清跑完会生成哪个文件、打开哪个界面、打印哪句回显或达成什么状态。交代默认路线的适用条件，替代路线只在改变读者做法时才提。
2. **严格按前置依赖铺路**：账号、订阅计划、API 额度、模型名、配置文件、目录和工作区，**在第一次被用到之前，必须已经在前一步准备好，或开篇明示由读者自带**。系统或版本差异会卡住操作时（如 macOS 隐藏以 `.` 开头的文件与保存弹窗、Windows 记事本自动加 `.txt` 后缀及命令提示符跨盘符 `cd` 切不动目录——Windows 进指定文件夹优先推荐直接点顶部路径地址栏右侧空白处输 `cmd` 回车，避开跨盘符坑），就在对应一步当场拆雷。
3. **一步只干一件可执行动作，严格按鼠标键盘真实先后写**：写清从哪点进去、敲什么或填哪一项、点哪个按钮。动作切换就另起一步，**创建配置文件时，先给要填入的原样内容，再写保存路径、防误存后缀与显示隐藏文件核对，绝不把保存动作写在给内容前面**；必要提醒和结果紧贴该步骤。必须依次执行的步骤用有序列表，并列准备或核对项用无序列表。
4. **入口链接与可复制原值彻底分开，绝不擅改已有安全占位符**：网页入口用清晰锚文本；命令、路径、接口根地址、配置片段和完整提示词放行内代码或代码块，原样保留字符、缩进与换行。刻意点清易填混的条件（如接口根地址 vs 具体路径、网页聊天会员 vs API 余额）。**安全凭据严禁露出真实密钥：如果原材料本身已经给出了明显脱敏占位符（如 `sk-xxxxxxxxxxxx`），原样保留不另换名；只有遇到真实密钥或未给占位符时，才替换为清晰占位符并写明真实获取路径**。
5. **关键一步紧跟可见完成标志**：写清屏幕上哪一块出现哪条消息、目录里多出哪个文件或打开看到什么内容才算过关；涉及无常见后缀或 Markdown 文件，顺手交代双击弹选择框时用什么打开。
6. **排错单列清晰同级章节或醒目区块，拆成短编号步骤**：高频报错排查（如 `401`、`ENOENT`）避免埋进过深的小节层级，方便慌神时顺目录一眼找到；每条拆成 1、2、3 简短排查动作并指回具体步骤号（涉及隐藏或无后缀文件如 `.env`，顺手补一句怎么重新打开）。涉及密钥的工具，在排错末尾提醒**截图发群求助前先给真 Key 打码，并补万一泄露立刻回后台删旧建新的止损动作**。

## 实操截图的三条路径

当真实软件界面里的入口位置、按钮名、字段或状态回显直接影响读者定位或判断时，在该步骤设截图锚点。命令和配置原值仍归代码块承载，**真实 UI 位置绝不能用 AI 生成图或概念示意图冒充**，严格按以下三条路径之一处理：

1. **已有现成实图**：必须实际打开原图，核对软件版本、可见界面、按钮与字段名称、动作前后状态是否与正文步骤完全一致，确认脱敏且有使用权限后再嵌入真实路径；标注重点动作区并保留周边识别上下文。版本或字段对不上时，立刻转走下面两条路径。
2. **本轮获准实采且工具环境可用**：操作真实应用或网页走到该步准确状态再截图，裁切突出目标控件同时保留页面上下文；涉及登录、提交等外部动作必须有对应授权。**输出图片前必须严格遮挡脱敏 API Key、Secret、Token、手机号、邮箱、私有组织名、余额及一切敏感信息**。实际打开核清清晰度与脱敏无误后再嵌入。
3. **当前缺图、缺环境或无实采授权（待采路径）**：依据可核实的材料，把菜单路径、按钮文字和预期回显清晰写进正文步骤，确保读者**不看图也能照着做完**；无法核实的网页按钮名、菜单方位或网址标待核，绝不凭记忆瞎猜，也绝不把冗长待补图占位框塞进给新手看的正文里。同时在**正文代码块之外**把全部待采截图统一包进**一个可直接复制转发的独立代码块**交付《实操采图执行单》（块首写一次总标题，多张图依次编号，若涉及成品打开效果一并列入脱敏采图；用户限定只交纯正文时遵守该范围）：

```markdown
实操采图执行单

1. [截图主题]
- 锚点位置：[实际章节与步骤编号，标明动作前或动作后]
- 目标与状态：[软件或网页入口、已知版本或待核版本、前置状态（如开启隐藏文件/扩展名显示）与应显示的界面回显]
- 聚焦标注：[需要框选的按钮、字段或输出区，以及应保留的周边定位上下文]
- 脱敏项：[此画面中必须打码遮挡的凭据、账号、本机用户名/路径或敏感数据]
- 图注：[读者看这张图时要核对的入口、动作或完成标志]
```

凡嵌入真实图片，交回父级前必按正文步骤 → 图片 → 预期结果连读验货；打不开、对不上字或看不清就先修资源或退回待采路径。

## 交稿前从第一步走到终点的依赖链核验

写完后把自己当成零基础读者，从第一行一步步走查到最后一行：
- 核对文中每个账号、环境变量、路径、文件和前置状态，确认首次调用前均已准备好；
- 核对配置文件是不是按先给原样内容、再写保存防误存的真实先后顺序写，原有脱敏占位符有没有被误改；
- 核对引用前一步输出值的步骤写清了怎么找、出错重试能不能顺回主流程；
- 局部改稿只查受影响步骤、截图锚点和下游依赖；没有真实跑通环境测试时，在正文外如实写清本稿仅据文字材料整理、尚未真机实跑验证，并顺手提醒可能的环境/权限待核项，绝不宣称新手实测零报错。
