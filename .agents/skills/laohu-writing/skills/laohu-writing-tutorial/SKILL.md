# 教程、实操指南与技术文档

若宿主先选中本模块，先回 [laohu-writing 主文](../../SKILL.md) 定用途、材料、授权和交付媒介。这里选择读者能完成的技术任务，安排操作依赖和读者定位所需的图片。父级提供读者基础、目标产物或问题、已知入口与版本、准确原值、可用截图及授权。稿件与图片状态交回父级整合和验收。用于公众号、飞书或 Markdown 时，父级把同一教学方法与对应媒介排版组合。只受托处理实操截图时，从对应小节开始。

## 按读者当前任务定型

先判断读者是在动手还是在理解，其次判断是在学习新事物还是在运用已会的技能。用户要查看准确字段时直接给可查阅信息。以下分法依据 [Diátaxis 技术文档框架](https://diataxis.fr/)。同一套资料可给不同交付，分别把各自任务做完整。

| 读者任务 | 开篇 | 正文与完成判断 |
| --- | --- | --- |
| **入门教程**：第一次学，要做出可见结果 | 说清要做成什么、需要什么，接立即可做的第一步。耗时确有依据且会影响开始时再给。 | 一条适用的最小推荐路线。按依赖拆动作，关键处紧跟完成标志和当前卡点的处理。读者可以凭这一稿走到第一个结果。 |
| **实操指南**：已有基础，要解决手头任务 | 直接给适用条件、操作入口和目标状态。 | 给对成败有影响的顺序、参数范围、分支条件和排错。读者能据现实条件选择路径并校验结果。 |
| **原理解释**：要理解为何如此设计或如何运转 | 明确要解释的现象、机制或实际取舍，从读者认识的对象接起。 | 从参与者、关系和变化推到结果及边界，按需要用实际对照、流程或关系图。只在有助于说明时引用具体步骤。 |
| **查阅手册**：干活时要找准确字段、命令或约束 | 标明适用版本、对象或范围，给可直接跳读的条目。 | 同类信息按相同结构列出键名、类型、默认值、约束和来源。命令、地址与配置可完整复制，有条件或未知值时在对应条目写清。 |

## 把入门路径写成能照做的六步

1. **给看得见的终点。**写明最终文件、实际打开的页面、启动状态或可取得的结果。把选默认路线的理由贴到实际适用条件，另一路只有在改变读者做法时才出现。
2. **按依赖铺路。**账号、订阅、API 额度、模型、文件、目录和工作区第一次被使用前，必须已由前一步准备好，或明示由读者自带。已知系统与版本差异会改变操作时，在相关步骤给当前适用入口。
3. **每一步有一个可执行动作。**写清从哪里进入、做什么、准确填什么。动作变了就拆成另一步，把必要条件、解释、警告与结果放在所对应动作旁边。真实顺序用有序列表，材料与选项用无序列表。
4. **把可点入口与可复制原值安排在正确位置。**网页导航用能看懂用途的锚文本。命令、路径、API 地址、配置和完整提示词以行内代码或代码块呈现，保留原值与换行。区分接口根地址与路径、订阅与 API 额度等会改变填写结果的条件。凭据给占位符及真实取得方式。公众号需要可见外部地址时，由父级组合公众号专项。
5. **紧接可观察的结果。**说明在哪看到哪条消息、状态或输出，涉及文件再核实际生成、保存与重开。相同动作用于多个界面时，核读者凭哪处界面特征可以辨认。
6. **把排错放在出错的地方。**对已有依据的常见症状，紧接一项可执行的检查或恢复动作和相关跳转。比如先核应出现的状态、返回到哪个步骤补哪项前提。默认给当前正确路径。版本核查、取证和修订来历在后台，读者需要做取舍时给相应资料。

## 实操截图的三条路径

当真实软件界面的入口、按钮或状态会影响定位、执行或判断结果，给这一步建立对应截图锚点。命令和配置原值仍由正文或代码块承载。截图负责指认实际操作位置和状态，关系图负责解释选择或结构，统一视觉分类从 [篇内图文](../../references/structure-and-argument.md#按读者任务安排篇内图文) 取。保持书面正文可照做。真实截图位置须用真实操作画面。

1. **已有图可用。**实际打开，核软件、适用界面或版本、入口、可见字段、动作前后状态和文字是否与步骤一致。适配的实图保护上下文，重点标注动作所在区域，核权限与脱敏后再嵌入实际资源。发现版本或字段不符时改用下面适用的路径。
2. **本轮授权采图，且工具和环境可用。**用真实应用或网页到达该步准确状态，对准应出现的控件、状态或回显。截图或裁切只突出本步，保留辨认所在页面所需的上下文。工具执行提交、登录等外部动作须有对应授权。输出图隐藏 API Key、Secret、Token、手机号、邮箱、私有组织名、余额及其他敏感数据。实际打开可用图核对清晰度、标注、状态与脱敏，再绑定真实资源。
3. **画面待采。**缺环境、可靠材料、工具或相应授权时，依据可确认的原文把菜单路径、按钮及结果写到步骤里。确实无法确认的界面值标为待核。交《实操采图执行单》到正文外，以真实章节或步骤定位。用户指定纯正文或限定格式时沿其边界。链接只用真实可访问资源。

```
实操采图执行单
锚点位置：[实际节名与步骤，动作前或动作后]
目标与状态：[真实软件或网页入口、已知版本或待核版本、到达此处的前置操作、应显示的状态]
聚焦标注：[要定位的按钮、字段或回显及应保留的周边上下文]
脱敏项：[必须遮挡的凭据、个人及组织信息，按此画面确认]
图注：[读者要在图中核对的入口、动作或完成标志]
```

已有图或授权实采图交回父级前，从“正文步骤 → 图 → 结果”实际连读。不能打开、正文所指找不到、版本不符或关键字看不清时，修实际资源，或按待采路径交单。

## 从读者的第一步走到终点

按成稿建立简短的反向提纲，区分选择、准备、行动、核验和排错。再从第一步顺走到末行，记录每个账号、变量、文件和条件何时首次出现、何时准备成功，找不到前置状态就回对应位置补齐。需要用早一步的值时，核可获得性与复制路径。遇到重试或其他分支后，要能回到正确步骤。局部修改仅查受影响的步骤、图文锚点和后续依赖。确已实操或取得新手结果时按真实范围报告证据。把可读正文、实际可用的图或待采单与关键待核项交回父级。
