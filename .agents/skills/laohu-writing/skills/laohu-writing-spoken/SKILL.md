# 口播与讲解稿

本配置只在用户把**可听取的成稿**作为本次目标时由 `.agents/skills/laohu-writing/SKILL.md` 读取。固定的是接收形式与听觉组织方法，不固定视频平台、营销口吻、三幕结构、痛点开场、句式或时长。需要公众号文章时使用宿主的公众号文章配置；若同一请求明确需要两种成品，由宿主分别编排，不从一个配置推导另一个。只谈录后复盘、无原音/原稿校对或内容讨论时，本配置不因材料里有口述/ASR 而触发。

输入继承宿主已确认的作者目标、听众、观点和声音、材料身份与证据边界、授权范围；再带入用户对时长/字数的要求及其是否为硬规格、可用的实际语速样本，以及确有的声画要求。论证、叙事或知识组织需要关键取舍时，沿用宿主的共用方法，相对本文件读取 `../../references/structure-and-argument.md`；其中的章节/阅读路径做法只在文章分支使用。实际修订词句时也沿用 `../../references/expression-and-density.md` 的共用表达方法，再由 `../../references/spoken-explanation.md` 深化听觉实现，不让媒介配置替代共用方法。按听觉方法写出口播净稿，并把附注与正文分开交回宿主。宿主负责最后的事实、归属、保护项、请求格式与交付检查。本配置不独立保存作品、不调用其他子级、不生成音频。
若某个听觉组织决定缺少具体口播处理、用户指定了已收录音频/口播参照，或明确要求比较此类方法，再按项目共用[本地作品方法库检索路径](../../../../../references/exemplar-study.md#从本地作品方法库检索并返回决定)核对句群、信息包和停顿关系；回到本配置的实际净稿步骤并以朗读/录音检查，不能用纸面原子声称实录效果。

## 按听众理解任务安排声音与画面

先定听众听完应理解、判断或完成什么，再选出必须由声音讲清的对象与关系。纯声音稿要能只靠听觉理解；用户明确要声画讲解时，writing 可根据理解任务主动提出必要的画面依赖，不要求用户先交完整画面方案。视听稿按声音与实际可达画面的共同信息安排并共同验收；声音里的主张对象和指向仍须清楚，但不要求它重复画面已清楚呈现的每项关系。画面尚未制作或不可访问时，标为待制作/待核的设计建议，不写成已看到的事实；writing 交接关键声画依赖，具体镜头拆分与真实音轨对齐仍由相应制作能力负责。静态图可按宿主职责协作设计，口播任务不自动扩成动画。

## 取舍时保住承重解释和作者声音

按听众理解任务选择承重材料、解释桥梁、可由画面承担的部分和本次不讲的支线。关键关系讲够，不用标题、术语或结论列表代替解释；若预算不足，先收窄支线，不压缩到听众只听见结论。保留作者已确认的态度、真实体验与表达力度，也保留确有作用的复沓、停顿和丰富句群；只删除不再增加理解、证据、态度或声音节奏作用的重复。长短句随内容起伏，不把短句、语气词、悬念、反转或广告句当口播公式。

## 区分建议预算与锁定时长

区分可调目标与明确锁定的时长/字数规格；只有锁定才按硬规格执行。若预算影响取舍，先减少次要内容，不以牺牲自然表达或听众理解的加速来硬塞内容，也不删除关键解释；用户明确选择的较快语速若经实际试读仍自然、可理解，可以采用。无共享默认语速；估时假设、录音校准、自然停顿和无声展示时段的计算见父级口播 Reference。只有锁定规格与必要内容确实冲突时，才交回用户选择。

真人录制与 AI 配音共用同一内容方法；区别只在真实试读、发音适配或用户明确提出的工具接口。没有用户要求和实际工具授权，不生成音频。依 Reference 复核后，只将净稿及已明确区分的附注返回宿主，不混入内部检查过程。
