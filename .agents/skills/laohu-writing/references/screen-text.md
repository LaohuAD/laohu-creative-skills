# 动画内屏显文字

本 Reference 处理动画镜头中的解释性文字，不负责字幕转写或动画镜头设计。它把一段内容转成画面中可读的文字组：文字承担什么作用、依赖哪段材料、怎样分组和先后出现、需要和哪个对象/状态同屏，以及哪些内容锁定。完整动画由 Analysis 设计负责人在形成唯一导演蓝图时即可读取；Motion 在实现中也可按需读取并把结果接回同一蓝图。用户直接要求为视频准备屏显文案时同样适用；一般文章、口播稿、单纯字幕制作和没有屏显文字的任务不触发。

## 先分清四类文字

- **口播原稿**决定说了什么，不等于必须逐字铺在画面上。
- **字幕**复现说话内容或无障碍文本，按来源、锁定状态和真实时间锚点处理；不得把它改写成解释卡片。
- **屏显解释文字**补足观众此刻需要辨认、比较或记住的名称、条件、步骤、关系、数值、结论或转折。它可以和口播分工，不必照抄口播；新补信息须有材料依据，示意内容标明其性质。
- **装饰性字样**只在确有情绪、节奏或视觉职责时使用，不冒充事实解释，也不挤占必读文字的阅读空间。

一个镜头可同时包含字幕、解释语和标签，但每项各自标明角色、来源、可编辑范围与观看职责。用户锁定的句子、术语、数字、单位、引用和标点按原样交付；有调整必要时返回制作负责人说明冲突，不私改。

对每项最终上屏文字，分别判断它的**表达功能、空间关系和时间行为**，不要让“标题/标签/字幕”等角色名替代设计。功能可以是复现口播、命名对象、状态或关系标注、比较、证据、提示、观点、节奏、步骤、数据/公式、总结、引用、情绪或装饰；同一文字可承担多个功能，也可没有独立功能而由图形完整表达。文字不必被固定分成“主信息/支持信息”两类；名称、比较项、证据、提示或观点都可在本段成为主要表达，是否附有限定或说明按材料需要决定。空间关系要说清文字与对象是并列阅读、贴附对象、嵌入对象、覆盖画面，还是处于现实场景/屏幕界面中。时间行为按阅读任务选择稳定显示、按语义揭示、强调、替换、展开、收束或退场；不因文字属于某一角色就套用一种固定样式或动画。文字、箭头、颜色、图形和动画都不得暗示材料没有的一对一对应、数量关系或因果关系。

字幕和配套图形/标签可以共同承担同一个观看任务，例如观众一边读一句解释，一边看对应部件被标出；只有二者争夺同一视线位置、时间或理解顺序时才拆分或错开。若总结文字需要成为本段主信息，先让制作负责人看到它对整幅构图的要求：可能要扩大总结的画面空间，重排对象，或在明确保护文字与图形的范围内让背景退开、遮罩、压暗、模糊或暂时退出。是否采用哪种处理由实际画面和所选表现方向决定，支持信息仍须能读，不能把压暗或极简当作默认效果。

文字承担的事实与视觉长相分开决定：保留已核实文案、数值、范围与关系。先读本片选定成熟来源的完整设计正文；来源规定的字形、字号、字重、色彩关系、材质/光照、版式层级、空间位置和显现路径，应按它的适用画幅与范围写入 Brief，不能被笼统的相对尺度描述稀释。只有来源未规定或当前媒介无法沿用时，才用相对尺度和自然语言描述可见目标。用户明确锁定的文字样式优先于来源组件的示例，字幕样式独立执行，不由主题文字组件覆盖。不能从“标题/数字/标签”等角色名推导一套全局默认皮肤，也不能把某组文字的局部处理扩成所有屏显文字规则。给 Motion 的文字设计应写成读者能想象的版面和行为；来源规定的可见尺寸关系也可直接写入，renderer 的内部 props 与代码字段仍留给实现。

## 从观看任务形成文字组

以动画设计负责人提供的观看单元和本段原稿范围为输入；在完整动画中该负责人是 Analysis。先问观众要认出什么、区分什么、跟随哪一步或记住什么结果；然后只写能完成该任务的屏显表达。文字要与将要出现的对象和关系绑定，避免脱离画面写成另一份文章。

按当前观看任务判断各文字组承担的是命名主体、说明关系、并列比较、给出证据/条件、提示下一步、表达观点、控制节奏或其他作用；可以有主次，也可以多个文字共同构成一项理解。不要先把所有文字塞进固定两层，再据此决定画面。列表按同一比较维度组织，步骤按真实先后组织，数字带上对象与单位，因果关系同时写清起点和结果。若图形已能清楚表达关系，不重复写一段同义说明；若图形无法表达条件或限定，则用短句补足。

每个文字组提交给 Motion 时包含：

1. 对应原稿/材料的可定位片段、事实来源及确定/推断/示意状态；
2. 文字原文与锁定/可编辑状态；
3. 角色（标题、对象名、关键判断、步骤、比较标签、数值/单位、限定、来源或收束）；
4. 组内层级、语义断行和建议先后；
5. 必须同时看见的对象、图形或关系，以及可独立阅读的最短完整信息；
6. 预期首次出现、完整可辨、有效阅读、退出或保留的职责。若没有剪后音频 timeline，这些只是画面预算建议，不伪装成 ASR 时间戳。

专项屏显文案负责文字原文、材料锚点、表达作用、分组和阅读时序，不单独接管全片导演决定。完整动画中，Analysis 选择要解释的材料；关键凝练题眼或主标题可按需交 `laohu-title`，Writing 负责解释性短句和文字组；准确且确有作用的现成标签无需强制重写。定稿内容交回 Analysis 写进唯一 `brief.md`；Motion 再将它落实到 renderer、真实字体资源、字形尺寸和位置参数。Writing 的工作结果不是另一份文案真源，也不替 Motion 决定镜头构图或动效。

动画成片的标题、标签、数字、单位、图例和画面素材中的可辨文字，由 Analysis 在 Brief 的 `<structure>` 按[屏显文字登记](../../laohu-motion/references/typography-and-legibility.md#原生双语讲解字幕)定稿。使用实际编号和时码的原生字幕由同一 Brief 的 `<inputs>` 登记源文件。写作可暂存备选，进入画面的版本须有具体材料依据和显示职责。材料不足以支撑数值、图例或结论时，收窄表达或留待确认。

## 可读与不误导

短不是目的，必要信息在实际尺寸下能读懂才是目的。优先删去重复和无关修饰，再压缩句子；不能删掉改变事实的条件、范围、方向、比较对象或单位。避免把完整解释拆成单字闪烁、让冒号/逗号独自占屏，或以不断跳字代替清楚分组。标点依句法和观看功能处理，锁定原文除外。

屏显文字要能脱离聊天上下文指明对象；避免“它、这里、上一步”等无法在画面中定位的代词。演示中的虚构数值、示意图和生成画面不得被写成真实观测或模型结论。无声画面如果承担关键知识传达，关键名词、关系、条件和结论不能仅靠口播才能补全；有旁白时，则避免把旁白整段重复铺屏。

交付前将文字组放回对应镜头顺读一次：对象指向是否明确、分组是否反映逻辑、支持信息是否必要、完整阅读状态是否可达、文字和画面是否互相补充。关于字体资源、真实字形测量、遮挡、背景对比和阅读窗，以 Motion 的[字体、字幕与可读性](../../laohu-motion/references/typography-and-legibility.md)为准；本文件不替代其 renderer 检查。
