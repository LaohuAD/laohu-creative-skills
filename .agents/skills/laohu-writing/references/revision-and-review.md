# 反馈、修订与终审

主文第三、六、七步需要处理模糊反馈、局部修改、用户认可项、全稿自审或改稿解释时读取。产出“反馈所指问题、修改范围、修订稿、未解决证据缺口”；局部意见回到对应步骤，全篇质量问题完成必要回退后进入主文第八步。不要把本清单附进文章，除非用户要审稿报告。

## 1. 先把反馈变成编辑任务

用户给的反馈是当前目标信息，先判断在谈哪种质量问题，不把它自动翻译成“全文重写”。

| 反馈所指 | 可观察的稿件线索 | 修改动作 | 完成判断 |
|---|---|---|---|
| 事实错误/观点不对 | 稿件与输入、来源或用户确认立场发生冲突，或把推论写成事实 | 回原材料核对；保留用户立场，修正事实或收窄推论 | 每项事实和立场均能定位依据；未经证实内容没有写成确定事实 |
| 结构不顺/跳跃 | 相邻章节缺少材料支持的时间、因果、论证、经验或观察关系 | 调整顺序、合并重复段，或只补材料支持的承接说明 | 章节关系可由标题和正文辨认；没有关系的支线已删去或分开 |
| 不自然/不像本人 | 句子出现不常见搭配、指代不清、语序生硬，或与作者已确认原话/态度/叙述视角不符 | 成熟口播里准确有力的判断先原句保留或最小书面化；确需替换时先指出对象、搭配、关系、范围或重复上的具体缺陷，再修词序、指代和搭配；材料没有的声音特征不补 | 朗读通顺，词义搭配自然；发生替换时仍保留原判断的对象、关系、力度和有效信息；事实范围经校准后，作者确认的立场与情绪仍在 |
| 啰嗦 | 多句重复同一判断，或句子未增加根据、解释、边界、场景功能 | 合并重复，删去没有新增作用的表达；保留证据、关系、氛围和必要边界 | 删除后中心、限定、材料根据和理解所需氛围均完整 |
| 不够有价值/讲得浅 | 已知阅读任务缺少相应解释、关键证据、例子或适用边界；观察/审美文章缺少材料中的场景关系或作者所见 | 只补影响理解的缺环；新事实回主文第三步；文章形态若为观察/审美，不强加操作建议 | 新增材料确实补足该形态需要的理解或感受，不是重复扩写 |
| 开头无吸引力 | 主题、目标读者可识别的处境、材料真实的观察理由或明确所得缺失；或开头所得找不到正文兑现位置 | 回主文第五步按文章形态选最有力的入口；允许提出具体处境、反差、代价或判断，按材料核对断言并让正文兑现 | 开头理由能定位到正文展开；题材推导的受众处境写成条件式邀请，群体频率判断有依据；观察/审美型入口保留其真实价值 |
| 期待没有兑现/阅读过程松散 | 明确提出问题/承诺的标题或开头，正文没有对应材料；或标题入口与实际材料、文章用途脱节；章节间只靠“继续看”式预告连接 | 先辨认标题入口的用途；只为明确承诺标出兑现段并补材料、解释或动作；局部场景/意象/原句入口若有材料联系，可由正文展开更大议题；章节末尾只提出由当前内容带出的下一层问题 | 明确承诺有对应回应；其他入口有材料锚点且正文关系成立；读者每读完一节都多得到一项判断、解释、经验或感受 |
| 配图/链接/行动引导不清 | 画面与所支持判断错位；图文解释隔得太远或重复；图注只重复图面标签或正文；alt 只说“概念示意”等类别、不描述实际对象关系；链接文字说不清落点；资源缺少打开或使用条件；关注/行动理由与本文所得脱节 | 按画面实际作用和论证次序安排证据/结果图在解释前或后；若该图承担开头阅读理由或需先展示才好理解，图后紧接作者解释。操作图靠近对应动作/结果。删除没有补充信息的重复图注，让 alt 描述可见对象、关系或读者应注意的变化；只有确有把解释图误认为实际操作、结果或证据的风险时，才在最能澄清的位置说明其概念身份。再核来源、目标页面、权限、费用、软件和第一步 | 画面及说明能帮助读者看懂对应判断或操作；图注只在补充正文或点出看图重点时保留，alt 描述具体图意，必要的概念身份澄清也不重复散落在图面、图注和正文；没有把所有图片机械前置；链接及行动引导兑现其文字预告，用户明确要求的资源、关注理由或 CTA 已交付 |
| 情绪不对 | 作者已确认的情绪、立场或力度被改弱；或情绪表达与作者确认的态度不符；力度未确认时出现材料不支持的心理判断；或事实核验把既有情绪一并磨平 | 先区分作者已确定与未确定的表达。已确认的力度按原意保留；未确定时才依据材料场景安排措辞。事实范围单独核对，仅修正相关断言 | 已确认的态度与力度得到保留；未确定的表达有材料依据；事实断言不超出证据，情绪承载关系清楚 |
| 排版不清楚 | 标题层级、列表或留白妨碍扫读；或指定 Markdown 接口无法识别结构 | 按内容关系调整标题、列表、表格或标记；遵守已指定接口 | 普通读者能辨认层级和重点，指定接口能读取语义结构 |

用户只说“感觉不对”时，先查看最可能造成体验问题的稿件局部；如果两种差异导向完全不同的改稿且无法从上下文判断，再用一个短问题确认。可以明确说明当前最可能的问题并先给一版小范围修订，未受影响内容继续保留。编辑判断、受众工作假设和事实主张分开处理：工作假设可用于选入口和解释顺序；一旦写成“多数人/通常都会”等可核实频率，就检查依据。

## 2. 保护已经确认的内容

改稿前把用户明确认可或要求保留的原句、主标题、章节标题文字、已确认事实和引文列为本篇保护项。除非反馈涉及该项、它与新证据冲突或用户明确授权重写，否则保护文字本身及其范围，不改写成近义句。只改首段时，复核标题、正文和小标题未被改动；改一段时，检查前后过渡，避免顺手重写无关章节。

当用户发来带元数据或标题层级的 Markdown 文件时，先区分编辑对象：

| 用户要求 | 处理 |
|---|---|
| 只改正文 | 保护 YAML 元数据、标题层级和确认过的标题文字；只改正文范围 |
| 调整文章结构 | 可调整文章章节，但保护明确标为不动的标题或字段 |
| 全面重写 | 按授权重写文章内容；仍保护事实、引用、来源和其他明确限制 |
| 修改 Skill、模板或项目规则 | 这不是普通文章改稿；转交 laohu-evolution 或相应维护入口，不自行改 name、description 或既定标题骨架 |

本表是保护用户已确认结构的编辑规则，不影响用户明确改变范围的权利。

## 3. 按编辑层级回退

用最先失效的层级修稿，不在下游层面掩盖上游问题：

1. **事实/来源层**：材料本身或出处错误、未核 → 回主文第一步、第三步。
2. **主旨/结构层**：中心判断不成立、章节不能回答同一问题 → 回第二步。
3. **段落论证层**：结论缺证据或推理桥、例子不支持 → 回第四步；需要外部依据时回第三步。
4. **开头和标题层**：标题错配、收益不清、承诺未兑现 → 回第五步，并查正文兑现。
5. **句子和语气层**：指代、词义、节奏、搭配或情绪偏差 → 回第六步。
6. **格式层**：Markdown 语义表达错或接口无法读取 → 回排版规则。

如果上游主张或材料变化影响已完成部分，重审受影响章节；不受影响的段落继续保留。

## 4. 终审分轮进行

| 轮次 | 阅读方式 | 可观察的通过条件 | 条件不成立时 |
|---|---|---|---|
| 事实轮 | 对照输入、出处和原始媒体 | 名字、数字、时间、否定、因果、亲历身份和引文与来源一致；事实范围校准与作者态度分开，必要条件贴在对应断言旁 | 改正文；只收窄证据不足的事实/推论，不自动削弱已确认的情绪和立场；仅在不同解释会改变主张时列最少待确认问题 |
| 结构轮 | 只读标题和段首判断 | 任务型文章呈现任务到解释/做法的推进；经验、观察或审美文章呈现材料支持的经历、观察或感受关系；用户要求或分享形态适合时，小标题承载本节成熟判断，操作/来源标题仍按查找用途命名 | 返回第二步调整骨架，不强迫所有形态套问题—答案结构；只有真实依赖的操作链编号，阶段名、并列栏目和叙事段落不伪装为步骤 |
| 价值与期待轮 | 对照标题、开头、章节标题和结尾，再定位每项兑现内容 | 读者所得具体；各主要章节交付新的理解或经验；每轮已知、利害与未知都有真实材料支撑，期待及时由证据、解释或行动兑现 | 缺哪一项就回第二、五步修价值链或结构；删除无内容支撑的悬念，不把中心判断拖到结尾 |
| 论证轮 | 每节标出主张、根据和推理桥 | 读者能从定位材料与明示推理看出结论如何成立，结论范围不超过证据 | 补推理桥、换成真正支持的材料或收窄结论 |
| 阅读轮 | 陌生读者从头连读，再扫读 | 开头的阅读理由、指代、背景、转折、段落功能和结尾均能对应本文形态；本人分享视角一致；口播标题已凝练、正文关键推理与实操未被摘要化；成熟原句仅在有具体缺陷时替换，改句保留原对象关系、态度力度和信息密度；新增说明填补真实理解/执行缺口；可复制提示词独立完整 | 补必要信息，删除无关负担；观察/审美关系不改成解题任务；回到最早断点重写标题、扩正文或补全提示词 |
| 图文与资源轮 | 查看每幅图、每条链接及结尾行动/关注引导 | 图像来自真实来源且贴近论点；数字和界面可读；链接落点、门槛和第一步说明准确；引导与本文交付的价值相连 | 回第二步重新策划位置；回第三步核来源、目标页面与使用条件；无法确认时删图或标出缺口 |
| 文字轮 | 大声朗读并逐句校搭配 | 现代中文搭配自然、重复有删减、抽象词有落点、修辞服务关系与节奏；长短句变化由真实场景、选择和认识变化驱动 | 改句子并保留作者声音；没有材料依据的修辞删除 |
| 接口轮 | 按目标 Markdown 解析约定检查 | 标题级别、引用、列表、表格、代码和图片资源可按语义读取；确有先后依赖的实操链用编号，并保留读者需要的输入、动作、结果和交接；完整提示词/命令有独立围栏，块内可原样复制，块外说明用途与调用步骤 | 改 Markdown 结构，不改材料含义；并列阶段不编号伪装流程；补齐围栏内缺项或移出混入的编辑说明 |

轮次不是用户可见栏目，也不必逐条输出审稿结果。内容层错误优先于文字层润色，接口层错误最后处理。

## 5. 返还修改意见

交付修改稿时，把说明长度控制在用户需要的范围：

- 用户只要正文：只给修订正文。
- 用户问“改了哪里”：给相关段落及一句修改理由。
- 用户问“为什么”：说明依据、解决的问题和仍有限制，不输出完整内部推理。
- 用户要比较：给少量有实质差异的版本，标明适用条件；不为数量凑多个近义句。
- 用户要诊断：区分已核实问题、编辑判断和仍待确认的疑点。

将已经解决的问题写回稿件本身；问题未解决时说清楚缺少的材料或需要用户决定的那一项。不要交付“初稿＋自我解释”冒充完成稿。

## 6. 终审完成条件

成稿同时满足：用户任务被回答；读者能说清文章帮助他理解、判断、感受或处理什么；中心判断有依据；重要材料与经历归属正确；重点案例有足够处境、动作/证据和解释支撑，不以摘要替代分析；章节按文章形态建立清楚关系并各自增加读者价值——递进解释呈现理解如何加深，并列或比较采用共同尺度、次序可查，步骤按依赖关系和完成标准组织，叙事与观察依材料中的时间、行动、场景、发现或感受展开；成熟口播里的有效命题优先保留，替换时能说清具体缺陷且不丢原判断的对象、关系、力度和有效密度；标题将口述主张压缩得清楚自然，正文保留理解和执行所需的推理与步骤；作者分享经历时人称和素材归属一致；事实边界没有连带磨平作者的已确认态度；开头和各主要章节提出的期待在正文兑现；文字符合现代汉语自然搭配且保有作者声音；完整提示词或命令可独立复制、使用步骤明确；图片按本段读者需要和论证次序放在相应解释前后，证据图或结果图承担钩子/先呈需要时紧接作者解释，操作图靠近对应动作，不将所有图片统一前置；链接和行动引导可用且说法准确；有不确定处时在相关断言附近标明；Markdown 语义与下游要求相容。

检查没有发现必须回退的问题后再交付。真实读者反馈、平台点击或传播数据属于后续质量证据，没有这些数据时只能说明文章稿已完成，不能宣称已验证传播效果。
