# 粗剪、精剪与语义保真

需要判断录音或录屏该留什么、剪什么时读取。先确定哪些完整表达能兑现讲述目的，再精修气口和接缝。完成后交出源范围、顺序、剪辑理由与待确认项，按[时间线与交接](timeline-and-handoff.md)编译及呈现。

## 1. 盘点真实素材与录制尝试

先按[输入与识别证据](input-and-asr.md)恢复来源、各自时钟、主音轨、已知时长、转写精度、同期画面和音轨偏移。多源的范围、顺序和同步分别核实。没有音源时仍可审文字、找重录候选和编译有依据的虚拟结果。

沿录制顺序找试麦、失败起句、录制中断、重来、同期 UI 或系统声。特别查每个文件边界前后，上一段话头未完、下一段同样开头时，把两者连读，判断是否同一次表达的重试。可用原声时逐次从开口听到说完，再按[探针办法](input-and-asr.md#用波形缩小候选范围)标静音谷底、底噪及疑似词首偏移。读完整尝试后才记录候选保留理由。

## 2. 做纸面粗剪并保全论证

**写一句剪辑承诺（Edit Promise）。** 说明这版剪辑让哪类观众听懂、相信、感到或能完成什么，准备用哪些真实片段兑现。例如新手要能完成版本覆盖，并知道凭什么可以下线旧表。按片型形成叙述主线（Story Spine），讲解可用开场问题、最少背景、逐步证明、综合与收束。纪录表达可用问题、人物或现场、证据、反面难点与收束。把看来精彩却服务另一主题的段落另标支线。

**重建表达单元。** 对照实际句段和画面，圈出对象、动作、限定、否定、证据、态度、编号和结论。跨 ASR 行的未完句合回完整意思。选能完整交代的 take，后来一条确实完整才比较流畅度。需要取前一次的开头和后一次的结尾时，分别核听，确认接起来的上下文和同期动作仍真实。找不到必要桥梁时登记缺口或补录建议，保留实际说过的话。

逐段扫三件事，先做结论和理由的纸面修改单。

1. **逻辑衔接。** 删除一段后，从前句只靠已保留的内容走到下一关键节点。观众能否解释动作为什么成立、条件是什么、指的是哪个对象？推不出来就保留承重句或标明确实需要补录。删除半句后要单独读回剩余部分，防止漏否定、只剩指代或落下悬空的编号。
2. **信息密度。** 区分同一句的误录重来、真正重复、逐步演示、纠错、刻意强调和态度差别。只删语义及表达作用均由保留段承接的部分。核查被剪版本独有的条件、转折、例子、语气和实际口播的可懂度。
3. **口语与画面配合。** 把绕口、重启或卡壳先标为精剪候选。白板或录屏里的“看这里”“点左边”可能正把注意力交给标记、点击、指针或回执。先查同期画面和动作终点，再决定保留。纯文本看似多余的承接语仍可能是实操步骤。

发生取舍时先守事实、授权和已锁定范围。参考 Murch 的顺序，按情绪、故事、节奏、视线、平面连续性、空间连续性逐层判断。一个可由实际画面遮蔽的跳剪可以让给更完整的讲述。保留事件真相所需的系统声、反应和解释前提优先于缩短时长。Murch 用排序表达个人剪辑偏好，实际决策写明这里牺牲什么和为什么。

**检查开头能否单独成立。** 看开场是否用第一条完整表达给观众话题、值得继续听的理由及可信依据。对短视频可检查最初约五秒，从实际 take 找结果与反转、数据、变化前后、一句能立住的判断或切身问题。弱开场可从已获准处理的试麦、废话和未说完的尝试着手。

**在审阅稿写出有价值的开头备选。** 若后文已有能独立听懂的结果或观看收益，且前置能让观众更早理解为什么值得看，在「开头备选」列出原时码和原句。说明能否直接前置，所需的对象、条件或同期画面，以及会怎样影响后面的论证或演示。主版先沿原录制顺序交付，备选等待重排授权，获准后才更新 `sequence`。

## 3. 闭眼精剪，再回同期画面

先不看画面，按粗剪顺序通听（Radio Edit）。听两侧怎样进入下一句，候选处是否有吞字、卡壳、重复、刺耳吸气或过长空白。确认能删的完整表达后，再走[气口与波形方法](pause-and-pacing.md)。有同期视频时，回到画面查动作、嘴形、指针与系统声，确定可保护的窗口。

每个确定的删除用于具体的连续源样本范围。读回留下来的词句，并按[声明式编辑](timeline-and-handoff.md#用编辑操作单修订计划)录入操作。相似度、VAD、识别置信度、字数或停顿长度可提示候选。实际落刀还要有语义、授权和精度证据。语义可删、波形未核时可交虚拟范围与待核项；气口精修在真实样本和上下文复核后才执行。

### 段落气口：保源停顿、剪口衔接、无源画面时间

已有真实停顿需要保留时随 source range 编译。要压缩长空白时从源区间剪除核实可删的中段。画面确需额外的停讲时段时只计算原声停顿以外的净缺口，由同一计划[加独立时段](timeline-and-handoff.md#无源展示时段)。画面功能优先于节奏秒数，有关时长、源余量和例外见[停顿规则](pause-and-pacing.md)。

### ASR 修正与确认口语

从[输入与识别证据](input-and-asr.md#识别输入能够证明什么)核定 `spokenCorrections` 的候选与确认字段。剪掉原声和更正识别分别作决定。字幕设计与显示标点使用[字幕契约](captions.md)。

### 完整覆盖与决定账本

每个源在已声明的 `sourceScope` 内由连续、无重叠的 `coverage` 项覆盖。按 `retain`、`delete`、`unresolved` 分类。处理整源且时长已知时，从 0 到 `durationSamples` 都要归类，包括头尾静默。只有选段或 SRT 时，限定实际证据范围，整份媒体未知的尾部、重叠说话、同步和其他缺口进入待确认项。整源或任何区间缺项时，完整覆盖仍待核。

每个删除明确源区间、原因和 `decisionId`。重复删除以 `relation:"repeated-content"` 标记，指向当前 `sequence` 真正保留、完整承接该信息的 `keptOccurrenceIds`，在有词证据时填 `keptTokenIds`。句段级使用真实承接 occurrence，词列表可留空。词只能归属该实例的保留范围。缺少承接实例时重查删减依据，有其他独立理由再另记。已知词时码的切点不能落在词内，句段级材料使用完整句段。

重剪超四分之一时列具体删减范围与理由。用本轮纳入处理且已知的源区间总时长作分母，用实际删除区间作分子。重复播放由各 occurrence 单独记，源范围未核实则只写已知删减，不报总比例。

### 重排、合并与授权

默认按已确认的来源及录制顺序。将相邻保留片段表达为一条连续剪后路线时，保留所有源区间、删段和词实例，`coverage.tokenIds` 按原 ASR 顺序。多源顺序缺证据则列待确认，或单独完成可确定的源。

用户已授权调整顺序后，才按 `authorization.reorder` 和该次决定编译重排，记录原后顺序、原因、授权和指代/同期复核。重复播放另需授权和实际用途。每次播放得到独立的 `occurrenceId`，同词复现由 `occurrenceId + tokenId` 区分。没有授权的建议可在审阅中呈现。

## 4. 生成可复核的审阅件并办交接

先由编译器检验全源覆盖、合法切点、保留实例、授权、时钟与哈希。按[审阅页契约](timeline-and-handoff.md#html-视图与反馈)把原顺序删除线对照、改动理由、待确认项与已编译时间线交给 laohu-htmlshow 呈现。优先提供真实可打开的审阅页。撤回改动的方式和绑定规则随审阅反馈契约处理。

有实体剪后文件时先逐缝核实，再按实际媒介和交付范围分遍验收。

- 纯音轨检查口语意思、换气、响度、接缝及同一房间底声。
- 静音画面检查手势、嘴形、跳变、信息顺序和观众能否看到关键结果。
- 纯字幕检查语义分组、断行、译文、阅读窗口和整体覆盖。
- 声画合看确认解说和实际证据是否在同一时点，字幕、动作和声音有无争抢。

没有的媒介标明未执行相应检查。真实音视频裁剪需要用户授权，导出后记录该版是否听审、是否批准。需下游动画时按[动画交接](timeline-and-handoff.md#动画交接)写真实可用的自然时窗、语义节拍与画面风险；原视频粗剪之后的表现与同期视图由 Motion 承接。

### 剪后逐缝核实

用 `extract-seams` 从同版剪后 WAV 导出每条实际接缝前后各 1.25 s 的窗口，靠近时间线边界时以实际范围为准。跨界顺听并对照两侧原声。检查词头词尾、否定与半句、呼吸和语调、重复、指代与编号。同期画面还要看嘴形、视线、手势、点击和系统提示。记录每条接缝的结论、缺陷和待核处。

获准短窗重转写时，逐缝识别每条窗口。疑似双词在约 2–3 s 横跨区间重听，区分合法重叠或叠词、ASR 误报和真实拼错。整片重转写可以定位但会掩盖剪口。没实体媒体或识别权限时，分别记录实际播放、逐缝核听与逐缝重转写状态。

以下本地原文给出会影响选择的来源边界。真正遇到对应取舍时读指定小节及其配套条款，然后把决定落到当前范围或回听检查。忠实执行冻结计划可直接走已定操作。([原文版本与许可](../SOURCES.md))

| 词首时码与听到的起音不一致 | 读 Cutting 的 Where cuts land 与配套第 6、7、18、19 条。0.40 s 是上游原素材两档交界。第 18 条把安全谷底确认置于沿词边界切之前，固定 padding 不能校正所有起音偏差。词定位缺失时核实际原音或可信对齐，保留证据精度。 |
