# 口播声音诊断与后期方案

要求修复、清理、塑形或统一口播时，直接用可访问的连续原音诊断、试听、试做与比较。有获准的剪辑任务时，只在确需处理声音缺陷的步骤进入此流程。只有转写时记下用户说明的问题和所需原音，继续本轮可独立完成的虚拟剪辑。

## 先确认音源、用途和授权

方案必须能回到真实音源。沿用主文已取得的稳定来源身份和内容哈希，确认实际音轨、主音轨采样率/时钟、已知时长、要处理的源范围，以及音轨与画面的偏移依据。多个录音、麦克风声和系统声分别识别；未知轨道、偏移或范围写为未知，不以默认音轨、文件名、0 偏移或局部时钟猜定。

沿用已表达的用途、希望解决的问题、必须保留的声音和允许处理范围。常规修复在现有授权内逐项试做并可回退。若会改变本人声音身份、实际口语或时长，或影响主要交付的取舍尚未解决，只停受影响的处理。用全新路径写出媒体。

## 让每项处理有可核依据

先按任务范围检查原始连续片段，选择能代表问题的短段：包含背景声或噪声底、普通发声、较强发声、齿音、呼吸/尾音及拟剪切点。听审能力可用时，记录确实听到的现象和对应源区间；若只取得波形、频谱、响度或其他测量，记下实际指标和来源区间；若依据只是用户描述、文件元数据或推测，也明确区分。没有可靠听音能力时不写“已听”“听起来”或“听审通过”，测量结果不能替代听感结论。

闭室、近讲或房间狭小本身不能证明存在混响；低音较多也不等于声音闷或难听。降噪、去混响、EQ、压缩、门限、响度标准化等名称不是问题证据。每项只在具体症状有实际依据时启用；不要复制用户某次 EQ 或其他一次性设置当通用预设。

| 可观察的问题 | 处理判断 | 处理后重点检查 |
|---|---|---|
| 连续、相对稳定的底噪 | 先在未处理原声中找代表性的背景样本，确认噪声是否跨目标范围持续，并核对其下是否叠有人声、呼吸或有用环境声；确有必要时才以降噪为候选。静态噪声取样前不得先用噪声门或自动增益改变噪声底。 | 人声是否仍自然，呼吸与齿擦音是否保留，有没有抽吸、泵动或水下感；有用环境声是否被连带清空。 |
| 句尾或音节间可辨的混响尾音 | 依据实际听到的尾音或相称测量区分混响与持续噪声，再把去混响作为独立候选；不能从房间描述直接推断。 | 尾音、字头和声像是否被截短，是否出现空洞、金属音或抽吸。 |
| 局部点击、碰麦或爆破声 | 定位真实的局部事件，只对问题范围试做点击声/爆破声修复；先确认它不是有语义作用的辅音爆破或刻意发声。 | 前后字头、辅音闭塞、爆破音和词尾是否完整，局部音色是否突变。 |
| 低中频浑浊、高频信息不足或偏轴拾音 | 结合原声、可用的频谱证据及已知拾音方向，判断是局部频段堆积、遮挡/偏轴还是录音本身缺失；只对能由目标源材料支持的频段作小范围 EQ 候选。低音多不是自动削低频的理由，EQ 也不能重建从未录到的细节。 | 清晰度是否提升而底噪未被夸大，辅音与齿音是否完整，音色是否变薄、刺耳或不像本人。 |
| 特定字词的齿音过强 | 只在齿音确实刺耳或妨碍聆听时试用去齿音或局部动态处理，不作为全片默认步骤。 | “s/shi”等辨字线索是否保留，有没有口齿含混、口齿漏气或局部暗哑。 |
| 剪后不同片段之间电平明显不一 | 先保留源段原有动态，剪辑后按段落匹配主观电平；段落间电平校正与整条成片响度是两个判断。 | 接段是否突兀，低声段是否被抬出噪声，强声段是否削顶或挤压。 |
| 同一语句内部的动态妨碍理解 | 只有句内响度起伏确实影响可懂度或连续性时，才候选自动化、压缩等动态处理；先完成有依据的源修复与音色处理，再决定是否需要动态控制。 | 起伏是否仍有表达作用，是否出现泵动、呼吸被放大或强声失去力度。 |

这些处理不是一组必须全开的预设。按已核实的播客后期次序（iZotope《How to Edit Podcasts》），先修复真实缺陷，再按需要做 EQ 与动态处理；参考 Auphonic Singletrack 将片段电平与整体响度分开，并分别判断噪声、混响和呼吸。修复、塑形与神经重建/换声是不同类别：修复针对可识别的噪声或局部损伤，塑形针对频响、齿音与动态；神经重建/换声可能重构音色或影响本人相似度、音节及时间位置，只有用户明确要求该类变化且当前有相应工具时才作为独立候选，不能当作更强修复的默认升级。实际参数字段和边界以 `schemas/asrcut.schema.json` 的 `$defs.audioPlan` / `$defs.audioPlanStep` 以及 `validateAudioPlan()` 为准；写入 audio-plan 前读取这两个定义，不能猜字段。后端只执行当前已接入并核实的功能：基本 FFmpeg 处理路径按其已实现能力使用；RNNoise/DeepFilterNet 降噪、NARA-WPE 去混响、VoiceFixer 神经重建等在当前调用链尚未接入时只是候选，不能写成已经能直接运行的功能，不得猜 CLI 或接口。缺少某一后端时，只退出依赖它的处理分支，继续完成独立且可用的步骤；不自动联网或安装整套模型，也不把另一种处理静默冒充为原候选。

## 单项试调与回退

先保留旁路原声和当前有效版本；每次只启用一个处理模块，或只改该模块的一项参数，其余参数与试听范围保持不变。改动后对同一源段做等响度旁路比较，记录实际使用的设置和可恢复版本；无可辨改善或损伤变明显时，退回上一个版本，或减轻这次改动后再比较。

- **降噪：**从轻量处理开始；只有背景噪声仍妨碍目标用途、且当前设置没有损伤人声时，才逐步增加降噪量。每次都检查无话背景段和同条件的人声段，特别留意辅音、齿音、呼吸与尾音。出现水下感或抽吸时先减弱降噪；仍存在则撤回或换方法，不靠继续加大处理量压住伪影。
- **EQ：**选实际有浑浊、共振或高频问题的片段定位，不套固定频点或曲线。用较窄频段试切来找出问题位置；每次只调一个参数，再用等响度旁路比较。找到确有改善的位置后采用最小有效改动，并返回完整词句检查音色、底噪、辅音和齿音。录音没有保留的高频细节不能靠无限提亮恢复；噪声开始变明显或人声变薄、刺耳时回退。
- **压缩/动态：**先做剪后片段电平匹配，再按普通词与实际偏强词句的源电平选择压缩阈值，观察哪些声音触发以及产生多少增益衰减。只控制妨碍可懂度或连续性的突峰，保留有意强调和句内强弱；若强调被压平、呼吸被抬高或出现泵动，先回退阈值或压缩量。需要继续调整时，一次只改阈值、压缩比或时间参数中的一项，不用压缩替代片段电平校正。
- **去齿音：**只对实际刺耳的字词或短段使用动态去齿音或局部处理，让问题齿音受控而辨字线索仍在。每次只改一项控制量并回听完整词句；出现口齿含混、漏气感或局部暗哑时减弱或撤销该处理，不压低全句高频来掩盖单个齿音。

每项处理后都回到原始上下文重听，至少包含前后词句、该段正常/强发声和拟剪切点；降噪还要回听无话背景。只听隔离出的噪声、孤立字头或处理器预览，不足以确认效果。无可靠听审时将调参标为待听审候选，不把数值变化或算法成功写成质量改善。

## 在连续音源上试做，再接回剪辑

先对含有必要前后文的原始连续范围试做声音修复。逐项说明：问题与证据、选用的方法及当前后端是否可用、作用的源范围、希望改善什么、必须保留什么、如何检查损伤，以及何时减弱或撤销该项处理。无证据的问题保持旁路；依据不足但可供比较的做法标为候选，不当作确定结论。

静态噪声取样必须先于会改变噪声底的门限或自动增益；源音修复在切成小片之前完成，以免失去连续底噪和尾音上下文。之后才按当前 edit-plan 的源范围，通过[时间线与交接](timeline-and-handoff.md)规定的唯一映射放入剪辑。不能因为片段时长相等就认定同步正确；还要核对处理器的延迟、前瞻、重采样及时钟换算，并在多个分散锚点检查源声与剪后目标时间。每个后端均按它自己的已核行为判断；某次合成校准得到的固定延迟不作为所有后端、素材或项目的通用补偿。映射或延迟未知时保留不确定状态并阻断依赖该对齐的处理，不能用截尾、补零或剪掉尾部掩盖偏差。

剪接完成后才匹配各段口播的电平，再按实际交付用途确定成片响度和峰值余量。用户给出目标或当前交付有强制规范时按该目标执行；没有强制规范时，负责作者可依据本次用途选择可撤销的工作响度目标；若本轮只需试听或比较处理结果，也可保留原源响度作为试听基准。把它标明为本次制作选择，不称为平台标准；缺少 LUFS 数字本身不阻断修复。只有目标互相冲突，或不同响度取舍会改变主要交付时才询问用户。分段电平与全片综合响度分开决定，不以全片标准化替代片段平衡；不设全用途统一的 `-14 LUFS` 目标。

## 用等条件比较候选并检查损伤

只有在候选之间的差别可能影响选择时才做 A/B。两版必须使用同一剪辑、同一源内容、同一范围和同一呈现响度；同时检查真峰值，若有一版在匹配响度时超过可用峰值余量，就把两版一同降低到共同可行响度后比较。否则“更响”会被误当成“更清晰”或“更好”。正式交付响度另按用途设置，不沿用试听比较电平。

可靠听审可用时，至少检查正常音量、强发声、齿音、词头/尾音、呼吸和剪口。分别听处理后人声、有意保留的背景/系统声及最终整体混音；与同段旁路原声在匹配响度下比较。重点查吞字、尾字被切、辅音损伤、金属音、抽吸/泵动、齿音异常、呼吸不自然、音色变薄、动态被压平及本人相似度下降。发现损伤时先减轻或撤销造成它的处理，不以某项指标改善抵消可懂度、自然度或身份损伤。

如不能可靠听审，仍可交付基于已取得来源与测量的候选，明确听审未执行、质量判断未知。频谱、响度、波形和处理器返回成功只证明相应技术观察或调用，不等于“好听”“自然”或符合用户偏好；技术成功与质量成功分开报告。

## 保护声音内容并交回主线

默认保留说话者身份、实际说过的内容、片段时长与同步关系。不得自动变调、合成/替换人声、补写或增删音节、加配乐、加混响或清除全部呼吸；这些属于会改变人声身份、内容或声画关系的独立选择，只有用户明确要求并且存在相应授权与已接入工具时才进入该分支。对录音里的配乐、系统提示音、演示声、环境声和呼吸，先查明它是否承担演示、氛围、节奏或信息作用，再决定保留、降低或处理；不能一律当噪声去掉。剪辑重排后要复核说话者原意、态度和声音接缝，不能让后期把不同语境拼成新的立场。

声音处理方案沿用源身份、哈希、轨道和时钟。每项问题都要能回查依据的源范围、证据类型、拟用方法和可用后端、目标与保护项、损伤与撤销条件、真实听审和时间映射状态。未知或不支持的分支保持待处理状态。实际接入剪辑时按[独立声音源绑定](timeline-and-handoff.md#已处理声音源的绑定)交付。

## 执行已获准的处理并交出实际试听

纯修音直接建立 `audio-plan/1` 的 `source` 绑定。绑定既有剪辑时才按原 edit-plan 指定同一 `--source-id`。从仓库根目录可用以下实现入口。

```bash
node .agents/skills/laohu-asrcut/scripts/audio-postprocess.mjs create-plan --input original.wav --out audio-plan.json
node .agents/skills/laohu-asrcut/scripts/audio-postprocess.mjs process --plan audio-plan.json --out processed.wav --tmp-dir .cache/tmp/asrcut-audio
```

先在新建方案中填写核实的诊断、待确认项与本轮启用步骤。执行器接受 FFmpeg 的受限降噪、高通、参数均衡、去齿音、压缩、静态增益与测量响度标准化，其他步骤保持旁路或待选。支持可选 `--ffmpeg`，默认使用已核实的本机工具。连续源先处理，验证原源哈希、采样率、声道、样本数与延迟校准，再接入既有剪辑范围。

剪后整轨模式需要 `create-plan --mode compiled-timeline --input cut.wav --edit-plan frozen-plan.json --timeline timeline.json --receipt cut.wav.artifact.json --out audio-plan.json`。该模式只支持静态增益或测量响度标准化。出片要在已获权的剪辑导出中成套提交处理方案、处理 WAV 与其处理回执，由[时间轴交付](timeline-and-handoff.md#已处理声音源的绑定)校验。

实际交付新 WAV、处理回执 `processed.wav.audio.json`、同内容同响度的两份试听副本和可打开的 `processed.wav.review.html`。页面反馈由人确认已听后下载，绑定方案、原源 SHA、处理输出 SHA 和实际对比副本。没有实际听审时报告 `not_auditioned`。技术检查支持相应测量和渲染结论，听感按真实比较确认。
