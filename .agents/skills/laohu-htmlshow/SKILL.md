# HTML 展示与排版

让接收者点开页面就能一眼看懂结构、顺畅读完正文，并轻松完成定位、比较或准确复制。HTML 是服务内容的载体：决定布局、视觉气质和交互的，是接收者拿到这份材料后要完成什么动作，而不是源文件格式。原文保真优先于视觉装饰，不替代专业创作，不擅自改写正文或补编缺失数据，也不自动发布上线。

根据最终使用场景分流；绝不因文章内容里偶然出现公众号字样就切换路线，公众号旧稿若只用于本地阅读，仍留在通用浏览器展示页。

## 2. 按真实用途选定页面形态与按需参考

读完原材料后，先确认接收者最核心的操作任务（连续阅读、总览并比较、检索与一键复制、按场次或镜头核对），再选定主导形态；混合内容允许分区组合，绝不把所有材料都硬塞进同一种固定卡片模板。

| 内容类型与使用任务 | 主导形态与结构重心 | 必须守住的重点 |
|---|---|---|
| 长文章、教程、复盘、深度随笔 | **沉浸阅读型**：居中单栏主文、清晰四级排印尺度、可收起且随滚动高亮的轻量目录、极细阅读进度条 | 保持连贯段落与呼吸留白，不把完整散文切碎成碎片卡片 |
| 分析报告、调研总结、多方案对照 | **报告与对照型**：顶部精炼导览或原文核心结论带 + 分章正文 + 对齐清晰且支持窄屏友好的对比表 | 概览只提炼原文已有判断，不编造指标数字；表格空缺处如实标未提供，不虚构评分 |
| 提示词合集、命令手册、模板库 | **提示词与素材工作台**：顶部即时搜索与分类筛选 + 每条卡严格分离用途解读与纯净原文框 + 单条与批量一键复制 | 复制出的文本逐字等同原文，绝不混入按钮文字、标题标签或中文解释 |
| 剧本、分镜表、制作说明 | **制片与分镜对照型**：宽屏多列对齐（场号/镜头、画面、动作、对白、声音），窄屏自动转为每镜独立纵向组 + 场次跳转 | 严格保留原始场次与镜头编号，长对白完整显示不截断，缺省字段不编造 |
| `laohu-asrcut` 交来的剪后时间线审阅 | 按需加载 [ASR 审阅页契约](references/asrcut-review.md)（平时不读） | 严守唯一编译时钟、`planSha256` / `annotationSha256` 与注释来源分离 |

动手制作浏览器展示页前，读取 [展示美学、交互与验收](references/presentation.md) 中对应当前形态的章节；涉及正式质量评分或盲测协议时，仅在明确要求下查阅 `{PROJECT_ROOT}/docs/governance/evaluation-protocol.md`。

## 3. 编辑部美学与高杠杆设计原则

默认按高水准数字出版物或精工工作台的审美标准落地，让页面一打开就显得克制、通透、有秩序：

1. **有温度的纸感底色 + 克制单主色**：默认选用柔和低饱和中性纸底（如暖白 `#FAF9F6` / `#F8F7F4`）配纯净内容面 `#FFFFFF` 与深炭墨正文（如 `#1F2328` / `#2B2A28`），全页只取 1 个契合题材气质的沉稳强调色（如出版墨绿、深海藏青、刊物砖红、暖琥珀或石墨灰），靠留白比例、字阶差与极细实线边界立住层次；除非用户明确要求，不用刺眼的霓虹紫蓝渐变大横幅、厚重黑阴影或在正经标题前堆砌装饰图标。
2. **舒服的中文排印与行长**：正文单栏行宽保持在易连读区间（宽屏正文主栏约 680–760px，宽表格、镜头板与大图可适度宽于正文）；系统原生中文字体与等宽代码字体栈离线生效，正文 16–17px 配 1.75–1.85 行高，段距明显大于行距，章节上方留足空间，让视线能自然喘气。
3. **只加真正省事的实用交互**：优先把好用的细节做到位——长文带当前章节高亮联动与一键收起的目录（收起后正文优雅重新居中）、提示词与代码块带一键纯净复制与清晰即时反馈、多条目工作台带即时关键词搜索或标签筛选、按需提供浅色与护眼暗色或字号微调，以及隐藏工具栏的干净打印样式。

## 4. 保真、安全与单文件落地契约

1. **落盘与目录**：先按 `docs/runtime.md` 核对保存授权；未获保存授权时在聊天中交付方案或完整 HTML 代码块。获授权后沿用上游作品目录（尚无目录时交 `laohu-archive` 确定路径），不另建以 HTML 为名的作品分类。文件名直观表达用途（如 `reading.html`、`report.html`、`prompt-board.html`、`script-view.html`），同页迭代覆盖前核对重名，不堆版本后缀。
2. **单文件自足与离线可用**：交付完整的 HTML5 文档（含 `<!DOCTYPE html>`、`lang="zh-CN"`、`charset="UTF-8"`、`viewport` 与标题），CSS 与必要原生 JS 全部内置，零外部 CDN 字体、框架、追踪脚本或联网依赖；本地媒体与附件用相对路径并在移交时列明。禁用脚本时正文仍可完整阅读。
3. **原文零损坏与代码转义**：逐字保留源文的正文、参数、引号、换行、缩进、占位符、编号和列表层级。源文中包含 `<script>`、`</script>`、HTML 标签或不可信链接时，必须做严格文本转义或安全数据封装，只作可见内容展示，绝不注入可执行脚本或属性，也不靠粗糙正则宣称完整解析 Markdown。
4. **纯净复制与本地文件双级兜底**：所有可复制内容必须从独立纯净文本源读取（如专属隐藏 `<template>`、转义后的 `<script type="application/json">` 或纯净 `<code>` 文本节点），严禁对包含按钮或注释的父容器调用 `innerText`。复制逻辑按三级顺序执行：`navigator.clipboard.writeText()` → 失败时降级离屏 `textarea` 加 `document.execCommand('copy')` → 仍失败时自动选中纯净文本区域并提示用户按 Ctrl/⌘+C 手动复制；**只有确认写入成功才提示已复制**。

## 5. 交付前真实核验与回报

先让最核心且最易翻车的一处内容呈现与交互跑通，再收尾整页，交付前核对四项：
- **内容完整**：逐节回对源文，正文、参数、表格空缺、代码特殊字符、编号与素材无一遗漏或误改。
- **多视口体验**：未指定设备时，桌面按 1280px、手机按 375px 核对阅读层级、标题自然折行、目录收放与对比度（普通正文至少 4.5:1），并在 320px 核对无整页横向溢出（宽表、长链接和代码块局部滚动）。指定了目标视口则按指定视口预览并保留 320px 回流检查。
- **交互与复制实测**：核对每个按钮对应真实动作、目录跳转不被吸顶栏遮挡、纯净复制写出的真实字符串与原文逐字相等且在本地文件模式下有兜底。
- **诚实汇报**：有浏览器工具时实际打开核验后再交付；无浏览器工具时完成源码、DOM 完整性与脚本逻辑静态自查，并明确说明未做浏览器实机渲染核验。告知可打开路径（或聊天代码块）、页面布局如何服务本次用途以及已完成与未验证范围。
