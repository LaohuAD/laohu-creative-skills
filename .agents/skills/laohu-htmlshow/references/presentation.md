# 展示设计与验收

制作通用 HTML 时按当前内容选读：阅读与宽度、结构与导航、可复制内容、制作材料、交付检查。下面的方法服务于接收者实际使用，不是固定页面模板，也不要求每页使用全部组件。

## 阅读与宽度：先让文字读得下去

正文需要连续阅读时，用居中的单列文章区，行宽随屏幕收缩；宽屏不等于把每一行文字拉到整个屏幕两端。空间是否合适，看正文是否处于页面视觉中心、行长是否便于读完并找到下一行，而不是看是否填满像素。比较表、镜头板和图片可以比正文更宽，不让整个页面受最窄模块限制。

不要预留不存在的右栏，把全部正文挤在左半边。布局使用 `minmax(0, 1fr)`、内容区 `min-width: 0` 和媒体 `max-width: 100%` 等约束，避免长文本撑破容器。长 URL 和参数块局部处理换行或滚动，不让整页出现横向滚动条。

保留原文的段落、诗行和代码换行。普通文章不能把 Markdown 编辑时的每次软换行都变成 `<br>`；标题不按固定字数硬切，先调整可用宽度与字号。需要主动控制标题断行时在语义完整的词组或分句间安排，不在词组内部拆开。窄屏允许浏览器自然折行，不能为“完整标题一行”设置全局 `white-space: nowrap` 导致溢出。`text-wrap: balance` 可改善短标题行长，但不保证每次都在标点处换行。

从已有品牌或内容气质选配色，以稳定正文色与清楚的层级为先；没有品牌时用简洁底色和少量强调色即可。重要判断、解释、引文与参数应能辨认，但不要规定每段必须强调几个词。普通文字对比度以至少 4.5:1 检查；符合大字条件时至少 3:1。透明底、图片背景、禁用态与深浅主题都应按实际背景分别核验，不能只检查一个色值。

## 结构与导航：目录帮助定位，不挤压正文

短内容不必有侧栏。长文、多场次或多个独立模块需要快速定位时，以真实标题层级生成锚点目录；重复标题生成不同 ID，目录文本与正文对应。`h1` 到后续标题按内容层级安排，不为获得某个字号跳级。

桌面侧栏与正文滚动独立：固定在视口左侧，内部按需滚动；展开时为正文分配真实空间，收起后正文重新居中或扩展，不留下半屏空白。点击目录滚动正文，目录仍留在视口原位；为固定页头预留 `scroll-margin-top`，别把目标标题遮住。

有父子目录时按层级展开与收起，折叠不删除正文。长目录不能随主文整块滑走，目录自身提供滚动范围。默认使用明确按钮控制开合；只有用户需要悬停展开时才增加它，并保留按钮、键盘和触屏替代，不让鼠标移开导致正在操作的目录意外消失。

窄屏改为可开合抽屉或页面内目录，不能用固定宽度侧栏挤没正文。展开按钮有可理解名称和 `aria-expanded`，键盘可打开、访问条目并关闭，关闭时焦点返回控制按钮。若使用遮罩式模态抽屉，应同时处理焦点限制与背景不可交互；非模态侧栏不能冒充模态对话框。

## 可复制内容：看清楚与复制准确同时成立

提示词、命令和参数需要复制时，展示层可以提供标题、标签与解释，但实际复制对象必须是用户需要使用的原文。把解释标签与完整原文分开，使用专属数据节点或文本节点读取，不用整个容器的 `innerText` 把按钮、标签和说明一起复制出去。

原文里的引号、换行、占位符、参数顺序和负面提示词不得被视觉整理悄悄改写；HTML 编码只是显示转义，复制时要恢复实际文本。源文包含 `<script>` 等代码时显示为文本，不能执行它。没有证据的参数解释留空或说明未知。

只有比较或筛选确有用途时，才加入分栏、标签切换、搜索或筛选；不为了显得高级把一段短提示词变成复杂面板。折叠内容仍须可访问，打印或导出前展示必要正文。不要把重要的约束默认藏进用户不易发现的折叠区。

`navigator.clipboard.writeText()` 依赖浏览器权限与安全上下文，必须处理失败。仅在 Promise 成功后显示“已复制”；失败时提示并选中对应文本供手动复制。不能保证所有浏览器直接打开本地文件时都可写入剪贴板，也不以过时兼容 API 的返回值代替实际验证。

## 制作材料：用关系决定布局

剧本或视频提示词涉及时间与制作职责时，先保留原始场次、镜头 ID 和顺序。需要一眼对齐画面、对白、声音时可用表格或对齐的段落；长对白优先完整显示，不能为统一卡片高度截断。窄屏可改为每个镜头一组的纵向排列，字段关系仍清楚。

不同方案需要比较时沿用同一组真实维度；材料缺失处明确未提供，不虚构效果评分、成本或耗时。能以文字顺序解释清楚就不强造流程图；因果、分支或空间关系确实重要时再画图，并给可阅读的文字说明。

图像或视频旁放与它对应的说明；没有媒体就保留明确的素材缺口或使用文字，不拉取无关图片填空。图片提供与当前用途相符的替代文本。作品中的按钮、参数或截图只能反映真实内容，不能拿设计示意冒充已完成软件或生成结果。

## 交付检查：结构通过与使用有效分开

- **内容**：逐节对照源文；代码、参数、特殊符号、列表层级和素材引用完整。视觉摘要之外保留用户要求的完整材料。
- **尺寸**：至少检查一组桌面和窄屏，普通内容能在 320 CSS px 宽度重排且不丢功能。确需二维展示的表格、图示在局部滚动，不用例外放任整页溢出。额外检查浏览器放大后的导航和正文。
- **操作**：验证每个真实按钮、目录跳转、抽屉开合、键盘与复制结果；区分本地文件模式和本机 HTTP 模式，不能用后一种通过推断前一种必然通过。
- **交付**：完整 HTML 可打开，附属资源可定位；不带本机私密绝对路径、未声明网络依赖或自动发布。打印有实际用途时检查打印样式，避免工具栏遮住正文。

这些检查分别证明明确事实。实际阅读效果仍需观察，不能把 WCAG 某几个数值检查当作整页完整合规认证。

## 依据与适用边界

以下来源于 2026-09-24 查阅。只吸收会改变选择或验收的部分，不复制整套第三方样式，也不把其默认宽度当成所有作品的统一要求。

| 来源 | 用于什么判断 | 不能据此推断什么 |
|---|---|---|
| [W3C：Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 窄屏与放大时的内容重排；普通内容避免双向滚动，二维材料单独处理 | 不要求所有大表格强压成一列 |
| [W3C：Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 普通文本 4.5:1、大字 3:1 的对比度门槛 | 达标不等于层级清楚或整站已无障碍合规 |
| [W3C：Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/) | 用标题结构表达章节关系，支持目录与辅助技术定位 | 不要求所有文本都拆成多级标题 |
| [MDN：text-wrap](https://developer.mozilla.org/en-US/docs/Web/CSS/text-wrap) | 自然折行与短标题的平衡；避免用 nowrap 掩盖布局问题 | balance 不保证语义断句或固定行数 |
| [MDN：Clipboard.writeText](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText) | 按权限和成功状态反馈复制结果，保留失败后备方式 | 浏览器显示正常不等于剪贴板写入成功 |
| [GitHub Markdown CSS](https://github.com/sindresorhus/github-markdown-css) | 普通 Markdown 阅读页可参考其内容容器、居中和窄屏边距处理 | 它不解析 Markdown，也不负责提示词工作台、剧本关系或公众号兼容 |
