# 微信公众号排版专项

若宿主直接选中本配置，先回读父级 [laohu-htmlshow 主文](../../SKILL.md) 确认交付端、保存授权与工作项目；沿用父级上下文提供的 `{SKILL_DIR}`（指向 `laohu-htmlshow` 目录）与 `{PROJECT_ROOT}`。本专项资产根目录记为 `{GZH_ROOT}` = `{SKILL_DIR}/gzh`（含独立 AGPL-3.0 / MIT 许可台账、11 套主题组件库、通用组件库、5 个确定性 Python 脚本与预览画廊）。

本专项负责把已有文章转为可直接粘贴进微信公众号编辑器的 `<section>…</section>` 内联 HTML 正文，并产出内嵌本地图片的便携正文与一键复制预览页。静态规则检查、浏览器复制写入与微信端实际粘贴显示严格分账，绝不拿静态通过冒充微信端已验证。

## 1. 输入归一化与作品目录

- **作品目录与保存边界**：遵守父级与 `docs/runtime.md` 的保存授权。未获落盘授权时在聊天中交付排版内容；获授权后沿用已有作品目录（独立文稿由 `laohu-archive` 核定位置）。后文工作目录均指作品目录，不改写技能仓库资产。
- **格式归一化**：
  - Markdown 文本或 `.md` 文件直接进第 2 步。
  - `.docx`、`.pdf`、纯文本 `.txt` 或网页富文本，先读取 `{GZH_ROOT}/references/format-normalize.md` 转为保真 Markdown 草稿（`.docx` 运行 `python3 {GZH_ROOT}/scripts/extract_docx.py`；`.doc` 提示另存为 `.docx`）。
  - 转换只整理结构，绝不增删改写实质内容；识别结构后直接继续，交付时列出有影响的推断供用户按点修订，仅在材料缺失到无法保持原意时询问。
- **全自动与手动节奏**：用户要求排版时默认按内容自主选主题并完成全链；用户明说先看选项或自己挑主题时，先展示主题列表等待决定；用户说直接排、一键或不用问时，全程自动完成并在交付时附简明决策说明。

## 2. 按阅读气质选主题（以单一索引为准）

先读取 [主题索引](../../gzh/references/theme-index.md)（11 套主题、主色、适用场景与正文下划线 CSS 的唯一真源）。主题分为两大阵营，按文章真实阅读任务与结构选一套完整落地，全篇绝不跨主题混用：

- **杂志卡片与视觉扫读阵营（原 6 套组件库）**：适合需要丰富结构块、明显视觉节奏与强扫描感的文稿——教程清单与工具盘点常用摸鱼绿（默认主题），强观点深度分析用红白色系，设计科技评论用石墨极简风，慢读随笔用留白禅意风，对比评测票据隐喻用摸鱼票据风，系统复盘内刊质感用橄榄手记。
- **纯净纸感长文连读阵营（WeDraft 本地适配 5 套）**：适合重视连续阅读舒适度、克制留白与优雅刊物秩序的文稿——生活随笔用素笺（`wedraft-plain-paper`），深度人物报道用墨刊（`wedraft-ink-journal`），人文知识长文用青岚（`wedraft-jade-notes`），技术方法数据用蓝图（`wedraft-blueprint`），文化观点叙事用朱砂（`wedraft-cinnabar`）。

若多个主题都真实适配，仅比较最贴近的 2 项（必要时补第 3 项），从阅读路径、信息密度和组件节奏上裁定 1 套直接执行，交付时一句话交代选择理由；无明显倾向直接用索引第一行默认主题。用户对现有主题都不满意、要按参考图调单篇风格，或明确要求新建可复用常驻主题时，转入第 6 节。

## 3. 读取组件库与原文结构解析

选定主题后按分支读取两份材料：
1. **原 6 套主题**：读取索引中对应的 `{GZH_ROOT}/references/theme-{标识}.md` + [通用增量组件库](../../gzh/references/common-components.md)（代码块、图片/GIF/占位、小标签标题共用，换色以所选主题变量为准）。
2. **WeDraft 5 套（`wedraft-` 前缀）**：读取对应 `theme-wedraft-*.md` + [阅读主题适配与装配](../../gzh/references/wedraft-adaptation.md)，将源文逐块保真编译为语义块 JSON 存入任务缓存，再调用确定性装配脚本输出正文片段（不安装或联网调用上游应用）：
   ```bash
   python3 {GZH_ROOT}/scripts/render_reading_theme.py --theme <wedraft-标识> --input <语义块.json> --output <初始正文.html>
   ```

### 零编造文案红线与精准解析规则

1. **严格文案来源边界（一切文字槽只取真源）**：排版只做视觉承载，**绝不代作者补写**封面钩子、副标题、引言金句、英文副标签、提示标签（如模板里的 `NOTE` 或 `END`）、GIF 动图角标、评分星级、作者署名、简介或点赞转发引导。原文已有或用户明确提供/授权的文字逐字保留；缺少来源时，**省略该文字槽及专属分隔符**（容器仍承载原文内容则保留容器与正文，整块无原文依据则整块省略）。仅说排版、直接排或一键排不构成新增文案授权。
2. **可复制载荷与行内术语按用途分流**：只要原文语境或用户意图表明一段内容是供复制、运行或配置的代码、命令、Prompt 或参数片段，无论原稿写成围栏、反引号还是普通段落、无论单行多行，一律进入独立可复制容器（代码与终端命令用通用库 1a 深色 / 1b 浅色或主题代码组件，含 Tab 缩进时附 `tab-size:4` 防手机端过度折行；原字符包括普通空格、Tab、空行与末尾换行一个不改，只做必要 HTML 转义，不猜填原文未提供的语言名；自然语言短 Prompt 若与程序代码同篇出现，优先用视觉上区别于程序代码的独立浅底/左竖条块承载且保持标签与本体视觉紧凑）；仅在句中作说明的文件名、函数名、变量名保留行内身份（先用主题等义组件，缺项用 1c）。载荷外的标签与解释文字留在原位，绝不混入代码节点。
3. **精细格式保留**：行内语义遵循 `common-components.md`（加粗、高亮、下划线、删除线、行内代码语义严格不互换）；保留 Markdown 行末双空格硬换行（`<br>`）、DOCX 转出的表格单元格 `<br>` 与四个不换行空格分隔。
4. **结构与标点自动处理**：
   - 章节按 `##` 顺序分配 `01 / 02 / 03…`，不跳号；末章为结语且主题定义了结语变体时使用结语符号，若原文严格要求一字不改或主题无结语变体则不把结语硬凑成多余数字序号。
   - 导读/目录组件（仅在主题骨架包含且原文有足够章节时使用）：默认精选最能体现本文核心价值的至多 3 个看点，按原文顺序排列并保留正文真实章节号，不足 3 章不凑数；用户要完整目录时列全章。
   - 中文叙述使用全角中文标点与弯引号；完整英文句子、英文专名、URL、代码标识符与代码块内一律保持原英文标点与直引号。

## 4. 按配方装配与视觉克制节奏

1. **先查配方再走骨架**：判定文章主导类型（教程、盘点、观点、访谈、数据复盘、随笔、案例），按所选主题的「文章类型 → 组件组合配方」与「完整文章模板骨架」装配，不逐段随机拼贴，也采用该主题「连续手机阅读的主题节奏」检查点。
2. **三层视觉密度克制**：原文已有的加粗、高亮、下划线、删除线全量按语义保留且不占新增配额。排版确需新增强调以辅助扫读时，仅标记原文已有的关键判断或词句，不改变语义主次与情绪力度：
   - **锚点层**（主色加粗 / 强引用）：全篇新增默认不超过 5 处；
   - **标记层**（下划线，样式严格取 `theme-index.md` 的权威 CSS）：每段 0–3 处，无需扫读定位时为 0；
   - **容器层**（引文、提示、卡片）：仅用于原文确有独立语义角色的内容，普通连续论证留作稳定正文基底。
3. **元素选用铁律**：
   - 突出小标题或局部提示用通用库左竖条或药丸标签（3a–3e），不拿四周虚线框套普通标题（主题库明确定义的特色虚线卡片与 2c 居中待补素材占位除外）。
   - `【插入…】` 等待补录屏、截图或动图占位一律使用通用库 2c 居中板块，绝不伪造图片地址或删除图片来凑通过。
   - 图片一律 `max-width:100%;height:auto;display:block;margin:0 auto`（自适应居中，不用 `width:100%` 拉糊小图）；有真实图注才加说明段；每张图逐一落实 `alt`（优先保留原文方括号或输入 HTML 的 `alt`，绝不留占位词；无来源且看得到图时据画面信息简写，无视觉证据但属信息图则标缺口待补，仅确认纯装饰图才留空 `alt`）。

## 正文片段静态规则

交付的干净正文必须是从顶层 `<section>` 开始的纯正文片段，绝不包 `<!DOCTYPE>`、`<html>`、`<head>`、`<body>`：
- **严禁**：`<style>`、`<script>`、`<title>`、`<meta>`、`<base>`、`<link>`、`<div>`、`<svg>`、表单与交互媒体标签（`<button>`、`<form>`、`<input>`、`<select>`、`<option>`、`<textarea>`、`<video>`、`<audio>`、`<canvas>`、`<iframe>`、`<object>`、`<embed>`、`<source>`）；`class`、`id` 与 `on*` 事件属性；`position:fixed/absolute/sticky`、`float`、`@media`、`@keyframes`、`@import`、`display:grid`、CSS 变量 `var(--*)`、外部字体 URL。
- **必须**：所有样式写进内联 `style`；所有可见文字节点用 `<span leaf="">文字</span>` 包裹（装饰性空元素内放 `<span leaf=""><br></span>`），防止粘贴进公众号后整片丢样式；`<span leaf>` 内禁止嵌套块级标签，同类同样式单子节点嵌套不超过 10 层。
- **渐变提示**：纯装饰背景允许 `linear-gradient`，有可见文字压在渐变底上时优先改纯色底或移至无文字装饰层。

## 5. 便携打包、强制校验与预览交付

严格按顺序走完以下 4 步才算交付完成：

1. **保存初始正文并生成便携包与预览页**：初始正文命名 `{原文件名}_排版_{主题中文名}({英文标识}).html`，运行便携打包（自动将本地图片按原字节和校验后的 MIME 内嵌为 data URI，不修改初始正文；缺图或 MIME 不符会直接报错停止）：
   ```bash
   python3 {GZH_ROOT}/scripts/wrap_preview.py <初始正文.html> --portable
   ```
   产出 `{...}_便携.html`（供移交和校验的干净正文）与 `{...}_预览.html`（带 375px 手机 / 700px 宽屏视图切换与一键富文本复制按钮的预览页）。仅当用户明确要求覆盖原正文时才加 `--in-place`。
2. **强制静态规则校验（必跑便携正文）**：先按需核对 [结构检查规则](../../gzh/references/structure-validation.md)，再对 `{...}_便携.html` 运行校验脚本：
   ```bash
   python3 {GZH_ROOT}/scripts/validate_gzh_html.py <..._便携.html>
   ```
   必须看到「内置静态规则检查通过」（退出码 0）才算本地静态校验完成。遇 ERROR 或未处理 WARN 逐个定位到触发节点修复并重跑；仅依据规则确认为具体合法例外时，才使用 `--accept-warning RULE@NODE=具体依据` 单节点放行，严禁批量忽略。同时逐张图片人工核验 `alt`（脚本不查 `alt`）与代码节点提取文本逐字符对照源文。
3. **连续手机阅读复核**：有浏览器工具时打开 `{...}_预览.html`，切至 375px 手机宽连续滚读开头、正文与后段（并在 320px 核对长链接、代码与宽表局部滚动无整页溢出）。检查强组件是否连屏争抢、正文基底是否稳定、论证是否被多余留白割裂、图注是否紧跟对应图片；若过密则只撤回不承担内容职责的新增装饰，不削弱主题特征也不改写原文。
4. **诚实汇报与粘贴兜底**：告知用户打开 `{...}_预览.html` 检查手机/宽屏效果并点击复制，再粘贴进公众号编辑器复核真实图片与样式；同时交付已校验的 `{...}_便携.html` 路径与校验结论、alt 人工核验状态，以及所选主题理由和重要结构推断。未经真实公众号编辑器实贴，微信端显示状态记为未验证（`UNKNOWN`）；若用户反馈粘贴出现差异，只定位受影响组件与最小内联属性修补重验，不借换主题或改文案掩盖。

## 6. 风格调整、复用主题建设与开源主题迁移

按用户所需产物严格分流：
- **单篇换风格**（如这篇不要现有主题、按参考图给这篇排一版）：读取 [风格设计与复用主题生成](../../gzh/references/theme-generator.md) 的单篇分支，成品与预览落在当前作品目录，不改 `{GZH_ROOT}/references/` 与主题索引。
- **长期建设新主题或迁移开源主题**（必须有用户明确授权）：读取 `theme-generator.md` 的长期分支完成专业设计与预览，再交 `laohu-evolution` 协同写回 `theme-{标识}.md`、登记 `theme-index.md` 并跑通 `python3 {GZH_ROOT}/scripts/component_lint.py {GZH_ROOT}`（0 ERROR）与真实文章 `validate_gzh_html.py` 校验。

新主题的 5 个必备章节（供 `component_lint.py` 校验）：设计变量速查表、各组件完整 HTML（内联 + leaf + 合规）、完整文章模板骨架、文章类型 → 组件组合配方表、Markdown → 组件映射规则表。
