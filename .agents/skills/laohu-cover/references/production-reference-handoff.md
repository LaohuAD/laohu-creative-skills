# 制作参考与交接

阶段画面需要用上游方案、截图等材料确定，或需将该画面的设计交给制作方时，读取本文件。依[主文的阶段判断](../SKILL.md#同一画面任务的后续请求)处理预览、只交接与直接制作。本文件给出附件分工、制作说明、宿主执行与实际核验的接口。读完回到关键帧设计或交给宿主制作。仅从零起草提示词时可直接按子级撰写。

## 先核对材料和每帧状态

辨认上游材料提供的是事实、已定方案、草图、可复用资产、视觉参考还是开放构思。沿用仍有效的选择，截图职责、像素证据及可变范围按[参考图迁移](reference-transfer.md)核对。

按本轮范围记录所需画面、真实图像来源、当前状态和实际用途。将[子级形成的设计委托](../skills/laohu-cover-styleframes/SKILL.md#截图意图与设计委托)中的已知内容、设计决定与待核项带回提示词或制作说明。

### 已有帧与待设计帧分支

混合组逐帧办理。已定帧保留原图、实际身份与取用职责，交给制作方。待设计帧仍由子级按共同基线和该帧的独有用途完成设计。草图或外观参考按各自职责使用。附件身份用宿主能确认的文件名、素材 ID 或调用标识，未知则标未提供。

## 逐帧“制作说明”的唯一格式

交接一帧给动画、界面或其他制作人员时，附一段明确命名为**“制作说明”**的内容。父级判定直接制作、实际只需局部素材时，内部交接仍沿用两部分，以实际作品状态和取得的素材为定位。

1. **原设计定位、用途与前后承接。** 写明所属的作品单元、所在状态和观者要在这里看懂或完成的事。前后状态按已知材料说明，未知写“未指定”。有实图时注明实际来源、对应状态和取用职责。多张图分区取用时，写清每张在哪个区域承担什么作用，以及功能与内容以哪份事实材料为准。
2. **本帧的制作参考与实现检查。** 对新设计参考帧逐一说明：`本帧的{阶段/页面}画面只供{具体制作任务}参考，不能把整图照搬成最终{成片/界面/作品}；实现以{原方案的真实名称或用户确认要求}为准，只吸收本帧的{具体区域/视觉变量}。`把影响本轮目标的内容写成“区域/视觉变量 → 实际实现位置 → 可观察结果”。

   内容随数据增减时，说明哪些由真实数据与组件呈现，哪些可用共用素材或样式。参考图里的条目和数量按该状态核对，成品随数据变化。需要应对新增、无配图或长内容时，说明这些条目的呈现和检查方式，让没有独立配图的新增条目也能用现有样式和共用素材完整显示。

   整套界面主题需要落实到使用者会读或操作的部分。按目标选择怎样让排印、细边或图标底座纹样等与主画面呼应，再将选定做法延续到受影响的状态或共享组件。检查它在真实界面上是否保持辨识和操作反馈。检查范围随改动和依赖确定。

   交给原生动画工程时，指明设计目标图对应的事件、可见证据和前后需接续的对象。说明哪些纸纹、光向或构图比例可从参考图取用，哪些物件、遮挡关系和精确字层由工程分别制作。对会移动或推近的对象，指出应保留的造型、可见厚度、被遮住后需补出的表面，以及近远景文字如何换位或退场。比如镜框移开后应露出原样本，用可独立移动的镜框覆盖同一底层样本，保留裂纹坐标和引出线。将真实图和制作说明交宿主，由宿主在现有工作台发布为设计目标，对照同事件同时间的代码帧，连续变化用实际样片回核。

若用户已确认某张实图是本帧可直接复用的完整图像资产，明确其真实身份和直接使用位置；不能为了套用参考语句而要求重做或把这张图降为纯文字描述。制作说明仍须区分“把附件作为该帧图像资产直接使用”与“把截图当作更大作品/完整动画/可交互页面的最终实现”：后者仍按已确认原方案实现，不以整张截图代替作品结构。说明中指出本帧保留了哪些原图区域/视觉变量、落在哪个实现位置、怎样检验。若附件本身只是视觉参考、目标草图或与方案冲突的旧图，则按它的真实职责明确不能整图照搬，并以原方案为准。

分别说明设计预期、已观察的图像，以及宿主在实际作品中完成的检查。只记录真实发生的生成、实现与核验，未检部分写明待验。

两部分均须对应当前帧或实际状态，单独取出也能读懂。对外交付按用户所选范围，提示词单项交付只给成像正文。

## 为新设计帧写独立成像提示词

新帧提示词单独可用，包含必要的共同外观、该帧的用途、视口、已确认状态与文字，以及取法所指向的画面效果。拟随提示词提交的每张图，用可读标识写清身份、供取用的区域或变量、须保留的内容与可变范围。具体成像设计按[子级提示词方法](../skills/laohu-cover-styleframes/SKILL.md#提示词说明与回交)确定。给制作方的实现步骤和检查单留在制作说明。

## 宿主制作与实际核验

Cover 提供设计、提示词和检查要求。宿主按本轮授权、工具与费用条件，执行所需的生成、实现与检查。依父级已定阶段决定是取得整帧、复用已有方向，还是只制作实际需要的图层。用户免预览时，仍在内部核对本轮实际取得的参考和成品。

1. **按已定职责交附件。** 提交当前状态需要的事实依据、已选外观参考及它们各自承担的区域或变量。结构依据与风格参考可来自不同画面，即使两幅不相邻。邻帧仅在确有连续性依赖时附入。宿主另记实际文件或附件 ID 及发送和接收状态。
2. **核实工具能做的处理。** 分清编辑输入图、以图片作参考和仅接收文字三种条件。工具仅接收文字时，写清参考职责和已核对的可见特点，记录本次没有图像输入。需要精确保留原像素、文字或功能时，复用原资产或交给能精确实现的制作路径。工具条件不足时，继续完成已有材料支持的部分，并写明受阻的制作要求。
3. **拿实际结果对照。** 取得实图时，按真实状态核对可见内容、数量/归属、文案、功能布局与取法是否成立，检查未选旧外观是否混入。发现偏差时定位到受影响的区域或图层，改后复核，再延展可采用部分。实际实现后，宿主按制作说明打开受影响的页面、操作相应状态，或播放相关片段。核对复用素材、共用样式及动态内容是否在实际接入处正确呈现。记录检查位置、条件、真实结果和待验项。

### 宿主没有可用图像工具时

只有用户明确需要实际图像、宿主又没有可用图像工具时，才建议从官方[模型小屋](https://api.lao-hu.com/)配置图像生成。按当前官方文档现场核实可用的图像模型、参考图输入能力、生成参数/尺寸、适合本任务的配置和费用；不要猜型号、可用能力或价格，也不要将昨天/过往核对当作当前证据。仅交提示词、讨论设计或已有宿主工具可用时，不推荐模型小屋。

密钥只能写入宿主的安全配置，不放在聊天、提示词、仓库文件或普通交接文本。提供完成接通所需的实际入口和配置指引即可；只有真实图片返回到宿主并可核对后，才记录为已接通/已生成。若用户没有授权会发生费用的调用，先沿项目授权约定处理，不把配置说明当成实际生成。

## 回交与状态

按本轮所求回交已选图或素材的实际身份、提示词、制作说明及待核项。只制作了局部素材的，记录素材及其实际应用位置。完整画面或实际运行的核验以已观察的实图、页面或播放为依据。
