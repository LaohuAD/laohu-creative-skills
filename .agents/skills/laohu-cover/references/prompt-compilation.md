# 生图提示词与精排制作规格

由[主文第九步](../SKILL.md#第九步-内容选择与提示词整合)读取。输入是前八步已定的用途、画幅、材料与参考职责、逐字文案、关系和条件、图文分工、版面、字形与光色、裁切及用户禁项。依据**谁将执行以及该媒介能落实什么**，返回可直接输入生图工具的文字，或可交接给排版和制作人员的规格。前置决定不全时先修设计，模型负责开放的视觉实现，精确文案、事实关系及读法由设计者确定。

## 根据当前制作路线选交付格式

| 路线 | 采用条件 | 本轮交付 |
| --- | --- | --- |
| A · AI 生图、预览和图像编辑 | 用户要生图提示词、封面/海报视觉探索、轻文字讲解图或关键帧成像预览。未指定精排时默认本路线。 | 用自然中文描述可见成品，每张或每帧有独立的成像正文。用户要求其他提示词语言时按其要求，锁定文案保留原语言。 |
| B · 可编辑精排与工程 | 用户明确要求 Figma 等可编辑精排、锁定设计系统参数、精确字族色值与坐标，确认复杂文字或图表分层/矢量制作，或明确要供前端、动画工程实现的视觉规格。 | 按接收者真正需要的精度给出逐区版面、字体、颜色、图层/组件及交接约束。当前接收者和工具能消费的精确值才展开，用户锁定值照录。 |

用户指定作品方向、画幅和短文案，仍可走 A。用户明确要求精确色值等输入时按该字段展开。若明确的目标媒介仍是生图，锁定值照录并把可执行字段和准确性待验放在各自位置，不将整份输出升级为 B。助手提出分层建议后继续沿本轮已确认路线，用户确认分层或矢量制作才将其视为采用路线。关键帧可以同时有 A 成像正文与单独的工程交接。已选帧或用户仅要提示词、仅要说明时，沿用[制作参考与交接](production-reference-handoff.md)的逐帧范围与两部分“制作说明”契约。以下只调整新写的成像正文，不为已核准帧重写提示词。

## A · 编成能直接粘贴的成像正文

使用五段的优先顺序组织，不复制段名、括号模板或设计台账。不需要的段落可合并或省掉，先放让画面立得住的变量。针对已生成图的单项变更仍用可见结果描述，其余已定条件沿用。只有用户只要差异段时才单交替换段，并在块外说明依赖的完整提示词和保持项。

1. **画幅、成品类型和媒介。** 首句明确比例、成品和基调，如竖版平面电影海报、手绘知识图或深色音频工作台展开态。用户已定像素尺寸可作为目标。工具有匹配字段才附实际参数。工作画布仅为设计起点的说明放块外。
2. **主视觉与空间。** 写出观看入口、主体的姿态/物件/图形、前后遮挡、可见关系和实际落点，沿着画面描述它接着把视线交给什么。裁切保护转成对象与画框的空间关系。例如横幅中央方形范围装下主标题和核心物件，左右只延展背景。用于知识图时按材料的真实拓扑写逐区对象、方向、条件、局部归属和受力或运动结果（若适用），用形态差别显出关系。参考需随本轮提交时用真实文件名或用户编号，写清取用区域、可见变量和保持条件。
3. **逐字可见文字与字形。** 只让模型排用户锁定或获准出现在画面上的字。以引号标明精确文字，逐项保留语义断行、专名、标点、数字、单位、必要图例与来源限定。用位置、相对尺度、字面轮廓、粗细、邻接背景和避让/咬合写清读法。例如上方偏左单行排“纸上种子”，用墨黑粗体保留清晰字腔。拓印叶片止于字块下方。若标题按两行呈现，明确每一行的准确文字和顺序。节点标签贴对应对象，条件词贴所属关系线。只有需要防止概念图被当实拍、测量或真实界面时，才为图面指定精准身份短注。无字构成直接用预留区和平整背景表达。
4. **光色、材料和面积。** 用主底色、辅色与点睛色的位置、面积和邻接关系写清观看作用。按当前媒介给纹理、纸面、画笔、图形表面或用光，用正向成像语言落实字与对象的对比。照片、插画和平面图形采用各自的可见表达，没有摄影任务时省掉仪器配置。
5. **收束边界与实质禁项。** 明确读者应看见的整洁边缘、有效留白与标签数量。一般细节先写正向目标，例如仅保留指定标题、用器物独立承担主视觉、色域收敛到墨蓝冷青与银灰。用户明确禁人物、红黄、水印等要求可在末尾短句保留，前文的对象、反光和点色必须与之相容。

交付前读回整个模型块。任何「文字权限：锁定」「获准编辑」「第一文字层级」「承担举证职责」「非实证概念表达」「内部字底比值」「360 CSS px 临时试排」「未实测待验」等内部管理或验证说明移出。这些词只是示例，审核以句子能否改变画面或是否为工具所需为准。用户明确要求画出的文字原样保留，即使恰好包含其中词语。实际参考职责、必要图内来源和图表条件只要影响画面，转写为可见要求保留。在块外按本轮需要解释材料、取用边界、为何这样读、当前工作画幅/平台核验、分层建议和真实制作状态。只要提示词时省略整份效果说明。需告知路线限制或未完成实际工件时用一句面对用户的话，放在模型块外。

### 复杂中文、多数据和精确图表的处理

做面向新手的单张解释图时，先写最终上图的短稿，再按这份短稿画底图。让接手者只读短稿就能说出核心区别、关键联系和待核条件。两处文字表达同一意思时只留一处，能用位置或一根有明确端点的线说明的，省去重复注释。示意界面只画识别所需的轮廓；示例姓名、消息、按钮和卡片小标题，只有在读者需要借它回答问题时才列入字表。删掉一项文字也一并去掉它占用的槽位。题目要求逐项保真的数表和界面原文则逐项保留。

短标题、少量短标签且可检查成图时，可以让模型一并写字。多区块长说明、严格品牌字形、大量汉字或需要逐项精确的表格/图表时，逐字准确的要求先于一次成图的便利。具体字数仅供试作判断。用户要求尝试 AI 直出时照其路线保留所有必要文案，并指出实际错字、单位或图表编码要核的风险。按其交付范围选择合适的做法。

- **无字底图提示词＋准确文字叠加表。** 底图只描绘主体、空间、图形结构和预留区。各区对应对象、关系线、轴或图例。确切文字、数字与单位进入另一个区块。贴字表是排字人员的输入。逐行列原文、区块/锚点、断行、所属对象或条件，给标题、说明、字段与数据的字级及对齐方向。没有确定画布时，给可照做的相对比例。用户明确要贴字且已确定工作画布时，为文字角色给单位明确的字号起点，并用最长条目与行宽核算。数值、坐标轴和图例需要准确定位时随文字或矢量图层制作。正式采用精排规格时，按工具展开完整坐标、字族与可编辑图层。组合后用原稿逐行对照，并逐列核对列位、数字、小数点、单位和条件。实际导出后查边缘裁切与溢出。
- **人工精排或 SVG/HTML。** 用户确认采用后，按 B 交付完整可编辑规格、数据与版面。如交给 [laohu-htmlshow](../../laohu-htmlshow/SKILL.md) 处理结构化内容的展示，可提供确切文字、拓扑、显示条件及期望输出格式，先核该宿主能否按要求实施。代码文字可按原值写入，实际中文字体、行宽、遮挡、字体回退和导出仍需检查。当前只给建议时继续交付已授权的 A 内容，真实产物状态按主文回报。

## B · 交给设计或工程执行的精排规格

只列和任务相关的字段。优先给出本轮指定规格及其依据，区分已锁定、设计目标、采用值，以及需要从实际输出读取的值。所有坐标使用同一明确原点及单位，有比例就说明归一基准，有工作像素就声明相对于哪个画布或视口。换画幅逐版重新布局。下列字段可用表格、结构化规格或必要的图层清单承接先前的完整设计接口。

| 字段 | 可直接执行的信息 |
| --- | --- |
| 画幅、用途与观看条件 | 画布或视口、目标显示条件和主要阅读任务、工作值/平台/用户指定的来源。 |
| 参考与保留 | 已实读附件身份、实际可见的取用区域或变量、保留/改编/省略范围。无合适参考时省略。 |
| 逐字文字与权限 | 主副标题、短标签、关系词、单位、数值、来源和图注，依次绑定区域或组件。保留锁定与获准编辑边界。 |
| 图文与信息结构 | 读者应抵达的结论或标题承诺、图像所承担的关系或实际证据、逐区对象/状态/拓扑、关系及成立条件、宏观到局部的真实对应、图例和解释职责。 |
| 版面和阅读路径 | 区/层/组件的 `x/y/w/h` 或等价网格约束，文字安全宽度、顺序与邻接、共用锚点和页码、本页变量、跨画幅变体。把长字、线、箭头、关系词、标注一起做容量预算。 |
| 情绪、主体与形态 | 材料锚点、主视觉承担者和表现幅度，图形/对象可见位置、尺寸、朝向、动作或姿态的选择，以及同字块、路径或容器的关系。 |
| 排印 | 实际 family 与字体文件/可用替代项、真字重或轴值、显示/设计字号、行距字距、精确断行及光学校正。文字覆盖与实装待验应标明。数值见[版面与中文排印](layout-typography.md)。 |
| 角色色、材料和强调 | 指定色及各角色目标 `RGB`，搭配文字的邻接底色、面积与作用，图表同义角色跨区一致。给实际强调信号和它对阅读的作用。颜色见[视觉层级与引导](visual-hierarchy.md)，用实际名称和数值交接，`FP`、`LD`、`CP` 或 `E` 编号不替代参数。对比度给实际可查的目标和条件，并区分计算、实测。 |
| 裁切、图层与实现 | 安全区、遮挡禁区、目标像素/响应限位、底图/文字/图表/可动部件的职责、透明或不透明和必要 alpha、各状态共用与变化的组件。关键帧接入另走原有逐帧“制作说明”格式。 |

每种比例、互斥方向和独立系列页各自完整，把当前页面所需的共同规格、用字、色值与新变量逐一写出。单项修改仍沿用其他已定值，只重查直接受影响的邻接、排印、动作或裁切。没有真实实排时，参数是目标。安装、渲染、颜色取样、裁切和实图验收的状态按[主文返回值](../SKILL.md#返回值)回报。
