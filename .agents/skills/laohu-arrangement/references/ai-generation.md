# AI 音乐生成与演唱控制编译

由主文确定“生成模型负责什么”后，以及需要把声音蓝图编译到音乐生成接口时读取。读者是本次生成包的编译者。输入至少包括目标成品与模型可决定的范围、声音蓝图、目标平台与本轮实际模式，以及本轮已确定或需要保护的音乐/音频材料。人声或其他有词作品还要辨明原始词稿、本轮演唱稿及词曲对应关系；其版本身份、授权和回填按[词曲交接与回填](composition.md#词曲交接与回填)承接。纯器乐沿用共同蓝图和音乐事件，不要求歌词材料。用户只讨论方案且平台未定时，先给平台无关的声音方案；普通嵌入式人声接口在平台未知时不触发裸歌词回退，默认编译英语 Style Prompt 正文与英语标签内控制指令的嵌入式 Controlled Lyrics，并把接口接受状态标为未知；用户明确要求中文时两者均用中文，嵌入歌词保持原文不翻译；明确要求双语时交付两组完整、等价、组名唯一的输入。用户指定 YuE2 外部 ABC 三输入时，改按下方 YuE2 分支分别编译英语 Style Prompt、未加标签的原文 Lyrics 和 native ABC。缺少材料只暂停依赖该材料的控制，不虚构平台字段、旋律或模型已经做到的效果。完成后把每个方向的可复制输入和实际无法传递的控制交回主文第八步验收。

## 先锁定生成任务和决定权

按本次实际输入选择一条路径：

- **从文字生成**：模型可探索未锁定的旋律、伴奏和制作细节；已锁定歌词、明确曲式或保护项仍须按用户要求保留。没有旋律时，不得声称模型能精确保留一条尚不存在的旋律。
- **从旋律/导唱生成**：标出要保留的音高、节奏、段落和可改编范围；只有接口确实接收该素材时，才能把它作为模型输入。生成后将对应内容逐句与源材料核对。
- **续写、改编或变换已有音频**：先区分用户要模型保留的音乐身份、允许变化的部分，以及当前接口正式提供的操作。把参考、续写起点、Cover/Remix 源和风格参考分别命名，不用“上传音频”代替保留范围说明。
- **只讨论生成方案**：交平台无关声音蓝图和待编译字段，不伪装成可以直接投喂的接口包。

在生成前逐项标成“锁定 / 本轮允许生成 / 待试听决定”，并把来源保全与音乐定稿分开判断：用户已锁定的音乐事件按范围保持；作者暂定稿只在本轮授权改进时返回创作步骤；忠实转换按可信来源投影指定事件，不顺手润色。歌词生成包中的“锁定稿”指已按既有授权核对、确定用于本轮表演的**本轮演唱稿**；若其相对原始词稿有变化，先核对差异再确立本轮生成基线，不得用改写基线追认超出授权的修改。保留原文件不等于音乐不可修改，存在文件也不等于用户已确认。开放项不必精确到平台没有依据承接的程度。目标平台和模式一旦确定，只使用当轮真实可见且已核实的字段；UI 控件、官方 API 与第三方封装是不同接口，名称不能互相挪用。

## YuE2 外部 ABC 三输入分支

仅在用户明确选用 YuE2 外部 ABC 接口，或给出可核对的对应服务 schema 时进入本分支。三个输入各司其职，顺序为 `Style Prompt` → 原文 `Lyrics` → native `ABC`；这是一项用户指定的接口约定，不把字段名扩写成未核实云 API。Style Prompt 默认用英语，写清作品声音身份、专业配器/制作、歌者音色与实际唱法，以及必要的段落和完整乐句控制动作；每项段间变化标出乐段或歌词锚点。Lyrics 只放已核对的本轮演唱稿；歌名作为元数据置于该输入之外。改词、段落标签/结构、段序/回返和演唱排版的授权分别判断：获准调整时按共同方法与原始词稿核差异，再以本轮演唱稿为准；未获准的原词句、标点、锁定段序与排版仍须保留。不嵌入演唱标签、不翻译、不按汉字数绑定音符。ABC 从已完成的音乐事件编译为两条单音声部和适用的和弦符号；它表达主唱旋律/节奏与一条器乐主题，不代替完整鼓、贝司、和弦配器或混音计划。

选择 `full` 或 `melody` 取决于本轮需保留什么：`full` 让谱面承载旋律与和弦符号；`melody` 去除和弦符号，但按用户的保护范围保留 Vocal 与 Ins 两条旋律事件、休止与时间格。翻唱不自动等于 melody；若须保留原和声或指定和弦就选 full。已有 ABC 默认先保护并投影到 native profile，不重规划、不重转写；缺少可信旋律谱时，只在用户授权下另作音乐创作，不从音频调用 SheetSage2 转谱，也不提供本地 YuE2 推理教程。

native 格式细则、ABC bounded checker、ComfyUI 节点接线、Style/ABC 冲突处理及时间上限见[YuE2 外部谱编译](yue2.md)。本分支只说明适用路由，不声称实际云端接受或模型必然遵从。

## 把声音蓝图写成有层次的 Style Prompt

人声作品的 Style Prompt 与嵌入式控制从主文第三步已完成的声音蓝图、第四步的全曲协调、第五步的演唱与制作意图、第六步的回听修订，以及本轮实际选定风格子级已写明的决定中编译。先从这些已完成决定中提取听者需要记住的实际音乐材料，包括主唱材料、器乐动机、riff、groove 或音色运动，核对其节奏/轮廓/重音/落点/音色关系、首次出现和有目的的回返；声音角色（如“主导”“支撑”）本身不是音乐材料。若主唱承载作品主要情感或意义且蓝图未另定听觉中心，须提取已设计的主唱记忆材料及其节奏/旋律轮廓/重音/落点/首现和回返，另外提取必要的音色与细微表演线；承担歌词转折/承转的完整乐句可以与记忆 hook 不同。再从同一主唱事件提取已定的伴奏基础支点：先明确维持该段拍感、能量方向与和声所需的关系；对实际采用的节奏、低音与和弦/持续层，保留它们在主唱关键重音、延展、释放和下一入口处的起音、时值/包络、音区及保持/变化，再编译回应、留白与装饰。若主唱不是听觉中心，按蓝图指定的中心编译，不强加主唱材料。若有歌词，再核对完整乐句之间的对照、复沓、呼告、设问或收束，并读取已定的起音、重音、连断、时值、承重词元音延展与释放。编译阶段不得临时补选或虚构核心材料；若蓝图缺少必要决定，返回主文第三/第五步完成设计后再编译。Style Prompt 与段级/句级标签共用同一组已定决定：全局基线进入 Prompt，标签只承载相对基线确已决定的局部增量。下列三个字段是本项目现行的 Style Prompt 组织方式，不是从 V4 引入的运行时方法：

- **Global Metadata**：风格/融合方向，速度、拍号和身体律动，全曲情绪运动，以及声场和制作轮廓。写已经定下的关系；不把情绪词当作节奏、音区或动态命令。
- **Vocal Details**：主唱身份、相对音区、音色、距离、咬字、已定的主唱记忆材料与必要表演线、和声层数/进入位置和少量效果。只写作品或用户已确认的声线条件；不能由歌词自动推断性别、声区或唱法。声部需要表达“主唱在前景”时，还要编译其具体记忆材料/表演主体，不能只保留角色词；气声、混响或其他效果不能代替旋律、音色主体或微细表演设计。器乐作品在此处写主题动机的前台乐器/音色，不填人声栏目。
- **Arrangement**：核心声部各自承担什么，在哪些段进入、退出、让位或回应；按本作听觉中心写出维持段落拍感、能量方向与和声的必要基础支点。主唱为中心时，说明相关节奏、低音与和弦/持续层怎样在已定主唱记忆材料或转折句的关键位置形成支撑，局部变化再进对应标签；其他中心按已选主题、groove 或音色运动编译，并保留必要的人声关系。段落间的可听差值、前景交接、转场和结尾怎样完成。技术规格只有目标接口有真实独立字段时才放入字段，不塞成风格词。

按“声音身份 → 身体/律动 → 已选记忆材料 → 声部职责 → 段落变化 → 结尾”组织。主唱为听觉中心时，把实际主唱记忆材料与必要表演线放入 Vocal Details，把维持关键主唱材料所需的节奏/低音/和声基础及局部支撑、留白和回应放入 Arrangement；全曲保持项进 Style Prompt，具体事件进对应乐段或完整乐句标签。其他中心按蓝图进入相应字段。每个短语要回到主文或已选风格子级的已定决定，并指向可听对象、状态、位置或相对变化。最终 Style Prompt 只留模型需要生成的声音结果，删掉分析理由、歌词复述、营销话语、重复形容词和没有位置的制作赞美。某一字段还未决定就留空，不为填满三段而造内容；Style Prompt 正文保留必要的结构与数字，不把用户未锁定事项写成确定事实。

全局层保留声音身份、拍感和听觉重心；Arrangement 只交代实际需要的声部进退、临时让位与回归、段落接缝和尾部。编译前从已完成蓝图分别提取全局保持项、乐段增量/例外及进入退出/边界，逐项定位到最终字段；关键转折/前景交接处，将主线结束与进入、低音/和声落点、脉冲及回应声部进出作为同一音乐事件写清位置、保持项、主要变化和恢复/收束。若主唱承载作品主要情感或意义且为听觉中心，Vocal Details 保留同一主唱记忆材料（节奏/轮廓/重音/落点、首现与回返）及必要表演线；记忆 hook 与承载转折/承转的完整主唱乐句可以不同。Arrangement 及相关段落/完整乐句标签须反映伴奏如何依据同一主唱事件安排音区、起音、持续、密度、留白和回应；若蓝图缺少这些决定，返回第三/第五步。若主唱并非听觉中心，沿蓝图的其他中心编译，不强加此条件。若有真实关键交接，在 Arrangement 与必要的相关段落标签中保留同一事件；蓝图缺少该事件时返回第四步，确无交接需要时不强造；局部协作细节可放在准确的相关段落标签，不限于主唱指令，Style Prompt 留全曲共同身份与基线。若全局概括与局部决定冲突，改写概括并明确该处增量。压缩后对照蓝图复核这些同一决定仍在最终 Prompt/标签中；若只剩“open”“brighter”或“lead vocal upfront”等概括而缺少具体关系/动作，返回相应设计或编译步骤补足。控制内容先由主文蓝图决定，再按语言选择编译成声音动作：默认英语；用户明确要求中文时，Style Prompt 正文与标签内控制指令均用中文，歌词原文保持不变；明确要求双语时两组都完整且对应。切换控制语言或制作另一语种组，只把同一已定蓝图和控制事件重新表达，逐项保持声音对象、歌词/段落锚点、位置、动作与保持/变化/恢复边界；不得在翻译时临时增删声音决定。发现共同蓝图缺项时，返回对应设计步骤补齐共同蓝图，并同步更新所有受影响语种组，不能只给一个语种新增决定。说清哪个声音对象在何处做什么；不因“悲伤”“脆弱”“更开阔”等情绪或效果描述自动指定气声、颤音、长音、升高音区等固定技巧。分别判断音色、音区、发声、咬字、元音延展、力度和录音距离；元音动作须绑定实际词/音节。Style Prompt 与局部标签若描述同一处须相互一致；局部标签仅写相对全曲/乐段基线确有变化的动作。把“前景更清楚”编成具体角色与位置，把模型无法可靠承载的精确音乐事件留在人工/符号交付路径；不靠抽象情绪词或效果词替代主唱旋律、音色主体和细微表演，也不把计划写成平台必然服从的承诺。缺少足以生成控制的决定时，返回主文相应蓝图/演唱与制作步骤或已选风格子级完成设计，不从 V4 查找控制命令、唱法范式或 Style Prompt 方法；决定齐备后才套用 V4 的外层标签形状与位置。

调用风格子级时，先执行该子级所选的本地工作默认与切换条件。子级句式是局部声音决定，不是完整蓝图；编译者先从最终共同蓝图提取本作听觉中心、已定材料、基础支撑、锁定关系与最终曲式，再把子级的风格决定合并到相应字段。共同蓝图已定的关系若被局部模板省略，最终包仍须保留；子级起稿句式不得覆盖共同锁项或原曲式。然后把最终决定分配到对应字段：脉冲/全曲制作轮廓进 Global Metadata，主唱动作进 Vocal Details，声部拍位/进入退出/段落差值进 Arrangement。子级列出的多个唱法或音色句式是按歌词、乐段和用户已有声线条件选择的候选，不要整组复制进同一 Prompt；纯器乐只写主题前台身份和编制动作，不生成空的人声控制。用户锁定录音关系与本地默认不同时，Prompt 反映用户的锁定路线，不能仍写本地默认。

风格模块为编译动作使用“主歌/副歌/间奏”等职责名时，先映射到用户已定曲式或本轮蓝图的真实乐段；作品没有对应段落就删去该句，不得为套用某个风格模板新造一套 verse/pre/chorus。

负向愿望先改成目标声音和边界；只有目标接口明确有负向字段时才单独填。接口有 `Exclude` 一类 UI 栏目，不代表否定句写进 Style Prompt 也同样受支持。采样率、码率、文件格式等若有独立设置，就放独立设置；不要靠 Style Prompt 文字承诺平台做到了。

## 按全曲、乐段、乐句和词语编译差量

控制从全曲向局部逐层收窄。每一级只写比上一级多出的、会产生独立可听结果的决定；不要为压短文本删掉有作用的轻声、近口语、重音或字尾变化，也不要把同一要求换词重复三遍。

| 层级 | 必须先决定什么 | 编译到哪里 |
|---|---|---|
| 全曲基线 | 速度与细分脉冲、groove、主唱身份/基准距离、整体能量与音区运动、前台声部和制作空间、结尾原则。形成连续的人物表演线、时间线、能量/音区线。 | Style Prompt。用少量完整关系说明“全曲始终如何”；不写逐句动作。 |
| 乐段增量 | 当前段落对全曲表达新增什么；相对前段的入口状态、主要人物动作、必要的声音变化，以及出口怎样交给下一段。 | 默认写在 Controlled Lyrics 的乐段标签内；标签可承载蓝图已定的本段主唱、伴奏或跨声部协作差量，不限于唱法。Style Prompt 留全曲共同身份与基线；有段落位置的局部事件写入所属乐段标签，需精确定位到完整乐句时放在相应句级标签。Style Prompt 已覆盖的基线不重写。只有接口实际拒收整套嵌入格式或用户明确选择其他模式，才编译到对应真实可用位置。单条控制效果不佳时局部修订并保留格式。 |
| 乐句/句级增量 | 哪个完整演唱乐句真的有不同的关系动作、距离、咬字、重音、连断、字尾或被全曲允许的停顿；若伴奏/跨声部动作必须精确锚定某个完整目标乐句，也明确它与该句的关系。先依句法、共享主语/宾语、连续谓语和实际气口划乐句；作词视觉换行不自动等于起唱或换气。 | 需要句级控制时，以独占行 `[(instruction 1｜instruction 2)]` 紧贴完整目标乐句的第一行上方；若完整乐句跨越数个歌词行，不把控制插入句中。句级标签可承载与该乐句有明确关系的主唱、伴奏或跨声部动作。连续乐句内部不插入会造成重新起唱的标签。默认不另交替代最终歌词的控制谱。 |
| 词/音节级动作 | 精确定位锁定文本中的承重词/音节，说明要听到的动作及作用，例如字头轻重、辅音收束、重音、元音延展或收短、相对音区/拍位、字尾和气息。解释它如何完成这句的否定、承认、转折或余波。 | 只在确有独立作用时将它纳入对应完整乐句的句级标签；需要保留的内部定位先编译到完整 Controlled Lyrics，不让底稿替代最终歌词。不可泛写“强调关键词”。 |

段落标签只作用于它标注的乐段；独占句级标签只作用于紧邻的完整目标乐句，以及该标签明确锚定于该句的关联声部动作。相同歌词、相同 hook 或同名段落不会自动继承其他段/句的具体唱法或声部动作。若蓝图要求关系动作在后续回返中保持，应在每个实际适用的后续段/句标签写出最短必要动作，或明确说明作用于哪些回返段；若回返有变化则按蓝图写该处差量。只对已定的回返关系这样编译，不逐行堆控，也不把动作强加给未指定的段落。

先判断设计路径：锁定的源旋律只把已核实音高、时值、拍位和气口作为源事实并加以保护；用户授权新谱曲时应实际写出本轮创作的音高和拍内时值；AI 探索时锁定关键节奏/轮廓/重音/落点、歌词承重词和段落/音域关系，具体音符可开放。歌手范围未知时不得虚构高音极限或声区切换。没有源旋律/导唱时不得把提示词设想写成既有音符、精确拍值或已成立换气。气氛词不能替代人物动作；技巧词也不能单独说明为什么用。每条控制连成“表达动作 → 可听变化 → 放置位置”，且不越过锁定的速度和能量关系。

局部标签可能改变时间感：`soft/close/speech-like`通常描述力度、音色或距离，不自动代表减速；`hold/sustain/pause/rubato`可能延长时间。若实际结果只有单条控制拖拍、失效或唱法不合适，先修订/删除该控制并保留整套嵌入格式；不要把局部负效判成接口拒收。需要真的自由速度/停拍时，在声音蓝图和伴奏恢复点中一并标明。编译后从头朗读完整生成歌词，核对乐句边界、控制连续性和段落交接。

## 项目默认英语控制指令的嵌入式 Controlled Lyrics

默认使用英语 Style Prompt 正文和英语标签内控制指令；聊天语言与歌词语言都不决定控制语言。用户明确要求中文控制时，这两部分均使用中文，嵌入的源歌词原文保持不变、不翻译。用户明确要求双语时，用两个唯一组名分别交付完整且音乐决定等价的 Style Prompt + Controlled Lyrics；歌词、段名、顺序、标点和排版按歌词锁、结构锁及本轮授权的演唱排版重排/结构开放例外执行。所有组的字段名保持 `Global Metadata`、`Vocal Details`、`Arrangement`。不使用语言字符比例推断意图，也不默认另交中文演唱摘要；明确请求的解释放在机器输入之外。每组分别以自己的 `--section` 运行校验。

读取主文蓝图已经确定的歌者对象、主唱记忆材料与表演线、情感动作、乐句关系、伴奏协作及段间声音变化，再把同一组决定按全局→乐段→完整演唱乐句编译差量；不得在生成编译时另行发明材料或代替主文设计。若主唱承担主要情感/意义且为听觉中心，主唱材料与必要表演不得只剩“lead vocal upfront”、气声或效果描述；缺少记忆材料、音色主体或细微表演决定时返回第三/第五步补足。默认英语；用户明确要求中文时 Style Prompt 正文与标签内控制均改为中文，歌词原文不翻译；双语则分别编译完整等价组。无论语言如何都说明声音对象、动作和位置。不得仅凭情绪词套用固定技巧。Style Prompt 与控制共用同一组已定声音决定；V4 只提供标签语法外形，不提供音乐命令或唱法方法：

- **全局**写入 Style Prompt，承载声音身份、整体唱法基线、脉冲与全曲声音运动；Style Prompt 按 Global Metadata、Vocal Details、Arrangement 三个职责组织。
- **乐段**写在段落标签内部，例如 `[Verse 1 ｜ instruction 1 ｜ instruction 2]`。每条只写相对全局基线新增且本段确有作用的主唱、伴奏或跨声部动作，并定位其对象与位置。
- **完整演唱乐句**确有独特控制时才增加独占行 `[(instruction 1｜instruction 2)]`，紧贴该乐句第一行上方。若乐句跨多个作词行，控制要覆盖完整乐句，不能插在连续句法中间。

全角 `｜` 只在段落/句级控制标签内部用于分隔指令；不在歌词正文或句尾附控制，不使用 ASCII `|` 代替，也不按视觉换行逐行贴标签。项目嵌入语法是用户已选定的交付约定，不是任何第三方接口的官方语法或生成保证。平台未知、官方资料未说明该语法、或尚无试听，都不构成切换格式的理由。只有当目标接口实际拒收整套嵌入格式，或用户明确要求另一种模式时，才适配对应格式；保留锁定歌词，并只说明本轮必要的平台事实。单条控制无效、唱出不理想或拖拍时修订该控制并保留整套格式。若用户明确只要裸歌词或文字草稿，则直接交该文字，不强加人声生成包。

歌词文字锁与段落结构锁分开判断。始终锁定原词、标点、歌词行序和默认换行；原稿已有段落标签时，也锁定标签名称与顺序，未经授权不得改名、重排或增删。原稿完全没有段落标签时，默认仍按歌词文本精确核对；不能仅因原稿无标签就默认结构开放。只有确认段落结构是本轮开放项，且先由当前声音蓝图确定实际曲式和每个标签的位置后，才对校验器加 `--structure-open`。此选项只允许新增标签并核对标签语法及原歌词字符/标点/换行，不判断新增标签是否符合曲式；必须人工对照已定声音蓝图核查标签名称、顺序与位置。锁定稿含有段落标签时，`--structure-open` 必须报错，不可借此解锁。结构未定时，不用此参数，也不声称工具验证过曲式。只有用户明确授权演唱排版重排时，才可合并或重分相邻歌词行；除此之外不得改行。获得授权后仍须逐字符保持歌词内容和标点，并在必要的平台说明中指出改变的是演唱排版而非改词。原歌词稿继续保留原排版。若使用 Markdown 围栏，且锁定源歌词没有末尾行结束符，闭围栏另起一行所必需的单个分隔符不算歌词载荷；源稿已有 LF/CRLF 时连末尾状态照原样核对，内部换行、额外空行和正文变化仍须精确一致。此例外只适用于围栏载荷，不静默归一非围栏正文，也不以改源稿或演唱排版重排绕过校验。

## 生成包的完整顺序与可复制模板

普通嵌入式人声方向默认交付完整可复制输入，顺序为：**Style Prompt → 完整 Controlled Lyrics → 本轮必要的平台说明**。默认 Style Prompt 正文与标签内控制指令为英语；用户明确要求中文时这两部分均为中文，源歌词原文不翻译；明确要求双语时以不同且唯一的组名交付两套完整、等价输入。保留固定字段名 `Global Metadata`、`Vocal Details`、`Arrangement`，不默认交中文演唱风格摘要。内部控制底稿只能用于编译和复核，不能替代最终标签歌词或要求用户自行拼接。平台拒收整套嵌入格式时才按实际字段适配；用户明确要裸歌词/草稿时也只交其指定文字。YuE2 外部 ABC 不套用此顺序，按独立三输入分支交付。纯器乐分支不使用歌词或人声假设，输出 Style Prompt、项目蓝图栏 Instrumental Form 和相关平台说明。

以下是占位接口；尖括号中的内容必须替换成已决定的信息后才可投喂。它不含示范歌词或示范音乐内容。

```markdown

[(<English instruction describing the decided vocal action on a target; when a source-lyric anchor is needed, quote that word or phrase exactly as written, in its original language, without translating or normalizing it>)]

## 方案 <方向名> Platform note
```

## 项目约定与当前平台事实分开记账

每次只记录会改变本轮输入/验收的接口信息。证据分成四类：`user-specified-interface` 表示用户指定了输入格式，只决定交付形状；`documented` 表示该产品/版本的官方资料说明了能力；`project-tested` 表示同一产品、模式和模型版本有可复核的真实试听；`creative-hypothesis` 表示作品需要但尚未验证的唱法。前两类不能代替试听效果，项目约定也不能升级成平台承诺。没有使用到的字段或通用风险不重复写进每份包。

截至 2026-10-06，复核的 Suno Help Center 页面说明其 Custom 流程有 Lyrics 与 Styles 输入，另有 Instrumental、Exclude、Creative Sliders、Vocal Gender 与音频上传相关的 UI 说明；Help Center 词汇页列出 Verse、Chorus、Bridge 等常见段落术语。这些是产品帮助/UI层事实，不等于所有版本、模式或 API 都有完全相同字段，也不证明逐句标签能稳定控制唱法。所查官方页面没有给出逐句嵌入控制语法或公开 Styles 硬字符上限；Suno API 登录门户不足以核实公开 API schema。因此本项目不填写未经核实的 Suno API 字段或固定平台字符上限。用户当前界面若有差异，按该轮实际界面重新确认字段；未核实项写“未知”，只交可支持的部分。

项目现行的 **1000 Unicode code points** 是普通 Style Prompt 的工作预算，不是 Suno 或其他平台的硬上限。按 Unicode 码点计数，空格、标点和换行均占预算；只计实际投喂的 Style Prompt，不把歌词或平台说明混入。若本项目已部署专用计数器就用它；没有时用能按 Unicode code point 计数的方式核算，不能凭肉眼估算。官方已核实的较低硬上限另行服从；平台上限未知时，不把 1000 写进平台说明里的“平台上限”。预算超出时先删同义重复、解释理由和无独立声音结果的修饰，不硬截断；优先保留原锁项、听觉中心、主唱声音身份及记忆材料/表演关系（适用时）、维持关键主唱材料的必要拍感、能量方向与和声支撑关系、groove、必要结构与数字，以及关键声部交接/转折和结尾。压缩后逐项复核核心关系没有丢失；使用嵌入式人声包时，具体声部支撑/协作事件不必全挤入 Style Prompt，先把局部动作放入准确的所属段落/完整乐句标签，再压缩重复或解释，保留参与声部、位置、动作及保持/变化/恢复关系。YuE2 外部 ABC 把专业演唱与段间控制集中在 Style Prompt，不能把局部标签当作可拆分出口，也不能为满足 1000 码点而删除主唱身份、核心句动作、段落锚点或关键配器事件；1000 仍只是本项目编辑预算，若压缩会损失这些决定，应保留必要内容并说明超过工作预算，只有确认目标接口硬限制后才按其真实限制协商取舍。

## 投喂前与试听后核对

普通嵌入式人声包生成前检查：目标模式和字段真实存在；主文蓝图中的锁定项、开放项、已选记忆材料及其首次/回返关系仍被正确表达；Global Metadata、Vocal Details、Arrangement 方向一致。若主唱承载主要情感/意义且为听觉中心，确认 Vocal Details 保留蓝图中的同一主唱记忆材料（节奏/轮廓/重音/落点、首次与回返）及必要表演线；记忆 hook 与承载转折/承转的完整乐句可不同，但各自作用须对应实际材料。若该段有伴奏，先确认其必要拍感、能量方向与和声基础支点已进入蓝图；对主唱为中心的段落，再确认实际参与基础支撑的节奏、低音与和弦/持续层在关键主唱重音、延展、释放和下一入口处的起音、时值/包络、音区及保持/变化已被编译到 Style Prompt 基线或准确的段落/完整乐句标签，能形成基础支撑后再添加回应和装饰。各声部动作应依据同一主唱事件安排，不能只凭织体密度、音色形容或装饰声部的进退代替基础关系。若蓝图另定听觉中心则按该中心复核，不强加主唱条件。若蓝图有关键交接，确认 Arrangement/相关段落标签中的同一事件保留主线句尾/下一入口、低音/和声落点、脉冲与回应声部进退及相应保持/变化/恢复状态；必要时把局部细节放在准确的所属段落/句级标签，不挤占全局基线说明。若压缩后丢失同一关系或表演差异，返回对应设计/编译步骤补齐。确有交接需要却缺少蓝图事件时返回第四步补齐；无交接需要时不强造。蓝图要求保持的副歌/乐句回返动作须在每个实际适用的后续标签明确重现，或写明覆盖范围；相同 hook/歌词不会自动继承具体唱法或伴奏动作。蓝图已定但最终标签漏掉该动作时回编译补齐，不把它留成仅有“same hook”的概括。切换语言或输出双语时，逐项核对各语种表达的是同一声音对象、锚点、位置、动作和保持/变化/恢复边界；若某组多出或缺少决定，回共同蓝图修订并同步重编译受影响组。默认英语 Style Prompt 正文和标签内控制；用户明确要求中文时这两部分均为中文且源歌词不翻译；明确要求双语时提供两组完整等价输入，字段名保持稳定。全局、段级与句级控制各有明确层级，局部只写相对基线的实际差量；句级标签紧贴完整目标乐句上方；全角分隔符只在标签内部。歌词锁、段落结构锁、已授权的演唱排版重排和结构开放条件分别核对；保留原词与标点，只有获授权时才重排，开放结构须按蓝图人工核对。无源旋律时不声称精确源音高/拍值/气口；授权谱曲与 AI 探索按各自责任填写或保留开放变量。Style Prompt 只含模型需生成的声音结果，不混入解释、歌词复述或臆造字段；未定字段可以留空。平台未知/官方未写明嵌入格式时仍保持项目默认并将接受状态标为未知；只有接口实际拒收或用户明确要求时才切换格式。语法与保真由本地校验器检查，指令语义和字段间一致性仍需人工核对。

YuE2 外部 ABC 走独立检查：Lyrics 与锁定稿逐字比较；Style Prompt 覆盖必要的全局和段间声音控制且与 ABC 的调/拍、旋律/休止及和弦符号选择没有未解决冲突；full/melody 依本轮要保留的和声选择，若要求精确保留和弦则确认符号谱确已编码，`full` 本身不要求至少一个和弦符号。指定时间上限须足以覆盖 ABC 纸面时长。若使用 ComfyUI，读取当前 `YuE2GenerateMusic` 的真实 `abc` 字符串输入和 `full`/`melody` 选项，核当前工作流实际接线：模板中的 ABC-planning helper 可能在关闭规划时给出空串；外部谱必须接到非空 ABC 输入，否则节点会将模式转为 `off`。此处是对已检查 ComfyUI 节点/模板的说明，不外推为其他云服务字段名；内部 `cot` 是实现参数，不是可任意映射的用户云字段。ABC helper/bounded 检查通过只证明本地 profile 和可观察事件，不证明云端接线、生成长度、声音和谐或演唱遵从。

实际生成后再试听核对：先听主唱记忆材料/其他已选主题、脉冲和曲式是否实现蓝图；再核对主唱音色主体、细微表演、关键承重词、句尾、段落差值、所有相关伴奏声部的支撑/留白/回应、声部冲突和旋律/音频保护项。若目标明确要求清唱或最小伴奏也能吸引听者，按同一实际人声试听独立/最低支撑版本，再核完整伴奏如何增益；没有音频就不报告效果通过。观察到格式正确只报告“输入格式已核对”；生成音频未听不报告音乐通过。遇到局部负增益，定位是哪个具体控制导致，再回到最早冲突层修订；不把风格、参考音频或项目控制标签的存在当成音频效果证据。只有用户任务确实要求比较或关键未知需要验证时，才设计比较；每个比较只隔离会改变判断的变量，不把 A/B 设成常规交付清单。
