# AI 音乐生成与演唱控制编译

由 [主文](../SKILL.md) 在确认交付 AI 音乐生成输入后按需读取。输入为已完成的声音蓝图、锁定材料与目标平台/模式；有词作品的原始词稿、本轮演唱稿与词曲对应关系沿用 [词曲交接与回填](composition.md#词曲交接与回填)。**本文件只编译已确立的音乐与声音决定，绝不靠堆叠空洞形容词或逐行乱贴标签代替编曲设计。**

> **YuE2 外部 ABC 三输入独立分流**：用户明确选用 YuE2 外部 ABC 接口时，不走本文件的嵌入式 Controlled Lyrics 语法，改读 [YuE2 外部谱编译](yue2.md) 交付 `Style Prompt` → 原文 `Lyrics`（无标签）→ bounded native `ABC`。

## 一、先定生成路径与权限边界

| 生成路径 | 决定权与核对边界 |
|---|---|
| **文本生成新曲** | 模型探索未锁定的具体旋律与微细制作；锁定歌词、明确曲式、声音世界观与段落能量必须落地。无源旋律时，绝不声称模型能精确保留一条尚不存在的旋律。 |
| **旋律 / 导唱 / 音频参考改编或续写** | 明确区分参考音频、续写起点、Cover/Remix 源与风格参考；仅当目标接口真实接收音频输入时才能承诺保旋律，生成后逐句回听核对。 |
| **仅讨论生成方案** | 平台未定且只讨论思路时，交平台无关的声音蓝图与待编译重点，不伪造成可直接投喂的平台 API 参数。 |
| **明确只要裸歌词 / 文字草稿** | 直接交付用户要求的纯净文字，不强行附加 Style Prompt、控制标签或平台说明。 |

## 二、物理听觉编译法：把抽象词译成 AI 模型真听得懂的声音指令

现代 AI 音乐模型听不懂宏大抽象赞美词（它们只会把这些词还原成千篇一律的罐头合成器与平庸唱腔），但对**具体的物理发声材质、演奏动作、空间干湿对比与动态落差**响应极准：

| 容易翻车的空洞写法 | 编译为可发声的物理听觉指令（完全按本作真实选角写实，绝不套用固定乐器词） |
|---|---|
| 抽象情绪词（如悲伤、大气、有史诗感、很高级） | 译成**空间距离、真实材质与动态反差**：录音干湿距离（贴耳近场干声 vs 宽阔厅堂残响）、本作实际乐器的发声材质与触键（如木质琴槌轻触、指尖拨弦颗粒、贴近琴码扫弦、真实哨片或气声质地、远景缓起弓弦）、段落能量落差（前段克制收窄 → 高潮前清晰呼吸停顿 → 重拍低频与宽声场协同打开） |
| 泛化角色词（如主唱在前景、副歌更有层次） | 译成**具体位置、让位与声部接力**：主歌中频只留人声与单件低密支撑，句尾空拍由核心器乐短句回应；副歌拓宽音区与立体声宽度、保持干净中频空间让主唱立在最前（**Style Prompt 内不写混音师 Hz/dB 数字如 `1-4 kHz`**；也不用易被模型误解成电音炸点的 `drops` 代指静音抽空，按曲速与节奏写成清晰的 `brief beat of silence` 或 `1-beat / 2-beat breath pause`） |
| 机械技巧映射（如悲伤就套气声颤音、高潮就全轨拉满） | 按当下歌词动作定具体微表演：字头轻重、胸声与混声切换、收放气息、延音落点与短停留白，高张力风格保留攻击性、颗粒感与身体冲击力 |

**面向下游音频模型的两道过滤关（防提示词污染与防蓝图串味）**：
1. **分清独到方向与粗糙杂项**：若用户明确给出了独特且声学自洽的音色或跨界方向（哪怕偏非常规），完整保留并转译为精准物理材质与频谱分工；仅对未锁定且会破坏核心情绪的堆料俗词，在换血成贴合材质后再编译，绝不让被放弃的俗套词透进 `Style Prompt`。
2. **从人类蓝图转机器输入时剥离散文与假精确细节**：制作人蓝图里的中文文学比喻、混音工程数字（Hz/dB）、艺人/原曲名、内部术语，以及下游文本生曲模型难以死数的小节算术叙事，全部在进入 `Style Prompt` 前剥离干净。只保留四类音频引擎真正吃得懂的物理要素——① 风格骨相、真实发声材质与演奏触键；② 歌者音色、干湿距离与唱法微动作；③ 空间远近与立体声开合对比；④ 清晰的段落能量弧、呼吸停顿与收尾方式。主干保持稳健克制，点睛材质少而准，绝不照抄陈旧模板词。

## 三、三段 Style Prompt 组织与 1000 码点工作预算

常规嵌入式接口沿用项目固定的三字段组织，**字段名保持 `Global Metadata`、`Vocal Details`、`Arrangement`**（纯器乐将 `Vocal Details` 替换为 `Motif / Front Identity`，并配项目蓝图栏 `Instrumental Form`）：

1. **`Global Metadata`**：主导风格与融合定位、真实 BPM 与拍号、身体律动特征、全曲情绪运动弧与整体录音空间质地（未锁定事项保持开放，不编造未知实测值；**歌手性别与真实音域未锁定时，不在 Style Prompt 中强锁猜测的固定调号**，若确需写参考调须在块外提醒用户换音域或移调时同步修改或移除）。
2. **`Vocal Details`**（人声必填；纯器乐改 `Motif / Front Identity` 写前台核心动机与音色）：歌者身份与相对音区、干湿距离、核心音色颗粒、已定的主唱记忆材料与表演基线、必要和声/叠录层次（真实二次叠唱与人工处理明确区分，不从歌词自动臆断性别或高音极限）。
3. **`Arrangement`**：核心声音线索与各声部职责、低频与节奏互锁、主唱/主线与伴奏的频谱让位及句缝回应、关键段落能量递进/呼吸停顿/转折衔接与结尾方式。调用风格子级时，将其专属律动与乐器骨相有机融入最终蓝图，不把未用到的占位段落强塞进曲式。

**音频引擎语序与 1000 Unicode code points 工作预算**：
- **核心基因前置、精炼不复读**：下游音频模型对前部信息权重最高，把最决定听感天花板的风格骨相、制作年代/空间质地、律动与核心材质放在每段前部；用凝练的声学短语取代长篇逐小节叙事，不把已经写在 `[Section ｜ ...]` 里的局部指令重复塞进 `Arrangement`。
- **1000 码点编辑预算**：仅统计实际投喂的 Style Prompt 正文（含空格、标点与换行），不计歌词与平台说明；它是项目编辑预算，**不是**对 Suno 等第三方平台的硬字符上限断言（平台已核实更低硬上限时服从平台）。超预算时先删同义修饰与解释性废话，绝不硬截断；属局部乐段或乐句的动作下沉到对应标签，确保声音空间、核心线索、低频律动、关键转折与结尾无损保留。

## 四、默认英语嵌入式 Controlled Lyrics 与克制演唱导演法

### 1. 语言规则（聊天语言与歌词语言均不改变默认控制语言）
- **默认**：英语 `Style Prompt` 正文 ＋ 英语标签内控制指令，嵌入的锁定原歌词**一字不改、绝不翻译**；默认不额外附中文演唱摘要（仅用户明确要求解释时放块外）。
- **明确要求中文控制**：`Style Prompt` 正文与标签内控制指令均改用中文，原歌词仍保持原文不翻译；三个英文字段名保持不变。
- **明确要求双语**：交付两组各自完整、音乐决定逐项等价且组名唯一的 `Style Prompt` ＋ `Controlled Lyrics`（分别用各自 `--section` 校验），切换语言绝不增删声音决定。

### 2. 三层差量控制与克制出手原则
控制按全局 → 乐段 → 完整演唱乐句逐层收窄，**下层只写相对上层确有独立听觉变化的动作**，绝不逐行贴满互相打架的指令干扰模型自然乐感：

| 层级 | 放置位置与精确语法 | 导演原则 |
|---|---|---|
| **全局基线** | `Style Prompt` | 扛住全曲统一的声音世界观、拍感、音色基线与整体动态弧。 |
| **乐段增量** | 段落标签内部：`[Verse 1 ｜ instruction 1 ｜ instruction 2]`（严格使用**全角 `｜`** 分隔，绝不用半角 `|`） | 只写本段相对全局新增的主唱姿态、伴奏进退、抽空蓄势或声场变化；同名回返段不会自动继承前段控制，需保持或变化时在对应段标清最短必要动作。 |
| **完整乐句增量** | 紧贴完整目标乐句首行上方的**独占行**：`[(instruction 1｜instruction 2)]` | **极度克制且短小防误唱**：全曲通常仅在真正改变情绪温度、咬字张力或承重词落点的 **2 到 5 处**关键完整乐句精准出手；每条指令精简为少数可执行表演动作（跨越数行的完整乐句只在首行上方标一次，绝不插进连续句法中间，也不贴在歌词行尾）。**默认面向整句或以句首/句尾位置表述，不往括号里塞入原歌词**（防止下游 AI 演唱模型把括号里的词直接唱出或整行忽略）；**仅当用户明确要求锚定具体原词，或长句内部确需点名区分不同词位动作时**，才原样引用该原语种词句且不翻译、不改拼写大小写，其余指令仍保持极短。 |

### 3. 锁词、锁结构与平台未知边界
- **锁词铁律**：严格逐字保留本轮已核对演唱稿的字符、标点、行序与默认换行；原稿已有段落标签时同步锁定标签名与顺序。仅当明确获得演唱排版重排授权才允许合并或重分相邻行（校验加 `--allow-performance-reflow`）；仅当原稿完全无段落标签且结构开放时，先依蓝图定曲式再加段标（校验加 `--structure-open` 并人工对照蓝图核对）。
- **平台未知不退回裸歌词**：嵌入式语法是项目选定的交付格式，不等于平台官方保证。平台未知、文档未说明或尚未试听时，仍交付完整嵌入式包，并在 `Platform note` 中简短注明接口接受状态未知。仅当目标接口本轮实际拒收整套嵌入格式或用户明确改选其他模式时才切换格式；若只是单条控制失效或拖拍（如 `hold`/`rubato` 拖慢节奏），仅修订或删除该条控制并保留整套格式。

## 五、可复制交付骨架

每个独立方向交付一套可直接一键复制的完整包（以下占位描述须全部替换为真实决定的声音内容，不得把尖括号占位符原样投喂；用户已提供歌名时沿用原歌名作方案名，不擅自另起新歌名；无必要平台说明时省略 `Platform note` 整节）：

### 人声包骨架（顺序固定：`Style Prompt` → 完整 `Controlled Lyrics` → 必要 `Platform note`）

## 六、投喂前机器硬校验与试听后纠偏

1. **普通嵌入式人声包静态校验（交付前优先运行）**：
   ```sh
   python3 "{SKILL_DIR}/scripts/check_controlled_lyrics.py" \
     --lyrics <已核对的本轮演唱稿文件> \
     --package <完整人声包文件> \
     --section "<方案名> Controlled Lyrics"
   ```
   按授权需要加 `--allow-performance-reflow` 或 `--structure-open`。核对 Style Prompt 码点预算、全局与局部指令无冲突、无泛化空词代替具体声音动作。校验通过只证明包格式、全角分隔与歌词文字保真，**不**证明平台接受或音频好听。
2. **平台证据分四级记账**：区分 `user-specified-interface`（用户指定格式）、`documented`（官方明确文档）、`project-tested`（同平台同版本实测试听）与 `creative-hypothesis`（创作假设），不编造未核实的 API 字段或字符上限（如 Suno Help Center UI 栏目不等于公开 API schema，负向 `Exclude` 仅在界面明确提供独立栏目时分列填写）。
3. **试听后四路反查精准返修（终审看真实音频，不盲目加词）**：拿到真实生成音频后，按实际听到的毛病反查最早断点、只动对应那一层，绝不靠继续堆砌形容词救场（未听音频前一律标明听感未验证）：
   - **整曲廉价塑料感、风格跑偏或情绪不对** → 回到 `Global Metadata` 前部重写风格骨相、真实物理材质与空间干湿，剔除空洞修饰词；
   - **全曲平直、副歌冲不上去或结构松散** → 先查前段是不是铺得太满导致高潮无处可升，优先做主歌/前段减法与清晰前置停顿落差，再精炼段标增量的对比动作，而不是给副歌继续硬叠乐器词；
   - **人声发闷、咬字糊或乐器抢戏** → 删掉与主唱抢中频的伴奏层或明确拉开音区与干湿景深，不靠硬写 louder vocal；
   - **模型误唱括号内容、拖拍或直接忽略控制** → 保留整套格式，只把出问题的单条 `[(...)]` 砍短到 3–6 个核心动作词、删掉非必需的引号原词或易拖拍的 `hold`/`rubato`，必要时改由 `Arrangement` 承载大动作。
