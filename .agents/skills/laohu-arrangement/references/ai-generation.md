# AI 音乐生成与演唱控制编译

由主文确定“生成模型负责什么”后，以及需要把声音蓝图编译到音乐生成接口时读取。读者是本次生成包的编译者。输入至少包括：目标成品与模型可决定的范围、已锁定或开放的歌词/旋律/音频、声音蓝图、目标平台与本轮实际模式。平台未定时，先给平台无关的声音方案；缺少材料只暂停依赖该材料的控制，不虚构平台字段、旋律或模型已经做到的效果。完成后把每个方向的可复制输入和实际无法传递的控制交回主文第八步试听验收。

## 先锁定生成任务和决定权

按本次实际输入选择一条路径：

- **从文字生成**：模型可探索未锁定的旋律、伴奏和制作细节；已锁定歌词、明确曲式或保护项仍须按用户要求保留。没有旋律时，不得声称模型能精确保留一条尚不存在的旋律。
- **从旋律/导唱生成**：标出要保留的音高、节奏、段落和可改编范围；只有接口确实接收该素材时，才能把它作为模型输入。生成后将对应内容逐句与源材料核对。
- **续写、改编或变换已有音频**：先区分用户要模型保留的音乐身份、允许变化的部分，以及当前接口正式提供的操作。把参考、续写起点、Cover/Remix 源和风格参考分别命名，不用“上传音频”代替保留范围说明。
- **只讨论生成方案**：交平台无关声音蓝图和待编译字段，不伪装成可以直接投喂的接口包。

在生成前逐项标成“锁定 / 本轮允许生成 / 待试听决定”。用户锁定的内容不让模型自行改写；开放项也不需要提前精确到平台没有依据承接的程度。目标平台和模式一旦确定，只使用当轮真实可见且已核实的字段；UI 控件、官方 API 与第三方封装是不同接口，名称不能互相挪用。

## 把声音蓝图写成有层次的 Style Prompt

人声作品的 Style Prompt 按 V4 的三个职责编译；各段共同描述一首歌，不是三份互相独立的形容词清单：

- **Global Metadata**：风格/融合方向，速度、拍号和身体律动，全曲情绪运动，以及声场和制作轮廓。写已经定下的关系；不把情绪词当作节奏、音区或动态命令。
- **Vocal Details**：歌者身份、相对音区、音色、距离、咬字、和声层数/进入位置和少量效果。只写作品或用户已确认的声线条件；不能由歌词自动推断性别、声区或唱法。器乐作品在此处写主题动机的前台乐器/音色，不填人声栏目。
- **Arrangement**：核心声部各自承担什么，在哪些段进入、退出、让位或回应；段落间的可听差值、转场和结尾怎样完成。技术规格只有目标接口有真实独立字段时才放入字段，不塞成风格词。

按“声音身份 → 身体/律动 → 前台声音或动机 → 声部职责 → 段落变化 → 结尾”组织。每个短语要能回到声音蓝图的一项决定，并指向可听对象、状态、位置或相对变化。最终 Style Prompt 只留模型需要生成的声音结果，删掉分析理由、歌词复述、营销话语、重复形容词和没有位置的制作赞美。某一字段还未决定就留空，不为填满三段而造内容。

调用风格子级时，先执行该子级所选的本地工作默认与切换条件，再把最终决定分配到对应字段：脉冲/全曲制作轮廓进 Global Metadata，主唱动作进 Vocal Details，声部拍位/进入退出/段落差值进 Arrangement。子级列出的多个唱法或音色句式是按歌词、乐段和用户已有声线条件选择的候选，不要整组复制进同一 Prompt；纯器乐只写主题前台身份和编制动作，不生成空的人声控制。用户锁定录音关系与本地默认不同时，Prompt 反映用户的锁定路线，不能仍写本地默认。

风格模块为编译动作使用“主歌/副歌/间奏”等职责名时，先映射到用户已定曲式或本轮蓝图的真实乐段；作品没有对应段落就删去该句，不得为套用某个风格模板新造一套 verse/pre/chorus。

负向愿望先改成目标声音和边界；只有目标接口明确有负向字段时才单独填。接口有 `Exclude` 一类 UI 栏目，不代表否定句写进 Style Prompt 也同样受支持。采样率、码率、文件格式等若有独立设置，就放独立设置；不要靠 Style Prompt 文字承诺平台做到了。

## 按全曲、乐段、乐句和词语编译差量

控制从全曲向局部逐层收窄。每一级只写比上一级多出的、会产生独立可听结果的决定；不要为压短文本删掉有作用的轻声、近口语、重音或字尾变化，也不要把同一要求换词重复三遍。

| 层级 | 必须先决定什么 | 编译到哪里 |
|---|---|---|
| 全曲基线 | 速度与细分脉冲、groove、主唱身份/基准距离、整体能量与音区运动、前台声部和制作空间、结尾原则。形成连续的人物表演线、时间线、能量/音区线。 | Style Prompt。用少量完整关系说明“全曲始终如何”；不写逐句动作。 |
| 乐段增量 | 当前段落对全曲表达新增什么；相对前段的入口状态、主要人物动作、1–3 项必要的声音变化，以及出口怎样交给下一段。 | 乐段标签或独立控制谱的乐段行。已经由 Style Prompt 推出的基线不重写。 |
| 乐句/句级增量 | 哪个完整演唱乐句真的有不同的关系动作、距离、咬字、重音、连断、字尾或被全曲允许的停顿。先依句法、共享主语/宾语、连续谓语和实际气口划乐句；作词视觉换行不自动等于起唱或换气。 | 只在接口和所选模式能承载时放在目标歌词上方；否则记入独立演唱控制谱。连续乐句内部不插入会造成重新起唱的标签。 |
| 词/音节级动作 | 精确定位锁定文本中的承重词/音节，说明要听到的动作及作用，例如字头轻重、辅音收束、重音、元音延展或收短、相对音区/拍位、字尾和气息。解释它如何完成这句的否定、承认、转折或余波。 | 只在该词确实需要独立处理且目标接口能表示时，落到句级控制或演唱底稿的精确定位栏。不可泛写“强调关键词”。 |

无旋律或导唱时，可以指定相对高低、长短、承重词、候选停顿和乐句方向；不得虚构绝对音高、精确拍值、已经成立的换气或歌手换声点。已有旋律/导唱时，才把音高、时值、拍位和换气绑定到对应音符/位置。气氛词（如悲伤、深情）不能替代人物此刻在对谁做什么；技巧词（如混声、颤音、长音）也不能单独说明为什么用。每条控制都要连成“表达动作 → 可听变化 → 放置位置”，同时不越过锁定的全曲速度和能量关系。

局部标签可能改变时间感：`soft/close/speech-like`通常描述力度、音色或距离，不自动代表减速；`hold/sustain/pause/rubato`可能延长时间。若连续标签会叠成拖拍或反复重新起唱，把共同唱法提升到乐段级，或删除造成冲突的具体局部控制；需要真的自由速度/停拍时，在声音蓝图和伴奏恢复点中一并标明。编译后从头朗读完整生成歌词，核对乐句边界、控制连续性和段落交接。

## 选择标准标签或项目嵌入控制

先看目标接口正式说明了什么，分清**段落结构提示**与**逐句演唱命令**。Suno 等平台可能在帮助页或界面中列出 Verse、Chorus、Bridge 等结构名称；这只足以按其当前接口使用结构标签，不能由此推出任意方括号语法、词级演唱命令或模型必然服从唱法。

- **标准歌词模式（默认）**：最终 AI Lyrics 只含目标接口当前支持的结构标签和锁定歌词；逐段/逐句控制谱单独放在 AI Lyrics 之前，供人审阅并在目标字段确实可承载时选择性编译。控制谱是随包交付的工作底稿，不让用户自行把控制表当歌词投喂。
- **项目嵌入模式（仅当用户明确选择或本项目接口已明确确认时）**：段级写在结构标签内部，格式为 `[Verse 1 ｜ <段级增量>]`；句级独占一行并紧贴目标歌词上方，格式为 `[(<句级动作>)]`。全角 `｜` 只在中括号内部用来分隔项目控制；不得写成 `歌词｜控制说明`，不得把句级控制放到目标歌词下方。嵌入格式是老胡项目的输入约定，不是 Suno 或其他平台的官方语法，也不保证模型按标签执行。若接口剥离、拒收或忽略控制，保留歌词并退回标准结构标签加独立控制谱。

两种模式均先锁定歌词内容、标点、段落次序；默认连换行也保持原样。只有接口把每个换行当作乐句/换气候选，且当前任务允许另行做演唱乐句编译时，才可合并或重分相邻歌词行：非空白字符、标点、段落顺序必须完全不变，并在 Platform Assumptions 中声明这是演唱排版，不是改词。作词稿继续保留作者排版。

## 生成包的完整顺序与可复制模板

每个正式交付方向都要独立完整，按 V4 顺序编排：**演唱风格 → Style Prompt → 最终生成歌词 → Platform Assumptions**。若走标准歌词模式，在最终 AI Lyrics 前加一节独立演唱控制谱；走嵌入模式时，最终歌词本身就是 Controlled Lyrics。不能只交共享歌词，再让用户从另一处自行拼控制。纯器乐分支不使用演唱风格、控制谱、歌词或人声假设，输出 Style Prompt、项目蓝图栏 Instrumental Form 和相关平台说明。

以下是占位接口；尖括号中的内容必须替换成已决定的信息后才可投喂。它不含示范歌词或示范音乐内容。

```markdown
## 方案 <方向名> 演唱风格
<用普通话说明主唱身份、全曲表演运动、承重词处理原则及需要避免的唱法；每项由作品/用户决定支持。>

## 方案 <方向名> Style Prompt
Global Metadata: <已确定的风格、速度/拍号/groove、情绪运动、制作轮廓>
Vocal Details: <已确定的主唱身份、音区/音色/距离/咬字、和声与效果；器乐时改写主题动机前台音色>

| 乐段/歌词定位 | 继承的全曲基线 | 本级新增的人物动作与可听演唱动作 | 时间/音区边界 | 证据 |
| 待填乐段/原文定位 | Style Prompt 中具体基线 | 独立可听的增量 | 不被局部控制改写的边界 | user-specified-interface / documented / project-tested / creative-hypothesis |

- 实际输入字段及各自用途：<字段名→内容；不写 UI 中不存在的 API 字段>
- 风格提示硬上限：<官方已核实值及适用模式/版本，或“未核实”；不得填项目预算冒充>
```

```text

```

占位符未替换的内容不是有效歌词或可解析提示。没有真实目标字段的 Exclude、歌词控制、乐器编制或参考音频参数，不得为了模板齐全而保留空字段或编造成 API 参数。

器乐包使用下列项目蓝图字段；字段名只用于本项目组织创作，不声称为平台字段：

```markdown
## 方案 <方向名> Style Prompt
Global Metadata: <风格、速度/拍号/groove、整体运动与空间>
Motif / Front Identity: <已确定的主导动机及前台乐器/音色>

## 方案 <方向名> Instrumental Form
<各段的功能、主题动机陈述/变化/回归、律动/和声/配器进退、能量转折、结尾或循环边界；只写本轮已决定项>

## 方案 <方向名> Platform Assumptions
<平台与模式、实际存在字段、已核实硬上限/未知项、参考音频用途、能力缺口与降级>
```

`Instrumental Form` 是项目内部蓝图栏。除非目标平台的官方文档明确使用同名字段，否则不得写成 Suno API 参数或保证平台会读取。Suno UI 的 `Instrumental` 选择、`Exclude` 栏或创意滑杆也不等于一个名为 `instrumental_form` 的 API 字段。

## 项目约定与当前平台事实分开记账

每次只记录会改变本轮输入/验收的接口信息。证据分成四类：`user-specified-interface` 表示用户指定了输入格式，只决定交付形状；`documented` 表示该产品/版本的官方资料说明了能力；`project-tested` 表示同一产品、模式和模型版本有可复核的真实试听；`creative-hypothesis` 表示作品需要但尚未验证的唱法。前两类不能代替试听效果，项目约定也不能升级成平台承诺。没有使用到的字段或通用风险不重复写进每份包。

截至 2026-10-06，复核的 Suno Help Center 页面说明其 Custom 流程有 Lyrics 与 Styles 输入，另有 Instrumental、Exclude、Creative Sliders、Vocal Gender 与音频上传相关的 UI 说明；Help Center 词汇页列出 Verse、Chorus、Bridge 等常见段落术语。这些是产品帮助/UI层事实，不等于所有版本、模式或 API 都有完全相同字段，也不证明逐句标签能稳定控制唱法。所查官方页面没有给出逐句嵌入控制语法或公开 Styles 硬字符上限；Suno API 登录门户不足以核实公开 API schema。因此本项目不填写未经核实的 Suno API 字段或固定平台字符上限。用户当前界面若有差异，按该轮实际界面重新确认字段；未核实项写“未知”，只交可支持的部分。

项目的 **1000 Unicode code points** 是 V4 项目 Style Prompt 的工作预算，不是 Suno 或其他平台的硬上限。按 Unicode 码点计数，空格、标点和换行均占预算；只计实际投喂的 Style Prompt，不把歌词、演唱控制谱或 Platform Assumptions 混入。若本项目已部署专用计数器就用它；没有时用能按 Unicode code point 计数的方式核算，不能凭肉眼估算。官方已核实的较低硬上限另行服从；平台上限未知时，不把 1000 写进“平台上限”字段。预算超出时先删同义重复、解释理由和无独立声音结果的修饰，不硬截断，也不删去已确认的前台声音身份、groove、关键声部职责、段落差值或结尾动作。只有用户明确要求保留超预算内容时，说明它超过的是项目工作预算，并按用户取舍执行。

## 投喂前与试听后核对

生成前检查：目标模式和字段真实存在；平台无关蓝图里的锁定项在包中仍锁定；Global Metadata、Vocal Details、Arrangement 方向一致；乐段与句级控制只表达增量且不冲突；锁定歌词没有被改写；缺少旋律时没有出现精确音高/拍值/真实气口声明；Style Prompt 没有混入解释、歌词或臆造字段。标准模式的 AI Lyrics 仅留支持的结构标签；嵌入模式已明确标记为项目语法而非官方保证。

实际生成后再试听核对：先听主旋律/动机、脉冲和曲式是否实现蓝图；再核对关键承重词、句尾、段落差值、声部冲突和旋律/音频保护项。观察到格式正确只报告“输入格式已核对”；生成音频未听不报告音乐通过。遇到局部负增益，定位是哪个具体控制导致，再回到最早冲突层修订；不把风格、参考音频或项目控制标签的存在当成音频效果证据。只有用户任务确实要求比较或关键未知需要验证时，才设计比较；每个比较只隔离会改变判断的变量，不把 A/B 设成常规交付清单。

## 来源与适用范围
