# YuE2 外部 ABC 编译

由主文确认目标为 YuE2 外部 ABC 三输入后读取。输入是本轮已明确的歌曲蓝图、原始词稿、本轮已核对的演唱稿、适用的旋律保护范围、来源草稿与实际接口；这里的“已明确”指完成本轮必需的音乐决定，不要求用户逐音审批。歌词版本、授权和回填依[词曲交接与回填](composition.md#词曲交接与回填)核对。作者暂定音符可在本轮授权改进后回作曲步骤修订，忠实转换则按可信来源投影指定事件。输出是可分别复制的 Style Prompt、原文 Lyrics 与 bounded native ABC。这里负责把已定或已获准修订的音乐事件投影到模型所用的谱面形状，不替代创作、一般 ABC/MusicXML/MIDI，也不指导模型本地推理。

## 三个输入各自承载什么

按本轮用户给定或实际 schema 可见的接口传入三个内容：

- **Style Prompt：** 默认英语。用自然完整的声音指令写作品身份、实际风格/融合、速度拍号、演唱主体与唱法、乐器/制作、整曲能量，以及必要的乐段差异和句级动作。由于歌词字段不承载控制标签，主唱关键完整乐句的声音方向以少数承重词/乐句锚点说明，并写清相关咬字、相对音区、重音、元音延展/释放或段间变化；伴奏在同一锚点的支撑、让位、回应和回归也须来自同一音乐蓝图。用自然语言描述表演方向和相对关系，不虚构拍内起止或声乐硬命令；精确音高、起音、谱面时值与休止由 ABC 事件承载，Style Prompt 不改变谱面事件，也不保证生成完全遵从。不要只留 `soft`、`emotional`、`lead vocal upfront` 之类角色/情绪词。
- **Lyrics：** 单独放已核对的本轮演唱稿，保留应受保护的原词句、标点、已锁定段序和排版；歌名作为元数据置于该输入之外。改词、标签/结构、段序/回返和演唱排版的授权分别判断，获准调整时依共同方法与原始词稿核差异，再以已核对的本轮演唱稿作为输入和比对基线；不能要求歌词包保留已授权更改的旧标签/段序，也不能用新基线追认越权改词。不加演唱标签、不翻译、不改成音节清单。Lyrics 与 note events 没有强制 phoneme-to-note 对齐字段，不把一个汉字等同于一个音符。若有单独编译后的 Lyrics 文本，按适用的文本锁与本轮演唱稿逐字比较。
- **ABC：** 从已完成的事件底稿选取本轮真正要让 YuE2 承接的主唱旋律与一条乐器主题/solo，并按下文编译。它不承载整套配器的多轨事件、鼓/贝司演奏控制或完整和弦排列；完整编曲仍由蓝图和 Style Prompt 表达，无法写进两条单音线的内容不能假装已编码。

此 profile 不承载逐词词谱绑定或专门演唱指令字段；把无法由 Lyrics/ABC 表达的词曲对应和演唱细节留在共同蓝图或适用的 Style Prompt，不增加 `w:`、新的声乐硬字段，也不按一字一音改写歌词或谱面。

这是用户指定或实际界面核实的输入形状，不推出任何云服务的固定字段名、长度限制或 API schema。目标服务未提供可核对 schema 时，只沿用用户给出的三个输入，不补造 API 参数。实际接受、生成遵从和声音质量均须另有证据。

## 先保护来源，再按要保留的内容选择 full 或 melody

先判断音乐来源状态，而不是只看有没有 ABC 文件：①**用户锁定**：按用户指定范围保持事件；②**作者暂定**：原文件仍须保留，但若用户本轮授权改进，就回主 Skill 的作曲步骤修订音符后再投影；③**忠实转换**：以可信谱源或用户明确要求本轮照原事件转换为准，保留指定音高、起音、时值、休止/和弦，不擅自润色。用户只要求格式转换时，音乐在这次转换中作为固定材料，不能顺手重写。原件保护与音乐事件是否定稿分别判断，任何投影另存新结果，不覆盖来源。需要精确保留原曲的翻唱，必须先取得对应录音/版本的可靠完整主旋律谱源并核对版本；曲名、熟悉的开头动机或记忆中的旋律都不能代替全曲谱源，也不能把按记忆新写的旋律冒充原曲。谱源暂缺时先获取可信版本谱，不从录音自动转谱、不调用 SheetSage2；只有用户授权原创或改变旋律时，才另按新作/改编分支创作。YuE2 文本接口并不因为歌词和音频属于同一歌曲就知道应保留的旋律。

按目标决定模式，而不把“原创/翻唱”当固定分界：

| 目标保留项 | 选择 | 编译时核对 |
|---|---|---|
| 主唱/乐器旋律与本轮明确要保留的和声 | `full` | 两条旋律事件按保护范围保留；若已有或已决定的和弦需要进入符号谱，再用支持的引号 chord symbol 标出。符号只写和弦身份与起点，不等于实际声部 voicing。 |
| 主唱/乐器旋律，不保留谱面和弦 | `melody` | 去掉和弦符号；仍保留需保护的 Vocal 与 Ins 旋律事件、音高、起音、时值、休止、小节网格和段落边界。模式允许伴奏由模型更自由生成，但不保证其结果。 |
| 有可信原旋律且要改编/翻唱 | 依要保留的和声选 `full` 或 `melody` | 不因“翻唱”二字默认去和弦；只改用户允许改变的部分。 |

本地 profile 对 `full` 不要求至少出现一个和弦符号；但若任务声称保留了用户锁定的和声，内容完整性仍须确认该和声已有符号表达，不能把无和弦的 full 输入称作和声已保留。`melody` 必须没有音乐行和弦符号。删和弦时不得动音符、tie、休止、声部时序或拍格。若用户要求比较投影前后的旋律事件，应逐条比较两条声部的发声音高、起音、合并 tie 后时值、每小节拍格和速度；和弦差异单独报告。本地 `strip-chords` 保留 Vocal 与 Ins 两条旋律；若只需保护其中一条，须由用户确认后另行编译另一条为同网格休止，不能默默删掉 Ins 主题。

## 将通用音乐事件投影为两条单音声部

通用事件底稿可能包含鼓、贝司、多个和弦音、复调、演唱标注和 MIDI 控制。投影到 YuE2 native ABC 时只保留其中被选定的两条单音线：真主唱进入 `Vocal`，一条有实际旋律职责的器乐主题或 solo 进入 `Ins`。`Ins` 不是键盘和弦或完整乐队总谱；不要把同时发声的和弦音堆成一串单音，也不把 kick/snare 用旋律字母假装成打击乐。其他乐器、贝司根音、和弦 voicing、律动与制作控制由 Style Prompt/编曲蓝图负责，不能声称由 ABC 的两条线完整锁定。

同一符号文件使用固定头部顺序与 bounded profile：

```abc
X:1
T:
M:4/4
L:1/32
Q:1/4=96
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins clef=treble name="Ins Melody" snm="Inst."
K:C
```

`T:` 留空；声部标识固定为 `Vocal`、`Ins`，不得换名或添第三条自定义声部。每组按 `V: Vocal`、谱面行、`V: Ins`、谱面行的顺序交替，每条谱面行包含 1–4 个实际小节；只有进入新段落或需要标明结构边界时才添加 `% verse`、`% chorus` 等注释，不要求每个 1–4 小节组重复段落注释。两线的小节数、拍号/调号变化时点、总时长与拍格必须一致；拍号或调号改变时，以匹配字段开启新的双声部组。该分组让模型看到主唱和一条器乐线，不表示通用 ABC 的任意 voice/staff 排版都能直接重用。

`M:` 使用显式分数拍号，分子为正整数，分母为不大于 1024 的 2 的幂；拍号或调号变化在两条声部的同一时间点同步，拍号变化用新组匹配的 `M:`，调号变化可在新组用匹配 `K:`，也可在小节内用 `[K:...]`，但两线必须同一音乐时点改变。`K:` 只使用 helper 支持的大调 `Cb, Gb, Db, Ab, Eb, Bb, F, C, G, D, A, E, B, F#, C#` 或小调 `Abm, Ebm, Bbm, Fm, Cm, Gm, Dm, Am, Em, Bm, F#m, C#m, G#m, D#m, A#m`。`Q:` 固定写 `Q:1/4=<正整数 BPM>`。`L:` 固定写 `1/<2 的幂>`，分母不超过 1024；`1/32` 常见但不是唯一，`1/8` 合法。改变 `L:` 时，所有音符和休止的长度乘数须同比调整，确保发声时长不变。每个 note/rest 的长度乘数只允许 `1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48`；更长时值拆成相邻同音 tie 音符，或相邻休止，不可使用近似时值。大写字母对应 C4–B4，小写字母对应 C5–B5；每个逗号下移一个八度、每个撇号上移一个八度（如 `C,`=C3、`c`=C5、`c'`=C6），谱面计算后的音高须在 MIDI 0–127 范围；`^`、`_`、`=` 与 `^^`、`__` 分别表示升、降、还原、重升、重降。helper 的临时记号在同小节按字母跨八度延续；小节线或调号变化时重置。Tie `-` 只能连接相同发声音高的音符，不产生新起音；rest 不能 tie，也不能有升降号或八度符号。跨小节的持音 continuation 即使未重复临时记号也保留前音音高，且谱尾不能留下未解决 tie。时值和休止均占用拍格，逐小节核平，不通过缩短相邻音符隐去空拍。完整小节休止 `Z` 按小节数计（`Z` 至 `Z4`）；跨和声/调号变化时不要用压缩休止跨过事件，改为普通休止并保留事件起点。

YuE2 的引号和弦名写和声标签，只能放在 `Vocal` 音乐行的真实和弦起点上，即使主唱当时休止也可出现；它不代表同时奏出整组音符。固定 helper 的 chord 白名单是：根音及可选斜线低音均为 A–G 音名，可带 `b`、`#`、`bb`、`##`；质量后缀只能为空（大三和弦）、`m`、`dim`、`aug`、`7`、`maj7`、`m7`、`dim7`、`m7b5`、`sus4`、`sus2`、`6`、`m6`、`7sus4`、`m(maj7)`。不得把 `C:maj`、数字转位、`13`、`alt`、`maj9` 或任意注释写成原生和弦语法；若持音期间和弦变化，在变化起点拆分该音并以同音 tie 连接，避免把第二段误作新起音。该白名单是本地 helper 范围，不是对云端解析器硬限制的断言。若复杂和弦属于用户锁定和声且白名单不能忠实编码，不可静默简化或声称 Style Prompt 会精确保留；暂停该和声符号交付，说明表达损失并提供通用谱/MIDI等准确承载路径，或在用户同意后再用可表示和弦核心。

本项目本地 checker 使用比一般 ABC 2.1 更窄的 bounded profile，以便可靠核对 YuE2 投影中的音符事件和模式。它不接收 `w:` 歌词字段、自定义 voice/directive、音符堆叠、装饰/倚音、slur、tuplet、repeat/alternate ending、broken rhythm、double barline 或 helper 未覆盖语法；遇到此类文本必须报告 unsupported 并返回重编译/目标解析器判断，不能默默删掉符号。遇到这些记号时，只有能够按原起音、时值、发声音高与结构精确展开成受支持事件，才可展开后投影；若三连音等节奏无法落入所选 `L:` 时间格，或复调/装饰属于用户锁定信息，不得默认量化、删去或改写后声称保留。说明具体损失，只暂停该关键取舍并请用户决定是否改用能承载的通用 ABC/MIDI/MusicXML，或授权有损转换。Style Prompt 可以描述演奏意图，但不等于精确保留这些符号事件。checker 拒绝只表示超出本地 profile，不表示其违反完整 ABC 标准或必然被云端拒绝。通用谱仍按 [输出契约](output-contracts.md) 的 ABC 2.1/目标方言处理。

## 将 Style 与谱面、模式及结构长度交叉核对

生成前把最终 Style Prompt、锁定 Lyrics、ABC 和所选模式放在一起检查。若 Style 指定的主唱旋律、速度/拍号、段落次序、主题材料或和弦与受保护 ABC 互相矛盾，先按用户锁定项消除冲突；无法由既有目标判断时，只暂停该冲突决定，不让不同输入各自描述一首歌。Style 可以补充 ABC 未编码的配器和制作，但不能把这描述成符号谱已包含鼓、贝司、多声部和弦或混音。

ComfyUI 公开的 `YuE2GenerateMusic` 节点包含 `style`、`lyrics`、`abc` 字符串输入，`mode` 的 `full`/`melody` 选项与 `max_duration` 秒数上限。实际外部谱非空时才是有谱输入；若 `abc` 为空，节点实现会把 mode 改为 `off`。检查当前工作流确认外部 ABC 确实进入这个非空 `abc` 输入。已核对的公开工作流模板用 `ABC_planning` 控件作接线辅助；关闭内部规划时可能给音乐节点送空字符串。使用外部谱时须替换空串或把该连接改接外部 ABC 字符串。这个映射只适用于已检查的 ComfyUI 节点与模板；不能拿它猜其他云端服务的字段名。实现内部 `cot` 也不是云端用户字段，不作为字段映射依据。

输入 ABC 的拍数可给出名义时长：总四分音符数 ÷ 四分音符 BPM × 60。比如 68 个 4/4 小节在 96 BPM 是 170 秒；若模板的生成上限仍是 120 秒，就不足以覆盖这份谱的名义长度。运行前用实际 ABC 计算长度，再确认 `max_duration` 至少覆盖目标长度；该参数只是上限，不能保证音乐生成到这个长度，长 Style/Lyrics/ABC 也可能受到模型上下文长度影响而提前结束。只有拍数计算能说明理论覆盖范围，不能证明输出文件完整。

## 检查和交付各自能证明什么

用项目 checker 的实际 CLI 检查 bounded profile：`python3 tools/check_yue2_abc.py inspect ABC [--mode full|melody] [--max-duration SECONDS] [--lyrics SOURCE --package-lyrics FINAL] [--output JSON]`；锁定投影用 `compare BEFORE AFTER [--voices Vocal|Ins|both] [--allow-tempo-change] [--output JSON]`；去和弦另存新文件用 `strip-chords SOURCE DEST`。`full` 不要求至少一个和弦符号；`melody` 要求音乐行没有和弦符号。`strip-chords` 默认保留两条旋律线，只移除音乐行和弦符号，不能覆盖源文件。歌词成对比较只统一换行符，保留其余字符、标点、顺序；只有成对提供 `--lyrics SOURCE --package-lyrics FINAL` 才执行。检查输入头部、两声部、调号临时记号、音高/八度、合并 tie 后的音符、时值、起音、休止、逐小节拍格、结构注释、和弦起点及指定模式约定；给出 `--max-duration` 时按本地计算的 ABC 名义时长校验。对 `melody` 投影另以 `compare` 检查两线事件不变；需要改变速度时显式允许并单独核对。检查通过只说明这些可观察文本/事件符合 bounded profile，不测试真实和弦和声、旋律审美、唱词可懂度、云端字段接通、接口接受、音乐生成完整度或音频遵从。

生成后只有在拿到目标云服务实际输出并完成收听/必要比较后，才能报告对应声音结果。遇到输入被忽略、旋律偏离或提前终止时，先分辨空 ABC/错误接线、模式、时长上限/上下文、谱面投影或生成偏差；不要因本地 parser 通过就宣称模型遵从，也不要把音频转谱当成补救步骤。
