# 三技能闭环交接与追溯协议

在规则审查、原因分析、能力写回或复查相接时使用本协议。单入口按本轮所需读取职责或深度对应小节，接回自己的工作步骤。任务范围、权限与材料保护以[能力运行约定](../docs/runtime.md)为准。

## 1. 三技能单一职责与交接红线

| 入口 | 负责判断与交付 | 交给下一步的条件 |
|---|---|---|
| audit | 定位有证据的目标差距，说明对象内部机制、职责和证据阶段；有确定修法的同材料对照按[局部改后对照](../.agents/skills/laohu-evolution/references/rule-expression.md#对已确认差距做报告内局部对照)回到问题包。 | 有需跨环节定因、未决架构、专业取舍或接口变更时交分析；修复与原文件写入归获授权的实施入口。 |
| analysis | 确定最早可证断点、可行方法与关键取舍，评价负载与跨技能依赖，产出决策级变更规格和验收判据。 | 将已定选择和仍未决的依赖移交实施；实际编辑能力文件归 evolution。 |
| evolution | 核实规则真源，逐项保义写回，接通调用、公开入口配置、机器接口、评测和下游，运行适用静检及写回双门禁。 | 遇到改变目标、核心方法或权限的未决决定，只暂停依赖写回，带具体事实及影响交还分析；把修改材料交给获授权的复查。 |

涉及规则改动，analysis 负责定清目标行为、根因与断点、受影响控制位置、新逻辑与分支、冲突如何裁决、保护项和验收。只有用户明确要求交给不经过 evolution 的独立执行者，或明确索要精确补丁时，analysis 才附原句级完整替换块。evolution 依据同一决定，[按语义对照](../.agents/skills/laohu-evolution/references/rule-expression.md#更新规则前按语义对照)清点各句可执行判断并编排正文，跟进消费者和评测。

## 2. 统一追溯主线（AUDIT-ID 交接契约）

为已确认问题沿用稳定编号，如 `A-01`。复查无旧编号但可定位原问题时，可由稳定段落、元素或行为锚点映射本轮编号。后续阶段用同一编号记录何处定因、如何写回、依据哪一层复核。多问题共享一处补丁时保留所有关联编号；独立新问题另编号。这些字段为跨 Skill 或跨 Agent 的内部交接数据，用户交付按任务自然展开。

| 流向 | 应交给接手者的内容 |
|---|---|
| audit → analysis | AUDIT-ID、影响（P0 阻断核心用途 / P1 削弱主要作用 / P2 局部损耗或隐患）、文件/章节/原句或片段、对象职责与判据、差距机制、证据层级（规则文字 / 加载路径 / 执行轨迹 / 实际成品 / 真实接收）、保护项、局部对照有无及材料、已查与未查方向。 |
| analysis → evolution | 原编号、八类断点之一或证据不足状态、选定方法与取舍依据、受影响文件/消费者/测试、复杂度和必读负载、控制点的旧位置/新逻辑/冲突裁决/保护项、须新增或同步的 eval 场景、未知与限制。 |
| evolution → retest 或独立验证 | 原编号、变更文件和真源归位清单、信息与力度保真核对、恢复位置、eval 同步记录、静检结果、待独立验证项。给独立执行者的普通输入不得附制作解释或评分预期。 |

授权复查时按原条件、原证据层级及保护动作检查，由[问题复查](../.agents/skills/laohu-audit/references/retest.md#更新原编号与状态)回填状态及证据。规则文字能证明文字差距，运行、成品和接收效果各须相称观察。项目四类验收证据沿用 [AGENTS.md](../AGENTS.md#验证)。

## 3. 万能造梦框架的跨入口接力与分级深耕

本节深度与交接仅用于三技能及其授权复查。其他入口遵循各自的框架契约。在已授权对象内，按[万能造梦框架](universal-dream-framework.md)确定要看哪些关系，把发现接到各自的工作结果：

- audit 覆盖适用作用，标出已确认差距、已有充分承接及未覆盖交点，以材料和判据支撑。
- analysis 快速核实上游的覆盖、材料和盲区，然后深查问题交点及直接因果依赖。新证据可改变范围内的判断，保留已核实观察供后续使用。
- evolution 将已选决定接到真实触发、动作、产物和消费者。分别核对实施链和目标 Skill 运行链。授权复查时核对原问题及受影响保护行为的直接依赖。

| 本轮深度 | 工作要求 |
|---|---|
| 新建能力、整体重构、跨职责大融合、完整能力设计、常规整体审查、整体解释、全流程调查、整体方案分析 | 实质审视全部 16 个交点，各入口把所需判断接到真实材料和结果。已有证据充分时沿用，仍补允许范围内的盲区。 |
| 单点修订、局部规则补丁、单项分析/审查/复查 | 深审受影响交点和直接上下游；其余做无副作用核对，确认保护项、权限和接口完整。有材料显示影响较广时，按实际依赖扩大检查深度，范围仍服从本轮授权。 |

按职责接力，各入口复用已确认目标、保护项和材料。跨同一因果链的观察可由同一方法支撑，实际判断和结果需可追查，交付无需逐格表述。普通业务请求沿目标能力正常路径执行。

## 4. 授权流转与自然接续规则

- 只要求找问题时，由 audit 完成诊断及适用的同材料对照。确有跨环节根因或核心取舍时，向用户说明分析能解决的待决点。
- 要求找问题并说明原因或给优化方案时，audit 发现实际差距后带编号和问题包接续 analysis。对象内部解释留在 audit；无已确认差距时交覆盖结果与证据缺口。
- 同时授权找问题、分析并改进明确指定的仓库能力时，依序审查、定因和写回。遇到会改变核心目标、方法或权限的未决选择，只暂停依赖它的写回，询问最小必要决定，其余工作继续。
- 已有明确方案或已知方法的常规执行可直接交有权实施的负责人。用户授权复查时按原编号接续；复查发现问题后的处理仍按本轮授权。

## 5. 共性经验向 knowledge/ 的按授权沉淀环

多个 Skill 反复暴露同一类有价值的规则模式或执行断点，且用户已明确授权沉淀长期经验时，evolution 按 [仓库资产规则](../AGENTS.md#资产与权限)记录适用条件、可观察信号、已验证探针或做法，供后续按需核对。个案尚待证实时保留其限度。需要影响实际运行的结论写回唯一规则控制点，保留触发、例外和停止条件。
