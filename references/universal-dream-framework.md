# 万能造梦框架：能力判断与设计方法

本框架把**四个判断维度**与**四个工作层次**交叉使用，用于完整检查创作、分析、规则、流程及其他能力中的目标、专业依据、具体实现和可观察结果。它是内部判断框架，不是固定问卷、线性流程、答案表或对外报告模板。

## 两条轴各自表示什么

四个维度描述“当前判断在看什么”：

- **灵魂**：目的、立场、价值判断、宏观策略及据以取舍的标准。创作中包括作品要达成的目的、作品立场、文化与审美判断和宏观策略；规则、产品或工程任务中，则看能力为何存在、保护什么、优先级如何，以及什么算偏离。它不只是愿望或口号。
- **筋骨**：使目标可成立的专业结构、理论、方法、技法、机制、标准或设计原理。创作中包括为实现灵魂而选择、组合与配置的成熟专业法度；规则、流程或工程中也包括适用的专业知识、结构关系、接口和可执行机制。它不等于流程清单或方法名称。
- **血肉**：把目标和专业方法落实为当前对象的具体内容、材料关系、动作、选择和表现设计。创作中是本作的内容、人物行动、信息、视角、意象或声音安排；其他能力中则是针对当前输入、状态、用户或组件的具体处理。它不等于抽象原则，也不等于最终交付物本身。
- **表皮**：最终接收者或使用者实际遇到的作品、界面、文本、行为或其他可观察产物，以及它在真实媒介、体裁、文化语境与使用条件中的呈现。创作文字包括真实词句段；规则和工程能力也须落到实际运行、界面、输出或使用结果，不可缩成排版与外观。

四个层次描述“判断在处理哪种工作关系”：

- **目标**：希望改变、实现或保留什么；对谁、在什么情境与边界内成立。
- **判断**：依据什么材料、知识与标准识别条件、作出取舍、判断适用性或确认达成程度。
- **行动**：由谁在什么条件下执行哪些选择、转换、创作、交接或纠偏。
- **结果**：预期要形成或交付什么，以及动作实际产生了什么、怎样被下一步使用或由接收者观察；预期与实际须区分，预期本身不是已发生的证据。

两条轴关注不同事物：维度不是时间顺序，层次也不是四个领域分类；这不表示实际工作彼此平行或没有逻辑依赖。已确认目标可能约束专业判断，材料和条件会改变处理动作，动作再形成由下游使用或由接收者观察的结果；具体依赖由领域方法决定，不从坐标顺序推定。概念、方法或媒介要素不按名称固定归类；例如“节奏”可以是所选成熟方法中的判断、当前作品的表现设计，或最终听到的语言效果，取决于它在本次判断中实际承担的作用。故事的幕、场、节拍等叙事尺度另由适用方法与媒介决定，不等同于任何维度或层次。

## 怎样完整应用

在本轮授权对象和已确认目标内，对四个维度与四个层次的全部16个交点逐一作实质审视；这是完整检查范围，不规定固定顺序，也不要求内部工作按坐标逐格排队。根据当前对象、材料、功能责任和任务条件，让问题与方法具体生长；不预设每格的标准答案、子项、问题数量或必须改变的动作。每个交点都要实际改变对当前目标、依据、处理或结果的理解，形成与这项任务职责相符的判断，而不是只留下一个标签。**完整覆盖不等于每格都要找出缺陷、增加规则或改变结果。**逐项检查可以确认已有内容已充分承接、某项关系有缺口、条件尚不明确，或在具体任务中经材料核验后没有独立贡献；这些是有依据的状态，不是统一模板。能力设计、创作或方案分析也依各自目的形成专业贡献，不默认进入审错。

每个交点须真正影响对目标、依据、选择、实现或结果的理解，不能只贴维度名、层次名或抽象质量词。四维与四层的交点表示两种观察方向在此相遇时的侧重，不是封闭内容类别、单一职责槽位或预设答案。相同的交点放进不同 Skill 后，要根据各自目的、对象和专业责任变成不同的操作、判断依据与产物，不能套用一套跨领域的固定检查清单。一个方向可以承载数个彼此独立的规则组，但只有职责、条件或动作确实不同才拆分；这不是增加规则条数的指标。一项完整方法也可横跨多个交点。规则在哪个交点被重点检查，不限制它必须只含该层内容。完整规则单元须自然承接完成工作所需的目标、判断、行动、结果作用；这些作用可以由同一段中的多句话、相邻步骤或共同条件共同表达，不要求每一句都包含四项。交点侧重点与规则内部工作作用相关但不等同，也不递归扩为64格或第三轴。

交点之间可以相互关联、合并、嵌套、反复核对或突出最重要的部分；同一材料可支持多项判断，也可因一项关键关系同时影响多个交点。四个维度会彼此支撑、校正或制约，四个层次也会共同构成实际任务关系；它们不是一条必须从“目的”机械走到“结果”的线性流程。完整方法应保留为一个可运行的整体，在它实际改变不同判断的位置接入，不拆成互不相认的格子，也不重复维护多份真源。子问题、知识、深度与组织随对象生长。完成全方向检查后，将相互依赖的发现综合成符合该 Skill 实际工作方式的自然主线和交付；不要求展示16格、逐格报告或把内部检查项变成用户问卷。

框架不规定能力架构的模块数量或分工，但可以指导整份 Skill 的架构、章节、段落和规则组怎样组织。正式标题应使用实际工作与职责语言，让不熟悉框架的执行者也能找到并完成任务；真实职责关系允许时，可以形成十六个自然功能组，但不强制一个交点一个标题，也不因“对外无需展示坐标”而省略各方向应承接的具体规则。实际功能仍按目标、专业对象、决定责任、输入与下游产物组织；一个模块或完整方法可以同时承接多个交叉方向，同一方向也可能需要数个独立规则组或连续功能共同完成。设计时按这些关系安排职责与依赖，运行时再看普通任务中条件如何改变选择、动作如何处理材料、结果怎样交给实际消费者。缺少某个坐标对应的标题不等于功能缺失；有标题、标签或规则数量也不证明其功能充分。只有核对实际条件、动作及其被消费的结果，才能判断已有规则是否承接。

知识和方法依据按当前对象与问题分布在相关判断中：确需专业支撑时，可采用本地材料、已选方法、适用标准、理论、术语或总结过的成熟经验，并确认它确实适用且能指导判断。任何单一交点不独占此要求，也不为形式覆盖而机械外搜；术语要有实际作用，缺少特定名称不等于缺少方法。相称依据确实不足且会影响结论时，说明具体缺口，不造理论或把知识缺口直接判成对象错误。框架提供方向覆盖与关系组织，不穷尽任何领域的专业知识，也不宣称其专业效果已被实证验证；宽度帮助发现遗漏的功能与关系，深度帮助展开关键条件、方法、材料动作和例外，二者最终都要落在接收者实际遇到或使用的结果上。方向数、子项数、字数和术语密度都不能代替领域依据、实际执行或接收质量证据。

## 范围、传递与表达

框架只应用于本轮授权对象，不以“完整覆盖”为由扩展到无关入口、对象、文件、外部动作或未授权作品。沿用事实、目标、保护项、用户决定和已核证据；上游交接提供的发现和材料可作为输入，但其坐标、标签、排列或遗漏不能限制下游按自身目的和职责重新完整应用框架。各类专业工作如何承接与落实，由对应入口的运行方法规定。

内部审视深度随对象和判断难度变化；结果表达则服从当前 Skill 的职责、用户所需产物、接收者和机器接口。能把多项交点融合成一个准确的解释、修订或实施动作时就自然融合；只有读者确实需要比较映射时才显式列项。框架帮助补全判断，不替代来源核验、事实边界、授权、质量证据或专业 Skill 的领域方法。内部完成16个方向的应用，不意味着最终必须逐格呈现；最终表达应把其中有材料支持、对用户有用的关系组织成易理解、能接续下一步的结果。
