# 老胡造夢技能

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [繁體中文](README.zh-TW.md)

> 老胡為 AI 造夢師準備的造夢師技能。
>
> 涵蓋音樂、封面、影片、標題等多個內容創作與發布領域，由造夢師依照自身審美水平合理搭配，完成 AI 創作與發布。讓我們一起為這個世界畫一個夢！

老胡造夢技能是一套以人為中心的 AI 創作 Skill 工具箱。它不替人決定「現在應該做什麼」，而是把不同創作能力拆成可以主動選擇、獨立調用並逐步組合的入口：人決定目標、範圍和關鍵取捨，AI 在確定的範圍內完成專業工作。

## 它解決什麼問題

你可以直接選擇目前需要的能力：發展選題、寫歌詞、設計封面、撰寫影片提示詞、整理作品，或找出一份作品真正出了什麼問題。

如果你還不知道該使用哪個入口，可以使用 `/laohu`。它會根據目前任務協助你釐清目標、比較可用能力，並把選擇權交還給你。

完整流程入口與專項入口可以分開使用。例如 `laohu-lyrics` 負責歌詞創作流程，未來建立的 `laohu-lyrics-rhyme` 可以只處理韻腳問題；大流程按需讀取專業方法，專項能力也可以獨立使用。

## 如何運作

```text
人的目標與材料
        ↓
/laohu 或使用者直接選擇一個入口
        ↓
確認本次任務的範圍、保護項與交付物
        ↓
入口按需讀取專業方法、案例與資產
        ↓
交付目前結果，等待人決定修改、繼續或結束
```

目錄可以依照職責組織，但所有需要被不同 Agent 獨立發現的入口，都會保持為可登記的第一層 Skill。流程 Skill 可以統籌專項能力；如果宿主不支援 Skill 對 Skill 的調用，就在目前入口讀取相同的 Reference，不能把推薦調用偽裝成已經執行。

## 專案結構

```text
laohu-creative-skill/
├── AGENTS.md       專案規則、路由邊界與資產保護
├── README.md       專案簡介與入口說明
├── LICENSE         CC BY-NC 4.0
├── skills/         可發現、可主動調用的 Skill 入口
├── works/          作品專案、過程檔案、確認稿與發布材料
└── knowledge/      可複用知識、案例、經驗與長期資產
```

`skills/` 下的 `.gitkeep` 只用於讓 Git 保留目前的空目錄，不代表對應能力已經完成。後續會按需要加入 `SKILL.md`、`references/`、`templates/`、`scripts/` 和測試檔案。

## 設計原則

- 人決定做什麼，AI 負責在授權範圍內完成什麼。
- 已經知道目標時，直接調用對應入口；不知道時再使用 `/laohu`。
- 只有獨立問題才拆成獨立 Skill，光影、押韻、景別等方法預設作為專業 Reference。
- 作品、個人資料與知識資產和工具箱方法分開，更新工具箱不覆蓋使用者資產。
- 每項能力都要寫清觸發條件、輸入、輸出、必須保留的內容與停止條件。
