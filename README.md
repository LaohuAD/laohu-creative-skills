# 老胡造梦技能

> 老胡为 AI 造梦师准备的造梦师技能。
>
> 涵盖音乐、封面、视频、标题等多个内容创作与发布领域，由造梦师根据自身审美水平合理搭配，完成 AI 创作和发布。让我们一起给这个世界画个梦！

老胡造梦技能是一个以人为中心的 AI 创作 Skill 工具箱。它不替人决定“现在应该做什么”，而是把不同创作能力拆成可以主动选择、独立调用和逐步组合的入口：人决定目标、范围和关键取舍，AI 在确定的范围内完成专业工作。

## 它解决什么问题

你可以直接选择当前需要的能力：写歌词、确定选题、设计封面、写视频提示词、整理作品，或找出一份作品真正出了什么问题。

如果你还不知道该使用哪个入口，可以使用 `/laohu`。它会根据当前任务帮助你澄清目标、比较可用能力，并把选择权交回给你。

完整流程入口与专项入口可以分别使用。比如，`laohu-lyrics` 负责歌词创作流程，`laohu-lyrics-rhyme`（未来建立）可以只处理韵脚问题；大流程按需读取专业方法，专项能力也可以独立使用。

## 怎样工作

```text
人的目标与材料
        ↓
/laohu 或用户直接选择一个入口
        ↓
确认本次任务的范围、保护项和交付物
        ↓
入口按需读取专业方法、案例和资产
        ↓
交付当前结果，等待人决定修改、继续或结束
```

目录可以按职责组织，但所有需要被不同 Agent 独立发现的入口都会保持为可登记的一级 Skill。流程 Skill 可以统筹专项能力；如果宿主不支持 Skill 对 Skill 的调用，就在当前入口读取相同的 Reference，不能把推荐调用伪装成已经执行。

## 项目结构

```text
老胡造梦技能/
├── AGENTS.md       项目规则、路由边界与资产保护
├── README.md       项目简介与入口说明
├── LICENSE         CC BY-NC 4.0
├── skills/         可发现、可主动调用的 Skill 入口
├── works/          作品项目、过程文件、确认稿和发布材料
└── knowledge/      可复用知识、案例、经验与长期资产
```

`skills/` 下的 `.gitkeep` 只用于让 Git 保留当前空目录，不代表对应能力已经完成。后续会按需要加入 `SKILL.md`、`references/`、`templates/`、`scripts/` 和测试文件。

## 设计原则

- 人决定做什么，AI 负责在授权范围内完成什么。
- 已经知道目标时，直接调用对应入口；不知道时再使用 `/laohu`。
- 独立问题才拆成独立 Skill，光影、押韵、景别等方法默认作为专业 Reference。
- 作品、个人资料和知识资产与工具箱方法分开，更新工具箱不覆盖用户资产。
- 每项能力都要写清触发条件、输入、输出、必须保留的内容和停止条件。
