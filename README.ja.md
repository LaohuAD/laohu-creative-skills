# 老胡造梦技能

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [繁體中文](README.zh-TW.md)

> AI で夢をつくる人のために、老胡が用意したクリエイティブ Skill です。
>
> 音楽、カバー、動画、タイトルなど、コンテンツ制作と公開に関わる複数の領域を扱います。造夢師は自分の美意識に合わせて能力を選び、組み合わせ、AI を使った制作と公開を進めます。一緒にこの世界に夢を描きましょう。

老胡造梦技能は、人を中心に設計した AI クリエイティブ Skill ツールボックスです。AI が次に何をするかを勝手に決めるのではなく、さまざまな能力を、人が選び、単独で呼び出し、段階的に組み合わせられる入口として整理します。目的、範囲、重要な判断は人が決め、AI はその範囲内で専門作業を行います。

## 解決すること

選題、歌詞、カバー、動画プロンプト、作品整理、完成作品の問題発見など、今必要な能力を直接選べます。

どの入口を使うか分からないときは `/laohu` を使ってください。現在の課題を整理し、使える能力を比較し、最後の選択をあなたに返します。

完全な制作フローと個別の専門入口は別々に使えます。たとえば `laohu-lyrics` は歌詞制作全体を扱い、将来作る `laohu-lyrics-rhyme` は韻や語尾の問題だけを扱います。フローは必要な方法を読み込み、個別の能力も単独で利用できます。

現在はディレクトリの骨組みだけがあります。具体的な `SKILL.md` は実際の制作課題に合わせて順次作成します。

## 仕組み

```text
人の目的と素材
        ↓
/laohu または直接選んだ入口
        ↓
今回の範囲、保護する判断、納品物を確認
        ↓
必要に応じて方法、事例、アセットを読み込む
        ↓
結果を渡し、修正・継続・終了を人が決める
```

異なる Agent が独立して発見する必要のある入口は、登録可能なトップレベル Skill として保持します。ホストが Skill から別の Skill を呼び出せない場合は、同じ Reference を現在の入口から読み込みます。実行していない呼び出しを、実行済みとして扱いません。

## プロジェクト構成

```text
laohu-creative-skill/
├── AGENTS.md       ルール、ルーティング境界、アセット保護
├── README.md       プロジェクト紹介と入口案内
├── LICENSE         CC BY-NC 4.0
├── skills/         発見・呼び出し可能な Skill 入口
├── works/          作品、草稿、確認済みファイル、公開資料
└── knowledge/      再利用可能な知識、事例、経験、長期アセット
```

`skills/` 内の `.gitkeep` は空のディレクトリを Git に保持するためだけのものです。対応する能力が完成したことを意味しません。必要に応じて `SKILL.md`、`references/`、`templates/`、`scripts/`、テストを追加します。

## 設計原則

- 何をするかは人が決め、AI は許可された範囲を実行します。
- 目的が明確なら対応する入口を直接使い、不明なときだけ `/laohu` を使います。
- 独立した問題だけを独立 Skill にし、光、韻、ショットサイズなどは原則として Reference にします。
- 作品、個人資料、知識アセットとツールボックスの方法を分離し、更新でユーザー資産を上書きしません。
- 各 Skill は、発動条件、入力、出力、保護する内容、停止条件を明記します。
