### 从用户输入到完整时间线

1. **定时间。** 已有音频用 ASRcut 取得保留段、词或句的真实时间；去停顿、重排或插入个人片头后，字幕、画面、声音都用剪后时钟。有稿无音频时先确定是屏显讲述、配乐驱动还是用户授权配音；纯画面按阅读和动作时长排。默认新作横屏 16:9。
2. **定视觉。** 当前主模型用 Analysis 输出唯一 Brief。每段记“哪句话或哪个观看任务、先看什么、如何变、留下什么给下一段”。风格目录决定形状、材料、色彩、字形与空间；另查动效目录决定动作从何处起、沿何路径、何时加速、何时停稳、触发谁。拟采用项写明真实 ID、画面片段以及希望保留的可见特点。区分原作示范内容与本片能陈述的事实。例如资金去向可以分支，只有真实份额数据才能让线宽代表资金量。
3. **把画面做成能执行的设计。** 每个屏显区间写出可见原文、文字归属与相对尺度、前态、动作触发、后态、接到下段的对象、声画落点；可跨句延续一个镜头。多分钟作品按论点推进编排远近、主次、空间及速度，在重要关系改变时变换镜头；保留需要停读的段落。新增长句交 Writing，标题或总结交 Title，事实经 Analysis 核对后进入 Brief 的文字登记。生成工程只显示登记文字。字幕继续使用项目固定的横竖屏双语规格。
4. **核验真实运动。** 关键帧看构图、层次和读字；跨镜移交再看短动态，检查停顿、加速和遮挡有没有传递意义。获准制作后打开持续预览工作台。用户明确豁免时沿其范围连续制作。Luna 领取具体镜头、已有条件、可调边界、输入输出与验收；审美选择、章节接力与全片统筹由主窗口负责。
5. **处理声音和素材。** 按真实动作列事件，给出起音、着点、尾音和音乐让位；本地成品缺合适音色时检索外部已制作素材，实际试听后采用。音乐跨段衔接核对拍头、乐句、和声与重叠区，检查接缝处的空洞。用户常用人声约 −3、音效 −12、音乐 −20 dB，运用前先对齐计量方式、活动区间和轨道基准；轨道推子、短时 RMS、整体 LUFS、真峰值分别报告。安静间隙不参加事件平均，保留动态余量，最终以同音量对白清晰、提示可听、总线无削波为准。
6. **分段构建，整片核对。** 各段使用同一主时钟和稳定的媒体标识。逐段预览前后连接、字幕安全区与命中音；修改后只重渲受影响镜头，最终复核拼接、整片声音、首尾和声画总时长。记录参考查找、设计、等待确认、实现、首渲、返修和编码的墙钟时间，并行段按最长路径计，保留返修前首渲作盲比。比较 Luna 与主窗口时锁定同一份 Brief、素材和质量标准，区别模型选择、指挥、返修和编码造成的时间差。

### 后续 Studio 与可选生成接口

OpenMotion Studio 的优势是从预览直接定位可编辑的对象和时间。验证替换时先用一个真实项目检查打开、定位、修改、保存后重开、音轨与字幕是否同钟、导出是否同帧；另外检查旧 Canvas/SVG/WebGL 镜头的确定性取帧和长片分段。将本项目原时间线作为唯一有效时钟，在适配层转换 Studio 所需信息；同一编辑在两边产生不同结果时先定位差异，再切换作品默认入口。四个自带工程成功打开仅验证示例。替换生效标志为普通制作命令实际打开新工作台，用户改动可保存并进入导出。

画梦枋未来生成音乐或视频时从 Brief 的素材说明接入。每项写所属镜头、媒体类型、用途、时长、透明或循环需求、本地候选不满足之处及当前可行方案。供应商配置就绪后，由应用管理凭据、费用授权、任务身份和结果文件；工程只引用有来源记录的本地结果。短缺音效先试听已完成的同类声音。镜头靠代码与已有资产达到设计目标时可直接制作。

### 验收与回退

- **目录与文件**：每个上游 ID 指向可读指南和本地预览；有真正工程文件的记录标明边界。原包先验证成员与差异，再清除；直接读取展开内容。正式资产可独立于下载缓存检索，私有库随工作盘单独保护。
- **真实路由**：从普通 Motion 请求测试旧配方、正式模板和用户对标三条路径。换工作目录后继续能查找；缺少某来源时报告该来源可用性。读到的字节、制作中绑定的标识和样片是否好看分别验证。
- **作品质量**：用同一段真实口播对照原片与候选改编。只看片能否读出关系，静音看焦点交接是否自然，开声辨认关键着点，小屏检查字的层级。首轮样片与返修片保持相同画幅、音量和播放条件，再由真实观看者选出更清楚、更有吸引力的一版并说明具体秒数。
- **长片与性能**：短片通过只证明该片段，正式切换 Studio 或普及新做法前，再用多段含音频、跨段转场的实际长片检查保存、导出与复现；用同输入的时间日志比较性能。

## 1．这次改造的目标与边界

要改变的是“从普通输入形成视听设计，再将设计实现”的实际行为。来源资源要同时参与长相、信息、动作与声音，成熟实现要保留其有效机制；全片要成为有身份、有变化、有信息与情绪表现的作品，而不是多个风格标签或默认卡片的集合。

共同目标：

- 内容事实、顺序、关系与视觉开放变量分开，不能由题材联想直接锁定冷色、暗场、工业材质或固定机位。
- 默认模式二为多来源融合。依据具体贡献组合形态、色彩、字体、材料、空间、动作与镜头，不依类别好坏或相似度选唯一来源。
- 专业术语与可见描述一起使用。Brief 写清对象、状态、运动、构图、文字与声画承接，代码与精确实现参数交 Motion。
- 字幕/关键词真实时间、屏显补充信息、素材身份和声画事件能接到同一影片时钟。
- 新知识可读、源码可运行、素材已取得、实际听审与最终质量是不同状态，不混报。
- 默认新作 16:9；关键方向/必要动态小样确认、持续工作台与最终预览沿既有规则，用户本轮明确免除的范围单独生效。
- 中文讲解制作字幕时默认中文上行、英文下行并置于底部安全区；有实际多章节的知识讲解默认顶部紧凑导航，用户/素材例外按第11节处理。
- 人类风格画廊纳入同批实施，AI以Markdown为生产依据，全部视觉资源从统一目录发现。

本轮已授权实施统一规则、资源目录、生产输入、字幕/章节消费者、音频处置与人工画廊。43 张受保护原卡和 111 闭包没有被改写；正式资源、当前普通工作入口与实际消费者的落点见第9节。方向关键帧和动态小样仍按普通生产规则执行；本轮维护工作获免，不改变后续作品的默认确认门槛。

## 3．统一后的真实制作路径

### 3.1 收拢材料和时间依据

恢复用户目标、原始素材、时长/画幅/锁定项与当前制作状态。真实录音/录屏需要剪辑与时间信息时，ASRcut负责实际编译与显示cue；Analysis可以形成剪辑设计，不能用估计词时码填表。中文字幕默认配英文译行，翻译独立于ASR原文但消费同一显示窗口；需要扩展现有caption契约而不是把英文塞进中文lines。没有口播/字幕需求时不生成空SRT。章节按实际内容分析并从同一时间线落地。

输出是本片真实材料和设计边界，写进唯一八块 Brief 的对应位置；不另建一套源稿或字幕时间表。

### 3.2 先完成足够的视觉和动作输入

完整新方向按第11节L0—L3：先读现有正式风格丰富中文目录、覆盖Atlas全部制作候选的视觉家族导航、Motion Prompt全部240项中文可见含义/用途概览、20项表达能力概览与共同动作语言。不同文件只区分职责，所有资源从一个视觉发现入口查询。需要比较的家族/候选继续展开，拟采用项必须读完整生产正文、必要条件与动作规格；Motion实现前再读源码/kit。历史长文、全量原prompt和授权追踪不混进默认正文。

“必读”是产生方案之前实际获得能比较的动作语言，不是列出一串术语 ID。渐进式加载限制无关全文和源码，不削弱必要的行为理解。当前上下文与来源版本一致时复用，换上下文后依实际缺失有界回读；持有回执不等于仍理解正文。

### 3.3 从内容需要发展多种可能，不先给风格判死刑

材料明确事实与关系，专业方法明确有哪些表达方式；造型、颜色、字体、材质与空间等开放选择依可见结果设计。候选检索分别看关联距离和实际贡献。熟悉参考与非惯常参考均有进入组合的机会，不虚构百分比，不按数量凑卡。

组合设计写清：从来源取什么 → 用在什么对象/段落 → 必要条件 → 与其他特征怎样连接 → 怎样适配 → 成片哪里可见。只有作用于同一属性/对象/时段且无法协同的要求才构成真实冲突；不同维度互相补充时直接组合。原卡的局部条件、示例与全片约束分开。

### 3.4 设计画面增加的信息与情绪/注意路径

先确定口播之外画面需要补足的名称、条件、比较、实例、过程、证据或结果，再选图形/文字/素材与排版。重要文字可以成为主视觉，不默认细线小字；图形与文字的关系、首次可读、有效停留和退出要明确。

以实际内容与受众关切设计兴趣和情绪变化，不强造反转，也不把“不强造”理解为默认平淡。视觉焦点通过尺度、色彩/明暗、位置、分组、运动和声音协同产生，不由“唯一强调色”自动保证。

### 3.5 形成可想象、可交接的完整 Brief

全片身份与逐段变化都写清，沿现有 `<role>`、`<inputs>`、`<confirmations>`、`<direction>`、`<structure>`、`<build>`、`<gotchas>`、`<start>`。正文使用“专业术语 + 具体对象/形态/材料/色彩/排版 + 前后态 + 路径/速度阶段/落定 + 上下段关系”，不是作者创作理由或 props 表。

普通新作只沿原生八块 Brief + `render(t)` 主线，不自动分流至 D3/directorDesign/production-plan 创作合同。先检查来源是否已经规定字号、网格、排版关系、圆角、线宽、字体/字重、颜色、材料或光影方法；能可靠承接的成熟规定直接沿用并适配本片内容。只有来源未规定固定方法或不能可靠提炼时，才由 Analysis 交接相对尺度、颜色角色、空间范围和动作性格，再由 Motion 求出所需参数。真实时码、画幅、锁定文字与成熟来源的精确曲线/相位继续保留；不把无关 props 字典搬进 Brief。

### 3.6 真实方向帧、动态小样与用户确认

用同一批关键内容制作有实质差异的组合候选；先渲染能比较的关键帧，连续过程承重时同轮提供实际动态小样。构图/对象/空间/文字或运动有真实区别，不能只换背景色，也不先制作几个完整影片。

默认按既定门槛等用户确认；明确免除时只免除等待，不免除内部检查。已有未来图库样例不替代本片样片。用户从图库选择样式 ID，回读该项 Markdown 后仍按本片内容设计。

### 3.7 忠实实现并检查真实消费

Motion 依据最终 Brief 选择 HTML/Canvas/SVG/Three 等适合的手段；允许直接运行受许可的原算法，不默认 Remotion，也不强行全部转成 Canvas。成熟动作保留时序、轨迹、曲线、阶段与依赖，局部参数按本作适配。

统一 `render(t)`、真实素材 ready、唯一事件时钟与最终混音。每个声画变化和素材命中点明确，不能用挂载时钟、卡片 start 或机械 BPM 对齐替代实际语义。成品不支持设计时定位最早断点，必要时只回改受影响 Brief 单元。

### 3.8 完整审查与局部返回

设计缺失回 Analysis；素材缺失去实际获取；代码偏离修 consumer；若结果不悦耳，回到真实音源、选段、命中点与混音。审查从观众实际所得看外观、信息、注意、运动、连续性和声音，不只查禁止项与字段。方向确认、工作台、最终预览之间的作用分开，任何阶段的 PASS 不代替其他阶段。

## 5．20 项能力和所有其他有用部分的采用规则

20 项表达能力的逐项清单在 B09，全体都要分析其输入、任务和表现，不只挑方便的卡。字体处理、字幕分组、媒体加载、透明层、确定性时钟、参数默认值、局部修改和用户反馈差异分析同样在范围内。没有字体二进制就记录没有，不以字体加载代码冒充素材包。

## 8．验收：如何确认实际改变了生成

### 8.1 结构与获取

Atlas 当前 504 slug 全覆盖、无重复、原 JSON 可追；Motion Prompt 240 ID/10 包对应完整、选用代码具备 kit；Overlay 20 项全部有迁移决定；15 MP3 有实际文件、来源、去重和状态。译文有原文依据，无来源不足时编造参数。源卡/闭包哈希不变，仓库链接和语法通过。

### 8.2 路由与输入

完整新 Brief 实际读取动作必读层和正式风格目录，拟采用项读取完整详情；局部修复不强读全部；无口播不造 ASR；旧工程不进入新原生合同；生产读取不返回人类展示画廊。输入脚本必须实际输出新增字段，不能只在 JSON 中保存。

### 8.3 设计行为

用普通输入检查：是否把题材颜色当必要条件；是否给非惯常参考提出了可行迁移；组合候选是否仅换色；所取特征在具体设计中是否可见；文字是否补足理解；每个真实 cue 区间是否有明确状态；段内动作是否有阶段；中后段是否仍发展；资源不适配时是否真去检索或返回设计。

不要求一律选择童话/卡片/等距，不规定必须几张卡或几种效果。测试要看判断和成品，不预置唯一风格答案。当前五层蛋糕失败案例检查其已知断点，但不能作为所有未来创作的固定模板。

### 8.4 实现与声音

看真实帧和连续小样，检查曲线/路径/相位、hold/exit 接续、文字层级、材料实际表现、最终尺寸与默认 16:9。对原算法移植核同 t、重复/乱序取帧、跨包变量、字体 ready、离屏合成、透明层与视频 seek。声音看源命中点与视觉相位，真实试听并连续审混音，固定增益和卡 start 不能代替听感与同步。

### 8.5 最终质量与人类接收

静态目录/字段/哈希与可运行只报告相应结构状态；自主检查最多提供观察。真实媒介中的已知目标差距继续记 FAIL；没有实际影片/试听/接收者反馈的范围按 UNKNOWN/OBSERVE，不凭来源成熟就宣称作品成熟。质量目标保持用户要求，不为证明通过改成“只要不出错”。

同批制作的人类画廊明确标记原示例、移植、重建和确认状态；待审可以如实展示，不冒称成熟标准。每次作品的方向帧和连续效果仍分别检查。章节/双语字幕新增验收见R09—R12。

### R01．统一认识：资源分类说明职责，不限制画面创作

Motion Prompt 的 UI、网页、照片、艺术风格、图解都能成为动画画面的一部分，不因 pack 名称而降低选择优先级。此前“并非全是动效”的说明只保留为实现和数据类型的区分，不再作为动画选材的边界。

Atlas 同样进入统一风格/视觉资源目录。它有些条目能支撑整体视觉方向，有些提供材质、光学效果、遮罩、运动或合成的一部分；两类都可以参与风格融合。不能因为不是一整套风格就放到一个正常选型发现不了的旁支。只有实际内容、使用条件与本片没有贡献时，才不采用；不以来源类别排除。

原风格卡、Atlas 效果、Motion Prompt 项目、Overlay 表达能力以及素材的区别，只用于回答“它能控制什么、怎样实现、需要什么”，不作为好坏或创意资格标签。一个条目可以同时具有多种职责。

### R02．物理文件分工与统一发现入口

之前 B03 已提出风格/效果/动作/实现分开保存，但未把统一发现和默认读取层次规定得足够具体。本轮补齐如下布局：

```text
templates/styles/
  index.json                  # 已有75项正式风格正文与来源的索引，不改原卡
  catalog.json                # 正式派生：跨来源统一目录，由下方真源生成
  effects/
    index.json                # Atlas 504项的ID、角色、中文正文定位和适用条件
    atlas.md                  # 制作相关的中文条目；按ID有界读取，不整篇注入
  motion/
    index.json                # Motion Prompt全部240项与表达方法的详情定位
    vocabulary.md             # 共同动作原则与精确用语，短而完整
    motion-prompt.md          # 保留各项必要条件与完整规格；按ID读取
    presentation-patterns.json # 20项表达能力及可组合条件
  gallery/
    index.html                # 人类浏览入口
    gallery.mjs               # 浏览、筛选、播放与稳定ID选择；不进生产选择输入
    gallery.css               # 画廊界面
    serve-gallery.mjs         # 本地预览服务
```

资源正文仍各有唯一真源。`catalog.json` 是可重建的发现视图，不再复制全文，也不成为第二份可编辑风格描述。新增目录中的文件分别承担知识、方法、实现或展示，不能重复维护同一规则。这里没有新增三级 Skill，文件分开也不等于每次都读取全部文件。

统一入口由 `laohu-styles.py` 的 `resource-overview`、`resource-search`、`resource-get`、`resource-family` 和 `resource-fulltext` 承接全域导航、检索、单项/家族摘要、完整 L2 与许可允许的 L3。用户和普通 Agent 不必先知道资源来自哪一个仓库。

工具与实际工程入口须一起接通：统一目录中的ID能进入候选详情读取与回执，不局限于旧75项ID。`input-candidate`类接口要根据来源类型读取正确Markdown与必要条件；`scaffold`检查本片实际采用项的输入/设计是否齐备，不再要求为取得通行回执而硬凑一张旧风格卡。旧索引、原有项目回执和受保护来源继续按其版本兼容；新资源的正文、来源版本、配方与依赖变化只使相关交付/探针失效，不把整库每次全部重读。

统一目录的一条记录包含：稳定命名空间ID、中文名/检索别名、能控制的可见表现、可提供的画面部分、必要输入与条件、可组合维度、正文定位、实现/资产获取方式。原厂ID保留在映射中，多个来源描述同一能力时交叉关联，不仅按名称机械去重。

按造型、颜色/明暗、字体/排版、材料/光影、空间/镜头、运动/转场、图解/数据、UI/交互、图像/实拍/合成、字幕/导航等视觉问题建立多标签发现；标签可以扩展，不能成为封闭风格菜单。来源与包名仍可查询，但不是默认相关性排名的主依据。

### R03．逐层加载：哪些必读，哪些条件读取，哪些不进入普通生产输入

| 层次 | 读取内容 | 触发与停止条件 | 谁读取 |
|---|---|---|---|
| L0 全域发现，完整新方向必读 | 已有75项丰富中文目录；覆盖全部Atlas制作候选的视觉家族导航；Motion Prompt全部240项的中文名、可见含义/用途短说明；20项表达能力概览；共同动作语言方法 | 在锁定方向前覆盖所有视觉来源。只给名称不够；导航须说明表现、条件与不同选择。不得只输出motion/camera而隐藏其他包 | Analysis |
| L1 候选比较，按未决视觉问题读取 | Atlas具体条目和其他候选的视觉摘要、能贡献的属性、实际条件；有熟悉和非惯常方向的比较 | 某个主体/材料/构图/动作尚未有足够选择，或目录摘要不能判断时展开；不按预设数量停读 | Analysis |
| L2 拟采用内容，必须读完整生产正文 | 来源核心效果、造型/配色/材料/排版、动作前后态/阶段/曲线性格、可变部分与必要条件、组合位置 | 任何要写进Brief的具体特征须读取其足够完整的生产正文；不能只靠L0/L1记忆或标题拼装 | Analysis；Motion复核当前仍缺的部分 |
| L3 真实实现，选定后读取 | 实际element/kit、必要代码、字体/图像/媒体依赖、准确相位/单位、已有资产或真实获取方法 | 该项进入实际制作时读取。代码共享kit按包复用，不重复加载；不能拿资料存在当作实现就绪 | Motion及相应资产/声音执行者 |

这里修正 B06 的可能歧义：96个motion/camera项目在全域目录中完整可见，其共同原则进入必读语言；不要求每个完整新Brief都通读96套长篇timing和源码。240项全部有中文概览，UI、网页、照片、艺术风格和图解与其余项目同样可选；拟采用项再完整读取规格。这样保留足够候选空间，又不把每轮输入扩大成整库手册。

Atlas L0 必须覆盖转换后全部可生产条目，不是按题材检索到前几项就结束：按视觉家族汇总其可见表现、主要不同做法和制作条件，各家族连接到其完整成员目录；L1展开某一家族时能看见该家族全部条目的可比较摘要，不只返回最高频的一种。全库可展开、可指定ID、可按属性交叉查，但不要求每轮把504篇详情全部读入。

若已有导航不足以使某种外观成为真实可发现选项，先补导航，不要求模型凭常识猜库里还有什么。选择记录须能指出哪项未决问题已解决、哪项仍需展开；不能以“读完若干页/若干卡”为停读理由。候选都呈现同一种长相、模型过早用题材锁定风格或只选择高频模板时，沿不同属性和较远关联重新展开。

不为本轮方案编造输入token节约百分比。实施后报告L0/L1/L2/L3实际输出字符、页数、重复量及用时，并结合成片与返工观察取舍；摘要过短而漏掉视觉可能性应扩充，不以减少眼前字数牺牲后续质量。

### R04．Atlas 的生产整理标准：保留能改变作品的部分

不把历史百科正文直接翻译后全部塞入正式生产文档。504项逐项提取“可见效果—控制条件—可变范围—与其他表现的组合—本项目实现/获取途径”，并记录实际信息是否足以支持这些内容。

生产正文默认包含：

- 看得见的主要特征：轮廓、色彩/明暗、纹理、空间、时间变化等来源确有的信息；
- 产生效果的关键机制和必要输入，例如是否需要多帧、运动场、遮罩、分层、特定受光；
- 与近似效果的关键区别，以免把压缩拖影做成一般RGB分色，或把真实玻璃做成半透明灰板；
- 可以调整与必须保留的特征，以及整体使用或局部借用的范围；
- 在画面中可承担的职责、组合位置和已有实现/素材/模型获取方式；
- 会影响实际选择的限制，不默认套用站点演示的字体、色值、样例主体或构图。

年代、发明者、长篇历史和大段引用链放入维护证据，不在默认制作正文展开。必要来源ID/链接、许可状态由工具/台账保存；确实改变当前动作的条件才以简短条件返回，例如某张图片不能再分发、某种技术必须有多帧输入。用户要求复古年代准确性、艺术史讲解或特定原作复现时，相关历史才按任务读取。不得为了省输入删除实际必要的来源核验或许可处理。

“质量筛选”在这里不评价风格好坏，而是核对条目是否准确、有足够效果特征、适用边界清楚、能帮助一项具体视觉决定。信息不足项保留来源待核状态，不用模型补造一套参数后标成熟。只含历史而无法支持当前视觉选择的部分留维护层，不进默认候选正文。

所有504个ID保留完整处置记录；进入正式视觉目录的条目能从统一入口找到。没有完整动画配方的效果仍可作为造型、材料、图像、合成或局部运动候选，不因类型而丢弃；正文不得冒称其已有可运行代码。

### R05．图片编辑 prompt 的客观取舍

Atlas的图片编辑prompt不是直接控制Canvas的指令，但并非对动画没有价值。动画可能需要背景、纸张/版画纹理、人物/图像素材、实拍风格处理、2.5D分层或三维贴图，此时关于光线、材料、颜色和边缘的描述可以成为图像制作输入。

采用条件：

1. 当前镜头确实需要图像生成/编辑或图像资产处理；
2. prompt中的可见描述对该素材有实际贡献；
3. 当前环境有明确可用的图像实现方法，并按授权取得真实结果。

三项不成立时，不把整段prompt放进Brief或普通生产输入。成立时先从正文确认效果，再读取对应prompt，把可迁移的视觉描述交给Image/Assets等实际方法；LetzAI专有入口、与当前素材无关的编辑口令和“保留原构图”等来源默认条件不能自动扩大全片。

原始prompt可保留在研究快照；正式库中的视觉效果文字以独立可理解的中文描述承接其有效信息，不依赖原prompt存在。不要为了“都收进来”把504段prompt每次一起读入，也不要因为不是代码就把有用的图像语言全部删除。

### R06．保真转换与实际效果核对

来源拆解后不降低其质量，需要保护的是足以让效果成立的构成与关系。记录原可见特征、必要输入、动作阶段/路径/节奏、可编辑内容和不宜改变的机制；具体源码有成熟实现时保留原算法和参数依据。

先做文本保真：逐项对照来源，确认没有删掉关键条件、把可选示例写成全局禁令、混淆近似概念、或新增来源没有的美术规定。然后对实际采用项制作真实结果，与来源声明/可用原示例核对。对图像看实际图像，对运动看连续过程，不能只核名称与曲线字段。

全量知识整理的覆盖检查与实际采用项的效果验收分开。没有必要先实现504个效果才能使用这套库，但不能把尚未实现/未核对的条目标成已验证成品。文字中的效果未出现，先检查实现；来源必要条件在设计时已被删除，返回设计。不得为迁就低质量样例重写原风格卡。

### R07．吸引观看的理由不止反差

反差是候选手段，不是每镜任务。设计时从实际内容和观看目的选择吸引理由，并落实为可见/可听变化：

| 可选择的作用 | 设计时要解决什么 | 对应的画面/声音决定 |
|---|---|---|
| 理解获得与清晰感 | 观众原来不清楚的关系怎样变得可见 | 分解、比较、演示、因果承接与信息补充 |
| 好奇与期待 | 观众知道在等待什么，信息何时揭示 | 有线索的遮蔽、局部展示、阶段与节奏 |
| 新颖与发现 | 哪里超出惯常经验，又靠什么读得懂 | 跨来源组合、非惯常材料/运动与熟悉参照 |
| 对比与惊讶 | 前后差别是否真的改变理解或感受 | 尺度/密度/方向/明暗/动作强弱变化 |
| 关联与价值 | 与观众的任务、关切或行动有什么联系 | 具体机会/代价/条件/实例，突出而非只贴标签 |
| 节奏与感官体验 | 何处推进、停留、释放或回返 | 速度/路径/镜头发展、声部密度和停顿 |
| 完成与掌握 | 状态改变后观众是否看到实际结果 | 落定反应、结果展开、阶段闭合与下一步 |
| 幽默、亲近、共鸣 | 内容是否提供可识别的情境、错位或立场 | 图像/角色/文字的具体组织与时机，不凭空贴表情包 |

这张表是本项目工作提示，不是完整心理学分类，也不要求每部作品集齐。Silvia的兴趣研究把新颖/复杂与能否理解联系起来，支持“新鲜但可跟上”的设计判断，不能用它证明一切反差都会吸引所有观众。[研究原文摘要](https://pubmed.ncbi.nlm.nih.gov/15755222/)

在Brief中只写本段实际选用的作用、依据和表现，不填写一串情绪词。纯审美作品可以主要以材料、运动和声画体验吸引；讲解作品还需检查是否真的增加理解。停留/安静可以成立，但必须有当前观看任务，不能用假漂浮填空。

### R08．人类风格画廊纳入同批实施计划

取消“等以后模型审美提升再列入制作”的安排。画廊作为 E11 已进入本轮实施；75 项正式描述可浏览，240 个 MIT 动画模块可播放，Atlas 家族和成员可发现但不伪装成完整动画预览。缺少的示例按真实待审状态呈现，不阻塞已能使用的部分。

画廊与AI使用同一资源ID和正式文本真源，但只有人通过HTML看渲染效果。AI在设计选型中读取Markdown与正式目录，不能读取衍生画廊HTML/样片来替代风格定义。这个边界不禁止Motion检查正在制作的实际作品，也不禁止按用户明确委托分析其指定对标。

制作动作：

1. 从统一目录派生画廊数据，展示原有风格与新增效果、动作、UI/图解等资源的中文分类和交叉筛选；不按类型把其他画面部分藏起来。
2. 当前已有合法可用的原示例或MIT纯时间绘制模块优先复用，减少模型重建审美造成的偏差；图片/外部作品按实际许可处理。
3. 每张展示标清“原来源示例/本地移植/模型重建”、静态或动态、已确认或待审，说明示例表现的是哪项特征。没有预览时显示真实待制作状态，不伪造已完成样片。
4. 原75张风格卡均可浏览正式描述；有代表性预览的直接接入，没有的按其正文制作。Atlas/240项也可通过统一目录发现，不能把504项均冒称完成动画样片。
5. 模式一用户选择稳定ID，返回该ID、模式和用户明确选择的特征，再回读Markdown；不把demo文案/默认配色一并当用户指令。
6. 模式二仍制作本片的组合方向帧/小样；模式三仍按明确对标拆解。图库不取代这两个过程。
7. 画廊清单只保存示例和确认状态；生产读取工具不返回展示DOM/CSS/截图。移除或损坏画廊不影响动画生产，画廊样片不足不反向改原卡。

画廊页完成是可浏览、可筛选、可正常播放并返回正确ID；“示例足以代表原风格”的范围需要用户或相称接收证据确认。待审示例可供人查看并标明状态，不能因确认未覆盖就把整个画廊无限期搁置。

### R09．知识讲解的默认章节导航与条件钉板

本轮用户允许章节条，并希望讲解类可默认采用。对有清晰多章节、观众可能需要定位/回看的知识讲解，默认设计顶部紧凑章节导航；用户关闭、单一短段没有实际章节、或已提供导航时分别关闭/不新增/复用。不是所有动画默认一条章节条。

章节由实际内容与转折分析，不强行切成固定数量或固定秒数。分析在Brief中确定章名、范围、边界、当前章强调和与主画面的关系；Motion从唯一时间线落到真实时码。导航可持续存在，但保持次要层级、不争夺正在讲解的主体；重要标题/图形需要顶部空间时设计范围和过渡，不能机械压小所有画面。

这与过去反对的“主画面旁始终占位的一整张总览地图”不同：顶部导航负责位置与回看，主画面仍可改变构图、景别、空间与信息。关键章节可以另外用鲜明标题或由总览进入局部，但不强迫每章照同一个模板。

还要区分两项真实能力：成片里绘制章节条只能帮助观众辨认位置；MP4像素本身不能变成可点击按钮。工作台/HTML播放器的章节点击须真正seek；最终交付保留一份由同一时间线派生的章节名称/时间索引，供用户填写平台章节或适用播放器读取。不能只画一个进度条就宣称已实现跳转。

章节索引以当前`timeline.js`事件为时间真源；ASR剪辑变化后重新生成。钉板则按本段是否需要持续比较、回顾或保留多个要点选用，不默认全篇常驻，也不因有章节条就自动叠加。章节条与字幕的位置/安全区要共同设计。

### R10．默认中文上行、英文下行：语义、时间、编译、渲染完整接续

**适用默认：**中文口播/讲解在需要制作字幕时，默认中文主行在上、英文译行在下，放在底部居中的合适安全区域；不贴死最外边缘。用户指定单语、其他语言组合、已烧录字幕或锁定样式时按其范围覆盖。不因默认双语强迫无口播/无字幕作品增加字幕。

**实际已查缺口：**当前`caption-manifest.mjs`为`caption-design/1`与`caption-manifest/1`，`compileCue`把`lines.join('')`与真实保留词核对，且每条cue只接受规定字段。把英文作为第二个`lines`字符串会触发原文不一致。必须新增翻译层，而不能删除中文保真校验或把翻译写进ASR原文。

#### 责任与数据

- Analysis决定语义分组、术语一致性与字幕在画面的职责；可取Writing的方法形成忠实而简洁的英文译文，不另写一份动画设计。
- ASRcut编译保留实例、词锚、中文显示文本和共同显示窗口，验证翻译绑定并导出；不把英文当作真实说出的语言或生成伪英文词时码。
- Motion使用同一manifest把中文/英文作为一组绘制，求解实际字体、字号、行距、底部安全区、字色/描边/承载层和与主体/章节的避让。

建议升级为可兼容的`caption-design/2`、`caption-manifest/2`：沿用中文原有`lines`与真实锚点，新增`translations[]`。每项明确目标语言、译文行、源cue/源中文内容绑定、翻译来源/修订状态；字段最终按实际schema实现，不以自由字典混入旧版。

显示起止仍只有一套：英文依附对应中文cue的displayWindow；整组同步进入、停留与退出。不根据英文长度均摊出新的ASR时间，也不把英文复制进中文tokenIds。译文/分组改变只影响字幕manifest和相关画面，不改变剪辑planSha256或原声。

保留`/1`读取、中文原文校验、旧哈希和旧SRT行为；新编译显式识别`/2`，不能静默把旧cue猜成双语。翻译绑定的中文或timeline变化时使对应派生字幕失效并重编，不能沿用过期英文。

#### 排版与过长处理

默认视觉为一行中文加一行英文；中文主要、英文次要，但两行在目标尺寸均可辨。按最终字体和实际画幅测量，不用固定汉字个数或源码里的固定脸位作为通用排版标准。字幕区域与主画面同时预留，不能在所有镜头上临时盖一块大底板。

长句优先在虚拟剪辑的显示编排中按语义分条；有真实词锚才能细分到对应时刻。只有句段级时间时保留其精度，不凭语速把一句分配成伪精确cue。英文先做保真且自然的精简表达，保留否定、条件、数字、单位与专名；不能为塞进一行而删掉改变含义的内容。

仍放不下或读不完时，调整分组/阅读窗口和构图；必要的换行/呈现例外应在设计中明确，不默默缩成不可读小字、关掉英文或拉长冻结音频。若需要改变影片时间，返回ASRcut授权范围重新编译，Motion不能自建时钟。

交换用SRT在同一cue内按中文、英文两行输出。SRT不承载全部字号/字重/颜色意图，正式渲染优先消费manifest；既有播放器/编辑器也需支持translations与显示顺序。只输出双语SRT但成片仍只绘中文，不算完成。

### R11．React、HTML、Canvas、SVG、Three.js 怎样互相接上

React是组织组件/状态和更新界面的方式，画面仍由DOM/CSS、SVG或Canvas等绘制；不等于另一个视频文件格式。已读Overlay的FocusCard含SVG，Terminal3D主要用CSS perspective与translate3d/rotate，并非因为名叫3D就使用Three.js。具体处理必须查实际实现。

| 要保留的实际表现 | 原生可选实现 | 适配关键点 |
|---|---|---|
| 文本分组、卡片、双语字幕、UI排版 | HTML/DOM+CSS，必要时SVG或Canvas文字 | 真实字体与测量、布局、遮挡；每个时刻直接设置状态，不依赖挂载动画 |
| 轮廓、标注、线条描绘、图表、遮罩 | SVG，或Canvas路径与裁切 | 路径/描边/遮罩和变换层级保真，实际语义和单位正确 |
| 粒子、逐像素处理、笔刷和已有Motion Prompt元素 | Canvas 2D，按需要离屏画布 | 源kit、作用域、缩放/分辨率、混合模式、随机种子 |
| 平面窗口的倾斜、翻面与透视 | CSS 3D或相应Canvas/SVG投影 | 不为了技术名头改成完整3D；保留观察方式和遮挡 |
| 真正空间模型、相机穿越、几何遮挡与受光材质 | Three.js/WebGL等已核实实现 | 摄影机、材质、光影、纹理、资源ready和统一t；Canvas灰色平板不能冒充真实玻璃 |
| 图片、实拍、录屏与透明动效层 | HTML video/image、Canvas合成或已核实媒体层 | 真实素材、seek完成、alpha与裁切、颜色与时钟一致 |

保持本项目原生HTML页面和`render(t)`契约，不为融入某张卡安装整套Overlay工作台。许可允许的原算法能直接运行就保留；需要改绘制方式时提取实际可见状态/阶段与依赖，再在对应工具中实现、对照动态，不是给TSX换后缀。

工具选择先以已定设计的可见效果、文字/材料质量、空间与运动要求为依据；能实际达到这些要求的候选之间，再比较渲染、依赖和维护成本。不能因Canvas依赖少就把需要真实折射/遮挡的三维设计降成灰板，也不因Three.js可用就给普通文字增加没有贡献的空间工程。若轻量实现未达到设计，改工具或实现，不暗改Brief来迎合省力路线。

统一局部时间从影片t及共享事件计算。React hooks、rAF、performance.now与CSS自动播放不原样带入离线取帧；可直接把状态写成t的函数，或使用可暂停并精确seek的Web Animations API，仍需在本项目浏览器中实测。[MDN：Animation.currentTime](https://developer.mozilla.org/en-US/docs/Web/API/Animation/currentTime)说明该属性可设置运行或暂停动画的当前毫秒时间；接口可用不替代项目确定性验证。

底层模块按实际能力完善：文本布局/测量、路径与遮罩、计数与形变、空间/相机、媒体取帧与合成、时间映射、字体ready及音画事件。已有模块满足就复用；只在缺少真实职责时新增。每项说明输入、返回可见状态、时间/单位、可调变量、资源依赖及验证方式。模块是可组合能力，不是替整片决定长相的默认模板。

Overlay源码许可分支仍按B12，不因“转成Canvas”而消失。公共可分发实现优先采用已有成熟代码和Motion Prompt MIT源；对必须使用受限源码的部分按真实许可条件单列，不把一般功能学习说成原源码满血移植。

# 方案 A：风格选择、融合设计、Brief 与验证改造

保存日期：2026-11-17。

本文保存上一轮已交付方案的完整正文，供本轮方案 B 和最终融合方案对照。正文内容不作删减；原回复中的仓库文件链接仅转换为从本文可解析的相对链接。本文为待执行方案，不表示生产文件已经修改。

---

**这次需要改造的核心，是动画设计的“选择与生成方法”：让模型从风格库中取得真实的视觉语言，发展出不同的组合，再通过画面比较完成选择，最后把选中的设计完整交给 Motion。**

现在的问题不只是“规则不够严格”。有些规则已经存在，却没有被执行；另一些地方只有原则，没有教模型怎样作出设计。继续增加“大胆、丰富、酷炫、认真阅读”等要求，解决不了这两类问题。

下面是针对当前项目的详细方案。**本轮只交方案，没有修改文件。**

**一、先明确：这次到底改变什么**

这次优化应让普通的“根据这段素材制作动画”请求，也能自然发生以下行为：

1. 口播和材料限定事实、关系、顺序及必要形态，不再自动决定全部配色、材质和情绪。
2. 风格库同时参与造型、色彩、字体、空间、运动和质感设计，不能只剩下“工艺与限制”。
3. 陌生的参考能够进入组合尝试，不会因为题材不像就提前被排除。
4. 候选之间存在真实的画面差异，而不是同一种构图换几个颜色。
5. Brief 写清楚观众实际会看到的对象、信息、动作和衔接，同时把工程参数留给 Motion。
6. 实现与审查都核对这些视觉决定是否真正出现，而不只是检查文件、字号字段和事件是否存在。

原版 Showreel、受保护风格卡、已有素材和成熟实现继续保留。这次主要调整它们的**读取、选择、融合、设计交接及验证方式**，不再另起一套动画框架。

**二、当前最早的断点在哪里**

结合最新 Brief 和现有文件，可以把问题分成四类。

| 已定位的问题 | 当前材料中的表现 | 应怎样处理 |
|---|---|---|
| 过早锁定表现形式 | Brief 写“拆开”“从下往上”只有实体才能成立，随后排除其他方向 | 修改设计方法，先区分内容关系与表现形式 |
| 风格选择偏向机制，外观比较不足 | 四个来源主要贡献拆解、引线、暗场、排版禁令；配色和材质又由题材联想产生 | 补足视觉属性的读取、比较与组合方法 |
| 已有正确要求没有落实 | 当前规则允许补充屏显信息、限制局部禁令；本次仍只保留命名与关系，并扩大全片限制 | 把检查接到真实 Brief 和画面，不重复添加同义原则 |
| 新旧交接要求混杂 | 新流程要求自然语言设计；字体 Reference 仍含旧 D3 的精确参数和 consumer 要求 | 明确原生与旧工程分支，消除输入冲突 |

其中有三处具体原句尤其值得作为后续回归对象：

- “这两个动作只有在一个可以被拆开的实体上才成立。”
- “层与层之间只有材质与名字不同，不换画风。”
- “画面文字只承担命名与关系。”

它们分别压缩了**表现形式、视觉变化和信息补充**的空间。问题不在于这些选择永远不能采用，而在于它们在这部作品里被过早确立为必要条件，后续设计只是在维护它们。

因此，这次不能只修最后的颜色。要从这些判断怎样产生开始改。

**三、把内容分析拆成“必须保留”与“可以设计”，阻止题材直接决定长相**

Analysis 读取输入后，先完成一张简短的设计边界表，写进同一份 Brief 的 `<inputs>` 或 `<direction>`。

| 判断对象 | 需要确定什么 |
|---|---|
| 内容事实 | 名称、数量、顺序、真实对象和关系 |
| 必须让观众看懂的变化 | 谁进入、谁分开、谁影响谁、前后有什么不同 |
| 用户锁定的外观 | 指定风格、品牌、真实产品、必须复现的素材 |
| 开放的视觉选择 | 色彩、材料、对象形式、构图、文字性格、镜头表现 |
| 可能引起误解的视觉编码 | 大小是否暗示数量，距离是否暗示强弱，连线是否暗示因果 |

这样处理之后，“五层”需要保留，五层的顺序需要保留；但是否采用五块工业厚板，不能从这两项事实直接推出。

同样，“能源”可以约束名称和解释内容，却不能自动推出“必须石墨色”；“芯片”可以使用真实芯片作为证据，也可以使用风格化图形作为解释。只有真实产品复现、品牌约束、数据编码等条件成立时，外观才受到对应限制。

建议在动画设计 Reference 中加入下面这段正式规则：

> 内容分析先确定事实、关系、状态变化和必要识别线索，再确定开放的视觉变量。题材联想可以提供候选，但不能单独决定配色、材质、字体或表现媒介。采用某种外观时，须说明它怎样支持本片的辨识、构图、情绪或观看体验；不能用“题材属于科技、商业或知识”替代视觉设计判断。

它解决的是最早的错误：**模型还没有比较视觉方案，就已经把方案的大部分决定掉了。**

**四、扩充风格目录的可比较信息，而不是重新把全文塞进上下文**

当前渐进式加载应保留：

> 全部正式中文目录 → 比较候选 → 读取候选完整中文正文 → 必要时扩读。

需要改的是目录承载的信息。

目前目录有“视觉、动作、镜头／空间／变化、表达与情绪、适用条件、局限、融合关系”七项。它们有价值，但“视觉”压缩得过多，难以系统比较字体、配色和构图。

建议保留七项主体，在“视觉”内增加可选的结构化属性：

| 属性 | 应从来源记录什么 |
|---|---|
| 造型 | 轮廓、几何或有机形态、厚薄、边缘、对象组织方式 |
| 色彩 | 色相倾向、明暗与饱和度关系、背景与主体关系、颜色承担的职责 |
| 字体 | 字形性格、粗细倾向、标题与说明的关系、排版表现 |
| 材质与光影 | 表面特征、透明或不透明、受光与阴影、必要的表现条件 |
| 构图与空间 | 平面或立体、前后关系、留白、观察方式、主体与文字的组织 |
| 信息组织 | 擅长怎样分组、展开、比较、标注或组织多层信息 |

执行要求需要明确：

- 每项提取都指向真实正文依据。
- 来源没规定的内容留空，不能根据风格名补造。
- 来源中的示例色值与其背后的配色关系分开。
- 目录展示短摘要，维护证据留在索引；普通阅读不反复输出整套引文与哈希。
- 原版卡正文不改，中文视图不因这次方案被重新解释成另一种风格。

尤其要调整“适用”和“局限”的读法：

**它们描述来源在什么条件下成立，不能直接变成题材准入名单。**

例如，“完整采用这种排版不适合密集教学”，不等于其中的字形处理、构图关系或转场方法都不能进入教学动画。

“融合关系”也应解释为已知组合方向，不能成为只允许这些组合的白名单。

这属于对现有索引的增强，不需要再建立一套平行风格库。

**五、把“寻找最合适的风格”改成“寻找具有不同贡献的参考”**

这一阶段采用两条独立判断：

- **关联距离：**与当前题材或常见表达有多接近。
- **设计贡献：**其中什么特征能改善当前画面。

不填写没有统计依据的“90%适合、30%适合”，也不把关联距离当质量分。

具体操作如下：

1. 从完整目录中找到能够直接解决表达任务的参考，作为可行的比较基础。
2. 再寻找在造型、材料、配色、排版、空间或运动上提供不同可能性的参考。
3. 对陌生候选，先提出可以怎样迁移其中的具体特征，再判断组合能否成立。
4. 只有真实事实、用户锁定、许可、必要技术条件或明确的表达冲突，才构成直接排除理由。
5. 出现“太童趣、太艺术、不像科技、不够商务”等判断时，必须继续说明它具体损害了什么；不能仅凭风格印象结束比较。

这一步有研究支持。设计类比研究发现，较少见和跨领域的参考可能促进新颖性；但较远的参考并不始终更好。因此，应扩大探索，再比较形成的方案，而不是把“最接近”或“最陌生”直接设为赢家。[类比设计研究](https://joelchan.github.io/files/2011-jmd-distancecommonness.pdf)、[参考距离与创意表现研究](https://joelchan.github.io/files/2014-desstudies-nearfar-in-press.pdf)

**停止条件也要写清楚：**

当主要视觉决定仍只有一个未经比较的答案，或所有候选实际上提供相同的外观与运动时，继续探索。
当关键选择已有明确依据，新增参考只重复已有贡献时，可以收束。

这样控制阅读成本，靠的是解决了哪些未决问题，而不是机械地读够几张卡。

**六、让“融合”成为实际操作，而不是在 Brief 里列出来源名称**

每个进入组合的特征，需要回答以下问题：

| 需要明确的内容 | 用途 |
|---|---|
| 从哪里取得什么 | 防止只借用了风格名称 |
| 用在什么对象或段落 | 防止局部做法扩大全片 |
| 必须保留什么条件 | 防止提取后失去原有效果 |
| 怎样与其他特征连接 | 让组合形成一个整体 |
| 哪些地方经过适配 | 区分来源已有方法与本片设计 |
| 最后能在哪里看见 | 让后续实现和审查有对象可查 |

这里可以采用“形态分析”的基本方法：把对象形式、色彩、材料、空间、运动等维度分别展开，再研究它们怎样组合。[形态分析原始方法说明](https://swemorph.com/ma.html)

但不必创建庞大的排列组合矩阵，也不需要穷举所有组合。只展开当前关键设计决定。

发生冲突时，按下面的顺序处理：

1. 看是否作用于同一个属性。卡片形态与童话配色通常不争夺同一属性。
2. 看是否作用于同一对象、同一时段。不同段落可以发展不同表现。
3. 看能否通过层级、范围或过渡解决。
4. 仍不能并存时，比较哪一种处理更支持已确认的作品目标。

不能把多张卡的限制直接取交集。否则几张来源叠加之后，只剩下“不能这样、不能那样”，外观和运动反而越来越贫乏。

同时，应区分：

- 完整采用一个风格时，要保留它的核心定义。
- 借用其中一个局部特征时，保留该特征成立所需的条件。
- 改变核心定义后形成的新组合，应明确是本片融合设计，不继续声称完整复现原风格。

**七、候选竞争比较“实际组合”，不比较风格标签**

默认融合模式下，方向确认前应形成有实质差异的组合候选。

差异可以发生在主体造型、材料表现、空间组织、文字角色、镜头或运动上。不能只是同一堆叠结构换三套背景色。

每个候选只需先完成：

- 简洁但可想象的整体视觉描述；
- 最能代表它的关键构图；
- 一项承重变化的动作设计；
- 这套组合带来的主要收益与尚未解决的问题。

随后由 Motion 用实际代码制作方向帧；表达依赖运动时，补真实动态小样。不先把几个完整影片都做完。

比较时采用同一批内容和文字任务，避免一个候选精心制作，另一个只是敷衍草稿。主要看：

- 信息是否清楚；
- 外观是否鲜明、完整；
- 视觉焦点是否明确；
- 新鲜感是否来自有效组合；
- 动作是否有过程和承接；
- 是否存在明显的制作缺口。

**制作成本单独记录。**不能因为某种方式省事，就把它写成“更符合审美”；也不能因为一种方向陌生，就推定它一定更高级。

这套候选方法是本项目根据研究与目标形成的工作设计，不是论文提供的现成动画标准，后续需要实际运行验证。

**八、Brief 要同时交付“全片视觉语言”和“逐段可见设计”**

保持现有八个 XML 块，不另造第二份设计文档。

其中 `<direction>` 解决全片的视觉身份，`<structure>` 解决真实时间里画面怎样发生。两者互相承接，不能用全局一句“统一风格”代替局部设计。

全片部分应明确：

| 内容 | 需要达到的描述程度 |
|---|---|
| 主体形式 | 能想象对象的轮廓、厚薄、摆放与组成方式 |
| 色彩关系 | 说明背景、主体、类别与强调分别怎样区分 |
| 材质与光影 | 说明实际看得到的表面、受光与空间感 |
| 字体与排版 | 字形性格、主次、相对尺度、位置与阅读顺序 |
| 运动性格 | 动作的轻重、速度对照、路径与收势 |
| 镜头发展 | 哪些阶段保持观察，哪些阶段改变尺度、位置或空间 |
| 信息与情绪发展 | 哪些内容需要展开，何处形成强调、期待、反差或确认 |

局部覆盖表建议采用以下栏目，仍放在 `<structure>`：

| 栏目 | 必须承担的内容 |
|---|---|
| 时间与材料锚点 | 真实字幕、词时码、素材状态或无声观看时段 |
| 本段新增的信息 | 观众此处实际多看懂什么 |
| 可见画面设计 | 对象形态、色彩、材料、文字与构图 |
| 连续变化 | 前态、触发、路径、速度阶段、接触或揭示、后态 |
| 注意力与声音 | 先看哪里、怎样交接、声音对应什么相位 |
| 前后承接 | 继承哪些对象与状态，怎样进入下一段 |

表格负责定位，复杂动作在对应单元下用完整自然语言展开。

有字幕时，每条实际显示区间都应能找到画面设计；连续镜头可以覆盖多条字幕。既不一句话强行切一镜，也不能用一句粗述概括几十秒。

**设计精度与实现精度要分开。**

- Analysis 决定字形性格、颜色关系、相对大小、位置范围和动作表现。
- Motion 确定字体文件、实际字号、色值、坐标、曲线和代码。
- 真实时间、画幅、锁定文案、品牌参数等应当精确的内容，继续精确。

“约占画面左侧三分之一”需要说清是文字组的宽度还是整个区域；“天青色主体配浅暖背景”需要交代主次与对比。这样的描述有明确边界，同时给实现留下合理余地。

Brief 的验收不是字数，而是：**接手者是否还需要重新决定这段画面的主要长相和动作。**如果需要，说明设计尚未完成。

**九、在排版之前，先设计画面要补充什么信息**

当前 Writing Reference 已允许补充解释信息，应保留并接入必需的设计步骤。

对每个承重段落，Analysis 先判断：

- 口播已经提供什么；
- 观众还缺什么才能理解；
- 图形可以表达什么；
- 什么需要文字、图片、实拍、录屏或其他素材补充；
- 补充内容来自原材料、已核实来源，还是明确示意。

然后再决定排版。

这样，文字不再默认只是对象名，图形也不再只是名词的容器。它们可以共同呈现具体比较、过程、条件、参与位置、案例或结果。

信息量应来自**新增的理解内容**，而不是多加小字。重要信息要有足够的画面空间与阅读时间；辅助内容依附当前理解任务，不同时争抢焦点。

视觉层级可以通过尺度、明暗、色彩、位置和间距共同形成，不要求全片只能有一个彩色元素。[视觉设计原则](https://www.nngroup.com/articles/principles-visual-design/)

因此，需要把“唯一信号色”从一种可能采用的来源做法，与“必须让主要焦点清楚”这一目标分开。

**十、动作设计要描述行为，不能只列缓动名称**

“移动到右侧，使用缓入缓出”仍然不足以形成丰富动画。它只交代了一段插值。

承重动作应根据需要描述：

- 起动前怎样准备；
- 主体沿什么路径进入；
- 何时加速、减速或改变方向；
- 哪个接触、揭示或变化最重要；
- 主体停下后，附属部分怎样跟随；
- 这个结果怎样产生下一步。

这些处理对应成熟动画方法中的时机、预备动作、呈现重点、弧线、跟随和动作重叠等原则。[Lasseter：传统动画原则在三维动画中的应用](https://users.cs.northwestern.edu/~animation/Lasseter_1987.pdf)

这里不能再写成“每个动作必须回弹、必须走曲线”。持续流动可以匀速，强调可以干脆停止，柔软材料与机械结构也应有不同表现。

应要求的是：**动作选择具有明确作用，关键过程实际被设计出来。**

长片再增加一项检查：中后段是否继续发展观察位置、构图、对象关系和节奏。共同风格可以保持，固定目录图、固定机位和同一种出现方式不能因为“保持统一”自动贯穿。

**十一、声音保留现有成熟路径，补上与视觉选择共同设计的关系**

目前声音 Reference 已经规定成品优先、缺资源继续检索、真实试听、共享事件、源 hitpoint 和最终混音。这些方法应保留，不重新发明一套。

需要加强两处：

**第一，方向选择阶段就核对声音是否支持这种动作。**

确定材料与运动性格时，同步提出声音需要的起音、力度、距离和尾音。不要等画面全部做完，再从本地挑一个“差不多”的声音。

**第二，素材不适合时，触发真实处理。**

按现有路径检索本地、搜索外部成品、下载核验、试听和必要剪辑。若仍不适合，返回当前设计问题，考虑调整动作或声音职责。不能以“库里有一个”为充分理由，也不能擅自转为合成音效。

配乐应按实际乐句、节拍位置、音色、密度和段落发展处理。跨曲需要时交叠淡变；一首音乐能够支持全片时也可以保留。BPM 和波形峰值是分析线索，不独自决定切点。

音量继续尊重你提出的人声优先关系，但把轨道增益、峰值与整体响度分开检查。最终以正常播放条件下的清晰度、突兀程度和连续听感判断，避免把几个固定 dB 数字当作全部验收。

**十二、把验证放在最早能发现问题的位置**

不能等最终 MP4 出来后，才发现设计方向已经错了。

| 检查位置 | 实际检查什么 | 发现问题返回哪里 |
|---|---|---|
| 候选读取之后 | 外观信息是否足够，是否只比较了近似机制 | 目录摘要或候选扩读 |
| 组合设计之后 | 来源特征是否真正结合，限制是否被错误扩大全片 | 融合设计 |
| Brief 交接之前 | 是否能重建画面，信息、文字与连续变化是否完整 | 对应设计单元 |
| 方向帧与动态小样 | 颜色、材质、字级、构图、动作是否实际成立 | 设计或实现，按最早断点处理 |
| 最终输出 | 正常速度、目标尺寸、连续声画是否达到设计 | 相关段落和直接依赖 |

静态脚本可以检查字段、来源、路径、哈希、时间和素材状态；**不能替代审美判断。**

动作量检测可以指出长时间无变化；不能要求用漂浮光点填满。对比与字号测量可以发现风险；不能证明观众一定看得舒服。所有质量结论都要回到实际画面和声音。

方向帧确认、持续工作台和最终预览继续沿当前规则执行；用户明确免除时，按本次范围跳过等待，内部验证仍保留。

**十四、实施顺序与完成条件**

后续获准实施时，按下面顺序推进：

1. **保护当前状态。**保存本轮涉及文件的实际内容及恢复位置，包括未提交修改；不以 Git HEAD 代替。
2. **先修设计方法与分工。**把选择、融合、Brief 和参数边界接通，合并重复说明。
3. **再增强目录。**逐条核对当前正式条目的正文依据；没有依据的属性留空，原文保持不变。
4. **同步读取工具。**验证目录分页、候选正文、证据定位、指纹失效和重读行为。
5. **修正新旧分支。**验证原生项目不会误进入 D3 参数合同，旧工程仍能继续使用原接口。
6. **更新相关审查和评测。**同时检查生成动作与结果，不只检查规则文字存在。
7. **用普通请求重新运行。**独立项目只提供原始素材与正常制作要求，不在提示词中泄露本次修复答案。
8. **根据最早失败位置修订。**读取不足修输入，组合贫乏修选型，Brief 清楚但没实现则修制作；不再把所有问题都归成“需要写更详细”。

验证至少覆盖：

- 当前五层蛋糕原始素材；
- 无口播动画；
- 用户锁定单一风格；
- 用户提供外部对标；
- 本地音源不适合、需要继续搜索；

## B07．Motion Prompt 原生接入：尽量运行原算法，不重造

源码的基本接口是 `cells[i](ctx, w, h, u)`：`u` 为秒，取值在该元素 cycle 内，画面是 u 的纯函数。它与本项目 `window.render(t)` 的时间函数方式接近，普通 Canvas 项通常不需要转成 React 或 Remotion。

具体移植步骤：

1. 选定 ID，取得当前版本的完整 element 和所需 kit；同时读取该 pack 尺寸、cycle、字体和局部图像依赖。
2. 每包独立模块/作用域。各 kit 有重复的 `C`、`CELLS`、尺寸等变量，不能把多个 pack 直接拼进同一全局。
3. 只把当前项目实际需要的代码与依赖提取到本地 runtime，保留 MIT 许可与原作者归属；不用整份上游网站当运行目录。
4. 用唯一影片时间 t 计算元素局部时间；不引入 Date、墙钟、挂载时钟或跨帧累积状态。
5. 普通一次性动作保留原入场/退场阶段，在 hold 区间调节停留；不把所有数字按句长拉伸。若场景短于必要动作时长，按来源 fitting 方法明确适配并看动态结果。
6. 原示例卡的画幅不是 16:9。保留本作规格，用上下文缩放与布局适配；不把 demo 卡宽高错当成最终画布，也不直接拉伸使字形变形。

8. 两个全屏转场不能因为各自可运行就同时叠加；检查整体焦点、前后状态和遮罩交接。Motion Prompt 的“每片一种 easing”等建议只作为其使用情境的方法，不升级为禁止本片必要反差的全局禁令。
9. `photo/artstyle` 的 Canvas 演示不能假装生成了对应真实照片、绘画或材质；需要实际图像时，调用已授权的生图/资产方式或合适素材，并按实际环境选择实现。
10. 依次测试进入、中间、hold、退出、边界、乱序取帧与同一 t 重复取帧；再看实际尺寸、字体和连续动态。对明确按原配方移植的部分，用同内容原源码作为行为基准，说明有意适配。

官方 `references/porting.md` 已明确上述 loop/hold/exit、作用域、尺寸和字体陷阱，应尽量保留其有效方法，而不是另写一套猜测性算法。

### React 到本项目原生方式的处理

不能把 TSX 文件改后缀就声称移植完成。先还原每项的可见状态、局部时间、路径、曲线、遮罩、字体布局、素材与事件；核对是否必须依赖 DOM/SVG/CSS 或仅用它们作为绘制方式。

本项目原生支持 HTML、Canvas、SVG 及按需 Three.js，不必把所有东西强行改成 Canvas。能由受许可的原算法直接接入时保持算法；需要变换绘制方式时，对照原实际动态检验，不用相似的函数名替代行为。预览/导出都由统一 t 驱动，局部速度只改变视觉函数的时间映射，不移动 ASR 的真实时间。

代码移植的公共发布路径受 B12 的实际许可约束；本节列出表达能力，不等于承诺把受限源码全部改名分发。可从 Motion Prompt MIT 代码和本项目成熟实现承接的通用能力先接通；只有来源独有、又必须用其代码的部分保留明确依赖，不把换写法当作消除许可的办法。

## B10．字体、排版与其他资产的融合

当前两个新仓库没有字体文件。后续整理应先查本项目已登记字族/字重、中文覆盖和许可，再补真正缺少的字体；不能说“已从 Overlay 获得一套字体”。

具体动作：

1. 保留现有字体资产真源和加载方式，建立字族、真实 face/weight、格式、中文覆盖、来源/许可和使用角色的可查记录。
2. 借鉴 Overlay 的真实字重注册目标，适配为本项目字体清单；不依赖其 Vite 构建器，也不只靠文件名猜字重。
3. Motion 等 `document.fonts.ready` / 实际 font load 完成后再设 READY；用最终字体测量，避免系统字体回退让样片与导出不同。
4. 标题、解释、标签、字幕、数字分别按角色设计，可组合但不强制一镜使用多字体；风格融合不以字体数量计。
5. 参数中的局部字号与坐标由 Motion 求解；Analysis 保留字形性格、主次、相对尺度和空间意图。
6. 对密集文字、中文长词、数字与单位、不同字重、缩放后手机阅读及动画过程进行检查。
7. 背景纹理、图像、图标、遮罩、调色与材料函数等也按同样方法：先查来源与实际贡献，再决定作为事实素材、风格语言还是执行模块接入；不把示例人物、品牌、伪数据或默认英文小标签当通用资产。

已有能力可满足时直接接通，不另建平行字体系统、调色系统或字幕主稿。
