# 剪辑知识怎样进入动画 Brief、Motion 和 ASRcut

**状态：提案，待老胡审阅；三个正式 Skill 已恢复到本次改动前的工作副本。**

这份方案解决一个制作问题：拿到陌生稿件，怎样把观众需要理解的关系、期待的结果或应当感到的变化，逐步落实为镜头、剪点、动作和可听的停顿。以下是拟议路径。已有 Reference 链接用于核对基线，固定版本上游链接供审方案时核对来源。日后如获实施授权，选用原文须筛入所属 Skill 的正式资产，以项目相对路径调用。

## 一、从现有能力接入

| 阶段 | 现有基础 | 拟补入的决定 | 直接交付与接手人 |
|---|---|---|---|
| Analysis | 已有观看任务、材料事实、资源分层读取、关键动作、字幕区间和八块 XML Brief | 在相邻观看单元间决定留、切、并置、省略；在节奏、证据、视线有冲突时明确优先项；让不同题材选不同起点 | 在唯一 Brief 的 direction 和 structure 中写承诺、证据、切出条件、下镜继承对象及声音关系，由 Motion 消费。见[动画设计](../../../.agents/skills/laohu-analysis/references/motion-design.md) |
| Motion | 已有风格全文、动效目录、原生配方、确定性 render(t)、共享事件和动态预览 | 先定镜头要解决的识别或注意问题，选择完整源效果、局部配方或原生方法；把时长、间隔、曲线和对象关系落实到实际绘制 | 从[动作语言](../../../.agents/skills/laohu-motion/references/motion-language.md)进入目录和本地工艺正文，产出同事件的代码帧、连续动态与需要的声音 |
| ASRcut | 已有源媒体身份、ASR 证据、留删重排授权、停顿三分法、剪后时间线和听审机制 | 判断不同 take 的独有信息，检查重排后前提、指代和操作状态；区分情绪停顿、操作等待和无效等待，逐个接头复核 | 决定进 edit-plan，由编译器生成唯一目标时间；Analysis/Motion 按真实锚点继续。见[粗剪与精剪](../../../.agents/skills/laohu-asrcut/references/editing.md) |

只调整视觉切点且原声继续播放，Motion 可以在原时钟上换画面。改变源语音的保留范围、次序或净时长，交 ASRcut 重编。已有录音时，此关系允许往返：Analysis 从原材料提出需要，ASRcut 给真实可用的时间，Analysis 完成观看单元；Motion 连看后若发现证据读不完，先试调整图层、揭示顺序和镜头窗口，仍不足才回传具体边界与净新增预算。纯视觉片由 Motion 使用本片事件；纯音频精剪直接走 ASRcut。

## 二、筛选、保真与查询

采用的资料应当能回答具体制作问题，能取得对应正文，并能随项目保存必要来源、许可与适用条件。先找决策及它拒绝的备选，再核对步骤、证据类型、参数单位、例外、依赖和作者所用工具。剪辑教师的手法、论文的研究结论、某一工具作者的工作偏好、可直接运行的本地配方，各有不同的使用依据。实施时在现有 Reference 中写本地操作方法；正式 assets 中拟保留所选归档文件的实际字节。交付清单须记录归档版本、成员路径、原始出处、逐文件许可条件和哈希。供查阅的外部指令文档和示例代码保留为阅读资料，其安装命令或外部服务不进入运行链。[归档范围与批次入口](https://github.com/adunext/human-video-knowledge/blob/332748002ec055dc2e6274835e3dd7d0ed1f3752/COLLECTION.json)

## 三、上次提炼具体丢了什么，实施前怎样补

完整原文仍在，只能证明原文可以取回。使用者首先接触的是中文入口；入口把“必须”改成“可以”，即使原文件就在旁边，普通制作也可能跳过关键动作。下面按上次草稿和固定版本原文逐项核对。它们是本轮已经发现的差异，并非全库已经逐条审过。

| 来源位置与原有判断 | 上次草稿传递的意思与影响 | 本地拟议处理与判断用例 |
|---|---|---|
| Cutting / Verifying a cut。原工具要求按**每个剪口**重新转写，用横跨拼接点的窗口查重复词或残句。怀疑双词时再查跨缝的约 2–3 秒；重叠窗口也可能误报。 | 草稿把逐缝转写降成了出现疑问时的可选手段。两者会产生不同验证覆盖，不能说完整继承原方法。 | 把「逐缝核听」「逐缝重转写」「疑点复查」分开。要复现原方法，需实体剪后音频、可用且获准的 ASR、逐缝窗口及回听原音。若只具备核听条件，本地能交付听审结果；转写覆盖单列未做。实施时比较真实双词、中文故意重叠和半句中断三个接缝。 |
| Cutting / Where cuts land 及 Pacing。作者把 ≥0.40 秒列为干净切点，0.15 到 0.40 秒区间要看动作，低于 0.15 秒列为不安全；表格在 0.40 边界有重叠。另有三种成片节奏，punchy 把间隙剪至 0.25–0.45 秒，balanced 只修约一秒以上间隙，restrained 只剪无功能空白。 | 草稿只点出几个数值，把**原始间隙筛选**与**剪后想留的间隙**都交给“按 profile 判断”。使用者可能把 0.40 秒既当剪点又当保留目标。 | 保留两张表各自的输入和单位，以及原作者的措辞、边界歧义和前置检查。本地如把 clean 降为待核候选，标明这是有意适配，原声里的思考、手势与系统声优先核实。以相同长度的无效等候和等系统反馈两段材料验证是否得到不同决定。 |
| Cutting / Take selection、The one deliberate pause、What to remove。先看同一意图的各次重录，偏好末次完整表达；头尾可来自不同 take；完整性优先于流畅。另要求开场论断后保留约半秒真实无口播画面承接声音转场，大量删减超过四分之一要交代删了什么及原因。配套 HARD-RULES 另有词边界、剪口 padding、切后批准和音频淡化设定。 | 草稿保住了大部分选 take 的理由，但将开场停顿压成“固定时长属工具设定”，没有把停顿与声音转场的依赖讲清，也没有说明大量删减的报告条件。 | 逐项列去向。原剪法适用于确有开场论断、真实可留画面及声音过渡的版本；锁定原音或纯音频时另判。大量删减条款属于编辑透明度，应列为采纳候选；从归档原文引入前说明本项目如何记录删除范围和理由。不能用一句“沿用本地规则”消掉未裁决部分。 |
| Editing and montage / Edit decision ladder、Rhythm and pacing。前者给出冲突时的启发式顺序；后者分静音画面、纯音轨、单看字幕、合看四遍，各自定位不同问题。 | 草稿传递了优先次序，但审片动作只列画面、声音、合看；字幕阅读任务可能被声音和画面同时掩盖。 | 有字幕且受众可能静音观看时，单查字幕是否承接对象、条件、数值及语义次序，再连看字幕是否与图表争夺同一阅读窗。无字幕片按适用范围略过。判断优先次序仍是该来源的启发式；涉及真实操作或事实因果时，单列本地保护条件。 |
| LottieFiles / Choreography 的 Shared Motion Events。多个对象回应同一个触发时，原文写的是启动落在彼此 50ms 内，可不同时间到达，采用同曲线家族并从触发点发出。相邻章节的 Stagger Patterns 则讨论按阅读、空间、波形等次序组织。 | 草稿的“同时启动、错开落定”保住大意，却丢了可检查的启动窗口、空间起点和曲线条件。制作时容易把共同反应和依次介绍当成同一手法。 | 以同一按钮触发几个反馈和逐项读列表作成对输入。前者按所选原方法核对启动时间差、空间起点和落定；后者按阅读顺序分配间隔。若为适配旁白而主动超出 50ms，注明改变的是哪一项以及理由，不把该数值推广到所有动画。 |
| LottieFiles / Multi-Element Patterns 的 List Items。同一行列出 8 项、单项 200ms、交错间隔 40–60ms 和总时长小于 400ms。 | 草稿给出核算公式，却没有把原表内的约束冲突直接呈给读者。 | 如果间隔指相邻启动、总长计到最后一项落定，则为 200＋7×(40–60)＝480–620ms；若总长只计到最后启动，则为 280–420ms。原文未在该行消除歧义。两种度量分别标明。具体成片优先哪个预算由任务决定，不擅改原数值，也不宣称全部同时满足。 |
| 动态数据可视化研究 / Tracking、Holistic judgments、Noticing。追踪一个集合约 3–4 个，与同时辨认个体身份约 1–2 个分属不同任务；整体均值和外轮廓也有不同的证据强度。作者分别讨论历史轨迹、突出对象、分阶段移动与交互重看。 | 草稿保住前两组数字，但建议整体变化时容易让人以为“整体判断”各项都有已知容量；固定视频与交互图可使用的补救也不同。 | 先问观众是认出某一条线、读整体趋势、看轮廓还是发现增删。逐项带上研究已知/未知、相应方法和复合任务时的干扰。例如多组轨迹并存会混淆来源；交互重看不能当固定播放视频已经提供的功能。验证用同一批点，仅换观看问题，看 Brief 是否随之改变。 |
| Manim 书签示例。示例同时演示等待标记、到下一标记前完成、给动作时长设上限，以及音节采用线性推算的限制。 | 只学到“用两个词绑定动作”，会把等到一个词才启动、两个词之间要完成、最多动多久当作同一件事。 | 将三类调用分别映射到本地已有的真实 time/occurrence/token。标明原例的音节推算只证明计算方式。本地若只有句级证据，改做受句段约束的动作或保留词级待核。 |

### 正式提炼拟保留的最小单位

以一项能改变选择的判断为单位，给它保留上下文。每项能回答：原文在解决什么；原作者让谁在何时做什么；前提与依赖是什么；比较了哪些方案；先做什么、冲突时谁优先；数字测量的对象、单位和边界是什么；例外、失败信号和停止点是什么；它属于作者偏好、工具限制、研究结果还是示范参数。检验成熟的原方法时，另附允许回读的原句短引、准确译义和精确章节。把本地决定单列为保留、明确适配、仅供查阅或暂缓，说明条件及理由。原文没有回答的部分保留未知。中文段落是否足够，取决于它能否使下一位执行者在相同材料上保留相同的选择和例外。

先按来源章节列覆盖表，再决定哪些做成日常触发、哪些只在选中方法后读取、哪些明确不采纳。每个采纳项要能从中文入口走到正式本地原件，也要能从原判据反查其本地去向。可以把同属一项判断的信息合在同段，不以字数或文件数规定信息密度。暂缺影片、只归档文字的案例，只有文字层结论可采用。

前轮选材偏向容易写成指令的工具文档。拟补筛 ACMI 的实际剪辑练习、第 0157/0158 批两份电影人访谈、第 0135 批 Micro-Edits，以及第 0139 批讲解中的理解错觉和场景转换研究。先核对原材料、实际选段和研究条件；只有确实提供独立判断才正式留用。目录出现论文或访谈标题，不能算已完成提炼。以上样例不能代替其余方法的逐段对照。

## 四、同一段材料怎样穿过三个环节

以下为方案走查。假设用户给的是两次录屏和口播，第一次完整说出“只有管理员能导入”，第二次流畅地演示拖入文件，原声在成功提示出现前留有等待。目标是让新手知道权限条件、能操作，并认得完成标志。

1. **从素材选择表达。** 粗剪时逐次核对讲解和对应的界面状态。第二次操作更清楚，但缺少权限条件。保持授权范围内的顺序，保住第一次的限定和第二次真实演示，试听拼接后的句法与语气。若两次操作来自不同账号或状态，分别交代；不能靠插镜伪装成一次真实操作。
2. **形成可以拍出来的 Brief。** 可写“先呈现导入区域与文件之间的位置。文件移近投放区时切到局部，保持同一文件和向右的运动。鼠标松开后维持局部景别，直到‘已导入’真实出现并能读清，再进入下一步”。把限定放到观众决定能否跟做之前。下一镜要读的是成功提示，因此关闭其他次要标注。原声锁定时视觉变化在既有时间内安排；缺少成功提示就回到素材选择。
3. **落实动作。** 用同一源片段在全景和裁切近景之间接续，确定性取帧，保持光标和文件的运动阶段。有意义的提示在目标出现后再标出；UI 演示采用真实结果。若文字、指针和字幕同时抢焦，先调次要标注时序。核看切点两侧及连续运动，跳到中间帧应仍能认出同一事件。
4. **处理停顿。** 实听原声并看等待期间的 UI。系统反馈、呼吸或等待结果的时间若已足够，直接保留。若画面能缩而讲述没有损失，按授权调整源范围；若确需额外看清结果，只把保留源停顿之外的净缺口交给同一 edit plan。编译后核对相关字幕、动作和声音是否仍引用本次出现实例与当前 revision。
5. **验收。** 静音看能否从画面跟住对象；只听真人口播核查条件、顺序和情绪；带声连看能否说出权限与完成标志。分别定位失误在哪个环节，避免用一个技术通过标记代替观看或核听。

|---|---|
| 初次交一篇无录音的知识稿，既有需跟踪的个体又有整体趋势 | Brief 为两类观看任务选择不同处理。只有语义依据时不生成精确词时码；不得因图表对象多就全部拆成单点入场 |
| 已锁视觉风格，口播里同一关键词出现两次，多个对象要在第二次出现时响应 | 锚点定位到指定出现实例；对象按职责同时开始或错开落定。检验事件起点、中段、落定与连续样片，核对次要项不占满阅读窗 |
| 同一说话者跨 take 重说，含否定、思考停顿和操作等待 | 留删记录能回到各次真实源范围；重排须有授权。对剪后实体接缝核听，确认语义、语气、编号及系统反馈，并区分保留停顿与新 presentation |
| 已锁定源音、只有转写或只做纯音频精剪 | 走该任务真正需要的分支。无可听原音标明未核听；纯音频不补画面观看时间；锁定的节目不因某个源表建议而改时钟 |

本表是待执行的验收设计。后续验证要用未参与编写的稿子和媒体，让正常入口实际产出 Brief、连续样片与剪后音频；首次观看者能否理解、感到转折或完成操作，应当单独记录。无需给每次日常制作增加一份研究报告。

## 六、收到实施授权后的职责和验收

本轮只交方案、恢复误写并保留获准的上游备份。以后由老胡明确指定执行时，Luna 负责组织实施与独立验收，Analysis 负责来源拆解和本地取舍，自进化 Skill 负责把已选方法写入实际入口，查找问题 Skill（laohu-audit）独立审查。比较方法或阅读补充材料属于方案阶段；保存方案、指出未来目录、下载上游三件事均不能推导出正式写回授权。

1. **先界定来源范围。** 从固定版本按问题、体裁和证据种类选材。交付来源目录、选/不选理由及未读范围。对每项候选，Analysis 给出逐段判断对照及本地实施拟文；核对许可证和正式分发依赖。运行时不依赖缓存。
2. **再做独立保真审查。** 审查者同时取得原文、上下文和拟文，标出遗漏、译义偏差、强度升降、阈值换义、适用域扩大或本地新判断未署明。用会令两种解释产生不同动作的输入检验。覆核人不凭原作者的自评关闭问题；发现缺口回到对应来源条目。
3. **正式接入。** 在批准范围内由自进化 Skill 写回原有入口或必要专项 Reference，Luna 组织执行。备份实际工作副本，核对每个消费者，保留许可和可恢复路径。已登记风格、动作配方、Brief XML、编译器和剪辑授权各有现有职责；如必须改变其中的接口或范围，单独说明原因与影响。
4. **再验证实际行为。** 让独立执行者用陌生稿件走普通入口，分别产出 Brief、连续样片和真实剪后接缝；选择会触发相反决定的成对材料。检查进入正确入口、读取了哪份正式正文、决定如何落入作品。移除缓存依赖的验收在隔离工作副本完成。受众理解、声音情绪和整体吸引力以成片播放与真实接收反馈评估。
5. **分别报告。** 路径/哈希是结构证据；真实请求走通才是路由证据；有实作才能评价行为；有接收者或相称媒介证据才能评价相应质量。每个已知遗漏单独记录，直到对应原文和测试输入复核通过。当前已确认的是上次草稿存在上表所列的信息损失，正式接入和成片质量均未验证。
