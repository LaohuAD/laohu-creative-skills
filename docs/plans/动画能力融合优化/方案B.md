## B04．HTML 只是给人看的展示层，Markdown 继续决定生产输入

采用以下单向关系：

```text
受保护来源 / 正式 Markdown 与资源索引
              ├─ Analysis 读取并形成 Brief → Motion 实现
              └─ 未来的人类展示画廊 HTML → 用户选择资源 ID
                                                    └─ 回到对应 Markdown
```

HTML 不成为生产真源。AI 不读取由模型制作的风格画廊 DOM、CSS、示例代码、截图或视频来重建/替代风格定义，也不把展示样片当作新的风格约束。用户从画廊选择 ID 后，Analysis 回读该项正式 Markdown。只有用户明确要求以其指定示例为对标时，才按模式三处理其可见要求，不能悄悄把模式一改为复刻画廊样片。

该边界针对“衍生的风格展示画廊作为设计参考”，不禁止 Motion 阅读本项目实际动画 HTML、调试当前工程，或使用有明确许可的官方独立代码模块。

模式一：用户可看风格示例选择单一风格，但示例只说明该风格的一种实现，不代替对当前内容的设计。

模式二：默认融合，仍在本片设计之后输出具有实质差异的方向帧/动态小样；不能用图库已有缩略图替代本片方向确认。

模式三：用户给定对标，按 Benchmark 拆解、核查和已授权收录规则接入；新的图库不取代其证据过程。

### 当前与后续阶段

- **当前阶段：**保留正式文字规格，不批量生成画廊。先完成 A 的设计选择与 B 的资料/实现接续。
- **后续启用条件：**同一正式条目已由实际代码表现，确认其关键辨识特征、运动、字体和材料成立；由用户确认展示可以代表该条目。未确认的样片只能标“待审展示”，不得伪装成成熟标准。
- **展示内容：**中文名称、稳定 ID、示例图/短片、此示例表现了什么、哪些部分仅是示例、来源与更新时间、返回正式条目的选择按钮。
- **技术隔离：**展示清单与生产索引分开；生产 API 不返回 gallery 路径，全文读取工具拒绝把展示 HTML 当卡片正文；画廊可移除而不影响生产。
- **失败处理：**样片与 Markdown 不符，隔离或撤下该展示，修样片；不为迁就不好看的样片改原卡。外观成立也不证明适配本片。

## B06．Motion Prompt：必读语言、按需规格、实际代码三层接续

源仓库实际有以下 10 包：`motion`、`camera`、`ui`、`lp`、`photo`、`motion2`、`lp2`、`camera2`、`artstyle`、`diagram`，每包 24 项。四个 motion/camera 包共 96 项，与动画运动和镜头设计直接相关；其余项目按网页、图片、图解等职责调用，不能统称 240 个动画。

### 每次完整 Brief 设计必读什么

1. 在产生动作方案之前，实际读取中文 `motion-language.md` 与 `vocabulary.md`：完整覆盖当前四个 motion/camera 包的 96 项中文名、英文检索名、具体行为、重要区别和可组合职责。不是只列 96 个名字。
2. 同次读取全部 240 项的分类概览和用途摘要，知道其余包有什么；不用在普通动画中强读 UI/网页的全部源码。
3. 本片拟采用的动作/镜头，必须读取其完整规格与必要上下文；不能从名称、短摘要或记忆重造效果。
4. Motion 实现时读取对应源代码与 pack kit，不能只读 Brief 里的术语。已在当前上下文且身份一致的内容可复用；阅读回执不证明理解。

这同时兑现“设计阶段必读动效语言”和 A 的渐进式加载：完整读取可比较的语言层，按实际选择深入规格和源码，不反复输出整个仓库。

### 术语怎样进入 Brief

Brief 的一个动作描述需要组合：**专业名称 + 具体对象 + 可见前后态 + 路径/阶段/速度性格 + 与当前内容和下段的关系**。词语帮助减少歧义，不替代画面描述。不写孤立的“Stagger + Morph + Zoom”，也不为了显得专业增加术语数量。

术语名、原始检索 ID 可出现在设计依据小表；主导演句仍须让未读源仓库的人想象画面。中文为主要描述语言，英文只在精确检索、对应原名或减少混淆时保留。

### 中文资料转换

名称、短含义与示例优先使用仓库 `packs/*/README.zh-Hans.md`；完整 timing/easing/phase 规格目前主要在英、日 API，需据代码核对后翻译，不把已有中文名称表说成全套中文规格已经齐备。别名建立检索映射，不改官方全局编号。

### 与 A 的关系

来源中的精确数字是成熟动作配方的证据，不能丢；它们留在详情/代码和 Motion 的实现映射中。Analysis 在 Brief 决定实际可见动作、节奏性格、幅度和时机；Motion 读取原规格保留曲线与阶段，需要适配时按已核实方法处理。不能因为 Brief 不写 RGB/PX，就把成熟实现参数一起删掉。

## B07．Motion Prompt 原生接入：尽量运行原算法，不重造

源码的基本接口是 `cells[i](ctx, w, h, u)`：`u` 为秒，取值在该元素 cycle 内，画面是 u 的纯函数。它与本项目 `window.render(t)` 的时间函数方式接近，普通 Canvas 项通常不需要转成 React 或 Remotion。

具体移植步骤：

1. 选定 ID，取得当前版本的完整 element 和所需 kit；同时读取该 pack 尺寸、cycle、字体和局部图像依赖。
2. 每包独立模块/作用域。各 kit 有重复的 `C`、`CELLS`、尺寸等变量，不能把多个 pack 直接拼进同一全局。
3. 只把当前项目实际需要的代码与依赖提取到本地 runtime，保留 MIT 许可与原作者归属；不用整份上游网站当运行目录。
4. 用唯一影片时间 t 计算元素局部时间；不引入 Date、墙钟、挂载时钟或跨帧累积状态。
5. 普通一次性动作保留原入场/退场阶段，在 hold 区间调节停留；不把所有数字按句长拉伸。若场景短于必要动作时长，按来源 fitting 方法明确适配并看动态结果。
6. 原示例卡的画幅不是 16:9。保留本作规格，用上下文缩放与布局适配；不把 demo 卡宽高错当成最终画布，也不直接拉伸使字形变形。
7. 示例背景、文字与配色换成本片已定内容时，区分可编辑内容与保持的运动机制；需要透明叠加时检查背景 fill、离屏合成、混合模式和裁切。
8. 两个全屏转场不能因为各自可运行就同时叠加；检查整体焦点、前后状态和遮罩交接。Motion Prompt 的“每片一种 easing”等建议只作为其使用情境的方法，不升级为禁止本片必要反差的全局禁令。
9. `photo/artstyle` 的 Canvas 演示不能假装生成了对应真实照片、绘画或材质；需要实际图像时，调用已授权的生图/资产方式或合适素材，并按实际环境选择实现。
10. 依次测试进入、中间、hold、退出、边界、乱序取帧与同一 t 重复取帧；再看实际尺寸、字体和连续动态。对明确按原配方移植的部分，用同内容原源码作为行为基准，说明有意适配。

官方 `references/porting.md` 已明确上述 loop/hold/exit、作用域、尺寸和字体陷阱，应尽量保留其有效方法，而不是另写一套猜测性算法。

特别需要阻止原流程中的限制反向覆盖 A：常驻章节条/钉板、段尾统一清空、固定暗色与三色、整期只许 20 张卡、每段只进不出、拿不准就加卡，都不作为本项目默认。它们不是为了批评来源，而是其手动编辑工作台与本项目融合创作的使用条件不同。

## B09．20 项表达能力逐项接续

“常驻”在本项目只指能力随时可调用，不指该图形必须全片占位。以下 20 项全部进入覆盖清单，每项在方法目录中说明输入、表现职责、可组合特征、必要素材、实现与许可状态；不能只录名字。

| 来源 kind | 可迁移的表达职责 | 本项目处理 |
|---|---|---|
| chapter-bar | 总览与当前位置 | 章节过渡、局部导航或短暂回顾；不默认全片常驻 |
| pin-board | 多项信息逐步保留与分组 | 按本片注意任务保留、展开或收束，不永久占角落 |
| caption-track | 真实时间字幕与重点标注 | ASRcut 的显示 cue 为真源；双语按需求，不擅改转写 |
| stat-proof | 数值、证据与出处共同出现 | 真实数值与单位、证据素材明确；示意不得伪装实测 |
| ring-metric | 比例/进度 | 输入必须具有分母、范围或明确进度意义 |
| odometer | 数字滚动与落定 | 保留数值意义；不把任何名词改成数字动画 |
| rank-bars | 排序与量级比较 | 核真实口径与类别，不用等长条暗示不同数量 |
| growth-curve | 随时间变化 | 真实数据或明确示意，不凭文稿词语补造曲线 |
| versus-card | 同维度对照 | 两方信息对等，按实际结论设计，不预设胜者 |
| quote-lockup | 引用/总结的层级与停留 | 主文字可占据主视觉；背景与支持内容协同 |
| punch-pill | 短判断/提示 | 配合局部强调，不作为固定药丸外观 |
| step-timeline | 步骤、进程与位置 | 保留真实顺序，与前后动画相连 |
| checklist | 完成状态逐项改变 | 勾选对应真实完成，不把普通列表全变成清单 |
| term-card | 术语与解释 | 原词、定义、对象关系同时明确，可扩展而非只贴名 |
| ui-callout | 真实界面/素材定位 | 对准实际对象，不发明 UI；坐标随实际画面计算 |
| blur-text | 由虚到实的文字显现 | 只作候选，不能重新成为所有文字默认入场 |
| type-shift | 文字组从一种组织变为另一种 | 重点研究阶段、位移、字重和阅读路径变化 |
| entity-chips | 人物/机构/产品的身份锚定 | 具体素材与身份正确；位置随画面，按任务退出 |
| focus-card | 实拍/录屏缩放与信息区域交接 | 可圆形/圆角/其他遮罩；构图服从内容，不套固定左右脸位 |
| terminal-3d | 代码/终端过程的空间展示 | 有实际内容或明确演示；不把所有知识片变成终端风 |

### React 到本项目原生方式的处理

不能把 TSX 文件改后缀就声称移植完成。先还原每项的可见状态、局部时间、路径、曲线、遮罩、字体布局、素材与事件；核对是否必须依赖 DOM/SVG/CSS 或仅用它们作为绘制方式。

本项目原生支持 HTML、Canvas、SVG 及按需 Three.js，不必把所有东西强行改成 Canvas。能由受许可的原算法直接接入时保持算法；需要变换绘制方式时，对照原实际动态检验，不用相似的函数名替代行为。预览/导出都由统一 t 驱动，局部速度只改变视觉函数的时间映射，不移动 ASR 的真实时间。

代码移植的公共发布路径受 B12 的实际许可约束；本节列出表达能力，不等于承诺把受限源码全部改名分发。可从 Motion Prompt MIT 代码和本项目成熟实现承接的通用能力先接通；只有来源独有、又必须用其代码的部分保留明确依赖，不把换写法当作消除许可的办法。

## B10．字体、排版与其他资产的融合

当前两个新仓库没有字体文件。后续整理应先查本项目已登记字族/字重、中文覆盖和许可，再补真正缺少的字体；不能说“已从 Overlay 获得一套字体”。

具体动作：

1. 保留现有字体资产真源和加载方式，建立字族、真实 face/weight、格式、中文覆盖、来源/许可和使用角色的可查记录。
2. 借鉴 Overlay 的真实字重注册目标，适配为本项目字体清单；不依赖其 Vite 构建器，也不只靠文件名猜字重。
3. Motion 等 `document.fonts.ready` / 实际 font load 完成后再设 READY；用最终字体测量，避免系统字体回退让样片与导出不同。
4. 标题、解释、标签、字幕、数字分别按角色设计，可组合但不强制一镜使用多字体；风格融合不以字体数量计。
5. 参数中的局部字号与坐标由 Motion 求解；Analysis 保留字形性格、主次、相对尺度和空间意图。
6. 对密集文字、中文长词、数字与单位、不同字重、缩放后手机阅读及动画过程进行检查。
7. 背景纹理、图像、图标、遮罩、调色与材料函数等也按同样方法：先查来源与实际贡献，再决定作为事实素材、风格语言还是执行模块接入；不把示例人物、品牌、伪数据或默认英文小标签当通用资产。

已有能力可满足时直接接通，不另建平行字体系统、调色系统或字幕主稿。
