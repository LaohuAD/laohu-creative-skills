# 三技能协作与追溯协议（Audit / Analysis / Evolution）

本协议仅用于仓库能力或复杂作品的**审查（`laohu-audit`）、定因与方案（`laohu-analysis`）、长期规则写回（`laohu-evolution`）**三者相接时。日常创作与单一业务任务不加载本文件。通用运行时权限与文件边界以 [docs/runtime.md](../runtime.md) 为准。

---

## 1. 单一职责与交接红线

| 入口 | 核心职责与交付 | 何时交接给下一步 | 红线（不越界做什么） |
|---|---|---|---|
| **laohu-audit**（找茬） | 锚定终端殿堂级成品标杆、先做三态前提判别与开篇总断，定位有证据的目标差距及其作用机制；确认存在差距时，按问题层级默认在报告内附同材料的最小对照（表皮给段落对照，前提/结构偏离给换血切口或骨架对照，提示词中继诚实标明待实渲验真）。 | 需跨环节追查系统根因、权衡未决架构/方法取舍，或涉及多文件接口变更时，带问题包交 `analysis`。 | 不改原件、不代做完整修复、不越权写回规则；绝不顺着跑偏前提抠表皮走形式；用户明确只诊断或禁试改时不出对照。 |
| **laohu-analysis**（分析与方案） | 穿透表层需求做三态先判，查明最早可证断点（含大模型生成机理断点）、比较可行路径与代价、评估负载与跨技能依赖，产出有立场的决策级方案或变更规格；确认具体材料差距时同样按层级给局部对照。 | 目标、方法与关键取舍已拍板，需要落盘修改规则文件时，交获授权的 `evolution`。 | 不直接编辑正式能力文件，不替用户私下拍板未决的核心目标或权限变更，不顺着跑偏前提设计精密烂方案。 |
| **laohu-evolution**（进化写回） | 核实唯一真源，按先除限、再归位、后增补原则将已确认方案保义写回规则/配置/接口/评测，跑结构检查并执行**自适应独立对比实证门禁（A/B/C）**——确认相对纯原生 A 与旧版 B 有真实净提升才算完成进化，否则自主打回重改或交用户回滚。 | 写回或对比验证中暴露改变核心目标、专业方法、权限边界的未决冲突，或经 2 轮自主打回仍存负进化/方向分歧时，带完整实测证据交回 `analysis` 或停下交用户拍板。 | 不夹带未经确认的自我发挥，不以静态检查通过代替独立对比实证，绝不对负进化强行宣称完成。 |

> **单用锋利、联用成飞轮（第一性原理三步引擎 + 实证闭环）**：
> - **单项独立使用**：只查缺口与过紧限制停在 `laohu-audit`；只追根因、权衡方案或从第一性原理设计能力停在 `laohu-analysis`；已有明确改动结论需要写回并验真时直接进 `laohu-evolution`。
> - **三技能贯通进化飞轮**（当用户要求彻底优化/重构一项能力或规则时自动贯通）：
>   1. `audit` 先用第一性原理与 4×4 造梦框架锚定本质标尺，对照前沿强模型纯裸跑（A）双向照出**真硬伤 + 负资产束缚**（含理论锁冷库、横轴缺环、示范锚词与子级残毒）；
>   2. `analysis` 逐层追根定位最早错位点、做减法除限、按增量融合三问设计**高杠杆升维方案**（重大底层转向或反复钟摆时先做单变量隔离探真交人类确真）并派生**纯终端受众标尺与命题**；
>   3. `evolution` 低熵写回真源并跨文件扫残、跑结构与反污染校验、亲自完成**隔离 A/B/C 对比实证与不合格打回闭环**，确认正进化后附一字不改原始输出交人类终审。

> **以解决问题推进审查与分析**：接到用户反馈、已有诊断或参考方法时，先结合完整上下文还原它针对的真实痛点与有效机制，沿实际材料深化根因与解法。影响事实、权限或实际选择的错误直接指出并局部校正；不靠挑措辞例外、维护旧规则或交一份纯否定清单代替推进解法。

## 2. 统一追溯主线（`AUDIT-ID` 交接契约）

跨入口流转或后续复查时，为已确认问题分配稳定编号（如 `A-01`），作为内部交接主线（面向普通用户的报告按任务自然展开，不强迫展示内部表单）：

| 流向 | 最小必要交接字段 |
|---|---|
| `audit → analysis` | `AUDIT-ID`、严重度（`P0 阻断核心用途 / P1 削弱主要作用 / P2 局部损耗或隐患`）、定位（文件/章节/片段）、差距机制、当前证据层、保护项、局部对照材料、已查与未查范围。 |
| `analysis → evolution` | 对应 `AUDIT-ID`、最早错位层与根因、4×4 归属层、选定方法与须显式留运行态的底层原理、A×B 共存条件与媒介适用边界、受影响文件与真源位置、下级子文件跨文件扫残清单、新逻辑与冲突裁决、上下文负载变化、保护项、须同步的纯终端盲测项与脱标盲辨项、仍未知项。 |
| `evolution → 复查 / 独立验证` | 对应 `AUDIT-ID`、改动与真源归位清单、恢复/对照基线、静检结果（`check_project.py`）、待独立验证范围。给独立盲测执行者的输入不得泄露制作聊天、设计意图或评分答案。 |

## 3. 万能造梦框架在三技能中的分工接力

三技能共同以 [万能造梦框架](universal-dream-framework.md) 为底层透视坐标，按任务规模分级深耕，不重复劳动：

- **整体新建、整体重构、常规全局审查或跨职责大融合**：实质透视 4×4 全部 16 个交点。`audit` 标出差距、已充分承接项与盲区；`analysis` 复用已核实观察并深挖问题交点的因果链与方法选型；`evolution` 将决定落实到真源、触发、动作与真实消费者。
- **局部修订、单点补丁或定向复查**：深审受影响交点及其直接上下游，其余交点只核对保护项、权限与接口完整。

## 4. 授权流转与 `knowledge/` 沉淀边界

- **按本轮授权止步**：只要求找问题停在 `audit`；要求找问题并给方案由 `audit` 接 `analysis`；同时明确授权改写指定能力时才贯通至 `evolution`。
- **局部对照边界**：`audit` / `analysis` 报告中的同材料局部改后对照仅用于佐证差距与修法，不改动原件，不冒充独立成品或独立行为验证；非文本媒介以真实媒体呈现，不得用提示词替代。
- **沉淀进 `knowledge/`**：仅当跨多个 Skill 反复验证有效的经验、事实或老胡个人偏好且获明确授权时沉淀进根目录 `knowledge/`；真正会改变运行时判断的规则写回对应唯一真源，不在多处复制副本。
- **证据报告口径**：所有审查、方案与写回交付的验证结论统一遵循 [评估与验证协议](evaluation-protocol.md)。
