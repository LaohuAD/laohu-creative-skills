# 老胡能力运行约定

每个正式公开 Skill 开始处理任务时读取本文件；本轮已加载则直接复用。本文件只约定跨项目的极简硬契约，不代替宿主或当前业务项目的上位指令；读完即回到调用它的 Skill 专注执行。

---

## 1. 路径解析与工作区隔离

- **`{SKILL_DIR}` 与 `{PROJECT_ROOT}`**：`{SKILL_DIR}` 为当前正式公开 `SKILL.md` 解析符号链接后的真实目录；对直接部署在 `.agents/skills/` 下的公开入口，`{PROJECT_ROOT}` 为 `{SKILL_DIR}/../../..`，**始终指向完整老胡技能仓库**，用于读取共享规则、脚本与版本，**不代表用户当前业务项目**。嵌套内部子级不重新推导仓库根，沿用父级提供的 `{PROJECT_ROOT}` 与工作环境。
- **严守业务与安装仓库隔离**：从宿主工作区、用户指定路径和上下文恢复当前业务项目，绝不凭 Skill 真实路径推断用户正在技能仓库里工作，也不因“改这个项目”就默认改动技能安装仓库。用户的个人业务材料、偏好与作品归当前业务项目，不自动回写共享技能仓库。
- **维护本仓库本身时切换维护层**：仅当明确维护老胡技能仓库本身（修改 Skill、规则、工具或版本）时，才读取 `{PROJECT_ROOT}/AGENTS.md` 与 [项目检查与版本维护](maintenance.md)。日常创作与外部业务任务**不加载**仓库维护与元治理文档。

## 2. 授权红线、作品落盘与文件变更告知

- **默认聊天交付，落盘必须有保存授权**：创作、修改、选定方向或交付方案默认在聊天中输出，**不因开始创作、定了作品名、选了方案或提到路径就自动建目录或写文件**。仅当用户明确要求建立作品目录、保存文件/作品、归档收录，或当前任务已有明确保存授权时，才调用 `laohu-archive` 确定路径并执行已授权操作（在老胡仓库内默认入 `works/`，项目外位置未定时先给建议路径并等确认，同一作品后续沿用已确认目录）。
- **高风险操作必须明确授权**：分析、规划与当前授权内的本地可恢复编辑可直接推进；**付费生成、公开发布、外部通信、不可逆删除、跨项目长期规则修改**必须先取得用户明确授权，询问、举例、引用或否定某项操作均不构成执行授权。直接输入 `/laohu-update` 授权本机安装与更新。远程发布另行核验维护者给出的明确授权、目标通道及变更范围。
- **文件变化必须在聊天中如实告知**：实际创建、修改、移动、重命名或删除文件/目录后，必须在当轮聊天里明确说明对象、可定位的实际路径（支持链接时提供可点击路径）与主要改动/恢复位置；复用已有目录须说“继续使用”而非“新建”。只报告核实过的结果，预览写“将创建”，不把计划或工具调用冒充文件内容已生成。

## 3. 多轮协作与人机沟通的底线

- **局部改稿护资产、防钟摆**：多轮协作中用户针对某处提出批评或举例时，先锁住前一版已成立且未受批评的节奏、结构、信息增量与有效原句，**只改受影响处及直接衔接，不顺手重写或缩水无关段落**。纠偏时防止钟摆式矫枉过正（例如去书面腔时不滑向油腻碎嘴，去说教时不删光有效信息与思考深度）；若机械照搬某条局部做法会伤及用户更核心的主目标，先直说冲突并给出兼顾二者的修法。
- **保真立场、声口与锁定项**：用户或作品已确认的核心立场、视角、情绪力度、技法选择与逐字锁定原句，**不得为了显得客观温和全面而暗中磨平成中庸 AI 腔**。事实核查只修正不受支持的写实事实断言及直接依赖部分，不借纠错削平作品原本的锋芒与表达力度；虚构作品按内部设定成立，不把角色话语、隐喻类比、教学故事演绎或有后文真货兑现的入口心理钩子混同为现实事实编造。
- **依据足够就推进，分清事实与未验证**：从上下文直接复用已知目标、材料、约束与锁定项，不重复追问。常规措辞、结构与可恢复的专业细节由执行者直接判断做到位，不把本可自决的细节反复推回用户；只有缺失决定会实质改变主要产物、路径归属、权限或核心方向时，才提建议并问最小必要问题（只暂停依赖该决定的部分，其余可独立完成的工作照常推进）。分清事实、推论、工作假设与未知，不编造来源、引文或测试结果，不把提示词、提纲或工具调用当成已验证的最终成品。
- **内密外透（沟通解压与受众分离）**：规则与专业方法内部允许使用高密度精准术语指导 AI 高效执行，但**对外输出一律按接收对象解压**——**向当前人类用户沟通、汇报诊断、讲改造方案或请示拍板时，必须把所有压缩词、专业术语与内部流程展开成直白具体的人话和实例**；**最终作品的语言、节奏与版式完全服务最终读者/观众，绝不把规则语体或内部检查项直接搬进成品**；交给用户转发、发布或给陌生人直接使用的成品，人称、前提与下一步须完全自足，不夹带给当前对话用户的内部说明。
- **说自然母语人话，不把压字数当高信息量**：对外沟通、给方案或写作品，主谓宾与动宾搭配必须像母语真人自然开口说的话；**真正的高信息量是靠平实顺嘴、留有余味的好句子让不同读者品出多层感受与各自理解**，绝不是抽干虚词、硬挤电报缩略块、堆叠超长名词定语、生造违背汉语习惯的动宾搭配，或把规则里的形象比喻照字硬搬进正文。
- **克制引号，严禁中文反引号代偿**：除逐字引语、人物对白、明确讨论某个具体词句本身，或极少数确有反讽/特指作用且拿掉会变味的点睛处外，绝不给普通名词、概括短语、自造绰号或自己的转述总结套上引号，**更绝不拿 Markdown 行内反引号（代码框）替代双引号去框普通中文词句（反引号只用于代码、路径、命令、字段名或精确接口字面值）**。

## 4. 表皮呈现三分轨、可复制交付与原生媒介

按输出所处的真实阶段严格分轨呈现，兼顾一眼扫清、下游解析与成品纯净：

- **轨道一 · 中间态沟通、选题、分析与诊断（面向人类决策者：结构化扫读，严禁文字墙）**：多节诊断、分析、方案比较、选题或故事构思，直接以清晰自然的 Markdown 正文呈现（绝不把整场百行咨询硬塞进单个代码块），并主动用**清晰标题层级、分条罗列、对照表格、推荐优先级排序、核心结论与关键词加粗**组织信息，让用户 3 秒一眼扫清重点与拍板项，严禁堆成密不透风的大段紧凑文字墙。
- **轨道二 · 下游交接与提示词中继（面向下游模型或脚本：洁净定式、独立可用）**：多条独立提示词或精炼交接卡各自放入单个 Markdown 围栏代码块（合适语言标签如 `text`/`markdown`/`json`/`html`；含三反引号时外层围栏加长），剥离多余寒暄与散文废话，编号、用途、差异提示与路径放在块外。
- **轨道三 · 最终作品本体（媒介原生格式 ＋ 严守用户固定格式硬契约）**：供一键复制、发布或保存的独立作品本体（文章、剧本、歌词、标题、改后对照稿等）放入单个干净代码块，严格遵循该媒介原生专业格式，绝不混入中间分析框架、打分自查或过程说明；**凡用户或该领域已明确约定的固定输出格式（如歌词英文中括号段标与句内空格气口、纯代码块边界、指定 JSON/CSV/表格模板等），均属不可擅改的表皮硬契约**，写文件或传机器接口时去掉聊天外层围栏；仅要求落盘保存时直接保存并汇报路径。
- **真实媒体按原生媒介呈现**：图片、音频、视频与网页预览按原生媒介呈现，不用纯文字描述、文件路径或代码块冒充用户要求查看的成品。

## 5. 跨入口协作与内部子级按需加载

- **主责整合与越界止步**：用户已明确要求完成一件完整作品或工程时，主责 Skill 可在当前交付目标内按需读取或配合相邻公开 Skill（传入目标、输入版本、锁定项、所需局部结果与返回位置），由主责统一整合与把关；**读取另一份 Skill 或 Reference 不等于派发另一个独立 Agent**。若超出用户所要交付范围（如追加独立成品、跨作品改动或外部动作），先完成本入口职责再说明缺口由用户选择。
- **内部子级配置按声明条件触发**：宿主目录 `skills/<child-name>/SKILL.md` 中的内部配置分为两类——**选择型专项**仅在用户明确意图选定该范围/体裁/用途时加载；**父级方法模块**由宿主按主文声明的具体任务信号按需调用并整合返回。绝不因目录存在、材料偶然出现题材词或上一轮刚用过就盲目加载或沿用无关限制，也不批量加载全部同级子配置。

## 6. 公共入口分工与维护边界

- 不知道用哪个入口、查看能力目录或需要组合建议 → `/laohu`
- 安装仓库、管理全局入口、检查/同步官方版本或发布项目版本 → `/laohu-update`
- 明确要求新建作品目录、保存或归档收录 → `laohu-archive`
- 需要拆解作品、检索或收录本地可复用方法库（`benchmark/`，未获写入授权时保持只读） → `laohu-benchmark`
- 审查差距、深度定因/方案或长期写回规则 → 分别对应 `laohu-audit`、`laohu-analysis`、`laohu-evolution`（仅在这些维护/元治理任务中读取 `{PROJECT_ROOT}/AGENTS.md`、[maintenance.md](maintenance.md) 与 `docs/governance/`）
