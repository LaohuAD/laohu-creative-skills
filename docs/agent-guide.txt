老胡造梦技能：Agent 使用指南

这是一份面向能够读取网页或文本 URL 的 Agent 的官方能力说明。用户提供本文件后，你可以用普通问答解释能力、帮用户选择入口、说明需要哪些材料，并给出可直接使用的请求方式。

阅读本文件只说明你了解了这些能力，不代表本机已经安装了技能、当前宿主已经发现它们，或你已经实际调用了某个 Skill。用户希望你执行任务时，按当前环境实际可用的正式定义、工具条件和用户授权行动；无法读取对应定义或没有相应工具时，要说明限制，不要声称已经调用或完成。

聊天中的完整文本交付

当用户需要可以直接复制、保存或转用的完整文字结果时，把结果本体放在 Markdown 围栏代码块中；作品、分析结论、审查结果、方案、规则、提示词、标题和结构化文本均适用。一篇作品或一份完整文档使用一个代码块，作品名称或标题与正文放在同一块，文档内部标题也保留在块内；多个独立结果分别成块。文件名、用途、路径和状态等交付附注放在块外。

用户本轮指定其他聊天展示方式时，遵从该要求。代码块只用于聊天显示：保存文件、写入文章或调用机器接口时，保持文件格式和接口契约，不增加外围聊天代码块。图片、音频、视频和网页预览按其原生媒介展示；随附的可复制文字仍按上述规则处理。

1. 总入口：laohu

适合：你还不确定该用哪项能力、需要组合多项能力、想了解技能目录或询问安装更新方法。
请提供：当前目标、已有材料或卡点，以及已经确定的用途和限制；不确定的部分可以直接说明。
交付：解释推荐哪项或哪组能力、为什么适合，并给出可以直接发送的任务请求。用户只想看目录时，列出当前实际定义的能力。
边界：负责选择和说明，不代替专业能力完成作品，也不会因能力缺失自动创建、安装或更新技能。用户已明确选择匹配入口时，直接进入该入口，不必重新推荐。

2. 严格审查：laohu-audit

适合：检查作品、提示词、脚本、Skill、项目或流程本身，确认具体缺陷或有依据的质量差距。
请提供：要审查的实际材料或可访问文件、预期用途、接收者、已确认要求和必须保留的部分。若材料很长，说明最相关的范围。
交付：可以复查的问题包，定位实际材料，说明适用判据如何检验眼前处理、材料或关系，差距怎样形成、影响哪项用途；质量判断须有适用依据，不能只给表面印象。确认具体材料存在差距后，默认在报告里先给问题和依据，再展示同材料局部改后对照及变化作用；必要的上下文可一并展示，同处多问题合并处理。
边界：找茬本身要解释当前被审对象内部为何没完成用途；即使对象本身是流程，也检查其中的实际处理与结果。只有要越出当前对象和证据，追查问题为何在更大流程中反复发生、判断责任/动机或比较修法时，才交由 laohu-analysis；audit 不覆盖或写回原件、不代做完整修复。用户明确只诊断或禁止试改时不出改后对照；没有证据的问题不会写成结论，没有具体材料不造作品。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-audit/SKILL.md

3. 分析与方案：laohu-analysis

适合：表现宽泛、原因未明、需要比较做法，或长期能力设计中有会改变下一步的重要判断；也可按需从真实作品研究具体处理方法，帮助形成创作方向。正式质量比较或评分时，按验证协议选择标尺并区分证据等级。
请提供：实际材料、已经确认的问题或目标、相关记录和来源、限制条件，以及你要决定什么。若希望研究作品，请提供作品名、可核验出处或可访问原文；可说明哪些事实已核实，哪些只是猜测。
交付：有依据的解释、未知项、方案比较，或一份能交给实施者的完整方案；当本轮已读取具体材料并确认差距时，默认在分析报告中直接展示同材料局部改后对照，并说明回应的问题、保留内容与变化作用；必要时将真实作品的原文与语境、可观察证据、专业解释和本地迁移动作分开说明，并交代适用条件、依赖、保护项、负责人和验收办法。
边界：分析报告中的局部对照不是完整创作、正式成品或独立行为验证，不改原件；用户明确只诊断/禁止试改时不出对照。analysis 不替代专业入口完成完整作品、不直接实施生产修复，也不把规则写回长期能力。普通创作无需例行外搜范例；流行度、获奖或模型熟悉度不能单独证明顶尖质量。审查差距用 laohu-audit；方法已经选定并要求写回时用 laohu-evolution。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-analysis/SKILL.md
按需的日常创作取法：https://github.com/LaohuAD/laohu-creative-skills/blob/main/references/exemplar-study.md#日常创作取法与方向

4. 长期能力改进：laohu-evolution

适合：改进 Skill、规则或其他长期创作能力，而且用户已经确定改进方法并要求写回。
请提供：希望改善的行为、已选定的方法与取舍、当前文件或仓库、必须保留的有效行为，以及授权修改范围。
交付：更新实际会被 Agent 读取或运行的规则、引用与调用关系，并按授权范围检查改动。
边界：不替用户裁决尚未选定的专业方法，也不代改当前作品。若关键方法或目标仍未定，先用 laohu-analysis；普通文章或图片成品交给对应创作能力。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-evolution/SKILL.md

5. 故事与创意构思：laohu-story

适合：从灵感、材料或已有点子发展创作方向，适用于文字、音乐、图像、视频等媒介的构想阶段。
请提供：已有点子或素材、希望表达的内容、媒介、已确定的事实和限制。若想让 Agent 主动找灵感，可以明确说允许从指定的虚构起点探索。
交付：不同的创意解释与角度、取舍理由，以及说明作品创作什么、为什么值得、如何展开的总体构想。
边界：负责构思和作品雏形，不替代完整文章、最终图片、成品生成或其他专业制作。要把口述或资料整理成完整分享文章，使用 laohu-writing；要做具体图片设计，使用 laohu-image 或 laohu-cover。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-story/SKILL.md

6. 通用内容写作：laohu-writing

适合：根据口述、ASR、资料、讨论、经历、观察、研究或现成稿件，创作或修订文章与口播讲解稿，并复盘其内容或结构；输入材料的媒介不替用户决定输出形式。
请提供：原始材料或文件、希望交付的内容形式及用途、读者/听众、事实与经历的来源、要保留的观点/语气/原句，以及明确不能改动的部分。只做录后复盘时，说明可提供的原音、计划稿/提纲或已确认目标；要断言实际录音漏讲，必须同时有可核对的原音和预定目标，缺任一类都不能下结论。可以直接贴材料，不必先整理成表格。
交付：一般内容写作由父级完整处理，按用户目标组织判断、根据、解释、体验或任务步骤，并保留事实、观点归属、授权及作者声音。只有明确要求可录制/配音的口播稿时，父级才读取内部口播配置，按听众理解任务组织净稿；时长和语速按本次目标估算，不作为通用硬上限，也不默认生成音频。只有明确要求微信公众号文章时，才读取内部公众号配置，按独立阅读路径组织文章；同一选题若要两种成品，分别改写，不强制先产出万能母稿。文章标题、正文关键表达、图解和外部 URL 继续按父级既有标题/cover/材料契约处理。
边界：口述、ASR、公众号等词出现在材料里，不单独触发对应媒介；普通文章不默认变成公众号营销文，口播也不强加短视频腔、固定三幕或短句。没有原音不能断言 ASR 错听；断言实际录音漏讲必须同时有原音和计划稿/提纲/已确认目标，只有计划而没有原音时最多指出转写未体现，只有原音而没有目标时也不能判断漏讲。只复盘不自动重写；writing 负责稿件与关键声画依赖，不取代 htmlshow-gzh 的 HTML 排版，也不接管 motion 的镜头拆分/音轨对齐。未经明确授权不保存或发布。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-writing/SKILL.md

7. 文字信息封面与图文版面：laohu-cover

适合：设计自媒体封面、海报、知识讲解图、信息图等需要读者阅读指定文字或信息的图片。
请提供：标题、主题或原始知识材料；读者是谁、要看懂什么或采取什么行动；平台、比例、锁定文字、品牌素材和禁项（已知时提供）。
交付：信息取舍和层级、图文关系、版面与排印方向、画面效果说明和可复制的图片提示词；可承接 writing 的篇内图 brief，回交插入锚点、局部关系、必要图注、完整提示词和设计状态。
边界：篇内图只设计正文此处需要的局部关系，不重述已建立的背景，不默认套封面比例或文章标题；交付设计和提示词，不直接生成、编辑或保存图片。图像模型是否能准确绘制复杂中文、长正文、数字或图表不能保证。只需纯画面构思时用 laohu-image；只需标题文字时用 laohu-title。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-cover/SKILL.md

8. 图片画面设计：laohu-image

适合：确定一张图片表现什么、主体关系、构图、风格、光线、色彩和观看方式。
请提供：主题或对象、画面用途、已有图像或参考（如有）、已确定的视觉方向、希望观者看到的关系，以及不能出现的内容。
交付：一段预期画面效果说明和一段可直接使用的图片提示词。
边界：设计画面与提示词，不生成、编辑或保存图片。若观者需要通过准确排版的文字获取信息，使用 laohu-cover；若要筛选剧本中可复用的人物、道具或场景资产，使用 laohu-assets。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-image/SKILL.md

9. 标题与关键表达文字：laohu-title

适合：从经历、事实、观点、故事或意象中发现值得表达的内容并凝练成句；可处理文章主标题、章内标题、题眼/中心/总结/过渡/原则句、歌词副歌核心句，以及封面与平台发布标题。具体人物、事件、原句或意象本身有价值时可以直接保留，不必一律抽象成普遍道理。
请提供：相关材料、句子在作品中的实际位置和职责、作者已锁定的观点/原句或允许探索的范围；标题任务另提供目标读者、平台与字段。拟篇内标题/关键句时，提供对应段落和上下文；拟歌词核心句时，提供已有歌曲材料与所需表达范围。仅有原标题也可先做句面诊断；核验事实、正文承接或平台字段时才需要相应材料。
交付：符合指定位置、职责与范围的关键表达及必要取舍理由；标题任务区分文章主标题、章内导航标题、封面与平台发布字段，完整发布包才使用默认21条，不把章内标题或单句任务误作独立发布广告，也不补齐未请求的结果。
边界：不代写整篇正文、整首歌词或口播稿，不改作者锁定观点，不包办旋律；不制作封面视觉、不发布内容，也不保证点击、曝光、排名或传播效果。要确定版面与图文结构用 laohu-cover。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-title/SKILL.md

10. 阅读与使用型 HTML：laohu-htmlshow

适合：把已有 Markdown、文本、提示词、剧本或结构化内容做成便于阅读、对照和使用的浏览器展示页。
请提供：已有内容或文件、谁来阅读、阅读或操作目的，以及需要强调的层级和交互（已知时提供）。
交付：按最终用途组织信息、布局和交互的 HTML 展示页。
边界：这是把已有内容变成展示载体，不代替专业创作，也不自动发布网页。若最终目标是粘贴到微信公众号编辑器，由本入口读取公众号专项 laohu-htmlshow-gzh。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-htmlshow/SKILL.md

11. 公众号排版专项：laohu-htmlshow-gzh

适合：把已有文章整理成可粘贴到微信公众号编辑器的 HTML 正文；也可在用户明确要求建设可复用主题时设计主题并交接长期写回。
请提供：完成的文章或文稿、希望的主题或风格偏好、必要的图片与格式要求。若只想浏览器阅读，使用 laohu-htmlshow 的普通展示页。
交付：公众号正文 HTML、复制预览和格式检查；按原文的阅读任务与结构选择完整主题，实际粘贴出现差异时定位具体组件并复验。静态检查、浏览器复制、微信公众号实际显示是不同的验证范围。
边界：它不登录公众号、不提交或发布文章；未经公众号编辑器实测，不承诺所有样式都能保留。它是三级专项，不单独参加全局入口登记，由 laohu-htmlshow 在明确的公众号格式任务中读取。

12. 剧本可复用资产：laohu-assets

适合：从剧本筛选、设计需稳定复现的资产；也适用于无剧本时从零设计或修改单件资产。同作多项资产需要共同设计方向、个体辨识与跨段连续性时，也由此处理。
请提供：剧本或相关片段及范围（如有）、已有角色或资产说明（如有）、连续性信息，以及本轮要做筛选、正式设计或局部修改。
交付：按范围筛选并区分对象身份，给出正式资产规格及有依据的变化关系；视觉资产默认整合为可单独使用的完整图片提示词；只有用户明确要求固定角色/旁白声音身份或授权声音资产范围时，才交付稳定声音提示词。视频任务在 P 方案被采用后，可结合完整源稿、初步镜头、已采用 P 与现有资产，全篇归并实体并列明逐 P 使用、依赖和故事内状态位置；同一资产只设计一次，不按 P 重造。提示词不等于图片/音频已生成或试听；实际生图、音频生成、编辑、试听或保存另需授权。人物、服装、道具、场景、状态、声音身份与四窗布局专项由本入口按明确任务需要读取。
边界：它设计可复现的资产规格，不要求必须有剧本或多个对象；单张画面的构图、光色与即时表现由 laohu-image 承接，单句台词表演与场景声场由 laohu-video 承接。七个专项是内部按需配置，不是独立的公开或全局入口；声音身份设计不自动创建实际音频或平台 voice ID。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-assets/SKILL.md

13. 作品收录与目录：laohu-archive

适合：用户明确要求新建作品目录、保存文件、继续归档或收录已有作品时。
请提供：作品名称和类别、已有目录（如有）、本次要保存的材料、希望使用的位置。项目外使用而位置未定时，先让 Agent 提出具体路径并等你确认。
交付：创建或复用的作品目录及实际路径；同一作品后续沿用已确认位置。
边界：创作、命名或讨论本身不等于保存授权；该能力负责目录和归属，不替代写作、设计等专业创作，也不会把所有草稿自动收进去。项目内默认使用仓库 works/；项目外不从技能安装位置猜作品目录。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-archive/SKILL.md

14. 完整项目安装与更新：laohu-update

请提供：作品、可读材料或出处，以及希望看清的处理（如有）；如果要用于当前创作，也请提供消费者、具体决定和阶段。若要保存，明确说明收录本次资料或选择收集模式。
交付：标明来源与读取范围、实际处理、必要上下文、机制解释及成立边界；说明它可用于哪一步、怎样转成具体产物与如何检查。要求拆解并收录时，同轮给出完整分析与具体入库方案，说明拟保留关系、拆分理由、复用场景、全文保存去向和检索入口，默认经用户确认后写入。已有确认方案或明确要求直接执行时按公开定义办理。资料不足时保留来源/方法候选，不伪装成熟方法。
边界：不从热度推因果、不推断作者私密过程、不复制原作独特表达；读取入口、搜索卡片或打开详情不等于采用或保存。用户只要求加载时只读取入口状态；读取或采用本身不授权写入。保存写入当前项目根 `benchmark/` 的私有研究库，与 `works/benchmark/` 作品档案分开；未确认工作区或归属时只暂停该决定。
公开定义：https://github.com/LaohuAD/laohu-creative-skills/blob/main/.agents/skills/laohu-benchmark/SKILL.md

怎样向 Agent 提需求

可以直接提供目标和已有材料，不必先学会 Skill 名称。把方括号内容替换为自己的信息；没有的内容可以省略或说明尚未确定。

通用请求：
“我的目标是【希望得到的结果】。我能提供【材料、文件或链接】，用途是【读者或使用场景】。已经确定或必须保留的是【事实、观点、文字、风格或限制】。请先判断适合的能力；如果我已经指定能力，请直接按这个范围处理。需要保存、修改项目文件或发布到外部时，只按我明确授权的范围行动。”

能力选择：
“/laohu 帮我选择入口。目标是【目标】，现有材料是【我提供的材料】，使用场景是【场景】。请说明推荐理由，并给我可以直接发送的任务请求。”

写作：
“/laohu-writing 请根据我提供的【口述、ASR、讨论、初稿或资料】，按【一般文本 / 文章 / 明确指定的口播稿 / 微信公众号文章 / 录后复盘】这一目标，为【读者/听众和用途】整理、创作或检查；区分输入材料与期望成品，保留【已确认观点、事实、经历归属或原句】。”

小说：
“/laohu-novel 请把【主题、故事构想或各章粗述】写成小说【正文范围】；保留【人物、关系、核心、结局、声音等锁定项】，在其余开放范围内补足创作所需内容。按【正文格式或篇幅要求】交付。”

动画制作：
“/laohu-motion 请根据我提供的【主题/口播稿/现有工程】，面向【观众和用途】制作动画。保留【原稿、事实、音轨、素材和限制】；目标画幅/时长为【已知规格】。若需要口播同步但缺原音，请使用暂定设计预算并标记待对齐；若明确不需要旁白或要做无声/界面动效，则按目标时长与事件节奏完成，不等待原音。若指定固定画风，请使用【画风】；请把镜头设计落实到可渲染工程，并检查最后媒体。若我只要方案或只审查，请停在该范围。”

审查：
“/laohu-audit 请按【用途和目标】审查本轮可定位读取的【作品或文件】，确认问题后在报告中附同材料的局部改后对照，并说明变化作用；不要改动原件。若我明确说只诊断或禁止试改，就只交诊断。”

标题或封面：
“请基于我提供的【文章或材料】，为【平台和读者】处理【标题文字 / 承载文字信息的封面】；保留【锁定文字、事实和限制】。”

选题：
“/laohu-topic 请根据我提供的【赛道/教学定位、真实问题或材料】，探索相关人群的任务与需求并确定或比较完整选题；判断【读者所得、材料依据和兑现条件】，保留【已锁定的读者、目标、事实与限制】。”

公众号排版：
“请把我提供的【已完成文章】排成可粘贴到微信公众号编辑器的正文 HTML，并提供复制预览和格式检查。”

这些模板用于说明请求结构，不是作品内容样例，也不构成安装、写入、保存或外部发布的授权。

项目内使用与全局安装

需要：Git、Python 3.9 或更新版本，以及能读取本地 Skill 的 Agent。项目检查不需要第三方 Python 依赖。先取得完整仓库；在你选择的父目录执行：

git clone https://github.com/LaohuAD/laohu-creative-skills.git
cd laohu-creative-skills
python3 tools/check_project.py

项目内使用：在完整仓库中打开 Agent。Codex 可发现 .agents/skills/；其他宿主若没有显示入口，可以让 Agent 读取仓库中的 .agents/skills/laohu/SKILL.md 开始。项目内使用不需要全局安装。

全局使用：在完整仓库根目录运行 install.py。以下命令以 Codex 为例，第一条预览，只有用户明确要求实际安装且预览无冲突后，才执行带 --write 的命令：

python3 tools/install.py install --host codex
python3 tools/install.py install --host codex --write

Claude Code 本机使用时，把宿主选项改为 claude，同样先预览：

python3 tools/install.py install --host claude
python3 tools/install.py install --host claude --write

当前工具全局直接登记一级和二级正式入口，共 22 个；三级及更深层级不单独创建全局入口，所属二级入口按任务需要读取。工具会把所选正式入口链接到对应宿主的用户级技能目录；链接指向这份完整仓库，因此仓库必须留在 Agent 可访问的位置。安装不会自动同步到云端或其他设备。不能把“链接已建”说成“宿主已发现”；按宿主方式刷新或新建会话后再确认发现状态。

只读查看已登记状态：

python3 tools/install.py status

同步已登记入口时先预览，再在用户授权写入后应用：

python3 tools/install.py sync
python3 tools/install.py sync --write

sync 只维护已经登记的目标，不会替新宿主安装，也不负责更新仓库内容。

卸载全局入口时先预览，再按用户授权写入：

python3 tools/install.py uninstall --host codex
python3 tools/install.py uninstall --host codex --write

卸载只移除仍与登记记录相符、且仍指向这份安装的技能链接；仓库、作品和其他技能会保留。不要在链接仍使用时移动或删除仓库，先卸载再搬迁和重新登记。发生同名冲突时停止说明，不覆盖、不删除冲突对象。

如需支持其他宿主，先确认其真实技能目录和目录链接能力，再把实际目录传给 --skills-dir；不要猜路径或承诺未经核验的平台、权限和云端环境。

完整项目更新

用户要求取得官方更新、检查更新、升级、发布项目版本或修复入口时，使用 /laohu-update。它管理完整 Git 仓库，包括技能、项目规则、工具和知识，不等于只复制技能文件，也不等于全局 sync。更新前核对官方仓库、本地状态与用户修改；出现规则或文件冲突时，先呈现具体差异和合并建议，等待用户决定后再处理。仅询问版本、更新内容或用法时只查询，不写入。普通自然语言的更新授权只更新与同步；直接输入 `/laohu-update` 时，命令本身已同时授权更新完整项目与发布已审阅的可发布改动。

作品保存与外部操作

在老胡项目内，经用户明确要求保存或收录时，作品默认归入仓库 works/；同一作品沿用已确认的目录。项目外且位置未确定时，先向用户建议一条具体路径并等待确认，再保存。调用某项创作能力、确定标题或完成聊天中的内容，不会自动授权创建文件或归档。

外部发布、公开分享、账户提交、付费生成、不可恢复删除和跨项目长期写入分别需要相应的明确授权。读到本文件或 README 不等于用户已经授权这些动作；用户亲自直接输入 `/laohu-update` 时，则按该命令的定义授权当前老胡项目的版本发布，不视为仅仅“读到了一条命令”。
